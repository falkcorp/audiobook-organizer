### Changed

- The maintenance jobs' write-set check (a test that reads each job's code and compares the resources it writes with what the job declares) now follows interface calls and function values through a call graph (`golang.org/x/tools/go/callgraph/vta`, with `cha` where a module interface has no known implementation) instead of only the calls it can see by name. An interface call is judged by the method's name and its implementations' bodies are walked, taking the union; a callback loaded from a struct field, a package variable, a slice or a map and passed on is resolved from the module's own stores, and a call through a function value it cannot resolve is recorded and fails the test unless it is allowed with a reason. A store write reached through a method whose name says nothing about writing, or an interface implemented by a wrapper, is now found, and a callback is still attributed to the caller that passed it and to no other. The 34 jobs derive the same write sets as before, so no declared write set changed. Test-only: no runtime behaviour changes.
- The test list of inert store calls is keyed by `<receiver>.<method>`, not by the bare method name, so a future write named `Move` or `Locked` on another type is no longer ignored.
- A new test checks that the native TagLib writer (`taglib_cgo.go`, what production builds) reaches the same write helpers, resource kinds, classified calls and file writers as the pure-Go variant the check walks (`taglib_support.go`).
- `jobs.FailJobWritesWith` (a test helper that swapped a package variable, unsafe under `t.Parallel`) is replaced by `jobs.KindsWithFailingWrites`, which builds the kinds over a failing derivation without changing anything global. `Kinds` reads the derivation from an unexported `KindDeps.writes` field (nil means the real one), and `effectsFor` takes it as a parameter.
