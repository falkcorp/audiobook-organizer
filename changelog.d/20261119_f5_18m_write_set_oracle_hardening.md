### Changed

- The maintenance jobs' write-set check (a test that reads each job's code and compares the resources it writes with what the job declares) now follows interface calls and function values through a call graph (`golang.org/x/tools/go/callgraph/vta`) instead of only the calls it can see by name, and is default-deny: a call it cannot fully resolve is recorded and fails the test unless it is allowed by an exact key with a reason. An interface call is judged by the method's name and its implementations' bodies are walked, taking the union; when the receiver can come from code the test does not see, every implementation the module declares is walked too, for the module's own interfaces and the standard library's alike. A callback is resolved from the module's own stores into the field, variable, slice, map or local it is read from, from what a called function returns, and from what the program's callers pass a constructor; each reason the set can be incomplete (an exported field, an unset variable, a function made outside the module, a parameter no caller supplies) is recorded. The 34 jobs derive the same write sets as before, so no declared write set changed; the run reporter's own op-log, op-error and activity rows are not counted as a job's writes. Test-only: no runtime behaviour changes.
- The test list of inert store calls is keyed by `<receiver>.<method>`, not by the bare method name, so a future write named `Move` or `Locked` on another type is no longer ignored.
- A new test checks that the native TagLib writer (`taglib_cgo.go`, what production builds) reaches the same write helpers, resource kinds, classified calls (including store-package functions it calls), write-named method calls and file writers (called or passed as a value) as the pure-Go variant the check walks (`taglib_support.go`).
- `jobs.FailJobWritesWith` (a test helper that swapped a package variable, unsafe under `t.Parallel`) is replaced by `jobs.KindsWithFailingWrites`, which builds the kinds over a failing derivation without changing anything global. `Kinds` reads the derivation from an unexported `KindDeps.writes` field (nil means the real one), and `effectsFor` takes it as a parameter.
