### Changed

- The maintenance jobs' write-set check (a test that reads each job's code and compares the resources it writes with what the job declares) now follows interface calls and function values through a call graph (`golang.org/x/tools/go/callgraph/vta`, with `cha` where a module interface has no known implementation) instead of only the calls it can see by name. A store write reached through a method whose name says nothing about writing, a callback stored in a struct field or a package variable, or an interface implemented by a wrapper is now found, and a callback is still attributed to the caller that passed it and to no other. The 34 jobs derive the same write sets as before, so no declared write set changed; the two hand-written aliases the old walk needed (`tagger.LibraryImporter.ImportPath` and `jobs.checkpointer.Save`) are gone. Test-only: no runtime behaviour changes.
- The test list of inert store calls is keyed by `<receiver>.<method>`, not by the bare method name, so a future write named `Move` or `Locked` on another type is no longer ignored.
- A new test checks that the native TagLib writer (`taglib_cgo.go`, what production builds) reaches the same write helpers as the pure-Go variant the check walks (`taglib_support.go`).
- `jobs.FailJobWritesWith` (a test helper that swapped a package variable, unsafe under `t.Parallel`) is replaced by `jobs.KindsWithFailingWrites`, which builds the kinds over a failing derivation without changing anything global. `Kinds` now delegates to an unexported `kindsWith` that takes the derivation as a parameter.
