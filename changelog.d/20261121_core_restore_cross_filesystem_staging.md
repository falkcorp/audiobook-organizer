### Fixed

- `storage restore-offline --checkpoint` (what `make rollback-restore` runs, and after the F3-07 flip the only way back) no longer refuses on an install whose state directory and store are on two filesystems. It used to fail with `storage: a swap target cannot be moved by rename: <stateDir>/.encryption_key: is on another filesystem than <store parent>/.mediacore-restore/<id>/staging/state/encryption_key`. `core/kernel`'s `stageSource` staged every checkpoint state file beside the store, so the swap's rename pre-check (`restorejournal.Validate`) refused the rename onto each state file in the state directory, and nothing moved. Each state file is now staged on its own target's filesystem by the new `restorejournal.StagingDest`, the twin of `SetAsideDest`. A file under the state directory is staged in `<stateDir>/.mediacore-restore/<id>/staging/state/<label>`, one beside the store in `<db parent>/.mediacore-restore/<id>/staging/state/<label>`, and any other file beside itself. The state directory's staging is its private directory, not `restore/<id>/`. A staged item inside `restore/` is refused by `ValidateTargets`, `Stage` refuses an id whose `restore/<id>` already exists, and an escape stages under a fresh id but journals under the failed restore's. So no guard was loosened. `--archive` with `--keyring` and `--gap-fill` stages the same way, and so does the escape from a failed checkpoint restore, which hit the same refusal.
- `AsideRoots` now includes the state directory's private directory when a target lies under the state directory. The new `restorejournal.StagingRoots` (the aside roots without `restore/<id>`) lists every directory a restore stages into. A restore refused before its intent is linked, and an escape, now remove what they staged on every filesystem, not only beside the store. An applied restore removes its emptied staging directories, so none is left in the state directory.
- Tests: `TestCheckpointRestoreAcrossFilesystems`, `TestArchiveRestoreAcrossFilesystems` and `TestRefusedRestoreAcrossFilesystemsLeavesNoStaging` use a probe that puts the state directory on a device of its own. `TestOfflineRestoreKillMatrix` and `TestEscapeKillMatrix` now also run every kill point with the state directory on another filesystem. On the code before the fix, the four restore and escape tests failed with the message above. `restorejournal`'s new tests cover where `StagingDest` puts each file, check that `AsideRoots` and `StagingRoots` contain every staging path, and check that `ValidateTargets` accepts state-directory staging in three layouts.
