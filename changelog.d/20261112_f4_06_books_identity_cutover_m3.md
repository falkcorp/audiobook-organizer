### Added

- books/cutover: the identity step M3 and its read-only preflight (dark: `IdentityStep` is built and tested, and nothing registers it until F4-08). It moves HEAD's users, roles, API keys, OAuth identities and the invite allow-list into core's auth and rbac stores with every ID kept and every key verifying by its stored SHA-256; deletes sessions, invites, the seed role rows and the bootstrap token hash; and rewrites each merge journal once so no raw invite token survives. A key's scopes are its atoms' native scopes cut to its owner's roles, with `core:admin` only for an admin owner, and the ambient scopes unless the set is Confined. An atom outside the table grants nothing and is reported. The step is sequential and resumable at every chunk.
- books/cutover: the preflight stops the upgrade, before any store of core's exists and with nothing written, on a user, key or identity row the importer would refuse or that does not decode, a key or identity whose user is not stored, two users that fold to one username, and a merge journal that is applying, undoing or unreadable. A blocker names the row's key and a fixed reason, never a value.
- core/app: `storage cutover-blockers list [--out <file>] | fix <key> --from <file> | delete <key> --confirm`, run with the service stopped over a store the cutover has not started on. It acts only on a key the current report names and whose blocker offers the action, commits the change, a record at `c/storage/cutover/blockers/<step>/<n>` and the `core.storage.cutover_blocker_*` audit event in one batch, and refuses (writing nothing) an edit after which the step's preflight still names the row or names a new one.
- core/auth: `CheckImportUser`, `CheckImportAPIKey` and `CheckImportIdentity`, the importer's record rules as predicates; the native importer calls them first and a cutover preflight calls the same ones.

### Fixed

- core/internal/storagemigrate: a cutover step's chunk batch is now indexed, so an importer that reads back what the chunk staged (a key checking its owner, which `authstore.ownerPresent` does) sees an owner imported earlier in the same chunk.
