### Changed

- The process config is now copy-on-write underneath (`internal/config/cow.go`). Every local write (`Mutate` with no Facade installed, `Project` on each settings rebuild, the boot normalisation, and the new test setters) builds a fresh deep copy and publishes it behind an atomic pointer that `config.Get()` returns. This is the foundation of the config-cow sweep, which moves the roughly 420 unlocked `config.AppConfig` readers onto `config.Get()` in package-sized slices.
  - Nothing reads `config.Get()` in production yet. `config.AppConfig` stays as a mirror that every publish refreshes, so every reader sees the same values as before.
  - `Config.Validate()` and `Config.Problems()` no longer normalise their receiver. The two boot sites that called `config.AppConfig.Validate()`, and in doing so rewrote the live config field by field outside the lock, now call `config.NormalizeAndValidate()`, which publishes the normalised config in one swap. With a Facade installed that is a no-op, because `Project` has already normalised the config.
  - If a `Mutate` callback panics, nothing is published. Before, whatever it had written before the panic stayed.
  - New guards in `internal/arch`: no writes through `config.Get()`; the test-only setters may not appear in production code; a ratchet on direct `config.AppConfig` writes in tests; and no production `config.Get()` while any such test write remains. The `AppConfig` ratchets now count `config.Get` uses as well. Under `go test`, a seal panics if a published snapshot is written in place.
  - `scripts/config_cow_codemod.py`, the sweep's re-runnable rewrite tool, lands with its tests. It gains `--skip-field`, which leaves the class-i fields that F7-09 re-points (`RootDir`, `ProtectedPaths`, `DownloadClient` and the rest) untouched.
