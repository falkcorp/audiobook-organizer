### Security

#### `go/path-injection` — the four remaining CodeQL findings are resolved as verified false positives

Each of the four still-open `go/path-injection` alerts was traced from its
attacker-controlled input to its sink and found to already sit behind a barrier
CodeQL cannot model. The two `os.Stat(op.backupPath)` rollback sinks in
`internal/fileops/safe_operations.go` read a path built by `safepath.Join`,
which rejects absolute components and requires the cleaned result to stay under
the backup directory. `listAudioFiles` in `internal/metadata/assemble.go`
enumerates a directory every caller has already put through
`fileops.ValidateUserPath` or the scanner's configured import roots. The
synchronous-scan fallback in `internal/server/handlers/filesystem.go` stats a
path produced by `pathvalidation.CleanAbsolutePath`. Each site now carries an
`lgtm[go/path-injection]` annotation naming its specific barrier, matching the
existing suppression in `service_mutation.go`, and new tests in
`internal/fileops` pin the `safepath.Join` containment the first two cite so the
justification cannot rot silently.
