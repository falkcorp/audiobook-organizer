### Fixed

- An organize scoped to one folder now organizes only that folder. `library.organize` accepted `folder_path` and the organizer ignored it, so a run scoped to one folder copied or moved every book in the library. The scope is now applied where the candidate set is built: a book is in scope only when every one of its (non-missing) `book_file` rows is inside the folder, matched on a path boundary (`/x/a` does not match `/x/ab`) after cleaning both paths. A book with files both inside and outside the folder is held back and counted as `straddles_folder_scope` in the run's outcome tally. Combined with `book_ids`, both limits apply. A `folder_path` that is empty, blank, relative, or contains `..` fails the run before anything is read or written instead of falling back to the whole library; leaving `folder_path` out still means the whole library.
- An organize with `fetch_metadata_first` and a `book_ids` list no longer widens to the whole library after the metadata pass: the post-fetch reload re-paged every book. The metadata fetch itself now runs only on in-scope books.
- An organize given an explicit empty `book_ids` list (`[]`) now organizes nothing instead of the whole library. Leaving `book_ids` out still means no restriction.
