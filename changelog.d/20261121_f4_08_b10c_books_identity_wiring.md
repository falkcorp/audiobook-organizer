### Changed

- Books is wired for the move of sign-in and sessions into the platform core, but the wiring is switched off until the flip lands (B10g), so a running install behaves exactly as before. With the switch on, books hands the core its sign-in inputs (the permission table, the account lookup, the Cloudflare Access sign-in and the Audiobookshelf compat method), keeps the browser session cookie named session_id so existing sessions survive, treats the owner gate as required whenever an owner e-mail is set (and refuses to start if an operator turned that off), and keeps the bootstrap token in the same file under /var/lib/audiobook-organizer. One predicate decides all of it, and the server refuses to start if any piece disagrees with it. Core gained two small read-only additions the wiring needs: a user and role lookup on the late auth handles, and a health snapshot the authenticated status route reads.
