### Fixed

- Bulk metadata apply (cached batch apply, batch-apply-candidates, auto-upgrade and the dry run) now has a fourth gate leg, `evidence`. A candidate is refused when its runtime is more than 10% off the files, when its author carries an editor/translator/narrator credit, when a new author's surname appears nowhere in the path or current author, when the title disagrees with the stored title and the file and folder names, when the narrator and the runtime both differ, or when the ASIN conflicts. If it would replace an existing title, author or series and there is no runtime to check, it is also refused. It passes only when at least two independent signals agree (runtime within 5%, title, author in path, narrator, ASIN, transcription). Each row of the dry run now carries every check's result, plus the file and candidate runtimes. Re-scoring the 2026-09-13 prod dry run offline with the same checks cut 6,177 would-apply rows to 2,994.
