- New Repairs-lane fixer `fragment-consolidation` folds chapter and disc files that an old scan imported as separate books back into the book they belong to. The trial is read-only and labels each row with a class. **moved**: a parent row names a path that organize emptied, so apply repoints that row at the file's new path and retires the fragment into the parent. A match that rests on the original name and size alone is a separate skipped `moved-unproven` row, unless the fragment was also imported from the parent row's folder or the durations agree. **copy**: the parent still has the file, so apply retires a fragment only when the match is proven by hash, or by import path with an equal size on disk. A name-and-size-only match is a skipped row. **no-parent**: three or more short fragments from one folder (sibling CD1/CD2/Disc N folders count as one) share a chapter key. The survivor is the lowest-id member that is organized and primary, and the row is skipped when there is none. Apply moves every row onto the survivor in chapter order, disc first and then the chapter number the key stripped, and skips the group when a position repeats or is unknown. It titles the survivor from the folder, points its path at the folder only when that folder's audio is exactly the group's files, and retires the emptied books. **manual-only** covers `books/itunes/**` (symlinks resolved), Doctor Who / Big Finish / Torchwood, and any fragment that carries an iTunes persistent id. **ambiguous** is a fragment that matches more than one parent, and **held** is a fragment whose own file is missing or unreadable.
- Retiring a fragment works the way a merge does. Every user's listening state and positions follow it onto the parent as a slice of its timeline, its external ids move over, it is demoted, and it is soft-deleted with `merged_into_book_id` set and `file_path` cleared, so the purge cannot delete the parent's file.
- Apply holds the merge lock for the whole row and re-plans the row under it. The title and folder writes compare against the values stored with the plan. A new plan after an interrupted group apply puts the moved rows back on the emptied members, including members that run already retired, so the group re-forms. A member whose group no longer forms is listed as a held `stranded` row. Apply never deletes a `book_file` row. Each step is journaled against the apply operation before it is written, so `POST /operations/:id/revert` undoes it, and a resumed run does not journal a step twice.
- New restorable change types:
  - `book_file_repoint_location`: a row pointed at a file already on disk, with nothing moved. The revert compares path and missing flag only.
  - `book_merged_into`.
  - `user_state_follow`: a journaled progress follow, restored through `merge.RestoreFollowedProgress`.
- An operation revert now restores a retired book only after every change that moved or repointed its file elsewhere has been reverted. If one of those changes is refused, every change of the retired book is refused with it. A primary demote journaled over an unset flag records "true", so the revert crowns the book again.
- "Undo last apply" on a single book refuses a batch that a Repairs apply journaled, and points to the operation revert instead.
- `metadata.ChapterGroupKey` (moved from the scanner) is shared by the scanner and the fixer, so both group chapter files by the same rule. `metadata.ChapterPosition` and `metadata.DiscFolder` read a file's chapter position and a disc folder's number.
- Repairs framework:
  - Rows can carry a `class`, their `members`, their `evidence` and a fixer-private `state`.
  - The rows endpoint takes `?class=` and returns `by_class` and `by_class_in_filter`.
  - The lane shows one chip per class, which lists that class's rows, plus an expandable list that links every book of a row.
  - `repairs.apply` is now resumable (ResumeRestart). It checkpoints settled rows, and a restart keeps their results and applies only the rest.
  - The writer gains journaled `book_file` repoint, move and track writes, still with no delete primitive.
  - The hands-off guard resolves symlinks before its iTunes check.
