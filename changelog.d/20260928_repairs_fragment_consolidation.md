- New Repairs-lane fixer `fragment-consolidation` folds chapter and disc files that an old scan imported as separate books back into the book they belong to. The trial is read-only and labels each row with a class. **moved**: a parent row names a path that organize emptied, so apply repoints that row at the file's new path and soft-retires the fragment. **copy**: the parent still has the file, so apply retires a fragment only when the match is proven by import path or hash, and a name-and-size-only match is a skipped row. **no-parent**: three or more short fragments from one folder share a chapter key, so apply elects the lowest id, moves every row onto it in chapter order, titles it from the folder and retires the emptied books. **manual-only** covers `books/itunes/**` and Doctor Who / Big Finish / Torchwood, **ambiguous** is a fragment that matches more than one parent, and **held** is a fragment whose own file is missing or unreadable. Before a row is written, apply re-checks with the strict ownership lookup that no book outside the row owns any of its files. Apply never deletes a `book_file` row, and each step is recorded against the apply operation so `POST /operations/:id/revert` undoes it.
- New restorable change type `book_file_repoint_location`, for a row pointed at a file already on disk with nothing moved. The revert puts the row's path, missing flag, hash and size back, and only while the row still holds exactly what the repoint wrote.
- `metadata.ChapterGroupKey` (moved from the scanner) is shared by the scanner and the fixer, so both group chapter files by the same rule.
- Repairs framework: rows can carry a `class`, their `members` and their `evidence`. The rows endpoint takes `?class=` and returns `by_class` and `by_class_in_filter`, and the lane shows one chip per class that lists that class's rows plus an expandable list linking every book of a row. `repairs.apply` is now resumable (ResumeRestart). It checkpoints settled rows, and a restart keeps their results and applies only the rest. The writer gains journaled `book_file` repoint, move and track writes, still with no delete primitive.
