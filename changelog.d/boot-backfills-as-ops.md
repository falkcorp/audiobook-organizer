- Four one-time library jobs that ran invisibly at every server start (external ID backfill, movement-atom cleanup, malformed M4B remux, and malformed M4B transcode followed by the known-bad-file quarantine) are now queued as their maintenance operations instead of hidden background goroutines. They show on the Operations page with progress, can be cancelled, wait for the startup warmup before they read the library, and are stopped cleanly at shutdown. Boot passes `{"if_needed": true}` to the external ID backfill and `{"quarantine_after": true}` to the transcode to keep the old boot behaviour; an operator's run without those params behaves as before. A run that finds nothing to do is tagged no-op so the activity feed hides it by default. The external ID backfill and the quarantine step now stop on the operation's cancel; before, they ignored it. The external ID backfill, movement-atom cleanup and remux ops are now marked cancellable. The quarantine's per-book check runs on a worker pool. The last two boot goroutines are converted too: the book path-set index build (`maintenance.book-atpath-index-backfill` with `{"if_needed": true}`, the sentinel-gated build instead of the forced rebuild) and the activity filter-index check for rows a rolled-back build left unindexed (`maintenance.activity-filter-index-backfill` with `{"reconcile": true}`, which was started from the activity service's build on a detached context). Both show progress, can be cancelled and wait for the startup warmup. The reconcile now starts after the warmup hold rather than the moment the activity service is built, and checks from a start mark the store keeps (persisted at open when rows sit above the seen-through mark, deleted only by a clean check or a completed backfill), so rows this boot writes are not mistaken for a rollback gap and a restart before the check ran does not lose one. Both ops report progress while they work, which changed the exported `BackfillBookAtPathIndex`, `RebuildBookAtPathIndex` and `ReconcileFilterIndexCoverage` signatures (they take a progress callback; nil is fine). An undecodable book row during the boot path-set build now marks the operation failed, as the forced rebuild already did, instead of only logging. If the reconcile fails or is cancelled after it withdrew the completion marker, the operation fails with an error naming `maintenance.activity-filter-index-backfill`, which is the run that re-enables indexed filtering, and the next boot enqueues that full backfill itself whenever it finds the indexes incomplete. The reconcile op declares manual liveness and throttles its check-phase progress stamps to one a second. While an interrupted transcode is waiting for an operator to confirm or dismiss it, boot does not queue another transcode. Boot also skips the transcode entirely when both it and the quarantine have already finished. Their start lines are now debug-level, so a run with nothing to do adds nothing to the default activity feed. Cancelling a remux or transcode now stops ffmpeg at once; the interrupted file is left untouched, its book_file hashes are not rewritten, and it is not marked permanently unfixable.
