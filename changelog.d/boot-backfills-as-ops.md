- Four one-time library jobs that ran invisibly at every server start (external ID backfill, movement-atom cleanup, malformed M4B remux, and malformed M4B transcode followed by the known-bad-file quarantine) are now queued as their maintenance operations instead of hidden background goroutines. They show on the Operations page with progress, can be cancelled, wait for the startup warmup before they read the library, and are stopped cleanly at shutdown. Boot passes `{"if_needed": true}` to the external ID backfill and `{"quarantine_after": true}` to the transcode to keep the old boot behaviour; an operator's run without those params behaves as before. A run that finds nothing to do is tagged no-op so the activity feed hides it by default. The external ID backfill and the quarantine step now stop on the operation's cancel; before, they ignored it. The external ID backfill, movement-atom cleanup and remux ops are now marked cancellable. The quarantine's per-book check runs on a worker pool. The book path-set index build and the activity filter-index reconcile still run as boot goroutines and convert in a follow-up.
