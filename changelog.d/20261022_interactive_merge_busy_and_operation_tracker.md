Restore, "Purge now", "Discard progress and purge" and the single hard delete take the merge lock, which a running combine holds for its whole run, so each of them hung until the combine ended. They now wait at most 3 seconds (`merge.InteractiveMergeLockWait`) and then answer 409 with the stable code `MERGE_BUSY` and the message "a merge or combine is running, try again in a moment"; nothing is changed when they answer it. The Library shows that text. The web app now follows merge, combine and purge operations in one app-level tracker next to the toast provider instead of inside the Library page: leaving the page no longer drops the outcome toast or unlocks the books, and the in-flight operation ids are kept in sessionStorage so a reload resumes following them. Locks are kept per operation id, so tracking the same operation twice cannot release its books early. Following an operation the server no longer knows (404/410) or may not read (401/403) now stops with "Lost track of operation X; see Activity" and releases the books, instead of polling forever. Each poll has a 30 second deadline and a retryable failure says whether it was a timeout, a 5xx or no answer. The combine outcome for an operation with no stored result now offers Undo with the operation id, and a purge that removed none of the books it looked at is shown as a warning, not a success.
