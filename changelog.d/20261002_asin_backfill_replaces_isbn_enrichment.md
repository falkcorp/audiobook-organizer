- `metafetch.asin-backfill` now says why it did not confirm an existing ASIN. Each `asin_suspect` / `asin_unverified` row carries `reasons` naming the rule that fired with its values (for example `runtime_conflict: book 612m vs audible 1043m`, `series_conflict: book "Red Rising" #1 vs audible "Red Rising" #2`, or the title/author pair). The result counts them per rule in `suspect_reasons` and `unverified_reasons`, and the log line includes the reason.
- Retired `maintenance.isbn-enrichment` and `scheduler.isbn-enrichment`, which wrote ASINs from Google Books / Open Library by title-prefix matching. Both stay registered but refuse with "retired: use metafetch.asin-backfill". The `isbn_enrichment` scheduled task is replaced by `asin_backfill`. It runs `metafetch.asin-backfill` live (`dry_run=false`) every 6 hours, is not part of the maintenance window, skips a tick while the previous run is still queued or running, and is enabled whenever the op is registered. The batch sweep behind the old ops (`EnrichMissingISBNs`, its cursor and the `isbn_enrichment_batch_limit` setting) is removed. The per-book ISBN lookup after a metadata apply is unchanged.
- A metadata apply no longer searches Google Books / Open Library for a missing ASIN or ISBN in the background (`ISBNService.EnrichBookISBN` is removed). A book left without an ASIN or ISBN is queued for `metafetch.asin-backfill` (Audible only, live, `retry_after_days=0`). A burst of applies is coalesced into one run after a 30s debounce. While the queue's previous run is still waiting to start, for example behind a full-library walk on the same concurrency key, new books are merged into the next run instead of stacking more runs.
