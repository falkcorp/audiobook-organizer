### Fixed

- core: follow-up to the full-text index (still dark). The reconciler's failure backoff no longer wipes its whole table when it reaches `Options.MaxBackoffEntries` (default 65536, new): with more poison marks than that, every one of them used to be retried on every pass. A full table now drops only the entries whose window is over, and if it is still full a newly failing mark is not recorded (it is retried on every pass) while every recorded entry keeps backing off. A backoff entry now belongs to the mark it failed on and stores its token: when the owner fixes the data and writes the entity again, the new mark is retried on the next pass instead of after the old window (up to 5 minutes), and a rewrite that still fails starts its backoff again at the first window. `core/internal/bleveindex.Engine.runRebuild` releases the index's writer lock with a deferred unlock, so a panic in a rebuild cannot leave the index locked. `storage.WriteFileDurable` creates its temp file with the OS and mode 0600 from the first instant, replacing a leftover of a crashed write, instead of creating it with the umask's default mode and changing the mode afterwards.
