### Added

- Importing a torrent through `POST /api/v1/deluge/discover/import` now links it to its book. The response gains `torrent_linked` (and a `torrent_link_note` when the link was skipped). When a `torrent_hash` is sent, it is lower-cased and checked against Deluge: the torrent must exist there and `content_path` must be one of its files. A verified hash is written onto the new version (`TorrentHash`, source `deluge`) and the new file row (`DelugeHash`), so the torrent no longer shows up again in the discovery list. A malformed hash, an unknown torrent, or a path that is not in the torrent is a 400; if Deluge is not configured or cannot be reached the file is still imported, unlinked, with a note. The file is imported in place and is not copied into the library by this change: a linked row is a candidate for the existing bulk Deluge import, which does the copy later. No Deluge storage move is made while `deluge_move_enabled` is false.
