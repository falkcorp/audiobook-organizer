### Fixed

- `InitConfig` built `AppConfig` from a hand-written struct literal that skipped 29 settings, so their shipped default, config-file and environment values never reached the running config. The most visible effect: `log_retention_days` (default 90) was always 0, which disabled the `purge_old_logs` task, so operation logs, operation changes and system activity logs were never purged. The others: `activity_log_compaction_days`, `activity_log_retention_change_days`, `activity_log_retention_debug_days`, `operation_log_retention_days`, `cache_invalidate_on_book_update`, `disable_per_user_search_filters`, `metadata_review_default_view`, `maintenance.acoustid_backfill` (and its `MAINTENANCE_ACOUSTID_BACKFILL` env), the five `deluge_*` settings, `protected_paths`, `path_aliases`, `plugins`, `ai_endpoints`, `itunes.path_mappings`, `dedup.embedding_thresholds_by_model`, `dedup.signals.confidence`, and the unused `enabled`/`on_startup` flags of `scheduled.{metadata_upgrade,asin_backfill,candidate_fetch,catalog_harvest,resolve_production_authors}`. The `tools.*` block was assigned constants and also ignored the config file; it is now read from viper with the same defaults. A stored config blob still wins over the config file and environment for any key it contains.
- New guard tests enumerate every `Config` field from its tags and every key viper knows, and fail when `InitConfig` does not read a field (or assigns it a constant), or when a default is set for a key with no field.
- `PruneOperationLogs` and `PruneSystemActivityLogs` deleted every expired row in one Pebble batch and one commit, and the first `purge_old_logs` run on an install that had never purged would have done that for the whole backlog (`syslog:` rows have no other cleanup). Both now delete in chunks of 5,000 rows (`logPruneChunk`, the same size as `PruneOperationChanges`' `opChangePruneChunk`) and commit once per chunk. All three prunes now take a `context.Context` and an optional per-chunk callback; a cancelled context stops between chunks, keeps what earlier chunks committed and returns the cancel. `maintenance.purge-old-logs` is now cancellable, reports progress after every chunk (`LivenessManual`, 10-minute silence budget) and logs how many records it removed if it is stopped, so the backlog can be cleared over several runs if the 30-minute budget runs out.

### Changed

- `log_retention_days`: 0 now means the default (90 days) and `-1` keeps logs forever. A stored `log_retention_days: 0` (the value every install carried while the key was never read) is dropped from the config blob once at startup, with a log line; `Validate` and the config load also normalise a 0 to 90, and the scheduler, the purge op and the maintenance deps resolve 0 to 90. `operation_log_retention_days` and the `activity_log_*` windows keep their existing rule (0 means their default); the field comment that claimed 0 kept operation logs forever is corrected.
- The Deluge settings tab now says `deluge_web_url` is set with `PUT /api/v1/config`, and that a config-file or environment value applies only until saved settings contain the key.
