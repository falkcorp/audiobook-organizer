### Added

- Core: the second half of core authentication, shipped dark (platform-core F4-02b). `core/auth` gains bootstrap-token redemption and first-run setup (the token is spent in the batch that creates the admin and its key), invites and temp-login and reset links as one-time tokens with epoch and creator re-checks at consume time, sign-out-everywhere and `Revalidate`, the user-merge stage, the method-bound `Compat` handle for an app's own surfaces (password verify, key authentication, principal building, key re-check), the auth-off mode with its synthetic `auth_disabled` principal (refused behind a non-loopback listener or trusted proxy unless the operator opted in), `PostRestore` and `RestrictLastAdmin`, and `BootWrites` (the `_system` user, the bootstrap token file and the start-up read-only key, none of it written by `New`).
- Core: `PostRestore` re-applies the revocation journal over a restored store (a revoked key stays revoked, a store with no journal coverage puts every active or disabled key to `needs_confirmation`), takes the more restrictive of the restored and the pre-swap state (key status, disabled or deleted users, changed passwords, links, the higher credential epoch, `SignInRestricted` and `PasswordResetRequired`), deletes every session and one-time token and bumps every epoch.
- Core: the `mediacore.auth` metrics scope: stage-12 attempts by method and outcome, throttle refusals by surface, bootstrap redemptions, `Revalidate` refusals by reason, and live session and key gauges, with `core/auth/testdata/series.golden`. Nothing in ABO or the kernel calls the service yet.
