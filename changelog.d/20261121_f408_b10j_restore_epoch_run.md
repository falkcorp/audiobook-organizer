### Fixed

- A restore boot that is killed after auth's post-restore hook committed, and then booted again, no longer bumps every user's credential epoch a second time (so a restored admin's `password.changed` line recorded epoch 2 where a fault-free restore records 1). The bump is epoch+1, so a re-run could not tell its own committed bump from none. Step 3 now stages one marker row (`restore_epoch_run` in the identity keyspace: the run key, the bump count and the sign-ins deleted, via the new `auth.RestoreEpochStore`) in the SAME batch as the sign-in deletion and the bumps. A re-run with the same run key skips the bump, still deletes any sign-in that exists, and reports the first run's counts; a run with another key bumps and replaces the marker, and a run with no key (the fail-closed fallback) bumps as before. The crash-matrix restore cell now compares each user's epoch and no longer exempts the `kernel.hooks.rbac #1` row.
