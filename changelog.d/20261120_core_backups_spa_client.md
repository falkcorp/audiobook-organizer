### Added

- An unwired SPA client for core's backup API (`web/src/services/coreBackups/`): list, create, delete, import, a download URL, and the staged restore (restore, revert, pending, cancel) over `/api/core/v1/backups*` and `/api/core/v1/restore/*`. It keeps the SSO-bounce, problem+json, timeout and Retry-After handling of the other core clients and tells a 403 for a missing scope (`permission_denied`, which is also what a non-interactive caller gets on restore and revert, since `core:backup.restore` is Sensitive), a non-interactive session on delete, import and download, a missing owner assurance and a foreign archive apart. Restore and revert have no deadline by default, as import has, because the server stages them inside the request; a lost answer means call `pending()`, never retry. `restart` is a no-op until the kernel wires the restart hook, and defaulting to no restart is an F8-04a flip obligation. Nothing imports it yet, so no page changes (F8-04 slice A6). The raw request transport the updater and backups clients both need (SSO-bounce handling, deadline, problem+json decoding, Retry-After) now lives once in `web/src/services/coreHttp/`, and both clients use it.
