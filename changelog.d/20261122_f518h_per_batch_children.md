### Changed

- The native task kinds `books.maintenance.transcribe-file-intros`, `books.maintenance.extract-wav-clips` and `books.maintenance.intro-migrate-single-file` no longer hold the books and book files of the whole library for the length of the run. A live run is now a parent that holds no rows and starts one short child run per 100 books, one at a time; each child holds its own batch's books and book files (and, kind-wide, the metadata cache and identity index that a book update writes), so a write to any other book's row is not held behind it, while the cache reaper and the metafetch cache sweep still wait for the short child. A child is started only by its parent: a start by hand is refused. The parent keeps a cursor (the last completed book) and the running totals in its checkpoint, so a restart resumes at the next batch and re-attaches to the child that was in flight, a cancel stops after the current child, and the parent's result is the sum of the children's. The three kinds are not registered yet and the existing v2 operations for the same work are unchanged, so nothing runs differently until the tasks flip.
- A child refuses a file that is not one of the files its batch was planned with, and counts it, rather than writing it.
- A restarted transcribe-file-intros parent keeps the run's counters and start time instead of resetting them to zero until the next batch finishes.
