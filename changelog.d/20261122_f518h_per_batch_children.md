### Changed

- The native task kinds `books.maintenance.transcribe-file-intros`, `books.maintenance.extract-wav-clips` and `books.maintenance.intro-migrate-single-file` no longer hold the books and book files of the whole library for the length of the run. A live run is now a parent that declares no row writes and starts one short child run per 100 books, one at a time; each child holds only its own batch's books and book files, so a metadata write to any other book is not held behind it. The parent keeps a cursor (the last completed book) and the running totals in its checkpoint, so a restart resumes at the next batch and re-attaches to the child that was in flight, a cancel stops after the current child, and the parent's result is the sum of the children's. The three kinds are not registered yet and the existing v2 operations for the same work are unchanged, so nothing runs differently until the tasks flip.
- A child refuses a file that is not one of the files its batch was planned with, and counts it, rather than writing it.
