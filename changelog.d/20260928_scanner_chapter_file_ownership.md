- Scanner: a file already owned by another book's `book_file` row is no longer imported as a new book. `saveBookToDatabase` now asks who owns the scanned files (`checkFileOwnership`) before creating an author, work or book, and before the organizer-ID relink. A chapter of a multi-file book, a group mixing owned and unowned files, or files owned by several books are skipped and logged at Info with the owning book IDs. A rescan of a book normalized to its directory still updates as before. A regrouped folder whose chapters were already imported one book each is skipped, not overlaid onto fragment #1. A new directory-shaped book has its folder's files checked too. A store error fails closed. This is the path that minted ~26,600 fragment books (Eldest, Scattered Suns).
- Organizer: an in-place move is refused, counted as a skip rather than a failure, when a file it would move is owned by a different book (`owned_by_other_book`), when the source or target is in the frozen iTunes tree (`frozen_itunes`), or when a multi-file book's path is only one of its files (`partial_multi_file`). In-place moves are now recorded as `organize_rename` with the real pre-move path (`Landing.SourcePath`), where before they were logged as `organize_skipped` with old == new, so undo could not see them. The `library_state` record now also carries the pre-move state.
- Scanner: an album group of more than 250 files in one flat folder no longer falls back to one book per file (a 1,188-file Bible folder became 1,188 books). It is sub-grouped by filename stem, and the sub-groups keep their own paths instead of all being normalized to the shared folder. An author shelf of whole novels still stays one book per file. A single stem group that is still over the limit is refused with a warning instead of being shattered.
- Scanner: chapter consolidation now recognises trailing numbers, bare numbers, `Chapter/Part/Disc/CD/Track N` and `N of M`, not just a leading number. A marker only counts when it starts a word and is followed by a number, so "Discworld" is not a disc marker, and `Book N` / `Vol N` are left alone as series positions. Durations are read on a bounded worker pool. A qualifying group over the 250-file ceiling is refused instead of becoming a book with no files.
- Filename fallback (both `metadata.extractFromFilename` and the scanner's `extractInfoFromPath`): a `X - Y` name with no parseable author no longer records `X` as a series. A chapter-only name such as `Eldest/98.mp3` now takes its title from the folder and its author from the folder above, where it used to give title "98" and author "Eldest".
