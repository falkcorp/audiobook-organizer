### Fixed

- A profile save or password change that core refuses with a validation error (422) now shows the field message core gave, with no "ApiError:" prefix, instead of "Unprocessable Entity". The same fallback (detail, then the first field message, then the title) applies to every identity call.
- First-run setup from a machine other than the host works from the sign-in page: its setup mode now has the bootstrap-token field the Setup page already had. A wrong, expired or spent token (401 `bootstrap_invalid`) and a closed setup (403 `setup_closed`) each get their own message on both pages; the Setup page no longer says "requires a login" for a wrong token.
- The Users page Created column shows each account's creation date again.
- The pending-invite list and invite revoke work with authentication off: they go through the books routes (`/api/v1/users/invites`), which admit what HEAD admitted, instead of core's native routes, whose 401 under auth-off signed the admin out. The table shows "Sent <time>" once an invitation email has gone out, as before. Nothing new is allowed: the routes are the ones HEAD had, and the invite link column stays gone (core keeps no tokens).
- With authentication off the Users page hides deactivate, reactivate and reset-password, and the Settings temp-login tab hides its picker and Generate button, rather than offering what core refuses; invite create and resend stay visible, disabled, under "Turn on sign-in to do this".
- The account list and the role list read every page from core instead of the first 1000, so a library with more than 1000 accounts no longer silently loses the rest.
