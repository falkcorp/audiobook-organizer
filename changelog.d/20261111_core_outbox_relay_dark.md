### Added

- core/outbox: the core outbox relay (F6-01), built dark. A producer stages a message into its own write batch (`outbox.Stage`), so the message and the producer's change commit together or not at all; the relay turns staged messages into per-topic, per-partition sequences in commit order, then delivers each to its consumers at least once, with bounded retry and backoff, dead letters an operator can retry or discard, and a retained backlog for a disabled module's consumers. Module consumers are task runs (`ConsumeIntoTask`), staged in the same batch as the cursor advance; plain, transactional and raw handlers are core's alone, refused for a module at registration and by a new archtest (`OutboxModuleConsumersAreTasks`). Delivery stops, loudly and without skipping, on a record it cannot read (a newer build's, or a corrupt one) and on a topic whose declared partition count no longer matches the one its messages were spread over; neither the log nor the health detail quotes the rejected value. An orphan consumer's cursors expire a full grace period after the first sweep that saw them unclaimed, not after their last touch. A run start that folds into an existing run is counted (`mediacore_outbox_folded_total`) and logged. The package has no caller yet: the storage owner, `Manifest.OutboxConsumers` and `Deps.Outbox` arrive with F6-03, so a boot is unchanged. Adds `events.TopicSpec.PayloadType()`.
