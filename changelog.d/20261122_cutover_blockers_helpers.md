### Added

- Two root-owned rollback helpers, `cutover-blockers-list` and `cutover-blockers-apply`, run the R2 runbook's Step 0 offline command (`storage cutover-blockers list`, `fix`, `delete`) without raw `sudo`. Each takes no arguments and is granted in the sudoers drop-in with `""` (exactly two new lines, no wildcard). Both refuse unless the service unit is already `inactive` and never stop or start it. `list` leaves the printed list and, when something blocks, the rows file in `export_dir`; `apply` reads one fixed-name request file from `export_dir` (one `fix` or one `delete`, strictly parsed), runs the command as the service user, writes the printed result to `export_dir`, and deletes the request only after a success.
- `make cutover-blockers-list` and `make cutover-blockers-apply REQUEST=<file>` run the helpers from the Mac and copy the files with size and sha256 checks.
- Owner scripts in `deploy/owner/` (copied to `~/aorg-owner/` on the server): `cutover-blockers-list.sh`, `cutover-blockers-apply.sh`, `service-stop.sh`, `service-start.sh`, `r2-p6-reinstall.sh` and `r2-p6-undo.sh`. Each has a `--dry-run` and exits non-zero on failure.
- `make service-stop` and `make service-start` (and the owner's `service-stop.sh` and `service-start.sh`) stop or start only the service through the `systemctl stop|start` lines the sudoers drop-in already grants, so no sudoers line is added. Each checks the state first, runs that one command, and waits until the unit is `inactive` or `active`.
- `cutover-blockers-apply` prints `NOT-RUN` and exits 4 when it refuses before its unit started (a request that does not parse, a service that is not inactive, a bad `export_dir`). The owner script and the Mac recipe then remove the request they placed, so a refused request no longer blocks the next run. The owner script also parses the request with the installed helper's own parser before placing it, clears leftovers of an interrupted placement, and offers to delete the owner's copy of the request after a success.
- `r2-p6-reinstall.sh` saves the pre-P6 state once in `~/aorg-owner/p6-before/` (the installed helper's sha256, `rollback.conf`, `sudo -n -l`). `r2-p6-undo.sh` refuses unless its checkout's helper has that hash, diffs `rollback.conf` against the saved copy, and fails when `sudo -n -l` prints nothing or no `restore-offline` line.

### Changed

- The R2 cutover runbook's P6 and Step 0 now name the owner scripts instead of commands to type, and Known gap 2 becomes the open question of whether the pre-freeze binary has `storage cutover-blockers`, and a new Known gap 5 records that a Step 0 `delete` has no tracked undo before Step 4 (an archive restore that keeps the current binary is not built). Step 0 now takes a restore point first and stops and starts the service with the new scripts. The sudoers block and the helper table in `docs/system/deploy-and-gpu-ops.md` list the two new helpers. The owner must reinstall the helper bundle (`bash ~/aorg-owner/r2-p6-reinstall.sh`) to get the new stubs and sudoers lines.
