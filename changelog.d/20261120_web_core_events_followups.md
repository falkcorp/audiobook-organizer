### Fixed

- The event stream client's waits (`web/src/services/coreEvents`, still unwired) no longer outlive a sleep. `performance.now()` does not advance while a laptop sleeps on macOS Chrome and Safari, so a 10 minute `Retry-After` recorded before the lid closed was still standing 10 minutes after the wake, and the old comment's claim that a resumed laptop moves no deadline was wrong. The deadlines are now read on an awake clock (`clock.ts`: `performance.now()` plus the time the wall clock ran ahead of it), which never goes back and counts a sleep as elapsed. A reopened hidden tab re-reads it, and a stream waiting on a timer is woken by the browser's `online` event (`VisibilitySource.onResume`) to re-read it. Holds are never dropped: a `Retry-After` that has not really elapsed still holds through tab flips and `online`. A wall-clock step forward cannot be told from a sleep, so it can end a wait early; a step back never stretches one.
- `clear()` called from inside a book-change batch handler (the consumer issued its refetch from `onBatch`) now also drops the rest of the flush that is delivering, which the refetch covers; changes added afterwards still open a new window.
- The e2e `mockCoreEvents(page)` is safe to call twice on one Page, as `scan-import-organize.spec.ts` and `setup-modes.spec.ts` do through `mockEventSource`: later calls, even a racing one, return the first handle and install nothing, a call that names different options throws, and a setup that failed stays failed for every later call instead of adding a second init script.
- Tests: the reopen resync tests now include a reset that arrives a moment after the open, which only the coalescing window merges; before, they also passed with a window of 0.
