### Fixed

- AI call metrics review follow-ups (PR #3948 round 1). A call whose deadline or cancellation arrives while the SDK is waiting to retry a 429 or 5xx is now counted as the throttle it was: one `error` request, an `ai_failures_total` reason of `rate_limit` (or the response's own reason), and the attempt's own duration, instead of a `timeout` or `canceled` request whose duration included the backoff sleep. The trace span carries the same classification. The span's `ai.model` attribute now holds the real model name; only the metric label is capped at five models. The scan batch phase's five-second back-off after a failed batch now ends early when the phase is cancelled or aborted, instead of holding the worker for the full wait. The batch-parse result tests now pin that the batch-size setting really cuts several batches that run concurrently, and the cancelled-first-call case really cancels. The dashboard description for "Tokens per accepted batch parse" names batch parse, and the attempt-recording middleware is documented as being on the parser clients only.
