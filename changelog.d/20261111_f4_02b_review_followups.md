### Fixed

- core auth (F4-02b review follow-ups, dark): consuming a plain temp-login link now guards the target's user row in its batch, so a promotion or disable that commits between the consume's read and its commit conflicts the commit and the retry re-runs the creator and dominance checks on the new roles (before, such a link opened a session for a target its creator no longer dominated). Minting a restriction-lifting reset link as an owner-assured actor is refused (`ErrDenied`) while `core.auth.owner.required` is off, since consuming it would always be refused. `SetStatus`'s disable now records `links_deleted` in its audit detail. `BootWrites` with bootstrap enabled and no state filesystem now deletes bootstrap tokens stored by an earlier boot before deciding whether it can mint, so a stale token never outlives a restart. `core.auth.bootstrap.enabled=false` together with `core.auth.setup_requires_token=true` makes first-run Setup unreachable; this is documented on the `Settings` fields and in the F4-02 seams, behaviour unchanged.
