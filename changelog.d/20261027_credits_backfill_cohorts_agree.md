### Fixed

- `maintenance.credits-backfill` dry runs, cohorts and a single full apply now agree. A book whose only unknown narrator names come from splitting its credit is re-evaluated after the first pass with every name another eligible book credits whole (unsplit) counted as existing, so the dry run lists it as a fill instead of `narrator_new_from_split` and the apply writes it. A split credit never creates a record without `allow`: it only links to a record another book creates. Within a `limit` or `book_ids` cohort that leaves that book out, the split book waits (`narrator_waiting_on_creator`, informational, no `limit` place used) and is written in the cohort that creates the record or a later one. The spelling settle runs to a fixpoint over the creating books that survive it, so a split book left without one goes back to `narrator_new_from_split`. At apply time the books that create records are written first, and a split book links only to a record whose creating write landed: a creator that fails, is locked, changed since the plan or refused at apply time sends its dependents back to `narrator_new_from_split`, unwritten. A `book_ids` run plans the whole library and only reports and writes its own books, so the spelling a new narrator record gets is counted over every eligible book exactly as in a full run, and books it names that no longer exist count as gone. The earlier caveats that cohorts differ from one full run no longer apply.
- The narrator respell lands on the right place. In the stored narrator list only the entry that names the person is respelled, preferring the exact entry over the whole list, so "Jean Paul Valley Jr." beside "Jean Paul Valley" no longer sends the book to review. In the narrator field the credit that is the name is respelled (a credit that carries a role, such as "Harvey Dent - translator", is skipped; a leading "Read by" is only a prefix the cleaner strips), and every credit of the same person is respelled, whatever its case.
- When two spellings of one new narrator tie on count, the record takes a mixed-case spelling, then an accented one, then the lexically smallest. `narrator_column_respelled` is listed only when the field text actually changed.
- An apply-time refusal of a narrator spelling no longer drops the book's author write, and the narrator records created for that refused fill are not counted as created.
- A book whose author id is missing from its join is held as `author_id_duplicate_name_in_join` when a join entry has the same name under another accent ("Renee" and "Renée"), where it was reported as a snapshot conflict.
- Repair plan rows now live under their own `plan/` row prefix. Storing or clearing a repair plan no longer deletes the operation's class-list rows (`ReplaceOpRows` with an empty prefix removed every row of the operation, so `ReplaceOpRows` is gone and `ReplaceOpRowsPrefix` refuses an empty prefix), and the handler test's in-memory row store enforces the prefix like the real one. Plans stored before this change are in the old row layout and are refused as legacy: re-run the repair to get a new plan (cut over, no backward compatibility).
- A canceled or failed run no longer drops the books it had parked for a split credit from every class: they are filed under `narrator_new_from_split` as the first pass left them. A `book_ids` run no longer lists an unreadable book outside its ids under `read_error`; the run stays incomplete and `out_of_scope_read_errors` counts them.
- An apply-time spelling refusal no longer leaves a narrator record nobody can find: the book's journal row names it when the book still has an author write, and the result reports every created record no written book credits as `narrators_created_unused` with `unused_narrator_names` (`maintenance.purge-empty-narrators` removes empty ones).
