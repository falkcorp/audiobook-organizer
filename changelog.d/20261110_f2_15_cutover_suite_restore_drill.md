### Added

- ci: the R2 cutover suite and restore drill (F2-15). `internal/books/cutover_suite_test.go` holds `TestCutoverOnR0Corpus`, `TestCutoverPreservesIDsAndReferences` and `TestCutoverLeavesOtherFamiliesByteIdentical`, which run on three corpora: the committed R0 corpus, a copy the pre-freeze release's binary booted and wrote a user, an API key, a setting change and a library scan into (`scripts/r2corpus/write_prefreeze_rows.py`), and F2-14's production-shaped store. They check each cutover step's counts against an independent scan, the quarantine report against the overlay's quarantine cases, every user, role, key, OAuth identity, import root and run ID, every reference to those IDs, that every books family outside the shared-family list is byte for byte the same, and that the legacy bookkeeping rows only grow (no ledger row deleted or rewritten, the schema version and the preference counter never go back). The list is generated (`scripts/ci/gen_shared_family_lists.py` into `internal/books/testdata/shared_families.golden`, checked in CI). `internal/books/restore_drill_test.go` holds `TestRollbackRestoreBootsPreviousBuild`, which restores the pre-migration checkpoint and a legacy archive with the build's own `storage restore-offline` and boots the pre-freeze binary on the result, plus a selftest that proves each check fails on a misbehaving fake step. A new `r2-cutover-suite` job (two shards) runs them in `extraction-gates`, `production-shaped-store` runs the `/shaped` subtests, and `scripts/ci/fetch_prefreeze_binary.sh` fetches the pre-freeze release's archive, refuses it unless its SHA-256 matches the release's `checksums.txt`, and extracts the binary. Only that job sets `R2_CUTOVER_STRICT=1`, which turns a missing pre-freeze binary from a skip into a failure. No cutover step is registered yet: the suite reads the module manifest's `Cutover` field and the `Cutover` flag of each `DataMigrations` entry, and fails on any step it finds (or a shape it cannot read) until F3-07 wires the real steps in.
