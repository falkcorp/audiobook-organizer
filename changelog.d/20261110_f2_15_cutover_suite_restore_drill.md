### Added

- ci: the R2 cutover suite and restore drill (F2-15). `internal/books/cutover_suite_test.go` holds `TestCutoverOnR0Corpus`, `TestCutoverPreservesIDsAndReferences` and `TestCutoverLeavesOtherFamiliesByteIdentical`, which run on three corpora: the committed R0 corpus, a copy the pre-freeze release's binary booted and wrote a user, an API key, a setting change and a library scan into (`scripts/r2corpus/write_prefreeze_rows.py`), and F2-14's production-shaped store. They check each cutover step's counts against an independent scan, the quarantine report against the overlay's quarantine cases, every user, role, key, OAuth identity, import root and run ID, every reference to those IDs, and that every books family outside the shared-family list is byte for byte the same. The list is generated (`scripts/ci/gen_shared_family_lists.py` into `internal/books/testdata/shared_families.golden`, checked in CI). `internal/books/restore_drill_test.go` holds `TestRollbackRestoreBootsPreviousBuild`, which restores the pre-migration checkpoint and a legacy archive with the build's own `storage restore-offline` and boots the pre-freeze binary on the result, plus a selftest that proves each check fails on a misbehaving fake step. A new `r2-cutover-suite` job (two shards) runs them in `extraction-gates`, `production-shaped-store` runs the `/shaped` subtests, and `scripts/ci/fetch_prefreeze_binary.sh` fetches the pre-freeze binary. No cutover step is registered yet: the suite enumerates them from the module manifest and fails until F3-07 wires the real steps in.
