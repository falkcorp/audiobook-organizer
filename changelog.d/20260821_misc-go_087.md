### Changed

#### `serviceregistry` — typed accessors for the config and event-bus services (ARCH-8)

`serviceregistry.Get[T](c, name)` lets a caller pick both the string key and the
return type `T` independently at each call site; a typo'd key or a mismatched
`T` only surfaces as a runtime panic. Added `config.GetConfig(c)` and
`plugin.GetEventBus(c)` — thin, named wrappers that fix the key and the return
type in the function signature — for the two services used with a single
consistent type across many builders (config: 15 call sites across 9 files;
eventbus: 3 call sites, an always-built "core"-group leaf with no
dependencies). Now a typo'd key name or a wrong return type is a compile error
at the call site instead of a runtime panic. Updated all 18 call sites (12
files) to use the new accessors. Left `serviceregistry.Get[T](c,
serviceregistry.KeyStore)` untouched: that key is deliberately used with
~15 different narrowed interface types across consumers (the earlier
store-decoupling work), so a single typed accessor can't serve it without
forcing callers back onto one wide interface. What happens when a service is
genuinely missing or undeclared in a builder's `Needs` is unchanged — both new
accessors still panic, exactly as `Get[T]` did.
