### Added

- Books' integrations cutover step (M6), built dark: `internal/books/cutover/m6` is a boot-blocking one-way data migration that moves what is left in the settings blob and HEAD's own rows onto the native stores. The metadata sources, AI endpoints, the Deluge Web UI and the webhook plugin become integrations instances (IDs kept, a core-invalid ID renamed and reported, secrets carried by reference, trust and secret origins carried over); the AI jobs, with their payload and batch-index rows, become native jobs in every state (a job whose type has no capability is imported failed, never open); the webhook plugin's events become one notification rule; `root_dir`, the import paths, path aliases, iTunes path mappings and protected paths become library roots and mappings in config, with each import path's scan state kept in `rootscan:` rows; the provider daily-budget and throttle rows and the search dirty set are dropped by rule. A row the step cannot convert is quarantined with its raw bytes instead of being overwritten or dropped, an unreadable secret keeps its instance, a separate `m6.Plan` function reports the plan per kind and writes nothing (it never goes through the runner, so a real boot after it still steps every row), trust is signed from the effective destinations (the stored URL with the operator's environment or config-file value applied, which for Deluge is also the instance's URL), a refused config list quarantines the rows that fed it, a renamed metadata source keeps its credentials, and a re-run is a no-op. The step is not registered yet (F7-09 registers it), so nothing changes for a running install.
