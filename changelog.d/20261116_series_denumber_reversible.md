### Changed

- The series de-numbering operation can now be undone. Every book it moves, every base series it creates and every numbered series it deletes is written to the operation's change log first, and reverting the operation puts the numbered series back under its own id with its books and positions as they were. An apply refuses to start if the run has no operation id or the store cannot restore a series.
- The operation no longer creates a base series for a plan that moves no book, and reports numbered series that hold no books at all as their own count (the empty-series cleanup removes them; this operation does not).
- A book is never moved onto a position another book already holds, never given a position over one it already has, and books from different numbered series that land on one position are all held back, each with a reason in the report.
- The apply set is now defined by what is accepted, not by a list of what is refused. A series is applied only when its name reads as a base, a separator, an optional marker (Book, Bk, Vol, Volume, No or #) and a number from 1 to 99, with no digit, connector (of, to, and, &), part, format, edition or volume word anywhere in the base, a base of at least three letters that is not an author's name or a part of the series' own author's name (surname alone, given name alone, name without initials; inverted, composite and accent-variant spellings), and a series that has an existing author. The number must also be corroborated, and only one thing corroborates it: a run of at least three series of the same author and base, numbered consecutively, in which every series holds exactly one distinct book, every book has a title of its own that differs from the base name and from the other members' titles, and no two members share an ASIN or ISBN. A book's own stored position never corroborates (the importer copies it from the name); a stored position that disagrees with the name still holds the book. One failing member holds the whole run as sibling_run_rejected. A numbered series that holds several distinct books is held whole as source_holds_multiple_books, never torn apart by position. Everything else is held with a named reason in the report, and a lone numbered series with no run is held as position_uncorroborated, counted in the summary like every other hold code.
- The medium confidence tier (bracketed positions) is report-only again: the `applyMedium` parameter is removed, and the low tier never applied.
- The apply honours the owner's series locks: a book whose series is locked is not moved, and a book whose position is locked is not given one, decided at planning and checked again inside the book write. A book whose locks cannot be read is held.
- The apply takes the scan stand-down for the whole run and stops if the lease lapses. An emptied numbered series is deleted with a new store operation, `DeleteSeriesIfUnreferenced`, that counts the book rows referencing it (live, trashed and secondary versions) and deletes it while holding every book write lock, so no book can be written into the series between the count and the delete; the operation also passes the name and author it journaled and the store compares them under its lock; a series that gained a book, was renamed, or was held by a repair in that window is kept and reported as kept, and a store that lacks the operation or cannot count refuses to apply or to delete.
- A base series is never created beside one of the same name under another author row, and a base series that already existed when the run went to create it is neither used nor recorded as created by the run.
- The change log is truthful about failures: the rows of a write that failed are voided so a revert never acts on them, the base is re-checked inside the book write, a cancelled apply still refreshes the series lists and writes its outcome report, a run with failed writes ends in an error instead of plain success, and an apply requires `reportPath`.
- New parameters `minBooks`, `baseName` and a `limit` that counts only plans that move a book, so a first apply can start on one visible series. The report lists every book decision, and an applied run writes its outcomes next to it.
- Part and format words (ch, ep, episode, disc, cd, side, reel, hour) and the short volume words (v, t, bd, nr, vols) are now read in both the series-name grammar and the planner's trailing-word check, and the volume-word check looks at every word of the base, not only the last. A decomposed (NFD) spelling of an accented base is read as the same name as the composed one.
- At apply time the base is read again, live and trashed books, before the first write into it, and the plan is skipped if a book took the position since planning or a row only the count can see appeared. The emptied series is deleted only if its name and author are unchanged and no other repair holds it since the plan; the undo snapshot is the row read at delete time. A skipped book never splits one book's versions across two series. A nil scan controller refuses the apply. A base name with repeated spaces is created with them collapsed, and an author id with no author row is held as no_author.
- Journaling order, unchanged but now stated: the `series_create` row is written after the base was really created by this run and before any book moves into it; each book's `series_id` (and `series_sequence`) rows are written before the book is; the `series_row_delete` row is written before the delete. A row whose write then failed is voided so a revert never acts on it.

- Reverting a de-numbering operation deletes the base series it created with the same check-and-delete (`DeleteSeriesIfUnreferenced`) instead of counting its books and then deleting: a book linked into the series between the two no longer ends up naming a deleted series. A created series that is referenced, renamed, held or already gone is kept and reported (`series_kept` in the revert result, one note per series in `kept`), and a store without the operation fails that row closed.
- The de-numbering operation now declares that it writes books and series, so the dispatcher does not run it beside the series prune, merge, normalize, rename or repairs-apply operations (a dry run holds the same set). The maintenance jobs, cleanup-series included, are not gated this way (they register without a write set), so do not run cleanup-series while this operation runs (it guards its own book writes and its series delete against a concurrent writer, but the two can still reach the same series from reads taken at different times, and the dispatcher cannot hold one back for the other). Its dry run reports how many emptied series it would delete, and the apply summary reconciles with that number: deleted, kept at delete time, already deleted by someone else, or not emptied or skipped before the delete.
- An emptied numbered series that someone else deleted before the apply reached it keeps its undo row live (journaled from the planned row when it was gone before the re-read), so reverting the operation recreates it and puts its books back; a failed void of an undo row and an undo row that could not be written are counted as failures and reported.
- The cleanup-series maintenance job now writes compare-and-set: its single-book unlink and its duplicate-series re-home skip a book whose series is no longer the one being cleaned (another writer moved it after the job read the series membership), count it as skipped and say so in the job log. Before, the unlink cleared the series of a book that had just been moved elsewhere and the re-home pulled it onto the kept series. Its series delete was still the unconditional one when this entry was written; the later "cleanup-series no longer deletes a series row unconditionally" entry under Fixed makes it conditional.
- Reverting a de-numbering operation no longer reports a created base series as kept while a book the operation itself moved into it is still there because that book's own undo row failed or was refused: the series_create row stays owed, so a retry removes the series once the book is back. The revert summary now says why a series was kept (a book the operation did not move still references it, it was renamed, held or already deleted).
- The de-numbering apply summary counts an emptied series not deleted because a read or write failed apart from one not deleted because a book or a change appeared since the plan.

### Added

- Undo support for series rows: change types `series_create` and `series_row_delete`, and a store capability that recreates a deleted series under its original id.
- Reverting a de-numbering operation (or any operation that restored a series row or a book's series link) now refreshes the series lists at once instead of after the cache expires.
