### Changed

- The series de-numbering operation can now be undone. Every book it moves, every base series it creates and every numbered series it deletes is written to the operation's change log first, and reverting the operation puts the numbered series back under its own id with its books and positions as they were. An apply refuses to start if the run has no operation id or the store cannot restore a series.
- The operation no longer creates a base series for a plan that moves no book, and reports numbered series that hold no books at all as their own count (the empty-series cleanup removes them; this operation does not).
- A book is never moved onto a position another book already holds, never given a position over one it already has, and books from different numbered series that land on one position are all held back, each with a reason in the report.
- The apply set is now defined by what is accepted, not by a list of what is refused. A series is applied only when its name reads as a base, a separator, an optional marker (Book, Bk, Vol, Volume, No or #) and a number from 1 to 99, with no digit, connector (of, to, and, &), part, format, edition or volume word in the base, a base of at least three letters that is not an author's name (checked across inverted, composite and accent-variant spellings), and a series that has an author. The number must also be corroborated: the book already holds that position, or the same author has at least two other series of the same base, each with a book, that make a run of three consecutive numbers with it. Everything else is held with a named reason in the report, and a lone numbered series with no such evidence is held as position_uncorroborated.
- The medium confidence tier (bracketed positions) is report-only again: the `applyMedium` parameter is removed, and the low tier never applied.
- The apply honours the owner's series locks: a book whose series is locked is not moved, and a book whose position is locked is not given one, decided at planning and checked again inside the book write. A book whose locks cannot be read is held.
- The apply takes the scan stand-down for the whole run and stops if the lease lapses. Before deleting an emptied numbered series it counts the book rows that reference it once more and keeps the series if any appeared since planning; a store that cannot count them refuses to apply.
- A base series is never created beside one of the same name under another author row, and a base series that already existed when the run went to create it is neither used nor recorded as created by the run.
- The change log is truthful about failures: the rows of a write that failed are voided so a revert never acts on them, the base is re-checked inside the book write, a cancelled apply still refreshes the series lists and writes its outcome report, a run with failed writes ends in an error instead of plain success, and an apply requires `reportPath`.
- New parameters `minBooks`, `baseName` and a `limit` that counts only plans that move a book, so a first apply can start on one visible series. The report lists every book decision, and an applied run writes its outcomes next to it.

### Added

- Undo support for series rows: change types `series_create` and `series_row_delete`, and a store capability that recreates a deleted series under its original id.
- Reverting a de-numbering operation (or any operation that restored a series row or a book's series link) now refreshes the series lists at once instead of after the cache expires.
