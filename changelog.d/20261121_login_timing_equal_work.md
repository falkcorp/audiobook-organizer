### Security

- A failed sign-in no longer takes a different amount of time depending on what the username belongs to. Every password check on the web sign-in, the Audiobookshelf-app `/login` and core's sign-in now does the same work: one argon2id derivation and one bcrypt comparison. Each runs against the stored hash when it is of that kind and against a dummy otherwise. Before this, an account whose password was still a legacy bcrypt hash, or whose stored hash did not parse, answered at a different speed from an unknown name, which told a caller the name existed. A bcrypt check now also waits for the same hashing slot as an argon2id one, so a busy server refuses both alike. The web sign-in now re-stores a verified bcrypt password as argon2id, as the app sign-in already did, so the bcrypt rows drain. Each start logs how many remain (a count, no names). The Audiobookshelf login timing test no longer fails on a loaded machine. It compares each case's fastest time over 25 rotated rounds instead of the median of five pairs, and a new structural test counts each path's work.
