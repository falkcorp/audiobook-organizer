### Changed

- Deploy waits on the systemd unit and reports exit 78 by name; the unit no longer restarts on exit 78 and stops within 60 s; `make rollback-restore` for releases that change the store.
- `make rollback` refuses when the store is at a level the previous binary cannot read (`<db>.storage-levels` against `.prev --print-storage-levels`), when a checkpoint pointer exists without a levels file, and while a restore or reset swap is in flight.
- Every privileged deploy and rollback step runs through root-owned helpers in `deploy/rollback-helpers/` that validate their own arguments and read their paths from `/etc/audiobook-organizer/rollback.conf`; the sudoers drop-in grants only those helpers and fixed commands, with no wildcards, no `tee` and no free `cp` into `/etc/systemd/system`. `Makefile.local.example`'s `deploy` installs the binary (atomically, keeping `.prev`), the unit and `deploy/local.conf` through `install-staged`, which never installs uploaded text as a unit file: the unit is copied from the root-owned helper bundle, and the `local.conf` drop-in is re-rendered from the staged file's one-assignment `Environment=` lines, refusing any other setting (so a deploy cannot set `User=root` or `ExecStartPre=`). Staged files are opened with no symlink in any path component and must be regular, singly linked and owned by the deploy user. `deploy/local.conf` now holds `Environment=` lines only: `ExecStart=`, `TimeoutStopSec=` and other host settings move to a root-installed `host.conf` drop-in (owner migration); `install-staged unit` and `install-staged local-conf` refuse, before copying anything, unless that `host.conf` exists as a root-owned regular file, not group- or other-writable, running nothing but the service user's `ExecStart=`, so the service can never restart on the base unit's command line. The same rules apply to every drop-in systemd will apply to the unit (`systemctl show -p DropInPaths` plus a scan of every unit directory, including the dash-prefix and type-wide `service.d` directories) and to the unit template and the unit's main file wherever systemd finds it (`FragmentPath`, refusing a generated unit or one outside the unit directories, plus every copy in them), and `local.conf` refuses loader and runtime-injection variables (`LD_*`, `MALLOC_*`, `PYTHON*`, `PERL5*`, `GCONV_PATH`, `GLIBC_TUNABLES`, `GODEBUG`, `NODE_OPTIONS`, `SSL_CERT_*`, `LOCPATH` and others). Unit files and drop-ins are read as systemd joins their lines (odd trailing backslashes continue, comments inside a continuation are skipped), `ExecStart=` may carry only the `@`, `-` and `:` prefixes, and drop-in directories of the unit's aliases are checked too. `deploy-debug` and `pprof-off` switch the pprof drop-in through `pprof on|off`; the storage-format sidecar files are read as the service user, and refusals print a length and hash in place of file contents; `deploy-debug` and `pprof-off` switch the pprof drop-in through `pprof on|off`. The documented drop-in is rendered by `scripts/storage_format_guard.py sudoers`, and tests check every `sudo` the deploy and rollback recipes run against it. `make deploy`, `make deploy-debug`, `make rollback`, `make rollback-restore` and `scripts/deploy-match-unit-type.sh` need the helpers installed (owner action).
- `make deploy`, `make deploy-debug` and both rollbacks wait `DEPLOY_READY_TIMEOUT` seconds (default 300) after the unit leaves `activating`, and refuse to report ready until the unit's `InvocationID` differs from the one read before the restart, so a restart that never ran no longer passes. `scripts/deploy-wait-ready.sh` without an ssh host waits at least `DEPLOY_READY_URL_TIMEOUT` seconds (default 1800).
- Rollbacks install `.prev` atomically, match the unit type before stopping the service, run the restore as the service user in a transient unit that survives an ssh drop and writes its own exit status into a log the deploy user can read without `sudo` (appended, never truncated; a second restore refuses while one is still running, before anything is stopped), and print the host's state and the commands that finish or undo the rollback when a step fails. `ROLLBACK_ARCHIVE` is a file name in the helpers' `archive_dir`.
- `storage restore-offline --into <dir>` writes the copy's own `<dir>.storage-levels` beside it.
