### Fixed

- Organizing a book in a protected folder (import or iTunes) that already has a library copy no longer fails with "duplicate file already organized". The organize preview and the organize action now resolve such a book to its existing library copy through the same lookup the metadata apply uses, so both act on the same row and show the same target. When the copy is already at its target, organize reports "already organized". The organizer no longer treats a book's own library copy (same file hash, same version group) as a duplicate: it declines with a 409 naming the copy, and never writes a second copy. The organize collision hook also skips pairs that share a version group, so it can no longer file a dedup candidate pairing a book with its own copy. A true duplicate on a different row is still refused and still reported to the dedup queue.
