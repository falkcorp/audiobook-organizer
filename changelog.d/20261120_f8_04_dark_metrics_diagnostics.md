### Added

#### Dark diagnostics prune task, `/metrics` mount and diagnostics adapters (F8-04 A3-A5)

Three pieces the F8-04 fold will wire, none of them reachable yet. `diagnostics.PruneTask` builds the `core.diagnostics.prune` task, which runs on the existing `core.diagnostics.schedules.prune` schedule and deletes finished diagnostics bundles older than `core.diagnostics.retention` (a zero or negative retention means the 24 hour default, and a bundle exactly at the edge is kept). `diagnostics.Prune` now treats a non-positive retention as the default too, instead of deleting every bundle. The kernel gains `mountMetrics`, which mounts the metrics handler as an infra route requiring `core:metrics.read` and registers the `<namespace>_build_info{version}` gauge only when it runs, so today's scrape is unchanged. It also gains the adapters that the diagnostics exporter and its HTTP routes take: the run-actor viewer, which compiles the person's current roles and grants the interactive checker only to a browser session, so an administrator's API key never reaches a sensitive scope; the export enqueuer; the run reader; and the route-pattern list. Nothing registers the task or calls the mount or the adapters yet.
