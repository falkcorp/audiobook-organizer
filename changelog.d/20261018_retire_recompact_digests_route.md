Three operator routes are retired: `POST /api/v1/admin/recompact-digests`, `POST /api/v1/cache/invalidate` and `POST /api/v1/activity/clamp-summaries`. Nothing in the web app, scripts or the AudioBooth client called them. They now answer 410 Gone for one release, behind the same admin or settings permission checks as before, so an unauthenticated caller still gets 401 and a caller without permission 403. Digest recompaction has a replacement: start the "Recompact activity digests" background operation with `POST /api/v1/operations/v2` and `{"def_id":"maintenance.recompact-activity-digests"}`, which the old route only did on your behalf. Flushing the in-memory caches has no replacement and now takes a restart (filed as a TODO item). The clamp route's job, shrinking oversized old activity summaries, already ran to completion in production and the write-time cap remains, so the retroactive clamp pass is deleted. Giving freed activity-database pages back to the disk is kept, as a new background operation, "Vacuum activity database" (`maintenance.vacuum-activity-db`), instead of a route. Started with no parameters it is a preview: it reports the file size, WAL size, page count, free-page count and an estimate of the reclaimable bytes, and writes nothing. With `dry_run=false` it runs the VACUUM, then truncates the WAL, and reports the bytes actually returned. It needs the same permission as the other activity maintenance operations (settings.manage), never runs beside activity compaction or reclaim, and is not scheduled. VACUUM needs roughly the database's size in free disk space while it runs, so check the preview first. The route handlers and tests are deleted, along with the code only they reached: the cache flush helpers, the activity service's clamp call and the SQLite store's clamp pass. No `database.Store` methods were removed, because all of this lived on the activity store.
