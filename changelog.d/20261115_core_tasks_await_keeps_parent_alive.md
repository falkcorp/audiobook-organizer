### Fixed

#### `core/tasks` — a parent waiting in `rc.Await` is no longer stopped by the watchdog

`rc.Await` was documented as relaying the child's liveness to the waiting run, but the executor's `await` never stamped the parent's liveness. A Task that enqueued a child and waited on it went silent, the watchdog struck it once it passed its `ProgressTimeout` and stopped it as a cancel, and a cancelled run is never resumed. Any kind whose watchdog limit was shorter than its longest child was affected (the scheduler's maintenance-window run is the production caller). While the child is queued, waiting on its dependencies, running or stopping, `await` now stamps the parent's liveness three times per `ProgressTimeout` from the waiting goroutine itself (in memory, no store write, no extra goroutine), so the stamps end with the wait. The stamp is liveness only: it is not progress for `ErrContinueInPlace` and does not mark the run as having reported. A child that needs a restart, a released stand-down hold or a decision does not keep the parent alive. The wait is still bounded by the parent's own `Timeout`, and the child's own watchdog still stops a stalled child, which ends the wait. `await` also returns the stop's cause (cancel or timeout) rather than a bare context error when its run read loses a race with the stop, and the `rc.Await` doc comment now states the behaviour as implemented.
