### Added

- core: `core/auth/oidc` (dark), core's generic OIDC and OAuth2 sign-in of 05-authn 4.7. Providers are a list: an `oidc` kind discovered through go-oidc from its issuer (id_token signature, issuer, audience and expiry checked, and the id_token must echo the nonce the flow sent) and a `github` kind. Every provider gets PKCE S256, which HEAD's GitHub flow never had. The state is signed (HMAC-SHA256) with a key derived from the secrets store under `mediacore/auth/oidc-state/v1`, lasts 10 minutes, is bound to its provider and to the browser's cookie, and is spent before the code exchange, so a replay never reaches the provider. For a native-app sign-in the state also carries the app's `redirect_uri`, S256 `code_challenge` and state: the `redirect_uri` is accepted only when the module's hand-off lists it exactly (plain absolute URI, no userinfo, fragment, whitespace, control character or backslash), a `plain` or missing method is refused, and the location the hand-off's `Mint` returns must stay on the same scheme, host and path before any browser is sent there; no web session is opened on that branch. Sign-in links by (provider, subject), never by e-mail. An unseen subject takes an existing account by e-mail only when the provider is trusted (`link_existing_by_email`), the account's address is one we verified, and the account holds no `core:admin` and has no password; otherwise the sign-in is refused with `email_in_use`. Unverified holders of the address lose it to a verified sign-in under the same guard, audited as `core.identity.displace` without the address. Admission is by the provider's allowed addresses and domains, an invite, or the `ExtraAllowed` hook, failing closed. The default role may not grant `core:admin`. No token, code, id_token or client secret reaches an error text or a log line, and `ProviderConfig` renders without its secret. `auth.Service` gains `LockEmails` and `NoteUserCreated` so the resolver takes the same e-mail lock as `CreateUser`. go-oidc v3.21.0, oauth2 v0.37.0 and go-jose v4.1.6 join `core/go.mod` at the versions the root module resolves. Nothing serves the routes until F4-05 and nothing registers anything until F4-08.
- core: an identity extension may now report that it could not decide. `auth.ErrExtensionUnavailable` from an `Authenticator` makes stage 12 open to the next method, log a warning naming the extension (never the error text) and count `mediacore_auth_extension_errors_total{extension}`; any other extension error is still a refusal and a store failure is still 503 `auth_unavailable`. This is 05-authn section 6's "extension authenticator internal error" row, which F4-02b had left open for want of a sentinel.
- `internal/cfaccess` gains `Extension`, Cloudflare Access as an `auth.Extension` (method `ext:cfaccess`, Interactive, OwnerVerifier, `OwnerSet` while an owner e-mail is configured, ordered between the API-key and session authenticators) for F4-08 to register. The verified Access JWT (header, else the `CF_Authorization` cookie) is the only identity; the unsigned e-mail and forwarding headers are never read. No token is no credential, a header token that does not verify is a 401 that nothing weaker can rescue (a bad `CF_Authorization` cookie, one of several of which is tried, falls through to the session authenticator), a service token (no e-mail) identifies nobody, and a failed key-set fetch (transport, non-200, a body that is not a key set) opens to the next method and grants nothing. The assertion's `Owner` is the verified JWT e-mail equal to the configured owner e-mail, its `AuthTime` is the token's `iat`, and it carries no scopes. Cloudflare's signing keys are now cached for an hour and refetched for an unknown kid at most once per 30 seconds with concurrent callers sharing one fetch (the previous remote key set fetched per unknown kid and never dropped a key), a redirect from the key URL is an outage and never followed, and a forged token under a cached kid is a 401 even while Cloudflare is down.
- core: `oidc.Resolver` remembers state-dependent refusals (not admitted, address held) for a minute per (provider, subject, address), so a refused identity costs one scan and one audit event per minute instead of the global e-mail lock and a scan per request; claims whose address is not plain ASCII, whose `azp` does not match, or whose discovery endpoints are not https are refused; failed sign-ins audit `core.auth.login` with a reason class; the native-app state is bounded so the binding cookie stays under 4 KB.

### Changed

- `internal/oauth` is gone. HEAD's OAuth state, providers and resolver now live in `internal/legacyoauth` unchanged (ABO's gin sign-in keeps its behaviour until F4-08 deletes them); the Cloudflare Access verifier, gin binder, service-token bouncer and owner-guard middleware moved into `internal/cfaccess`, with the binder taking the gin chain's three hooks instead of importing `internal/server/middleware`. The Access key-set fetch used by the gin binder now has a 10 second bound.
