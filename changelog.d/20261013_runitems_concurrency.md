- Five whole-library operations that ran on a single core now use a worker pool: the LSH fingerprint index backfill, both passes of the AcoustID reset (file clearing and candidate dropping), the Deluge centralize job and the Deluge path update. The two AcoustID ops size the pool to the CPU count; the two Deluge ops use 4 workers so the Deluge daemon is not flooded. Deluge centralize now records its resume position as the unbroken completed prefix, so a restart after out-of-order completion never skips a file. A new test, TestRunItemsCallsDeclareConcurrency, fails the build when a RunItems call omits Concurrency without a `// runitems:sequential <reason>` comment.
