### Changed

- The build embeds ci/prefreeze_release.txt and the pre-migration checkpoint records it as from_release, so a rollback names the release to reinstall (F3-07).
- The shipped deploy files (unit, both plists, local.conf.example, compose) set canonical ABO_* environment names; AUDIOBOOK_ROOT_DIR, which nothing read, is gone (F3-07).
- The app SDK gains `Manifest.Settings`, `Cutover` and `Rewrite`, `Importers` and `Deps.Secrets`, and P1 checks a module's settings paths and the one-M8 rule; no manifest declares any of them yet (F3-07).
- Core declares `core.ai.journal_retention` and `core.http.public_base_url`, the two keys the rename table named and no section declared. `public_base_url` is admin-protected, so a host that still sets the retired `PUBLIC_BASE_URL` is refused at boot once the flip lands (F3-07).
- The kernel builds the data-migration plan from every manifest's `DataMigrations` plus the steps its `Cutover` func returns, and registers the one `Rewrite` as the plan's last step (M8) with the swapper that serves it; a Cutover step's importers refuse until P4b binds them, so a step that runs early writes nowhere (F3-07).
- The kernel can boot the layered config store, the secret store and module settings behind one off-by-default switch (`Config.CoreConfigBoot`): P0 reads the file, environment and boot record, P4b opens the keyring before the migration list and binds the config and secrets importers and a sealing quarantine, P4d attaches the stored values, and `core.config` reports its health tokens. The audiobook organizer leaves the switch off, so its boot is unchanged (F3-07).
- `kernel.CoreKeys` is removed; the rename-table check for core's keys now reads a fixture the app's test generates (F3-07).
- `app.Options.CoreConfigBoot` carries that switch into the kernel; with it set the store path and state directory come from the config layers at P0, and every offline command and the keyring export resolve them through the same P0 (`kernel.ResolveStorage`), so serve and offline open one store (F3-07).
- The keyring and the config boot record are written through a labelled view of the state directory (`internal/statefs`): `*os.Root` in production, with its symlink and escape refusals, the 0600 mode and the keyring's no-replace link kept, and the crash kit's in-memory filesystem under test, so the boot crash matrix now kills and fails every keyring, secret-metadata and boot-record write (F3-07).
- The hello example and `coretest` boot through the config boot. Offline commands resolve the store and state directory with step 0 alone: they no longer read the boot record, so they never set an unparsable one aside, a command that writes refuses a user that does not own an existing state directory before creating anything, and the fallback warning reaches standard error when no logger is set. A relative compiled state directory is made absolute (F3-07).
