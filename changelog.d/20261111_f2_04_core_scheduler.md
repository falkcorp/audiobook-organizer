### Added

- core: the fresh task scheduler, `core/internal/scheduler` (dark: nothing constructs it until the kernel wiring row). One goroutine polls every `core.tasks.schedule_poll`; each scheduled kind has one durable clock, and a due fire commits the clock advance and the run's insert in one batch, so a crash can neither lose nor repeat a fire. A first boot seeds every clock and fires nothing; a restart after downtime fires each kind once and counts the instants it missed (`Coalesce`), or waits for the next on-time instant (`SkipMissed`). `DailyAt` and `Cron` are evaluated in `core.tasks.timezone`: a wall time skipped by a daylight-saving change fires at the first instant after it, and a repeated one fires once. A disabled key stops firing and its re-enable fires once with nothing missed; a closed `When` gate advances the clock without a run; a held kind's clock is not polled; a clock read error skips the kind for that poll. Maintenance windows (`core.tasks.windows.<name>`, default `nightly` 01-04) fire once per opening and start their members one after another in `Order`, stopping when the window closes. `ValidateSchedules` refuses, at registration, a schedule key outside the registering owner's namespace, an undeclared or wrongly typed key, a key shared by two kinds, and `tasks.Every` on any kind but `core.outbox.relay`. Also new: the schedule-parity harness `core/tasks/taskstest/schedule`, which replays a scenario over a fake clock and returns the sequence of seeds, fires, folds and window openings; the window kind `core.window.nightly` in `core/tasks`; the 14 core schedule keys and the `core.tasks.windows` map in the core config sections; and `tasks.ScheduleConfig` now encodes as one JSON value, so a schedule key is one config key (F2-04).

### Fixed

- core scheduler (F2-04 review round): a maintenance window that wraps midnight (for example 23-4) now fires at every opening, whether the process restarted inside an opening or the window was first seen at noon (its clock holds the start of an opening, never a poll time); a transient storage error while starting a due run keeps the fire for the next poll instead of losing it (only an executor refusal advances the clock alone); a kind first seen while disabled waits one period after it is enabled, as before the rewrite; `SkipMissed` counts an instant as missed only when the process was down for it, not when a poll was merely late; a schedule value that cannot run (two timings at once, an unparsable cron, a malformed `daily_at`, a negative `every`) is refused when config loads or applies it, on every schedule key; the scheduler no longer folds a start into a running run on its own, the executor's dedupe rule does.
