### Fixed

- The Users page's accepted-invites list now shows the time each guest accepted, every field HEAD showed, and every accept (F4-08 B10x2). The first version under core identity (B10x) listed the Cloudflare guest-policy sync's outcome rows, so `accepted_at` was the time the sync last reported (seconds after the accept, or much later when the sync was delayed), an accept whose invite named no address was never listed, an accept whose sync failed before it recorded anything was never listed, and `email`, `email_binding`, `sso_grant` and `displaced_user_ids` were missing. Books now keeps its own accept row per invite (`acceptedinvite:<invite id>`, `database.InviteAccept`), written from core's `InviteAccepted` callback first, on its own recover, before and independent of the guest-policy sync and the guest key, so a sync failure or a panic in it never costs the accept its row, and an invite with no address leaves one. The row holds the username and the accept time read from the account the accept created (core's event carries neither; `CreatedAt` is core's own clock reading for the accept, not the time the callback runs), the address, the binding and grant HEAD's four-way rule would have recorded, and the displaced accounts. The list joins the sync's outcome by invite id for `guest_policy_status`, `guest_policy_detail` and `guest_policy_at`. If core's identity view cannot return the account at that instant, no row is written and none is made up (logged, no value in the line).
- The identity cutover (M3) carries the accepts HEAD's list was still showing. Each used HEAD invite whose `used_at` is within 30 days of the cutover gets an accept row with HEAD's own values (including the sync's status, detail and time that HEAD recorded on the invite), keyed by HEAD's derived invite id and never by the token; the invite row, token included, is deleted as before. Older and open invites are not carried, and an invite row that does not decode is deleted, counted and logged without its key. A resumed run rewrites the same bytes.
- Removed `GuestPolicyStore.ListGuestPolicyOutcomesSince`, B10x's list reader, which nothing reads now that the list is read from the accept rows.
