### Security

#### The shared guest Cloudflare service token is removed

Invitations used to hand every guest the same Cloudflare Access service-token header pair (`CF-Access-Client-Id` and `CF-Access-Client-Secret`) in the invitation email and in the public invite lookup, so anyone holding a live invite link could read a credential that got them past Cloudflare for as long as it lived. It is gone with no compatibility shim. The public invite lookup no longer returns `guest_headers`, the admin invite list no longer returns `guest_headers_configured`, the `INVITE_CF_ACCESS_CLIENT_ID` and `INVITE_CF_ACCESS_CLIENT_SECRET` settings are deleted, and the accept page and the invitation email no longer tell anyone to install custom headers. A guest now gets through Cloudflare by email login: accepting an invitation adds their address to the guest Access policy (`CF_ACCOUNT_ID`, `CF_GUESTS_POLICY_ID`, `CF_POLICY_API_TOKEN`), and the page and email say to sign in to Cloudflare with that address and its one-time code (the email leaves that step out when the policy sync is not configured). A server still carrying either old variable logs a removed-setting warning for each at startup and ignores it; a config update naming one is refused with the removal message. Revoke the old service token in Cloudflare. This supersedes the service-token wording in the 2026-10-19 invite email entry.
