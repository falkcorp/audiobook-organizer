### Fixed

- The toast text for a started operation ("Library Scan started", "... starting") now comes from the same per-def label table as the activity bell, instead of a second private copy of the old table. Before, a scan started from the dedup or AcoustID pages read "Library.Scan starting…" or "Acoustid.Scan starting…".
- Five trigger calls in the web client named operations no def has (`library.reconcile`, `library.reconcile-scan`, `dedup.scan`, `dedup.scan-llm`, `dedup.embed`), so their placeholder in the bell showed the raw id. They now name the defs their endpoints enqueue (`reconcile.apply`, `reconcile.scan`, `dedup.full-scan`, `dedup.llm-review`, `dedup.embed-scan`), and a test checks every trigger id is a registered def.
- The operator's purge of the trash (`library.purge-soft-deleted`) and the nightly purge of books past retention (`maintenance.purge-deleted`) both registered the display name "Purge soft-deleted books", so the bell and the Activity page could not tell them apart. They are now "Purge soft-deleted books on demand (dry run by default)" and "Purge soft-deleted books past retention", and a server test fails if two registered operations share a display name.
