### Security

- Sign-in return paths: a return path whose dot segments resolve to a scheme-relative URL (`/.//host`, `/%2e//host`, `/a/..//host`, `/./%2F/host`, `/%252e%252e//host`) is now refused everywhere it is checked, instead of being followed as an off-site redirect after login. There is one implementation per language: core's `oidc.SanitizeReturn`, which the legacy OAuth login now calls too, and the shell's `sanitizeReturn`/`safeReturn`, which the web app's login and book-detail return links use. Both decode the path, remove dot segments, refuse backslashes and control characters, and require a single leading `/`. One shared payload table (`core/auth/oidc/testdata/return_payloads.json`) drives the Go, legacy-handler and TypeScript tests. Encoded slashes, dots and control characters in a return path (`/%2F/x`, `/%09/x`) are now refused as well.
