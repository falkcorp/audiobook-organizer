### Fixed

- **Store set reads no longer return a short result when one member cannot be read.** `GetBooksByVersionGroup` and `GetBooksByWorkID` walk an index and point-read each member, and skipped a member on any read error, so a group with one unreadable book came back short with no error and dedup, version-group operations and library-copy lookups acted on it as the whole group. Only a not-found member (a stale index entry) is skipped now; any other error fails the call. The same fix applies to `GetBookVersionsByBookID`, `ListABSSessionsForUser`, `ListAPIKeysForUser`, `ListDirtyUserPlaylists`, `ListUserBookStatesByStatus` and the junction pass of `GetAllAuthorBookCounts`, which also now check their index scan's read error. `GetAcoustIDStats` returns its book-read error instead of reporting every file under "(unknown)". The row-scan helpers now join a `Close` error onto an earlier error instead of dropping it. Callers that treated a group read error as an empty group now fail (the split-version and works-list endpoints), skip the book (the organize filter, so a read error cannot add a second primary), or log it (metadata write-back and library-copy lookup).
