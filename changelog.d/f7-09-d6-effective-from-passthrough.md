- Added the builder for the cutover's operator-URL view, dark (nothing live calls it): `m6.EffectiveFromPassthrough` turns core's operator-layer passthrough values into the settings-field-to-URL overlay M6 signs trust from. It answers `integrations.ai.openai.url` as the `url` field of `ai/openai` (an operator path's last segment is the adapter's settings field) and `integrations.download.deluge.url` as the `url` field of `download/deluge`; empty, blank and null values are no overlay, a value that is not a string fails the cutover for its instance without printing it, and a pin test walks every integrations passthrough row of the rename table and the env bindings so a new destination cannot be left unmapped.
- Renamed the OpenAI operator setting `integrations.ai.openai.base_url` to `integrations.ai.openai.url` (the adapter's own field, which `OPENAI_BASE_URL` also binds to), so an operator-set URL reaches the native instance instead of being dropped. A host that still sets the old path, by file key, by `ABO_INTEGRATIONS_AI_OPENAI_BASE_URL` or by its `_FILE` form, is refused at deploy preflight and at boot (serve and every command, before any store is opened) with a message that names the new path and never prints the value; nothing is copied or overwritten silently.
- A metadata source's credential is now a stored secret only: `integrations.metadata.<source id>.credentials.<k>` is no longer an operator-layer setting. A host that sets it by environment variable (or its `_FILE` form) or operator file is refused at deploy preflight and at boot, told to set the credential in Settings, Metadata tab (or `PUT /api/v1/config`), by key name only. M6 still moves every source's stored credential onto its instance, now covered by a per-source test that starts from M2's output.
- `audiobook-organizer config check` now runs the same refusal of those two settings the start runs, beside core's retired-name report: it exits non-zero, names the key (and, for an environment variable, the environment spelling of the setting to use) and never prints the value. It was green on a host the start refused.
- The refusal and the deploy preflight read `<NAME>_FILE` as `<NAME>` (core reads any variable from the file a `<NAME>_FILE` names), the preflight takes its list only from `deploy/retired-env-names.txt`, and one table of cells shared by Go and Python pins the matching. `docs/configuration.md` and `docs/system/deploy-and-gpu-ops.md` state what the preflight does not see (`EnvironmentFile=`, the live environment, the operator file).
- The OpenAI base URL variables `OPENAI_BASE_URL` and `ABO_INTEGRATIONS_AI_OPENAI_URL` now reach the `url` overlay of the OpenAI instance, which the old binary ignored. A stored key is withheld, not sent, when the effective destination differs from the one it was stored for, and a cell in `core/integrations` pins it.
