- Added the builder for the cutover's operator-URL view, dark (nothing live calls it): `m6.EffectiveFromPassthrough` turns core's operator-layer passthrough values into the settings-field-to-URL overlay M6 signs trust from. It answers `integrations.ai.openai.base_url` as the `url` field of `ai/openai` (the native instance's name for it) and `integrations.download.deluge.url` as the `url` field of `download/deluge`; empty, blank and null values are no overlay, a value that is not a string fails the cutover for its instance without printing it, and a pin test walks every integrations passthrough row of the rename table and the env bindings so a new destination cannot be left unmapped.
- Renamed the OpenAI operator setting `integrations.ai.openai.base_url` to `integrations.ai.openai.url` (the adapter's own field, which `OPENAI_BASE_URL` also binds to), so an operator-set URL reaches the native instance instead of being dropped. A host that still sets the old path, by file key or by `ABO_INTEGRATIONS_AI_OPENAI_BASE_URL`, is refused at deploy preflight and at boot with a message that names the new path and never prints the value; nothing is copied or overwritten silently.
- A metadata source's credential is now a stored secret only: `integrations.metadata.<source id>.credentials.<k>` is no longer an operator-layer setting. A host that sets it by environment variable or operator file is refused at deploy preflight and at boot, told to set the credential in Settings, Metadata tab (or `PUT /api/v1/config`), by key name only. M6 still moves every source's stored credential onto its instance, now covered by a per-source test that starts from M2's output.
