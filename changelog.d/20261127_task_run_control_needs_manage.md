### Changed

- Cancelling, discarding, deciding and approving a task run now needs the kind's own manage permission (a new required `Perms.Manage` on every task kind) as well as the operation's own permission. Before, the person who started a run could always cancel it, and anyone holding the executor-wide manage permission could cancel any run; neither is enough on its own now. Core's own kinds name `core:tasks.manage`; every books kind names the same eight permissions the old settings-manage permission carried, which is what gated the old v1 operation controls (the newer v3 cancel let the person who started a run, or anyone who could trigger scans and held the operation's permissions, cancel it; that is narrowed to the new rule when the switch happens). A task kind that states no manage permission is refused when it is registered, and the refusal names the kind. A run whose kind is no longer defined can no longer be cancelled or discarded by a signed-in person. Nothing is wired to a route yet, so nothing changes for a running server.
