### Fixed

- Bulk metadata apply: the certainty gate (`internal/applygate`) gains three blocking evidence checks. `cast_in_author` refuses a candidate whose first author is the files' narrator and whose later authors appear nowhere in that credit, the shape of a full-cast drama credited to its writer plus the cast (13 Big Finish dramas on the 2026-09-13 preview), including when the stored author equals the narrator, since the apply would write the whole list over it. A narrator who is a later author is not blocked, names are compared in full when both sides give a first name, and the check steps aside when the provider names its own narrator. `series_number` refuses a title overwrite whose volume number the result keeps nowhere (`series_number_lost`) and one that keeps the number only as the position of a differently named series (`series_renamed`, "Empire of Man 04 - We Few" -> "Prince Roger" #4); a number kept as the position of the matching series passes, and a trailing number with no series position behind it ("Title - 01") is not read as a volume. `partial_book` refuses one part or disc of a book matched to the whole book, a box set matched to one volume, and a book whose sibling folder holds another part of the same candidate; a range ("Disc 1-3") counts as the whole book, and a single-file book's file name is read for a marker. The sibling index is built before the first apply from the whole candidate source (every book with cached candidates, or every row of the operation), never the request's book list, so a preview and an apply of any subset see the same siblings; it skips soft-deleted rows, non-primary versions and books whose files are all missing. A book the index cannot read is recorded with whatever is still known (folder, ASIN): rows in a related folder or with the same ASIN are blocked for manual review ("sibling <id> unreadable; manual review"), every other row proceeds, and the count is reported in the op log and the preview summary; only a failed cache listing fails the run. A number kept as the series position is stored as the bare series name plus the position ("Party Hard: Pixel Dust, Book 1" -> title "Party Hard", series "Pixel Dust", position 1), pinned by a test on the apply path.
