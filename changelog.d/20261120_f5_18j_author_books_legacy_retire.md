### Changed

- Saving a book no longer writes the legacy author-to-book index rows (`author_books_legacy:`), the index's copy of each book's single `AuthorID`. The author-to-book index now holds the credit list only, which is the author source (owner rule: author and narrator are ordered credit lists). Because the book write no longer touches author data, the book write methods' shared resource rows (`ModifyBook`, `UpdateBook`, `CreateBook`, `RecomputeBookAggregates` and the 21 rows derived from them) drop `authors`, and so do the declared write sets of 19 maintenance kinds and 18 maintenance jobs. Measured on the pinned tables: the maintenance jobs whose write sets overlap `tombstone-cleanup`'s (`authors`) go from 20 to 2.
- The author-to-book index is trusted only after the current process has checked it: its boot reconcile must find every credit row readable and every listed book's `AuthorID` in its credit list. Until then, and whenever that check finds a book whose `AuthorID` its credits do not name, cold author listings during startup use the full scan, as before the index existed. The boot log reports `uncovered_books` with a sample, and `maintenance.credits-backfill` writes the missing credits. The old completion marker is deleted, so rolling back to an earlier build makes that build rebuild its index before trusting it.

### Added

- `maintenance.author-books-legacy-retire` deletes the legacy rows older builds left. It previews by default (counts, nothing written). It refuses, deleting nothing, while any book in any state has an `AuthorID` that is missing from its credit list or whose credit list cannot be read, and it lists those books, because the legacy row is the last place that author was indexed for them. It deletes in synced chunks, is safe to re-run, and finishes a cancelled run on the next. It has not been run on the production library.
