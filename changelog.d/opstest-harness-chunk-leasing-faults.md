- New test harness for v3 operations (`pkg/ops/opstest`). `Conformance(t, def, params)` runs an op against an in-memory World (the real Pebble store, synthetic books) at chunk sizes 1, 3 and the op's default with at least 4 workers. Each run goes through a real operations registry (register, enqueue, dispatch, the fence, cancel, abandonment, the scan stand-down, the Writer the registry builds, the ledger's production commit cadence, and the boot sweep that resumes a crashed run), so the harness tests the code the server runs rather than a copy of it. It checks nine rules, each as its own subtest: preview writes nothing (a preview also leaves a DirtySet's entries in place), history follows the write made in the same Writer call, no write or history row after the fence is revoked (including one a leaked goroutine makes after its run ended), a crash or a graceful shutdown followed by a resume completes and commits every item and runs Finish once over all of them, a mid-chunk crash re-runs only that chunk, a partition runs on one worker in order, an AppendOnly claim holds, progress never goes backwards, and items are idempotent across every crash and resume. Faults (`CancelAt`, `CrashAt`, `ShutdownAt`, `CrashMidChunk`, `InsertBelowCursor`, `AbandonAt`, `LoseLeaseAt`) are injected through per-run, nil-by-default `RunnerHooks` that only a registry built with `Options.RunnerHooksForTest` has; an architecture test keeps the harness and that seam out of production code. A mutation test per rule shows each one fails on a deliberately broken op. Known differences from production: the World supplies the DirtySet compare-and-delete the Pebble store does not have yet (production still refuses DirtySet sources), and its store leaves out the warm-up gate, stand-down persistence and v1 operation rows (a test names each, and fails when the registry starts using a store capability the World does not serve).
