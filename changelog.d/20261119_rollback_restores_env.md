### Fixed

- `make rollback` and `make rollback-restore` now put back the previous release's systemd unit and `local.conf` drop-in together with its binary. Before this, a rollback started the old build under the new environment, which after an env-name change fails open on the peer allowlist and drops the Cloudflare Access, ABS JWT and owner-email settings. Each deploy through `install-staged` keeps the unit and drop-in it replaced as a generation in `<bin>.envgen/`, named by the sha256 of the binary it replaced; a rollback finds the generation by the hash of the binary it restores (never by position), and refuses before anything is stopped when there is none. The environment capture is deleted only after the new binary is in place, so a deploy that fails half way and is re-run no longer files the new unit under the old binary. Several generations are kept (the newest three, plus the newest three pinned ones: the last build before a store level step or before the retired-name list was enforced), and redeploying the installed build rotates nothing. `RELEASE=` checks the environment for the fetched file before it replaces `.prev`, so a refusal leaves `.prev` and its environment as they were; `ROLLBACK_ENV=<sha256>` names the generation a fetched release needs (refused when its recorded store levels differ), and the old `ROLLBACK_ENV=snapshot` is gone.
- `DEPLOY_ALLOW_NO_ROLLBACK=1` is refused for the build that carries the config flip (`enforced: true` in `deploy/retired-env-names.txt`, or a list that cannot be read), and its warning now names the older release a rollback then reaches.

### Added

- `make deploy-env-check`, run first by `make deploy`, `make deploy-debug` and `deploy-preflight.sh`: refuses a `Makefile.local` whose deploy recipes bypass `install-staged` (they keep no `.prev`, unit or `local.conf`; `DEPLOY_ALLOW_NO_ROLLBACK=1` overrides), and a `deploy/local.conf` that sets an env name the new binary ignores. The retired names come from `deploy/retired-env-names.txt`, generated from the rename table and pinned to it by a test; the check reports only, until the app wires `RetiredConfigNames`.
- `make install-rollback-helpers` (dry run by default; `APPLY=1` exports `HEAD` into a fresh `sudo mktemp -d` directory under `/opt`, installs from there with `sudo` and removes it afterwards, since the installer refuses to run as root from a checkout the deploy user can write): the owner's one-time installer of the rollback helper bundle, `rollback.conf` and the sudoers drop-in, rendered from the recipes' own command table and checked with `visudo -c` on a temporary file before it is moved into place. Idempotent; an edited `rollback.conf` is shown as a diff and left alone. `make rollback-check` lists the kept environment generations (read-only). `scripts/deploy_generation_args.py` measures the staged build's version and store levels for the deploy. `make deploy-env-check` also scans the repo's unit template for retired env names.
