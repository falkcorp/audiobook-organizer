### Added

- F4-07, the reach oracle's books half: R0's recorded reach against R2's after M3. `scripts/r2corpus/record_r0_reach.py` boots the pinned R0 release binary (v0.223.0, `Linux_x86_64`) on a throwaway copy of the overlay corpus, with the Deluge discovery flag and the fingerprint worker on, and records for every route of R0's router (572, dumped from the tag's source by `scripts/r2corpus/dump_r0_routes.py`) and every principal of 05-rbac section 12 (37: seven sessions, twenty-eight scoped keys, the anonymous caller and the auth-disabled principal) whether the route's authorization decision allowed or denied the request. A probe is a request that fails after authorization when it is authorized, so a 401 or 403 is a denial and any other status below 500 is an allow. A 429, an unexplained 5xx and a connection error are recorder failures, never verdicts; a census of users, books and task definitions before and after the pass, and a canary request per principal, fail the run when a probe changed the store or killed the server. The task definitions (234) are recorded as start and approve verdicts per principal. The answers are under `internal/books/rbacreach/` (data only, no Go file); `--check` re-derives them and exits 1 on any differing cell. The recording was made on a GitHub-hosted runner, because the release has no usable Darwin arm64 asset.
- `TestIdentityCutover_ReachOracle` (in `internal/books/cutover`, because the M3 rig lives there) runs M3 over the same corpus with each key principal seeded as a HEAD key row, resolves every manifest route and every task definition's start and approval through the atom table, evaluates the principals with a test-local copy of core's compiled checker, and asserts after equals R0 except for the listed expected differences, each asserted on both letters and failing if it matches no cell. Changing any atom row that a route enforces, in M3's table or in the route resolution's, fails the oracle (`TestReachOracle_AnyChangedAtomRowIsReported`).
- The oracle found three differences the spec did not list, and the spec's owner ruled on each (`docs/agent-tasks/platform-core/seams.d/F4-07.md`, "Ruled"); the oracle is green with 217 differing cells, all claimed by a row. An API key of an `fp-worker` user whose scopes lie outside the worker scope reaches no route after the cutover (HEAD let it through every authenticated-only route), and an admin's API key, the bootstrap key included, no longer reaches the three admin debug edit routes, whose scope is `Sensitive`; both are listed in 05-rbac sections 6.3, 6.2 and 12. The core-route half, auth-off across core routes and the run on the registered path are F4-08's.
