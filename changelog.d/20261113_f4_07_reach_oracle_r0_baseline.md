### Added

- F4-07, the reach oracle's books half: R0's recorded reach against R2's after M3. `scripts/r2corpus/record_r0_reach.py` boots the pinned R0 release binary (v0.223.0, `Linux_x86_64`) on a throwaway copy of the overlay corpus, with the Deluge discovery flag and the fingerprint worker on, and records for every route of R0's router (572, dumped from the tag's source by `scripts/r2corpus/dump_r0_routes.py`) and every principal of 05-rbac section 12 (37: seven sessions, twenty-eight scoped keys, the anonymous caller and the auth-disabled principal) whether the route's authorization decision allowed or denied the request. A probe is a request that fails after authorization when it is authorized, so a 401 or 403 is a denial and any other status below 500 is an allow. A 429, an unexplained 5xx and a connection error are recorder failures, never verdicts; a census of users, books and task definitions before and after the pass, and a canary request per principal, fail the run when a probe changed the store or killed the server. The task definitions (234) are recorded as start and approve verdicts per principal. The answers are under `internal/books/rbacreach/` (data only, no Go file); `--check` re-derives them and exits 1 on any differing cell. The recording was made on a GitHub-hosted runner, because the release has no usable Darwin arm64 asset.
- `TestIdentityCutover_ReachOracle` (in `internal/books/cutover`, because the M3 rig lives there) runs M3 over the same corpus with each key principal seeded as a HEAD key row, resolves every manifest route and every task definition's start and approval through the atom table, evaluates the principals with a test-local copy of core's compiled checker, and asserts after equals R0 except for the listed expected differences, each asserted on both letters and failing if it matches no cell. Changing any atom row that a route enforces, in M3's table or in the route resolution's, fails the oracle (`TestReachOracle_AnyChangedAtomRowIsReported`).
- The oracle found three differences the spec did not list, and the spec's owner ruled on each (`docs/agent-tasks/platform-core/seams.d/F4-07.md`, "Ruled"); the oracle is green with 217 differing cells, all claimed by a row and listed by name in `reach_golden_test.go`, so three unsaturated rows cannot swap cells at an equal count. An API key of an `fp-worker` user whose scopes lie outside the worker scope reaches no route after the cutover (HEAD let it through every authenticated-only route), and an admin's API key, the bootstrap key included, no longer reaches the three admin debug edit routes, whose scope is `Sensitive`; both are listed in 05-rbac sections 6.3, 6.2 and 12. The core-route half, auth-off across core routes and the run on the registered path are F4-08's.
- Review of the oracle's gate: every expected-difference row asserts the number of cells it claims (a partial reversal of a ruled change, or a gain absorbed by a row, now fails) and the rows' counts add up to the 217 differing cells; the oracle's size (572 R0 routes, 505 compared, 64 delegated, 3 R0-only; the compared count is derived by the oracle, not typed) is pinned, as are the delegated set and the uniform-404 routes; the atom-row mutation check now asserts the gate fails, and a second check changes each manifest route (widened, narrowed, AllOf to AnyOf, a guard dropped; 979 mutants: 952 killed, 949 by a moved reach and 3 by the owner-set comparison alone, and 27 that move no principal's reach and that no check fails) and requires the oracle to fail on every one that moves reach; a route added without a requirement, a new route, a dropped route and a delegated route each fail by a named check. The recording names its overlay store (`overlay_sha256`, compared by `--check` and, offline, by a Go test) and the run that wrote it. A throwaway `--check` against the real R0 showed that the stored config cannot be part of the recorder's census: its own authorized `PUT /config` probes rewrite it. The route dump script has a unit test (`scripts/tests/test_dump_r0_routes.py`). The three routes whose handler checks `core:admin` are pinned with the 11 cells the pin hides listed as an obligation on F4-08.
