#### F4-07 — reach oracle, books half: R0's recorded reach against R2's after M3

`scripts/r2corpus/record_r0_reach.py` boots the pinned R0 release binary on a throwaway copy of the overlay corpus and records, for every route of R0's router (572 at v0.223.0, dumped from the tag's source by `scripts/r2corpus/dump_r0_routes.py`) and every principal of 05-rbac section 12 (seven sessions, twenty-eight scoped keys, the anonymous caller and the auth-disabled principal), whether the route's authorization decision allowed or denied the request. A probe is a request that fails after authorization when it is authorized (a dummy path id, an empty body), so a 401 or 403 is a denial and any other status below 500 is an allow. A 429, a 5xx and a connection error are recorder failures, never verdicts; a census of users, books and task definitions before and after the pass, and a canary request per principal, fail the run when a probe changed the store or killed the server. The answers are under `internal/books/rbacreach/` (data only, no Go file). `--check` re-derives them and exits 1 on any differing cell.

`TestIdentityCutover_ReachOracle` (in `internal/books/cutover`, because the M3 rig lives there) runs M3 over the same corpus with each key principal seeded as a HEAD key row, resolves every manifest route through the atom table, evaluates the same principals with a test-local copy of core's compiled checker, and asserts after equals R0 except for the listed expected differences, each asserted on both sides and failing if it matches no cell. Changing any atom row that a route enforces, in M3's table or in the route resolution's, fails the oracle. The core-route half and the run on the registered path are F4-08's; see `docs/agent-tasks/platform-core/seams.d/F4-07.md`.
