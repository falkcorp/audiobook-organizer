### Added

- A test harness that runs the identity upgrade's real server and asks it, one request at a time, what a person or a key gets to do. It starts the whole application on a disk copy of the upgrade test library, runs the upgrade's account, key and settings steps, and then sends every route to every kind of caller (administrator, editor, viewer, keys with and without scopes, the Cloudflare Access owner, a server with sign-in switched off), comparing each answer with what the previous release recorded. A route is only counted when the server's own sign-in and permission step stood in front of it, so a route that skipped the check cannot pass as allowed. The harness also checks the accounts the upgrade creates (every old password still signs in, a wrong password and a disabled account are refused), the Audiobookshelf entry points (Cloudflare Access sign-in and a shared e-mail address that must not pick between two administrators), and that a key made after the upgrade is refused by the Audiobookshelf side. Each caller sends from its own address so the server's rate limiter can never make an answer look like a refusal, and a rate-limited answer fails the check instead of counting. It also shows that a server whose stored settings say sign-in is off comes back with sign-in on once the operator sets the documented value and restarts, and that an administrator can then use the routes that were refused while it was off. It changes no server behaviour: it only reports where the upgraded server answers differently from the old one.
