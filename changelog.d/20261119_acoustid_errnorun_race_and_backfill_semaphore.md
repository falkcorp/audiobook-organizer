### Fixed

- The acoustid window-backfill test `TestWindowBackfill_RemoteOnly_PendingGraceFailsNamingWaitingWorkers` no longer fails intermittently in CI with "acoustid.window-backfill is not running". It called the worker hub's hello endpoint right after the clock advance that ends the run, so whenever the heartbeat detached the run first (one 5 ms poll later) the call correctly answered "no run". The test now makes no hub call after that advance, and proves the run was still going at 90 seconds by waiting for two heartbeat reports instead of sleeping. The hub itself was right: a caller cannot see "not running" before a run exists, and the test helper already waits for the run to be attached.
- The acoustid fingerprint backfill sized its per-file semaphore straight from the injected worker-count hook. A hook returning 0 or less (the native kind's `KindDeps.Fingerprint.Workers` is not clamped, unlike HEAD's `backfillWorkers`) made the semaphore unbuffered, so the first file waited on it until the run was cancelled. The semaphore now takes its size from the same clamped value as the book pool.
