### Added

- The `core.email` notification channel's SMTP connection now passes the same egress guard as an outbound HTTP request (F7-09 T2, TODO-F7-05-SMTP-DIAL-GUARD). `integrations.GuardedDialer` is an optional dial capability of a `Gate`, `integrations.GuardedDial` hands an adapter that dial (or one that refuses, `ErrNoEgressGuard`, when its gate offers none), the Registry's gate wrappers forward it with the `core.integrations.disabled` check, and the `providerhttp` gate implements it with the same trusted-or-public guard choice an HTTP request makes. An email instance whose host resolves to a private, loopback, CGNAT or link-local address is refused before any connection unless it is `Local` for that host and port or `core.integrations.egress.lan_allow` lists it; link-local and the cloud metadata addresses are refused whatever the trust; a failed lookup connects to nothing; the address that was checked is the one dialled. `mail.SMTPConfig.Dial` carries it into the sender, and a nil `Dial` keeps the plain dial of the invite flow. Dark: nothing registers `core.email` yet, so no running behaviour changes.
- An `smtp://host:` origin (a host-and-port instance with its port unset) now normalises to `host:587`, the port the sender dials, so a Local email instance with no port set is admitted at its own host.
