### Changed

#### Events flip: the browser stream, the outbox and the relocation follow-up run on core (F6-03)

The SPA now reads one server-sent-event stream, `GET /api/core/v1/events`, through the `coreEvents` client, in place of hub A's `GET /api/events`. Hub A (`internal/realtime`) and its route are deleted; `/api/events` answers 301 to `/api/v1/events`, which is 404. Book changes arrive as `books.book.changed.v1`, one frame per committed write and batched by the SPA over 250 ms; the stream is limited to holders of `books:view`, where hub A gave it to every signed-in user. `system.status` and `scan.auto_triggered` are no longer sent. The shutdown notice is `core.stream.closed.v1` with reason `shutdown`, and the listener now honours `OnShutdown` so open streams are closed before the drain.

Run frames (`core.task.run-changed.v1`, `core.task.finished.v1`) reach a subscriber who is an administrator or who holds the View requirement of the run's kind (default `core:tasks.view`), the rule REST applies; `core.task.log-appended.v1` stays administrator-only because a log line names no kind. No storage level is raised by any of this.

The books relocation follow-up is durable: `SetRelocationOutbox` is called before the store takes writes, the Deluge consumer is registered as an outbox task consumer, and `NotifyDelugeAfterOrganize` is no longer the only way an organize copy moves torrents: with the tasks switch off (production before the F5-18 switch commit) the single-book organize request still calls it directly after its copy, exactly as before, and with the switch on the staged message replaces it. Exactly one of the two runs for one organize copy, chosen by whether the store has a relocation outbox installed, which is installed only while the switch is on. The F5-18 switch commit deletes the direct call. Retry is in-run because outbox redelivery stops at the task start: a `move_storage` that fails transiently is retried up to three times (1 s, then 2 s), a Deluge refusal is not, and a move that still fails fails the run, which resumes from zero. The v2 path-update shell shares that code, so it now fails a run on a failed move as well. Until F5-18 registers books' task kinds the relocation message fails its run start.
