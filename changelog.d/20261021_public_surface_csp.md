### Security

#### Content-Security-Policy and Permissions-Policy on every response

The web app was served with no Content-Security-Policy, so any injected script would have run unrestricted. Responses now carry a policy that allows scripts only from the app's own origin plus the one inline pre-paint theme script, allowed by hash (computed at startup from the `index.html` the binary actually serves, so it cannot drift from the build). Other sources are limited to same-origin (requests may also go to the one host of the configured Cloudflare Access team, `cf_access_team_domain`, so the app can still tell an expired Access session from an outage; nothing is added when it is unset, and no wildcard is ever allowed), with images also allowed from `data:`, `blob:` and `https:` (metadata search shows provider cover URLs), `object-src 'none'`, `base-uri 'none'`, and `frame-ancestors 'self'`. Styles keep `'unsafe-inline'` because the UI library injects them at runtime. A handler that sets its own policy (the OpenID browser page, the Cloudflare recovery page) keeps it. A `Permissions-Policy` turns off camera, microphone, geolocation, payment and USB. Checked in a real browser against the embedded build: no violations on the app's main routes.

The policy stays enforcing and now also reports: browsers send violations to an unauthenticated `POST /api/v1/csp-report` (via `report-uri`, and `report-to` with a `Reporting-Endpoints` header), which logs one line per violation with the directive, the blocked resource, the page and the source file. Every reported URL, with or without a scheme, goes through one reduction first: the query and fragment are dropped, secret path forms such as `/invite/<token>` are redacted, and the page the violation happened on is always cut to its first path segment, so a token in it never reaches the log, whatever Host the request carried. A blocked or source URL on the same site as that reported page (decided against the page's own host, never the request's Host header, which a proxy may rewrite), or a relative or schemeless one, is cut the same way; a third-party URL keeps its redacted path so a blocked script stays identifiable. The invite-route redaction matches case-insensitively and ignores empty path segments, so `/INVITE/<token>`, `/Invite/<token>` and `//invite/<token>` are redacted like `/invite/<token>`. Values are logged quoted, so a crafted report cannot forge a log line, and truncation never splits a character. A report is capped at 8 KiB and ten violations, and the limits count violations, not requests: a burst of 10 then one every two seconds service-wide, and a burst of 10 then one every ten seconds per visitor, so one caller cannot use up the budget and leave a real browser's reports unlogged and a full batch of ten from one browser is logged. A batch larger than what remains is logged up to what remains and the rest are dropped, rather than the whole batch being refused; a request refused outright spends neither budget. Reports over a limit are dropped, counted, and the count is logged with the next one.
