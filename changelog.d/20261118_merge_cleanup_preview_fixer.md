### Added

- A read-only Repairs fixer, `maintenance.merge-cleanup` ("Fix mistaken merges", Duplicates group, last in the group), lists every book that carries a merge pointer but is not in the trash and still has a live file, and says what each merge really is. It is `PlanOnly` and has no apply path: nothing is written to books, files, journals or decisions, and a library scan is not stood down for it. Each row is one of three kinds. `unmerge`: the two books are different works (a different title and credit, runtimes measured and apart). `swap_keeper`: the same work, but the target runs under 80% of the loser's length, so the target is a fragment and the loser is the copy to keep (a target about half the loser's length, or under thirty minutes, is held as `runtime_ambiguous` instead). `repoint_chain`: the pointer leads into the trash or to a book that does not exist, and exactly one live book is reachable another way (the dead book's version group, or the holder of its retired file rows). A merge that looks correct, or cannot be told, is listed as `no_verdict` and left alone.
- The verdict reads a book's title, credits, series position, ASIN, file count, summed runtime and file hash. A runtime is only compared when every present file has a measured length; a book with one that does not is held as `runtime_incomplete`. A chain is followed by its own pointer walker, not `ResolveMergeSurvivor`, which returns the first non-trashed book and so would compare a loser with another loser; the verdict is made against the live end of the chain. A cycle unmerges one member (longest known runtime, then most files, then oldest, then lowest id) and holds the rest until a re-plan.
- Holds are listed on every row, in the order the gates ran, and the first is the row's skip kind: `handled_by_version_group_repair` (the version-group fixer's own `planGroup` would write a book this row would write, so the two fixers never plan the same book), `retired_shell`, `cross_group`, `swap_target_not_primary`, `swap_would_not_crown_keeper` (the swap is simulated through `reviveMembers` and `versionprimary.Elect`), `group_needs_handoff`, `sync_redirect_present`, `owner_says_distinct`, `owner_veto_unresolvable`, plus the verdict skips and the three chain skips. The facts later work needs are also row flags, which count across every class even when an earlier hold settled the row: `group_needs_handoff`, `sync_redirect_present`, `owner_says_distinct`, `chain_via_merged`, `chain_via_trashed`.
- Each row carries origin evidence: `origin_match4` (the pointer, an explicit false primary flag and a metadata-source hash shared with the target, which is the only thing MATCH-4 writes), `origin_match4_partial` (the pointer and flag but no shared hash) or `origin_other`. It is evidence only; a pointer is repaired the same whoever wrote it. The plan logs one census line with the merged-book count, rows, exclusions (trashed, no live file, missing, no longer merged) and the counts by class, by first skip kind, by every hold (a row held twice counts under both) and by flag.
- The plan classifies the merged books on a bounded worker pool (`min(NumCPU, 8)`, `registry.RunItems` with `Concurrency` set) over per-run caches of books, groups, file hashes and credits. Its progress label reads an atomic counter, because `RunItems` calls Label inside the workers.
- `RepairsPanel` words every new skip kind, class and flag; the deep-link reference lists them.
