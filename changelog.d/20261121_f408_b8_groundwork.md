### Changed

- The `server-bootstrap` skill and its `bootstrap.sh` exchange the bootstrap token on core's native route, `POST /api/core/v1/auth/bootstrap`, and read the token from `.bootstrap-token` (leading dot, the path the sudoers rule names) in the state directory. The native answer is the bare body (`key`, `key_id`, `user.username`, `generated_password`) and the request takes `token` only. `bootstrap.sh` also stops grepping a journal field that is no longer logged.
- The unit-lifecycle test signs in through `/api/core/v1/auth/{bootstrap,login}`.
- The SPA's sign-in, setup, account, session, user, invite and API-key calls use core's native identity routes (`/api/core/v1/...`) through `@mediacore/api-client`, in `web/src/services/coreIdentity.ts`. Core answers bare bodies and Problem errors; the adapter keeps the shapes the pages read. This takes effect only when the server mounts those routes (the identity switch, B10g); until then the legacy routes still answer, but the SPA no longer calls them.
- Invite and temp-login links are read from the URL fragment (`/invite#token=...`, `/login/temp#token=...`). The fragment is removed with `history.replaceState` before any request and the token travels in a request body only. The old `/invite/:token` page is gone.
- The Users page lists, disables, enables and revokes through core and shows an account merged into another as merged, with no Enable action. Creating an invitation with e-mail and resending one stay on the books routes (`POST /api/v1/users/invite`, `POST /api/v1/users/invites/:id/resend`) until a books wrapper over core's invite create exists; so does admin set-email. API-key rotate stays gone (410). The pending-invitation list no longer shows a copy-link column: core keeps no invite token to list, so the link is shown once, when the invitation is created.
- The setup page has a bootstrap-token field, required by core when the browser is not on the server's own machine. API keys no longer have a description (core has none).

### Added

- The permission-literal ESLint rule of the platform-core UI spec (07 section 7.18): no string literal in a permission position (a `usePermission`, `useAction` or `hasPermission` argument, a `permission` or `*_PERMISSION` property or constant, an API-key scope list). It runs over all of `web/src`; the allow-list of not-yet-moved files is gone.
- Playwright specs for the invite and temp-login fragment links (`/invite#token=` and `/login/temp#token=`), written against the native identity routes.

- Permission constants for the SPA are generated from `books.AtomTable()` (`cmd/permsgen`, `make generate-permissions`) into `web/src/generated/permissions.ts`, and CI fails when the file is stale (`make permissions-check`).
