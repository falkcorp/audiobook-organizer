### Fixed

- Repairs apply no longer loses its scan stand-down lease on a long row. The 5-minute lease was renewed once per row, at the row's start, so a legitimate fragment-consolidation row that retired 315 books (American Gods) wrote for 5m34s unrenewed, the registry reaped the holder, and every remaining row was abandoned. Every write through the repairs Writer now renews the lease, so a row that is making progress keeps it however long it runs, while a wedged write still lets it lapse. A renewal that fails mid-row stops that row's writes at once; the row is reported `aborted_standdown_lost` with the steps it got through (a resume re-runs it, and the fixers skip steps already written) and the remaining rows are not written.
- A lost lease is no longer misreported by individual fixers. The version-group primary fixer turned the error into text, so a lease lost between crowning the new primary and demoting the old one settled the row as `failed` and left the group with two primaries for good; it now aborts the row, and the resumed row recognises its own half-write (by its history rows) and finishes it. The fragment fixer's primary hand-off swallowed the refusal, so a copy row could report `applied` with the hand-off unjournaled; it now aborts, and the next run (a restart resume or a retry, which is a new operation) finishes the hand-off when the fragment's state and this fixer's history show it is still owed, refusing the row instead of guessing when they cannot tell. Direct store writes the Writer cannot route (the hand-off election, the listening-state follow, junk-author creation, the folder-books path-key claim) renew the lease first.
- An apply row waiting for the process-wide merge lock now renews the lease every 30 seconds while it waits, so an outside holder (a dedup merge) keeping the lock past 5 minutes no longer makes the row's first write fail.
