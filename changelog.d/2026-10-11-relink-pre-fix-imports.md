### Added

- New Repairs fixer `maintenance.relink-pre-fix-imports` ("Link pre-fix imports to their versions") for the files imported before the 2026-10-10 import-order fix. Each of those imports left a version that no `book_file` row names and a row with no `VersionID`. The plan (the dry run) lists every row of every live book that has a version or a row naming one, classed `would_link`, `same_book_version`, `already_linked`, `held_by_other_book`, `foreign_version_id`, `dangling_version_id`, `no_candidate`, `hash_mismatch`, `ambiguous`, `path_not_allowed` or `book_deleted`. Each row shows its book, file path, proposed version and reason. Apply writes only `would_link` rows, which adopt the book's one stranded version through `versions.CreateIngestVersion`, and `same_book_version` rows, which link to the version of the same book that holds the row's torrent (compared on `holder.BookID`) in one compare-and-set. Each row is re-checked under the merge lock and `versions.LockTorrent`. A row with no `FileHash` gets one from `filehash.BookFileHash`, read before the locks; a hash that fails is left to `backfill-file-hashes`. Each link is journaled as the record-only `book_file_version_link`, which the op revert does not undo. The fixer never creates, changes or deletes a version or a `book_file` row, and a re-run finds nothing new to link. The plan pass runs on a bounded `registry.RunItems` pool with one item per book, and the apply engine partitions rows by book.
- `versions.IngestVersionParams.AdoptVersionID` makes `CreateIngestVersion` adopt-only. It links the row to that stranded version or returns `ErrVersionNotAdoptable` with nothing written, and it never creates a version.
