### Added

- `make export-keyring` and `make export-install-secrets` bring the files only the service user can read (the keyring from `secrets export-keyring`, the install's `.encryption_key` and `config.yaml`) to the machine you run `make` on, through two new root-owned rollback helpers (`export-keyring`, `export-install-secrets`), with no raw `sudo`. Each helper takes no arguments and is granted in sudoers with `""`. The reads run as the service user in a transient unit and reach the helper over a pipe, not the group-readable restore log. The helper writes each file into a new `export_dir` setting in `rollback.conf` (a directory the deploy user owns, mode 0700, opened with no symlink in any component) with `O_EXCL|O_NOFOLLOW`, mode 0600, owned by the user who ran `sudo`, under a fixed timestamped name. The make target copies the files with `scp` into `OFFHOST_DIR` (default `~/aorg-offhost/<UTC stamp>`, mode 0700), checks size and sha256, and only then deletes the remote copies. Neither helper stops the service or needs it stopped.
- `install_helpers.py` takes `--export-dir`, and the owner must reinstall the helper bundle (`make install-rollback-helpers APPLY=1`) to get the new stubs and sudoers lines.

### Changed

- `offline_env` in `rollback.conf` now accepts `ABO_*` names beside `HOME` and `ABK_*`, and the installer's default is `HOME=<state_dir> ABO_CORE_PATHS_STATE_DIR=<state_dir>`. The flipped binary refuses `ABK_STATE_DIR` at boot and in every offline command, so the old default broke `make rollback-restore`, `make rollback-restore RELEASE=<tag>` and the new `make export-keyring` on a flipped install. Every helper now refuses a `rollback.conf` that sets `ABK_STATE_DIR` together with an `ABO_` state directory. The release fetch (`make rollback-restore RELEASE=`) uses `ABO_CORE_PATHS_STATE_DIR` for its scratch directory and, when a pre-flip binary refuses that ("core's state directory ... is not ABO's ..."), retries once with `ABK_STATE_DIR`; any other failure is not retried. ABO-only in `rollback.conf` works with a pre-flip binary only when `state_dir` is the compiled default; otherwise that binary refuses, fail-closed. An installed host needs the reinstall in precondition P6 (`REPLACE_CONF=1`).
- The export unit has a deadline (`RuntimeMaxSec=60` plus a helper-side wait), and the helper stops the unit itself on a timeout or an oversized output, but only when the unit carries a token this call set, so a hung export cannot block the next and a lost race never stops another caller's unit. A frame that claims more than 1 MiB is refused even when the output is short, each frame failure has its own message, and `make export-keyring` refuses a stray `ABSENT config` line. When a copy does not match, the target prints the exact `ssh ... rm -f --` cleanup command.
- The R2 cutover runbook's Step 1 and Step 7 name the two make targets, add precondition P6 as an exact command (before the prod-copy rehearsal), and narrow Known gap 2 to `storage cutover-blockers`. Known gap 4 records that the state-directory variable is static in `rollback.conf`.
