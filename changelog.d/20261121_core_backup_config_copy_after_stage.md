### Fixed

- `core/backup`: a staged restore of an archive that carries the config file is no longer refused by the real swap. `StageRestore` copied the archive's config files to `<state_dir>/restore/<id>/config.restored/` for the operator to merge, and did so before its Stager ran `Stage`. `restoreswap.Swapper.Stage` refuses an intent whose `restore/<id>` already exists ("an intent id is never reused"), so every such restore failed with `restore/<id> already exists`. That was the default path (no `ReplaceConfig`), and also `ReplaceConfig` when the rename pre-check fell back to staging the files. The package's tests use a fake Stager that only creates the intent, so none caught it. Nothing in production builds `core/backup` yet, so the bug was waiting for the F8 wiring. The config files are still read before `Stage`, so an unreadable one still refuses before anything is staged. They are now written once `Stage` has created `restore/<id>/`, as the stage note already was. A write that fails then is a warning, since the restore is already staged, and the files stay in the restore's staging directory beside the database. `TestStageRestoreThroughTheSwapperKeepsTheConfigCopy` drives the restore through the real `restoreswap.Swapper`, and it failed with that refusal before the fix.
