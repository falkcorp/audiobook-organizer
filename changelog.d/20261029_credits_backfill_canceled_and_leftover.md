### Fixed

- `maintenance.credits-backfill` files the books a canceled apply never reached. An apply that is canceled, or that loses the scan stand-down, used to leave the cohort books it had not yet written in no class, so the result's counts did not add up and a reader could not tell them from books that were never eligible. They are now listed under `canceled_not_written` (informational, in the result and in the class-list paging like every other class): the cohort's unwritten books when the stop came during the writes, every planned book when it came before the cohort was picked (the planning pass or the split replan). Books that were never scanned stay the difference between `books_listed` and `books_scanned`.
- `maintenance.credits-backfill` no longer takes a narrator record that a crashed operation left behind for a preexisting one. A record created by an apply that crashed (or lost the stand-down) and was never resumed was still read as "always there" by every later operation, because only the resumed operation's own journal was read, and each `limit` cohort runs under its own operation id; a split book in a later operation could link to it although no creating write ever credited it. An apply now also reads the `narrator_create_intent` and `credits_backfill` rows of every other credits-backfill operation whose status is not `completed`, judged against that operation's first journal row, and treats an unlinked record they name as new: it is created again by a book that credits the name whole, or deleted at the end of the run with a `narrator_delete` row if nothing credits it. It reads the whole operation history once per apply and refuses to start if the store cannot list operations. A discarded operation is not listed, so a record only its journal rows still name is not found.
