### Fixed

#### A no-auth install is no longer signed out by a refused action

With authentication turned off, the web app treats any "authentication
required" answer as being signed out and drops the install to a sign-in
screen with nothing to sign in to. Actions that need a real user account
(disabling or re-enabling a user, resetting a password, issuing a temporary
login, your own profile, sessions and API keys, the audit log, backups,
health and updater controls, and the books-side equivalents) were refused
that way (F4-08 B10sr).

They are still refused, because they need a signed-in user, but the answer is
now a 403 "turn authentication on to use this route" (`interactive_required`
from core, `FORBIDDEN` from the books routes). The web app shows it as a
refused action and keeps the session. A request with authentication on and no
credential still gets 401 `authentication_required`.
