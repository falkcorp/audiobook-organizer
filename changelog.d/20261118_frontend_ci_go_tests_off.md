### Changed

- `Frontend CI` no longer runs the tests of the shared `reusable-ci.yml` (`skip-tests: true` in `frontend-ci.yml`): its Go tests, its frontend tests and its Python tests. Its `Go CI` job ran the whole non-short suite in one unsharded `go test -race` and took 40-57 minutes of the job's hard-coded 60 minute cap; 6 of the last 18 runs that reached a verdict were cancelled at the cap (the main push run 44262876677 among them). `ci.yml` already runs the short Go suite sharded, the coverage floor, the applygate and seqnum tests at full size, and the same frontend tests, lint and build on every change that reaches this workflow, so those were duplicated. Not duplicated, and given up: the Go tests that `-short` skips no longer run on a pull request that touches both `web/` and Go (`nightly.yml` still runs them, but its own Go CI hit the 60 minute cap on 3 of its last 8 runs, filed as `NIGHTLY-GO-CI-CAP`), and the Python tests that `ci.yml`'s repo-guards job does not run (a root `pytest --cov=.`). The `Go CI` job still builds the module (`go build ./...`, about 4 minutes) and the job names are unchanged. The inputs that only the removed tests used (`go-test-timeout`, `coverage-threshold`, `fetch-base-branch-tip`) are removed from `frontend-ci.yml`, and a comment there lists them for the day the tests are turned back on; `free-runner-disk` stays.
