### Added

- core: `core/backup` (dark), the platform-core backup and restore of every core store. It writes the `mediacore-backup/1` archive (a manifest first, one SHA-256 per entry, a keyring-derived MAC bound to the install), keeps the catalogue and retention (the newest verified archive and a pending restore's archive are never deleted; retention runs before the space check), verifies at three levels (checksum, entries, open), and stages a restore in the one swap slot after provenance, compatibility, upgrade-floor and secrets-coverage checks. It reads HEAD's `legacy-abo/0` archives for the staged and the offline restore, as foreign restores, and registers the `core.backup.*` tasks, the `backup` metrics scope and (in `core/internal/backuphttp`, unmounted) the `/api/core/v1/backups` routes. Archives never hold a plaintext secret or the keyring, every tar entry is bounded and must be a regular file, and a privileged restore option (foreign, replace-config, unreadable-secrets, weak-verify) needs an interactive-owner proof that only the route supplies, so the task path cannot pass one. A failed verification is shown as a fixed reason code (`checksum_mismatch`, `manifest_mismatch`, `store_unopenable` and so on, with `failed` for a cause it does not classify) in the routes' bodies; the error text, which names host paths, goes to the operator's log and the archive's `.verify.json`, and a staged restore's warnings carry fixed phrases for the same reason; the secrets-coverage refusal and warning give the number of missing keys, never their IDs. Every extraction (staged restore, the open-level verification, re-signing, the offline restore) first checks the archive's declared bytes plus a margin against the free space of the filesystem it writes to and answers `insufficient_space` (507) rather than fill it, stops at the bytes it admitted, and refuses a PAX or GNU sparse file; the default archive limits are lower (4 TiB archive and total, 256 GiB per entry, 262144 entries). An import ignores the `name` it was given and stores the archive under a service-chosen name, a manifest's ID must be a ULID and its strings are bounded, two files with one archive ID list as one, only an Own archive takes the retention floor or is opened by the scheduled verification, stale temporary files of crashed runs are removed, and the `runs` counter's reason label is `schedule`, `manual` or `other`. ABO's own backup and routes are unchanged.
- core: `storage restore-offline --archive` takes `--keyring <file>` (the keyring export, mode 0600) and `--gap-fill <file>` (the off-host `config.yaml`), staged under the state-file labels `keyring` and `gap_fill`; the files they replace are set aside, never deleted, and an archive without them leaves the live files alone. A legacy archive restored without `--gap-fill` warns what then migrates empty. An app that sets no `R1ArchiveExtract` now extracts archives through core's extractor, which writes only the store (`db/`) of a `mediacore-backup/1` archive.
