### Added

#### R2 fixture corpus, stage 2: the labelled overlay and the blocker corpus (F2-13)

`scripts/r2corpus/overlay/` is a Go program built only at the R0 tag, against that tag's own `internal/database` (every file carries `//go:build r2corpus_overlay`, so no build or vet of main sees it). `build_overlay.py` checks the tag out in a temporary worktree, builds the program there and runs it on copies of F2-12's stage-1 store; stage 1's bytes are never touched. The overlay (`internal/books/testdata/r2corpus/overlay/`) adds the rows R0's API cannot write: custom roles over every atom, a subset, an unknown atom and only unknown atoms; API keys whose scopes lie outside their owner's roles or under a custom-role owner; user and key status edge cases (padded, upper-case, empty, unknown, revoked-at, no expiry); an OAuth identity and an invite allow-list row; runs left running, stopping (for each StopReason), interrupted, dropped, waiting on dependencies and awaiting a decision, with their checkpoint, chunk ledger, lease, intent, plan rows and row marks; a scan stand-down marker, a debounce bucket and requires stamps; AI jobs in each status; an invalid integration field; and one undecodable row in each family that quarantines (secret, settings-blob field, role, invite allow-list, run, syslog, import root, AI job). Each blocker store under `blockers/` holds one row the cutover preflight must refuse: an undecodable or importer-rejected user, an undecodable or orphaned API key or OAuth identity, and a merge journal left at `applying` or `undoing`; a finished and an undone merge share one control store that must not block. `manifest.json` lists every case with its step, outcome, the keys it wrote and its spec reference, every store's files, and R0's answers recorded on the overlay (`answers/overlay/`).
