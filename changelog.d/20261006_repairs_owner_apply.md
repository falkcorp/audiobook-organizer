- **Repairs: owner-only apply of iTunes-tracked library copies.** The fragment-consolidation fixer now marks a manual-only library copy as owner-applicable when every fragment is proven byte-identical to the parent by content hash and the fragment's own iTunes path is the only reason it was held (never an iTunes Media file, a book with an iTunes PID, Doctor Who / Big Finish, listening state or external ids). In Repairs such a row shows its proof and its own "Apply (owner)" button; the confirm names the book and says iTunes tracks the file and only database rows change. The apply retires the fragment row only (database rows, revertible from the operation), never writes the parent, files or iTunes, and journals an audit entry with the owner's user id. The new `POST /api/v1/repairs/:fixer/owner-apply` endpoint is honoured only for an admin's interactive sign-in (password/OAuth session or Cloudflare Access SSO) from the same origin; API keys, ABS tokens, temp-login and invite sessions are refused, and bulk apply, scheduled runs and resumed applies never include these rows.
- **Auth:** requests now record how they were authenticated (`session`, `session_delegated`, `api_key`, `cf_access`, `abs`), and sessions record their origin (password or OAuth login), so features can tell a person's own sign-in from an API key or a delegated login link.
