### Added

- An app that sets `app.Options.IdentityBoot` now serves core's identity routes. At P5 the kernel gives the router its auth service (`Router.SetAuth`), so every non-Public route runs stage 12 (authenticate) and then stage 13 (permission and interactive-method check, `owner.required=false` through `auth.Service.OwnerRequired`), and mounts the auth, module-catalog, UI, role, audit, settings and storage-reset routes on the core group and the OIDC routes on the fixed `/api/v1/auth/oauth` group. Stage 13's 403 refusals are audited as `core.permission.deny`. With the switch off, which is the default and what the audiobook app still passes, no identity route is mounted, the stage chain is unchanged, and a module's non-Public native route still refuses the boot with `ErrNoAuthService`.
- The factory-reset route stages through the running service: it takes the install ID from the open store, plans the hook under the reset's kept-path rule, refuses while any swap is staged, and asks the service to restart only after the reset is staged. The offline `storage reset` command shares its plan check and its staging step with it.
- The request's client address, peer, HTTPS flag and on-link flag now come from one resolver (`httpapi.ClientInfoFrom`), which is built on auth's own fallback and is never more local than it: a forwarding header is believed only from a trusted proxy, and a v4-mapped address is unmapped before the loopback and private-range checks.
- Task approve, reject and decide routes admit the user's own interactive session and an API key whose scopes name the required permission, and refuse a delegated session (SEC-24), as `taskhttp.Deps.VerifiedMethod`.
- `config.Store.ReadPermission` and `auth.Service.OwnerRequired` expose the per-key read permission and the owner-required setting to the routes that need them.
