### Fixed

- A book write that links a book to a series now checks that the series row exists. The two row writers (`createBook` and `updateBookLockedMode`, so `CreateBook`, `UpdateBook` and `ModifyBook`) do one point read of the series inside the book's write lock and refuse with `ErrSeriesNotFound` if it is gone. Before, a writer that had read series N before a `DeleteSeriesIfUnreferenced` and stored `series_id = N` after it left its book naming a deleted series, which every list then showed as having no series. The check runs only when a write makes a link, so a book that already names a missing series (older builds left some) stays editable and clearing the link is always allowed. A series held for an undo is a legal target. The split-version, split-file, split-to-one and M4B-transcode copies drop a deleted series from the copied book instead of failing the whole copy over a link the source had already lost.
- The Repairs series-prune fixer (`dedup.series-prune`) now deletes through the store's check-and-delete (`DeleteSeriesIfUnreferenced`) for both row kinds, the single-book orphan and the merged-away duplicate, instead of counting references and then calling the plain `DeleteSeries`. A book linked into the series after the plan, a rename or a re-author, or a row someone else already deleted settles the row as changed since the plan and keeps the series. A store that cannot verify a delete refuses the row, and a store that cannot count references right now is refused before a merge moves its first book, so a row is not left half applied.
- Reverting an operation now runs under the write-set the operation's definition declares. The revert is an HTTP request, not a dispatched operation, so the dispatcher's write-set gate never saw it: reverting a `maintenance.series-denumber` run could rewrite books and series beside `dedup.series-prune`, a series merge or a rename. The handler now takes the registry's write-set hold (`HoldWriteSet`) for the length of the revert. It answers 409, naming the writer, while a running operation or another revert declares an overlapping write; while it runs, the dispatcher keeps every operation whose writes overlap queued and starts them when the revert ends. An operation whose definition declares no writes is not gated, as in the dispatcher.
- Removed `database.SeriesRefCount`, the helper the series-prune fixer used to count a series' references before its delete. Nothing in production called it once the fixer moved to the check-and-delete, and the deadcode ratchet flagged it; the per-series counter itself (`SeriesBookRefCounter.GetSeriesBookRefCount`) stays.
