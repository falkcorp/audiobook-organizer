### Added

- core: `core/integrations/download` (dark), the media-neutral download-client contract of 05-download, phase 1 only (what ABO uses today). It declares the normalized item state machine (`State`, with unknown client values mapping to `StateWarning`, never `StateCompleted`), `Item`, `File`, `ItemFilter`, `ClientStatus`, `Caps`, the `Client` interface every adapter implements and the optional `FileLister` and `Relocator` capabilities, the typed `Adapter` constructor (the kind is always `download`), client-to-host path mapping (`PathMapper`, `Mapping` with a Fold option for Windows remotes: longest prefix on a separator boundary, UNC paths and `..` refused, an unmapped path fails closed), and the `Pool` (`Instances`, `Lease`, `Items`, `Files`, `Relocate`). The Pool fills each item's host path, caches an instance's `Caps` for an hour and drops the cache when the instance changes, refuses every call with no client call while integrations or the instance is disabled, validates a `Relocate` against every instance (capability and path mapping) before it sends anything, and then fans out over instances at a fixed bound. Two metric families, `mediacore_download_unknown_state_total` and `mediacore_download_unmapped_paths_total`, are pinned by `core/integrations/download/testdata/series.golden`. The Deluge adapter `core.deluge` (`core/integrations/download/deluge`) is HEAD's Web JSON-RPC client behind that contract: every call takes a context, requests leave through the instance's integrations client with a per-call 30 second limit instead of a five minute transport timeout, the re-login happens once per expired session however many callers hit it, Deluge's 0-100 progress becomes a 0-1 fraction, errors are classified (`ClassAuth`, `ClassNotFound`, `ClassBadOutput` and the rest) with a redacted body excerpt, and the Web UI password is read from core secrets at login time. Health only reads; connecting the Web UI to its first daemon happens in the instance test. It has no add and no remove (phase 2). `coretest.DownloadConformance` is the one suite every download adapter passes (state table, filters, status, files, relocate, auth failure and re-login, cancelled context; live mode behind `MEDIACORE_LIVE_DOWNLOAD=1`), and `coretest.FakeDownloadClient` is the in-memory client modules test against. Nothing registers `core.deluge` or builds a `Pool` until the integrations flip (F7-04). Path mapping refuses a path segment that is not one plain name in the destination's syntax (a Windows client path takes no backslash, slash, colon or NUL inside a segment; a host path takes no separator or `..`), then re-checks the result against the mapping root, in both directions. The Deluge client never follows an HTTP redirect, so `auth.login` cannot send the password to a host nobody configured (a 3xx is an error), and the password is scrubbed from any answer text kept in an error.
