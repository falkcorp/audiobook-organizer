### Fixed

- **Undo no longer reports success for changes it cannot restore.** The operation revert engine (`internal/audiobooks/revert.go`) failed each row whose change type it has no reversal for (`author_delete` from `maintenance.purge-empty-authors`, `maintenance.author-duplicate-merge` and the API author merge; `narrator_delete` from `maintenance.purge-empty-narrators`), then marked **every** row of the operation reverted anyway. Pressing Undo on a purge op therefore stamped its whole ledger as undone while nothing was restored. The engine now marks only the rows it actually restored (the store method `RevertOperationChanges(op)` is replaced by `MarkOperationChangesReverted(op, ids)`). An op with no restorable row is refused with a 409 naming the counts ("this operation's changes are a record only and cannot be undone automatically: N author_delete rows"). A mixed op restores what it can and returns `partial: true` with `restored`, `failed`, `not_restorable` and `not_restorable_types`. A restore that errors is no longer marked reverted either. The Operations indicator and the Activity Log now show the server's summary instead of "Operation reverted successfully", and they surface a refusal.
