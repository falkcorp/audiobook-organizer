### Changed

- A module's system actor now starts its own kind past the kind's `Start` requirement only when the executor itself began the start: the scheduler's tick for a kind that declares a Schedule, the outbox relay's dispatch of a declared consumer, or a child enqueued by a run of the same module that the system started. The kind carries `Permissions.SystemStart` (a reviewed reason; renamed from the earlier outbox-only flag) and the flag is never enough alone. A person's, an API key's and a module client's start of the same kind is judged on `Start` as before, and a child of a person's run keeps that person's authority. Every scheduled books and core kind whose `Start` includes an AuthRequired scope (the settings.manage expansion, backup create and verify, updater check) now carries the flag so its schedule can fire.
- Boot (P7) runs the executor's real start rule for every scheduled kind and every declared outbox consumer target, refusing a schedule that could never start, a consumer that targets another module's kind, and (once the outbox is wired) a flag with no declaration. The run record stores the origin of the start.
