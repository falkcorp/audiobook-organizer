### Added

- `internal/books/cutover`: `UnfoldAIBackend` and `FoldAIBackend(values, prev)`, the two converters between the retired `ai_backend.{embedding_mode, llm_mode, local_base_url, local_embedding_model, local_llm_model}` settings and the `ai_endpoints` instance list, which the Facade's five `ai_backend.*` rows (`internal/books/appconfig`) call: a read of the five settings is `UnfoldAIBackend` over the stored `ai_endpoints`, and a write of any of them is one `FoldAIBackend` of that list, admin-only, checked against the credential-egress rule, and a no-op when the list already reads that way. Until the config flip (F3-07 slice e8) the shipped binary does not reach them. The list is read by HEAD's seed mapping: the `local-llm` row exists when the URL is not empty and carries the URL and both models; a mode is the capability ticks on `local-llm` and, for the cloud modes, on the `openai` row, plus that row's priority (5 for fallback, otherwise 20), never `enabled`. A write changes only what it names; a write of what the list already reads, and every key not named, leave the list byte for byte as it was, and every other endpoint, and every `auth_ref`, is carried through unchanged. A mode that needs a row that is not there ("set the local server URL first", "set an OpenAI key first"), a URL with credentials or another endpoint's URL, a model with nowhere to live, an empty embedding model that would change the row, an unknown mode and a malformed list are refused with an error that names no value.
