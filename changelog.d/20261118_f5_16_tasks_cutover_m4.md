### Added

- The R2 tasks cutover's data step, M4, built dark (`internal/books/cutover/m4`, F5-16): it imports every stored operation record into the native task store (the v3 and v2 operation families, and the v1 `operation:`, `operationlog:`, `op_result:`, `opsummary:` and `opstate:` families), renames every stored kind reference through the kind-rename map, carries the schedule clocks, pause and stand-down markers, completion and revision stamps, and rewrites the `act:` activity feed in a second, non-cutover step. Runs are imported one at a time by parallel workers, each run's rows deleted in the same batch that writes it, so an interrupted boot resumes from the top. A run's log lines (v3, v2 mirror and v1) are numbered 1..n in time order, so lines HEAD numbered from a counter that restarts every boot no longer replace one another; an item with two outcomes keeps the later chunk's and carries the other whole; a run whose pages would still collide is quarantined. The activity step renames a repairs row (`repairs.plan`, `repairs.apply`) to its run's `books.repairs.<fixer_id>` kind through the task store, and holds a row whose run is not there. Rows that cannot be imported are set aside in the quarantine with a reason, never dropped. Nothing registers the step yet (F5-18 does), so no production behaviour changes.
- The kind-rename map of the R2 tasks cutover (`internal/books/cutover/kindrename`): HEAD's 269 stored operation IDs and its scheduler task names mapped to the task kinds the native engine will register, generated from the op-ID ledger, a checked-in dump of the booted registry's alias table, the retired-ID list and the scheduler's task table. A test fails when the generated file differs from a fresh run.
- An R2 corpus slice for M4 (`internal/books/testdata/r2corpus/m4`): hand-built overlay cases beside the R0-written stage-1 feed, with the expected counts of every family checked into `answers.json`.

### Changed

- The deadcode baseline lists M4 and the kind-rename map's 75 identifiers (like M3's) until F5-18 registers the step; the opv2 row-key guard allowlists M4's frozen copy of the `opv2:op:` prefix as a read-only declaration.
