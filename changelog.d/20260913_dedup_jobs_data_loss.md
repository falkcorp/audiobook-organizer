### Fixed

- `maintenance.dedup-books` now really moves a duplicate's file rows to the book it keeps (`MoveBookFilesToBook`). Before, the "move" was a no-op, so the duplicate was soft-deleted while it still owned the files and still named the kept book's path. A purge with delete-files on could then delete the kept book's audio. Now a failed move fails that pair and nothing is soft-deleted. A duplicate is retired only after a check that it owns zero file rows, and its `file_path` is cleared when it is. A "read by narrator" junk row whose path is shared with a live book (the same path, a file row another book owns, or one of its own rows at a live book's path) is also retired with its path cleared. Books under the iTunes library (`books/itunes/**`) are refused. The kept book is the version group's primary whenever one of the pair is primary. A successor is promoted only after the files have moved, right before the duplicate is retired, so a failed step never leaves a group with two primaries or none. A run interrupted part-way converges on a rerun. Every book write goes through `ModifyBook`. Dry-run applies the same checks and tracks the retirements and promotions it would make, so a later primary hand-off in the same dry run matches apply. A run with failed writes now reports failure.
- `maintenance.fix-version-groups` no longer deletes a book's file rows and recreates them from a disk scan when it moves the book out of an author folder. That rebuild lost fingerprints, transcripts, durations, iTunes PIDs and track numbers. Now existing rows are repointed in place, but only when the old file is gone and the new file has the recorded size; a matching file name alone is not enough. Rows are created only for files that have none, and files another book owns are left alone. The job refuses a target folder with no audio, a match it can't tell apart because two rows share a file name, and a target where no file could be verified as the book's. It also refuses books under the iTunes library. Unlinking a mismatched title from a version group no longer leaves either group without a primary.
- `dedup.quarantine-chapter-artifacts` no longer soft-deletes a version group's primary while the group keeps members that aren't artifacts. The decision is made per group over the whole set of artifacts, so two artifact primaries of one group can't both be removed. A retired primary is demoted. The op also skips books under the iTunes library. Soft-deletes go through `ModifyBook`, and failed writes or unreadable file lists are counted and fail the operation instead of only being logged.
- The iTunes-library guard resolves symlinks for both the checked path and the configured roots. For a path that doesn't exist yet, it resolves the nearest existing parent. So a link outside `books/itunes/` that points into it is refused.
