### Fixed

- `maintenance.dedup-books` now really moves a duplicate's file rows to the book it keeps (`MoveBookFilesToBook`). Before, the "move" was a no-op, so the duplicate was soft-deleted while it still owned the files and still named the kept book's path. A purge with delete-files on could then delete the kept book's audio. Now a failed move fails that pair and nothing is soft-deleted. A duplicate is retired only after a check that it owns zero file rows, and its `file_path` is cleared when it is. Books under the iTunes library (`books/itunes/**`) are refused. The kept book is the version group's primary whenever one of the pair is primary, and a primary is never retired until a successor has been promoted. Every book write now goes through `ModifyBook`. Dry-run applies the same checks, so its counts match what apply would do. A run with failed writes now reports failure.
- `maintenance.fix-version-groups` no longer deletes a book's file rows and recreates them from a disk scan when it moves the book out of an author folder. That rebuild lost fingerprints, transcripts, durations, iTunes PIDs and track numbers. Now existing rows are repointed in place. Rows are created only for files that have none, and files another book owns are left alone. The job refuses a target folder with no audio, or a match it can't tell apart because two rows share a file name. It also refuses books under the iTunes library. Unlinking a mismatched title from a version group no longer leaves either group without a primary.
- `dedup.quarantine-chapter-artifacts` no longer soft-deletes a version group's primary while the group has other members. It also skips books under the iTunes library. Soft-deletes go through `ModifyBook`, and failed writes or unreadable file lists are counted and fail the operation instead of only being logged.
