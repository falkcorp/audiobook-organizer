### Fixed

- `maintenance.dedup-books` now really moves a duplicate's file rows to the book it keeps (`MoveBookFilesToBook`). Before, the "move" was a no-op, so the duplicate was soft-deleted while it still owned the files and still named the kept book's path. A purge with delete-files on could then delete the kept book's audio. Now a failed move fails that pair and nothing is soft-deleted. A duplicate is retired only after a check that it owns zero file rows, and its `file_path` is cleared when it is. Every "read by narrator" junk row is also retired with its path cleared, so a purge deletes nothing through it. A junk row whose own file rows name a live book's file, or sit inside a live book's folder, is refused and left alone; that check uses every live file row, not the one-owner-per-path index. Books under the iTunes library (`books/itunes/**`) are refused. The kept book is the version group's primary whenever one of the pair is primary. A successor is promoted only after the files have moved, right before the duplicate is retired, so a failed step never leaves a group with two primaries or none. A run interrupted part-way converges on a rerun. Every book write goes through `ModifyBook`. Dry-run applies the same checks and tracks the retirements, promotions and version-group joins it would make, so its primary hand-offs match apply's. A run with failed writes now reports failure.
- `maintenance.fix-version-groups` no longer deletes a book's file rows and recreates them from a disk scan when it moves the book out of an author folder. That rebuild lost fingerprints, transcripts, durations, iTunes PIDs and track numbers. Now existing rows are repointed in place, but only when the old file is gone and the new file has the recorded size; a matching file name alone is not enough. Rows are created only for files that have none, and files another book owns are left alone. The job refuses:
  - a target folder with no audio;
  - a match it can't tell apart because two rows share a file name;
  - a book with rows, none of which is kept or verifiably repointed into the target, since moving its path would strand them;
  - books under the iTunes library.

  Unlinking a mismatched title from a version group no longer leaves either group without a primary.
- `dedup.quarantine-chapter-artifacts` no longer soft-deletes a version group's primary while the group keeps members that aren't artifacts. The decision is made per group over the whole set of artifacts, so two artifact primaries of one group can't both be removed. A retired primary is demoted. The op also skips books under the iTunes library. Soft-deletes go through `ModifyBook`, and failed writes or unreadable file lists are counted and fail the operation instead of only being logged.
- The iTunes-library guard resolves symlinks for both the checked path and the configured roots. A dangling link is followed to its target, and a path that doesn't exist yet is resolved through its nearest existing parent. So a link outside the library that points into it is refused, even when the configured root is itself a link. Roots are resolved once per check, not once per file.
