- New Repairs fixer, "Duplicate copies". It finds whole copies of one book that live as separate books, so a chapter fragment that matches every copy is listed as ambiguous by the fragment fixer and never applied. Two books count as copies only when every clause holds: at least 90% of the smaller copy's audio is hash-identical to the other (files under 60 seconds and intro/credits titles never count), the titles match after a leading track number is stripped, the authors match or one is unknown, the ASINs do not conflict, and no not_dup label exists on the pair. Durations do not have to be close: a short copy contained in a full one is exactly the case to fix.
- Apply keeps the best copy (organized with every file present under the library root, then most present files, longest present audio, not under "Unknown Author", already primary, best metadata), repoints its missing files at a copy's present twin, folds in a file it lacks when the file is on disk and the track numbers then run without a gap (at most 25% extra audio), and retires the other copies into it: listening progress, external ids and version-group primacy follow, and the retired copy keeps its file rows. Database only. Every step is undoable from the apply operation.
- iTunes copies are ignored, never elected and never written (owner decision). A row whose version-group hand-off would change an iTunes copy's primary flag is skipped. Doctor Who / Big Finish / Torchwood stay manual-only.
- Listed, never applied: unproven copies (same title, audio not proven identical), conflicting ASINs, not_dup labels, groups that are not all proven copies of each other, no eligible survivor, a copy with listening progress whose track layout differs, a file that cannot be folded, too much folded audio, a copy with user tags the survivor lacks, no primary heir, unreadable state.
- The fragment fixer now treats a fragment that matches exactly one non-iTunes parent plus iTunes copies of it as having that single parent. It applies only when the fragment itself is not an iTunes copy, and the iTunes copies are never written.
- The fragment fixer's plan takes a read-only `assume_retired` param (losers mapped to survivors, plus the rows to fold): every row of such a plan is skipped and records the outcome it would have had, to measure the unlock before anything is applied.
- Undoing a file repoint now hands the file-path index back to the other row that still names the file, so after the undo a lookup by path finds it again (affects the fragment fixer's moved class too).
- The fragment fixer's retire step moved to a shared helper used by both fixers; its behaviour is unchanged.
