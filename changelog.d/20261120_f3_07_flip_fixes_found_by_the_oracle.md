### Fixed

- Upgrading to the build that moves settings into the shared configuration no longer turns OAuth sign-in off. The upgrade wrote each sign-in provider without the fields the configuration schema requires on every provider entry, the schema refused the whole list, and the upgrade set the list aside (sealed) and left sign-in disabled. Entries now carry every required field, and a test boots a store that uses every setting and compares the resulting configuration with the one the previous build loads from it.
- The scheduled tasks no longer read two settings the upgrade drops. A task's "run on startup" flag and the weekly full scan's check interval have no equivalent in the shared configuration (a task declares its start trigger in code, and the full scan's period is its `every`), so after the upgrade they read as off and zero: the full scan's hourly due-check never ran. The due-check is now fixed at one hour, the task settings page answers 400 with a hint when asked to change either setting (it used to answer 200 and change nothing), and the library scan keeps `scan_on_startup`, the one start setting that carries over. The release note lists every dropped name.
