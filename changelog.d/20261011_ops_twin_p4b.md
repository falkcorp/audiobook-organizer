### Changed

- `scheduler.purge-deleted` is merged into `maintenance.purge-deleted`. Both ran the same purge of soft-deleted books under two IDs and two concurrency keys, so both copies could run at once. The scheduled `purge_deleted` task now enqueues the `maintenance.*` op, and the old ID keeps working as an alias, so stored rows and API callers still resolve. The surviving op now requires `settings.manage` (it deletes books and files) and keeps the 2h budget the scheduled copy ran with, up from 30 minutes. The purge now receives the op's own context, so that timeout and a cancel actually stop it between books; previously the maintenance copy ignored both.
