### Fixed

- The shared raw transport of the core web clients (`web/src/services/coreHttp`, used by `coreUpdater` and `coreBackups`, still unwired) now keeps its deadline and the caller's abort signal live while the response body is read, not only until the headers arrive. A server that sent the headers and then stalled the body used to hang `res.json()` and the problem decoder for ever, past `timeoutMs`; it now ends in `ApiTimeoutError` (the deadline) or the caller's own `AbortError`, never a "the answer is not JSON" protocol error, and an error answer with a stalled body ends the same way instead of as a refusal that carries the status alone. The timer and the abort listener are released when the body ends, is cancelled (`discardBody`, which the clients call before they throw a status or content-type mismatch) or is aborted. A call with no deadline (import, restore, revert) is still ended only by the caller's signal.
- `BACKUP_REFUSAL_CODES` also lists the generic codes any backup route can answer with: `internal`, `not_found`, `method_not_allowed`, `conflict`, `precondition_failed` and `throttled`.
- Tests: the 200 text/html bounce is now also checked never to read `response.redirected`, on the response the transport builds as well as the one fetch returned.
