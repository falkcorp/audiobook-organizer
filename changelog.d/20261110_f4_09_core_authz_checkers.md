### Added

- core: `core/internal/authz` (dark), the implementation of `rbac.Checker`: `authz.Compile`, the compiled checker the kernel will inject as `rbac.Deps.Compile` (wildcards, implication, a key's checker as role ∩ key with the admin flag only when the key names `core:admin`, Sensitive scopes refused to non-interactive principals before admin, confinement decided on the effective set); `authz.AuthDisabled`, the auth-off principal (no `core:admin`, no `AuthRequired` or `Sensitive` scope, and the auth-off rule that drops `AuthRequired` members from an `AllOf`); and `authz.ForSystem(cat, perms)`, the background-task principal holding exactly its declared scopes, which refuses a Sensitive scope it was given (a module's as well as core's) because every check runs through the catalog as a non-interactive principal. Every checker fails closed: an undeclared scope is held by no one, admin included; a missing catalog, or a system scope set naming `core:admin`, a wildcard or a restricted core scope, yields a checker that holds nothing. A new guard, `archtest.NoSystemPrincipalOutsideKernel`, lets only `auth`, the tasks executor and `kernel` import `authz` at all (so `Compile`, which can mint an interactive admin checker, is fenced too), refuses any `//go:linkname` naming it, and keeps `rbac` from importing it. 05-rbac §3.4 and §12 are amended to match. The shared matching vectors live in `core/rbac/testdata/match_vectors.json` (F4-09; nothing calls `authz` until F4-08).
