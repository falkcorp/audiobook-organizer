Every way of combining books can now be undone with Operations > Revert (`POST /api/v1/operations/:id/revert`), not just through `POST /merge/undo/:journal_id` and `POST /merge/sibling-undo/:journal_id`, which #4060 retires. The merge cores now write an undo pointer to their own journal at the point each journal is written, before the first change. A combine or sibling move whose pointer cannot be written is refused.

- Operations that merge books record that pointer under their own operation id, so reverting the operation undoes every merge it made: merge-chapter-groups, dedup.split-book-bulk-merge, dedup.book-merge, maintenance.merge-same-path-dupes and the iTunes heal duplicate collapse.
- Merges that no operation runs get an operation id of their own: the manual combine, the split-book candidate merge, the review combine and duplicate-of applies, diagnostics merge_versions, and the dedup engine merges. `POST /audiobooks/combine` and `POST /dedup/split-book-candidates/:id/merge` return it as `operation_id`. Diagnostics returns it as `sibling_operation_id`. GET /audiobooks/:id/changes lists it on the surviving book.
- A new `merge_sibling_journal` revert type puts moved version-group siblings back. As with the retired route, the merged books stay in the trash.
- New maintenance job `backfill-merge-undo-pointers` gives older journals the same pointer, each under a fresh id. It previews by default.
