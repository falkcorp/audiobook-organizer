### Fixed

- Moving a book between version groups could slip between `itunes.regroup`'s apply-time recheck and its moves. A batch edit that set `version_group_id` or `is_primary_version`, a version link or set-primary from the versions page, or a scanner version link could make the regroup target a group's primary after the recheck had cleared it, and the iTunes files would still land on it. These writers now take the shared version-group hand-off locks of the group the book leaves and the group it joins, across the write. A batch edit whose book changed group since it was read is retried from a fresh read. The versions page's link and set-primary used their own private locks, which serialized only each other; they now share the hand-off locks, so they also exclude primary hand-offs. The regroup lock test now starts its competing hand-off while the recheck is reading the group, so a lock taken only after the recheck fails it. Splitting a version off a book now takes the same locks for the source's group and the group a split would mint, across the mint, the new member's creation, the row move and a failed split's rollback; a split whose source was grouped by another writer in the meantime is refused with 409 `split_source_grouped`. Each versions-page handler releases the locks before writing its response, so a slow client never holds them.
