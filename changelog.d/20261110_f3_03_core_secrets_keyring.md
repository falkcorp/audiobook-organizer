### Added

- Core: `core/secrets` is now the secret store (platform-core F3-03), shipped dark. It keeps one keyring file, `secrets.keyring` in the state directory (owner-only permissions, written atomically), with exactly one active data key and one active derive key. Each secret is sealed with AES-256-GCM, bound to its name and the app, so a record copied to another name or app does not decrypt. Opening the store never deletes anything: a lost keyring with stored secrets refuses to start unless key regeneration is allowed, and then the old records are kept as "must be re-entered". It also provides operator-only values that are never saved, a create-only importer for the cutover, derive keys with rotation and in-memory retirement, the `mediacore.secrets` metrics, and the `core.secrets` health tokens (`secrets_undecryptable`, `derive_key_retire_blocked`, `secrets_keyring_not_exported`). No boot opens the store until F3-07, so nothing on disk changes.
- Core: three offline commands. `secrets export-keyring --out <file>` copies the keyring to an owner-only file and records which keys it holds. It opens no store, so it works while the service runs. `secrets rotate-derive` adds a new derive key and keeps the old one for verification. `secrets set-install-id --install-id <id>` puts the keyring header's install ID back after a factory-reset undo. The last two run only with the service stopped. All three run only as the state directory's owner.
- Core: `core/internal/keyedmutex`, a per-key mutex copied from ABO, which serializes writes to one secret name.
- Core: `core.http.basic_gate.password` is declared as a secret setting (admin-protected). The OIDC `client_secret` is not declared yet, because the config engine cannot bind a secret inside a list entry.
