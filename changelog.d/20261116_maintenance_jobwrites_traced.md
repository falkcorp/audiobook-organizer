### Fixed

- The write sets of the 34 native maintenance job kinds (`jobWrites` in `internal/maintenance/jobs/kinds.go`) are now derived from the one method-to-resource table the converted maintenance groups use, instead of a second hand-written list that disagreed with it. The table moved to its own package, `internal/maintenance/resources`, so both families of kinds read the same rows without importing each other. `enrich-book-files`, `recompute-itunes-paths`, `backfill-book-files`, `bulk-deluge-import` and `scan-composer-tags` write book rows (a file-row method recomputes the books aggregate through `ModifyBook`) and now declare `books`; every job that calls a `ModifyBook`-family method also declares `authors`, `metadata_cache` and `indexes`, which the store writes underneath the call. 20 of the 34 jobs changed, 14 did not. The kinds are not registered yet (F5-18 registers them), so no running job changes behaviour today; at the cutover the wider sets make more job pairs wait for each other. The SSA oracle test now finds the store methods each job reaches and checks them against the table, so the two cannot drift again.
