### Added

- Core auth: an invite that an admin mailed to its address now binds that address to the new account as verified when it is accepted, in the same write as the account. An invite is flagged as mailed only through the new admin call `MarkInviteEmailDelivered` (core:admin, interactive sign-in, an open invite that names an address; a repeat call changes and records nothing). The accept binds only when the invite is flagged, its creator still holds core:admin, and no other account holds the address verified; it then takes the address from accounts that only typed it in, records the binding in the accept's audit entry and reports it in the `InviteAccepted` hook. An accept that does not bind leaves the address unverified and touches no other account. Creating an invite for an address another account holds verified is refused, as the previous server did.
- Core auth admin calls for a module that serves the admin screens: `SetUserEmail` (core:admin, interactive, over a user the caller dominates; the address is stored verified, an empty address clears it, an address another account holds verified is refused, and no sign-in is ended by it), `RotateInvite` (replaces an open invite with a new link for the same username, address and role and exactly the same expiry, in one write, so a failed replacement leaves the old link working), the actor-checked reads `Invite` and `AdminInvites`, and `AdminUser` and `AdminUsers` (users.manage, interactive; the records carry no password hash, token or key). `CreateInvite` and `DeleteInvite` now decide on the signed-in caller of the request and refuse when the request carries none or a different one.
- New audit actions `core.invite.mark_delivered`, `core.invite.rotate` and `core.user.set_email` (user-scoped).
- The account lifecycle hook gains `UserDeleted` (fired after a user delete commits, with the address the account held) and `UserMergedAway`.
