### Fixed

- The restore staging sweep from #4940 no longer treats a bare `restore/<id>` as proof of a linked intent. `Stage` creates `restore/<id>` before it links the intent, so a kill between the two leaves an empty `restore/<id>` beside the staged key copy. The sweep read that directory as "an intent was linked" and passed over the staging silently, forever. A linked intent is now one whose `journal.json` exists or that the slot names. An empty `restore/<id>` that is a real directory and that the slot does not name, beside a staging-only `.mediacore-restore/<id>`, is removed first, then the staging. Any other `restore/<id>` (holding a stray file, or a symbolic link) is left in place with its staging and named in a warning. The kill matrices' orphan check uses the same rule.
