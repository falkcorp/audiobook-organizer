### Changed

- The `model` label of the `ai_*` metrics now always names the models configured in settings and folds every other model to `other` (owner decision on AI-MODEL-LABEL-CAP-POLICY). Before, the first five distinct models a process happened to call were named, so a settings experiment could leave the model actually serving traffic as `other`, and which models were named changed with which task ran first after a boot. Now the named set comes from `filename_parse_model`, `metadata_review_model`, `cover_art_model`, `dedup.review_model`, the embedding model and, with routing on, the enabled pool rows' chat, embed and per-capability models, and it is filled at first use and again whenever settings are saved, so the same settings name the same models after every restart. A model replaced in settings keeps its name until restart (its series stays exported), and the set is still bounded to five pairs per process, so the 945-series worst case is unchanged; a configured model past that bound is `other` and logs a warning until restart. An empty model is now labelled `other` instead of `unknown` (the trace span still says `unknown`), which frees the slot it used to take and keeps the series cap. New `config.Generation` counter moves on every `config.Mutate`.
