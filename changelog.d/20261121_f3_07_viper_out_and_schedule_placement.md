### Changed

- Config flip (F3-07), slice 4: viper is gone from production code. `internal/config` no longer has `InitConfig`, `registerConfigDefaults`, `configFromViper`, the viper decode helpers, the removed-key warnings, the ABS/invite registrars, `parseEnvBool` or `DefaultSMTPPort`. `internal/dedup/unified.LoadScoreConfig` no longer reads `dedup.signals.*` from viper, so per-kind base/scale/boost overrides set in `config.yaml` are no longer read. The defaults, the `ScoreOverrides` argument and the stored settings are what it uses. `internal/arch` `TestNoViperImports` fails a production file that imports viper again. Viper is still a test-only dependency of two cutover oracle tests, which hold M2's reading of HEAD's `config.yaml` against viper's own decoding.
- `config.ResetToDefaultsForTest` now restores `internal/config/factory_defaults.json`. That file is generated from the books settings projection by `TestFactoryDefaults_Golden`, which also fails when the file is stale (regenerate with `go test ./internal/books -run TestFactoryDefaults_Golden -update-factory-defaults`). It replaces the second copy of the defaults that the viper registrar held.
- `deploy/retired-env-names.txt` is regenerated and says `enforced: true`, because the app has handed the retired names to core since slice 3. From now on `make deploy` refuses a `deploy/local.conf` that still sets a name the new binary refuses at boot. Before the flip deploys, rewrite `local.conf` with the rename map.
- `store.VerifyStoreOpens` is deleted. The restore stager uses `VerifyStoreOpensWith`. The books scan default for supported extensions is `audioext.Default()`, and the `metadata_fetch` defaults come from `config.DefaultMetadataFetchConfig`, so each default exists only once.

### Fixed

- A settings blob without `metadata_sources` once again means HEAD's six default sources, with Audible, Open Library and Audnexus enabled. After slice 3 it projected an empty list, so an install that had never saved its sources had none. The list is `config.DefaultMetadataSources()`, carried in the books projection base. A stored list, even an empty one, still replaces it.
- The config cutover (M2) keeps each scheduled task's nightly-window membership. Config stores a schedule key as one whole value, so a converted value holding only `enabled` and `every` took reconcile, dedup_refresh, author_split, series_prune, db_optimize and library_scan out of the window. Each rename-table schedule target now carries the placement from HEAD's maintenance order (window `nightly`, position 0/1/3/4/17/19). `Convert`/`Unconvert` take the target, write that placement, and accept nothing else. Books' six schedule defaults carry the same placement.
- M2 no longer quarantines (and so turns off) the following scheduled entries:
  - An entry that is enabled with interval 0 for a window task now runs window-only, as it did in HEAD.
  - `ai_dedup_batch` with interval 0 is now daily, HEAD's fallback (new converter `schedule-zero-daily`).
  - An entry enabled with no interval and no window never ran in HEAD. It is now carried disabled, and its `enabled` is reported as dropped.
- `scheduled.library_scan.enabled` moves to its own key, `modules.books.scan.periodic_enabled` (default true). The library_scan schedule key stays enabled with its interval and window, and the runtime gates read the new key, so HEAD's rules (timer = enabled; window = toggle and (enabled or scan_on_startup)) hold on every path. A HEAD-shaped save of the whole `scheduled.library_scan` entry reaches the new key: the settings write path now splits a holder value into the rows inside it.
- The M2 report counted every quarantined row twice. The second count was filed under the settings row's key, so the report showed an unnamed quarantine that did not exist.
