### Added

- core: the fresh task executor, `core/internal/executor` (dark: ABO builds none until F5). It provides one `WriteRuns` path with compare-and-swap transitions and fence epochs; the dispatcher and its gates (ready signals, pause, held, concurrency key, write set, module cap, zombie cap, stand-down, `NotWhile`, worker slots); `RunHost` for `tasks.RC`, items and the per-run writer; the resume sweep, its four policies and HEAD's supersession of stale quiesced runs; cancel with grace and zombies; the watchdog; bounded shutdown with one systemd extension for Uninterruptible runs; the Batch runner and its chunk ledger; Fixer plan, approve and apply with row marks; stand-down holds, lanes and ref locks; and the 18 `<ns>.ops` instruments. A plan's apply run starts only through Approve, which needs `Perms.Approve` and a caller identity (and `Perms.Start` for the run it starts). A plan is decided once: a second approval or a reject after an approval is refused, concurrent approvals start exactly one apply run, and an approval always starts a new run, never folding into another. An apply run applies only the plan its approval names; without one it applies nothing, and a rejected plan is refused. A Fixer whose `Approval` does not require a plan is refused at registration. A run's writer refuses every write once the run is canceled, timed out, quiesced or shutting down. A run canceled after its claim but before its body started never starts its body, and a claim that lands while a stand-down holds its key waits for the hold. A failing `OnTerminal` hook no longer keeps a run from ending: the run ends without the notification, and the failure is recorded on the run. A cancel is final, even against a run stopping for a stand-down or a shutdown. A run that was claimed but had not started when shutdown began goes back to the queue instead of starting. Also new: `core/tasks/taskstest/parity`, which runs HEAD's resume, cancel and shutdown tests as behaviour oracles against the executor; an executor cell in `TestABOMetricsGatherNoDuplicate`; `tasks.ItemsOptions.PartitionBy`, so each item of a partition keeps its own `ItemTimeout` clock and counts; and a `core/tasks` fix that refuses a parent's `LockRefs` while a nested item holds a run-table lock (F2-03).

### Fixed

- core/storage: a second `GetForUpdate` of a key in one batch no longer replaces the first read's precondition with a value committed since. Previously a batch whose writes were built from the first read could commit over the newer value, and two concurrent approvals of one task plan both succeeded (F2-03).
