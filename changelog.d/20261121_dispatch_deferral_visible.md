### Added

- The task executor (dark until the flip) makes a write-set or concurrency-key deferral visible. A queued run that a dispatch gate holds now reads back, through the run view and the run payload (`deferred`, `blocked_by`, `deferred_since`), with the gate's reason, the running run behind it and when its unbroken wait began. The fields are computed at read time from the last dispatch pass and are never stored, so dispatch writes no run row. The blocking run's ID is shown only to a caller who may view the blocker's kind, and never on the realtime stream; the reason and the start of the wait are shown to anyone who can see the run. A new gauge, `dispatch_wait` (seconds, by `def_id`, `reason` and `trigger`), reports the longest wait of a registered kind, so a scheduled kind queued behind a manual one can be alerted on once the executor serves metrics. Which runs are deferred is unchanged. The `dispatch_deferred` counter no longer counts a canceled run a second time when the cancel lands while a dispatch pass is holding the run as a candidate.
