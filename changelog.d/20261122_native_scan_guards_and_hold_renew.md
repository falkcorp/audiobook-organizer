### Changed

- Groundwork for the tasks cutover, not yet reachable: the native stand-down hold can now be renewed by the run that holds it (`Hold.Renew`) and by the run's progress reports, its lease is 5 minutes as before the cutover (the kernel's `core.tasks.standdown_lease` default had said 2 minutes, so the executor never ran on 5), and a lapsed lease cancels the run and stops its writes (a renewal, the reaper and a new hold on the same key reaching the same expired lease can no longer both win, and a run whose hold lapsed ends failed, never succeeded). The native folder-cover and chapter-folder repair now park the library scan for their live applies, and those two, the iTunes clone and the missing-file repoint wait while a library scan runs. A continued transcribe-file-intros attempt queued behind a scan now waits before it starts instead of inside the run. The chapter-folder repair's abort now says whether the scan stand-down lapsed or its marker could not be written. Nothing changes for the running server.
