### Changed

- A task run's actor now records the API key it was started with (`tasks.Actor.CredentialID`: the key's id for any key-bound principal, core's api_key method and every module compat surface built over a key alike; empty for sessions and every other principal; never key material, never logged at info level, and not part of the run's wire form), and `auth.Principal` gains an exported `KeyRef()` that reports the key behind such a principal (F5-18). The diagnostics export's viewer resolution (`diagnosticsViewerFor`) decides on the credential and not on the method's name: an actor with a credential id has its key read again when the run builds its bundle, a missing, revoked, not-active, expired or other user's key ends the run, and a key whose scopes changed since the run started narrows the bundle to the user's current roles within the key's current scopes, non-interactive. An actor with no credential id is resolved as before only when its method is session, session_delegated, auth_disabled or system; a token actor with no id, and any other method with no id, is refused. The same-actor rules (a starter may cancel its own run, same-actor dedupe) still compare the person and method only, so a new sign-in or a rotated key does not change who counts as the starter. A run stored before this change decodes with an empty credential id.
