### Changed

- A task run's actor now records the API key it was started with (`tasks.Actor.CredentialID`: the key's id for any key-bound principal, core's api_key method and every module compat surface built over a key alike; empty for sessions and every other principal; never key material, never logged at info level, and not part of the run's wire form), and `auth.Principal` gains an exported `KeyRef()` that reports the key behind such a principal (F5-18). The diagnostics export's viewer resolution (`diagnosticsViewerFor`) decides on the credential and not on the method's name: an actor with a credential id has its key read again when the run builds its bundle, a missing, revoked, not-active, expired or other user's key ends the run, and a key whose scopes changed since the run started narrows the bundle to the user's current roles within the key's current scopes, non-interactive. An actor with no credential id is resolved as before only when its method is session, session_delegated, auth_disabled, system, or an identity extension's or module compat surface's method that is registered with auth (an exact name match; the method's own Interactive flag is never honoured, so only a core session is compiled interactive); a token actor with no id, and any method that is not registered, is refused. The same-actor rules (a starter may cancel its own run, same-actor dedupe) still compare the person and method only, so a rotated key, or a second key of the same user, does not change who counts as the starter. Client.Get, Runs and Timeline return a run's actor without the credential id; only the run's own `rc.Actor()` and the stored record carry it. A run stored before this change decodes with an empty credential id.
