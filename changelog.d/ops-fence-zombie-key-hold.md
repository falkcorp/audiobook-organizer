### Fixed

- A stopped operation can no longer keep writing. Every run now carries a revocable write permit (`registry.Fence`), revoked before its context is canceled on every stop path: user cancel, timeout, watchdog kill, scan stand-down quiesce, shutdown, abandonment and a lost stand-down lease. The Repairs `Writer` checks it before every write, so a canceled apply that does not stop when asked is refused with `registry.ErrFenced` instead of retiring more books.
- The Repairs apply loop now checks for cancel before every row, not only between partitions. Rows not started when the apply was canceled are reported `canceled_skipped`. They are not checkpointed, so a resume checks them again. This closes the 2026-10-01 shape, where an apply kept writing after Cancel until a restart.
- A run whose goroutine outlives the 5 s abandon grace (a zombie) now keeps its `ConcurrencyKey` and declared write set until the goroutine really returns, so a second run of the same def waits instead of overlapping it. Its worker slot is still freed at the grace, and its row still becomes terminal at abandonment. `Registry.Zombies()` and `ZombieCount()` list zombies, and the watchdog logs a WARN once a zombie is 10 minutes old, then once a minute. Cancel on a zombie is a no-op. Shutdown no longer stamps `interrupted_*` over a zombie's terminal status. The `abandonedAlive` side map is gone, because the zombie's handle now carries that state.
