### Added

- New maintenance operation `maintenance.credits-backfill` fills in and tidies each book's author and narrator credit lists so they agree with the book's single author and narrator fields. It is a dry run unless started with `apply`. It fills an empty author list from the book's author, adds that author at the front when the list leaves them out, numbers list positions 0, 1, 2, and so on, fills an empty narrator list from the narrator field or the stored narrator list, and refreshes a stale author snapshot. Anything ambiguous (a missing or merged author record, a combined "A, B" author record, a narrator field that disagrees with the list) is listed for review and not changed. The operation never creates an author. It creates a narrator only for a single unsplit name or a stored list entry, and a name that exists only after splitting a string needs the `narrator_new_from_split` opt-in. iTunes books need the `itunes` opt-in and owner-manual books are held. Each written book is journaled, so the operation can be reverted. The revert refuses a book that changed after the run. Results list each class with its book ids and before/after samples, and show which books would file under a different author.
