### Added

- New maintenance operation `maintenance.credits-backfill` fills in and tidies each book's author and narrator credit lists so they agree with the book's single author and narrator fields. It is a dry run unless started with `apply`. It fills an empty author list from the book's author, adds that author at the front when the list leaves them out, numbers list positions 0, 1, 2, and so on, fills an empty narrator list from the narrator field or the stored narrator list, and refreshes a stale author snapshot. Anything ambiguous (a missing or merged author record, a combined "A, B" author record, a narrator field that disagrees with the list) is listed for review and not changed. The operation never creates an author. It creates a narrator only for a single unsplit name or a stored list entry, and a name that exists only after splitting a string needs the `narrator_new_from_split` opt-in. iTunes books need the `itunes` opt-in and owner-manual books are held. Each written book is journaled, so the operation can be reverted. The revert refuses a book that changed after the run. Results list each class with its book ids and before/after samples, and show which books would file under a different author.

### Changed

- The `maintenance.credits-backfill` review pass: a book whose author field a person has locked is now held on the whole author side, and a book whose narrator field is locked is held on the narrator side (`held_narrator_user_locked`). Placeholder authors such as "Unknown Author" and junk narrators such as "N/A" are listed for review instead of being written. A narrator name is matched without regard to accents, and a name that matches two records is listed for review. Where a later rescan moved the author (the book's author snapshot names a different credited person than the author field), the author is no longer put first; the book is listed under `author_id_snapshot_conflict`. This also covers a book with an empty author list whose snapshot names a different author than the author field: the organizer files such a book under the snapshot, so it is held and its snapshot is left alone. The signal is the snapshot only: a book whose list positions all tie and whose snapshot does not disagree is still numbered with the author field first, as before.
- Reverting a `credits_backfill` write restores the authors in the order they were stored in, so the book files under the same author folder as before the run. The revert used to renumber by the canonical order, which could move the filing author.
- `limit` now means the first N eligible books by id, in a dry run as well as an apply, so a dry run with a limit shows exactly what the apply with that limit writes.
- The operation declares a books write, so it is gated like the other book-writing operations, and its description says so.
- A write the run refuses (the book changed since the plan) or that fails now voids its own journal row, so the revert refuses it and a resume does not see a stranded row. `narrators_created` counts only narrators whose book write landed.
- The result reports `books_eligible` and `books_to_reidentify`, with the ids under `search_identity_changes`: the books whose author search identity changes and which will spend Google Books quota (1,000 requests a day) at their next metadata run. The class lists in the result are not capped, as in the credit census; each count clicks through to its ids. A full apply lists about 150,000 to 300,000 ids in the result, roughly 5 to 9 MB.
- The `maintenance.credits-backfill` apply now holds the library scan down for its whole run, not only for the writes. Planning a full library takes longer than the five-minute hold, which used to lapse before the first write, so the run wrote nothing and every re-run did the same. The hold is renewed on every book. If it is lost anyway the operation reports "scan stand-down lease lost" instead of "context canceled".
- A narrator name that matches an existing record only without its accents (for example "Renee" and the record "Renée") is credited under the record's spelling, and the narrator field is rewritten to that spelling in the same journaled write, so the written book no longer shows as `narrator_column_differs_junction` in the census. Reverting restores the old field. A book whose stored narrator list (`NarratorsJSON`) would then disagree with both is listed under `narrators_json_disagrees_both` instead of written.
- The apply re-checks the book's field locks right before each write: a lock a person sets after the plan holds the whole book for that run (`held_user_locked` or `held_narrator_user_locked`), and the journal row is voided.
- Reverting a journaled write that never landed (the run died between the journal and the write) on a book with untidy author positions now counts the book as restored instead of refusing it as changed since the run.
- With a `limit`, a book that could not be read keeps its place in the cohort instead of the next eligible book taking it.
- A dry run of `maintenance.credits-backfill` also declares the books write, so it keeps other book-writing operations waiting while it reads the library.
