### Added

- New maintenance operation `maintenance.credits-backfill` fills in and tidies each book's author and narrator credit lists so they agree with the book's single author and narrator fields. It is a dry run unless started with `apply`. It fills an empty author list from the book's author, adds that author at the front when the list leaves them out, numbers list positions 0, 1, 2, and so on, fills an empty narrator list from the narrator field or the stored narrator list, and refreshes a stale author snapshot. Anything ambiguous (a missing or merged author record, a combined "A, B" author record, a narrator field that disagrees with the list) is listed for review and not changed. The operation never creates an author. It creates a narrator only for a single unsplit name or a stored list entry, and a name that exists only after splitting a string needs the `narrator_new_from_split` opt-in. iTunes books need the `itunes` opt-in and owner-manual books are held. Each written book is journaled, so the operation can be reverted. The revert refuses a book that changed after the run. Results list each class with its book ids and before/after samples, and show which books would file under a different author.

### Changed

- The `maintenance.credits-backfill` review pass: a book whose author field a person has locked is now held on the whole author side, and a book whose narrator field is locked is held on the narrator side (`held_narrator_user_locked`). Placeholder authors such as "Unknown Author" and junk narrators such as "N/A" are listed for review instead of being written. A narrator name is matched without regard to accents, and a name that matches two records is listed for review. Where a later rescan moved the author (the book's stored order or its author snapshot names a different credited person), the author is no longer put first; the book is listed under `author_id_snapshot_conflict`. Cases with no such signal behave as before.
- Reverting a `credits_backfill` write restores the authors in the order they were stored in, so the book files under the same author folder as before the run. The revert used to renumber by the canonical order, which could move the filing author.
- `limit` now means the first N eligible books by id, in a dry run as well as an apply, so a dry run with a limit shows exactly what the apply with that limit writes.
- The operation declares a books write, so it is gated like the other book-writing operations, and its description says so.
- A write the run refuses (the book changed since the plan) or that fails now voids its own journal row, so the revert refuses it and a resume does not see a stranded row. `narrators_created` counts only narrators whose book write landed.
- The result reports `books_eligible` and `books_to_reidentify`, with the ids under `search_identity_changes`: the books whose author search identity changes and which will spend Google Books quota (1,000 requests a day) at their next metadata run. The class lists in the result are not capped; each count clicks through to its ids.
