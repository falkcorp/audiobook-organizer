### Added

- Core: authentication service, shipped dark (platform-core F4-02, first half). `core/auth` gains the identity `Store` (split into five interfaces of at most eight methods), the native store `core/internal/authstore` over `c/auth/` with `authtest.StoreSuite`, and `auth.Service`: API keys, sessions, `PrincipalFor`, the stage-12 middleware, password sign-in (`Login`) and the user methods (`CreateUser`, `User`, `UserByUsername`, `Users`, `ChangeOwnPassword`, `SetStatus`, `DeleteUser`, `SetRoles`). Credentials are 54-character base62 tokens with a CRC32 check and only their SHA-256 is stored. Account writes need `core:users.manage` through an interactive sign-in and dominance over the target's roles; role changes pass `CanAssign` on every role added and removed; the last active `core:admin` holder cannot be disabled, demoted or deleted, and two concurrent demotions cannot both land. Password and status changes bump the credential epoch and are journaled in the revoking batch. Nothing in ABO calls the service yet; ABO's routes keep their HEAD behaviour until F4-08.
- Core: `core/auth/password` holds the argon2id hasher as an instance (`password.New`), with the derivation semaphore sized to GOMAXPROCS and the dummy hash built at construction, which removes a deadlock HEAD's lazy dummy could hit under a full semaphore. Lowered hash cost is refused outside test binaries, both at run time and by `archtest`.
- Core: the sign-in throttle, the login ceilings and the bootstrap attempt limiter are instance state in `core/auth` (`Throttle`, `LoginCeiling`, `BootstrapLimiter`); ABO's gin gates (`login_gate.go`, `bootstrap_gate.go`, `invite_gate.go`) keep only the request keying and call them.

### Changed

- Core/ABO: e-mail normalisation (`NormalizeEmail`, `SameEmail`) and the bootstrap key lifetimes moved from `internal/util` and `internal/config` into `core/auth`; `internal/config/invite_config.go` is now `env_only_settings.go`.
- ABO: the session cookie name is resolved per request from the connection's trusted scheme, and an `X-Forwarded-Proto` header from a peer that is not a configured trusted proxy is ignored. HEAD believed it from any peer, so a direct caller could pick the plain cookie name a sibling origin can plant.
- ABO: the saturated-login policy reads the throttle's configured soft threshold (`(*Throttle).SaturationPolicy`), and the throttle's limits can be reloaded (`SetLimits`).
