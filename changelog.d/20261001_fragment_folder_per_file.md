- Metadata fetch: a chapter or part file the scanner filed as its own book row is now skipped (`sibling_part`) when each file sits alone in a folder named exactly like it (`Gregory Benford/Great Sky River 18 6/Great Sky River 18 6.mp3`). The resolver used to look for the rest of the set only in the row's own folder, found nothing, and searched the fragment title against Audible and the other sources, spending the audnexus budget on thousands of these rows. It now also looks at the like-named folders beside that one ("cousins") under the same rules as siblings: the counted ("179 of 200") and trailing-token ("18 6") titles still need enough cousins of the same set, a file of 2 h or more is still a whole book, and with no trustworthy duration six or more files are needed. A chapter-number title ("98") counts cousins only when its own file and the cousins' files are chapter-named too, and only under that duration rule, so a whole book with a junk "01" tag in `Author/Dune/Dune.m4b` beside `Author/Hyperion/Hyperion.m4b` is still searched. Rip-detail titles never borrow cousins. A parent folder that is the library root, an import path or a generic folder is never listed, and each parent is listed once per pass (barring concurrent first reads of the same folder, the same limit as the existing folder listing).
