### Fixed

- The scheduled metadata candidate refresh no longer fails on nearly every book it selects. In the latest production run all 814 selected books errored (482 Audnexus timeouts, 332 Audnexus "Bad ASIN" 400s), and the same books were selected again every six hours. Cause: the search treated any ten letters and digits as an ASIN, so every ten-letter word of a book's title (800 of the 814) was looked up on Audible and Audnexus as one. A lookup is now sent only for a value in the ASIN grammar (`metadata.CanonicalASIN` for a stored or typed value, normalised to upper case; `metadata.ASINInText` for free text, which accepts only an upper-case `B` + digit token as written). The identity hash is unchanged, so no cached row turns `identity_stale`.
- An Audnexus 400 whose JSON body says "Bad ASIN" is the provider's permanent answer about that ASIN, not a failure of the provider: the region loop stops at the first region (it asked 3, or 9 on the full list), the answer is remembered as a negative cache row for the provider's negative TTL, and the provider's breaker is not charged. Only Audnexus is read this way; any other 400 (a proxy's error page, JSON about another parameter, another provider's 400) is still a failure and is never cached. A whole query that is an ASIN (pasted into "Search again", in either case, or the ten-digit form) is still looked up directly (`metadata.ASINQuery`); a one-word title is not.
- The Audnexus request's 10 s deadline no longer includes the wait for the provider's shared token bucket. It was set before the request queued, so 20 workers on a 2 requests-per-second bucket spent it all waiting. `providerhttp.Limits.AttemptTimeout` now bounds the exchange itself, starts once the request holds its token and daily-quota reservation, survives a configured override of the budget, and a timed-out attempt is retried once after a backoff. The retry applies only to a provider that has an `AttemptTimeout` (a zero-value provider sends one request on a dial timeout, as before). Worst case: one region 21.5 s (10 s, a backoff of at most 1.5 s, 10 s) inside Audnexus's 30 s `Timeout`. The ASIN lookup now also stops at the first region that times out (a hung service will not answer in the next region), so a hung lookup is 21.5 s and two requests; before, the three regions each had a 10 s deadline of their own, queue included, so the same lookup was 30 s and three requests. A region that answers 5xx still goes on to the next. The rate limiter's "would exceed context deadline" refusal (a call that could not get its token before the caller's deadline) is classified `timeout` instead of `other`.
- A book whose only failed source is identifier-asked (Audnexus) no longer blocks the fallback providers that still owe it an answer: they are asked, the book is reported as degraded (or as an error when the fallback finds nothing).
- A chain source that could not be asked (Audnexus on a 5xx, a timeout or a hold) while another source found a candidate is no longer forgotten for the row's 30 days. The cache row records it as owed (`owed_sources`, additive: a row without the field owes nothing, as before). The batch fetch's verdict and the scheduled "only unmatched" selection treat a row with a due owed source as due for a re-ask of ONLY that source: the row's candidates are kept, the answer is merged into them (Audnexus's own-ASIN candidate ranks ahead of a review-only Open Library or Google Books one), the fallback providers and the Google Books budget are not asked on its account, and the debt is cleared the moment the source answers. The re-ask is bounded: after the 1st failed ask the next is due after 6 h, then 24 h, 3 d and 7 d, and the 5th failed ask ends them (about 11.5 days in all), so an ASIN that never answers is not asked every six hours forever. A provider hold sends nothing and does not spend an ask. A forced refetch, a changed search question or ASIN, or a refetch after the 30-day TTL asks again. A source that fails in a later search keeps the candidates it earlier supplied for the same question and ASIN, so a degraded refetch never drops or outranks the better source's candidate.

### Added

- Candidate-fetch result rows carry `failed_sources` and `error_cause` (`bad_asin`, `timeout`, `rate_limited`, `quota`, `provider_held`, `upstream_5xx`, `client_4xx`, `canceled`, `transport`, `other`), both omitted when every source answered. The op log ends with a `refresh summary: refreshed N, degraded M (by cause), failed K (by cause), deferred D, not asked J` line, also on cancel; a resumed run seeds it from the stored rows.
- A book is counted "not asked" in the refresh summary only when no source was asked: a cached row whose fallback provider ran live, or whose owed source was re-asked and failed again (degraded), is not. Deferred books (a fallback lookup put off) have their own count and are not "refreshed". The op's selection message says how many books were picked only for an owed-source re-ask and how many wait on their backoff.
