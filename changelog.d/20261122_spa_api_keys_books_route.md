### Fixed

- Settings → API Keys makes and manages keys through the books key route (`/api/v1/auth/api-keys`: list, get, create for yourself or another user, activate/deactivate, revoke) again, with that route's request and answer shapes and its atom-name scopes (`library.view` and so on), instead of core's native `/api/core/v1/me/api-keys` family (F4-08 B10sk). A key minted on the native route got none of the ambient scopes (`core:self`, `core:metrics.read`, `books:reading`), so a key made in the SPA and handed to an Audiobookshelf client could not sync progress. The books route mints through the one shared scope rule, ambient scopes included, so the key holds what an imported key holds. The description box from B10u stays and is sent as the books route reads it. A guard test (`apiKeysRoute.guard.test.ts`, empty allow-list) fails if any file under `web/src` calls a core-native API-key path.
