### Added

- An admin can undo a user merge again once identity is on, as long as nothing has changed since. Core gains `Admin.PlanUserUnmerge` and `Admin.StageUserUnmerge`, which put the account the merge folded away back as it was (its status, its address, its keys and its sign-ins, with a fresh credential epoch so no session or token from before the merge comes back to life), take off the target the roles the merge gave it, and end the target's sessions only when a sign-in moves back. The reversal is whole or refused: it names the first thing that no longer matches (`source_changed`, `key_moved`, `signin_moved`, `email_claimed`, `target_inactive`, `target_merged`, `not_merged`, `source_deleted`, `target_deleted`), and a removal that would leave no active admin stays refused. Books undoes its own rows by the same rules as before and commits them, the journal and core's half in ONE batch, so a refusal at any step writes nothing; the merge journal now records which sign-ins moved and the committed version of each moved key (journal only, never in a preview or an answer).
- Resume of a merge whose straggler sweep did not finish (`sweep_pending`) now re-runs the idempotent sweep and clears the marker, exactly as the first run does and with the same loud error on failure. Undo refuses (409 `sweep_pending`) while the marker is set and works after the resume. Every other resume, and the undo of a merge made before the identity switch, stays 409 `merge_permanent`.
- undoing a merge brings the account back; a guest's Cloudflare access and phone key must be reissued
- The undo route answers a core refusal with its code (409), an actor who does not dominate an account with 403 (it was 500), and the plain denial with 403.
