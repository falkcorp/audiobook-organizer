### Fixed

- Scanner import no longer copies tag track/disc numbers onto each book_file row on its own. The book's files are now judged together with the same guard `maintenance.tag-backfill` uses (moved to `metadata.JudgeTagPositions`): tag numbers are used only when every file has a tag track, the (disc, track) pairs are distinct, and either every file or no file carries a disc tag. A rip tagged "track 1" on every chapter, or one where only some files carry a disc tag, now keeps its positional (segment-list) order instead of importing with duplicate tracks or with disc 2 sorted before disc 1. Each refused multi-file book is logged once with the reason.
