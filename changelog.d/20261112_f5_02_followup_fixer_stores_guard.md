### Added

- tools/fixerstores, internal/plugins/maintenance: a static guard for the repairs fixers' shell stores. `TestFixerStores_NoFixerReachesAStoreExceptThroughTheShell` runs a VTA call-graph pass (a module of its own, `tools/fixerstores`, so x/tools stays out of the root go.mod) from every fixer's Plan, Replan, Apply, Meta, BeginApply, AfterApply, RequiredPermissions and PlanOnly. It fails on a `FixerStores` accessor called on anything but a store-family interface, on a conversion of the plugin's deps into one, on any other plugin dep, and on a func argument it cannot follow, unless the reviewed allowlist (`testdata/fixer_stores_allowlist.txt`, keyed on function and accessor, shrink-only: a stale entry fails too) says why. It skips under `-short` and runs in the "Fixture Tests (no -short, race)" jobs; `scripts/ci/fixture_weights.json` carries its weight. It complements the tripwire tests: VTA is unsound for reflection and imprecise for function values stored in struct fields.

### Changed

- repairs: a refused apply run state (a writer or stand-down that would not start) is cached for the attempt instead of being rebuilt per row. The refusal is logged once, the stand-down is asked for once, and every row of the attempt still fails with the same error; a resumed attempt builds again.
- maintenance: `repairsGuardTags` and `versionGroupPrimaryRepair`, the two bodies a fixer shares with an operation, take the stores they read as a parameter (operations pass their deps, fixers pass the shell's), so the guard protects the call that fills the parameter. `shellDeps` and `withFixerStores`, which rebuilt the plugin around the shell's stores for those two calls, are removed.
