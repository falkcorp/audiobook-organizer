### Added

#### Kernel realtime hub, dark (F6-03 slice E4)

`core/kernel/realtime.go` builds the App's one realtime hub the way the events flip will wire it, but nothing calls it yet, so no runtime behaviour changes. It maps the `core.realtime.*` settings onto the hub, with a floor of 4096 on the resume ring so the journal's live tail cannot crowd every other topic out of the `Last-Event-ID` window; the floor is a stopgap until the section default is raised, and it logs a warning when it overrides a value the operator set. It returns the hub's bus subscriptions as a core boot problem when the two control topics (`core.principal.invalidated.v1`, `core.rbac.changed.v1`) are not declared, rather than letting a revocation wait for the next heartbeat. It also adds the run and shutdown hooks. A new `core/internal/httpmw` test pins that a per-write deadline and `Flush` reach the connection through every writer of the perimeter chain, over HTTP/1.1 and HTTP/2 with gzip negotiated, and that a deadline set that way is enforced.

`core/auth` gains `Service.Refresh`, the hub's required rights refresh: it rebuilds any principal auth built (a session, a core or compat API key, a compat surface's own, an identity extension's such as `ext:cfaccess`, the auth-off binding) from the user and key as stored now, so a role change reaches an open stream within one heartbeat. It never widens: a key principal is rebuilt over the scopes it was built with that the stored key still holds, and a principal an extension or compat surface narrowed stays narrowed. A revoked, expired or moved credential, a deactivated user, a compat surface's principal whose user must reset a password, or a principal auth did not build is refused. Before this, the kernel's own refresh refused every compat and extension principal, which would have cut off every Cloudflare Access stream at its first heartbeat.

An identity extension's principal now ends with its credential. `auth.Assertion` gains `ExpiresAt`, which `internal/cfaccess` fills from the verified Access token's `exp`. An extension that asserts no expiry is bounded by the new `core.auth.extension_max_age` setting (default 24h, at most 168h) after its sign-in time. Stage 12 refuses an assertion already past its bound, and `Revalidate` and `Refresh` refuse the principal once it passes, so an open stream no longer outlives a Cloudflare Access token. Refresh never extends the bound. The kernel declares the setting; the auth wiring maps it when the identity flip lands, and the 24h default applies until then.

The hub's `max_clients`, `max_per_bucket`, `write_timeout` and `retry_after` now apply on a settings reload, to the next stream or write, with no restart (`realtime.Options.Live`, `sse.Options.Limits`).
