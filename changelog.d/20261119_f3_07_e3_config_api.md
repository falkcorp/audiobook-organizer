### Changed

- `GET /api/v1/config` and `PUT /api/v1/config` speak the configuration Facade's key shape. GET answers `{generation, keys: [{name, class, value | secret, locked_by, restart_pending, admin}], naming_pattern_tokens}` (a secret carries its metadata, never a value or a mask), and PUT takes `{"set": {<key>: <value>}, "unset": [<key>]}`: one write that commits entirely or not at all, refused with 400 for an unknown or read-only key, 403 for a missing permission or credential, 409 for a key an operator layer sets, 422 naming every invalid field. The old flat body, the `env_locked` annotation, mask echo detection and the separate `secrets` object are gone; a secret is written by naming the key with its new plaintext and cleared by listing it under `unset`. The Settings page, the first-run wizard and the Metadata tab read and write this shape (F3-07).
- The five `ai_backend.*` settings are served and saved as a view over the `ai_endpoints` list, so saving the AI Backends section works through the same PUT (F3-07).
- The settings routes resolve a section permission through books' atom table (`Server.SetConfigAtoms`), so a user who holds `settings.manage` through a role keeps the keys core guards with `core:settings.manage` and its siblings; before this wiring every such write was refused (F3-07).
- During the first-run window (no user exists and setup is not complete), the setup wizard may write exactly its own keys (`root_dir`, `playlist_dir`, `setup_complete`, `openai_api_key`, `enable_ai_parsing`) without the admin role, so a fresh install can set the library path before its first account exists. Nothing else opens in the window, and the whole update is refused if it names one other key (F3-07).
- `config.EnvLockedSettings` and `config.SettingLocks`, the old GET handler's only callers, are removed (F3-07).

### Fixed

- A settings import in the web app no longer repoints a saved credential at a new address: it never sets a metadata source's `base_url` (a new source or an existing one keeps the server's value), keeps `embedding.base_url`, and lists every other URL it dropped under what it ignored (F3-07).
- A secret supplied to the host through an environment variable, a `_FILE` variable or the config file reaches the secret store: `Deps.Config.Secret` reports it with its source and the store refuses to overwrite or delete it. Before this, `config.Store.OperatorSecrets()` had no caller, so such a secret read as unset once the config boot is on (F3-07).
- A stored credential can no longer be redirected to another host by a settings write. A write that changes the origin (scheme, host or port) a credential is sent to is refused with the field named, unless the same write replaces or clears the credential: `openai_base_url`, `embedding.base_url` (the OpenAI key follows it), the Deluge web URL and RPC host and port, a metadata source's `base_url` with its stored credentials, the built-in Google Books and Hardcover keys (a changed, added or re-added source), an AI endpoint that references a stored key, and a webhook URL with its secret. HEAD allowed all of these; table-completeness tests fail when a credential or URL setting is added without a rule (F3-07).
