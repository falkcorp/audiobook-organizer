- `audiobooks` handlers: `GET /audiobooks/:id/files` and `GET /audiobooks/:id/segments` now report `file_exists` from an `os.Stat` made for the response, not from `!BookFile.Missing`. The stored flag only changes when a scan or repair notices, so rows whose files had vanished read as present (393 of 409 sampled production rows pointed at absent paths). The stored flag is still returned as `missing`. The stat runs on a pool of 8 workers under a 3-second deadline per response, so a hung mount cannot stall the request. A path the stat could not answer (permission, I/O error, deadline) reads `file_exists: null` with the cause in `file_check_error`, and is never reported as missing. The web types and the book-detail segment mappings carry the new fields.
- `maintenance.duration-backfill`: recently verified books skipped by `SkipAgeDays` are counted as `recently-verified-skipped` instead of being added to `estimated-segments`, which now counts estimated segments, not books. `read-errors` is split into `missing-on-disk` (the read failed with not-exist) and `read-errors` (every other failure), and each is followed by one example path in the progress and summary lines. Failed segment, aggregate or duration writes are counted as `write-errors`; they had been added to the read-error count. Per-file read failures are logged through the project logger: missing files at debug, other failures at warn.
