- Metadata search, placeholder authors: "Unknown Author", "read by narrator" and the other system placeholders are no longer sent to providers as the author a search is narrowed by, whether they came from the batch fetch's hint or from the search ladder refilling the author from the book's AuthorID. The same rule covers the narrator, which the ladder also tries as an author, and the single-book fetch's author and narrator. A book with no usable author is searched by title plus narrator, and its own ASIN is looked up directly when it has one. The bulk metadata fetch strips them too. The apply gate's identity check accepts a cache row hashed with no author only when the book's author is a placeholder, so rows written this way do not read as identity drift, and the candidate-fetch "no match" line names the author actually searched instead of the stored placeholder.
- Metadata search, placeholder and chapter titles: books titled "", "Unknown Title", "Chapter 3", "03" or "06 Chapter 6" are no longer skipped by the batch candidate fetch or left out of the bulk metadata fetch. Both use one predicate (`metadata.IsUnsearchableTitle`) and one resolver (`metabatch.ResolveCandidateSearchQuery`) that searches by the book's transcribed title, then a file's transcribed title, then the work folder's name (`metadata.ChapterTitleFromDirectory`). A book is skipped only when none is usable, with a per-book reason line and, on the bulk path, a `skipped_no_title` or `skipped_fragment` ledger row. The stand-in title is only a query: it is never written onto the book. The bulk path resolves it inside its worker pool and keys the provider fetch cache on it, as the per-book search already did.
- Bulk apply gate, transcription-found candidates: a candidate found by searching the book's transcribed title, whose title matches that transcription (normalized equality and the shared title matcher), now passes the certainty gate's title check and, when the caller proves the cache row differs from the book only in that query, its identity leg. It is still refused on an ASIN conflict, a partial book, and identity_stale for any other reason (an author change, a row fetched for another query, a book that has since been given a real title). The transcription counts as one agreement, not two, so it cannot pass the evidence leg on its own. The evidence is recorded on the candidate and the gate verdict (`identity_evidence`) and in the bulk apply's applied and refused lines. The evidence is in the API and bulk-apply preview JSON and the op log; no web view renders it yet. A candidate found by any stand-in query is identity_stale in bulk apply unless this evidence lifts it, on both the cache path and the candidate-fetch op-result path (whose own identity check compared only the stored title, which a stand-in search leaves unchanged). So a candidate found by the folder-name fallback stays identity_stale.
- Bulk apply, Doctor Who / Big Finish / Torchwood: both bulk-apply planners (the cached apply, including the review page's bulk buttons, and the candidate-fetch op-result apply) now refuse these books as `owner_manual_only`, judged on the book's path, title, series and every file path, the query it was found by, and the candidate's title and series. No bulk owner review lifts it. A single review row the owner approves, and the single-book apply dialog, still apply them.
- Bulk apply, transcription evidence: a transcription vouches for a candidate only when the candidate also credits the author heard in it (the full rule the unattended score leg uses), so "X, by A" no longer passes a candidate "X" by B. The file-level transcription is taken from the first file (lowest disc, then track) only. The evidence is recorded only when the gate's verdict is not identity_stale or owner_manual_only, and a refused log line says the refusal stands.
- Bulk apply, cache identity: a cache row or fetch result recorded with no author no longer proves the author of a book that has one (the book row's author snapshot is usually empty, so that proof held for any author). The batch fetch now hints, hashes and records the book's live author. Existing rows recorded with no author for a book that has an author read as identity_stale in bulk apply until the book is refetched.
- Metadata fetch cache: the provider fetch-cache stamp keys on the author a search actually sends, so rows fetched while a placeholder author was still sent are refetched instead of replayed until they expire.
- Metadata search: "Chapter One", "Part II", "Book 1", "Vol. 2", "Prologue", "Introduction", "Opening Credits" and similar section headings are unsearchable titles; "1984" and other titles stay searchable.
