### Changed

#### `tools/cmd/oplint` becomes `core/archtest/tasklint`, run in CI over core and books' task packages (F2-17, dark)

The ops-definition lint moved into the core module as a test-support package
(05-tasks §5T.8.4): its paths are `analysis.Analyzer` flags instead of
constants and an `init`, and its rules are 05-tasks' six over core's model
(`unregistered-kind`, `writer-bypass`, `store-capture`, `missing-help`,
`sequential-empty-reason`, `deletes-owner-review`; `unregistered-bundle` and the
probe flag are gone, and the allow directive is now `//tasklint:allow`). It runs
as Go tests: `TestTasklint_Core` over `core/...`, and `TestTasklint_Books` over
books' task packages, where HEAD's not-yet-converted definitions pass only
through `internal/books/testdata/tasklint_exempt.d/`: one entry file per
conversion row plus `F5-18.txt`, read as one union that
`TestTasklintExemptions_ShrinkOnly` lets only shrink against the merge base with
`origin/main` (in CI's shallow checkout, against `origin/main` itself, which
ci.yml fetches at depth 1 for the short-test and fixture-test jobs). `make oplint` is now `make tasklint`. The two type-aware guards
`archtest.ResumeContinueCheckpoints` and `archtest.RunItemsDeclareParallelism`
land with their self-tests. Core gains `golang.org/x/tools` (test-support only),
and the short-test and fixture-test CI checkouts now fetch full history for the
ratchet. No route, schedule, stored row or runtime behaviour changes.
