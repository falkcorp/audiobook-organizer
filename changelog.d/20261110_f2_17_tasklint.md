### Changed

#### `tools/cmd/oplint` becomes `core/archtest/tasklint`, run in CI over core and books' task packages (F2-17, dark)

The ops-definition lint moved into the core module as a test-support package
(05-tasks §5T.8.4). Its paths are now `analysis.Analyzer` flags instead of
constants and an `init`, and its rules are 05-tasks' six over core's model:
`unregistered-kind`, `writer-bypass`, `store-capture`, `missing-help`,
`sequential-empty-reason` and `deletes-owner-review`. `unregistered-bundle` and
the probe flag are gone, and the allow directive is now `//tasklint:allow`.

`unregistered-kind` now runs over every loaded package at once, so a kind
registered by another package (a kernel registering an owner's kinds) counts.
It also follows helpers that return `tasks.Definition`, and with list functions
on, a list function counts only once something calls it.

It runs as Go tests:
- `TestTasklint_Core` runs over `core/...`.
- `TestTasklint_Books` runs over books' task packages. There, HEAD's
  not-yet-converted definitions pass only through
  `internal/books/testdata/tasklint_exempt.d/`: one entry file per conversion
  row plus `F5-18.txt`, read as one union.
- `TestTasklintExemptions_ShrinkOnly` lets that union only shrink. Its base is
  explicit in CI: the merge queue's base commit, or the PR merge ref's first
  parent, fetched at depth 1 into the default shallow checkout. Recreating the
  directory after it was deleted fails.

`make oplint` is now `make tasklint`.

The two type-aware guards `guards.ResumeContinueCheckpoints` (whose from-zero
allowlist is a per-kind list; core's is empty) and
`guards.RunItemsDeclareParallelism` land in `core/archtest/guards` with their
self-tests, so `coretest` never links x/tools. Core gains `golang.org/x/tools`,
test-support only (13 §13.5.2). No route, schedule, stored row or runtime
behaviour changes.
