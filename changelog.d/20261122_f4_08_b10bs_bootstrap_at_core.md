### Changed

- After the identity flip a new bootstrap key is redeemed at core's `POST /api/core/v1/auth/bootstrap` with `{"token": ...}` (the key is `.key` in the answer, named `bootstrap`, scoped `core:admin`, 8h by default like HEAD's recovery key); the books route `POST /api/v1/auth/bootstrap` now refuses every request with `401 invalid bootstrap token` before it reads a token, a stored hash or any account, so a hash a HEAD boot left in books settings can no longer spend a token, find or create an admin, or remove core's token file (F4-08 B10bs). The `server-bootstrap` skill, its reference and `bootstrap.sh` (which now reads the token file instead of the log) describe the new flow and what a non-interactive bootstrap key cannot do, and the deploy runbook notes that keys minted before the flip keep working.
