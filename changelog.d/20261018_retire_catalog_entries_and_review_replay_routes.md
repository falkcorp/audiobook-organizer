Retired the author-catalog read routes (GET `/api/v1/catalog/entries` and `/api/v1/catalog/entries/:id`) and POST `/api/v1/review/replay-approved`. Nothing in the web app, scripts or agent tooling called them. They now answer 410 Gone for one release, with their usual authentication and permission checks still running first, and the handlers and their tests are deleted. The catalog stubs have no replacement. The owner-kept diagnostics (`GET /api/v1/op-defs/:id`, `/ai/capabilities`, `/ai/endpoints/status`, `/tools/:name/status`) are untouched.

The replay stub points callers at `POST /api/v1/review/bulk` with `{"action":"approve","ids":[...]}`, listing the approved items with `GET /api/v1/review/items?status=approved`. Approving an already-approved item again runs its recorded action once `review_apply_enabled` is on, so a decision made while apply was off still executes. The approve note shown while apply is off now says to approve the item again after enabling apply, since replay no longer exists. `CatalogStore.ListEntries`, `CatalogListQuery` and `EditionGroupMembers` moved into test code because the retired route was their only production caller. No store interface methods were deleted and no data is touched.
