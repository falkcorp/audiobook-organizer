### Fixed

- Path containment checks no longer treat a sibling directory as inside a root. A bare `strings.HasPrefix(path, root)` counted `/lib2/a.m4b` as inside `/lib`. Every "is this under the library root / import path / protected path" check listed as a follow-up in #3338 now uses the new `pathutil.IsWithin`, which matches only on a path-separator boundary. Affected: organizer filters, in-place re-organize and preview, the hash-duplicate check, reconcile passes (including the one that deletes duplicate library files), scanner organized-hash stamping and version-group primary election, the empty-parent cleanup after purge (it could remove empty directories in a sibling of the library root), dashboard, import-path and quick-query counts in both stores, library size accounting, the Deluge protected-path guard, and the iTunes test-mapping sampler. Paths that really are inside the root get the same answer as before.
- `pathutil` no longer imports `config`, so lower layers such as `database` can use its path helpers without an import cycle. `PathVars` and `AbbreviatePath` now take the root directory as a parameter; nothing outside the package called them.
