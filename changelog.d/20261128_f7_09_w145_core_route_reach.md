Fixed core's integrations and library routes being wider than HEAD's reach before the F7-09 mount. The six instance routes (list, get, create, update, delete, release hold) now require both `core:integrations.manage` and `core:settings.manage` for every kind, so a principal holding only HEAD's integrations.manage atom (`core:integrations.manage` and `books:integrations.manage`) is refused them; the settings.manage atom's holder, which maps to both, still passes. The instance health route moves from `core:integrations.read` to `core:integrations.manage`. `browseLibrary` now requires both `core:library.browse` and `core:settings.manage`; its registered-roots confinement is unchanged. The adapters list and the two test routes are unchanged, and the legacy `/api/v1/deluge/*`, `/api/v1/itunes/library/download` and `/api/v1/openlibrary/*` routes keep their reach, now pinned by a boot test. None of these core routes is mounted yet, so nothing is served differently until F7-09 mounts them.
