### Added

- The task engine's write fence now checks every resource a write touches. A gated write used to carry one resource tag, so a store call that also wrote a second resource its kind never declared was let through. `Write.Resources` carries the full set, `tasks.CheckWrite` refuses an empty set, an undeclared member or a blank one before the write-ahead record and before the write itself (in Preview as well as Live), and the executor's writer and the `writertest` double (`internal/books/writer/writertest`) share that one check. The other `tasks.Writer` test doubles in the suites do not run it. Nothing calls it from a live path yet: the books gated writer (`internal/books/writer`) stamps each store call with its method's whole row, and a store wrapper (`internal/books/writer/metafetchgate`) puts every write of the metadata fetch behind it. Tests show a kind that writes a resource it did not declare is refused for every row of the method table, that the three writes the earlier store-key comparison could not see (a write that changes no key, the delete of a key that is already gone, a key created and deleted in one window) are refused when attempted, and that `resolve-production-authors` and `auto-match-transcribed` run their real metadata apply through a writer that enforces their declared effects.
