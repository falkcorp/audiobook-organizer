### Added

- The revocation journal can now drop the lines no retained backup needs (`journal.File.Trim`, `journal.Component.Trim`), which is what retention's `PruneJournal` will call once F4-08 binds the journal and F8-04a G2 wires it. Nothing calls it yet, so no running binary changes. A trim to seq N rewrites the journal beside itself and renames it over the old one, keeps every later line byte for byte (so the store's head, the unapplied queue and the location file's anchor stay valid), and records the last dropped line as the new header's base. It never drops past the store's committed head, an unapplied-queue entry, a gap line whose record the store still holds, or a restore line whose hooks have not run, and a crash at any step leaves the old journal or the trimmed one, whole. The header gains an optional `chain_base` flag, omitted from every journal that is not trimmed, so existing journals read and verify unchanged. The crash-matrix memory filesystem now keeps a file's lock through a rename, as `flock(2)` does.
