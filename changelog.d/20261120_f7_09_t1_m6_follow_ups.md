### Changed

- Books' integrations cutover step (M6, still unregistered) takes the F7-08 round-2 follow-ups. An AI endpoint's capability tick HEAD does not register, a wildcard tick and a feature core does not declare are dropped and reported, not carried; core refuses an imported endpoint that carries one, so the whole endpoint would otherwise be quarantined. When a renamed ID lands on another entry's exact HEAD ID, the exact entry keeps it in either order, for metadata sources and AI endpoints. A renamed source takes only its own credentials. An unreadable one is carried as an unreadable marker, and a secret already under the new name is reported, not bound. A path alias whose root is an ancestor of a library root is carried to that root with the relative path appended, so the root renders as it did. Aliases inside a root or shadowed by more specific ones are quarantined with a reason that says the rendering is lost. Unread plugin entries and webhook settings keys are quarantined with a report line. Mappings under a refused roots list get their own reason. An unproven operator Deluge URL is reported instead of quarantining the stored value. Import-path quarantine records are no longer sealed. A metadata source's `rate_limit.max_concurrent` is reported as dropped. Nothing changes for a running install until F7-09 registers the step.
