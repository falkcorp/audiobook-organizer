### Fixed

#### Core event-stream client: the #4785 round-2 flip preconditions (F6-03 E1)

The new `web/src/services/coreEvents` client (still unwired) no longer reconnects at once when a stream is resubscribed under a standing `Retry-After`. Its backoff lives in the manager per stream key and restarts from the first attempt once a closed stream's wait has lapsed. A 429 or 503 `Retry-After` now holds back every stream in the tab, including a new keyed stream. Every wait is measured on one clock that never steps back and also counts the time a sleeping machine missed (`coreEvents/clock.ts`), so a wall-clock step back never stretches one and a wait that elapsed under a closed lid is spent on wake; a wall-clock step forward reads as time passed, so it can end a wait early. By default, resync handlers take only the shared stream's resets, merge a burst within 250 ms into one call and run at most once every 5 seconds. So opening a run's log or a flapping server no longer refetches every view, and a reopen's two resets (the open and the one the server owed) are one refetch. No reset is dropped before that merge, because a `gap` can also be a real loss in the middle of a stream. A handler that takes every stream (`*`) gets one call per stream that reset, never one merged across streams. The shared stream drops a keyed-only topic even for `*` subscribers.

### Added

#### Core event-stream adapters and an e2e stream mock (F6-03 E2, E3)

`bookChanges.ts` folds per-book `books.book.changed.v1` frames back into the `{kind, ids[]}` batches that Library's `applyBooksChanged` takes. It follows the legacy coalescer's rules: a fixed 250 ms window, deleted supersedes created and updated, flush order deleted/created/updated, at most 500 ids per batch. The consumer drops the pending window with `clear()` as it issues its REST refetch. `shutdown.ts` watches for `core.stream.closed.v1{shutdown}` for the App backdrop. It holds the shared stream open itself, fires once per shutdown and detaches every listener it added. `web/tests/e2e/utils/mockCoreEvents.ts` is a fetch-stream mock for e2e: an init-script shim streams controllable frames (opened, events filtered by topic and key, reset, `closed{shutdown}`, 429 with `Retry-After`). A `page.route` guard records any request that reaches the network, and every later call on the mock then fails naming it. Mocking the same page twice throws; the shim's state is per document, so it starts over on each navigation. Nothing imports any of this until the F6-03 flip; `eventSourceManager` stays until then.
