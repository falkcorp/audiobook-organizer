- New Repairs fixer **Missing files** (`reconcile.missing-files`) in `/review?lane=repairs`, taking over from the old Reconcile tab (the tab is retired in 03-PR10). Its trial reads the latest saved reconcile scan, picked by the same rule as `GET /operations/reconcile/scan/latest` (the newest completed scan whose result decodes, nightly runs under the retired `maintenance.reconcile-scan` id included), and lists one row per book: each match from book to untracked file (the row proposes the new path; the match type is the row's class, and the match type and confidence are in its reason and evidence), and each book the scan found no file for as a skipped row with the reason "no candidate file". A match is offered only while the book is still at the path the scan found missing and that path does not exist (an existing folder counts as present; a path that cannot be read is an error row, never "missing"), the book has exactly one file row at that path and none at the matched file, the matched file is on disk and no other book holds it (by path or by a file row). The matched file's size and modification time are part of the check. iTunes books (including a book with an iTunes path), and matches onto files in the iTunes library, are skipped with the reason "iTunes".
- Applying a Missing files row writes directly through the Repairs writer (owner decision 2026-10-14): it re-reads who holds the matched file, the book and the iTunes check right before writing, then sets the book's path and repoints the book's file row at the matched file, each as a compare-and-set that is journaled and revertible from the Operations page. Nothing moves on disk, no file row is created or deleted, and the fixer no longer hands its picks to Reconcile Apply. While the file index is still warming up after a restart, the trial fails with "file index warming up; retry in a few minutes" and an apply holds the row as retry later.
- Repairs fixers can now require more than the lane's `library.edit_metadata` (`repairs.PermissionScoped`); starting a plan, apply or owner apply checks it. Missing files requires `settings.manage`, like the Reconcile Apply operation.
- The **Match missing files** command now says its matches are reviewed in Repairs, under Missing files.
