- New Repairs fixer **Missing files** (`reconcile.missing-files`) in `/review?lane=repairs`, taking over from the old Reconcile tab (the tab is retired in 03-PR10). Its trial reads the latest saved reconcile scan, picked by the same rule as `GET /operations/reconcile/scan/latest` (the newest completed scan whose result decodes, nightly runs under the retired `maintenance.reconcile-scan` id included), and lists one row per book: each match from book to untracked file with its match type and confidence, and each book the scan found no file for as a skipped row with the reason "no candidate file". A match is offered only while the book is still at the path the scan found missing, that path is still not on disk, the matched file is on disk and no other book holds it (by path or by a file row); the apply re-checks all of it and refuses a row that changed. iTunes books, and matches onto files in the iTunes library, are skipped with the reason "iTunes". Applying starts one Reconcile Apply operation carrying exactly the selected matches (split into several runs only above the bulk-apply cap); its result is on the Operations page. No file row is deleted.
- The **Match missing files** command now says its matches are reviewed in Repairs, under Missing files.
