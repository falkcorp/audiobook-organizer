- Metadata provider answers are now cached by the question asked, not by the book that asked it. A duplicate copy, a track row or a re-import asking the same question as another book is answered from the stored answer with no provider call, and an empty answer ("this provider has nothing") is stored too, for 14 days on Audible and Audnexus, 30 on Open Library and 7 on Google Books, so a book no provider can answer is no longer re-asked on every pass. Errors, throttle refusals and 429s are never stored. The search fan-out, the bulk fetch walk, the single-book fetch's context search, product lookups by ASIN and the ASIN backfill's Audible searches all share the cache. "Search again" on a book deletes the stored answers its questions map to. New settings: `metadata_fetch.shared_cache` (default on; off restores the per-book cache) and `metadata_fetch.negative_ttl_days.{audible,audnexus,openlibrary,google}`. In a synthetic 1,000-book scenario with 600 distinct questions the first pass makes 600 provider calls instead of 1,000 and a repeat pass makes 0 instead of 400.
