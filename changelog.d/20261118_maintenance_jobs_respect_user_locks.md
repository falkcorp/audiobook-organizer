### Fixed

- Maintenance jobs and ops no longer overwrite a column the user locked. Several writers changed a locked title, author or description straight through `ModifyBook` and so undid the user's edit on every run. They now go through the new `database.ModifyBookRespectingLocks`, which reads the book's field locks under the book's write lock (so a lock saved a moment before the write still holds), writes nothing when a lock covers a column the run changed, and reports which locks held. A lock set that cannot be read stops the write; it never reads as "not locked". The writers: cleanup-series (both the single-book unlink and the duplicate merge, which now also keeps the series row a locked book still names), fix-read-by-narrator, fix-author-narrator-swap, refetch-missing-authors, author-split (`maintenance.author`), iTunes regroup (title), booksig recovery audit (description), and the author conjunction repair's paths (the primary-author rewrite, the title-as-author relink, the junk-row unlink that follows it, and the author merge, which now refuses to delete an author a locked book still credits). Each run's summary or log counts the books it left alone and names the lock.
- A lock saved between the two writes of an author relink (credits first, then the primary author) now holds the primary write and puts the credits back, instead of leaving a book whose credits name the new author while its primary names the old one.
- The write-set gate can now be told about maintenance jobs: `jobs.OpWrites` returns each job's derived write set in the form `OperationDef.Writes` takes, and a test fails when a registered maintenance job has no Writes unless it is a listed, reasoned read-only job. Wiring it into `registerMaintenanceJobOp` is a separate reviewed change (it makes every maintenance job serialize against every other books or series op).
