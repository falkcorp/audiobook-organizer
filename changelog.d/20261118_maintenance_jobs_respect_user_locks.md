### Fixed

- Maintenance jobs and ops no longer overwrite a column the user locked. Several writers changed a locked title, author or description straight through `ModifyBook` and so undid the user's edit on every run. They now go through the new `database.ModifyBookRespectingLocks`, which reads the book's field locks under the book's write lock (the window in which a lock saved just before the write can lose is narrowed to one batch, not closed: lock writers take a different lock than the book write), writes nothing when a lock covers a column the run changed, and reports which locks held. A lock set that cannot be read stops the write; it never reads as "not locked". The writers: cleanup-series (both the single-book unlink and the duplicate merge, which now also keeps the series row a locked book still names), fix-read-by-narrator, fix-author-narrator-swap, refetch-missing-authors, author-split (`maintenance.author`), iTunes regroup (title), booksig recovery audit (description), and the author conjunction repair's paths (the primary-author rewrite, the title-as-author relink, the junk-row unlink that follows it, and the author merge, which now refuses to delete an author a locked book still credits). Each run's summary or log counts the books it left alone and names the lock (a repair's own lock counts as well as a user's).
- The title-as-author relink and the junk-row unlink now write a book's credits and its primary author in ONE commit (`ModifyBookCredits`) with the lock read inside it, so a lock never finds a book half moved and nothing is ever written back from a list read earlier. A store that cannot make that one commit is refused, not given a two-write fallback. A journal row written before such a commit is voided when the book is held or the write fails.
- An author merge (conjunction repair, duplicate-merge, strip-merge) is all or nothing per author: every book's lock is read before any book moves, one locked book holds the whole author, and the held author is counted in its own bucket (`held_user_locked_author`, `merges-held-user-locked`), not as a failure. Books moved before a lock saved mid-run are counted and the author cache is refreshed.
- The author split counts a book locked between its two writes as held, not as an error, and keeps the composite author for it. The fragments regroup's survivor update reads the title lock inside its write.
- The write-set gate can now be told about maintenance jobs: `TestOpWrites_*` derives each job's write set in the form `OperationDef.Writes` takes, and fails when a registered maintenance job has no Writes unless it is a listed, reasoned read-only job. Wiring it into `registerMaintenanceJobOp` is a separate reviewed change (it makes every maintenance job serialize against every other books or series op).
