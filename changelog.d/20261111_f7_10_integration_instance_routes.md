### Added

- core: the integration instance routes, `core/internal/integrationhttp` (dark: nothing mounts or imports it until F7-09). It registers on the core group the ten routes of the integrations registry's HTTP surface: the adapters list, `GET` and `POST {kind}/instances`, `GET`, `PUT` and `DELETE {kind}/instances/{id}`, the unsaved-body test at `POST {kind}/test`, the instance-scoped test at `POST {kind}/instances/{id}/test`, the instance's health, and `DELETE .../hold`, which releases the instance's active hold through a one-method `HoldReleaser`. Each route is a thin adapter over the registry, which keeps every security rule: a stored secret is never sent to a new origin, `Local` needs an interactive administrator, locked fields and version conflicts are 409, a failed secrets backend is 503. Secrets are write-only: a response carries a set or unset marker per secret field and never a value or a secret name, no answer quotes the registry's error text, and the test route answers only `ok`, `class` and `status`. A test is recorded as `core.integration.test`, and a test that cannot be recorded shows its caller no result (F7-10).
