### Changed

- `scheduler.metadata-refresh` is merged into `maintenance.metadata-refresh`. Both ran the same read-only scan for books with incomplete metadata under two IDs and two concurrency keys, so both copies could run at once. The scheduled `metadata_refresh` task now enqueues the `maintenance.*` op, and the old ID keeps working as an alias, so stored rows and API callers still resolve. The surviving op now requires `settings.manage` and keeps the 4h budget the scheduled copy ran with, up from 2 hours. It still refuses to run while a library scan holds the library.
