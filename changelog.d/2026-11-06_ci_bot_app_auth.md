### Changed

- CI: the four bots that write to GitHub (`todo-collect`, `auto-revert`, `ratchet-lower`, `memory-leak-scan`) now authenticate as the org-owned CI bot GitHub App instead of `GITHUB_TOKEN` or the personal `JF_CI_GH_PAT`. Each run mints a short-lived installation token with `actions/create-github-app-token` (pinned to a SHA), narrowed per workflow with `permission-*` inputs from the org variable `CI_BOT_APP_CLIENT_ID` and org secret `CI_BOT_APP_PRIVATE_KEY`, and commits as `<app-slug>[bot]` (slug and user id are looked up at runtime by the new `scripts/ci/set_bot_git_identity.sh`). A missing variable or secret now fails the job with a clear error instead of falling back to a token that cannot push. The app is the only bypass actor on the main merge-queue ruleset, which the daily TODO collection and a real auto-revert both need: since the queue went on, their direct pushes to main were rejected (GH013). Each job's own `GITHUB_TOKEN` is cut back to read-only (plus `issues`/`actions: write` for auto-revert's bug filing and gate re-run).
- CI: `todo-collect` now checks, before it pushes, that its commit sits directly on the default branch tip and touches only `TODO.md` and `todo.d/`; it previously persisted `GITHUB_TOKEN` in the checkout, which silently overrode the token in its push URL. `memory-leak-scan` no longer puts `[skip ci]` on its commit and PR title: with the PR now opened by the app, the marker would have suppressed the required checks the merge queue waits for.
