Added `module.Deps.TaskRows`, a handle a module uses to read the stored runs and rows of its own registered task kinds (list, rows, the plan of an apply run and one planned row of it) and to replace the rows of its own run (the maintenance jobs' class lists). A run of another module's kind, and a query that names one, are refused with `ErrTaskRowsForeign`. It answers `ErrTaskRowsNotBound` until the task engine is built. Nothing in ABO uses it while the tasks flip is off.

The kernel's start-permission rule for view-class scopes (SEC-9) now asks for a reviewed `StartableByViewers` reason only when a principal holding what a viewer can hold could satisfy the kind's start requirement. It reads core's scope catalog for each scope's class and for what the viewer seed is granted, treats a scope the catalog does not hold as held, and also refuses `Public` and `AnyAuthenticated` as a start requirement. A requirement that also names an action-class scope the viewer lacks, such as the settings atom's `core:system.view` beside `core:settings.manage`, needs no reason.
