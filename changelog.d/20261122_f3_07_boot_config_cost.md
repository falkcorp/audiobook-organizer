### Changed

- Config flip (F3-07): a boot builds its retired-name judgement store only when a retired name is set. Step 0 used to build a full scratch config store on every boot (every core and module section registered, then loaded) only to see whether a set retired name refuses boot. With none set that check cannot refuse, so it is skipped; `config.Store.AnyRetiredNameSet` answers from the environment and the operator file's top-level keys. A boot with a retired name set is judged exactly as before. The skipped store was a third of each boot's CPU in the crash-matrix tests.
- core config: registering a list of sections rebuilds the key index once at the end, not after each section (`config.Batch`; `RegisterSections` and the kernel's module-section loops use it). The per-section rebuild made registration quadratic in the number of sections. The index a batch leaves is the one the per-section rebuilds left.
- core kernel tests: every boot of one test shares a config section cache (`bootseam.WithSectionCacheForTest`), so the kill-matrix tests no longer rebuild every core section on each of their hundreds of boots.
- CI fixture tests: the fixture job runs six shards, up from three, and the package weights are measured from three green GitHub pipelines of the flip (slowest of three). internal/books measured up to 3,251 s, which is six parts, one per shard. internal/server keeps its earlier weight so it stays split for the macOS nightly, where it ran 1,030-1,390 s as one process. The A/B/O flip crash matrix runs as three tests (`TestBootCrashMatrix_ABOFlip_Part1`..`3`), each running every third first-level job of the same census (`crashmatrix.Scenario.Part`/`Parts`), so the planner can place it across shards instead of one 25-minute process.
- CI/tests: the R0 binary handed to `TestR0OpensR1Store` is now named by `AORG_TEST_R0_BINARY` (was `ABO_R0_BINARY`). A variable with the app's `ABO_` prefix that names no config key makes the flipped core config log a warning, so CI's exported harness variable made every boot under test append that warning to its log, and `TestCutoverRefusedByOlderBuilds` (the refused boot writes nothing) failed on CI only. `TestNoReaderOfADroppedField` loads through `typedload` (one type-checking goroutine) instead of `packages.Load`, whose concurrent checkers hit go1.27's go/types data race (golang/go#81122) under -race.
