### Fixed

- `itunes.regroup` skipped almost every iTunes book linked to a library copy. Any group whose files touched a book in a version group with a non-primary member was skipped, and every iTunes copy linked to a library copy is non-primary. It now skips only moves that would change a version group's editions: files leaving a group member (or emptying one), or files added to a group's primary copy, to a group with no identifiable primary, or to an edition that already holds another book's tracks. A non-primary iTunes edition may now receive its own album's ungrouped fragments. The rule reads where a book's files are, not only its primary flag: a book with any file under the library root (a library-folder copy, which can hold iTunes PIDs and need not be flagged primary) never receives iTunes rows, and files never leave a book that is organized or has files under the root. A target edition must hold only this album's tracks, so a file row with no PID also blocks it. Trashed and merged-away books are never a target or a source, Doctor Who / Big Finish / Torchwood books are skipped and counted, and the apply re-reads each group's books just before writing it and skips the group, with a logged reason, if anything changed since the plan. The op now refuses to run when `root_dir` is not set. A library-folder copy (a file under the root, or organized) is never retitled from the iTunes album tag: it keeps the metadata the metadata pipeline gave it, and the summary counts these as `library-title-kept`. Primary flags follow the shared incumbent rule (an unset flag is primary when it is the group's only unset member), where before an unset flag always read as not primary. A book row with no creation time no longer crashes the snapshot. The dry run (still the default) reports how many groups the rule change unblocks and newly blocks, and breaks skips down by reason. The op writes database rows only: no file on disk, tag, or iTunes library file is touched.
