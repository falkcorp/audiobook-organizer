### Fixed

- Books config cutover (F3-06 follow-up, still dark): a viper-read setting that the settings blob lacks but `config.yaml` holds (`log_level`, `organization_strategy`, `file_naming_pattern`, `playlist_dir` and the rest of the ten) is now staged from the file, as the pre-cutover build read it, instead of being deleted by the strip with nothing stored. The file's value is cast to the key's type by the same spf13/cast functions viper's typed getters call (so a quoted `"10.7"` is 10, not 0), and a number the plan cannot hold exactly (`.inf`, `.nan`, or beyond 2^53) for a key the settings blob lacks is refused by name instead of being read as absent and stripped. A value equal to the default is staged too, for the registry to skip as it does a blob member's. The `concurrent_scans` default is now compared against `max(NumCPU, 4)` on the host the upgrade runs on, not a recorded 10, and `playlist_dir`'s default is `playlists`, so an explicit empty value counts as a setting. Eight flat keys the old build still read (`audible_base_url`, `audnexus_base_url`, `google_books_base_url`, `openlibrary_base_url`, `itunes_library_itl_path`, `itunes_library_write_path`, `itunes_library_read_path`, `itunes_library_xml_path`) are now retired names, so the new build warns or refuses on them instead of ignoring them.
