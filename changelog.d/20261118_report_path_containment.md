### Fixed

- A report path passed to a maintenance operation (`reportPath`, or `report_path` for `series-phantom-repair`) is now confined to `{root_dir}/.reports`. Before, the operation wrote its report to whatever path the caller gave it, so a caller with permission to run the operation could point it at any file the server can write. A bare file name is a file in that directory; an absolute path must name a file directly in it; `..` segments, a symlinked directory that leads out of it, a report file that is itself a symlink, and a directory in place of a file are refused, and nothing is created outside the report directory when one is refused. With no `root_dir` configured there is no report directory to keep a path inside, so an explicit path is refused. The check lives in the shared report-path helper, so it covers every operation that resolves a report path: `book-shape-report`, `dedupe-book-file-rows`, `merge-same-path-dupes`, `metadata-cache-reap`, `mark-missing-files`, `missing-file-repoint`, `recover-missing-files`, `repoint-missing-to-folder-audio` and `rewrite-path-prefix`. `series-denumber` (which also writes `reportPath + ".applied"` beside it) and `series-phantom-repair` wrote the caller's path directly and now resolve it through the same check before they read or write anything.
- Anyone who passed a `reportPath` outside `{root_dir}/.reports` (a path under a temp directory, say) now gets a refusal that names the directory the report must go in; pass a bare file name, or a path to a file directly inside it, instead.
