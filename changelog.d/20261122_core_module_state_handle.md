### Added

- Core now gives every module a labelled state filesystem (`Deps.State`, `module.StateFS`) and a keyring-exported query (`Deps.SecretsKeyringExported`), so a module's start hook can delete a legacy file under a crash-matrix label and can tell whether the keyring has been exported before it deletes a key. The handle removes a file or a directory tree by absolute path inside the state directory and the directory beside the store, refuses anything else (a path that leaves them through `..` or a symbolic link, either root itself, an empty label), and fsyncs the parent directory under the same label, so the crash-matrix kit sees, kills and fails each removal like a core boot writer. The query is true only when every key of the keyring is named by an export record and is false when the record cannot be read or the secret store is closed. Nothing in the application calls either yet. The handle also refuses, with `module.ErrStateCoreOwned` (which wraps `ErrStateConfined`), any removal of a path that is, lies inside or contains something core owns: the open store and its sidecars and checkpoints, the swap lock and restore directories, the keyring and its export record, the config boot record, the bootstrap token and the backup location file. Each owner exports the name of what it owns (`secrets.OwnsStateName`, `config.OwnsStateName`, `storage.CheckpointRoot`, `restoreswap.LegacySuffixes`), so a hook that reaches for the store or the keyring is refused and the list cannot drift from the files.
