### Fixed

- The task routes core will mount at the F5-18 flip now match the reach of the v1 task routes they replace (F5-18, dark: nothing mounts them yet, so the running binary is unchanged). `GET /schedules` needs `core:tasks.manage`, as `GET /api/v1/tasks` needed settings.manage. `GET /counts` counts only the runs the caller may view, deciding once per kind, through the new optional `tasks.KindCounter` on the run store; a store without it makes the route refuse rather than answer raw totals. A run of a kind this build does not register follows the View rule its stored `def/<kind>` snapshot recorded (snapshot version 2 now carries it); a kind whose snapshot is missing, unreadable or from before this change is hidden from every caller, an administrator included, and the log says which kind and why (`reason "no view snapshot"`), never a run id. A disabled module's snapshot written by an earlier build stays hidden until the module is enabled once.
- The M4 import now writes an imported actor's auth method the way a live request of that user is stamped: `api_key` becomes `token`, `cf_access` becomes `ext:cfaccess`, `abs` becomes `books.abs`; `session`, `session_delegated`, `system` and an empty method are kept. A method outside that list is kept as HEAD wrote it and counted as `auth-method-unmapped` in the M4 report. This lets an imported run's own actor match the executor's own-run arm, which makes it depend on #5077 (cancel and discard need `Perms.Manage`, no own-run arm): without that change the same user could discard an imported run, which HEAD allowed settings.manage alone to do.
- A diagnostics export that HEAD had not finished (queued, running, paused, stopping, interrupted or awaiting a decision) is imported as a canceled run with the reason "imported; restart the export", never as work the executor could pick up. Finished exports import unchanged, and the M4 report counts the cut-short ones (`diagnostics-export-canceled`).
- The M4 import now records, for each kind it carries over, who may read that kind's runs, as HEAD's read gate said: a Repairs fixer's runs need the same permissions the fixer needs (every permission for a fixer no longer registered, bar the ones the owner retired), every other kind's runs are readable with library.view. Without it every imported run of a kind with no definition would have been hidden from everyone. The M4 report counts the kinds recorded (`kind-view-stamped`); an atom HEAD's gate names that books cannot translate stops the import and names the kind.
