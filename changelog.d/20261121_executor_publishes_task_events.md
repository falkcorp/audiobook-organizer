### Added

- The core task executor publishes `core.task.run-changed.v1`, `core.task.log-appended.v1` and `core.task.finished.v1` after each run commit (F5-18, slice E6b, dark: nothing wires `Options.Events` before F4-08, and a nil publisher costs nothing). Run-changed goes out for every committed transition, a queued run's insert and merge-fold, and each persisted progress tick; log-appended for each run-log line, keyed by the run; finished once per terminal transition. Payloads are built when the change is staged and published only after their batch commits, so a failed or retried commit publishes nothing. Events for one run leave in commit order and are published by one drainer goroutine, so a slow subscriber never holds a lock the executor needs. Stream payloads never carry `blocked_by`. The drainer's queue is bounded (16384): when a stalled subscriber fills it, superseded run-changed are coalesced to each run's latest view, then new run-changed and log-appended events are dropped and counted, and `finished` and terminal run-changed are never shed; the committer never waits. Shutdown drains the queue, and after its deadline abandons it so the drainer exits as soon as the in-flight subscriber call returns.
