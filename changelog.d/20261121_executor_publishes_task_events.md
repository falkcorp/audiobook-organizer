### Added

- The core task executor publishes `core.task.run-changed.v1`, `core.task.log-appended.v1` and `core.task.finished.v1` after each run commit (F5-18, slice E6b, dark: nothing wires `Options.Events` before F4-08, and a nil publisher costs nothing). Run-changed goes out for every committed transition, a queued run's insert and merge-fold, and each persisted progress tick; log-appended for each run-log line, keyed by the run; finished once per terminal transition. Payloads are built when the change is staged and published only after its batch commits, so a failed or retried commit publishes nothing. Events for one run leave in commit order and are published by one drainer goroutine, so a slow subscriber never holds a lock the executor needs. Stream payloads never carry `blocked_by`.
