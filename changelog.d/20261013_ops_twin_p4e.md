### Changed

- `scheduler.author-split-scan` is merged into `maintenance.author-split-scan`. The two copies ran the same split, but the scheduler copy lacked later fixes: it overwrote a book's primary author even if the book had been re-credited in the meantime, it skipped a book silently when its author list could not be read, and it counted every relinked book as "updated" rather than only the ones whose primary author changed. The surviving op keeps all three behaviours, so an apply under either ID is now the safer one. Both still default to a preview, and the scheduled `author_split_scan` task still sends no mode, so scheduled runs stay previews. The old ID keeps working as an alias, so stored rows and API callers still resolve. The surviving op now requires `settings.manage` and keeps the 2 hour budget (up from 1 hour). It is still re-queued after a restart, because an interrupted apply leaves the composite author in place and a rerun finishes it without crediting anyone twice.
