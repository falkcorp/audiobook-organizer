### Fixed

- core: the diagnostics bundle's opaque query now runs to the next whitespace in every context. A raw quote, backtick, apostrophe, bracket, angle bracket or comma in a directory name inside a request target or URL query no longer ends the redaction early and leaves the rest of the name in a free-text log line. The path part of a request target or URL is read to the same end, so a directory name with a quote in it after a doubled slash or an encoded separator is replaced whole. A quoted route with a query loses its closing quote and any punctuation glued to it in the redacted bundle. Pinned by exact-output tests, a widened planted-marker generator and fuzz target, and linear-time tests for a line of quotes.
- core: a URL in a diagnostics line now ends at the first byte that cannot be in a host, so the path that follows a quoted host in compact JSON (`"https://host","p":"/Users/name"`) is redacted and not read as part of the URL. A path-bearing token right after a cut URL, and an encoded path after a closing-tag or placeholder prefix inside a whitespace-free run, are judged the same wherever they start; a differential test compares the scan with and without its linear-time skip.
- core: the diagnostics bundle no longer leaves a percent-encoded absolute path readable when it follows a root placeholder or a closing tag with no quote between them, and a URL cut short by a byte that cannot be in a host keeps its opaque query and fragment placeholder. A URL with no host, a drive where the host would be, or a host that holds an encoded path separator is judged as a path, not as a URL. A new property test plants a marker through independent prefixes, contexts, spellings and directory names and fails if any byte of a path is readable in the redacted output.
