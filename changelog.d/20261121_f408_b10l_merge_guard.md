### Added

- Under core identity (`server.WithIdentity`, which nothing sets yet) the user-merge preview, apply and resume routes now answer 409 `merge_unavailable_under_identity` before any account is resolved, any body is read, any plan is built or any grant is minted, and `usermerge.Service.BuildPlan`, `Apply` and `Resume` refuse the same way (`Service.CheckAvailable`, fed by `usermerge.WithIdentityFlipped`). Once the identity cutover has moved accounts, keys and sign-ins into core's store, books' merge would plan from rows that no longer exist and write rows nothing reads; this is the stop-gap until the merge is ported onto core's `StageUserMerge`. Undo stays B10b2's 409 `merge_permanent`. A server without the option behaves exactly as before.
