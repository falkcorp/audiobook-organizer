### Fixed

- The provenance ledger directory, `{root_dir}/.ledger`, is created `0750` (`library.LedgerDirMode`) instead of `0775`, and an existing one has group and world write removed (the operator is told, as for the report directory's world write; read and execute bits and the setgid and sticky bits are left as found). A directory the group can write is one where any group member can unlink or rename the ledger file whatever the file's own mode is, and the next export would then start a new file from its stored cursor with a gap nobody sees. The report directory is unchanged (`0775`, only world write ever removed).
- A report or ledger path that is refused because of its shape (`..`, an absolute path elsewhere, a name with a directory in it, a NUL byte, the directory itself) is now refused before anything is created; before, the report directory was made, checked and probed first, so a refused path could leave a new `.reports` behind on a root that had none. An absolute path spelled through a symlinked root is still accepted on a first run, when the directory does not exist yet.
- Refusals and errors about the ledger say ledger, not report, at every stage: the directory checks, the write-time open (`library.OpenReportFile` takes the word from the directory it is opening in), the writable-probe file name (`.ledger-write-probe-*`) and the chmod failure message. Every refusal still matches `library.ErrReportFileUnsafe`.
- `library.Mounted` trims whitespace from the root before judging it, as the report and ledger path resolvers do, so a root with stray whitespace in the configuration is no longer refused as unreadable by the mount check while the resolver would have accepted it.
- The job write-set oracle counts `library.ReportPathNotify` and `library.LedgerPathNotify` as file writers (they create the directory, remove write bits from one that has too many, and create and remove a probe file), and fails if a name in its table of outside file writers is not a function of the package it names.
- Corrections to what was claimed for the report-path work: the executive summary said a refused path creates nothing, which was false for a path refused only after the directory had been prepared (now true for every refusal about the path's shape, and stated for the rest); `t6g2Deps.ReportPath`, the hook the native `book-shape-report` kind is wired through, says it must be `Plugin.resolveReportPath`; `core/library/doc.go` lists the ledger helpers; the stale `last-edited` headers on the backfill-file-hashes job and its two tests are brought up to date; and the test that points every report op at the ledger's absolute path now asserts the refusal's reason rather than only that some error occurred.
