### Added

- core: the native task stores (`core/tasks`, dark): `NativeStores` over the `c/tasks/` keyspace, with the key layout and raw staging in `core/internal/taskstore` (run rows with derived queue, kind, state and done indexes kept in step on every write; per-run event, intent, item and log pages; checkpoints, chunks, plan rows, applied-row marks, strikes, debounce buckets, schedule clocks, the pause marker, stand-down markers and per-subject stamps), the one-shot `Importer` that writes v1 rows into the same keyspace (a run that was running or stopping lands as interrupted, a second import of the same run is refused, and `RenameKind` moves a kind's runs, clock, definition snapshot, debounce buckets and stamps in resumable pages), and the `taskstest.StoresSuite` conformance kit with importer cases (F2-02; nothing calls it until the kernel wires boot in F2-16). Every staged write checks what it read again at commit time, so two writers racing over the same run get a conflict rather than a lost update; a run whose ledger has closed refuses further progress, checkpoints, chunks and row marks; `Prune` deletes only runs that are still terminal and still older than the cutoff when it reads them again, removes orphan done-index entries and walks past rows it cannot decode, so no entry stalls it; a terminal run without a finish time is refused rather than stored where retention would delete it at once; and every method that reads before it writes refuses a batch that is not indexed (`tasks.ErrBatchNotIndexed`, via the new `storage.Batch.Indexed`), so a second write of a run in one batch can never read past the first and lose it. `RunStore` gains `Marks` and `Strikes`, and `RenameKind` also moves start idempotency records.
