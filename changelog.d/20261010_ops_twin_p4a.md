### Changed

- `scheduler.temp-file-cleanup`, `scheduler.trash-cleanup`, `scheduler.tombstone-cleanup` and `scheduler.db-optimize` are merged into `maintenance.temp-file-cleanup`, `maintenance.trash-cleanup`, `maintenance.tombstone-cleanup` and `maintenance.db-optimize`. Each pair ran the same work under two IDs and two concurrency keys, so both copies could run at once. The scheduled tasks now enqueue the `maintenance.*` op, and the old IDs keep working as aliases, so stored rows and API callers still resolve. The survivors now require `settings.manage` (they delete files or rewrite data) and keep the longer budgets the scheduled copies ran with: 1h for the three cleanups and 2h for the database compaction. The temp-file cleanup still writes its daily summary line to the activity feed.
