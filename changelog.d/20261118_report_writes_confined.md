### Fixed

- Maintenance reports are now written through a confined open as well as a confined path. `library.WriteReportFile`, `library.PreflightReportFile` and `library.OpenReportFile` (new, in `core/library`) open the report relative to a handle on `{root_dir}/.reports` with `O_NOFOLLOW`, then fstat the descriptor and refuse anything that is not a regular file owned by the process's user with a single link. The file is truncated only after that check, so a hard link or another user's file is refused untouched. This closes the window between the path check at the start of a run and the write, in which a symlink or hard link planted at the report's name would have redirected the write. All twelve report writers, `merge-same-path-dupes`'s preflight, the `-decisions.tsv` sibling of `dedupe-book-file-rows` and `series-denumber`'s `.applied` file go through it, and a new test drives every one of them against a planted symlink, a planted hard link and a missing directory.
- A report path is now a file directly in `{root_dir}/.reports`: a bare name, or an absolute path whose directory is that one. A name with a directory in it (`mine/chosen.tsv`) is refused, where it used to be accepted and its directory created. Report writers no longer create directories, and `library.EnsureDirWritable` and the `afterCreate` hook are removed.
- `maintenance.file-provenance-export`'s `path` is confined to its own directory, `{root_dir}/.ledger` (`library.LedgerPathNotify`), not the report directory: every report writer truncates the file it is given and `reports-prune` deletes by name, so a ledger kept among the reports was one wrong report name from being emptied (for example `book-shape-report {"reportPath":"ledger.jsonl"}`). Nothing that resolves a report path can reach `.ledger`, a ledger path in `.reports` is refused, and a report path in `.ledger` is refused. It was an absolute path anywhere, appended to; it is now a bare name, or an absolute path in `.ledger`, opened through `library.OpenReportFile` (append), which refuses a link planted at its name; the cursor does not advance when it refuses. The op refuses to run, on a preview too, when the library root is not mounted (`library.Mounted`), so an unmounted share's mountpoint never receives the ledger. The op still requires the settings-manage scopes and `files.write`.
- A ledger kept outside `.ledger` has to be moved in or restarted: the export resumes from its stored cursor, so a new file starts at that point. A ledger copied in must be a regular file owned by the account the service runs as, with one link (a `sudo cp` leaves it root-owned and it is refused until `chown`ed). Resolving a report path now also vets a file that is already at a fixed default name, so a foreign-owned or hard-linked file left at such a name stops that op up front, with a message that names the file.
- `backfill-file-hashes` writes its report through `library.OpenReportFile` (new `ReportTouch` for a fresh run, then its own size and owner check and truncate; new `ReportReadAppend`, O_RDWR with no truncate, for a resume) instead of its own path-based `O_NOFOLLOW` open. That open followed a symlink in any directory above the file and did not check the link count, so a hard link at the report name was opened read-write. The size cap on a resumed report is kept.
- A default report file name that is not a single plain file name is refused by `library.ReportPathNotify` (the CodeQL barrier row claimed that already). The refusal messages for a missing or relative `root_dir` now say to configure an absolute `root_dir`, and the doc comments on `ReportPathNotify` and the report-directory helper no longer claim a mode or an "owner-only" property they do not provide. `series-denumber`'s help text names the report directory, and the `t6g2Deps.ReportPath` and `t6g6Deps.ResolveReportPath` hooks say they must be `resolveReportPath`.
