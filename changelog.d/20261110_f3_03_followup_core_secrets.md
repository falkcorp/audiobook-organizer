### Fixed

- core/secrets: a `secrets.Value` no longer prints its bytes when fmt or slog cannot call its methods: held in an unexported field, alone or in a slice, array, map or nested struct, under any verb. The bytes now sit behind a pointer to a pointer, which fmt prints as an address on every path. A struct holding the `*secrets.Store` in an unexported field (the kernel's `kernelSecrets`), or a bound `secrets.Ref`, no longer prints operator values with `%s` or `%q`, and a type check fails any later Store field that holds key material without a pointer (F3-03 follow-up).
- core/secrets: `Get`, `Meta` and `All` copy an operator value under the store's lock, and `Ephemeral` wipes a replaced value only after the new one is in place, so a read beside a replace never returns the old value's zeroed bytes.
- core/secrets: `UnexportedKeys` takes the key digests under the store's lock, so a call running beside `Close` no longer hashes key material `Close` is wiping and reports a fully exported keyring as unexported.
- core/secrets: `Open`, `secrets rotate-derive` and `secrets set-install-id` refuse a keyring path that is not a regular file (a symbolic link, dangling or not, or a directory) with an error that says so, as `secrets export-keyring` already did; a dangling link was refused as "it appeared meanwhile".
