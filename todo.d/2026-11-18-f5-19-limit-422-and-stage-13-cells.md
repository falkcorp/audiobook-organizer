- [ ] **F5-19-HANDOFF-TO-F5-18** What the dark journal route (`core/internal/loghttp`) leaves for the mounting row. (1) The stage-13 cells in `permissions_test.go` (`403` for a `core:system.view`-only principal, `401` for no principal) and in `routes_test.go` (`TestLogRoute_AuthOffAnswers401`, booted cell) are `t.Skip("needs stage 13: F4-08")`; F5-18 deletes the skips once a router can be built with an auth service, because until then `Router.Build` refuses every non-Public route and no request can be sent through one. Handler-level tests call the handler with the principal and its checker bound, as `core/internal/audithttp` does, and `TestLogRoute_QueryStringBindsToTheRequest` proves the query tags through `Router.OpenAPI`. (2) The wire shape is `httpapi.CursorPage` (`{items, next_cursor}`, 05-http-api §4.4), not the brief's `{records, next}`: the spec names the system journal a cursor-paged feed and wins over the brief. The SPA's log view moves to `items` and `next_cursor` in the same PR that mounts the route, and the brief's code contract should be corrected. (3) Every malformed query value answers 422 `validation_failed` (a bad `level`, `since` after `until`, an unparseable `since`, `until` or `limit`), the same as `core/internal/audithttp`; a cursor the journal did not issue answers 400 `invalid_cursor`. (4) The other-user rule is applied inside the store's scan through the new `log.JournalQuery.Hide`, so F5-18 wires `Deps.OtherUser` (the books predicate) and nothing else; an app's own `JournalStore`, if one is ever supplied, must honour `Hide` too (`logtest.JournalStoreSuite` case `hide_is_as_if_the_record_were_absent`). One residual remains by design: when a single `Query` examines 20000 rows without filling the page, the cursor names the last row examined, which can be a hidden one.
