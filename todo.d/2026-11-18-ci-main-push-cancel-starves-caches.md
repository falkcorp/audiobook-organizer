- [ ] **CI-MAIN-PUSH-CANCEL-STARVES-CACHES** `ci.yml` cancels an in-progress push run on main when the next merge lands (`concurrency` group per ref, `cancel-in-progress` true for non-merge_group events). Caches written by PR and merge-queue refs are invisible to other refs, so main is the only ref whose caches help everyone, and a cancelled main run never reaches its cache saves. The apt .deb cache now saves right after its install step (PR "apt mirror rotation"), which makes the save likely but does not guarantee it. A guarantee needs a concurrency or trigger change (e.g. do not cancel push runs on main, or a scheduled cache-warm run on main), which was out of scope there. Check `gh api repos/{owner}/{repo}/actions/caches` for `apt-debs-*` entries on `refs/heads/main` a day after the PR merges.
