- [ ] **DM-CHUNK-CONFIG-UNWIRED** (due: before R2, as its own core PR after main is green; owner: platform-core). The config keys `core.storage.data_migration.chunk_items` and `core.storage.data_migration.chunk_bytes` are declared (`core/kernel/core_sections.go`, about lines 364 and 975) but nothing reads them: they are absent from `DataMigrationsConfig` (`core/kernel/storage.go`, about line 168), so every data step runs with the fixed chunk size of 2000 items whatever an operator sets. A declared key that is never read is the defect: it promises a setting that does nothing, silently. Fix one way or the other, with cells: wire both keys into `DataMigrationsConfig` and the chunker (a cell that a configured chunk size changes the chunk count of a data step, and that a bad value is refused at config load), or, if nothing should tune chunking, delete both declarations and their docs. Not a correctness problem for the F4-08 deploy: at production scale M2 and M3 each fit in one chunk (M3 read 651 rows on the production-shaped corpus), and multi-chunk kills are covered by TestIdentityCutover_CrashAtEveryChunk and the TestMidM3_ cells. Found by the F4-08 mid-M3 coverage work on 2026-11-28.
