Since #5067 it runs only inside the `production-shaped-store` job of `.github/workflows/extraction-gates.yml`, gated on `R2_SHAPED_GENERATOR_CELL=1` (`scripts/ci/run_production_shaped_store.sh`), and that job runs only when the `changes` classifier reports `shaped=true` for a PR's diff. Code outside those paths (a storage, claim or key-family change in core, a new books key family) can break the generator's output without the cell running. Make it run at least weekly on main whatever changed. `extraction-gates.yml` has no `schedule:` trigger today, and its `changes` job (a verbatim copy of `ci.yml`'s classifier, held equal by `scripts/tests/test_ci_classifier.py`) has no PR diff on a scheduled run, so adding a cron there means deciding what every other gate job does on a `schedule` event. Either give `production-shaped-store` an `if:` that also accepts `github.event_name == 'schedule'` and make the other jobs skip on schedule (keeping the terminal `extraction-gates` job's verdict correct), or run the job from a small separate scheduled workflow that reuses `run_production_shaped_store.sh`. Either way, a scheduled failure must be visible (an issue or a failed run on main), not a silent skip.
