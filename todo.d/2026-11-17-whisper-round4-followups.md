- [ ] **WHISPER-ROUND4-FOLLOWUPS** Review items from the non-Mac worker's fourth round that are not fixed in that PR: (1) `manage-whisper-server.py --restart` over WinRM is unverified at runtime: whether a process started with `Start-Process` from a pywinrm shell survives the shell closing needs one try on the target box. (2) The Job Object assignment opens the child by pid (`OpenProcess`), which has a pid-reuse window; the handle multiprocessing already holds would avoid it. (3) Whether the assignment succeeds when the worker already runs inside a job (Task Scheduler, uv, a CI runner) is not established; the `child_unprotected` flag on `/health` now shows the failure but nothing exercises the nested case. (4) The supervisor's health probe accepts any 200 on the port, so another process holding it makes a run that failed to bind count as healthy once it has run 120 s. (5) `whisper-windows.yml` has no `paths:` filter and installs `uv`, `pytest-timeout` and ffmpeg unpinned. (6) Upload bodies are read whole into memory, up to 256 MiB per part times the threadpool's concurrency (bounded by the loopback default). (7) `install-whisper-supervisor.ps1` registers the task without `-ExecutionTimeLimit`, so Task Scheduler's default limit may stop the supervisor after about 3 days without a failure that `-RestartCount` would act on. (8) `test_whisper_mlx_pins.py` says "The one deliberate change to this pin" although two pins were edited. (9) `Engine.run` waits for a free runner without re-checking the clip deadline, and an unreapable temp directory on Windows is not handled. (10) A crashing clip costs one model load with no worker-side backoff. (11) The start path of a decode child lacks the run path's `except BaseException` guard, so an unpicklable ready message would leave a child alive without a pin check (unreachable with our own child). (12) A stop during a hung decode can wait up to the clip deadline because the child is killed only after the web server returns; uvicorn's graceful-stop behaviour was read from the code, not tried, and `timeout_graceful_shutdown` is not set. (13) The Mac worker (`whisper_mlx_server.py`) does not send the `identity` object yet, so its results are still journalled under the `/health` identity.
