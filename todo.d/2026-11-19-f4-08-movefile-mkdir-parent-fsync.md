- [ ] **F4-08-MOVEFILE-MKDIR-PARENT-FSYNC** `journal.MoveFile` creates a missing destination directory with `MkdirAll` and fsyncs only the leaf directory (`core/backup/journal/move.go`, the `journal.move.dirsync` region); the parents it created are never fsynced. The kernel then writes `backup.location.json` pointing at the new path and removes the source, so a crash can lose the new directory, and the moved journal with it, while the record points there. Fix: fsync each ancestor `MkdirAll` created (stat from the leaf up to the first one that existed), under `journal.move.dirsync`, and add a crash cell over a fresh destination directory (none of the journal's cells uses one; the site "MoveFile creates a missing destination directory first" pins the current sequence and changes with the fix). Found in the round-1 review of the labelled-FS seam PR; out of its scope because that PR keeps production behaviour.
