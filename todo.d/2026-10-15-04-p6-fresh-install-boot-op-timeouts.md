- [ ] **04-P6 fresh-install boot ops** On a fresh install, or any library where their done flags are unset, the four boot-enqueued ops (`maintenance.external-id-backfill`, `movement-atom-cleanup`, `malformed-m4b-remux`, `malformed-m4b-transcode`) are full-library walks with timeouts of 30 min, 60 min, 120 min and 6 h, which a large first run can exceed. Each holds a registry worker while it runs. They are PriorityLow, so they never jump queued user work, but they still occupy workers. Decide whether a first run should get longer timeouts, a resumable checkpoint (ResumeRestart over a file cursor), or a lower per-plugin concurrency cap. 04-P7 adds a fifth: `maintenance.opchange-book-index-rebuild` `{"ensure": true}` (60 min timeout) walks the whole operation-change journal every boot to verify the index, and a first build or a rebuild after a rollback walks it again; the journal is never pruned by log retention (see UNDO-WINDOW-PRUNE), so it only grows. A run cut by the timeout leaves the index untrusted (reads use the full scan) and the next boot resumes from the backfill cursor.
