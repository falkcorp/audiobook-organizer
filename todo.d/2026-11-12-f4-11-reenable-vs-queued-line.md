- [ ] **F4-11-F4-08-REENABLE** F4-08 decides how an admin's re-enable of a user survives the drain of an older queued revocation line. A revocation line a newer build journaled is queued by the first older build to boot, and applied by the first build that knows its kind. The drain applies what the journal says, in the journal's order, and auth journals revocations only, not their undo, so a re-enable (a user re-enabled, a password set again, a key re-enabled) made after the line was journaled and before that upgrade boot is overridden by the drain. The window is unbounded: any time before the upgrade, and any ordinary upgrade boot, not only the time between the queue and the drain. Options: journal the re-enables (a line kind for each undo, so the replay sees the order), or an age rule (a queued line older than a bound is not applied, and the boot fails closed for it instead). Until then the same property holds for any re-apply of a journal line after the store's head, as a restore does.
