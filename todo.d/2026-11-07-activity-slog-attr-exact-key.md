- [ ] **internal/activity: match slog attribute keys exactly when reading op_id/component.** `extractSlogAttr` (`internal/activity/writer.go`, called for `p.OpID` and `p.Component`) takes the first `" <key>="` substring anywhere in the line, so a quoted message or an earlier attribute value holding text like `x opID=other` (a folder or file name) attributes the activity row to the wrong operation or component. Read the keys from `scanSlogAttrs(line)` with an exact key match instead (msg excluded). This must land before R1-15/R1-18 route ABO's logging through the core pipeline: the pipeline writes context attributes (the operation attrs) after the record's own, so the first-substring match would then see record values first. R1-36 keeps the interim `logger.InfoCtx` helpers writing the context attributes first, as HEAD did, until then.
