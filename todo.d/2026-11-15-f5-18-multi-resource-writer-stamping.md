- [ ] F5-18: let a gated writer call carry every resource of its method's row. The shared method-to-resource table (`t6WriterResources`, `internal/plugins/maintenance/kinds_resources.go`) gives most store methods a row of several resources (ModifyBook is `books`, `metadata_cache`, `indexes`; the file-row methods are `book_files`, `books`; MergeBooks has seven). `tasks.Write.Resource` (`core/tasks/writer.go`) is ONE `entity.Ref`, and `core/internal/executor/writer.go` checks only that tag against the kind's Effects (`ErrOutsideEffects`). A write tagged `books` that also touches `metadata_cache` or `indexes` therefore passes untagged: it is not refused, but the executor's conflict model never sees the other resources, so a kind that declares only `indexes` or only `metadata_cache` can run beside it. Either stamp one `Do` per resource of the row, or extend the writer API so a write names several resources; do not build a per-call workaround in the kinds. Stamping is per group (each group's writer interface takes its rows from its view of the table), not one global books writer. Register for the books module the names the rows use that no kind declared before: `settings`, `metadata_cache`, `indexes`, `sync_identity`, `fingerprint_index`, `field_states`, `embeddings`, `files`. Recorded in `docs/agent-tasks/platform-core/seams.d/F5-09.md` and `F5-10.md`.
