- [ ] **Purge file journal follow-ups (PR 4140 review, n5, n6)** Two items left open. (n5) The journal has no boot-time replay of its own. A crashed manual pass is covered by its `ResumeRestart` re-run, and any leftover records can now be drained from the purge dialog ("Finish removing N files", offered when nothing is purgeable), but a crashed nightly (`ResumeDrop`) still waits for the owner to do that, and a library scan in the gap re-imports the files as new books. A boot hook was not added because at boot the library mount may not be up yet, and an unmounted ZFS or NFS mount point is an empty directory, so a stat reads ENOENT, which the replay takes as "gone" and clears the record: the hook needs a mount-readiness check (the library root is a mount, not the bare directory) before it can run safely. (n6) Every path check in the purge (journal path, `book_atpath` key, `BookFilesAtPath`) compares exact bytes, so a row naming the same file as `/lib//x`, in NFD instead of NFC, or in different case on a case-insensitive filesystem is not seen; storing and comparing `filepath.Clean` paths would remove the `//` and `./` forms.
