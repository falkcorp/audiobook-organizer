## Goal
After this PR the Deluge client can read what the cleanup fixer needs per torrent (ratio, seeding time, added and completed times, finished flag, the file list with sizes and per-file progress) and can remove a torrent together with its downloaded data. Nothing in the application calls the new remove method yet; the PR only adds capability and pins the exact JSON-RPC shapes in a fake server.

## Steps
1. **Types.**
   - `TorrentFile{Index int; Path string; Size int64; Offset int64}` with json tags `index`, `path`, `size`, `offset` (Deluge's `files` entries; `Path` is relative to `save_path`).
   - `TorrentDetail` embeds `TorrentStatus` and adds `Ratio float64 "ratio"`, `SeedingTime int64 "seeding_time"` (seconds), `TimeAdded float64 "time_added"`, `CompletedTime float64 "completed_time"` (Unix seconds; Deluge returns these as numbers that may be integral or fractional, so decode as `float64`; `0` means unknown), `IsFinished bool "is_finished"`, `Files []TorrentFile "files"`, `FileProgress []float64 "file_progress"`, `FilePriorities []int "file_priorities"`, `TotalDone int64 "total_done"`. Add a helper `(d TorrentDetail) AbsPath(f TorrentFile) string` returning `filepath.Join(d.SavePath, f.Path)`.
2. **Field list.** `torrentDetailFields` is `torrentFields` plus `ratio, seeding_time, time_added, completed_time, is_finished, files, file_progress, file_priorities, total_done`. Build it by appending to a copy so the two lists cannot drift.
3. **Reads.**
   - `GetTorrentDetail(hash string) (*TorrentDetail, error)`: `core.get_torrent_status(hash, torrentDetailFields)`. An RPC error whose message mentions an invalid or unknown torrent, or a successful decode into an empty object (`Hash == ""`), returns `ErrTorrentNotFound` (callers need "already gone" to be distinguishable from "Deluge is down"). Validate `hash` first (step 5).
   - `ListTorrentDetails(hashes []string) ([]TorrentDetail, error)`: one `core.get_torrents_status({"id": hashes}, torrentDetailFields)` call per chunk of at most 50 hashes; results returned sorted by `Hash` for determinism.
   - `ListTorrentDetailsByLabel(label string) ([]TorrentDetail, error)`: calls the existing `ListTorrentsByLabel(label)` (light fields, case-insensitive, empty label means all) to resolve the hashes, then `ListTorrentDetails`. Rationale: keeps the existing case-insensitive label semantics and fetches `files` only for torrents in scope. The `id` filter key is documented but unprobed; the test pins the request shape.
4. **Remove.** `RemoveTorrent(hash string, removeData bool) (bool, error)`: `core.remove_torrent(hash, removeData)`. Result `true` returns `(true, nil)`. Result `false` returns `(false, ErrRemoveRefused)` (an error as well as the bool, so a caller that ignores the bool still fails closed). An RPC error naming an invalid torrent returns `(false, ErrTorrentNotFound)`. Any other RPC error is wrapped with the hash. It never retries except the single post-re-login replay described in step 6, and never calls any other method.
5. **Safety of the id.** An EXPORTED `NormalizeTorrentID(s string) (string, error)` (10-PR1 and 10-PR2 reuse it) accepts exactly 40 or 64 hex characters, lowercases them, and rejects empty strings, whitespace, and anything else with a clear error before any request is sent. `RemoveTorrent`, `GetTorrentDetail` and `ListTorrentDetails` call it. An empty or malformed id must never reach `core.remove_torrent`.
6. **Session expiry.** `Login` sets `authed` once and never clears it, so after Deluge's web session times out every call on the long-lived process-wide client fails until restart (verified: `authed` is written only at `client.go:135`). `Login` holds `c.mu` and itself calls `call("auth.login", ...)`, so the retry must NOT live inside `call` (it would deadlock or recurse). Add an unexported `callAuthed(method string, params ...any)` wrapper and make every public method except `Login` use it. `callAuthed` runs `call`; if the RPC error text contains "Not authenticated" (case-insensitive), it takes `c.mu`, sets `authed = false`, releases `c.mu`, calls `Login()`, and replays the original request once. It never does this for `auth.login`, and a second auth error is returned as is. Keep this inside `client.go`; do not change the public method set. This affects every client method, so report it in the hand-back. Never replay `core.remove_torrent` more than once, and only after a fresh successful `Login`.
7. Leave `ListTorrents`, `ListTorrentsByLabel`, `GetTorrent`, `MoveStorage`, `ListLabels`, `Connected` behaviour byte-identical (same request params, same decoding).
