## Goal
Library files that were organized before 10-PR1 have no torrent link, so the cleanup fixer cannot prove which torrent a book came from. This PR adds a v2 operation `deluge.link-backfill` that, for each torrent in scope, finds the library `book_file` row holding the same audio content, verifies it by content hash, and writes exactly one field (`BookFile.DelugeHash`). It defaults to preview. It never deletes anything.

## Steps
1. **Def.** ID `deluge.link-backfill`; `Liveness: sdk.LivenessRunItems`; `Plugin: "deluge"`; `Writes: []sdk.Resource{sdk.ResBookFiles}`; `Permissions: []auth.Permission{auth.PermIntegrationsManage}`; `ConcurrencyKey: "deluge.link-backfill"`; `ResumePolicy: sdk.ResumeRestart` (the op is idempotent); `Timeout: 4 * time.Hour`; `Cancellable: true`; no Schedule, no Triggers (manual only). Capabilities: `CapLibraryRead`, `CapLibraryWrite`, `CapFilesRead`.
2. **Params.** `dry_run` / `dryRun` (`*bool`, resolved with `opmode.ResolveDryRun`, so omitted means preview; log the disagreement error), `label` (default: `config.AppConfig.DelugeDiscoveryLabel`, `internal/config/config.go:1669`), `limit` (0 = all), `workers` (default `runtime.NumCPU()`, capped at 8).
3. **Source list.** `p.client.ListTorrentDetailsByLabel(label)`. A nil client or an unreachable Deluge fails the run with a clear error (nothing written). Skip torrents whose `NormalizeTorrentID(hash)` fails. Only files whose extension is an audio extension count (D62); skip the rest and count them `non_audio`.
4. **Candidate resolution, per torrent file F (absolute path = `SavePath` joined with `F.Path`).** Try in order, stop at the first rule that yields candidates:
   a. `DelugeOriginalPath == abs path` (match against a map built once from `GetAllBookFilesCore`).
   b. Hash first: compute `H = filehash.BookFileHash(abs)` (reads head+tail only above 100 MB; no audio decoding), then `BookFilesWithHash(H)`.
   c. Provenance: resolve at run time with `prov, ok := database.AsCapability[database.FileProvenanceStore](p.store)` (`store_capability.go:90`). When `!ok`, skip rule (c) entirely and count `provenance_unavailable` once per run (and list it in the report); never fail the run for it. Otherwise `prov.FindFileEventsByHash(H)`, then `BookFilesAtPath(event.Path)` for each event path.
   d. Basename plus size under RootDir is a CANDIDATE source only: it feeds Step 5 verification and never writes on its own.
   Path equality alone is never sufficient to write.
5. **Verification.** A candidate row R is verified only when `H` equals `R.FileHash`, or equals `R.OriginalFileHash` with `R.OriginalFileHashKind == database.FileHashKindSampled`, or the earliest provenance event for R has `Digest.SHA256Chunk == H` and `Digest.SizeBytes` equal to the torrent file size. Anything else counts `unverified`.
6. **Outcome per torrent.** Collect verified rows across all audio files of the torrent. Partition by `book_file` ID: if two torrents resolve to the same row (cross-seeded copies), skip BOTH for that row and count `ambiguous` (no arbitrary winner). If R already has a non-empty `DelugeHash` equal to the torrent hash, count `already_linked`; if different, count `conflict` and write nothing.
7. **Write.** In live mode only: `ModifyBookFile(R.BookID, R.ID, fn)` where `fn` re-checks under the store's lock that `DelugeHash == ""` and `FilePath` is unchanged, returns `database.ErrSkipBookFileWrite` otherwise, and otherwise sets `DelugeHash = torrentHash` and nothing else. Never set `ImportedFromDelugeAt`, `DownloadHash` or `DelugeOriginalPath`. Decision on bulk-import candidacy: a linked row with a nil `ImportedFromDelugeAt` WILL enter `GetBookFilesNeedingDelugeImportCore` (feeding `/discovery/import`, `deluge.centralize` and `maintenance.bulk-deluge-import`, all manual). That is acceptable only because the file already lives in the library; pin it with a test (Tests, last item) and say so in the hand-back so the owner sees it. Preview counts what would be written and writes nothing.
8. **Concurrency (project rule).** Use `registry.RunItems` over torrents with options from a named function `linkRunOptions(workers int, total int, tally *linkTally) registry.RunItemsOptions` that sets `Concurrency: workers` (never omitted). The tally uses `atomic.Int64` counters; the `Label` closure reads them through atomics only (it runs inside worker goroutines). Workers partition by torrent; the write path is protected by the `ModifyBookFile` re-check plus the Step 6 ambiguity skip, so two workers cannot link one row. Add a comment saying so.
9. **D55.** Keep `internal/deluge/importer_adapter.go` (live caller at `:83`). `internal/plugins/deluge/import.go` is dead code kept "until 10 PR 2": delete it in this PR only if `grep -rn` shows no non-test reference after your change and its tests move or go with it; otherwise leave it and record why in the hand-back. Do not delete either silently.
10. **Report fields.** Final summary and result JSON: `torrents`, `files`, `linked` (or `would_link` in preview), `already_linked`, `unverified`, `ambiguous`, `conflict`, `non_audio`, `errors`, `provenance_unavailable`.

## Rollback
Revert the commit. Links already written are inert (`DelugeHash` on a row only informs later rules); to undo them, a follow-up op would blank `DelugeHash` where `ImportedFromDelugeAt` is nil, which this PR does not provide.

## Guardrails
- This op never deletes anything: no `book_file` row deletion, no torrent removal, no file removal, no repoint, no `MoveStorage`. `deluge_move_enabled` stays false (D57).
- It writes one field, `DelugeHash`, through `ModifyBookFile` with a re-check. Path match alone is never a reason to write.
- No server-side audio decoding; the head+tail hash from `filehash.BookFileHash` is the allowed read.
- Explicit `Concurrency` in the run options; atomics in the tally and in `Label`.
- No production calls; fixtures are synthetic; no real titles, hosts, IPs or library paths in code, tests or comments. the project's banned-word rule applies (see the charter, section 6).
- Never delete `book_file` rows; no iTunes writes; leave `internal/writeback/` alone.
