## Goal
Merge `scheduler.temp-file-cleanup` into `maintenance.temp-file-cleanup`, `scheduler.trash-cleanup` into `maintenance.trash-cleanup`, `scheduler.tombstone-cleanup` into `maintenance.tombstone-cleanup`, `scheduler.db-optimize` into `maintenance.db-optimize`. The `scheduler.*` def and its body are deleted, the task retargets to the survivor, the loser ID becomes a `FormerIDs` alias on the survivor, and the survivor now declares `Permissions: settings.manage` and the larger of the two timeouts, so the merge neither widens who can run a deleting op nor shortens a budget prod runs were sized against.

## Steps
1. Create the worktree. Verify the ids and files named in this brief against the tree (`grep -n 'ID: *"<id>"'` in the two files). If a line number differs by a few lines that is fine; if a def is missing or the bodies differ from the Files table, stop and report.
2. Confirm the four pairs have identical bodies: temp-file both call `sweep.CleanupOrphanedTempFiles`, trash both call `CleanupTrashedVersions`, tombstone both call `ResolveTombstoneChains`, db-optimize shares the helper named in the comment at the top of `internal/plugins/maintenance/db.go`. Before deleting anything, diff the two `Run` bodies side by side. Anything the loser does that the survivor does not (an activity flush, a progress call, a guard, a config read) is ported to the survivor in this PR and listed in the PR body. If they are identical apart from plumbing, say so.
3. On the survivor def: add `Permissions: []auth.Permission{auth.PermSettingsManage}` (import `internal/auth`), raise `Timeout` (and `ProgressTimeout` where the loser sets one and the survivor uses `LivenessNone`) to the larger of the two values listed in the Files table, and add `FormerIDs: []string{"<loser id>"}`. Keep the survivor's other fields. Do not change `ConcurrencyKey`: the survivor keeps its own, and the loser's key disappears with the loser. The survivors' Resume policy is `ResumeDrop` on both sides, so nothing to justify here.
4. Retarget the task: in `internal/scheduler/tasks.go` change the `EnqueueOp` ID and the error text to the survivor's ID, in `internal/scheduler/maintenance.go` change the `taskV2DefIDs` value. Send `struct{}{}`/`map[string]any{}` instead of `schedulerExtraOpParams{}` unless the survivor's Run decodes `legacy_op_id` (check its param struct; `json.Unmarshal` with unknown fields is fine, `DisallowUnknownFields` is not). The comment above each TriggerFn that says "EMPTY ON PURPOSE" stays.
5. Delete the loser: its `Register*Op` method in `extra_ops.go`, the `addOpRegistrar` block in `internal/server/scheduler_extra_ops.go`, and every helper only that body used (`go build ./...` and `staticcheck`/`go vet` tell you; the deadcode ratchet in CI fails on leftovers). 6. Add (or, if an earlier 04 PR already created it, append a row to) the table-driven test `internal/server/op_twin_merge_test.go`, package `server`.
