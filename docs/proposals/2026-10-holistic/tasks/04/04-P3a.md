## Goal
The scheduled `.bak-*` cleanup takes its retention from a dedicated `backup_retention_days` setting instead of `purge_soft_deleted_after_days`, and the PR records both prod values so nobody learns of an early deletion after the fact. Nothing about which files are matched changes.

## Steps
1. **Step 0, verify the premise (stop and report if it differs).** Run `grep -rn 'backup_retention_days\|BackupRetentionDays' internal web/src --include='*.go' --include='*.ts' --include='*.tsx'`. At the base commit the only hits are the `BackupRetentionDays()` method on `Server` (which returns `PurgeSoftDeletedAfterDays`), its interface declaration `internal/plugins/maintenance/deps.go:811` and its one caller `internal/plugins/maintenance/cleanup.go:370`. There is **no** `backup_retention_days` config key, so the drift described in census F4 ("the twin reads BackupRetentionDays") does not exist in code: both ops resolve retention from `purge_soft_deleted_after_days`. If your grep finds a real config key, skip to Step 2 and make the one-line change at `extra_ops.go:686`; otherwise do Steps 1 to 4 as written and say so at the top of the PR.
2. **Step 1, D5 pre-check (read-only, no code). Read both prod values from Settings before merging, and report them in the PR body**: the current `purge_soft_deleted_after_days`, and the value of `backup_retention_days` if the Settings page or `GET /api/v1/config` shows one (expect: absent). Use the Settings page in the browser or an authenticated `GET /config`; do not write anything and do not call any other prod endpoint. If you cannot reach prod, leave a `PRE-CHECK: pending owner` line in the PR body and do not mark the PR ready; the coordinator will ask the owner. State the effective retention in days that the nightly job uses today, and say which `.bak-*` files, by age bucket, a shorter value would delete on the first run after deploy.
3. Add the config key and helper as described in the Files table. The helper returns `BackupRetentionDays` when > 0, else `PurgeSoftDeletedAfterDays` when > 0, else 30. Keep `persistence.go` and the viper default in step (default `0`).
4. Switch `runCleanupOldBackups` (line 686) and `Server.BackupRetentionDays()` to the helper. Do not touch the walk, the `.bak-` predicate, `pathutil.ShouldSkipDir`, or the app-dir guard.
5. Add the Settings field, following `purgeSoftDeletedAfterDays` through api.ts, Settings.tsx, useSettingsHandlers.ts and sanitizeSettingsImport.ts.
6. Write the table test and the changelog fragment. Do not merge `scheduler.cleanup-old-backups` into its twin here: that is 04-P4f.
