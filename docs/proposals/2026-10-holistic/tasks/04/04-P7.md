## Goal
The every-boot `opchange-index-backfill` goroutine (backfill, verify, rebuild-if-dirty, then trust the index) becomes an op mode on `maintenance.opchange-book-index-rebuild`, enqueued at boot after warmup, so a multi-minute walk of the operation-change journal is visible and cancellable.

## Context the agent must read first
- `internal/server/server_lifecycle.go:1128-1176` (the goroutine and its long comment on why it runs EVERY boot: a rollback to an older build writes rows with no index entry and the sentinel cannot know).
- `internal/plugins/maintenance/opchange_book_index.go:50-140` (the op: **preview by default**, `dry_run=false` rebuilds; interface `opChangeIndexRebuilder`) and `internal/database/pebble_store_opchange_index.go` (`EnsureOpChangeByBookIndex`).
- `internal/operations/opmode` (`ResolveDryRun`): an omitted mode must stay a preview; the owner rule is that no new write mode may default to live.
- Everything 04-P6 added (the warmup dep, the boot-enqueue helper, the shutdown proof); build on it.

## Steps
1. Create the worktree. Verify the ids and files named in this brief against the tree (`grep -n 'ID: *"<id>"'` in the two files). If a line number differs by a few lines that is fine; if a def is missing or the bodies differ from the Files table, stop and report.
2. Read `EnsureOpChangeByBookIndex` and the goroutine's error handling (Canceled is Info, any other error is `Error` and reads stay on the full scan). Reproduce exactly that classification inside the op: an untrusted index must fail the op (visible red row), not complete quietly.
3. **Every boot, not once.** The goroutine's reason for existing is that the sentinel cannot detect a rollback; so the boot enqueue is unconditional and the op does the verify. If the verify is clean it must finish fast; record the "index already trusted" outcome with the no-op tag.
4. Concurrency with a manual run: the def's `ConcurrencyKey maintenance.opchange-book-index` already serializes; the store also has a "waiting for another opchange_by_book index pass" progress message (`opChangeIndexProgressTo`). Keep both; add a test that a boot-enqueued ensure and a manual rebuild do not run concurrently.
5. **Readiness gate.** Boot goroutines that touch the store wait for the memdb warmup first (`b.WaitForWarmup()` raced against `s.bgCtx.Done()`, `server_lifecycle.go:1072` and `:1153`; memory note: the warmup is asynchronous after a restart, roughly 130 s). An enqueued op starts as soon as a worker is free, so the wait must move INTO the op. Add `WaitForStoreWarmup(ctx context.Context) error` to the maintenance `ServerDeps` interface (`internal/plugins/maintenance/deps.go`), implemented in `internal/server/server_maintenance_deps.go` with the same capability lookup and `select` the goroutines use. If 07 R3/R4 (D44: readiness in `/health`, ops wait for warmup) are already merged, use their gate instead and delete this helper; say which in the PR body.
6. **Shutdown.** The goroutines were enrolled in `s.bgWG` so shutdown waited for them before `CloseStore` (comment at `server_lifecycle.go:966-970`: they must not hold Pebble iterators while the store closes). Ops run in the registry's pool instead. Prove that registry shutdown cancels the op's context and waits for the run to return before the store closes (read `Registry.Stop`/shutdown in `internal/operations/registry/`); if it does not, stop and report: that would be a regression this PR must not introduce. Add a test that cancels mid-run and asserts a prompt return.
7. Delete the goroutine. Do not delete `resolveOpChangeIndexBackfiller` unless the retargeted `indexed_store_capability_test.go` case still covers the indexedStore path. Keep `GetBookChanges` serving from the full scan until the index is trusted: that behaviour is in the store and must not change.
