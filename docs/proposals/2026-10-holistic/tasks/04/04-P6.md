## Goal
Six whole-library goroutines that run invisibly at every boot (no progress, no cancel) are replaced by enqueues of the registered ops that do the same work, so they show on the Operations page, can be cancelled, and wait for the store to be warm. The ops keep their present behaviour when an operator runs them; boot passes a new `if_needed` param to get the sentinel-gated behaviour the goroutines had.

## Steps
1. Create the worktree. Verify the ids and files named in this brief against the tree (`grep -n 'ID: *"<id>"'` in the two files). If a line number differs by a few lines that is fine; if a def is missing or the bodies differ from the Files table, stop and report.
2. **The census called these exact twins; they are not.** Each op today is the FORCE variant (`external-id-backfill`: "runs in full ... even after the boot-time pass has recorded completion"; `book-atpath-index-backfill`: "ignoring the one-time startup sentinel"; `activity-filter-index-backfill`: default path skips a gap the boot reconcile would fix). Only strip-movement, remux and transcode call literally the same function. So the conversion adds a boot mode to each op rather than just enqueueing it. Write that finding at the top of the PR body.
3. **Readiness gate.** Boot goroutines that touch the store wait for the memdb warmup first (`b.WaitForWarmup()` raced against `s.bgCtx.Done()`, `server_lifecycle.go:1072` and `:1153`; memory note: the warmup is asynchronous after a restart, roughly 130 s). An enqueued op starts as soon as a worker is free, so the wait must move INTO the op. Add `WaitForStoreWarmup(ctx context.Context) error` to the maintenance `ServerDeps` interface (`internal/plugins/maintenance/deps.go`), implemented in `internal/server/server_maintenance_deps.go` with the same capability lookup and `select` the goroutines use. If 07 R3/R4 (D44: readiness in `/health`, ops wait for warmup) are already merged, use their gate instead and delete this helper; say which in the PR body.
4. **Shutdown.** The goroutines were enrolled in `s.bgWG` so shutdown waited for them before `CloseStore` (comment at `server_lifecycle.go:966-970`: they must not hold Pebble iterators while the store closes). Ops run in the registry's pool instead. Prove that registry shutdown cancels the op's context and waits for the run to return before the store closes (read `Registry.Stop`/shutdown in `internal/operations/registry/`); if it does not, stop and report: that would be a regression this PR must not introduce. Add a test that cancels mid-run and asserts a prompt return.
5. Boot enqueues must not starve user-triggered ops: the defs already use `PriorityLow`; keep it. Mark the 'nothing to do' completion with the existing no-op activity tag so six instantly-completed rows per restart do not read as noise.
6. Implement the per-op params. Defaults must preserve what an operator gets today when the param is absent. Params are decoded with `json.Unmarshal` (empty body allowed, as `runActivityFilterIndexBackfill` does).
7. Boot enqueue: a single helper, each call `EnqueueOp(s.bgCtx, id, params)`; failures log and continue. Params: external-id `{"if_needed":true}`; book-atpath `{"if_needed":true}`; strip-movement `{}`; remux `{}`; transcode `{"quarantine_after":true}`; activity filter-index `{"reconcile":true}`. Because the activity store exists before the registry, enqueue the activity reconcile from `startBackfills` (the registry exists there) rather than from the activity service's PostInit.
8. Do NOT change permissions, ConcurrencyKeys, timeouts or resume policies of these defs, and do not touch `library.scan` or its key.
9. The transcode def is `ResumeAsk` (destructive; operator confirms). A boot-enqueued run that is interrupted by a restart must keep that behaviour: do not change the policy to make boot easier. State in the PR body what happens when the server restarts mid-transcode (the row surfaces for confirmation; the next boot's enqueue is deduped by the op's ConcurrencyKey while that row is live).
10. Write the tests; run `-race` on the two touched packages.
