## Goal
Merge `scheduler.purge-deleted` into `maintenance.purge-deleted`. The `scheduler.*` def and its body are deleted, the task retargets to the survivor, the loser ID becomes a `FormerIDs` alias on the survivor, and the survivor now declares `Permissions: settings.manage` and the larger of the two timeouts, so the merge neither widens who can run a deleting op nor shortens a budget prod runs were sized against.

## Steps
1. Create the worktree. Verify the ids and files named in this brief against the tree (`grep -n 'ID: *"<id>"'` in the two files). If a line number differs by a few lines that is fine; if a def is missing or the bodies differ from the Files table, stop and report.
2. Diff the two bodies (they are visible above): they are the same logic apart from three plumbing differences: the scheduler copy threads `ctx`, checks `r.Store == nil` and `r.Deps.AudiobookService == nil`; the server copy uses `context.Background()` and checks `s.Ops() == nil`. The correct merge keeps ONE body (the server's) and threads `ctx` into it, so the survivor's Timeout actually bounds the purge. Add the nil-service guard the scheduler copy had if the server copy lacks an equivalent (`s.audiobookService == nil`).
3. On the survivor def: add `Permissions: []auth.Permission{auth.PermSettingsManage}` (import `internal/auth`), raise `Timeout` (and `ProgressTimeout` where the loser sets one and the survivor uses `LivenessNone`) to the larger of the two values listed in the Files table, and add `FormerIDs: []string{"<loser id>"}`. Keep the survivor's other fields. Do not change `ConcurrencyKey`: the survivor keeps its own, and the loser's key disappears with the loser. Timeout is 2h (the scheduler's budget). The Resume policy is `ResumeDrop` on both sides.
4. **Preview default: do not invent one.** `maintenance.purge-deleted` and the loser are both class `no-mode` in `write_op_modes.golden`: they always run for real, and the existing safety valve is `PurgeSoftDeletedAfterDays <= 0` returning early. The census text for this row ("a test that the survivor deletes nothing on `{}` params") does not hold at HEAD; do not write that test. Instead assert the real behaviour (Tests). If you think a preview mode is needed, say so in the PR body for the owner; do not add it here (the golden file's header forbids adding new `no-mode` rows and forbids silently changing a class).
5. Retarget the task: in `internal/scheduler/tasks.go` change the `EnqueueOp` ID and the error text to the survivor's ID, in `internal/scheduler/maintenance.go` change the `taskV2DefIDs` value. Send `struct{}{}`/`map[string]any{}` instead of `schedulerExtraOpParams{}` unless the survivor's Run decodes `legacy_op_id` (check its param struct; `json.Unmarshal` with unknown fields is fine, `DisallowUnknownFields` is not). The comment above each TriggerFn that says "EMPTY ON PURPOSE" stays.
6. Delete the loser: its `Register*Op` method in `extra_ops.go`, the `addOpRegistrar` block in `internal/server/scheduler_extra_ops.go`, and every helper only that body used (`go build ./...` and `staticcheck`/`go vet` tell you; the deadcode ratchet in CI fails on leftovers). Port or delete the loser's tests as listed.
7. Add (or, if an earlier 04 PR already created it, append a row to) the table-driven test `internal/server/op_twin_merge_test.go`, package `server`. Row type: `{loser, survivor string; perms []auth.Permission; minTimeout time.Duration}`. Test `TestTwinMerge_AliasPermissionAndTimeout` boots with `bootRegisteredOpIDs(t)` (`internal/server/op_id_aliases_test.go`) and, per row, asserts: (a) `srv.opRegistry.Def(loser)` returns the survivor's def (ID == survivor); (b) `Def(survivor).Permissions` equals `perms`; (c) `Def(survivor).Timeout >= minTimeout`; (d) drives `handlers.NewOperationsV2Handler(nil, <registry>, nil, true).TriggerOperationV2` for both IDs with a caller holding only `auth.PermScanTrigger` (helpers `withCallerPerms`/`newOpsV2Ctx` are in `internal/server/handlers/operations_v2_permissions_test.go`; if they are not importable from package `server`, copy the 10-line helper into the new test file) and expects HTTP 403 with no `EnqueueOp` call. If the real registry does not satisfy the handler's registry interface, use `handlersmocks.NewMockOperationsRegistry` returning the survivor's real def from the booted registry.
