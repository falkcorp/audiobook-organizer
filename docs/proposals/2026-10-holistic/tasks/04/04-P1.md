## Goal
The two report-only health checks that declare a nightly cron but never run get real TaskScheduler tasks inside the maintenance window and carry `settings.manage`. A guard test then fails any op that declares `Schedule` with no driver, with an explicit allow-list of the 12 D24 ops that are intentionally off.

## Steps
1. Create the worktree. Verify both defs at HEAD: `grep -n 'ID: *"maintenance.file-integrity-check"\|ID: *"maintenance.orphan-book-files-cleanup"' internal/plugins/maintenance/*.go`. Confirm the orphan op is report-only: `delete:true` must error and no caller of `DeleteBookFilesByIDs` exists in `orphan_book_files*.go` (`grep -n DeleteBookFilesByIDs internal/plugins/maintenance/orphan_book_files*.go`). If that is false, stop and report.
2. Add `Permissions` to both defs.
3. Add the two tasks, `taskV2DefIDs` entries and `maintenanceOrder` entries. Mirror the existing tombstone task's TriggerFn but pass `map[string]any{}` (or `struct{}{}`) as params, because these defs take no `schedulerExtraOpParams`.
4. Write `internal/server/op_schedule_driver_test.go`: boot with `bootRegisteredOpIDs`-style setup, walk `srv.opRegistry.ActiveDefs()`, and fail on any def with `Schedule != nil` whose ID is not a value of `scheduler.TaskV2DefIDs()` (export a read-only accessor from `internal/scheduler/maintenance.go` if the map is unexported). The allow-list names exactly the 12 D24 IDs, each with a reason string: `deluge.protected-paths-sync`, `maintenance.author-dedup-scan`, `maintenance.author-split-scan`, `maintenance.batch-poller`, `maintenance.cleanup-old-backups`, `maintenance.db-optimize`, `maintenance.metadata-refresh`, `maintenance.purge-deleted`, `maintenance.series-prune`, `maintenance.temp-file-cleanup`, `maintenance.tombstone-cleanup`, `maintenance.trash-cleanup`. Add two more assertions so the list cannot rot: every allow-list entry still exists as a registered def (or alias) and still declares a Schedule, and no allow-list entry is now a `taskV2DefIDs` value (a driven op must leave the list). Later 04 PRs merge twins and retarget tasks; each removes its own allow-list rows in its own PR (the 04-P4x, 04-P5, 04-P12, 04-P14x briefs say so).
5. Run the tests, add the fragment.
