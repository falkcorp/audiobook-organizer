## Goal
The five whole-library `registry.RunItems` calls that run on one core (`RunItemsOptions.Concurrency` omitted, which clamps to 1) get an explicit, justified `Concurrency`, and an AST lint fails the build when a new call omits it without a stated reason.

- `internal/operations/registry/run_items.go` (`RunItemsOptions`: `Concurrency`, `CheckpointFn` (sequential only), `CheckpointStateFn` (concurrent, watermark), `ResumeFrom`, `Label` is called from worker goroutines).
- The five sites: `internal/plugins/acoustid/lsh_backfill.go:109` (options at 148), `internal/plugins/acoustid/reset_all.go:111` (146) and `:182` (194), `internal/plugins/deluge/centralization.go:104` (183), `internal/plugins/deluge/path_update.go:118` (141).

## Steps
1. Create the worktree. Verify the ids and files named in this brief against the tree (`grep -n 'ID: *"<id>"'` in the two files). If a line number differs by a few lines that is fine; if a def is missing or the bodies differ from the Files table, stop and report.
2. Re-run the census scan so the list is current rather than trusted: `go run` the scan from `runitems_scan.go.txt` (copy it to a scratch dir outside the repo and run it against the worktree root; do not add it to the repo). Expect exactly the five sites above. Any additional site: add it to this PR if it is a whole-library loop, otherwise mark it `// runitems:sequential <reason>`.
3. For each site read the `fn` closure and decide: (a) is every captured variable goroutine-safe (counters need atomics or a mutex; slices appended to need a lock); (b) do items touch disjoint rows (if two items can touch the same book, partition per CLAUDE.md or leave sequential with a reason); (c) what is the resume semantics.
4. **Resume semantics.** `CheckpointFn` runs only in sequential mode. Under concurrency use `CheckpointStateFn` (serialized, carries a watermark correct under out-of-order completion) and feed the stored watermark back through `ResumeFrom`. For `centralization.go`, `localCount` is already an `atomic.Int64` (line 102) and is fine. The real races are `checkpoint.ProcessedFiles = globalIdx+1`, `checkpoint.LastError` and `reporter.Checkpoint(checkpoint)` (lines ~129-178): `globalIdx` is dispatch order, not a completion watermark. Guard `checkpoint.LastError` with a mutex, drop the direct `reporter.Checkpoint` call, and use `CheckpointStateFn` plus `ResumeFrom` for the resume position. Apply the same check to `path_update.go`. Check every `Label` closure for the same race (it runs inside worker goroutines; `-race` only catches it if a test runs the op concurrently).
5. Set `Concurrency` as listed. For Deluge, honour the target's own rate limits: 4 workers, and keep any existing per-call delay.
6. Write the lint test. Make it fail first by running it before the fixes (it must name the five offenders), then pass.
7. Add a `-race` test per touched op that runs it with the fake store/clients already used in that package's tests with `Concurrency` > 1 (see `duration_backfill_*_test.go` for the pattern).
