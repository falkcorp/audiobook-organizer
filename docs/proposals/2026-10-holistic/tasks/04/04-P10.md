## Goal
The three post-import dedup checks (importer, organize/iTunes/manual create hook, metadata-apply) use one helper that enqueues the batchable `dedup.check-book` op, so bursts coalesce and the work is visible and cancellable. The existing flag becomes the escape hatch for the soak: default true, setting it false restores the old goroutines.

## Steps
1. Create the worktree. Verify the ids and files named in this brief against the tree (`grep -n 'ID: *"<id>"'` in the two files). If a line number differs by a few lines that is fine; if a def is missing or the bodies differ from the Files table, stop and report.
2. **Stop condition, check first.** `dedup.check-book` declares `Requires: book_sig_v1`. Read the registry's Requirement handling: what happens to a book that never gets a signature (no audio, fingerprinting disabled, un-fingerprintable)? If such a book's check is deferred forever, the Layer 1 exact-hash check that import relied on is lost for it. If so, DO NOT flip the default: implement the helper and the call-site changes with the default left at false, say so at the top of the PR body with the evidence (file:line), and let the coordinator ask the owner.
3. Write the helper and route the three sites through it when the flag is true and a registry is available; otherwise keep the existing goroutine. Keep the `bgWG`/`bgCtx` ownership for the fallback path exactly as it is (shutdown must still drain it before the store closes).
4. Flip the default only if the stop condition cleared. Do not delete the flag or the goroutine paths: that is the follow-up after the soak.
5. Tests, fragment.
