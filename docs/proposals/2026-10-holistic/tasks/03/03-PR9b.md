## Steps
1. Confirm the precondition (04 P14c merged; name the surviving reconcile op and its saved-result keys) and write that into your report's first line.
2. Write the fixer Evaluate-style (same rules as 9a): one pure read-only `evaluate(ctx, reader, candidate) (repairs.Row, error)` used by Plan and Replan alike; decision inputs carried in the row fingerprint and `Detail`; Apply only writes. Candidate set = (a) matches from the latest saved scan, (b) books with missing files that have no candidate file.
3. Rows: a match row shows book -> file, match type and confidence, and is applicable only if the file is still untracked and still on disk and the book is still missing it (re-checked in `evaluate`, so Replan catches drift). A "no candidate file" book is a skipped row with the reason `no candidate file`, so the count stays clickable.
4. iTunes rule: any row whose book or file is an iTunes-managed path is skipped with the reason `iTunes`; never write iTunes data (use the predicate from `duplicate_copies_fixer.go:41-45`).
5. Apply: runs `reconcile.apply` with the PICKED rows only (never the whole scan), through the op registry the way other fixers start ops. Never delete a `book_file` row; reconcile repoints. If `reconcile.apply` currently deletes or recreates rows, STOP and report instead of wrapping it.
6. Rewrite the one description string in `ReviewWorkspace.tsx` (this is the only frontend source edit; this PR is the last in the `ReviewWorkspace.tsx` order before PR 10 for it, so rebase carefully).
7. Tests (failing first), register the fixer, update the `RepairsPanel` fixture, changelog fragment.
