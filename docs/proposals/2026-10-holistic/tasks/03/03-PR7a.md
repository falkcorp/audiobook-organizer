## Goal
Review gains a fifth lane labelled **Authors & series** with a segmented control whose first sub-view is **Authors**: duplicate-author groups with inline canonical name, suggested-name chip, Author/Narrator toggle per variant, remove-from-merge, books popover, Validate, Find real author, Split, and Merge / Merge selected / Merge all. It also lists `entity_type: 'author'` embedding candidates, which the Duplicates lane hides. No new server routes.

**Parity-matrix rows closed** (ids from section 3.1 of the spec): C14, C15, C16, C17, C18, C19, C22, C54, plus the partial rows C20 and C21 (the verbs exist on `pages/Authors.tsx` without the duplicate-group context; this PR adds the context)

## Steps
1. Baseline: `cd web && npx vitest run src/components/review src/components/dedup/__tests__/DedupAuthorTab.test.tsx src/components/dedup/__tests__/dedupTabs.selectAll.test.tsx`; list the case names you must port. Read the E2E blocks and note their selectors.
2. Widen `ReviewLane` to `'dupes' | 'metadata' | 'regroup' | 'repairs' | 'authors'`. Let the compiler list every place that must change (`LANES`, `LANE_ORDER`, any `switch` or Record over `ReviewLane`). Place `authors` before `repairs` in `LANE_ORDER` (its doc comment says Repairs stays last): the final order is `['dupes','metadata','regroup','authors','repairs']`.
3. Write `lanes/authors.ts` with `label: 'Authors & series'`. Every verb in the descriptor is mandatory (total map); the action types carry `entity: 'author' | 'series'` so a series id can never reach `mergeAuthors` (this PR only uses `'author'`; 7b uses `'series'`).
4. Write `useAuthorsLane`: fetch `getAuthorDuplicates()` only while the lane is active; keep the refresh command (`refreshAuthorDuplicates()`); a second rail section **Author candidates** lists `getDedupCandidates({entity_type:'author'})` (closes F5/C54). Four states and an `AbortController` on every fetch. The author list has no pagination on the server: measure the response size on the sandbox and report it (spec section 5 risk) before declaring done.
5. Write `AuthorGroupSpine` / `AuthorsPanel`: carry behaviour over verbatim from `DedupAuthorTab.tsx:395-547`. Per group: canonical name with an **Edit canonical name** pencil and a `Use suggested: "…"` chip; each variant row has an Author/Narrator toggle (reclassifies before merge) and a remove-from-merge button (tooltip `Remove "<name>" from this merge`); a clickable book-count chip that opens a popover of that author's books (`getBooksByAuthor`); a **Validate** button (`POST /dedup/validate`); a **Production Company** chip with **Find Real Author** when the group is a production company; **Split into N authors** when the name is a composite. Buttons per group and in the lane toolbar: **Merge**, **Merge Selected (N)**, **Merge All (N)**; Merge All opens a dialog titled **Confirm Merge All** with Cancel / Confirm.
6. Keyboard: `j`/`k` move, `m` merge the focused group, `Enter` expand, `Esc` close, `?` help; handlers are registered only while the lane is active (copy the guard from `useDupesLane.ts:1054-1140`).
7. Wire the lane into `ReviewWorkspace.tsx`: render `<AuthorsPanel>` when `lane === 'authors'`; the hook receives `active = lane === 'authors'`. The lane is reachable by `?lane=authors`; do not write the lane back to the URL.
8. Port the tests and the E2E blocks (Appendix B.1 and B.2 rows marked 7a). Selectors change from tab-based to lane-based; assertions about progress now assert the toast and the notification-bell entry (`startJob`), because the page-local poll is gone. Keep the four-state error assertions from "Dedup Error Handling".
9. Do not delete or edit anything under `web/src/components/dedup/` or `web/tests/e2e/dedup*.spec.ts` in this PR except to leave the old blocks in place (they are deleted in PR 11). Do not touch `pages/Authors.tsx`.
