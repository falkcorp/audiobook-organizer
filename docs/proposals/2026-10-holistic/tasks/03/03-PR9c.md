## Steps
1. Baseline build/vet/tests for `internal/dedup`, `internal/plugins/dedup`, `internal/plugins/maintenance`, `internal/server/handlers`.
2. Write the fixer Evaluate-style: one pure read-only `evaluate(ctx, reader, candidate) (repairs.Row, error)`; Plan lists the candidates `ListSplitBookCandidates` produces (call the detector, not the HTTP handler), Replan re-evaluates one cluster with the SAME function; the decision inputs (member book ids, suggested keep, folder) go into the row fingerprint and `Detail`.
3. Each cluster is a row whose members (`RowMember`) are its books with Role `keep` or `fragment`; the suggested keep is shown. A cluster containing any iTunes-managed book is a skipped row with the reason `iTunes` (same predicate as `duplicate_copies_fixer.go:41-45`).
4. Apply: merge one cluster through the path you chose; never delete a `book_file` row (the merge repoints); apply must return `ErrChangedSincePlan` if membership changed.
5. Do NOT remove or change the routes, the CLI or the existing split-book ops. Do NOT change `fragment_consolidation_fixer.go`.
6. Add a measurement helper for D21 that is test-only or a documented query, not a new runtime feature: a test that, for a fixture of N split clusters, reports how many would also appear as fragment-fixer "no parent" rows. In the PR description tell the owner exactly how to run both trials on prod and compare (Repairs lane, trial each fixer, compare the book id sets).
7. Tests (failing first), register, fixture update, changelog fragment.
