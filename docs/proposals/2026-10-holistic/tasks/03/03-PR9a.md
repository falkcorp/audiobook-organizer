## Goal
A new Repairs fixer replaces the old Series tab's "Prune Series" preview-and-confirm. It has TWO row kinds, matching what the existing prune does: (1) duplicate-series group: several series with the same normalised name and author; applying MERGES them, repointing their books to the canonical series and then deleting the emptied series; (2) orphan series: a series with no books; applying deletes the series row. Books ARE changed by kind (1) (their series link moves), and never by kind (2). It is written so the ops v3 port (05 wave 12D) is mechanical: one pure read-only `evaluate` drives both Plan and Replan.

**Parity-matrix rows closed** (ids from section 3.1 of the spec): C34 (the prune preview, confirm and prune)

- WHAT THE PRUNE REALLY DOES (read both in full before designing rows):
   - Preview: `internal/server/server_title_helpers.go:16` `computeSeriesPrunePreview(store seriesPruneReader)` returns `Groups` of `Type` `"duplicate"` (canonical id, merge ids, book count) and `Type` `"orphan"` (a series with 0 books, via `GetBooksBySeriesIDCore`). It groups by `strings.ToLower(strings.TrimSpace(name))` + author id, and does NOT skip held series.
   - Execute: `internal/server/duplicates_helpers.go:142` `func (s *Server) executeSeriesPrune(ctx, store seriesPruneStore, progress, operationID)` is a Server METHOD over the whole library. Phase 1 merges duplicate groups (grouping by `util.NormalizeString(name)` + author id, SKIPPING held rows via `database.SeriesHeld`), repoints each book with `store.ModifyBook` (SeriesID only), guards deletion by an unfiltered reference count (`database.SeriesMembershipAllVersions`; fail-closed, see the long comment and `internal/database/series_bookref.go`), then `store.DeleteSeries`; phase 2 deletes orphans behind a second reference-count guard; it records `store.CreateOperationChange` rows and calls `s.InvalidateSeriesCache()` when anything changed. The store contract is `seriesPruneStore` (`duplicates_helpers.go:54`): `GetAllSeries`, `GetBooksBySeriesIDCore`, `DeleteSeries`, `GetBookByID`, `ModifyBook`, `CreateOperationChange`. The preview and execute grouping rules DIFFER (normalisation, held rows): the fixer must use the EXECUTE rules, because that is what writes.
   - A per-row apply therefore cannot call `executeSeriesPrune` (whole library, Server method). Extract the per-group merge and per-orphan delete cores into a shared package (below) and have both `executeSeriesPrune` and the fixer call them.
- `internal/server/handlers/duplicates/handler.go:736-760` (`SeriesPrunePreview` HTTP wrapper), `internal/dedup/op_params.go:53` (`SeriesPruneParams`), `internal/server/duplicates_ops.go:21` (the `dedup.series-prune` op), `internal/scheduler/tasks.go:600` and `maintenance.go:167` (the scheduled `series_prune` task that keeps calling the op: it must keep working unchanged).

## Steps
1. Baseline: `go build ./... && go vet ./internal/dedup/... ./internal/plugins/maintenance/... ./internal/server/...` and the package tests; record pass counts. Use gopls `findReferences` on `executeSeriesPrune`, `computeSeriesPrunePreview`, `seriesPruneStore` before moving anything. 2. Extract the cores into `internal/dedup/series_prune_core.go` (a pure move of the logic, not a rewrite). `executeSeriesPrune` becomes a loop over the cores plus its existing progress, counters, `CreateOperationChange` and cache invalidation. Prove no behaviour change: run the existing prune tests unchanged (`grep -rn executeSeriesPrune internal --include=*_test.go`) and add a before/after golden for a fixture library.
3. Write the fixer Evaluate-style so 05 12D is mechanical: (a) one pure read-only `evaluate(ctx, reader, candidate) (repairs.Row, error)` deciding ONE candidate (a group or an orphan) with no Writer; (b) `Plan` lists candidates with `PlanSeriesPrune` and calls `evaluate` on each, returning all rows, applicable and skipped, uncapped; (c) `Replan` reloads that one candidate and calls the SAME `evaluate`; (d) every decision input (canonical id, merge ids, book counts per series, reference counts, held flag) goes in the row fingerprint fields and `Detail`, never recomputed in Apply; (e) `Apply(ctx, w, fresh)` only performs the write, through the extracted cores, and returns `ErrChangedSincePlan` if the fresh row no longer matches. No package state; inject a clock if one is needed.
4. Row kinds and labels. Duplicate row: title `Merge N duplicate series into "<name>"`, members = the canonical series (Role `canonical`) and the series to merge away (Role `merge`), with book counts; applying repoints their books and deletes the emptied series. Orphan row: title `Delete empty series "<name>"`, applying deletes the series row only. A held series (`database.SeriesHeld`) is never a merge-away member and an orphan row is skipped with the reason `held for undo` if it is held. If the reference-count guard shows any book (including trashed rows or non-primary versions) still points at a series, the row is skipped with the reason `still referenced`; it is never applicable.
5. Description text for the lane: "Series records that are duplicates of each other, and series that no book belongs to. Applying a duplicate row moves its books to the kept series and removes the empty copies; applying an empty-series row removes the empty series. Each change is recorded and can be undone from the apply operation." Verify the last sentence is true by checking that the extracted cores record `CreateOperationChange` rows (the same ones the op writes); if the fixer path cannot record them, delete the sentence.
6. Apply must invalidate the cached series list exactly as the op does (see Context); the mechanism you find goes in the report.
7. Do not change the scheduled task `series_prune`, the op `dedup.series-prune` or the HTTP preview/execute routes (their fate is 04's and 01's).
8. Tests (below), watch them fail on a stub, then pass. Header bumps; `changelog.d/<date>_repairs_series_prune_fixer.md`.
