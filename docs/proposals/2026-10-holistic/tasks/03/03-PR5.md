## Steps
1. Baseline `cd web && npx vitest run src/pages/__tests__/DedupLabels.test.tsx`; note the 5 case names.
2. Create `useDupesLabels.ts`: move the fetch/override logic from `DedupLabels.tsx`; type the label rows with `Score` and `ScoreBreakdown` (fixing audit D11); every fetch has an `AbortController` and the four states (loading, error, empty, populated). Do not use `apiFetch` inline in the view.
3. Create `DupesLabelsView.tsx`: a stats strip whose counts are clickable and set the matching filter; a server-paged `ConfigurableTable` filtered by label, source and band with configurable columns; a one-click human override using `LabelToggle`; render the breakdown with the existing `EvidencePanel` / `dedupEvidence` adapter.
4. Suspicious view: move `SuspiciousQueue` (`DedupLabels.tsx:161-266`) unchanged except for the import path; keep the "why suspicious" reasons and the override.
5. `DupesPanel.tsx`: add the segmented control with exactly the three labels **Queue**, **Labels**, **Suspicious**. It is a sub-view, not a `SpineViewMode`; the three-position view-mode toggle remains on Queue. Local React state, seeded once from `?view=`; never written back to the URL (writing it back double-fetches; this defect shipped before).
6. `ReviewWorkspace.tsx`: pass the seeded `view` down; change the "Manage labels" command (`:378-389`) so `run` sets lane `dupes` and sub-view Labels. Its description: "Opens your past \"duplicate / not a duplicate\" decisions, which are used to check and tune the scoring." (unchanged text).
7. Port the 5 `DedupLabels.test.tsx` cases into the two new test files, covering all 4 states and override; watch them fail against a stub first. Leave `pages/DedupLabels.tsx` and its test in place (deleted in PR 11).
