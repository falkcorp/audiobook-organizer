## Steps
1. Baseline vitest for `src/components/review` and the three source test files listed in Context.
2. Lift `buildClusters` into `lanes/dupesClusters.ts` as a pure function with a typed input (the loaded candidates) and output (clusters with member book ids, pair ids and the pairs' ordering). Unit-test it before wiring any UI.
3. `viewModeLabel` in `ReviewWorkspace.tsx`: for lane `dupes`, mode `candidates` returns **Clusters** (compact stays "Compact rows", two-column stays "Two columns"). Do not add a fourth toggle position.
4. `DupesClusterSpine.tsx`: cards grouped from the loaded page. Each card lists members with cover, path, folder-files chip and quality chip, and a radio to choose the primary; actions on the card: **Link cluster**, **Reject cluster**, and a per-member **Remove from cluster**. Because clusters are built from one server page, a card whose books also appear in pairs on other pages shows the line "N more pairs for these books are on other pages" (N from a `total`-aware `entity_id` count). Do not build a server clustering endpoint.
5. Actions: `linkCluster {ids, primaryId}` -> `api.linkDedupCluster`; `rejectCluster {ids}` -> `api.rejectDedupCluster`; `removeFromCluster {ids}` -> `api.removeFromDedupCluster`. Keep the irreversible-link guard: confirm dialog on link-cluster, `expected_total`/`FILTER_CHANGED` untouched on filter-scoped verbs, selected-row verbs sequential via `runSequential`. Preserve the old tab's behaviour that a partial failure is reported after the refetch (ported test).
6. By series: a **By series** toggle in the Clusters view lists the series-summary rows; each row has **Link all pending pairs in this series**, behind a confirm dialog that shows the count, calling `link-series`.
7. Port the tests (failing first). Selection across pages on the cluster spine must keep the contract the Version Groups tests asserted.
