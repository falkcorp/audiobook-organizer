## Goal
Bulk identification never reads the harvested Audible author catalog, so every book whose author is harvested still costs provider calls. After this PR the candidate search first looks a book up locally with zero provider calls: B1 by identifier (`cat_pid:`), B2 by an exact folded-credit block (or a `cat_author:alias:` hit) for EACH credit in order, producing candidates tagged with their stage of origin and marked review-only. The same PR adds the folder-parse variant for books whose stored title is a person's name or equals the author.

## Steps
1. Create the worktree. Confirm 02-PR7a, 02-PR6 and 02-PR4 are on `origin/main`.
2. B1: if the book has an ASIN, `GetEntryByProviderID(provider, marketplace, asin)` (a point read). A hit yields exactly one candidate, tagged `B1`. Use the configured catalog provider and marketplace the harvest op uses (`config.AppConfig.Catalog`).
3. B2: for EACH credit in the book's ORDERED live credit list (`database.LiveBookAuthorNames`, never the flat string), fold it (`authorjunk.FoldKey` / `catalog.AuthorNameKey`) and resolve the block by the EXACT key, or via `cat_author:alias:<fold>` when the exact key is empty. Never call `EntryIDsByAuthorName` from the bulk path. A block with more than 2,000 entries is skipped and counted (`oversize_block`), not scanned.
4. Within a block score titles with trigram Jaccard on folded titles, then a bounded Levenshtein on the top few (cap the edit distance at 3 for titles under 30 runes, 6 above), against EVERY title the question carries (stored title, parsed title, folder-parse title). Skip entries with `StaleSince != nil`. Keep at most 5 candidates per book. Convert with `catalog.EntryMetadata`. Tag the candidate with stage `B2` and the credit position it came from.
5. Homonym safety, at match time and with no network: for a credit's block, read each entry's matching `Authors[].ProviderAuthorID`. If the block holds more than one distinct ProviderAuthorID for that folded name (homonyms) and the book's author row has no author ASIN to choose with, produce no candidate and count `homonym_skipped`; if the book's author has an ASIN, restrict the block to entries carrying it. Entries with `ManualOnly` set stay candidates but are tagged manual-only so the apply gate treats them as it treats any manual-only record.
6. Aliases: write `cat_author:alias:<fold>` from the harvest's own name variants (initialled, reordered, with and without middle names) and from the authority list (`internal/authority`), in the same write path that creates the block. Provide a one-shot backfill function `BackfillAuthorAliases(ctx)` called at the end of a harvest run, not a new op.
7. Review-only: candidates carry `Source = catalog.SourceName` (a new constant, e.g. `"Audible Catalog (local)"`); add it to `IsReviewOnlyCandidateSource`, so `applygate.ReviewOnlySource` refuses it in every bulk path and only an owner review pin applies it. Add a regression test that a catalog candidate with a perfect score is refused by `applygate.Evaluate` with reason `review_only_source`.
8. Wire into `searchMetadataForBook` before `runSearchFanout`, behind `metadata_fetch.catalog_stage`. Catalog candidates are added to the pool the scorer ranks; they are NOT a substitute for the provider fan-out in this PR (D31: review-only candidates first). With the flag off, behaviour and call counts are exactly today's.
9. Folder-parse variant (rides in this PR; the spec gives it no PR of its own). Today `ResolveCandidateSearchQueryMemo` produces a folder stand-in only when the stored title is unsearchable. Add: when the stored title is a known person (`j.knownPerson`) or folds equal to one of the book's live authors, ALSO produce the folder title (`j.folderTitle`) as the question (`Source: SearchQuerySourceFolderTitle`) when the folder name is itself not a person. This is a new question, so it gets a new cache key (02-PR6) and bypasses any negative entry with no bust. Add tests for: title equals author with a folder `Author/Real Title/file`; title is a different person's name; a folder that is itself a person (no stand-in); a part-row (still refused, as today).
10. Counters: add `catalog_candidates`, `provider_candidates` and `oversize_block` to the candidate-fetch op's tally and its final summary line, so the owner sees how many candidates cost zero provider calls.
11. Measure: on a synthetic library of 5,000 unidentified books against a catalog of 800 author blocks (about 100 titles each), count provider calls with a counting fake provider with the stage on and off.
