## Goal
Identification has no orchestrator: a 6-hour timer re-reads the whole library to find work. After this PR a low-priority op `identification.advance` drains a durable dirty set (`ident:dirty:<bookID>`, from PR 4) and runs each marked book through the existing question, candidate-search, scoring and decision pipeline once; writers mark books dirty (a scan that changes identity fields, a new primary book, an applied merge, a retitle, a fetched catalog harvest for the book's author); the 6-hour `candidate_fetch` tick becomes the safety net. The op is written in the v3 shape from day one so the later port is an adapter swap and `advance.go` does not change.

## Steps
1. Create the worktree. Confirm 02-PR4 and 02-PR6 are on `origin/main`; read 04's scheduler PRs' merged state (`internal/scheduler/tasks.go` merge order: 04 P1, P4a, P9, P12 first).
2. DESIGN RULE (the point of this brief): the body must be what the v3 SDK's `Batch` takes, so the port is an adapter swap. `internal/identification/advance.go` holds ONLY: the `Source` (Pages), the `Item` function and the `Finish` function, with `PartitionBy = bookID` and a `Concurrency` value that names its derivation. It contains no loop, no worker pool, no chunking, no progress or checkpoint code, no import of `internal/operations/registry`. All of that belongs to the runner (v2 `RunItems` now, v3 chunk-leasing runner later, D28a). Add a package test that fails if `internal/identification` imports the operations registry (parse its imports).
3. Source: `Pages(ctx, after, limit)` over `IdentDirtyPage`, page size the constant `PageSize = 256` (D28a's chunk; the same constant the v3 `DirtySet` uses so a leased chunk is one page). `Key = bookID`; `Order = Unordered` because a re-mark can land below the cursor. No slice of all marks is ever materialized: a page is read, processed, then the next.
4. Item: for one `Mark`, in order: (1) re-derive, never trust the mark: load the book; if it is gone, not primary, quarantined, or `ident` is `applied` or `held`, just compare-and-delete the mark and return; (2) build the question and run the existing per-book pipeline through `FetchOne` (which already walks cache, catalog stage if enabled, providers, scoring, and writes the candidate row; with 02-PR6 a repeat of an unchanged question costs 0 provider calls); (3) re-derive the state, record `ident_reason` and the question fingerprint via `SetIdentReason` for the reasons the derivation cannot see (`no_usable_title`, `fragment` for a sibling-part skip, `manual_only`, `quota_deferred` for a Google-capped or throttled book); (4) clear the mark with `ClearIdentDirty(bookID, epoch)` using the epoch READ AT THE START: if a writer re-marked the book while it ran, the mark survives and the book is processed again. Idempotent: running Item twice for the same state is harmless. Return an `Outcome` the Finish counters use (`skipped_done`, `fetched`, `deferred`, `error`).
5. Concurrency: the Item is network-bound. `Concurrency` = `candidateFetchWorkers(metafetch.EnabledSourcesBudget(), config.AppConfig.MetadataCandidateFetchWorkers)`, the same derivation as `metadata_candidate_op.go`, named in a comment as "sum of enabled provider budgets" (the v3 `Network(n, ...)` form). Mutual exclusion with a concurrent candidate-fetch of the same book uses the existing `s.candidateFetchClaims.claim`.
6. Partition: `PartitionBy(m) = m.BookID`. Within one page keys are unique, so no two workers can hold the same book; across pages processing is sequential. State this in a comment (the repo's rule for loops whose correctness depends on exclusive access).
7. v2 adapter in `internal/server/identification_advance_op.go` (NOT in a plugin package: the per-book function is a `*Server` method, and `internal/server` blank-imports `internal/plugins`, so a plugin cannot import it; this deviates from the spec's `internal/plugins/identification/` and must be said in the PR description). Register with `addOpRegistrar`: `Liveness: LivenessRunItems`, `DefaultPriority: PriorityLow`, `ResumePolicy: ResumeRestart` (the dirty set IS the resume state), `ConcurrencyKey: "identification.advance"`, `Writes` declared for books, the candidate cache and the ident keys, `Permissions: settings.manage`, a `DependsOn` list of `metadata.candidate-fetch`, `metafetch.asin-backfill`, `catalog.harvest-authors` (they share Audible's budget), and add `identification.advance` to those three ops' own `DependsOn` (the dependency is one-directional; see the comment in `catalog_harvest_op.go`). The adapter loops: `Pages` -> `opsregistry.RunItems(ctx, reporter, page, fn, RunItemsOptions{Concurrency: n, ErrMode: ErrModeCollect, Label: <reads only the item>})` -> next page, until a page is empty, then `Finish`. `Label` and every counter shared across workers use atomics or one mutex. The adapter owns nothing else: no chunk leasing, no ledger, no status of its own (status while on v2 is items done and the current book id per worker from `RunItems`, which is enough until the port).
8. Writers mark dirty (nil-safe, never failing the writer): scanner `applyScannerFields` when `Title` or the author link of an existing primary book changed, and on creation of a new primary book; `MergeBooksWithOptions` on success; the 02-PR5b retitle stamp; the catalog harvest on a completed author with new or changed entries. Do NOT mark dirty on a candidate-cache write (the driver itself writes the cache; marking there would make it loop forever) and do not mark on a book read.
9. Scheduler: with `identification_advance_enabled` false (default) nothing changes. With it true, the `candidate_fetch` tick marks the books its whole-library selection finds dirty and logs `safety_net_marked=N` (this number should trend to 0 once writers mark correctly: it is the metric for gaps in the marking), and a 5-minute `identification_advance` tick enqueues the op if `IdentDirtyPage("", 1)` is non-empty and no run is active.
10. `StageStatus` (separable, see Files): add the type and fields only, readers untouched. This is the "touches every writer" item from the architecture doc; convert writers in a follow-up.
11. Run `go test -race` on the new packages; the dirty-set restart test is the proof that no work is lost or repeated beyond in-flight items.

## Rollback
Disable the op (`identification_advance_enabled=false`; the 6-hour `candidate_fetch` tick then runs exactly as before) and, if needed, revert the PR. Dirty marks left behind are inert keys under the registered `ident:` families. Writers' `MarkIdentDirty` calls are nil-safe and cannot fail a scan or merge.
