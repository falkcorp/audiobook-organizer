# 02-PR2: Remove per-row waste in the compiled filter path (duration re-parse, by-value Book copies)

## Goal
`durationMatches` re-parses the duration expression for every row although `compileFieldFilter` already validated it and discarded the result, and `matchesCompiledFilters` / `hydrateAuthorSeriesNames` move a 904-byte `database.Book` by value on every row. After this PR the duration expression is parsed once per request, and the per-row path passes the book by pointer, with no change in which rows match.

## Steps
1. Create the worktree. Run the PR 1 benchmarks and keep the output as "before" (if PR 1 has not merged, stop and report; this brief depends on it).
2. Duration: in `compileFieldFilter`'s duration case, keep the existing validation error text exactly, but store the parsed `durationExpr` on the returned `compiledFilter`. Add `durationMatchesExpr` and make `fieldMatchesCompiled` use the stored value. A filter that failed to compile never reaches the matcher (the compile returns an error first), so the old `err != nil -> return false` branch in `durationMatches` stays only inside the wrapper.
3. Pointer receivers: change `matchesCompiledFilters(book database.Book, ...)` to take `*database.Book` and update every caller (`grep -rn 'matchesCompiledFilters(' internal`). The function must not mutate the book; add a one-line comment saying so, because callers may pass a pointer into memdb-resident data.
4. `hydrateAuthorSeriesNames`: today it copies a book in and out. Change it to `hydrateAuthorSeriesNames(dst *database.Book, src *database.Book, authorNames, seriesNames map[int]string)`. Its caller `matchesFieldFiltersWithStrippedFallback` (service_filtering.go:314) gets a new scratch-`*database.Book` parameter; update both callers (service_filtering.go:1062 and service_query.go:674) and have the per-request closure each builds own the scratch (one per goroutine, never shared). The caller owns one scratch `database.Book` per goroutine, assigns `*dst = *src` once (a stack copy, no heap), then sets `dst.Author` / `dst.Series` when missing. NEVER write through `src`: it can point into the memdb-resident row, and mutating it would corrupt shared data (add a test for this, see Tests). The existing behaviour (leave an already-set Author or Series untouched; no-op with nil maps) must be identical.
5. Do not touch the per-user `GetUserBookState` call or the stripped-field `GetBookByID` fallback; they are separate findings (F5c, F6) with no PR in this wave.
6. Re-run the PR 1 benchmarks and compare. Record before/after ns/op, B/op, allocs/op for each sub-benchmark.
