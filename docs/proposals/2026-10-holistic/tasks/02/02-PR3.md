## Steps
1. Create the worktree. Read both existing test files fully; the Go tables are the corpus seed.
2. Create `conformance.json`. Move all 25 match cases and 8 error cases from `querygrammar_test.go` into it with identical names, patterns, `quoted` and expectations. The existing inputs contain real published book titles (the public-repo rule applies to new files): replace each such input with a synthetic string of the same shape (for example `The Alpha Beta`, `Gamma Saga`, `Delta`), keeping each case's expected result; the shape of the input, not the title, is what the case tests. Match cases set `want_match`; error cases set `want_error: true` and `go_error_contains` (the substring the Go test asserts today, for example `no closing /`, `invalid regex`, `no lookahead`).
3. Add `ts_error_matches` (a regex source string) for each error case from what the TypeScript pre-check says: run each error pattern through `regexValueError` or `compileValue` in vitest, copy its message, and store a regex-escaped fragment of it. Known divergence: Go reports a backreference as `invalid regex` while TypeScript reports `backreferences`; the corpus records each engine's own wording and the suites assert only that BOTH engines reject the pattern plus their own substring. Never loosen one engine's check to match the other.
4. Add new cases that exercise the translation seams, at least 20: `\p{L}` and `\p{Lu}` classes, `(?i)` and `(?-i)` flags, `\d` with non-ASCII digits, an anchored `^\s*\d` (the number-leading shape), escaped slash `a\/b`, a literal `*` in a quoted value, a pattern with a space, `(?s)` dot-all, Unicode case folding (`ß` against `SS`, `İ`), an empty input against `*`, a very long input (10,000 characters), and `\b` word boundaries. Build the expectations from the Go engine's real output (run it, do not guess), then run the TypeScript engine. Where the two engines genuinely differ, DO NOT change an expectation to hide it: record the case with `engines: ["go"]`, a `skip_reason` naming the difference, and list it in the PR description as a known divergence for the owner.
5. In `querygrammar_test.go` add `TestConformanceCorpus`: `os.ReadFile("testdata/conformance.json")`, `json.Unmarshal`, `t.Run(name)` per case; for match cases `CompileText` then `Match`; for error cases assert the error contains `go_error_contains`. Cases whose `engines` excludes `go` are skipped with `t.Skip(skip_reason)`. Delete the two inline tables only after the corpus run shows the same 33 cases passing.
6. In `queryGrammar.test.ts` add the corpus describe block. Resolve the path with `path.resolve(__dirname, '../../../internal/querygrammar/testdata/conformance.json')` and `fs.readFileSync` (the `node` types are enabled). If `tsc` objects to `__dirname` under ESM (`"type": "module"`), use `fileURLToPath(new URL('../../../internal/querygrammar/testdata/conformance.json', import.meta.url))` instead. Do not copy the JSON into `web/`: one file is the whole point.
7. Run both suites. Report the case count per engine and the number of skipped cases with their reasons.
