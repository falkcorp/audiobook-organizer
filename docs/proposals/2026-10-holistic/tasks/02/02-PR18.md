## Goal
With the new boolean setting `review_metadata_server_query` ON, the Metadata lane stops loading every reviewable row. It sends one server query per settled filter (150 ms debounce, abortable), holds only the visible page plus the facet counts, and "Select all N matching" fetches ids only. With the flag OFF (the default) the lane behaves exactly as today.

## Steps
1. Create the worktree. Confirm 02-PR17 is merged (`grep -n 'view=page\|evaluateReviewQuery' internal/server/handlers/metadata_cache.go internal/server/handlers/metadata_cache_query.go`). If not, stop.
2. Add the setting end to end: Go config field, default `false`, persistence, `Config` type in `api.ts`. Add `review_metadata_server_query?: boolean` to `interface Config` (api.ts:958); the web app does not read `review_apply_enabled` today. The lane reads the new key once with `api.getConfig()` at mount; do not add a frontend flag system.
3. In `api.ts` add `getReviewPage` (maps the lane filter state to the PR 17 parameters, including `ungrouped` and, if PR 17 added it, `skipped`) and `getReviewMatchingIds` (`ids=all`). Both accept an `AbortSignal`.
4. In the lane, branch on the flag. Flag ON: do NOT call `getCachedReviewResults(0, 0, true, ...)` at all. Replace the load effect and the `useMemo` chain (lines 973 and 1196-1372) with one query effect keyed on the settled filter object: 150 ms debounce, an `AbortController` per request (abort the previous one; an aborted request never updates state), the response sets `pageRows`, `facets`, `total`, `generation`. Keep the per-page detail fetch (line 1420) because evidence needs the full row.
5. Every one of the seven `refresh()` call sites becomes a page refetch plus facet refetch (about 130 KB), not an index reload. Do not delete the helper; make it mode-aware.
6. `selectAllMatching` (line 1995): in page mode call `getReviewMatchingIds` with the current filter, keep ONLY the ids (1.2 MB at 40k rows), store the response `generation`, and make `allMatchingSelected` mean "every id in the current ids list is selected". Before applying a selection, compare the stored generation with the current page's; if the ids list is older, refuse with a visible message ("The queue changed; select all again") and do not send. The existing apply path already sends `APPLY_CHUNK_SIZE` (500) ids per request, so nothing downstream changes.
7. `QueueRail`: in page mode render the server facet counts. The Title box keeps its error display (`titleFilterError`) from the 400 message the server returns for a bad pattern, and also from the existing client pre-check `regexValueError` so a typo is reported before a request is sent.
8. If PR 15's note names a closure retaining an old results array, fix it in the same hook while you are rewriting the effect chain and say which; if PR 15 has not been filled in, do not guess: leave a TODO comment pointing at it and mention it in the report.
9. Leave index mode intact for one release. Add a test that flag OFF still issues exactly one `view=index` request and zero `view=page` requests.
10. Review the diff in two commits (query hook and API, then call sites) because the lane file is 2,300 lines.
