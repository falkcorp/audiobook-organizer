## Goal
Today a provider answer is cached per book (`metadata_fetch_cache:<bookID>:<provider>#q<hash>`), only when non-empty, so duplicate copies and track rows each pay for the same question, and a book nobody can answer is re-asked on every pass. After this PR an answer is keyed by the question (`pcache:q:<provider>:<endpoint>:<sha256(normalized question)>`), shared across books, empty answers are cached with a per-provider negative TTL, errors and throttles are never cached, and `asin-backfill` goes through the same cache.

## Steps
1. Create the worktree. Run `go test ./internal/metafetch/... ./internal/database/... -count=1` for a baseline.
2. `NormalizeQuestion` first, with its table test, because every other piece depends on it. Rules (spec section 3.4): the key hashes EXACTLY the parameters sent to the provider and nothing looser. NFKC, then a case FOLD (not `strings.ToLower`: `\u0130` and `\u00df` must fold, use `golang.org/x/text/cases` Fold), whitespace collapsed to one space, punctuation that no provider tokenizer keeps (quotes, apostrophes, commas, periods, colons, dashes, brackets) turned to a space, letters, digits and `&` kept. Author credits are an ORDERED list: normalize each credit on its own and join with `\x1f` in credit order, never sorted (`A, B` and `B, A` are different keys). Narrator, series, ISBN and ASIN are included only for calls that send them. Provider id, endpoint and marketplace are a prefix outside the hash so a bust by provider is a prefix delete. Add the cases the spec names (`Title: Part 2` equals `Title - Part 2`; `A, B` differs from `B, A`; `A , B` equals `A, B`; a field the call does not send never changes the key).
3. Key families and entry type: `pcache:q:<provider>:<endpoint>:<hex sha256>`; the entry stores the raw pre-filter results, `asked_at`, and `empty`. TTL on read: a non-empty entry is valid for `MetadataFetchCacheTTLDays` (today's knob); an empty entry for the provider's negative TTL. An expired entry reads as a miss (do not delete on read).
4. `askVariant`: build the P1 key from the provider and the exact call (title only, or title+author), read it BEFORE `waitForLimiter` (a hit costs no limiter token), and on a hit run `p.accept(v, rs)` on the stored raw results (an empty raw answer yields no results and no call). On a miss take the token, call, and write the entry for BOTH non-empty and empty answers, but ONLY when `err == nil`. Any error, `ErrProviderThrottled` and 429 write nothing: pin each with a test. Keep `metrics.RecordCacheHit/Miss(searchCacheName)` calls and add the label value for the new cache so a hit ratio can be read from `audiobook_organizer_cache_hits_total`.
5. `cachedLookupASIN`: P2 `pcache:asin:<ASIN>` (30 days, positive only; a nil,nil "no such ASIN" is cached as an empty negative with the provider's negative TTL ONLY IF the code can distinguish it from an error; if it cannot, leave the empty case uncached and say so).
6. Chain walk and `SearchByContext`: the P1 key hashes the FULL `SearchContext` (ISBN, series, narrator) plus title and author, because `FetchMetadataForBook` sends it (`service_fetch.go:188-189`). A key missing a field the call sends would serve one book another book's answer; add a test that two books differing only in series produce different keys.
7. Pointer rows: when a book's search writes or reads P1 keys, record `bookID -> [P1 keys]` so the per-book "Search again" (`BypassFetchCache`/the existing bust) deletes the P1 keys that book's current question maps to. Readers try P1 first, then fall back to the legacy `metadata_fetch_cache:<bookID>:...` row (read old, write new; the pattern `CachedMetadataForProvider` already uses). Do not migrate legacy rows in bulk and do not delete them.
8. `asin_backfill.go`: replace the direct `SearchIdentities` calls with a P1-cached call. Its retry-after marker logic is unchanged.
9. Config: add the flag and the four negative TTLs end to end (struct, default, viper read, persistence). `metadata_fetch.shared_cache=false` makes every read and write go back to today's per-book keys; a test proves it.
10. Do NOT add any new metric framework: reuse `metrics.RecordCacheHit/Miss/Set`. Do NOT change scoring, the accept filters or the variant ladder.
11. Measure: build a synthetic scenario of 1,000 books where 300 share 100 distinct questions plus 400 unanswerable questions asked twice; count provider calls with a counting fake provider before (flag off) and after (flag on).

## Rollback
Set `metadata_fetch.shared_cache=false`: reads and writes return to per-book keys; `pcache:` rows become inert. Revert the PR to remove the code; the `pcache:` family should then be range-deleted so it does not sit unregistered (the keyfamily partition test names any stray prefix).
