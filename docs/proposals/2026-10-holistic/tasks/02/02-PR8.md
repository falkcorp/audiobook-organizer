## Goal
The Macs have written window fingerprints (`fpwin:`) for the library, and nothing compares them: `fingerprint.WindowSetSimilarity` has no production caller. After this PR an inverted index over window prints (`fpwinidx:`) generates candidate pairs in O(n*b), a new SUPPORTING dedup signal `SigWindowAcoustID` verifies them with `WindowSetSimilarity`, and the existing chapter-fragment fixer shows window containment as extra evidence for fragment-to-parent matches. The owner's approval of a consolidation list by id is unchanged. No audio is decoded on the server.

## Steps
1. Create the worktree. Confirm 05 PR 3 is on `origin/main` (the index-build op needs the cancel fence) and read 03 PR 1's merged parity pin if present; if the dedup candidate-set baseline is not pinned yet, stop and report (this PR changes dedup scores).
2. Position-independent bands. Window prints of the same audio at different offsets do not line up frame for frame, so reuse of `Subprints` (position-based samples) would miss offset copies, which is exactly the fragment case. In `window_lsh.go` take every pair of consecutive frames (8 bytes, the unit `Subprints` uses) of the window's `Raw` as a shingle, and compute a b-band, r-row MinHash over the shingle SET. Choose (b, r) by experiment on synthetic prints with the targets: recall of at least 0.95 at 1 percent per-bit noise between two prints of the same audio, and a false-candidate rate of at most 2 percent between unrelated windows. Record the chosen b and r and the measured rates in the PR description; make b and r constants with a version byte in the key so a re-tune is a new index version.
3. Sizing, before enabling anything: count the ws1 windows a file gets (`window_plan.go`), then keys = files with windows x windows per file x b (+ one meta row per file). For the 742k-file figure the proposal uses, print the arithmetic in the PR description, with the on-disk estimate at about 40 bytes per key. If the estimate exceeds 5 GB, STOP and report instead of shipping; the owner decides (the spec says to size it here).
4. Write-through in the same batch as the window write (`PutFingerprintWindow`), idempotent, with the member list so a replaced or deleted window removes its rows without recomputing the old print. Wire `DeleteFingerprintWindows` and `CarryOverFingerprintWindows`. Windows of kind `whole` are not indexed (they are the full-file print path). Never read audio.
5. Backfill op `dedup.window-index-build`: modelled on `lsh_index_build.go`, iterating files that have windows and no meta row, `Concurrency` set explicitly to `runtime.NumCPU()` (this is a whole-library CPU loop), `ResumePolicy: ResumeRestart`, a `ConcurrencyKey`, `Writes` declared for the new keyspace, `Permissions` declared (`settings.manage`), flag `fpwinidx_v1_done` set only on a complete pass. It must honour cancellation per item (05 PR 3). The op is NOT scheduled by this PR.
6. `CollectWindowAcoustID`: gate on `IsWindowIndexBuilt()` exactly as the LSH collector does (INFO and return nil when not built; no O(N) fallback). Probe with the query file's window bands, keep candidates with at least 2 band hits (configurable), load both files' windows (`WindowsForFile`), convert to `fingerprint.WindowPrint`, call `WindowSetSimilarity`; `ErrIncompatibleWindows` and `ErrNoComparableWindows` mean INCOMPARABLE: emit nothing and count them (a provenance mismatch is missing evidence, not disagreement). Skip `LowConfidence` results for the dedup signal. Emit `SigWindowAcoustID` with `Raw` = the similarity and a confidence scale like the LSH collector; one signal per candidate book (dedupe by book).
7. Scoring: add the kind as supporting with a default boost, include it in `DefaultScoreConfig`, bump `FormulaVersion` to `noisy-or-v2`. Do NOT trigger or schedule a rescore: bumping the version makes every stored pair stale and the owner schedules the corpus rescore in a window with no scan (D33). Add a loud comment at the constant and a line in the PR description.
8. Fragment containment evidence. For a fragment file F and candidate parent file P, compute `containment = |bands(F) ∩ bands(P)| / |bands(F)|` from the two `fpwinidx_meta` member lists (an exact set intersection of band keys, no probing). Add it to the fixer row's evidence string (`window containment 0.NN of the fragment's bands appear in the parent`) and as an informational check. It never changes `provenMatch`, never makes a row applicable, and a row that is not already supported by the existing hash/import-path evidence stays unapplicable. The default threshold `fragment_window_containment_min` only controls whether the line is shown as supporting (>= threshold) or weak (< threshold).
9. Leave `internal/plugins/maintenance/fragment_consolidation_fixer.go`'s owner-approval-by-id flow, its apply path and its undo journal byte-for-byte unchanged.

## Rollback
Set the new kind's boost to 0 in the score config (the signal stops affecting scores); the fixer's containment line is informational. To remove the index: revert the PR, then range-delete `fpwinidx:` and `fpwinidx_meta:` (a rollback wipe must cover both ranges, as the `fpwin_fail:` note in `fingerprint_window.go` warns about its own sibling). The FormulaVersion bump cannot be undone by reverting alone: pairs rescored under `noisy-or-v2` keep that stamp; the owner reschedules a rescore after a revert.
