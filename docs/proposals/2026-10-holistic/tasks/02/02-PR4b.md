## Goal
A Library or Review filter `author:<pattern>` matches a book when the pattern matches **any** of the book's credited authors (the `BookAuthor` credit rows), in credit order, instead of only `book.Author.Name`. Co-authored books stop disappearing from author filters. The `narrator:` field is unchanged by this PR (it is a flat string today; its credit list is a separate item).

## Steps
1. Read the matcher. Decide between (a) a plural `bookFieldValues(book, field) []string` used only for `author`, with the existing single-value function delegating for all other fields, or (b) joining is NOT acceptable (a regex must not match across two names). Choose (a).
2. Load credits once per query and thread them (DECIDED: thread `creditsByBook`, do not put names on the book copy, because `database.Book` has no credit field and adding one would leak into serialization). Extend the `needAuthor` block in `buildAuthorSeriesNameMaps` (:376) so that, along with `authorNames`, it builds `creditsByBook map[string][]string` (book ID to ordered credit NAMES, resolved through `authorNames`) from the store's credit rows, and return it. Pass it through `matchesFieldFiltersWithStrippedFallback` (:314) and `hydrateAuthorSeriesNames` (:354) into `matchesCompiledFilters` as a `creditNames func(bookID string) []string` parameter, down to `fieldMatchesCompiled`, which calls the new `bookFieldValues(book, field, creditNames)`. If the memdb summary already exposes credit IDs, use that instead of a store call and say so in the PR body.
3. In `bookFieldValues`, for `author` return `[primary name, credit names in order]` with duplicates removed and the primary kept first. An empty primary with credits present must still return the credits.
4. The match is true if the pattern matches **any** value. Negated filters (`-author:` or whatever the grammar uses; check `searchParser.ts` and the Go grammar) are true only if the pattern matches **none** of the values.
5. Do not change ordering, pagination, counts or the `narrator` case.
