## Goal
Make the owner's goal number a product feature: every book has an identification state `ident` in {unasked, asked_empty, has_candidates, applied, held} (with an `ident_reason`), maintained by write-through so each state's count is O(1), filterable in the Library with `ident:` (plus `ident:missing`, the goal's definition), with `asin:` as a new filter, and counts shown in the metadata-cache summary so the number can be clicked through. The same PR provides the durable dirty-set API that PR 14 drains.

## Steps
1. Create the worktree. Confirm 02-PR5a and 02-PR5b are on `origin/main` (`grep -n 'Stale' internal/database/iface_metadata.go`).
2. Write `DeriveIdentState(book, cache) (state, reason)` as ONE table-driven function with a doc comment holding the rules: no cache row -> `unasked`; row with zero candidates -> `asked_empty` (`LastEmptyFetchAt` or `EmptyAnswers` present); row with at least one candidate -> `has_candidates` (reason `stale` when `cache.Stale`); `MetadataReviewStatus` of `matched` or `audio_confirmed` (the handler's "applied") -> `applied`, whatever the cache row says; `no_match` or an owner-rejected book -> `held`. State this mapping in the PR description and have the owner confirm the `held` rule; it is the one judgement call. Reasons emitted by this PR are only `stale`, `rejected`, `no_match`; other reasons (`fragment`, `manual_only`, `quota_deferred`, `no_usable_title`) are added by later PRs.
3. Storage, all under new registered prefixes: `ident:state:<bookID>` -> state byte(s) plus reason; `ident:by:<state>:<bookID>` -> empty (membership, keys-only); `ident:n:<scope>:<state>` -> 8-byte big-endian counter for `scope` in {all, primary} (primary uses `database.EffectiveIsPrimaryVersion`, where a nil flag reads as NOT primary per the Library's own rule; add a test for nil); `ident:meta:built` -> marker with a schema version.
4. Write-through: one helper `stageIdentUpdate(batch, bookID, book, cache)` reads the old state row (a point read), derives the new state, and stages: the new state row, delete of the old `ident:by:` key, set of the new one, and counter deltas. Counter read-modify-write is serialized by one `identMu` (counters only; the per-book stripe lock already serializes a book). Call it in the SAME batch as the change from every chokepoint listed in Context. Convert `PutMetadataCache`/`DeleteMetadataCache` from single `db.Set`/`db.Delete` into a batch.
5. Boot rebuild: if `ident:meta:built` is absent or its version is old, `RebuildIdentIndex` scans the books and cache rows and rewrites everything, on a tracked background goroutine started AFTER memdb warmup (warmup is asynchronous; do not block startup). While it runs, `IdentCounts()` returns `ready=false` and the filter returns `ErrIdentIndexBuilding`, which the Library handler maps to HTTP 503 with `Retry-After`, never to a wrong count. The rebuild is a whole-library loop: scan sequentially (it is IO-bound on one Pebble iterator) but derive on a bounded worker pool sized `runtime.NumCPU()` with one writer, and say so in a comment (the repo's concurrency rule).
6. Drift guard: `IdentCountersDrift()` recounts from the `ident:by:` keys and compares to the counters; call it from tests and once at the end of every rebuild (log WARN with the delta; repair by rewriting counters). This is the guard for a writer that was missed.
7. Dirty set: `MarkIdentDirty(bookID)` writes `ident:dirty:<bookID>` -> a monotonically increasing epoch (8 bytes) and returns it; `IdentDirtyPage(after, limit)` returns up to `limit` `{BookID, Epoch}` in key order (PR 14 uses limit 256); `ClearIdentDirty(bookID, epoch)` deletes the mark ONLY if the stored epoch equals `epoch` (compare-and-delete under the book's stripe lock) and returns whether it did. Do not call `MarkIdentDirty` from the scanner or merge in this PR (PR 14 does).
8. Library filter. `ident` is not a field of `database.Book`, so it cannot live in `bookFieldValue`. In `service_filtering.go` extract `ident` field filters before the walk, resolve each to a set of book ids through a narrow capability (`IdentBookIDs(states []IdentState) (map[string]struct{}, error)`, obtained with `database.AsCapability`), and intersect with the request's `RestrictToIDs` the way the tag narrowing does. Values: the five states plus `missing` (= `unasked` + `asked_empty`, the goal's definition). A negated filter `-ident:x` resolves to the union of the complement states (the states are exhaustive). Unknown values are a 400 listing the valid ones. When no other filter is present and the scope is primary, the count is the counter (O(1)); otherwise it is the restricted walk.
9. `asin`: add a `case "asin"` to `bookFieldValue` next to `isbn10`, add it to `allFilterFieldNames` (the `TestFilterFieldNames_MatchTheMatcher` test then proves it is implemented). First prove ASIN is present on memdb-resident books (not stripped): write the test against the real memdb path, not a hand-built `Book`.
10. Summary: add `ident_counts` to the review summary object: `{unasked, asked_empty, has_candidates, applied, held, missing, ready}` for the primary scope.
11. Frontend: add `ident` and `asin` to `searchParser.ts`'s field list, the help text in `SearchBar.tsx`, parser tests. The Review grammar is NOT changed here (PR 17/18 own it).
12. Run the full package tests for database, audiobooks and server handlers.

## Rollback
Revert the PR. The index is derived and rebuilds on the next boot of any version that has it; the `ident:` rows are inert to older code, but if the revert leaves the prefixes unregistered, delete them with a range delete over `ident:` first (the keyfamily partition test will say if a stray family exists). The cache writes return to single `db.Set` calls.
