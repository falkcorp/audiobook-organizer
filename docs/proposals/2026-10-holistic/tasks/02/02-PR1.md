## Goal
Today the only filter benchmark, `BenchmarkOwnerQuery_100k`, measures `matchesFieldFiltersRT`, which compiles the filters again for every row, so it is an upper bound that does not describe production. After this PR the production predicate (filters compiled once per request) has its own benchmarks at 100k rows and at 40k primary rows, the old benchmark is renamed so nobody mistakes it for production, and a test fails if a per-row compile is ever introduced into the list path.

## Steps
1. Create the worktree and branch named in Guardrails. Run `go test -run '^$' -bench 'BenchmarkOwnerQuery_100k' -benchtime 5x -benchmem ./internal/audiobooks/` once before editing and keep the output line as the "before" figure for the old benchmark.
2. In `filter_duration_test.go` rename the benchmark to `BenchmarkOwnerQuery_100k_ConveniencePath`; do not change its body. Grep for other references to the old name (`grep -rn 'BenchmarkOwnerQuery_100k' . --include='*.go' --include='*.md' --include='*.yml'`) and update each (the holistic proposal docs may cite it; leave those, they describe the old name on purpose).
3. In `filter_compiled.go` add `var compileFiltersHook func()` with a comment ("test hook; nil in production") and call `if compileFiltersHook != nil { compileFiltersHook() }` as the first statement of `compileFieldFilters`. This is called once per compile, not per row, so it costs nothing on the hot path.
4. Create `filter_compiled_bench_test.go`. `BenchmarkCompiledPredicate_100k`: build `books, files := syntheticLibrary(100_000)`, warm a `newRuntimeIndex()` exactly as the old benchmark does, call `compileFieldFilters` ONCE outside the loop, and in the timed loop call `matchesCompiledFilters(books[j], cfs, ri.runtimeOf)` per row. Use `b.Run` sub-benchmarks for four filter sets: (a) `title:/^\s*\d/` regex, (b) `duration:>20m`, (c) `-metadata:applied duration:>20m` (the owner query, directly comparable to the old benchmark), (d) `library_state:organized`. Call `b.ReportAllocs()`.
5. `BenchmarkHeavyPushdownWalk_40kPrimary`: Pebble-backed fixture of 100,000 books of which 40,000 are `IsPrimaryVersion=true` (follow `BenchmarkScopedTagFacets_Cold`; creating 100k books is slow, so build the fixture before `b.ResetTimer()` and keep sub-benchmark count small). Time `svc.CountAudiobooksFiltered(ctx, ...)` with `ListFilters{IsPrimaryVersion: &yes, ExcludeQuarantined: true, LibraryState: "organized"}` (the heavy-pushdown branch) and, in a second sub-benchmark, the primary-only filter. Find the exact count method name with `grep -n 'func (.*AudiobookService) Count' internal/audiobooks/*.go`; if the count call needs different arguments, use the one the handler uses at `internal/server/audiobooks_helpers.go` lines 117-127.
6. Create `filter_compile_once_test.go`: set `compileFiltersHook` to increment an `atomic.Int64`, run one list request through the service over 1,000 synthetic books with two field filters (the benchmark calls `matchesCompiledFilters` directly and has no service entry point, so use `svc.GetAudiobooksWithTotal(ctx, 50, 0, "", nil, nil, ListFilters{FieldFilters: ...})` on a Pebble-backed `NewAudiobookService` fixture; print the observed compile count first and assert it equals 1 only if the observed count is 1, otherwise report the count and the compile sites that fired), restore the hook with `t.Cleanup`, and assert the counter is exactly 1. Then do the mutation check by hand: temporarily change the predicate to call `matchesFieldFiltersRT` per row, confirm the test fails with a count of about 1,000, and revert. Do not commit the mutation.
7. Run the benchmarks (commands in Tests) and paste the ns/op, B/op and allocs/op lines into the PR description and into the report. Compute ms per full pass (ns/op divided by 1e6).
8. Decision line for the PR description: state whether `BenchmarkHeavyPushdownWalk_40kPrimary` with the `library_state` filter is over 100 ms per call. If it is, add a `todo.d/` fragment (headerless) titled "Library enum filters: build per-value posting lists (spec 02 section 3.5)"; if it is not, say so and add no fragment. This is the trigger written into the spec for the deferred bitmap index.
