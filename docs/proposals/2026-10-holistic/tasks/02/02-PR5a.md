## Goal
`database.MetadataCandidateCache` gets a `Stale` flag, and every reader that already refuses a candidate whose ASIN was replaced now also refuses a row marked stale, as `identity_stale`, and the candidate-fetch selection picks stale rows for refetch. Nothing sets the flag yet (that is PR 5b), so production behaviour is unchanged; the point is that the gate is closed before any stale row can exist.

2. Add the two fields to `MetadataCandidateCache` and the summary field. Existing rows decode with `Stale=false` (omitempty), so no migration is needed.
3. Implement `CandidateIdentityStale(entry, book, c) error`: nil entry or nil book or nil c returns nil (as today); `entry.Stale` returns `fmt.Errorf("%w: book %s: the book was retitled or re-credited after these candidates were fetched (question %s)", ErrCandidateRowStale, book.ID, entry.StaleQuestionFP)`; otherwise fall through to the existing ASIN logic. Define `ErrCandidateRowStale` next to `ErrCandidateASINReplaced`.
4. Rename at all call sites (mechanical, compile-checked). In `batch_apply_one.go` the existing code already does the right things with a non-nil error (sets `ts.ExplainsStaleIdentity = false`, joins `idErr`); do not add a second code path. A transcription must NOT lift a stale-row refusal: that is the behaviour you get for free from the existing branch, and a test must pin it.
5. Summary and selection: copy `Stale` into the summary index in both the full scan and the incremental refresh, then in `unfetchedCandidateBookIDs` build `staleByBook` from the summaries and skip the `continue` at ~:202 for those books (`keep` does not exist there; `candidates` is a `map[string]int` of counts).
6. Do NOT set the flag anywhere. Do NOT touch `pebble_store.go` (that is PR 5b). Do NOT change `cacheSearchResponse` in `internal/metafetch/cache.go`: a refetch writes a new row (prev is only carried when the SourceHash matches, and a retitle changes it), which clears the flag by replacement. Add a test that pins exactly that (see Tests).
7. Run the package tests listed below and `go build ./...`.
