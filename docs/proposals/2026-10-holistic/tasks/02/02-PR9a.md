## Goal
`searchMetadataForBook` multiplies a candidate's score by 0.75 when the candidate names no author and by 0.85 when it names no narrator. Open Library and Google rows have no narrator by construction, so every one is pushed down whatever its title match. After this PR the interactive Search/Browse dialog ranks by a new `RankScore` in which a missing value is neutral (factor 1.0); the score breakdown still shows that the field was absent; and every automatic decision is byte-identical to before, because `Score`, the stored candidate order, merge tiering and `RerankTopK` are not touched.

## Design (amended 2026-10-10 after three review rounds of the first design)
The first design made `Score` itself neutral and re-derived the old penalised score at every apply gate (`LegacyAutoApplyScore`), then the old pick at every `Candidates[0]` site. Each review round found another order source it missed (merge tiers including the owner-rejected tier, `RerankTopK`'s pure-score order, pre-deploy direct-ASIN rows with no `asin_match` step, `POST /metadata/bulk-fetch`'s ungated pick). That approach is abandoned. The rule is now:

1. `MetadataCandidate.Score`, the stored candidate order, merge tiering and `RerankTopK` stay exactly as at HEAD, penalties included. Every gate and every `Candidates[0]` site reads HEAD-identical data, so "the auto-apply gate is unchanged in effect" holds by construction.
2. A new field `RankScore` (`json:"rank_score,omitempty"`, also on `ScoreBreakdown`) holds the same computation with the author-missing and narrator-missing factors at 1.0. The scorer records it alongside `Score` (`scoreRecorder.mulAbsence` multiplies `Score` only and marks the step `rank_neutral`), so `RecomposeRankScore(steps)` reproduces it. A rerank rescales `Score` exactly as before and carries `RankScore` at the same ratio to it.
3. `RankScore` is read ONLY where a person reads a ranking in the interactive Search/Browse dialog: the search-metadata response is ordered by `metafetch.SortForDisplay` (own-ASIN class first, then `RankValue()`, stable) at response time, and the two dialogs sort by `rankScoreOf` client-side. The stored row is not re-sorted. A row cached before the field existed has no `rank_score` and ranks by `Score`.
4. The review lane, review snapshot, op-results, cached batch apply, transcription auto-match, upgrade and junk-title paths are NOT re-sorted and do not read `RankScore`: pinned review applies stored `Candidates[0]`, matched to the snapshot's hashed first row, so re-sorting there would let the owner approve one row while the system applies another. The dialog's apply posts the clicked candidate itself (`apply-metadata` takes the candidate body, never an index), so the re-sorted list applies exactly the row shown.
5. Differential tests pin each reviewer probe to HEAD's stored order and gate verdict: rerank A/B, X/Y top row, merge with a rejected tier, the pre-deploy direct-ASIN row, bulk-fetch's pick.
6. `applygate/evidence.go` is untouched. `pickBestMatchFromScored` (single-book fetch) and `POST /metadata/bulk-fetch` keep their behaviour; both are filed as todo.d fragments (SCORE-MISSING-AUTHOR-FETCH, BULK-FETCH-NO-GATE).

## Steps
1. Create the worktree. `grep -rn 'Author missing\|No narrator\|author_missing\|narrator_present' internal web/src --include='*.go' --include='*.ts' --include='*.tsx' | grep -v _test` and list every consumer of those labels or ids. Keep `narrator_present` as the step id for the narrator rows.
2. Add `scoreRecorder.rank`, `mulAbsence` and `RecomposeRankScore`; make the other recorder methods carry `rank` (`mul`, `add`, `mulResult`, `replace`, `adopt`); switch the three missing-value branches (`service_search.go` author and narrator, `browse_search.go` author) to `mulAbsence`. `Score` must come out bit-identical to HEAD.
3. Add `MetadataCandidate.RankScore` / `RankValue()`, set it from the breakdown in `newSearchCandidate`, carry it through the series boosts and `recordRerank`.
4. Add `metafetch.SortForDisplay` and call it in the search handler's response (`respondCandidates`); sort the two dialogs by `rankScoreOf`. Touch nothing else that orders or reads candidates.
5. Write the differential tests (Tests below) and run them; they must pass without any gate change.
6. Run the calibration unit tests and report the harness's top-1 figures; show the ranking effect with an Audible and an Open Library row of equal title similarity (report both ratios).
