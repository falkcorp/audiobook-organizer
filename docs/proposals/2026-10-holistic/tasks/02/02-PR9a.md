## Goal
`searchMetadataForBook` multiplies a candidate's score by 0.75 when the candidate names no author and by 0.85 when it names no narrator. Open Library and Google rows have no narrator by construction, so every one is pushed down whatever its title match. After this PR a missing value is neutral (factor 1.0), the score breakdown still shows that the field was absent, and the auto-apply gate is unchanged in effect.

## Context the agent must read first
- `internal/metafetch/service_search.go` lines 1355-1415: the author block (`Author match` 1.5, `Author/narrator swapped` 1.4, `Author mismatch` 0.7, `Author missing` 0.75 at ~1377) and the narrator block (`Has narrator` 1.15, `No narrator` 0.85 at ~1408), and line 1351 `if score <= minScore`.
- `internal/metafetch/score_breakdown.go` lines 100-180: `scoreRecorder.mul` DROPS the step when `factor == 1` (line 130), so a plain factor of 1.0 would erase the breakdown row. `RecomposeScore` and `IsConsistent` define what a valid breakdown is.
- `internal/applygate/evidence.go` lines 100-175 (`CheckEvidenceInBatch`, `tally`) and 281-318 (`checkAuthorPath`: a candidate with no author returns `OutcomeUnknown`, which is not an agreement; `MinAgreements = 2`).
- `internal/applygate/applygate.go` lines 57-62 (`MinScore = 0.90`) and 188-208 (`ScoreGate`): the score leg compares the raw unbounded score with 0.90.
- `internal/metafetch/candidate_fallback.go:87`: `IsReviewOnlyCandidateSource` (Open Library and Google Books are review-only and never auto-apply anyway).
- `internal/plugins/metafetch/calibrate_scoring.go` header (the `metafetch.calibrate-scoring` harness; do not run it against production, run its unit tests).

## Steps
1. Create the worktree. `grep -rn 'Author missing\|No narrator\|author_missing\|narrator_present' internal web/src --include='*.go' --include='*.ts' --include='*.tsx' | grep -v _test` and list every consumer of those labels or ids (the evidence panel may display them). Keep `narrator_present` as the step id for the narrator rows so existing consumers keep working; the ids you add are `author_unknown` and `narrator_unknown` only for the missing branch.
2. BEFORE changing anything, write the applygate regression test and run it at HEAD: a candidate with an empty `Author`, a title that equals the book's title, a runtime within 5 percent of the book's, from Audible (not review-only), for a book that has a live author. Record what `Evaluate` returns at HEAD (which leg fails, with what reason). This is the baseline the change must not worsen.
3. Add `scoreRecorder.unknown` and switch the two branches. Everything else in the author and narrator blocks is untouched (match, swapped, mismatch, has-narrator).
4. Run the scorer tests; update the expected numbers. For each changed number write the arithmetic in the test table comment (old product, new product).
5. Re-run the step-2 regression test. If the candidate that failed at HEAD now PASSES (the score leg no longer stops it because ×0.75 is gone and evidence has two agreements from title and runtime), the gate has been loosened: add `ReasonAuthorUnknown = "author_unknown"` and, in `checkAuthorPath`, return `OutcomeBlock` with that reason when the candidate names no author AND the book has at least one live author AND the ASIN check is not an agreement (an ASIN match is independent proof). State this in the PR description as a gate-preserving guard, with the before/after verdicts. If the candidate failed for another reason at HEAD and still does, add nothing and say so.
6. Run the existing `calibrate-scoring` unit tests and the metafetch and applygate packages. The harness's top-1 accuracy figure on its fixture must not drop; paste the before and after numbers.
7. Show the ranking effect: add a test with one Audible candidate and one Open Library candidate (no narrator) of equal title similarity; at HEAD the Open Library row scores ×0.85 lower for the narrator alone; after the change the two differ only by the has-narrator ×1.15 that the Audible row legitimately earns. Put the two scores in the test.
