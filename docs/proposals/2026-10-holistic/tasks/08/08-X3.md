## Goal
The standing ban says audio decoding (fingerprinting, transcription, WAV extraction) runs on the Mac workers only; `ffprobe` is allowed on the server. Three operations still decode in-process on whatever host runs the server, including production. After this PR each of them returns a clear error before touching any audio unless the deployment explicitly opts in with `ALLOW_SERVER_DECODE=1` (developer machines and the CI agents that have the tools set it; production does not).

## Design (decided; do not add a Settings key)
- The switch is an **environment variable**, not a persisted setting: a safety ban must not be flippable from the Settings page by an editor, and persisting it would put it in the whole-struct config blob (the zero-overrides-default hazard in 07 F12).
- New leaf package `internal/serverdecode` (imports only the standard library, so it sits in layer L0 of 07-G2):
  - `const EnvVar = "ALLOW_SERVER_DECODE"`;
  - `var ErrRefused = errors.New("audio decoding is not allowed on this server")`;
  - `func Allowed() bool` (`strconv.ParseBool(os.Getenv(EnvVar))`, false on empty or unparsable);
  - `func Check(opID string) error`: nil when allowed, else `fmt.Errorf("%s: %w: decoding runs on the Mac workers; set %s=1 only on a development host", opID, ErrRefused, EnvVar)`.

## Steps
1. Create the package and its test.
2. Add the guard to the three ops as `if err := serverdecode.Check("<op id>"); err != nil { return err }`. Keep the op ids exactly as registered (`acoustid.fingerprint-rescan`, `maintenance.extract-wav-clips`, `maintenance.transcribe-book-intros`).
3. In `intro_transcribe.go` leave `reparse_only` runs working with the guard unset: add a test that `{"reparse_only": true}` with the env unset does **not** return `ErrRefused`.
4. Optimize sweep: filter the child as described; add a test beside the existing optimize tests (find them with `grep -ln optimizeDef internal/plugins/maintenance/*_test.go`).
5. Run the package tests; give each test that now fails with `ErrRefused` the `t.Setenv`. Do not weaken the guard to make a test pass.
6. In the PR body, list the callers in "Context" and what each now sees: the op ends `failed` with the message above. In particular `acoustid.reset-all` followed by `acoustid.fingerprint-rescan` (`handlers/dedup/handler.go:2286-2292`) wipes every stored fingerprint and then the rescan is refused; the Mac workers refill the library. Say this plainly; 03 PR 4 adds the confirm dialog and hides the command while no worker has checked in. Do not change the handler here.
