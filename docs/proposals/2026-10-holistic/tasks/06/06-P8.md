How to run a go fix batch (applies to every 06 go fix brief):
1. Create the worktree from a fresh `origin/main`; `git log -1 --format=%h` is the base. The appendix (`docs/proposals/2026-10-holistic/06-bleeding-edge/gofix-batches.md`) is a 2026-10-08 census, **not** your input: 01 tier 2 deleted code since.
2. Check the flag syntax on the pinned toolchain: `go help fix` and `go tool fix help` (the census used one `-<analyzer>` flag at a time, `go fix -diff -rangeint ./...`). Use `-diff` first. Run each analyzer of your batch separately and together; the together-run must equal the union.
3. Rerun with the extra build tags so tagged files are included: add `-tags "pprof bench embed_frontend fts5 native_taglib"` (check that `go fix` accepts `-tags`; if it does not, say so in the report).
4. Exclude `internal/writeback/` by policy even though the census found 0 files there: after applying, `git diff --name-only | grep '^internal/writeback/'` must print nothing.
5. Apply for real only after the diff review: run the same command without `-diff`, then `gofmt -l .` (must print nothing) and `git diff --stat`.
6. Do not hand-edit generated mocks (`make mocks-check` must stay green) or generated files.

Scope: the whole module, `./...`; `waitgroupgo` and `testingcontext` only. Census: 29 files, 24 of them tests, and five non-test files that need individual reading: `internal/compactprogress/step.go`, `internal/fingerprint/workerclient/worker.go`, `internal/repairs/standdown.go`, `internal/server/handlers/abs/cache_refresh.go`, `internal/server/server_search.go`.

7. Produce the real file list: `go fix -diff -waitgroupgo -testingcontext ./... | grep '^+++ ' | sed 's/^+++ //;s/\t.*//' | sort -u > /tmp/P8-files.txt` (use the scratchpad directory instead of `/tmp` if you have one) and compare its count with the census count 29. A difference is expected (the tree moved); explain large ones (more than 20 percent) in the report.
8. Review every hunk class once with this checklist:
   - `waitgroupgo` turns `wg.Add(1); go func(){ defer wg.Done(); ... }()` into `wg.Go(func(){ ... })`. This changes goroutine lifetime wiring. Reject or hand-fix a hunk when: `Add` and the `go` statement are far apart or in different branches; `Done` is called on a path other than a plain `defer`; the closure is passed `wg` or calls `wg.Done()` itself; `Add(n)` with n > 1 was used; the goroutine body can panic and a `recover` wrapper sat between `go` and `defer`.
   - `testingcontext` turns `context.WithCancel(context.Background())` in a test into `t.Context()`: `t.Context()` is cancelled just *before* cleanup functions run, so a test that cancels at the end and then asserts on shutdown behavior in `t.Cleanup` may change meaning. Read both hunks (the census found only 2 sites).
   - Never leave a hunk half-applied: either the whole goroutine site is converted or it is untouched and listed in the PR body.
9. Apply: `go fix -waitgroupgo -testingcontext ./...`. Re-run `go fix -diff -waitgroupgo -testingcontext ./...`: it must now print nothing (fixed point). If the second run still produces hunks, apply again until it is empty and note the number of passes.
10. Changelog fragment (`### Changed`, one line: which analyzers, how many files).
11. One commit. PR body lists: base SHA, the exact commands, file count versus census, and the review notes.
