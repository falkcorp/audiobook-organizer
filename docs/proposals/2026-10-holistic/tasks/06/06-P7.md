How to run a go fix batch (applies to every 06 go fix brief):
1. Create the worktree from a fresh `origin/main`; `git log -1 --format=%h` is the base. The appendix (`docs/proposals/2026-10-holistic/06-bleeding-edge/gofix-batches.md`) is a 2026-10-08 census, **not** your input: 01 tier 2 deleted code since.
2. Check the flag syntax on the pinned toolchain: `go help fix` and `go tool fix help` (the census used one `-<analyzer>` flag at a time, `go fix -diff -rangeint ./...`). Use `-diff` first. Run each analyzer of your batch separately and together; the together-run must equal the union.
3. Rerun with the extra build tags so tagged files are included: add `-tags "pprof bench embed_frontend fts5 native_taglib"` (check that `go fix` accepts `-tags`; if it does not, say so in the report).
4. Exclude `internal/writeback/` by policy even though the census found 0 files there: after applying, `git diff --name-only | grep '^internal/writeback/'` must print nothing.
5. Apply for real only after the diff review: run the same command without `-diff`, then `gofmt -l .` (must print nothing) and `git diff --stat`.
6. Do not hand-edit generated mocks (`make mocks-check` must stay green) or generated files.

Scope: the whole module, `./...`; `newexpr` only. At the census every one of the 67 files was a `_test.go` file (381 hunks): it replaces local pointer-helper calls (`ptr(x)`-style) in fixtures with `new(value)`.

7. Produce the real file list: `go fix -diff -newexpr ./... | grep '^+++ ' | sed 's/^+++ //;s/\t.*//' | sort -u > /tmp/P7-files.txt` (use the scratchpad directory instead of `/tmp` if you have one) and compare its count with the census count 67. A difference is expected (the tree moved); explain large ones (more than 20 percent) in the report.
8. Review every hunk class once with this checklist:
   - Each rewrite must replace a call to a *local* helper that returns a pointer to its argument; `new(expr)` (Go 1.26) is equivalent. Reject any hunk whose helper does something else (copies, defaults, trims).
   - Typed untyped constants: `new(5)` is `*int`; if the helper was `ptr[int64](5)` or took an `int64`, the hunk must preserve `int64`. The compiler is the guard; read hunks near numeric and duration fields.
9. Apply: `go fix -newexpr ./...`. Re-run `go fix -diff -newexpr ./...`: it must now print nothing (fixed point). If the second run still produces hunks, apply again until it is empty and note the number of passes.
9a. After applying, find helpers that no longer have callers: `go vet ./...` does not report unused functions, so run `staticcheck -checks U1000 ./...` (the repo already runs staticcheck; use `make staticcheck` output if it covers U1000) and `go build ./... && go test -count=1 -run xxx ./...` to confirm a deletion compiles. Delete only helpers that are unused after the rewrite **and** were the targets of these hunks. A helper still used by non-rewritten call sites stays.
10. Changelog fragment (`### Changed`, one line: which analyzers, how many files).
11. One commit. PR body lists: base SHA, the exact commands, file count versus census, and the review notes.
