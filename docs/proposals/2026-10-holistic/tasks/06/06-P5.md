## Steps
**Regenerate with `go fix -diff` at the PR base, never rebase an old diff. Run only in freeze window F (roadmap §5; D50), after 01 tier 2 (T1-T7) has merged. `omitzero` is excluded (D40): never apply it, and confirm the final diff has no `omitempty` -> `omitzero` change.**

How to run a go fix batch (applies to every 06 go fix brief):
1. Create the worktree from a fresh `origin/main`; `git log -1 --format=%h` is the base. The appendix (`docs/proposals/2026-10-holistic/06-bleeding-edge/gofix-batches.md`) is a 2026-10-08 census, **not** your input: 01 tier 2 deleted code since.
2. Check the flag syntax on the pinned toolchain: `go help fix` and `go tool fix help` (the census used one `-<analyzer>` flag at a time, `go fix -diff -rangeint ./...`). Use `-diff` first. Run each analyzer of your batch separately and together; the together-run must equal the union.
3. Rerun with the extra build tags so tagged files are included: add `-tags "pprof bench embed_frontend fts5 native_taglib"` (check that `go fix` accepts `-tags`; if it does not, say so in the report).
4. Exclude `internal/writeback/` by policy even though the census found 0 files there: after applying, `git diff --name-only | grep '^internal/writeback/'` must print nothing.
5. Apply for real only after the diff review: run the same command without `-diff`, then `gofmt -l .` (must print nothing) and `git diff --stat`.
6. Do not hand-edit generated mocks (`make mocks-check` must stay green) or generated files.

Scope: the whole module, every top-level package (`./...`), all ten analyzers of batch 1.

7. Produce the real file list: `go fix -diff -any -forvar -minmax -errorsastype -reflecttypefor -stringscut -stringscutprefix -stringsbuilder -stditerators -inline ./... | grep '^+++ ' | sed 's/^+++ //;s/\t.*//' | sort -u > /tmp/P5-files.txt` (use the scratchpad directory instead of `/tmp` if you have one) and compare its count with the census count 80. A difference is expected (the tree moved); explain large ones (more than 20 percent) in the report.
8. Review every hunk class once with this checklist:
   - `forvar`: removes `x := x`; only legal when the closure semantics are unchanged (Go >= 1.22 per-iteration variables); `go.mod` is `go 1.27.0`, so fine.
   - `minmax`: `if a < b { x = a }` shapes replaced by `min`/`max`; check NaN-free float use and that both branches really were the same variable.
   - `errorsastype`: `errors.As(err, &t)` becomes `errors.AsType[T](err)`; check the variable `t` is not used after the `if` in a way that changes scope.
   - `stringscut`/`stringscutprefix`/`stringsbuilder`/`stditerators`/`reflecttypefor`/`any`/`inline`: confirm the rewritten expression has the same type; `inline` is one hunk (`//go:fix inline` directive), read it.
9. Apply: `go fix -any -forvar -minmax -errorsastype -reflecttypefor -stringscut -stringscutprefix -stringsbuilder -stditerators -inline ./...`. Re-run `go fix -diff -any -forvar -minmax -errorsastype -reflecttypefor -stringscut -stringscutprefix -stringsbuilder -stditerators -inline ./...`: it must now print nothing (fixed point). If the second run still produces hunks, apply again until it is empty and note the number of passes.
10. Changelog fragment (`### Changed`, one line: which analyzers, how many files).
11. One commit. PR body lists: base SHA, the exact commands, file count versus census, and the review notes.
