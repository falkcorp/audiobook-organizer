## Goal
For about 30 minutes after every restart the process runs at 3.5 to 4 cores, 77 to 88 percent of it in the Go GC (measured 2026-10-14 on a binary from main 591c9123f with a 5.87 GiB, 60M-object live heap). After this brief: (1) the trickle list warmer never forces a GC (`runtime.GC()` / `debug.FreeOSMemory()` are gone from `library_list_warmer.go` apart from one baseline GC taken after memdb is published); (2) `CountPrimaryBooks` is served from memdb instead of a 322 MB, 4.2M-object Pebble scan every minute; (3) the authors and series cache warmers do not run Pebble full scans while memdb is still loading. Heap profile 25 minutes after restart must still plateau near 5.9 GiB, and a CPU profile taken 10 to 30 minutes after restart must show `gcBgMarkWorker` under 10 percent of CPU.

2. **Trickle warmer: remove the forced GCs.** In `library_list_warmer.go`:
   - Delete `runtime.GC()` and `debug.FreeOSMemory()` at the per-tick site (about :789-790) and at the eager baseline (about :528-529). Remove `FreeOSMemory` at the trickle baseline (about :629-630) as well.
   - The trickle baseline needs a settled live-heap number. Keep exactly one `runtime.GC()` immediately before the baseline is taken, and only after memdb is published (use the readiness check the file already uses to start the trickle; if there is none, wait on the same signal `warmAudiobookListCache` uses). A baseline taken before the memdb is fully live is stale-low and the ceiling guard would then skip every remaining query.
   - Do not add a replacement timer or a "GC every N ticks" knob. The runtime paces GC; `GOMEMLIMIT` is the safety net. Do not touch `GOMEMLIMIT` or `GOGC`.
3. **Trickle warmer: guard without stop-the-world.** Replace `readHeapAllocMB` (`runtime.ReadMemStats`) with a read of `runtime/metrics` `/gc/heap/live:bytes` (live heap after the last GC, no STW). The existing ceiling (`ListWarmerHeapDeltaMB`, config `list_warmer_heap_delta_mb`, env `LIST_WARMER_HEAP_DELTA_MB`, default 4096) now compares live-heap growth since the baseline; check that its meaning in `.env.example:54-55` and the docs still holds and update the text. If `/gc/heap/live:bytes` is zero (no GC has happened yet), the guard must skip the ceiling check for that tick, not treat zero as "huge growth" or "no growth" without a test. Update the stale comments: "about 13GB baseline" (:48), the baseline description (:611-618), and the "5-20ms on a 1GB heap" comment (:785), which no longer applies because no GC is forced.
4. **`MemStore.CountPrimaryBooks`.** Add a method on `MemStore` that walks the `books` table in one read transaction without decoding, counts rows that are not soft-deleted and are primary versions (reuse `bookIsSoftDeleted` and `IsPrimaryVersion`, exactly as `PebbleStore.countPrimaryBooksScan` defines them: read it first and match its predicate, including how it treats `NULL`/empty version groups), and also produces the number of primary books with a leading-number title that `countPrimaryBooksScan` feeds into `metrics.SetNumberLeadingTitles` (use the same `titleutil` helper the scan uses). Guard with `requireTablesComplete(memTableBooks)`; on an incomplete table return the error so the caller falls back, never a partial count. In `PebbleStore.CountPrimaryBooks`, call `p.memOrFallback("CountPrimaryBooks")` after the TTL cache check; when it returns a `MemStore` use it; otherwise run the existing Pebble scan. Keep the cache, keep the metric update on both paths. This is a read of data the process already holds; there is no new write path and no concurrency change.
5. **Entity warmers wait for memdb.** In `startCacheWarmers`, start the authors and series warmers behind `WaitForWarmupCtx(s.bgCtx)` (resolve it with `database.AsCapability[interface{ WaitForWarmupCtx(context.Context) error }](s.Ops())`, wrapped in a 5 minute `context.WithTimeout` like the existing waits). A nil return means nothing is left to wait for: memdb is published, or the warmup failed and the store fell back to Pebble. Either way run the warmer as before (memdb path when published, Pebble path when not), so a failed warmup never skips the warm. A ctx error on shutdown returns without warming; on the 5 minute bound, run the warm as today. Put the capability lookup and the bounded wait in one small unexported helper next to `warmAudiobookListCache`, used by both entity warmers; do not add a third hand-rolled poll loop (the two existing `memReadyChecker` polls at :167 and :842 are out of scope).
6. **Narrow Pebble decode for BookFile fallbacks.** `getBookFilesForIDsPebbleScan` (the Pebble path of `GetBookFilesForIDsCore`, pebble_store_authors.go:941-1010 is its main caller) decodes the full `BookFile`, including the base64 `AcoustIDFingerprint` blob (about 2.4 GB of base64 decode in the authors path). Read the callers of `GetBookFilesForIDsCore`: if none needs the fingerprint (check the `Core` type it returns), decode into a narrow struct that omits it. If a caller does need it, do not change that caller; add the narrow variant for the others. Do not change what memdb stores (that is the follow-up in Step 8).
