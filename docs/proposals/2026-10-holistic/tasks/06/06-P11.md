`vitest` and `@vitest/coverage-v8` move from 4.1.x to 5.0.x with the full suite still green (185 files, 1,834 tests at the census). A second, separately revertible commit turns on Vitest 5's persistent module cache (`fsModuleCache`) and records the timing change.

## Steps
1. **Baseline first** (record all numbers in the PR body): `cd web && npm ci && /usr/bin/time -p npx vitest run --reporter=dot 2>&1 | tail -15`. Expect about 185 files, 1,834 tests, about 52 s wall at the census; use your own measured numbers as the baseline, they are what the PR compares against.
2. **Commit 1, the upgrade.** `cd web && npm install -D vitest@^5.0.3 @vitest/coverage-v8@^5` (add `@vitest/ui@^5` only if it is already a dependency). Check engines: Vitest 5 needs Node >= 22.12 and Vite >= 6.4 (the repo has Node 26 and Vite 8.2). Run the full suite. Do not set `clearMocks` yourself: Vitest 5 defaults it to true, and the census proved 1,834 of 1,834 tests pass with it on. If any test now fails because of clearMocks or the other documented break (unawaited async assertions fail), fix the test, do not disable the new default, and list the tests in the PR body.
3. Run coverage once (`npx vitest run --coverage`) and confirm the 30/20/20/25 thresholds still pass; Vitest 5 may compute v8 coverage slightly differently, in which case report the old and new percentages and do not lower a threshold without saying so.
4. **Commit 2, `fsModuleCache`.** Add the option exactly as the Vitest 5 docs spell it. Run the suite twice back to back (cold cache, then warm) and record both wall times and the `import` and `environment` phase totals from the reporter summary. Confirm the cache directory is git-ignored, that `npm ci` on a fresh clone does not depend on it, and that CI does not accidentally share a stale cache across Vitest versions (if CI persists `node_modules/.vite` or similar, say so). If the warm run is not faster or any test becomes order- or cache-dependent, drop commit 2 and say why.
5. Changelog fragment (`### Changed`, `#### Frontend tests run on Vitest 5`).
6. Keep the two commits separate in the PR so commit 2 can be reverted alone.
