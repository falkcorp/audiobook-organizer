## Steps
1. **Baseline before editing** (record in the PR body): `cd web && npm ci && time npx tsc --noEmit -p . --extendedDiagnostics` (TS 6.0.3: expect about 8.9 s, 0 errors), and `npx vitest run --reporter=dot | tail -5` for the test count.
2. **devDependencies, exactly** (remove the old `"typescript": "^6.0.3"` line):
   ```jsonc
   "@typescript/native": "npm:typescript@^7.0.2",
   "typescript": "npm:@typescript/typescript6@^6.0.2"
   ```
   Install with `cd web && npm install` (not `npm ci`), then commit the regenerated lockfile.
3. **Scripts, exactly:**
   ```jsonc
   "build":         "tsc -p . --noEmit && vite build",
   "typecheck":     "tsc -p . --noEmit",
   "typecheck:ts6": "tsc6 -p . --noEmit",
   "lint":          "eslint ."
   ```
   `lint` is unchanged; it is listed so the four-script set is explicit.
4. **Which binary is which (verify, do not trust).** The aliases do not rename binaries: npm links the package's own `bin` names. `typescript@7` declares `tsc` (and `tsserver`), `@typescript/typescript6` declares `tsc6`. So `web/node_modules/.bin/tsc` is TS 7 and `web/node_modules/.bin/tsc6` is TS 6. Prove it: `npx tsc --version` prints `Version 7.0.x`; `npx tsc6 --version` prints `Version 6.0.2`; `ls web/node_modules/.bin | grep -i '^ts'` lists both; `npm view @typescript/typescript6 bin` shows `tsc6`. If both packages also declare `tsserver`, report which one npm linked (it affects editors only).
5. **What typescript-eslint resolves.** `import 'typescript'` resolves the dependency *named* `typescript`, which is now the `@typescript/typescript6` alias, so `cd web && node -e "console.log(require('typescript').version)"` prints `6.0.2` (TS 7.0 ships no JS API, so nothing can resolve it by accident). `npm ls typescript typescript-eslint` must show `typescript-eslint@8.x` deduped against `typescript@npm:@typescript/typescript6@6.0.2` with no `ERESOLVE`/`invalid` marks. typescript-eslint's peer range is `typescript >=4.8.4 <6.1.0`; 6.0.2 satisfies it. Note in the PR that the alias lands one patch below the previously installed 6.0.3 (parse-only use; fine).
6. **Seeded-error control, both compilers.** Create `web/src/__p9_control.ts` containing `export const x: number = "not a number";` (do not commit it). `npx tsc -p . --noEmit` and `npx tsc6 -p . --noEmit` must each exit non-zero with `TS2322`. Delete the file. Then both must exit 0 again.
7. **Other `tsc` callers.** `grep -rnE '\btsc\b' Makefile Dockerfile* .github .woodpecker web/package.json scripts` and decide for each: they now run TS 7. The `Dockerfile` frontend stage runs `npm ci` and `npm run build` on `node:26-alpine` (musl): TS 7 ships platform-specific native binaries as optional dependencies, so **build the image** (`docker build --target frontend-builder .` or the equivalent stage name in the `Dockerfile`) and confirm `npm run build` passes there. Do the same check for linux/arm64 if a runner is available; otherwise list it as unverified. The lockfile must contain the optional platform entries (`grep -c '@typescript/native-' web/package-lock.json` or the actual package names printed by `npm ls --all | grep -i native`).
8. `Makefile`: add `web-typecheck`. Do not change `web-build`.
9. Changelog fragment (`### Changed`, `#### Frontend type checking runs on TypeScript 7`; name the two aliases and `tsc6`).
