## Goal
Deploy builds (`make build-linux`) use a committed CPU profile (`pgo/prod.pprof`) through `-pgo=pgo/prod.pprof`, together with `-trimpath`; dev, test and CI builds do not use PGO. A measured A/B on a fixture-library scan shows whether PGO helped, and the profile carries no host paths or labels.

## Context the agent must read first
- `docs/proposals/2026-10-holistic/06-bleeding-edge-go-node.md` rank 8, S2 (the `GO_BUILD_FLAGS`/`GO_LDFLAGS` variables from 06-P3), §5 P12, §7 Q3.
- https://go.dev/doc/pgo (merging profiles with `go tool pprof -proto a.pprof b.pprof > merged.pprof`; `-pgo=off|auto|<path>`).
- `Makefile` `build-linux` as left by 06-P3, `Makefile.local.example` `deploy`, `docs/BUILD_TAGS_GUIDE.md`.
- Memory-derived constraint (do not rely on it from memory, check): CI never fetches Git LFS and the LFS budget is exhausted, so the profile must be a plain committed file. `git check-attr filter pgo/prod.pprof` must print `unspecified`.
- Mac note: a changed profile invalidates the build cache for that build mode, and Go build caches have filled the Mac disk before: keep PGO off for dev, test and CI.

## Steps
1. **Profiles come from the owner; you never touch production.** If `pgo/` has no input and the task did not give you profile files, write `pgo/README.md` with the capture recipe (below), stop, and report `BLOCKED: needs profiles`. The recipe for the owner: with 06-P3 deployed and `ABK_PPROF_ADDR=localhost:6060` set via the drop-in, port-forward over ssh, and during real work (a library scan, a dedup run, an identification run, each at least 60 s) run `curl -o scan.pprof 'http://localhost:6060/debug/pprof/profile?seconds=60'` (same for the others). The binary must be the `-trimpath` build from 06-P3.
2. **Merge:** `go tool pprof -proto scan.pprof dedup.pprof ident.pprof > pgo/prod.pprof`. Keep it under 5 MB; if larger, report before committing.
3. **Public-repo scrub, mandatory before the first `git add`:**
   - `go tool pprof -raw pgo/prod.pprof | grep -nE '/Users/|/home/|/root/|/var/lib/|C:\\'` must print nothing (host paths mean the binary was not built with `-trimpath`; stop and ask for a new capture).
   - `go tool pprof -raw pgo/prod.pprof | grep -n -i 'label'` : if the profile carries pprof label values (Go 1.27 adds goroutine labels), read them; any value that looks like a book title, author, file path or id means **do not commit**; report instead.
   - `go tool pprof -top pgo/prod.pprof | head -30` is a sanity check that the hot functions are this repo's, not noise.
4. **Makefile.** Add `GO_PGO_FLAGS := -pgo=pgo/prod.pprof` next to the 06-P3 variables and use it only in deploy targets (`build-linux`). All other targets must pass nothing (the default `-pgo=auto` looks for `default.pgo` in the main package directory, which does not exist; do **not** create a file with that name).
5. **A/B on a fixture library.** Build twice with the same tags and `-trimpath`, once with `-pgo=pgo/prod.pprof` and once with `-pgo=off`. Run the same operation (a scan of a fixture library, and the dedup bench if `make build-bench` covers it) 5 times each, alternating, on an otherwise idle machine; record median wall time and CPU seconds. Also record binary size (stack traces and inlining change with PGO). **If the PGO median is not better, or any test fails, do not merge**: report the numbers and let the owner decide.
6. `pgo/README.md` (Markdown header required): capture date, binary version (`git describe`), the three operations profiled, the scrub commands from Step 3, 'refresh quarterly', and 'never commit a profile from a binary built without -trimpath'.
7. `docs/BUILD_TAGS_GUIDE.md`: a short PGO section (deploy builds only, how to rebuild with `-pgo=off`).
8. Changelog fragment (`### Changed`, `#### Deploy builds use a committed PGO profile`).

## Tests
- `make -n build-linux | grep -c -- '-pgo=pgo/prod.pprof'` prints 1 and `make -n build build-api | grep -c pgo` prints 0.
- A real `make build-linux` (needs the musl cross compiler) or, if unavailable, `go build -trimpath -pgo=pgo/prod.pprof -tags "pprof" -o /dev/null .` on the host.
- `go build -pgo=off ./...` still works.
- `go test -short -count=1 ./...` on the PGO build's source is unchanged by PGO; run `make ci`.
- The A/B from Step 5, numbers in the PR body.

## Acceptance
- [ ] `git check-attr filter pgo/prod.pprof` prints `unspecified`; `ls -l pgo/prod.pprof` is under 5 MB.
- [ ] The Step-3 scrub commands print nothing alarming (paste the outputs).
- [ ] `grep -rn 'pgo' Makefile` shows PGO only on deploy targets.
- [ ] No file named `default.pgo` exists anywhere (`git ls-files | grep -c default.pgo` prints 0).
- [ ] A/B medians and binary sizes are in the PR body, and PGO is not slower.

## Rollback
Build with `-pgo=off` (or `git revert`). A bad profile cannot affect correctness, only speed; the rollback is a rebuild and redeploy.
