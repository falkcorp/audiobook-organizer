## Goal
After this PR a run that hits its deadline is recorded as `timed_out`, not `canceled`: the
v3 record says `timed_out`, the v2 mirror row still reads `canceled` with the `timeout:`
message prefix (so the previous binary stays correct), `operations_failed_total` and
`audiobook_organizer_ops_runs_total{outcome="timed_out"}` both move, and the
`ops.zombies` gauge reports the registry's zombie count (05-PR3). The dead `"timeout"` case in
`recordRunMetrics` is gone.

## Spec conflict this brief resolves (read first)
The upstream PR 2 brief creates `internal/operations/registry/otel_metrics.go` and names the
instruments `ops.runs{def,outcome}` -> `ops_runs_total`. 11 section 3.7 supersedes it
(`implementation-briefs.md` is explicitly "follow 11 if so"): the instruments live in
**`internal/opsmetrics`** (built by 11 PR 4), are named `audiobook_organizer.ops.*`, label by
**`def_id`** (not `def`), and use the outcome set `{completed, failed, canceled, timed_out, dropped}`.
11 PR 4 already emits `ops.runs` and `ops.run.duration` from `worker.go`/`registry.go`. So this PR does **not**
create `otel_metrics.go` and does not create instruments; it changes what is recorded. Also: 11
does not list an `interrupted` outcome, and the code comment at `worker.go:661-667` says an
interrupted run is a pause whose resumed attempt reports its own outcome; keep that. Only
`dropped` (an `interrupted_dropped` terminal) is newly counted. Record both points as spec corrections in the report.
