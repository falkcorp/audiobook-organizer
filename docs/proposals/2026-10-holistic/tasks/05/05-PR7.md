## Design decisions made in this brief
1. **Ledger universe at startup.** Because some plugins register only in `PostInit` when their dependencies exist (a Deluge client, an enabled iTunes service), checking the ledger against the live registry would refuse to boot a correctly configured server that simply has no Deluge. The startup check therefore resolves each ledger ID against the union of: the live registry's defs and aliases; the **static** plugin `OperationDefs()` lists (the same five the existing test enumerates, which are dependency-free); native v3 bundles built with zero `Deps`; and `opscatalog` tombstones. An ID in none of them is a startup error. This is stricter than today's test only in that it also runs in production. State this in the PR body.
2. **Where the check runs.** `opRegistrationGate` runs before `container.Start` and cannot see PostInit registrations. Add a second call, `s.opCatalogGate()`, in `Start` immediately **after** `s.container.Start(...)` succeeds, and keep the first gate unchanged.
3. **Retired IDs move to the catalog.** `retiredOpIDs` (`op_id_aliases_test.go:53`) becomes `opscatalog.Tombstones` (`internal/opscatalog/tombstones.go`); the test imports it. Census PRs (04 P2, P12 and the P4x twins) append to the same map, which is why it must be a plain `map[string]string` with a reason per ID.
4. **Embedding the ledger.** `op_ids.golden` stays at `internal/server/testdata/` (moving it breaks the test path and every census PR that appends to it). Add `internal/server/op_ledger_embed.go` with `//go:embed testdata/op_ids.golden` and pass the bytes to `opscatalog.ParseLedger`.
5. **oplint dependency.** Adding `golang.org/x/tools` is a new `go.mod` requirement. Merge order for `go.mod`/`go.sum` (08 section 4): 01 P2, 11 PR 2, **this PR (adds x/tools)**, 05-PR8, 01 P75, 07 F1; each is a trivial `go mod tidy` rebase. Declare it as a `tool` directive if the repo's Go version supports it, so it stays out of the server binary's import graph; either way run `go build ./... && go mod tidy` and check the server binary does not link it (`go list -deps . | grep x/tools` empty).

## API (`internal/opscatalog`)

// Deps is the set of narrow capability interfaces the catalog builds each
// bundle's own Deps from. It is constructed once in internal/server from the

// type assertion (sdk-api.md 11.1). Never database.Store.
type Deps struct { /* narrow interfaces; grows with each port wave */ }

// All is the only list of bundles linked into the binary. cmd/server imports

// per package as the port waves land.

// Tombstones are ledger IDs that deliberately resolve to no op, each with the
// reason no FormerIDs alias points anywhere (moved from op_id_aliases_test.go).

// ParseLedger returns the IDs in an op_ids.golden body (comments and blank
// lines skipped; same rules as readOpIDLedger).
func ParseLedger(b []byte) []string

// Universe is every ID the process can resolve: live registry defs and aliases,
// static plugin OperationDefs, native bundle defs, FormerIDs, tombstones.
type Universe struct{ /* set of string */ }
func BuildUniverse(live []registry.OperationDef, aliases map[string]string,
	static [][]registry.OperationDef, bundles []ops.Bundle) Universe

## oplint rules (`go/analysis`, run on `./...`)
A type-aware analyzer (`golang.org/x/tools/go/analysis`), using `go/types` information, not name matching on strings:
1. **Unbundled def.** A package-level value built by `ops.Task`, `ops.Batch`, `ops.Fixer` or `ops.Pipeline` that is not reachable from the same package's `Ops(Deps) ops.Bundle` function.
2. **Unregistered bundle.** A package that defines `Ops(...) ops.Bundle` but is not referenced from `opscatalog.All` (check through the type-checked references in `internal/opscatalog/catalog.go`).
3. **Writer bypass.** Inside a function literal assigned to the `Run`, `Item`, `Apply` or `AfterApply` field of an `ops.*Spec` composite literal (and any function it calls within the same package, one level deep), a call to a method whose receiver type is declared in `internal/database` (the `Store` interfaces or `*PebbleStore`) and whose name starts with one of `Create`, `Update`, `Delete`, `Set`, `Modify`, `Upsert`, `Insert`, `Put`, `Add`, `Remove`, `Save`, `Mark`, `Record`, `Repoint`, `Merge`. Allowed only with a `//oplint:allow <reason>` comment on the call line; the reason is required. Keep the prefix list in a single table at the top of `analyzer.go` so it can be tuned; report the count of findings on the current tree in the PR body (expect none, because no native def exists yet; run the analyzer over `internal/plugins/...` as a sanity probe and report the number it would flag in v2 code, labeled informational).
4. **`database.Store` in `Deps`.** A struct named `Deps` (or any struct passed to an `Ops` function) with a field whose type is, or embeds, `database.Store`; also a closure-captured value of that type inside a definition (R21).
5. **`Sequential("")`.** An empty or whitespace-only reason string.
6. **Missing `Help`.** A warning (not an error) when `Common.Help` is empty.
7. **`Deletes(...)`.** Any use of `ops.Deletes` or `rc.Deleter()` is reported for owner review (diagnostic category `owner-review`), never silently allowed.
The analyzer must not report in `_test.go` files or under `pkg/ops/opstest`.
