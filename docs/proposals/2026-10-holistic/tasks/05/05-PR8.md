## Goal
After this PR a definition declares its timer in exactly one place (`ops.Schedule`) and the
existing `TaskScheduler` runs it, using the same durable interval clock and daily clock it uses
today, plus a new cron evaluator for `ops.Cron`. Un-ported ops keep their `TaskDefinition`
untouched. A declared cron that has never run on a timer stays disabled and is listed as
"declared, not active". A scheduled writer runs as a Preview unless its schedule says `.Live()`.
The three names for one op (def id, task name, legacy label) stop being three for any op ported
afterwards.

## API

```go
// internal/scheduler/cron.go
package scheduler

// CronSpec is a parsed 5-field expression.
type CronSpec struct{ /* minute, hour, dom, month, dow bitsets; dom/dow OR rule as in standard cron */ }

// ParseCron parses "m h dom mon dow". It returns an error naming the field for
// anything it does not accept. Supported: "*", "a", "a-b", "a,b,c", "*/n", "a-b/n".
// Not supported (error): names (JAN, MON), "?", "L", "W", "#", seconds, years,
// and macros such as @daily.
func ParseCron(expr string) (CronSpec, error)

// Next returns the first fire time strictly after `after`, in loc, or the zero
// time and false if none exists within 5 years. DST rules: a time that does not
// exist (spring forward) fires at the first valid time after the gap; a time
// that occurs twice (fall back) fires once, on the first occurrence.
func (c CronSpec) Next(after time.Time, loc *time.Location) (time.Time, bool)

// Prev returns the most recent fire time at or before `at` (used for missed-fire detection).
func (c CronSpec) Prev(at time.Time, loc *time.Location) (time.Time, bool)
```

```go
// internal/scheduler/v3_schedule.go

// RegisterSchedules turns every definition that declares an ops.Schedule into
// scheduler state, keyed by the def ID (there is no second name). It is called
// once at startup with the catalog's definitions. A definition without a
// Schedule is ignored. A definition whose Schedule is Disabled (Step 3) is
// recorded and reported but never fires.
func (ts *TaskScheduler) RegisterSchedules(defs []ops.Definition) error

// NextFire reports when a registered definition will next fire (for
// GET /api/v3/ops/defs in 05-PR9), or false if it is manual, disabled, or
// its config gate (Schedule.When) is currently off.
func (ts *TaskScheduler) NextFire(defID string) (time.Time, bool)

// ScheduleStatus is the API-facing view (also used by the tasks page).
type ScheduleStatus struct {
	DefID    string
	Kind     string // "every" | "daily_at" | "cron" | "window" | "disabled"
	Active   bool   // false for "declared, not active"
	Live     bool   // schedule says .Live()
	LastFire *time.Time
	NextFire *time.Time
	Missed   int64
}
func (ts *TaskScheduler) ScheduleStatuses() []ScheduleStatus
```

Mapping from `ops.Schedule` to the existing clocks (no new timer mechanism is introduced):
- `Every(d)`: the durable interval clock (`claimIntervalRun`), key = the def ID.
- `DailyAt("HH:MM")`: `daily_at.go` (`nextDailyAt`, `claimDailyAtRun`), server-local zone as today.
- `Cron(expr)`: the new evaluator; a due check each poll tick (use `intervalPollFor` for the poll period); the last-fire stamp goes through the same durable stamp as the interval clock.
- `InMaintenanceWindow(order)`: appended to `maintenanceOrder` at position `order` relative to other declared orders (stable, ties broken by def ID); runs when the maintenance window pass reaches it, exactly as a `TaskDefinition` with `RunInMaintenanceWindow` does today.
- `OnStart()`: the `RunOnStart` behaviour.
- `When(func() bool)`: re-read each tick (the `IsEnabled` behaviour); a false gate means "not active right now", not "disabled".
- `Params(p)`: the params for scheduled runs. `Live()` / `Preview()`: see D8 below.

## Steps
1. Verify dependencies: `grep -n 'file-integrity-check' internal/scheduler/maintenance.go` (04 P1) and `ls pkg/ops internal/opscatalog`. Missing means BLOCKED; say which.
2. Implement `cron.go` and its table tests (Tests section).
3. **Disabled rule (F1, D24).** For a definition adapted from v2 whose `OperationDef.Schedule` cron string has no `TaskDefinition` that enqueues it (decide with the same parse as the F1 command: cross-join `Schedule` values against `EnqueueOp` targets and `taskV2DefIDs` values in `tasks.go`/`maintenance.go`), register a `ScheduleStatus{Kind: "disabled", Active: false}` and never fire it. Do **not** invent a TaskDefinition for the 12 D24 defs; they stay off and show as "declared, not active". The two D23 checks already have TaskDefinitions from 04 P1 and are therefore not "disabled"; their cadence is kept as it runs.
4. **Seed the clock on first load (correction 4).** When `GetSchedV3(defID)` returns no record and the def has a legacy task name in `legacyTaskNames` (a frozen copy of the reverse of `taskV2DefIDs`, created in this PR so removing an entry from `taskV2DefIDs` later does not lose it), seed `LastFire` from `loadIntervalLastTick(legacyName)` (and the daily stamp for `DailyAt` tasks) before computing the next fire. Test: a def ported from `library_size_refresh` does not fire at once when the old key says it ran 10 minutes ago.
5. **D8.** The scheduler passes `mode` from the schedule, never from a default: a scheduled run of a def whose `Effects` write is enqueued as **Live** only when `Schedule.Live()` was declared; otherwise as Preview. `ValidateCatalog` refuses a scheduled writer that declares neither `.Live()` nor `.Preview()`. Ported schedules copy what the task does today (if today's TriggerFn sends params that make it write, the port declares `.Live()`; if it sends `{}` and the op defaults to dry-run, it declares `.Preview()` and the PR body says so). The v3 scheduled-writer mode check also applies to adapted v2 defs whose `Schedule` fires through this scheduler: they run exactly as today (their `TriggerFn` is unchanged).
6. **Coalescing and missed fires.** A schedule that fires while the def's previous run is queued or running coalesces into it (as v2's cron dedupe, `registry.go:848`). Missed fires (process down across one or more due times) are counted in `ops_schedule_missed` and **at most one** catch-up run is enqueued. Record `ops_schedule_lag` (fire time minus due time) at each fire. Both are OTel instruments from 11 section 3.7, created by 11 PR 4 in `internal/opsmetrics`: `audiobook_organizer.ops.schedule_lag` (histogram, unit `s`, view in `internal/telemetry/views.go`, attribute `def_id`) and `audiobook_organizer.ops.schedule_missed` (counter, attribute `def_id`). Do not add `client_golang` series.
7. `PutSchedV3` after every fire and every config-gate edge; the record holds last fire, next fire, last run id, missed count.
8. Add `cadence.golden` and its test (below) and run it on `origin/main` first so the committed golden is the pre-change behaviour.

Must NOT change: any existing `TaskDefinition`'s behaviour (the golden test proves it); the interval clock key names or format; `daily_at.go` semantics; `library_scan`'s tasks and the `library.scan` key; the maintenance-window order of existing tasks.
