## Goal
After this PR a canceled, timed-out, watchdog-killed or abandoned run can no longer write
through the Repairs writer, and its exclusive `ConcurrencyKey` and declared write set stay held
until its goroutine really returns, so a second run of the same def cannot overlap a zombie.
The Repairs apply loop checks cancel before every row, not only between partitions. This stops
the 2026-10-01 shape (an apply kept retiring books after Cancel until a restart). The worker
slot is still freed after the 5 s grace so the pool does not shrink, and the v2 row still
becomes terminal at abandonment exactly as today (the C-3 fix must survive).

## Steps

1. **Add `internal/operations/registry/fence.go`.** Exact API:

```go
package registry

import (
	"context"
	"errors"
	"sync/atomic"
)

// ErrFenced is returned by every write path of a run whose fence was revoked
// (user cancel, timeout, watchdog kill, quiesce, shutdown, abandonment, lost
// stand-down lease). The write it guards was not made.
var ErrFenced = errors.New("registry: run is fenced (canceled, abandoned or lease lost); write refused")

type fenceState struct {
	epoch   atomic.Uint64
	revoked atomic.Bool
}

// Fence is a revocable write permit for one run attempt. The zero Fence
// (no registry, tests, direct callers) is never revoked.
type Fence struct{ st *fenceState }

func newFence(epoch uint64) Fence
func (f Fence) Epoch() uint64
func (f Fence) Revoked() bool
// Check returns nil while the permit is valid and ErrFenced after revoke.
func (f Fence) Check() error
func (f Fence) revoke() // idempotent; unexported, only the registry revokes

type fenceKey struct{}
func WithFence(ctx context.Context, f Fence) context.Context
// FenceFromContext returns the run's fence, or the zero Fence when absent.
func FenceFromContext(ctx context.Context) Fence
```

   05-PR5 moves this file into `internal/operations/opswriter/fence.go`; keep it free of registry-private imports so the move is a rename.

2. **Install and revoke the fence in `executeRun`.** After the decorator at `:246`, create `fence := newFence(1)` and `runCtx = WithFence(runCtx, fence)`; store it on the handle (`:276-286`). Revoke it **before** the context is canceled on each of these paths (order matters: a goroutine that checks the fence after it sees ctx.Done must already see it revoked):
   - `Registry.Cancel` (`:1126`): revoke, then `h.userCanceled.Store(true)`, then `cancelIfActive`.
   - timeout: the `context.WithTimeout` at `:243` fires with no code of ours running, so revoke from the select at `:507-519` as soon as `<-runCtx.Done()` is observed, before the grace wait. Because a deadline can pass while the goroutine is mid-write, that interval is a known gap of at most one scheduler tick; say so in a code comment, and state it in the report.
   - watchdog kill (`watchdog.go` calls `h.cancelIfActive()`): revoke inside `cancelIfActive` / `cancelWithCause` themselves so every cancel route revokes, then drop the explicit calls if redundant. `cancelWithCause` is also what `Shutdown` uses.
   - stand-down quiesce and `AcquireScanStandDown`: they also go through the handle cancel, so they are covered by the same change.
   - lost stand-down lease: in `RenewScanStandDown` (`scan_standdown.go:230`), when it returns false for a holder that has a handle, revoke that handle's fence.
