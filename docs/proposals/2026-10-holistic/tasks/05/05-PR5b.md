## Goal
After this PR a resumed Fixer apply reports a row "already applied" (marked, listed in
`FixerResult.Applied`, handed to `AfterApply`, not written again) only when the store holds
THIS row's apply marker: a per-row record (`opv3:rowmark:<opID>:<rowID>`) the run wrote when
that row's own `Apply` returned nil, in any attempt, naming the history `Apply`'s writes
recorded -- and all of that history still stands (no journal row voided or reverted, or
followed by a later journal row of its book on what it wrote; every metadata batch still
the newest history on every field it wrote, whatever wrote after it, and never undone). A row whose current values equal
`Proposed` because someone else made the same change between the attempts has no marker
and is skipped as `changed_since_plan`, not counted as the fixer's own -- also when the run
wrote ANOTHER row of the same book or book_file. Today (05-PR5) that case is
indistinguishable and is reported applied; the comment in `pkg/ops/fixer.go` `applyRow` says
so and points here.

**Revised 2026-10-14 (review of #4017).** The first cut gathered evidence per SUBJECT (any
history of the run for each of the row's books and book_files). That cannot meet this Goal:
two rows of one book (title, then publisher), the first written and the second parked, plus
a foreign edit of the publisher, made the second row look like the run's own. Evidence is
now per ROW, as above; the Steps and Tests below describe that.

## Steps
1. Measure the reads first: for a book with more than 100 history rows, does
   `GetBookChangeHistory` return the rows a check needs? It truncates by key (field name),
   not by age, and drops undecodable rows silently, so the check reads the uncapped
   `PebbleStore.ReadBookChangeHistory`, which also counts undecodable rows (the check
   then fails closed).
2. Per-row evidence. `applyRow`, after `Apply` returned nil, calls
   `w.MarkRowApplied(irc.Context(), planned.ID)`. Each Writer write notes what it recorded
   on the item's context (`ops.NoteHistory`): `ModifyBook` its metadata batch
   `(book, batch id)`, every journal row (`ModifyBookFile`, `RepointBookFile`,
   `ModifyBookAuthors`, `Effect`) its id, minted by the Writer. The marker
   (`opv3:rowmark:<opID>:<rowID>`) names exactly those. `RowApplied(rowID)` is true only
   when the row's own marker exists (from any attempt: a marker exists only because this
   run's `Apply` for that row returned nil) and everything it names stands: each journal row
   still under the op id, not `Voided`, `RevertedAt` nil; each batch still in its book's
   history with no `undo` row in the batch (undo-last-apply) and none at or after it on a
   field it wrote (single-field undo, operation revert). A crash between `Apply`'s last
   write and the marker loses only the evidence: the resume skips the row as
   `changed_since_plan` and never writes it twice.
3. `applyRow`: `irc.Resumed() && refusal == "" && alreadyApplied(planned, fresh) && applied`,
   with `applied` from `w.RowApplied(irc.Context(), planned.ID)`; a read error is the item's
   error (fail, not "applied"). `Row.Subjects` plays no part.
4. The marker store and the journal point read are new narrow capabilities in
   `internal/database` (their own file, never on `Store`).
5. Wire the capabilities in `newV3Writer`. `repairs.Writer` wraps `opswriter` and does not
   implement `ops.Writer`; its surface test is unchanged.
6. Deadcode: run `make lint-deadcode-ratchet`. New identifiers reachable only through the v3
   runner are unreachable until 05-PR7; do not add them to the baseline without the owner's
   approval (05-PR5 needed two). Prefer placing the reads where a reachable caller already
   exists, and report every new name.
