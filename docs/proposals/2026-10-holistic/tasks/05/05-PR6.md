## Goal
After this PR any def written against `pkg/ops` can be tested with one line,
`opstest.Conformance(t, def, params)`, which proves: preview writes nothing; history rows
follow their writes; nothing is written after the fence is revoked; a crash followed by a
resume processes every item at least once and re-runs no chunk the ledger recorded; items of a
partition run on one worker in source order; progress is monotone; and it all holds under `-race`
with at least 4 workers and `ChunkSize` in {1, 3, default}. Each fault injector has a
deliberately broken def that it catches, so a green result means something. This replaces the
16 hand-written fake reporters that silently lack the production reporter's side interfaces (F21).

## API to implement (copied from `sdk-api.md` section 12)

```go
package opstest

// World is an in-memory store + fake clock + seeded scheduler.
func NewWorld(t testing.TB, opts ...WorldOpt) *World

func (w *World) Books() *FakeBooks // implements the read interfaces ops use
func (w *World) Run(def ops.Definition, params any, opts ...RunOpt) *Outcome

type RunOpt func(*runCfg)

func Live() RunOpt                         // default is Preview, as in prod
func Seed(n int64) RunOpt                  // completion order of concurrent items
func Workers(n int) RunOpt                 // default GOMAXPROCS, never 1
func ChunkSize(n int) RunOpt               // overrides the def's ChunkSize (Conformance also runs 1, 3 and the default)
func CancelAt(item int) RunOpt             // cancel when item n starts
func CrashAt(item int) RunOpt              // stop the world after item n; Outcome.Resume() continues
func CrashMidChunk(chunk, item int) RunOpt // stop the world while chunk c is leased and item i of it is done;
                                           // Resume() must re-run chunk c from its first item, never re-run
                                           // any chunk the ledger recorded, run every item >= 1 time and the
                                           // items of chunk c <= 2 times, and leave Done == Total
func InsertBelowCursor(item any) RunOpt    // proves an AppendOnly claim or fails it
func AbandonAt(item int) RunOpt            // item goroutine ignores ctx; asserts fenced writes
func LoseLeaseAt(item int) RunOpt          // the scan stand-down lease, not a chunk lease

type Outcome struct {
	State    state.V3            // the v3 state: package internal/operations/state, created by 05-PR4 (read it first); the proposal writes state.State
	Result   json.RawMessage
	Writes   []WriteRecord       // in commit order
	History  []HistoryRow        // in commit order
	Intents  []Intent            // unresolved at end
	Progress []ops.ProgressSnapshot
	Plan     []ops.Row           // Fixer preview rows / recorded intents
}

func (o *Outcome) Resume(opts ...RunOpt) *Outcome

// Assertions every op gets for free by calling opstest.Conformance(t, def, params):
//   - Preview performs zero writes;
//   - every History row follows its Write (ledger-after-write);
//   - no Write after the fence is revoked (CancelAt, AbandonAt, LoseLeaseAt);
//   - crash + resume (CrashAt and CrashMidChunk at several chunks) processes
//     every item at least once and re-runs no chunk the ledger recorded;
//     with PartitionBy, every item of one partition ran on one worker in
//     source order; for AppendOnly, InsertBelowCursor fails the claim;
//   - progress Done is monotone and ends equal to Total when Total is known;
//     Chunks.Done ends equal to Chunks.Total;
//   - runs under -race with Workers >= 4 and ChunkSize in {1, 3, default}.
func Conformance(t *testing.T, def ops.Definition, params any, opts ...ConformanceOpt)
```

## Fault semantics (precise, so two implementations agree)
- `CrashAt(item n)`: the world stops (all goroutines released, no further store writes accepted, buffered chunk counters discarded) immediately after the item with global start index n **returns**. `Outcome.Resume()` starts a new attempt of the **same op id** over the surviving fake store (snapshot, ledger, checkpoint, intents, writes). Expected: every item at least once overall; chunks the ledger had recorded before the crash are not leased again.
- `CrashMidChunk(chunk c, item i)`: the world stops while chunk `c` is leased by some worker and that worker has completed item `i` (zero-based index inside the chunk) of it but not the chunk's last item. Because the ledger records only completed chunks and the buffered counters of an unfinished chunk are discarded (05-PR5), the expected outcome after `Resume()` is: chunk `c` is re-run from its first item; no chunk marked in the ledger before the crash is run again; every item of the source ran at least once; items of chunk `c` ran at most twice; every other item ran exactly once; `Progress` after resume starts at the ledger's folded count and ends `Done == Total`, `Chunks.Done == Chunks.Total`. If `c` is oversized by `PartitionBy`, `i` indexes into that oversized chunk.
- `InsertBelowCursor(item)`: while the run is in flight (an `AppendOnly` source), insert `item` into the source at a position that sorts **before** the current cursor. If the def claims `AppendOnly`, the item is skipped by a chunk-ledger resume and `Conformance` must fail with "AppendOnly claim violated: item inserted below the cursor was never processed". If the def claims `Snapshot` or `Unordered` the injection is a no-op and the test records that the claim was not tested. This is the fault for the activity-digest tier shape (F11).
- `AbandonAt(item n)`: when item n starts, its goroutine ignores `ctx` and keeps trying to write after `Cancel`; the test asserts zero committed writes after the fence revoked, the run's key held until the goroutine returns, and a second `World.Run` of the same def stays queued until then (the PR 3 behaviour, reproduced inside the harness).
- `LoseLeaseAt(item n)`: the fake scan stand-down reports the holder's lease lost when item n starts; asserts the fence is revoked and no later write commits. (It is the stand-down lease, not a chunk lease; chunk leases are never reassigned while the owner lives.)
- `CancelAt(item n)`: cancel when item n starts; asserts `Finish` runs with `Canceled == true` and the partial `Summary` equals the ledger's folded counts.
- `Seed(n)`: seeds the scheduler that decides which free worker takes the next chunk and the interleaving of item completions, using a deterministic random source and `synctest` or a controlled yield point. Same seed, same `Outcome.Writes` order.

## Conformance assertion set (one subtest each, named so a failure points at the rule)
1. `preview_writes_nothing`
2. `history_follows_write` (every `HistoryRow` has a `WriteRecord` with a smaller commit index for the same subject)
3. `no_write_after_fence` (CancelAt, AbandonAt, LoseLeaseAt)
4. `crash_resume_at_least_once` (CrashAt at 3 positions) and `crash_mid_chunk_no_completed_chunk_twice` (CrashMidChunk at the first, a middle and the last chunk)
5. `partition_one_worker_in_order` (only when `PartitionBy` is set; every partition's items observed on one worker id and in source order, and no partition straddles two chunks)
6. `append_only_claim` (only for `AppendOnly` sources)
7. `progress_monotone` (`Done`, `Failed` and counters never decrease across snapshots **including across a resume**; ends equal to `Total` when known; `Chunks.Done == Chunks.Total` at the end)
8. `idempotent_item` (run the whole source twice with `ResumeFromZero`; the second run's `Writes` produce no `Changed` fields)
9. matrix: the whole set above is repeated for `ChunkSize` in {1, 3, def default} with `Workers` = max(4, GOMAXPROCS) under `-race`.

## Steps
1. Build `World` and the fakes first. The fake `OpsV3Store` must implement the same CAS and index semantics the real one has for the methods the runner calls (`TransitionRunV3`, `CommitLedgerV3`, snapshot pages, intents); where the real store has a rule (a stale `ExpectFenceEpoch` is rejected), the fake enforces it or imports the real in-memory logic from `internal/database` if 05-PR4 exposed one. Do not write a fake that is more permissive than the store.
2. Implement `Run`/`Resume`/options and the fault hooks as injection points in the runner (a small exported interface `RunnerHooks` with `OnItemStart(chunk, itemIdx int)`, `OnItemDone(...)`, `OnChunkLeased(...)`, `OnChunkDone(...)`, `BeforeLedgerCommit()`; the production runner passes a nil hook). `RunnerHooks` also carries three test-only injection points, all nil in production: `Chunker func(items int, partitions []int) []ChunkRange` (replaces the chunking function), `LeasePolicy func(set func(chunk int) bool, next int) int` (chooses the next chunk to lease; receives the ledger's completed-set so a mutation can return a set chunk), and a `ProgressSink` option (`WithProgressSink(func(done, total int64))` on `Run`/`Resume`) that receives every progress publication so tests can assert monotonicity and so a mutation reporter can replace the runner's folding. Read 05-PR5 for the runner's chunk and ledger types first.
3. Implement `Conformance` over those hooks.
4. Write the mutation tests (Tests section). Each broken def is a tiny `ops.Batch` or `ops.Fixer` defined in `*_test.go`.
5. Run the three example defs from `examples.md` through `Conformance`.

Must NOT: sleep to order events (use hooks or a fake clock); run any case with fewer than 4 workers; import `internal/server` (the harness is a leaf package); touch production code except the hook seam in the runner (keep its cost to a nil check).

## Tests
Keep green: `go test -race ./pkg/ops/... ./internal/operations/...`.

Mutation tests in `pkg/ops/opstest/conformance_mutation_test.go`; each must run `Conformance` against the broken def with a recording `testing.TB` (an interface wrapper capturing `Errorf`) and assert the **named subtest fails** while a correct twin passes:
- `TestCatches_WriteAfterCancel`: an `Item` that keeps writing after cancel through a store handle captured before the fence; fails `no_write_after_fence`.
- `TestCatches_HistoryBeforeWrite`: a def that calls `Effect` returning history rows and records its own history first; fails `history_follows_write`.
- `TestCatches_AppendOnlyLie`: a def claiming `AppendOnly` over a source that accepts inserts below the cursor; fails `append_only_claim`.
- `TestCatches_NonIdempotentItem`: an `Item` that appends to a side-effect log each time it runs; with `CrashMidChunk` the chunk's items appear twice, which is allowed up to 2 times, so the def's `Finish` result (which counts the log) differs between a clean run and a crash+resume run; fails the `idempotent_item` assertion (not any other); say so in the test comment.
- `TestCatches_PartitionStraddle`: a runner-level mutation (a `RunnerHooks.Chunker` that splits a partition across two chunks) makes two workers touch one partition concurrently; fails `partition_one_worker_in_order`.
- `TestCatches_CompletedChunkRerun`: a `RunnerHooks.LeasePolicy` that returns an already-set chunk on resume; fails `crash_mid_chunk_no_completed_chunk_twice`.
- `TestCatches_PreviewWrites`: a def that writes outside the Writer in Preview; fails `preview_writes_nothing`.
- `TestCatches_NonMonotoneProgress`: a `ProgressSink`-fed reporter that counts in-flight items into `Done` and loses them on resume; fails `progress_monotone`.
- `TestExamplesConform`: the three example defs from `examples.md` pass `Conformance` at `ChunkSize` {1, 3, default}.
- `TestSeedDeterminism`: the same seed gives byte-equal `Outcome.Writes` ordering twice.
- Commands: `go test -race -count=2 ./pkg/ops/opstest/...`; `go vet ./pkg/...`; `make ci`.
