## Goal
After this PR an author can write a Task, Batch, Fixer or Pipeline against `pkg/ops`, register
it, and run it on the existing registry executor. A Batch runs on `runtime.NumCPU()` workers by
default, is cut into chunks of 256 items leased to workers, records finished chunks in a per-run
ledger, and a resume re-leases only unfinished chunks. Writes go through a fenced `Writer`
that orders intent, write and history. An adapter registers any unchanged v2 `OperationDef` as a
v3 definition, so from this PR on there is one executor, one queue and one exclusive-key map
(the `library.scan` key is never split). **Invariant: every item is processed at least once; no
completed chunk is processed twice.**

## Resolved conflicts and gaps (spec corrections for the report)
1. **Progress across a resume.** `examples.md` says progress resumes at 512 after a crash that had 652 items done; `state-and-persistence.md` 2.1 says `Done` never goes backwards; Conformance requires monotone progress. Resolution implemented here: **a worker buffers an item's counters locally and sends them to the ledger goroutine only when the whole chunk completes.** `ProgressSnapshot.Done`, `Failed`, `Counters` and the `Summary` are exactly the ledger's folded values, so they are monotone within and across attempts; in-flight work is visible per worker (`Workers[].ItemIndex`) but is not in `Done`. A crash discards the buffered counts of in-flight chunks, which is also what makes a non-idempotent `Item` double-count visible to the harness (05-PR6).
2. **Types the SDK sketch uses but never defines** (`Priority`, `Notify`, `Trigger`, `Actor`, `Outcome`, `RunRef`, `EnqueueOpt`, `Hold`, `StageFailure`, `ErrorPolicy`, `Changed`, `EffectSpec`, `HistoryRow`, `Guard`, `Results`, `Requirement`, `SubjectType`, `Resource` constants, `Readiness`, `ServiceKey`, `BudgetRef`, `Total`). Section "Supporting types" below gives a proposed minimal shape for each; they are this PR's design, not copied from the proposal.
3. **Fence location.** 05-PR3 puts `Fence` in `internal/operations/registry/fence.go`; this PR moves it to `internal/operations/opswriter/fence.go` (a rename plus type alias `registry.Fence = opswriter.Fence` is not needed: update the importers; there are few).
4. **`DirtySet`** needs a mark epoch the 02 marker must write; that producer is 02 PR 14's concern. This PR implements the compare-and-delete reader side and documents the key shape it expects (`<prefix><subjectID>` value begins with an 8-byte big-endian epoch); 02 PR 14 owns the marker.

## Runner design to implement (`batch_runner.go`, `chunk_ledger.go`)

- **Chunking.** `Snapshot`: freeze keys at start into `opv3:snap:{op}:{page}` (10,000 keys per page via `PutSnapshotPageV3`); chunk c is the key range `[c*size, (c+1)*size)` of the frozen order. With `PartitionBy`: stable-sort keys by partition key (source order kept inside a partition), cut every `ChunkSize` items but push a boundary forward to the next partition edge; a partition larger than `ChunkSize` is one oversized chunk; store the boundaries as `[]int32` offsets via `PutChunkOffsetsV3`. `PartitionBy` requires `Snapshot` (the only exception is a `DirtySet` source, where the partition key is the unique entry key). `AppendOnly`: take `ChunkSize` items from `Pages`, lease them as a chunk `{first_key, last_key}`; the ledger records completed key ranges (merged when adjacent), not chunk numbers, so a deletion between runs cannot shift chunk membership. `Unordered`: chunks are cut from the stream; no ledger; resume restarts from zero; for `DirtySet` one 256-key page is one chunk.
- **Leases.** `Lease{Chunk, Worker, LeasedAt, Heartbeat, ItemIndex, Item}` in an in-memory table. A worker heartbeats after every item (and on `rc.Touch()`). **A lease is never reassigned while its owner goroutine is alive.** A heartbeat older than `ItemTimeout` (or `Timeout/6` when `ItemTimeout` is 0) marks the worker `Stuck` in progress and informs the watchdog; the way out is cancel or restart.
- **Ledger.** `opv3:ledger:{op}`: a bitmap (1 bit per chunk) for `Snapshot`, a merged key-range list for `AppendOnly`. A chunk is complete only when every item returned from `Item` (ok, failed-and-continued, or skipped); an error with `OnItemError: Stop` leaves the chunk incomplete. **Only one goroutine, the runner's ledger goroutine, writes the ledger.** Workers send chunk completions (with the chunk's buffered counters) on a channel; the ledger goroutine folds them and calls `CommitLedgerV3` (ledger + lease table in the checkpoint + progress snapshot in one batch) at most every 2 s, or on every completion when completions are rarer than that. Bounded: a 10,000-item run of 1 ms items commits at most one batch per 2 s (plus the final commit).
- **Counters and Label.** `rc.Count`/`rc.Skip`/the ok and failed tallies live in a per-chunk struct owned by the worker; they are merged into the ledger only on chunk completion (see "Resolved conflicts" item 1). `Label(item)` is called by the worker for its own item and stored on its lease; it reads nothing shared.
- **Resume (same op id).** Read the ledger; every chunk whose bit is unset (including those in the saved lease table) is free and is leased from its **first** item; a set chunk is never leased. Progress restarts from the ledger's folded counts. `ResumeContinue` with `Unordered` is refused by `ValidateCatalog`.
- **Cancel, pause, stand-down.** Check `ctx` and the pause gate (`pause_gate.go`) between items; the stand-down lease is renewed by the Writer on each write (as `repairs.Writer` does via `beat`). After cancel, `Finish` runs with the partial summary and `rc.Canceled()` true.
- **Workers.** Default `CPU()`; `FromParam` is clamped to `[1,max]`; the pool is bounded (`errgroup.Group` plus `SetLimit` or a semaphore); no unbounded goroutines. `Sequential(why)` must carry a non-empty reason (oplint flags `""`).
- **Fixer apply** uses the same runner with `Row.ID` as the default `PartitionBy`, `Evaluate` called again at apply time, and the fingerprint of `Row.Inputs` re-checked (mismatch gives `ErrChangedSincePlan`).
- **Terminal cleanup.** At a terminal state the snapshot, chunk offsets and ledger keys are deleted in the transition batch (05-PR4 already does this); the final counters survive in `RunRecord.Progress`.

## Writer (`internal/operations/opswriter`)
Every Writer method, in order: (1) fence check (`ErrFenced` on a revoked fence; this also covers a lost stand-down lease because PR 3 revokes the fence on lease loss), (2) in `Live` mode write the intent row (`PutIntentV3`) **before** touching the store, in `Preview` mode record the intent as a plan line and return `ErrPreview` without writing, (3) perform the write inside the store's critical section (`ModifyBook` callback) capturing "previous" there, never from the caller's earlier snapshot, (4) write the history row (`opchange:` / metadata history) **only after the write committed**, (5) `ClearIntentV3`. A crash between 2 and 5 leaves an intent; recovery lists those subjects as "may be partially applied". The Writer has no delete method. `Effect` wraps steps 1, 2 and 5 around an op-supplied function and records the history rows the function returns after it returns. No history row when no tracked field changed (open question Q7, recommended answer: no row; the intent and its clear are still recorded).

## Adapter (`v3_adapter.go`)
- `Register(r *Registry, def ops.Definition) error`: builds a registry `OperationDef` from `Common`: `ID`, `Plugin` (from the bundle), `DisplayName` = Title, `Description` = Help, `ConcurrencyKey` = Exclusive (default def ID), `DefaultPriority`, `Timeout`, `Permissions` = `[]auth.Permission{Permission}`, `Writes` from Effects, `FormerIDs`, `ResumePolicy` mapped (Continue to `ResumeRestart`, FromZero to `ResumeRestart` with a reset, Drop to `ResumeDrop`, Ask to `ResumeAsk`), `Liveness` = `LivenessRunItems` for Batch/Fixer (the runner stamps liveness per item) and `LivenessManual` for Task. The `Run` closure builds the `RC`, resolves `Mode` (Preview unless the request is Live; scheduled runs follow the schedule), and drives the kind.
- `FromV2(def registry.OperationDef) ops.Definition`: wraps an unchanged v2 def so the catalog can hold it; behaviour is unchanged. An empty v2 `Permissions` list gets `settings.manage` from 08 PR X2 at the route, not here.
- `ValidateCatalog(defs []ops.Definition, ledgerIDs []string) error` (called at startup; PR 7 wires the embedded ledger): refuses duplicate IDs, invalid schedules, `Unordered` with `ResumeContinue`, `PartitionBy` on a non-`Snapshot` source (except `DirtySet`), a Fixer without `Writes`, an empty `Permission` **on native v3 defs only** (adapted v2 defs rely on X2's default until ported), a scheduled writer with neither `.Live()` nor an explicit preview note (D8, enforced in PR 8), `Sequential("")`, and a native def with non-terminal migrated runs and no `LegacyResume`. The ledger-ID check is PR 7's; stub it with a clear error type here.
- Readiness: `Effects.NeedsReady` (`ReadyNone`, `ReadyStore` default when `Deps` hold a store interface, `ReadyIndexes`). The dispatcher holds such runs in `queued{wait_reason: ready}` until 07's readiness signal reports it; the wait is shown in progress and does not count toward `ProgressTimeout`; schedules that fire during warmup coalesce.
