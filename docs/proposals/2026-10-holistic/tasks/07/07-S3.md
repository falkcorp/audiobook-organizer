## Goal
`internal/server/indexed_store.go` wraps the store in a decorator that intercepts a handful of write methods (`CreateBook`, `UpdateBook`, `ModifyBook`, `FillBookMediaInfo`, `DeleteBook`) to enqueue search re-indexing. Everything else (tag writes, aggregate recomputes, author or series renames) already reaches the index through the store's `ChangeObserver` hooks, so there are now two mechanisms, and the decorator also hides every capability interface from plain type assertions (the 2026-07-30 incident in `internal/database/store_capability.go:14-40`). Make the observer the only mechanism and delete the decorator. After the change the server's store is the raw store, capability lookups need no `Unwrap` walk for it, and the method-count gate (below) goes down.

- `internal/server/server.go:~590` builds `indexed := &indexedStore{Store: store}; resolvedStore := database.Store(indexed)`; `server.go:597` area holds the comment that explains the wrap.
- `internal/server/server_lifecycle.go:69-110` `startSearchIndexing` ("It does NOT wrap the store"), called at line 213.
- `ChangeObserver` is declared at `internal/database/change_observer.go:22` with `BooksChanged`, `BooksNeedReindex`, `AuthorRenamed`, `SeriesRenamed`; installed by `database.AsCapability[database.ChangeObservable](s.store)` then `SetChangeObserver` at `internal/server/search_result_cache.go:42` (`initSearchResultCache`). **There is exactly one observer slot** (`PebbleStore.changeObs`, an atomic pointer): the search result cache already occupies it, so S3 must compose, not replace (see Design 1).

- `indexedStore` also provides the authorcredit capability: `AuthorityLookup` and `AwaitAuthorityLookup` at `internal/server/authority_evidence.go:236-248`, with compile-time assertions for `authorcredit.AuthoritySource` and `authorcredit.AuthorityWaiter`. ## Design (decided)
1. **Compose observers.** Replace the single `searchChangeObserver` registration by one `serverChangeObserver` in `internal/server` that implements `database.ChangeObserver` and fans out: (a) the existing result-cache behaviour (move `searchChangeObserver`'s methods unchanged into it or call it as a member), (b) `s.enqueueIndex(id, false)` for every id in `BooksChanged` and `BooksNeedReindex`, (c) author/series rename fan-out as `searchChangeObserver` does today. Observer methods must be cheap and never call back into the store (interface contract, `change_observer.go:15-21`); `enqueueIndex` is already non-blocking (bounded queue; overflow marks the book dirty for the reconciler).
2. **Install order.** The observer is installed in `NewServer` right after the store is built, before any goroutine can write, and `enqueueIndex` is a no-op while `s.indexQueue` is nil (as now), so a write between `NewServer` and `Start` is treated exactly as today (not indexed; startup reconcile seeds only missing docs; keep the comment about that gap).
3. **Authority capability relocation.** Recommended: a package-level provider in `internal/authorcredit`: `func SetAuthorityProvider(p AuthoritySource)` plus fallbacks in `AwaitAuthority` and `CurrentAuthority` that consult the store capability **first** (so test stores that implement it keep working) and the provider second. `Server` registers `s.authorityEvidence` (a small adapter exposing `AuthorityLookup` and `AwaitAuthorityLookup`) at construction and clears it on `Shutdown`. Reject the alternative of embedding the capability into a new decorator; that recreates the problem. If you find a cleaner owner-friendly route while reading `authorcredit` callers, document it in the PR and ask before taking it.
4. **Delete flag.** If `applyIndexChunk` re-derives delete-vs-reindex from the store (verify), `BooksChanged` carries no delete bit and none is needed. If it does rely on `del`, stop and report; do not guess.
5. **`Unwrap` and capability helpers.** `store_capability.go`'s doc comment names `indexedStore` as its example. Rewrite the example to say a decorator hazard class remains in general (other decorators exist; find them with `grep -rn 'func (.*) Unwrap() database.Store'`) but this specific one is gone.

## Method-count gate
"Method-count gate" means 07-G1: `TestStoreFlattenedWidth` must still pass with baseline 455 (S3 does not add Store methods) and `TestStoreReferenceCount` must pass with a baseline that S3 lowers by hand to the measured value. The PR body states both numbers before and after. If S3 would add any method to a Store role interface, stop: it is the wrong design.

## Steps
1. Re-measure the three counts; read `applyIndexChunk` and every `enqueueIndex` caller; list which Store write methods the decorator intercepted and, for each, which `notify*` hook covers it in `PebbleStore` (read `memdb_sync.go` choke points). Any write path with **no** hook is a hole: add the missing `notifyBooksChanged` call in the store (smallest correct change), not a decorator.
2. **Per-path test (required):** one test per formerly intercepted method (`CreateBook`, `UpdateBook`, `ModifyBook`, `FillBookMediaInfo`, `DeleteBook`) plus a tag-write, using a real in-memory Pebble store with the new observer and a recording queue: each produces exactly one index request for the right id (deduplicated by the worker's `seen` map, so assert "at least one, only for that id"). Add a deleted-book case that the worker removes the document.
3. Install the composed observer; delete the decorator; relocate the authority capability; fix compile errors.
4. Run the full server package tests and `internal/authorcredit`; fix tests by removing decorator references, never by weakening assertions. `-race` on `internal/server` queue tests.
5. Mutation check: comment out the `enqueueIndex` call in the observer; the per-path tests fail.
6. Lower the G1 reference baseline.
