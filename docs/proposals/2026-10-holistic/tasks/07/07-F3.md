## Design (decided)
1. **Packages.** `@tanstack/react-query@^5.104.1` dependency; `@tanstack/react-query-devtools@^5.104.1` devDependency. Commit the lockfile.
2. **Provider.** `web/src/main.tsx`: `<QueryClientProvider client={queryClient}>` inside `ErrorBoundary`, outside `BrowserRouter`. Devtools: lazy (`React.lazy`) and rendered only when `import.meta.env.DEV`. On sign-out (`AuthContext.tsx:112` path) call `queryClient.clear()` so one user's cached rows never reach the next.
3. **`web/src/lib/queryClient.ts` (new)** exports `queryClient`, `queryKeys`, and `startQuerySync()` (the SSE subscriber, called once from `main.tsx`).
   QueryClient defaults:
   | Option | Value |
   |---|---|
   | `staleTime` | 30 s |
   | `gcTime` | 5 min |
   | queries `retry` | `(count, err) => count < 1 && !is4xx(err)` (no retry on a 4xx; a 404 "no repairs endpoints" or a 403 shows at once) |
   | mutations `retry` | 0 |
   | `refetchOnWindowFocus` | false |
   | `refetchOnReconnect` | true |
   | `throwOnError` | false (errors render in place) |
   `is4xx` reads the status from the error type `api.ts` throws (`buildApiError`); check its shape first.
4. **Key conventions.** One `queryKeys` object, never inline keys. First segment is the domain (`books`, `repairs`, `review`, `ops`, `system`). Parameters object last. Id lists sorted. A key never contains a `file_path`. Required keys: `queryKeys.repairs.fixers()`, `.ownerStatus()`, `.rows(fixerId, planOpId, params)`, `queryKeys.ops.v2(operationId)`, `queryKeys.books.all()`.
5. **Reads.** Fixers, owner status and rows become `useQuery`; the `queryFn` calls the existing `api.*` function with `{ signal }` (api.ts is not edited; it already chains a signal; confirm). Rows query is `enabled` only when the lane is `active` and a fixer and plan are chosen, so an inactive lane makes no requests and polls nothing. `placeholderData: keepPreviousData` for paging.
6. **Writes and polls.** Trial, apply and owner-apply become `useMutation` (no retry, **no optimistic apply**). The returned operation id feeds an op-poll `useQuery` on `queryKeys.ops.v2(id)` with `refetchInterval: (q) => isTerminal(q.state.data) ? false : REPAIRS_POLL_INTERVAL_MS` (1500, keep the exported constant). The poll is `enabled` only while the lane is active.
7. **Invalidation after Apply.** `onSettled` of the apply mutation and the terminal poll result invalidate `['repairs','fixers']` and `['books']`. **Plan rows are not invalidated** (immutable per plan).
8. **SSE subscriber** (`startQuerySync`): `books.changed` -> `invalidateQueries({queryKey:['books']})`; `operation.status` -> `invalidateQueries({queryKey:['ops','v2', <operation id>]})` using the field confirmed in "Verified". Keep the polling (the stream gives up after 5 reconnects). Return the unsubscribe function; call it in a test.
9. **Lane logic that stays** whatever the library (do not delete): `withNewerPlan` and the `knownPlans` rule, the confirm-once `dispatch`, `dry_run:false` in `startRepairApply`, the page-size and fixer storage keys, the exported constants.
