## Steps
1. **`store_width_test.go`.** Port the A.3 program as `func flattenedMethodCount(t *testing.T, dir, iface string) int`, parsing the package directory with `go/parser` (skip `_test.go` files, exactly as A.3 does) and following embedded interfaces of the same package; an embedded interface from another package counts as one `<external:Name>` entry and the test **fails** if any appears under `Store` (the count would be incomplete). Constants: `const storeMethodBaseline = 455`. Test `TestStoreFlattenedWidth`: `n := flattenedMethodCount(t, ".", "Store")`; fail with an explanatory message only if `n > storeMethodBaseline`; if `n < storeMethodBaseline`, `t.Logf("NOTE (not a failure): Store is now %d methods; lower storeMethodBaseline in this PR", n)`. Positive controls inside the test: `flattenedMethodCount(".", "catalogStore")` must equal 130 or be positive and less than the `Store` count (do not hard-code 130; assert `0 < catalog < n`), and `n > 100` so a parse that found nothing cannot pass.
2. **Mutation check (run once locally, do not commit):** add one method to any role interface (for example `BookStore`) and confirm the test fails; remove a method and confirm it passes with the NOTE. Paste both outcomes in the PR body.
3. **`store_consumers_test.go`.** Walk `internal` and `cmd` from the repo root (find `go.mod` by walking up, as `slogGuardRepoRoot` does), skip `_test.go`, `testdata`, `vendor`, `node_modules`, directories named `mocks`, and the files `internal/database/mock_store.go`. Count, per file, lines that match `\bdatabase\.Store\b` and are not comment lines (strip lines whose first non-space characters are `//`). Constant `const storeReferenceBaseline = 31`. The test owns a table `storeReferenceKinds` mapping `file -> kind` (`assertion`, `wiring`, `testhelper`, `consumer`) for the current references so the numbers in B-decisions D2 stay checkable: 11 or 14 assertions (the 14 lines at HEAD are in `internal/plugins/metafetch/asin_backfill.go:196`, `internal/plugins/maintenance/{move_book_file_rows.go:156, repairs_ops.go:32, repoint_book_file_rows.go:231, repoint_missing_to_folder_audio.go:1218, build_folder_book_files.go:129, fs_regroup_xml.go:176, relink_stale_series_fixer.go:634}`, `internal/server/search_reconciler.go:173`, `internal/maintenance/jobs/merge_chapter_groups.go:38-39`, plus comment-carrying lines in `internal/server/maintenance_fixups.go`, `internal/dedup/engine.go`, `internal/dedup/lifecycle.go`), 13 wiring/unwrap lines, 2 test-helper signatures, about 5 genuine wide consumers (`internal/plugins/maintenance/deps.go:524`, `internal/server/provider_throttle_wire.go:38,63`, `internal/server/catalog_harvest_op.go:159`, `cmd/root.go:666`). Build the table from the real grep output; it is a classification aid, not a gate: the gate is the total.
   Test `TestStoreReferenceCount`: fails if the total exceeds `storeReferenceBaseline`; logs a NOTE if below. Positive control: the walker must visit at least 500 `.go` files.
4. Do not edit `internal/database/store.go`, any role interface or any mock. Do not add the tests to `ci/gates.txt` (07-G4 owns the manifest; `go test ./...` already runs them on all three runners).
5. Header comment of each test: say the baseline may only be lowered, by hand, in the PR that lowers the count, and name 07-S3 and 07-M14 as the PRs expected to lower the reference baseline.
