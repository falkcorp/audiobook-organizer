## Goal
Gates are scattered: `scripts/check-errcheck-ratchet.sh`, the interface-width job and `.interface-width-baseline`, `.errcheck-baseline`, and now three Go-test ratchets (G1, G2, G3). Some fail when the count falls (so a good PR goes red until someone edits a number). Do three things: (1) write the list of gates once in `ci/gates.txt`, (2) make every ratchet fail only on a rise (07-C1 did the two shell ratchets; this PR verifies and adds a test that keeps it so), (3) add a scheduled workflow that opens a PR lowering any baseline whose measured count is now lower.

## Manifest content (initial)
Commands: `errcheck` = `bash scripts/check-errcheck-ratchet.sh`; `interface-width` = `make lint-width-full` via the existing width script; `store-width` = `go test ./internal/database/ -run TestStoreFlattenedWidth -count=1`; `store-references` = `go test ./internal/database/ -run TestStoreReferenceCount -count=1`; `layering` = `go test ./internal/arch/ -count=1`; `appconfig-reads` = `go test ./internal/config/ -run TestAppConfigDirectReadRatchet -count=1`; `slog-guard` = `go test ./internal/logger/ -run TestGuard_NoDirectSlogCalls -count=1`. Gates: `errcheck` (ratchet, `.errcheck-baseline`), `interface-width` (ratchet, `.interface-width-baseline`), `store-width` (ratchet; baseline is a Go constant in `internal/database/store_width_test.go`), `store-references` (same file family), `layering` (check; `internal/arch`), `appconfig-reads` (ratchet; constant in `internal/config/appconfig_reads_test.go`), `slog-guard` (check; `internal/logger`). Go-constant baselines cannot be rewritten by a bot safely, so the manifest marks them `kind=ratchet-const`; for those the bot only **opens an issue comment in the PR body of its run** listing "measured N < baseline M, lower the constant", and the lowering is done by hand in the PR that caused the drop (D47 / G1-G3 headers already say so). Only the two file-based baselines are auto-rewritten.

## Steps
1. Create `ci/gates.txt` and `run_gates.py` (stdlib only). Exit codes: 0 all pass; 1 any failure; 2 manifest error.
2. Add the `--measure` flag to the errcheck script; confirm the interface-width gate can print its count (`lint-width-full` already does).
3. `--lower` for file baselines: measure, and if `measured < baseline` write the new number; never write a higher number (assert in code and in the test).
4. Write `ratchet-lower.yml` modelled on `todo-collect.yml`: pinned SHAs, `permissions: contents: write, pull-requests: write`, a bot branch name `bot/lower-ratchet-baselines`, rebase-only merge note in the PR body, and a step that exits cleanly (no PR) when nothing changed.
5. In `ci.yml` keep the existing required-check names (`Errcheck Ratchet`, `Interface Width`) by leaving thin jobs that call `make lint-errcheck-ratchet` and `make lint-width-full`, and add the new `Gates` job. Say in the PR body that the owner may later collapse the names; do not edit `.github/branch-protection.json`.
6. Add a unit test that fails if any ratchet script in `ci/gates.txt` still contains a "went down" failure branch (grep for the old message text in the two scripts) so the one-way rule cannot regress.
