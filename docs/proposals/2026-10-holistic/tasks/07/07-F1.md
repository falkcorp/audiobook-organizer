## Goal
`web/src/services/api.ts` and `web/src/types/index.ts` hand-copy Go response shapes, so a renamed JSON field compiles on both sides and fails at runtime. Generate the TypeScript from the Go structs so a rename is a compile error in the frontend. Start with the types the server actually serialises to the SPA, in a bounded set, and make drift a CI failure.

## Verified at HEAD (`93a9b745f`)
- `tygo` v0.2.21 is resolvable (`go list -m -versions github.com/gzuidhof/tygo` lists it); no `tool` directive exists in `go.mod` today (`grep -n '^tool' go.mod` prints nothing; `go 1.27.0`).
- `web/src/types/` holds `index.ts` only; there is no `generated/` directory.
- Handler request/response structs live next to handlers under `internal/server/handlers/*` and in domain packages such as `internal/repairs` (`internal/repairs/engine.go:63-69` has `json:"fixer_id"` style tags).

## Design (decided)
- Add tygo as a **Go 1.24+ tool dependency**: `go get -tool github.com/gzuidhof/tygo@v0.2.21` (this adds a `tool` line to `go.mod`); run it as `go tool tygo generate`. No global install, no CI download step.
- Config in `tygo.yaml` at the repo root, one `packages:` entry per Go package, `output_path: web/src/types/generated/<pkg>.ts`, `type_mappings` for `time.Time: string`, `json.RawMessage: unknown`, `uuid`-like types `string`. Generated files carry tygo's "generated, do not edit" banner.
- **Initial package set (bounded):** `internal/repairs`, the DTO structs of `internal/server/handlers/system`, `internal/server/handlers/operations` (v2 operation shapes) and the `database` core projections the SPA reads (`BookCore`, `BookFileCore`, in `internal/database/bookcore.go` and `bookfilecore.go`). Add others in later PRs, each with a deleted hand copy.
- **Freshness gate:** a script `scripts/ci/check_generated_types.sh` runs `go tool tygo generate` and `git diff --exit-code web/src/types/generated`; it is listed in `ci/gates.txt` (kind `check`).
- **Contract golden tests:** for each generated package, a Go test marshals a fully-populated sample of each exported DTO and compares to a checked-in JSON golden under `testdata/`; a vitest test in `web/src/types/generated/contract.test.ts` loads the same golden JSON and assigns it to the generated type (`satisfies`), so Go-side and TS-side shape agree. Keep sample data synthetic.
- Replace hand-written duplicates of the generated types in `api.ts` / `types/index.ts` by re-exporting the generated type (`export type { RepairFixer } from '../types/generated/repairs'`) so no import site changes. Delete the hand copy in the same PR.

## Steps
1. Confirm T2 (the tier-2 deletions) is on `main` so no deleted struct is generated; list the structs generated and the hand copies removed.
2. Add the tool, config and the first package (`internal/repairs`); generate; make the SPA compile against it (`(cd web && npx tsc --noEmit)`).
3. Add the other packages one at a time, each in its own commit.
4. Write the freshness script and the golden tests; add to the gate manifest.
5. Mutation check (local): rename a JSON tag on a generated struct; the freshness check fails, and after regenerating, `tsc` fails at the usage sites.

## Tests
- `go tool tygo generate && git diff --exit-code web/src/types/generated`
- `go test` for the golden tests, `npx vitest run web/src/types`, `(cd web && npx tsc --noEmit)`, `npm run build --prefix web`
- `go build ./...` (the `tool` directive must not break the build)

## Guardrails
- Do not hand-edit generated files. Do not generate types for structs that carry secrets (tokens, password hashes) even if exported; list any you skip.
- Do not touch `internal/writeback/`.
- Worktree: `git worktree add ../aorg-07-f1 -b feat/07-f1-tygo-types origin/main`, then `npm ci --prefix web`.
- Headers on hand-written files (generated files carry tygo's banner; keep the repo header lint passing by adding the generated directory to its exclusion list if the lint complains; say so).
- Commit: `feat(web): generate TypeScript types from Go with tygo`; named files only.

## Report format
Packages generated, hand copies deleted (count), gate added, mutation outcome, anything unverified (for example a Go type tygo cannot express).
