## Goal
Today startup failure handling is ad hoc: some steps return an error and abort, some log and continue, and which is which lives in the reader's head. Make the classification a single reviewed table in code, so a failure in a *degraded* step leaves the server up and visible in `/health` `degraded[]`, and a failure in a *fatal* step stops the process before it serves.

## Steps
1. Read every step in its current code; record in the PR body, per step, what happens today on failure (abort, log-and-continue, panic). Where today's behaviour differs from the table, say which way it changes.
2. Write the table, `Run`, and an **AST scan test** in `internal/startup`: walk `cmd` and `internal` non-test files with `go/parser`, collect the first argument of every call whose selector name is `Run` on a `*startup.Steps` value; each must be a string literal (a non-literal fails: "step names must be literals"); fail if a literal is missing from `Table` and if a `Table` row is never referenced (no dead rows).
3. Convert the call sites. The degraded set is a mutex-protected sorted set of tokens; `/health` renders it as the `degraded` array (merged with R2's `memdb_warming`).
4. Tests: fatal step failure returns the error and no token; degraded step failure returns nil and the token appears in `/health`; the same token added twice appears once; a degraded step that later succeeds on retry clears its token (provide `Clear(token)` and use it where a retry path exists, otherwise leave a TODO line in the PR body naming the step).
5. `go test ./internal/server/ ./cmd/ -short -count=1`, `go vet`, `-race` on the new test.

## Acceptance

## Rollback
Revert; `runStep` is a thin wrapper and the call sites return to direct calls.

## Guardrails
- Data-safety first: never mark degraded any step whose failure could cause the server to write with a wrong key, wrong config blob or missing store. `loadConfigFromDB` degrading to defaults is only acceptable because defaults are read-only-safe; if reading the code shows a default can overwrite stored config on the next save (the whole-struct blob hazard in 07 F12), make that step fatal and explain.
- `/health` tokens are fixed strings; no error text.
- Worktree: `git worktree add ../aorg-07-r3 -b feat/07-r3-startup-step-classes origin/main`.
- Headers on touched files; fragment headerless.
- Commit: `feat(server): classify startup steps as fatal or degraded`; named files only.

The final table, the per-step before/after behaviour, any row you changed from the brief and why, test output, anything unverified.
