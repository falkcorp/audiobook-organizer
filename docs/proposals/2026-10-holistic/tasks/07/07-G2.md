## Goal
There is no enforced layering today. Add `internal/arch/layering_test.go`: it loads the module's import graph, assigns every package a layer number from one Go map, and fails when a package imports a package with a higher number unless the edge is listed in a second map of known violations. That second map may only shrink: the test also fails when a listed edge no longer exists, so the PR that fixes an edge must delete its entry. No `depguard`, no `.golangci.yml` change, no new CI job, no baseline file.

## Steps
1. **Load the graph without a new dependency.** In the test, run `go list -json=ImportPath,Imports ./...` with `os/exec` from the repo root (find `go.mod` by walking up; fail fatally if not found), decode the concatenated JSON objects with `json.Decoder` in a loop, keep only imports with the module prefix `github.com/falkcorp/audiobook-organizer/`. Non-test imports only (`Imports`, not `TestImports`). Do not use `golang.org/x/tools/go/packages` (not needed and not a direct dependency). Positive control: the graph must contain at least 150 module packages and the edge `internal/server -> internal/database`, else fail ("the loader is broken, not the code").
2. **Assign layers.** Rule: start from the layer table's named packages; any other package takes the layer of its directory family (`internal/plugins/*` and `internal/maintenance/jobs` = 4; `internal/server/**`, `internal/realtime`, `internal/syncapi` = 5; `cmd/*`, `tools/cmd/*` = 6); every remaining package takes `max(layer of its in-module non-test imports)` computed from the graph, floored at 3 (domain), or 0 if it imports no in-module package. The module-root `main` package has the key `"."` (import path equal to the module path) and layer 6. One `var layerOf = map[string]int{...}` keyed by import path relative to the module (`internal/database`: 2). Every one of the 184 packages must be present; the test fails listing any package missing from the map (so a new package must choose a layer). Decide the unlisted packages by reading their imports; when a "leaf" candidate turns out to import a domain package, classify it by what it imports and record the decision in a trailing comment. Domain packages that `internal/database` imports today (`matcher`, `fingerprint`, `chaptershape`, `metastate`, `syncapi/progress`) are either reclassified to layer 0 if they turn out to import only layer-0 packages (decide each with `go list` evidence and write the evidence in a comment), or their edge goes into `allowed`.
3. **Known violations.** `var allowed = map[[2]string]string{ {"internal/database","internal/chaptershape"}: "reason", ... }` (key: importer, imported; value: a one-line reason). Fill it from the first failing run. The test then asserts three things: (a) no edge violates the rule unless listed; (b) **every listed edge still exists in the graph**, otherwise fail with "remove this entry, the edge is fixed" (this is the one-way ratchet); (c) every listed edge really violates the rule (an `allowed` entry for a legal edge fails, so the map cannot rot into a general whitelist).
4. **Mutation checks (once, locally, not committed):** add an import of `internal/server` to a file in `internal/config` -> the test fails naming the edge; delete the `internal/metadata` -> `internal/operations/registry` import line's `allowed` entry -> it fails; fix an edge without removing its entry -> it fails.
5. Write `docs/architecture/layering.md`.
6. Do not move or edit any production package in this PR.
