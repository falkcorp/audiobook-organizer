## Execution record (2026-10-09, coordinator, owner grant for workflow edits)
Step 5 found the gap it asked about, and the fix changed the design: a commit with **no** `Continuous Integration` run is "unverified" to `select_span` in `.github/workflows/scripts/auto_revert.py` (docstring lines 18-26; the anchor test at line 200 accepts only a GREEN conclusion), so it stays inside the revert span and cannot anchor it; `auto-revert-backstop.yml` line 62 (`--limit 1`) would likewise read an older run as the tip's verdict. A trigger-level `paths-ignore` would give every docs-only push to `main` no run, widen every later revert span by one innocent commit, and three in a row would exceed `max_span` and downgrade the revert to a report. So **no `paths-ignore` was added**; the `changes` job classifies every event (push and pull_request alike; `workflow_dispatch` and any diff error fail open to both true), and a docs-only event produces a run in which everything but `Changes` is skipped, which concludes `success` and anchors. Consequences: `todo-header-lint` stays in `ci.yml` without `needs: changes` (nothing to move), the docs-only PR shows one `Changes` job rather than none, and a docs-only push to `main` no longer runs the Go jobs (the brief's "always runs everything" for push is kept for any push that touches a non-docs path). Step 6 hits: `internal/database/storage_format_test.go:220,240` and `internal/server/handlers/abs/library_fake_test.go:1417` only assert on literal path strings; no test reads a docs file. The stale "Fails in BOTH directions" comment above `interface-width` in `ci.yml` was corrected to the D47 one-way rule in the same PR. Throwaway PRs run after the merge (a PR branched before it carries the `ci.yml` diff itself, which the classifier correctly reads as go+web, so pre-merge throwaways cannot show the docs-only case); results are recorded below when done.

## Goal
A docs-only PR runs only the changelog-fragment check and the TODO header lint (under 2 minutes). A web-only PR runs the frontend jobs plus the reusable workflow's Go jobs (it cannot skip them until 07-C3). A Go-only PR runs no frontend job. A push to `main` always runs everything.

## Steps
0. **Check required checks before editing.** `gh api repos/{owner}/{repo}/branches/main/protection/required_status_checks --jq '.contexts'` (and `gh api repos/{owner}/{repo}/rulesets` if protection returns 404). `todo.d/README.md:61` and `CLAUDE.md:335` say the TODO fragment job lives in `ci.yml`, and `CHANGELOG.md:11125` lists "Minimal CI Summary" as a required check. A path-ignored workflow never reports, so any required check that `paths-ignore` would skip leaves docs-only PRs pending forever. Paste the list in the PR body; if a required job would be skipped, keep it reporting (run it unconditionally or report from the `changes` job) rather than relying on the filter.
1. `ci.yml` triggers: under both `push` (branches `[main, master]`) and `pull_request` (branches `[main, master]`) add
   `paths-ignore: ['docs/**', '**.md', 'changelog.d/**', 'todo.d/**', '.claude/**', 'agents/**', 'skills/**']`. Keep `workflow_dispatch`. A mixed PR (docs plus code) still runs because `paths-ignore` skips only when **every** changed file matches.
2. New first job `changes` (`runs-on: ubuntu-latest`, `timeout-minutes: 5`, `actions/checkout` pinned to the same SHA the file already uses, `fetch-depth: 0`, `permissions: contents: read`). One `run:` step of at most 20 lines, no third-party action, that writes `go=` and `web=` to `$GITHUB_OUTPUT`:
   - `workflow_dispatch` and any `push` event: `go=true`, `web=true` (a merge to `main` is always fully gated, because `auto-revert.yml` acts on that verdict);
   - `pull_request`: `files=$(git diff --name-only "origin/${{ github.base_ref }}...HEAD")`. `web=true` if any path starts with `web/` or `.github/workflows/`. `go=true` if any path is **not** under `web/`. (So a `web/`-only PR gets `go=false` for the jobs in the table, and the reusable `ci` job still runs because `web` is true; a workflow-file change sets both.)
   - on any error from `git diff`, fail open: `go=true`, `web=true`.
   Pass the base ref through `env:` rather than interpolating it into the script.
3. Add `needs: changes` to every job in the table and the `if:` shown there. For `ci` use `if: ${{ needs.changes.outputs.go == 'true' || needs.changes.outputs.web == 'true' }}` and `run-frontend: ${{ needs.changes.outputs.web == 'true' }}`. A skipped job reports as skipped, which the workflow conclusion treats as success; that is intended.
4. Create `todo-header-lint.yml` with the moved job (same name `TODO Fragment Headers`, same checkout pin, `submodules: recursive`). Delete the job from `ci.yml`. Keep the comment block above it only if it still applies; otherwise delete it with the job.
5. **Verify, do not assume (auto-revert).** Read `auto-revert.yml`'s span selector and its "last green anchor" logic and the helper it calls (`.github/workflows/scripts/`, tested by the `Repo Guards` step "Test the auto-revert span selector and repo scripts").
