## Goal
Tests build stores by calling `NewPebbleStore(` (367 call lines in test files) or `NewPebbleStoreInMemory(` (242), each with its own cleanup and its own ideas about memdb warmup, which is why warmup-dependent tests flake. Add one helper in `internal/database/dbtest` and nothing else; migrating the call sites is 07-S1b.

## Verified at HEAD (`93a9b745f`)
- `internal/database/dbtest/` holds only `invariants.go` (`AssertStoreInvariants`, line 62) and `invariants_fires_test.go`.
- Test-file call lines: 367 `NewPebbleStore(`, 242 `NewPebbleStoreInMemory(`.
- White-box tests in `package database` cannot import `dbtest` (it imports `database`): an import cycle. They are out of scope for migration and keep calling the constructors directly.

## API (decided)
```go
package dbtest

type Option func(*options)

func OnDisk() Option               // real Pebble directory under t.TempDir() instead of the in-memory VFS
func WithoutMemDB() Option         // UseMemDB=false, for tests of the fallback path
func NewStore(tb testing.TB, opts ...Option) *database.PebbleStore
```
Behaviour: in-memory by default (`NewPebbleStoreInMemory`); registers `tb.Cleanup` calling `store.Close` exactly once; **calls `store.WaitForWarmup()` before returning in every mode, including `WithoutMemDB`** (skipping it risks a `-race` report under `-count=20 -race`, because the warmup goroutine is still iterating `p.db` when the test body or cleanup runs). `WithoutMemDB` means: construct normally, wait for warmup, then set `store.UseMemDB = false` after construction, exactly as `internal/database/soft_deleted_count_test.go:52` does; fails the test (`tb.Fatalf`) with the constructor error. Returns the concrete `*database.PebbleStore` because many tests need capability methods. No global state, no package-level cache, safe for `t.Parallel()`.
