## Goal
After a restart the memdb (in-memory read layer) warms for roughly 130-200 seconds (measured; the "memdb warmup published" log line carries `duration_ms`). During that time reads silently fall back to the slow Pebble path, `/health` says "ok", and any operation started in the window runs against the slow path. Make the state visible and make operations wait.

## Design (decided)
1. **`/health` body** stays unauthenticated and detail-free. New fields: `"ready": bool` (memdb published **or** warmup finished by falling back; i.e. nothing left to wait for), `"memdb_ready": bool`, `"warmup_ms": int` (omitted until done), `"degraded": []string` (empty array when none; R3 fills it). `degraded` entries are fixed machine tokens such as `"memdb_warming"` and `"search_index"`; never error strings, paths, versions or counts. HTTP status stays 200 while warming (liveness) so existing probes and the SPA reconnect loop do not change; callers that need readiness read `ready`.
2. **Warming is `status: "ok"` with `ready:false`**, not `status: "degraded"`. Add the token `memdb_warming` to `degraded` while `!ready`.
3. **Ops wait (dispatcher hold).** Non-exempt operations are held back in the dispatcher, BEFORE they are claimed, while the store warms (bounded at 300 s from the first cycle that saw it warming, via `operations.WarmupGate`). A held op keeps its queued row and takes no worker slot, no plugin or `ConcurrencyKey` slot, no write-set claim, and no run timeout or watchdog clock, so Registry.Cancel and Shutdown act on it as on any queued op. While held its progress message reads "waiting for startup warmup" over its own progress numbers; the previous message is restored (and `op.updated` published) when the hold ends. The store is resolved through the decorator chain with `database.AsCapability[operations.WarmupStatuser]`; a store without it never holds. **Exemption rule:** user-triggered ops that finish in seconds opt out with `OperationDef.NoWarmupWait` (`entities.series-rename`, `entities.author-merge`, `dedup.purge-stale`, `dedup.purge-legacy-fp-candidates`, `library.import`); every other def waits. If the bound expires, release the held ops and log once.
4. **Fallback counter** only counts when `UseMemDB` is true and memdb is not ready; reads on stores built with `UseMemDB=false` (tests) do not count.
