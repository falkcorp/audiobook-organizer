## Goal
Direct field reads of the global `config.AppConfig` are how config races and the zero-overrides-default incidents (an 11-day silent disable of chapter consolidation) get in. A source-scanning test fixes the number of direct selector uses outside `internal/config` at today's value; it fails only when the number rises.

## Verified at HEAD (`93a9b745f`): the doc's 636 is not reproducible
The doc (A.5) says "636 non-test references in 204 files" but does not print the command. Measured now with plain greps over `internal` and `cmd`, non-test files only: `grep -rn 'config\.AppConfig\.'` -> 598 lines in 188 files; `grep -rn 'AppConfig\.'` -> 611 lines in 194 files (this also counts uses inside package `config`; 12 of the lines are inside `internal/config`). Different instruments, different numbers. **Do not copy 636.** The test defines its own instrument (below) and the baseline is whatever that instrument reports at the PR's base commit; put the number, the command, and the discrepancy with 636, 598 and 611 in the PR body.

## Context the agent must read first

- `internal/logger/slog_guard_test.go` (source-scanning test pattern, walker positive control).

## Instrument (decided)
An AST walk over every non-test `.go` file under `internal` and `cmd` (skip directories `testdata`, `vendor`, `node_modules`, names beginning with `.`, and `mocks`):
- Resolve the local name under which the file imports `github.com/falkcorp/audiobook-organizer/internal/config` (normally `config`; aliases exist).
- Count each `*ast.SelectorExpr` whose `X` is the selector `<configAlias>.AppConfig` (that is, each use of the form `config.AppConfig.Field`, and also bare `config.AppConfig` passed as a value or address, such as `&config.AppConfig`, which is counted separately as "address-of / value uses").
- Files **inside** `internal/config` are counted in a separate informational total (their uses are `AppConfig.` with no qualifier) and are **not** part of the gated number.
- Also log, informationally, how many counted uses are on the left side of an assignment (writes) so the mutate-through-`Mutate` goal in D8 can be tracked.
The gated number is the count of qualified selector uses outside `internal/config`.

## Steps
1. Write the walker and the instrument above. `const appConfigReadBaseline = <measured>`.
2. `TestAppConfigDirectReadRatchet`: fail only if `count > appConfigReadBaseline`, with a message that names the five files with the most uses and says "read `config.Snapshot()` once at the top of the function, or take the value as a parameter"; if `count < appConfigReadBaseline`, `t.Logf("NOTE (not a failure): ...; lower appConfigReadBaseline to %d in this PR")`. Positive controls: at least 500 files scanned, and the count is greater than 100 (a broken alias resolver would report near zero).
3. **Mutation check (once, locally, not committed):** add one `_ = config.AppConfig.RootDir` to any non-test file outside `internal/config` -> the test fails; remove one existing use -> it passes with the NOTE. Paste both outcomes.
4. Header comment: the baseline may only be lowered, by hand, in the PR that lowers it; 07-M2, 07-M3 and 07-M5 are the expected sources of decreases; usage inside `internal/config` is out of scope until 07-M1 makes it a leaf.
5. Do not change any reader in this PR.
