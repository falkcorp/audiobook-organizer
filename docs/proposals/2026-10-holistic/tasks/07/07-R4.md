## Goal
systemd today considers the service started the moment the process forks (`Type=simple`), so `systemctl restart` returns, the deploy script sleeps 3 seconds, and the version check can pass long before the server can serve. Make the process tell systemd when it is ready, and make the deploy wait on the same signal.

## Verified at HEAD (`93a9b745f`)
- `deploy/audiobook-organizer.service` v4.4.0: `Type=simple`, `Restart=on-failure`, `RestartSec=5`, `StartLimitBurst=5`, `StartLimitIntervalSec=60`, `MemoryMax=12G`, `ExecStart=/usr/local/bin/audiobook-organizer serve --host 0.0.0.0 --port 8484`.
- `Makefile.local.example`: `deploy:` (line ~71) and `deploy-debug:` each do `systemctl restart`, then `sleep 3` and one `curl` of `/api/v1/system/version`. `Makefile` `rollback:` target (line 768; its `systemctl restart` is at line 787) ends with the restart and no wait.
- Listeners are bound inside goroutines (`configureAndStartHTTP`, `internal/server/server_lifecycle.go:788-905`), so there is no point today at which "the port is bound" is known. `READY=1` needs an explicit `net.Listen` first.
- Warmup measured at 130-200 s (R2). **`/health` has no `ready` field at HEAD**; it exists only once R2 (and R3's `degraded[]`) have merged, which is why R4 depends on both. The wait script must treat a body without `ready` as an error, not as ready.

## The unit file text (owner installs it)
Change these lines in `deploy/audiobook-organizer.service` (bump to 4.5.0) and add the sentence below to its header comment:
```
[Service]
Type=notify
NotifyAccess=main
TimeoutStartSec=300
```
`TimeoutStartSec=300` sits above the measured 130-200 s warmup. If READY is sent after bind (not after warmup; see Design), the timeout is generous, and it is the number to tune if the owner wants a stricter bound. Keep `Restart=on-failure` and the start limits unchanged.

**Required sentence, in the PR body and in the unit file's header comment: "the owner installs the unit".** The agent must not run `systemctl`, `scp` or `ssh`, and must not edit `/etc/systemd`. The repo file changes; the host copy changes only when the owner copies it, runs `systemctl daemon-reload`, and restarts. A binary built by this PR runs correctly under the old `Type=simple` unit (the notify call is a no-op without `NOTIFY_SOCKET`), so the merge order between binary and unit does not matter.

## Design (decided)
- **READY is sent after the fatal steps (R3) and after the listener is bound, not after memdb warmup.** Reason: warmup is 130-200 s and a systemd start timeout that long would turn every slow disk into a restart loop; the server answers `/health` with `ready:false` during warmup and ops wait (R2). The deploy waits on `/health` `ready:true` for the end-to-end signal.
- New `internal/server/sdnotify.go` (stdlib only): `func notify(state string) error` writes to the unix datagram socket named by `NOTIFY_SOCKET` (supports a leading `@` abstract socket); returns nil when the variable is unset. Public helpers `NotifyReady()`, `NotifyStopping()` (`STOPPING=1` on shutdown), `NotifyStatus(msg)` (`STATUS=` text for `systemctl status`; fixed strings, no paths).
- `configureAndStartHTTP`: call `net.Listen` synchronously (so a bind failure is a startup error), then `Serve` in the goroutine on that listener, then `NotifyReady()`. Cover every listener the function starts (HTTP, HTTPS, HTTP/3 if present: a UDP listener for QUIC is bound by the library, so for HTTP/3 treat "started without error" as bound and say so in a comment).
- Do not add a dependency (`coreos/go-systemd`); the protocol is a single datagram.

## Steps
1. Write `sdnotify.go` and its test first.
2. Rework listener startup; keep behaviour on bind failure (return a startup error from `Start`). Add a test that occupying the port makes `Start` fail instead of logging from a goroutine.
3. Add `scripts/deploy-wait-ready.sh` (args: base URL, timeout seconds). Test it locally against a throwaway `python3 -m http.server`-style stub or a tiny Go test server returning `{"ready":false}` then `{"ready":true}`; paste the transcript.
4. Edit the unit file and the Makefile targets. Do not run any of them.
5. `go test ./internal/server/ -run 'Notify|Listen|Start' -short -count=1`, `go vet ./internal/server/`, `shellcheck scripts/deploy-wait-ready.sh` if available.
