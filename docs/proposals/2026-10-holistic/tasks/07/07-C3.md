## Design
1. **Units of work.** A unit is either a whole package or a `(package, test-name subset)` pair. Packages whose weight exceeds a cap (start with 150 s) are split into k test-name groups with `balance()`; k = ceil(weight / 150). Expected: `internal/plugins/maintenance` (k=4), `internal/server` (k=3), `internal/metafetch`, `internal/scanner`, `internal/database` (k=1 or 2; decide from the timings you generate). Everything else is a whole-package unit with weight from `scripts/ci/short_test_weights.json` (new; default 10 s for an unknown package, same as `_DEFAULT_WEIGHT`).
2. **Shard assignment.** Longest-processing-time-first into 4 bins over all units, deterministic (sort by `(-weight, name)`), exactly as `fixture_test_packages.py` does. Shard `k/4` runs its units: all its whole packages in one `go test` invocation (one coverprofile), each split unit as its own `go test -run '^(A|B|...)$' pkg` invocation (one coverprofile each), in parallel up to the runner's cores (`--jobs`), then merges the shard's profiles with `merge_profiles` into `coverage-k.out`.
3. **Completeness proof (the self-check).** Before running, the script computes, for every test package, `list_tests()` (so subtests are not at issue: only top-level `Test*`, `Fuzz*`, `Example*` names, as the existing script defines them) and asserts that the union of names assigned across the 4 shards equals the full list with no duplicates and no name unassigned. The same assertion is a unit test with a stubbed lister. A package with a compile error in its tests must fail the shard, not be silently skipped (the existing `list_tests` already exits non-zero).
4. **Flags.** Every `go test` runs with `-short -race -covermode=atomic -timeout 25m` and `-coverprofile=<path>`; keep the 25-minute `-timeout` and the job `timeout-minutes: 35` (the invariant comment). Shards do not run `go vet` (the reusable `Go Vet & Build` job already does; `make test-short` ran it as a prerequisite).
5. **Coverage job.** A job `coverage` (`needs: go-test-short-shards`) downloads the four `coverage-k.out` artifacts, merges them with the same `merge_profiles` (expose it as `short_test_shards.py --merge OUT IN...`), writes the result to `coverage.out`, then runs `make coverage-check-short` unchanged, so `.ci/coverage-floor.txt` and the floor logic are untouched. System packages for the shard and coverage jobs: whatever `coverage-gate` installs today (`libtag1-dev`, `bc`).
6. **Switching off the duplicate.** Request a one-input change upstream (below); once merged, pin the new SHA in `ci.yml` and pass `run-go-tests: false`.
