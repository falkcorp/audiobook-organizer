## Goal
A PR run of `ci.yml` drops from 22-24 minutes to under 10 minutes wall, longest shard under 8 minutes. Today the same suite runs twice in parallel: `Minimal CI / Go Tests (short, race)` (19.3 min, `go test -short -race ./...`, job id `go-test-short` at line 119 of the reusable workflow at the pinned SHA) and `Coverage Floor (PR gate)` (22.7 min, `make test-short`). After this PR one matrix job runs the short suite in 4 shards, a second job merges the coverage profiles and applies the floor, and the reusable workflow's duplicate Go test job is switched off.

## Design
1. **Units of work.** A unit is either a whole package or a `(package, test-name subset)` pair. Packages whose weight exceeds a cap (start with 150 s) are split into k test-name groups with `balance()`; k = ceil(weight / 150). Expected: `internal/plugins/maintenance` (k=4), `internal/server` (k=3), `internal/metafetch`, `internal/scanner`, `internal/database` (k=1 or 2; decide from the timings you generate). Everything else is a whole-package unit with weight from `scripts/ci/short_test_weights.json` (new; default 10 s for an unknown package, same as `_DEFAULT_WEIGHT`).
2. **Shard assignment.** Longest-processing-time-first into 4 bins over all units, deterministic (sort by `(-weight, name)`), exactly as `fixture_test_packages.py` does. Shard `k/4` runs its units: all its whole packages in one `go test` invocation (one coverprofile), each split unit as its own `go test -run '^(A|B|...)$' pkg` invocation (one coverprofile each), in parallel up to the runner's cores (`--jobs`), then merges the shard's profiles with `merge_profiles` into `coverage-k.out`.
3. **Completeness proof (the self-check).** Before running, the script computes, for every test package, `list_tests()` (so subtests are not at issue: only top-level `Test*`, `Fuzz*`, `Example*` names, as the existing script defines them) and asserts that the union of names assigned across the 4 shards equals the full list with no duplicates and no name unassigned. The same assertion is a unit test with a stubbed lister. A package with a compile error in its tests must fail the shard, not be silently skipped (the existing `list_tests` already exits non-zero).
4. **Flags.** Every `go test` runs with `-short -race -covermode=atomic -timeout 25m` and `-coverprofile=<path>`; keep the 25-minute `-timeout` and the job `timeout-minutes: 35` (the invariant comment). Shards do not run `go vet` (the reusable `Go Vet & Build` job already does; `make test-short` ran it as a prerequisite).
5. **Coverage job.** A job `coverage` (`needs: go-test-short-shards`) downloads the four `coverage-k.out` artifacts, merges them with the same `merge_profiles` (expose it as `short_test_shards.py --merge OUT IN...`), writes the result to `coverage.out`, then runs `make coverage-check-short` unchanged, so `.ci/coverage-floor.txt` and the floor logic are untouched. System packages for the shard and coverage jobs: whatever `coverage-gate` installs today (`libtag1-dev`, `bc`).
6. **Switching off the duplicate.** Request a one-input change upstream (below); once merged, pin the new SHA in `ci.yml` and pass `run-go-tests: false`.

## Steps
A. **Generate timings for `internal/plugins/maintenance`.** On a machine with the toolchain: `go test -short -race -json ./internal/plugins/maintenance > /tmp/maint.json`, then sum `elapsed` per top-level `Test*` from the `pass`/`fail` events into the same shape as the other keys of `go_test_timings.json` (name -> seconds, rounded to 2 decimals). Do the same for `internal/server` if its entries were measured without `-short`. Commit only the JSON, not the raw stream. A stale value costs balance, never coverage.
B. Write `short_test_shards.py` and its tests (stub `list_tests` and the runner; no network). `--plan` prints the unit list and per-shard estimated seconds; `--check` runs the completeness assertion against the real `go test -list` output.
C. Wire the workflow and the Makefile target. Keep the existing explanatory comments about timeouts; add a comment describing the shard mechanism and linking `scripts/ci/short_test_shards.py`.
D. Open the upstream request. When it merges, pin and flip `run-go-tests: false`; otherwise apply the inline fallback.
E. **Equivalence proof on one PR.** In the PR body record: (1) the old run's total coverage from `Coverage Floor (PR gate)` (`Total coverage: X%`); (2) the new merged total; they must agree within 0.1 percentage points; (3) the union check output; (4) wall time of the longest shard and of the PR run, before and after. If a shard exceeds 8 minutes, rebalance (move units, adjust weights) before merging.

## Guardrails
- A package failing to compile must fail its shard; never swallow `go test -list` errors (`list_tests` already exits non-zero; keep that).
- Never change `.ci/coverage-floor.txt` in this PR; the floor is raised by a human only.
- No audio decoding on the server and no iTunes writes are involved; tests that need `ffmpeg`/`fpcalc` skip in `-short` today and must keep skipping (do not install those tools in the shard job; the `Fixture Tests` job installs them).
- Pin every action to a SHA; push workflow files with `git push`, not the MCP contents API.
- Public repo: no internal hosts or IPs; `falkcorp/github-common` is public org infrastructure and may be named.
- Worktree rule: `git worktree add ../aorg-07-c3 -b ci/07-c3-short-test-shards origin/main`; never edit main.
- File headers on every touched file (Python, YAML, Makefile, JSON has none); fragment `changelog.d/<name>.md` without header or `##` headings.
- Commit: `ci: shard the short Go test run in four and merge coverage`.
