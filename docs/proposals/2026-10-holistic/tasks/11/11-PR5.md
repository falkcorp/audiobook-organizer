## Goal
After this PR a new `client_golang` metric family cannot be added to the tree: a Go test, run by `make ci` and by every CI runner because it is part of `go test ./...`, counts the families declared through `client_golang` and fails when the count rises above a committed baseline of 69. The count falls over time as families move to OTel; it never has to be raised.

## The quantity being counted
The spec says "constructors" and also says baseline 69, but there are only 44 `client_golang` constructor calls; the other 25 families are Pebble descriptors built by `newPebbleDesc`. A ratchet on constructors alone would leave 25 unguarded slots. The counted quantity is therefore:

```
count = (calls to prometheus.NewCounter|NewCounterVec|NewGauge|NewGaugeVec|NewHistogram|NewHistogramVec|NewSummary|NewSummaryVec|NewUntyped|NewCounterFunc|NewGaugeFunc
         and the same names on the promauto package)                      # 44 at HEAD
       + (calls to newPebbleDesc whose first argument is a string literal)  # 25 at HEAD
       + (calls to prometheus.NewDesc outside the body of newPebbleDesc)    # 0 at HEAD; closes the "new hand-written Collector" loophole
       = 69
```

Verification commands (regex approximations of the AST count, for the hand-back; the test itself uses `go/parser`):

```bash
grep -rhE '(prometheus|promauto)\.New(Counter|Gauge|Histogram|Summary|Untyped)(Vec|Func)?\(' --include='*.go' --exclude='*_test.go' internal pkg cmd | wc -l   # 44
grep -cE 'newPebbleDesc\("' internal/metrics/pebble_collector.go                                                                                         # 25
grep -rn 'prometheus\.NewDesc' --include='*.go' --exclude='*_test.go' internal pkg cmd                                                                   # only pebble_collector.go:119, inside newPebbleDesc
```
