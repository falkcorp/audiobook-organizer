## Goal
Every direct AI request (7 chat sites in `openai_parser.go`, 1 in `metadata_llm_review.go`, 1 embeddings site) is timed, counted by outcome, and traced; token usage the SDK already returns is recorded; failure reasons are classified with the existing error predicates; and scan-phase parse results are counted accepted or not. The five series `ai_requests_total`, `ai_request_duration_seconds`, `ai_tokens_total`, `ai_failures_total` and `ai_parse_results_total` appear on the existing `/metrics` scrape, with no new endpoint or scrape config, and a Grafana dashboard and one alert read them. The dormant `WithOpenAISpan` becomes the generic `WithAISpan`; the placeholder `RecordOpenAIMetric` is deleted.

## Steps
1. **Instruments** on `telemetry.Meter("ai")` (OTel name, exported Prometheus name, attributes):
   - `ai.requests`, counter, `ai_requests_total{provider,model,task,outcome}`, `outcome` in `ok, error, timeout, canceled`. One per attempt that reaches the SDK; a retry is a new attempt.
   - `ai.request.duration`, histogram `s` with the view, `ai_request_duration_seconds{provider,model,task}`.
   - `ai.tokens`, counter, `ai_tokens_total{provider,model,task,direction}`, `direction` in `input, output`. From `Usage`; a reply whose usage is all zero (some local servers omit it) records nothing rather than a false zero. Embeddings record `input` only.
   - `ai.failures`, counter, `ai_failures_total{provider,model,task,reason}`, `reason` in `rate_limit, quota, unreachable, timeout, permanent, reply_parse, count_mismatch, other`. Classify transport errors with the existing predicates in this order: `*ReplyParseError` / `*ResultCountError`, `isPermanentQuota429` (`quota`), HTTP 429 (`rate_limit`), `isUnreachableError`, deadline (`timeout`), `isPermanentAIError` (`permanent`), else `other`.
   - `ai.parse_results`, counter, `ai_parse_results_total{task,accepted}`, `accepted` in `true, false`.
   - Names must follow spec §3.1: counters carry no `_total` in the OTel name; no unit `"1"`.
2. **`observe`** in `telemetry.go`: `observe[T any](ctx, m callMeta, fn func(context.Context) (T, error), usage func(T) (in, out int64)) (T, error)` where `callMeta` is `{provider, model, task string}`. It owns, in one place: the span (`WithAISpan`, name `ai.<task>`, attributes `ai.provider`, `ai.model`, `ai.task`, token counts added to the span on completion, `RecordError` plus `error=true` on failure), the timer, `ai.requests`, `ai.request.duration`, `ai.tokens`, and `ai.failures` for transport errors. `fn` is the single SDK call. Cancellation: a `context.Canceled` is `outcome="canceled"`, `context.DeadlineExceeded` is `outcome="timeout"` with `reason="timeout"`; neither is an `error`.
3. **Reply-quality failures.** `*ReplyParseError` and `*ResultCountError` are produced after the SDK call has already returned successfully (for example `parseBatchMetadataFromJSON` after the `DoWithRetry` loop in `ParseBatch`, `openai_parser.go:685-730`), so the attempt was an `ok` request. Add `recordReplyFailure(ctx, m callMeta, err error)` that increments `ai_failures_total{reason="reply_parse"|"count_mismatch"}` and marks the current span as an error, and call it where those errors are returned to the caller. This is a deliberate refinement of the spec sentence "always incremented together with `ai_requests_total{outcome="error"}`": for these two reasons the matching request is `ok`. The spec's own alert already excludes them from the numerator (`reason!~"reply_parse|count_mismatch"`), and the dashboard's failure-ratio panel must do the same; add a separate panel "Reply-quality failures by task". Report the refinement in the hand-back so the spec can be corrected.
4. **Labels.** `provider` is `openai` or `local`: set a field when the three constructors run (`NewOpenAIParser` gives `openai`; `NewOpenAIParserWithBaseURL` and `newRoutedEndpointParser` give `openai` only when the base URL is empty or the OpenAI host, otherwise `local`). `model` is the model string actually sent at that site; fold anything over 64 characters or containing whitespace to `other`. `task` is the closed enum of 9: `filename_parse, audiobook_parse, batch_parse, cover_art, cover_text, author_dedup_review, author_discovery, metadata_review, embed`. Never add `endpoint`, `node`, a filename, a prompt or a reply to any metric label or span attribute (rule C1, C5, and public-repo hygiene). If the parser knows its pool endpoint id, add it to the span only (`ai.endpoint_id`).
5. **Wrap the 9 sites.** Wrap only the SDK call and the reading of the returned value; leave retry, prompt construction and parsing where they are. For `ParseBatch` the wrap is inside the `DoWithRetry` closure, so retries are separate attempts. For embeddings, wrap inside the attempt loop; keep `attemptCancel()` directly after the call.
6. **Parse results in the scanner.** In the loop at `ai_batch_phase.go:231-262`, count each item once at its final disposition in the phase run: resolved with a non-nil result for which at least one field was merged is `accepted=true`; resolved with a nil result (the `aiMeta == nil` branch at 236, journalled as "had nothing") or a result that merged nothing is `accepted=false`; an item left unresolved after the split-and-retry (the `!out.resolved[i]` branches at 232 and 331 with no per-book error) is `accepted=false`. Detect "merged at least one field" by comparing the book fields before and after the merge block, not by editing each branch. Read lines 225-340 first and describe your disposition table in the hand-back; an item that is retried inside the split must not be counted twice. Task for the batch phase is `batch_parse`. `ParsedMetadata.Confidence` is carried but never compared anywhere (`grep -n 'Confidence' internal/scanner/ai_batch_phase.go internal/scanner/ai_parse_async.go`), so "accepted" means usable, not high-confidence; do not invent a confidence gate or label.
7. **Contract and docs.** Move the five names from `series_reserved.txt` into `series.golden`, seed them in the contract test, write the dashboard and alert, and update `docs/AI-REFERENCE.md`.
