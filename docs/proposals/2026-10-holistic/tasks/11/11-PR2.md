## Goal
After this PR an operator can set `otel_metrics_otlp_endpoint` and the same OTel instruments that feed `/metrics` are also pushed to an OTLP/gRPC collector on a periodic reader. With the key empty (the default) nothing changes. A bad endpoint, an unreachable collector or a failing exporter costs the OTLP copy only: the server starts, `/metrics` keeps serving, and the only trace is one error-level log line. The trace endpoint is never reused for metrics.

## Steps
1. Extract `parseOTLPEndpoint` from `traceEndpointOption` without changing a single accepted or rejected input. Keep `TestTraceEndpointOption_Forms` untouched and green; add `endpoint_test.go` with the same table against `parseOTLPEndpoint`.
2. Add `metricEndpointOption(t otlpTarget, insecure bool) []otlpmetricgrpc.Option`: `WithEndpointURL` for `http(s)://`, `WithEndpoint` for bare and `dns:///`, and `WithInsecure()` only for a bare `host:port` when `MetricsOTLPInsecure` is true (an `http://` URL is already plaintext by the SDK rule the trace path uses).
3. Write `newMeterProvider`. Reader 1 is always the Prometheus exporter (`prometheus.New(prometheus.WithoutScopeInfo(), opts...)`, the 11-PR1 form). Reader 2 exists only when `cfg.MetricsOTLPEndpoint != ""`: `otlpmetricgrpc.New(ctx, ...)` then `metric.NewPeriodicReader(exp, metric.WithInterval(cfg.MetricsOTLPInterval))`. Cumulative temporality. DEVIATION (2026-10-10 review): the original step said not to set a selector, but `otlpmetricgrpc` reads `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE` before applying options, so an unset selector lets the environment flip the push to delta and violates owner decision D66 (cumulative). The code therefore passes `WithTemporalitySelector(metric.CumulativeTemporalitySelector)` explicitly, and pins the transport and headers the same way (see `metricEndpointOption` and `newOTLPReader`). Interval handling: a zero or unparsable value becomes 60s with one warn line; clamp to 5s..1h.
4. Never fatal, no fallback. Any error from parsing or creating the OTLP exporter is logged once at error level through `slog.Log` (this package is allowed that one direct slog use; see `internal/logger/slog_guard_ratchet_test.go`, do not add a new call site, extend the existing single log line in `InitOTEL` (lines 75-81) with `otlp_metrics` and `otlp_metrics_error` attributes), and `newMeterProvider` returns the provider with the Prometheus reader only and a nil error. Only a failure of the Prometheus reader itself may still return an error. If `MetricsOTLPEndpoint` is empty, do NOT consult `ExporterEndpoint` (the trace endpoint) under any circumstance.
5. `InitOTEL`: pass `cfg` through; the returned shutdown still shuts the provider down once (the existing `meterShutdownOnce` pattern).
6. Config plumbing as listed. `Environment` empty means `"prod"`.
7. Write `METRICS-RUNBOOK.md`. State plainly that `/metrics` remains the primary surface and that OTLP is an optional push copy of the same instruments.
