## Goal
After this PR ops metrics are OTel instruments in one small package, `internal/opsmetrics`, that the v2 registry already feeds (runs by outcome, run duration, items processed, in-flight runs) and that the v3 runner (05 PR 5) will feed with the rest. `def_id` is the only per-operation label and is a closed set; no per-run `op_id` label is created by the new code. New alert and recording rules sit beside the old ones for a 30-day soak. The legacy `operations_*_total`, `operation_duration_seconds`, `op_items_processed` and `op_items_total` series keep being emitted unchanged.

## Steps
1. **Instruments** (meter `operations`; OTel name, kind, attributes, exported name):
   - `audiobook_organizer.ops.runs`, counter, `{def_id, outcome}` with `outcome` in `started, completed, failed, canceled, timed_out, dropped`; exposes `audiobook_organizer_ops_runs_total`.
   - `audiobook_organizer.ops.run.duration`, histogram `s` with the view, `{def_id, outcome}`; exposes `audiobook_organizer_ops_run_duration_seconds`.
   - `audiobook_organizer.ops.items`, counter, `{def_id, outcome}`; the v2 registry can only count progress, so it records `outcome="processed"` (v3 will record `ok`, `failed`, `skipped`; document the four values in the package comment). Exposes `audiobook_organizer_ops_items_total`. Do not confuse it with the legacy gauge `audiobook_organizer_op_items_total` (note the missing `s`); put a one-line comment saying so in `opsmetrics.go` and in `alert-rules.yml`.
   - `audiobook_organizer.ops.inflight`, observable gauge, `{def_id, plugin}` (spec says `kind, plugin`; v2 has no `kind`, and stall detection needs `def_id`, so this is a deliberate deviation, reported in the hand-back); exposes `audiobook_organizer_ops_inflight`.
   - Declared with typed recorders but NOT wired here (05 PR 5 wires them; they appear in the golden only when wired): `ops.queue_depth`, `ops.fenced_writes`, `ops.zombies`, `ops.checkpoint_age`, `ops.schedule_lag`, `ops.schedule_missed`.
2. **Cardinality (rule C1).** `def_id` values come only from `RegisterDefID` (called by `RegisterOp`); an id not in the set is recorded as `"other"`. Add `TestUnknownDefIDFoldsToOther` and `TestNoRunIDAttribute` (reflect over the attribute keys the package can emit; none may be `op_id`).
3. **Wire the registry** as listed. Keep every existing `metrics.Inc*` / `metrics.Observe*` / `metrics.SetOpProgress` call exactly as is: during the soak both families are emitted, which is the one sanctioned exception to "never both" because the names differ.
4. **Inflight leak check.** Use the observable-gauge callback over the authoritative `r.running` map, not a +1/-1 counter pair (a missed decrement would leave a permanent false in-flight run and a false stall alert). `Shutdown` must unregister the callback; a registry created per test must not leak callbacks into the next test.
5. **Rules** (the metric names below are the Prometheus names the exporter produces; verify them against the contract test scrape before committing):
   - Keep `AudiobookOrganizerOpFailuresHigh` and `AudiobookOrganizerOpStalled` as they are, with a `# Soak until <date + 30 days>; then delete in a follow-up PR` comment.
   - Add `AudiobookOrganizerOpFailuresHighV2`: `sum(rate(audiobook_organizer_ops_runs_total{outcome=~"failed|timed_out"}[15m])) > 0.1`, `for: 10m`, severity warning (the expression lists `timed_out` so it stays correct once 05-PR2 produces that outcome; until then a deadline hit is recorded as `canceled`, and the alert comment must say so; the old counter did not count timeouts either).
   - Add `AudiobookOrganizerOpStalledV2`, per def, firing when a def has runs in flight and no item progress in 30 minutes. A plain `A and rate(B) == 0` never matches because the two sides carry different labels; write it as `sum by (def_id) (audiobook_organizer_ops_inflight) > 0 unless on (def_id) sum by (def_id) (rate(audiobook_organizer_ops_items_total[30m])) > 0`, `for: 30m`. The `unless` form also fires for a def that has never produced any item.
   - `recording-rules.yml`: group `audiobook_organizer_compat` with `record: audiobook_organizer:ops_items_by_op_type:sum`, `expr: label_replace(sum by (def_id) (audiobook_organizer_ops_items_total), "op_type", "$1", "def_id", "(.*)")` (the spec's `sum by (op_type)` over a series that has no `op_type` label would return nothing; the colon-named record avoids colliding with the still-emitted legacy gauge name).
6. **Do not delete** the legacy gauges `op_items_processed` / `op_items_total` or their `SetOpProgress` / `ClearOpProgress` helpers. Deleting them after the soak is a separate follow-up; add a `todo.d/` fragment (no header) naming the date and the grep that proves nothing else reads them: `grep -rn 'op_items_processed\|op_items_total' deploy internal`.
7. Update the dashboard JSON with `jq` or a script, keep it valid JSON, and keep every other panel byte-for-byte.
