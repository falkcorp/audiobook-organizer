## Goal
After this PR, any package can get a meter with `telemetry.Meter("<area>")`, every histogram's bucket list is declared in one views table, OTel series carry no `otel_scope_*` labels, the service version comes from build info, and a golden test pins the name and type of all 69 existing Prometheus families so no later migration can rename or drop one silently. No existing series name, type or label set changes.

## Steps
1. **Placeholder file.** Run `git fetch origin main && git log origin/main -- internal/telemetry/metrics_handler.go`. If `01-P6` already deleted `internal/telemetry/metrics_handler.go`, leave it alone. If it still exists, delete it in this PR. Either way run `grep -rn 'MetricsHandler\|GlobalMeter\|GlobalTracer' --include='*.go' .`; the only hits must be the definitions (verified at HEAD: `metrics_handler.go:30`, `telemetry.go:194` and `:199`, no callers). Delete `GlobalMeter`/`GlobalTracer` in `telemetry.go`.
2. **`Meter` and naming rules.** Implement spec §3.1 exactly. Add `TestInstrumentNames`: creating each instrument in the golden's OTel entries (none yet; the test must be table-driven so later PRs add rows) rejects a counter name ending in `_total`, unit `"1"` (which appends `_ratio`), and any attribute key outside `attr.go`.
3. **Views.** Copy the bucket lists from the live code, not from the spec prose: `operation_duration_seconds` from `metrics.go:48` (18 buckets 0.1 to 86400), `review_index_request_seconds` from `pipeline_metrics.go:104` (0.1 to 120), `fixer_duration_seconds` from `pipeline_metrics.go:126` (0.1 to 7200), `cache_get_duration_seconds` and `ai_dispatch_slot_wait_seconds` as explicit expansions of `prometheus.ExponentialBuckets(0.0000005, 4, 10)` and `ExponentialBuckets(0.001, 4, 10)` (verify the first against `metrics.go:232-240` before copying). Add the `deluge.rpc.duration`, `ops.schedule_lag` and (reserved) `ai.request.duration` entries from spec §3.4 and §3.9 so later PRs only add instruments. `TestEveryHistogramHasAView` creates every histogram the golden marks `source=otel` against a `ManualReader` provider and fails on any without a view.
4. **Exporter options.** `prometheus.New(prometheus.WithoutScopeInfo())`. Keep `target_info`. Add the resource and views to `metric.NewMeterProvider`. `TestNoScopeLabels` scrapes a test instrument and asserts no `otel_scope_name` / `otel_scope_version` label.
5. **Resource.** `service.version` from build info; if build info reports `(devel)` or empty, use the value passed to `telemetry.SetVersion` (called from `main.go`, see Files); never the literal `0.221.0`. `service.instance.id` is a random per-process id. No hostname, no IP.
6. **Golden file.** Write `testdata/series.golden` with the 69 rows above (tab-separated name, type, labels). It is the source of truth; the table in this brief is its human copy.
7. **Contract test (the core of this PR).** Put it in a directory of its own (`internal/telemetry/contract/`), not in `internal/telemetry`. Reason: an external `telemetry_test` package compiles into the same test binary as `telemetry_test.go`, whose line-55 test installs a no-op meter provider; the OTel global delegates only to the first provider set, so a later `InitOTEL` would silently not receive instruments. A separate directory is a separate process, and also avoids an import cycle once 11-PR3 and 11-PR7 make `aidispatch` and `ai` import `telemetry`. `TestMain` calls `telemetry.InitOTEL(ctx, telemetry.LoadConfig("contract-test", ""))` before anything else.
   The test must prove all 69 names reach a real `promhttp.Handler()` scrape of the default registry. A naive scrape lists far fewer: a `client_golang` Vec with no children emits no `# TYPE` line, an OTel instrument with no data point is not exported, and the Pebble collector emits nothing without a source. So the test seeds, and its seeding is a table in the test (one row per golden entry: how it was seeded), with a final assertion that every golden row has a seeding row:
   - `metrics.Register()`, then call the exported setters for each family (`IncOperationStarted("x")`, `RecordCacheMiss("x","y")`, `SetOpProgress("id","type",1,2)`, `SetBackendAvailable("x", true)`, `IncFilenameParse`, `IncMetadataFetch`, `ObserveReviewIndexRequest`, `SetNumberLeadingTitles`, `ObserveFixerDuration`, and so on; list them with `grep -n '^func [A-Z]' internal/metrics/metrics.go internal/metrics/pipeline_metrics.go`).
   - Pebble: `metrics.SetPebbleSource(metrics.PebbleStoreMain, fn)` with a fixed `PebbleSample` (`fixedSample()` is at `internal/metrics/pebble_collector_test.go:16` and is test-only in package `metrics`, so copy it into the contract test).
   - aidispatch: call `aidispatch.RegisterMetrics()` (new, see Files) and drive `aidispatch.Call` through `aidispatch.New(...)` with fake endpoints so that all five families get a child (request, inflight, slot wait, a failover, a no-capable refusal). Copy the endpoint fixtures from `internal/aidispatch/dispatch_test.go`.
   Two assertions, both required:
   - (A) every golden name is present in the scrape with the golden type and, for the labelled families, the golden label names;
   - (B) the set of exposed family names with prefix `audiobook_organizer_` or `ai_dispatch_` or `ai_` (plus `target_info`) equals the golden set union the reserved list; any extra name fails with "add it to series.golden in this PR". Do NOT assert on `go_*`, `process_*`, `promhttp_*` or `scrape_*` (they vary with the Go version and OS).
   Add `TestReservedAISeries`: none of the five names in `series_reserved.txt` is exposed yet (11-PR7 moves them into the golden).
8. **otelgin.** The first run of (B) will show whether `otelgin` emits `http_server_request_duration_seconds` through the global meter (spec F14, not measured). If it does, add it to the golden as `source=otel`; if it does not, record "not emitted" in the PR description. Do not guess.
9. Update `docs/AI-REFERENCE.md` and add the changelog fragment.
