## Steps
1. BEFORE deleting anything, run `go build -tags cgo ./... && go vet -tags cgo ./...` (and `GOOS=linux GOARCH=amd64 go build ./...` if you are on macOS) so a function used only under a build tag or cgo shows up as a compile error early. Also run the scratch `deadcode` once more with `-tags cgo` and once with `-test`: a symbol that only the tagged or test build reaches stays.
2. Interface-satisfying methods (for example logger and middleware error methods, memdb indexer methods, store methods) look dead to `deadcode` but break the build or the interface assertion when removed. If the compiler complains, keep the method and list it in the report.
3. This group covers 01 appendix F rows P12, P31, P46, P28. The table is the exact list of 16 functions (157 lines) from appendix B category D, verified present at HEAD `93a9b745f` (every file exists and each function is on the stated line). Not in the table because an earlier PR already deletes them: `preserveExistingFields` (P6). HELD BACK (still live: do NOT delete in this PR; each needs a separate decision together with the named test or file): `HandOffCrownedValue` (internal/undo/restorable.go:897, 10 lines; test seam: used by internal/plugins/maintenance/retire_into_test.go:639 in another package); `EnqueueAIParseWired` (internal/scanner/ai_parse_async.go:64, 7 lines; test seam: used by internal/server/library_ai_parse_op_test.go:62 in another package); `LoadApplyRenameFailure` (internal/organizer/apply_failure.go:262, 4 lines; test seam: used by internal/metafetch/apply_collision_failure_test.go:74 in another package).
4. Install `deadcode` into a scratch GOBIN (`GOBIN=$SCRATCH/bin go install golang.org/x/tools/cmd/deadcode@v0.51.0`; `golang.org/x/tools` is not a dependency in `go.mod`, so v0.51.0 is the version appendix A used), do not add it to `go.mod`. On your branch base run `$SCRATCH/bin/deadcode ./... | grep <package>` and confirm every function in the table is still reported. A function that is NOT reported any more is live: leave it and say so.
5. For EACH function before deleting it: (a) LSP `findReferences` or `grep -rn "<Name>" --include=*.go .`, callers must be tests only; (b) reflection/string dispatch: `grep -rn "\"<Name>\"" internal cmd web/src` (JSON field names, registry string names, `MethodByName`, templates), (c) `go:linkname` and generated mocks. Any production hit means the function stays; list it in the report.
6. Delete the function WITH its doc comment, then run `go build ./...` immediately. Remove imports and package-level helpers/constants that become unused only because of the deletion (in scope: the same problem), and list them.
7. Delete or edit the tests that exercised only the deleted functions. Every deleted test needs one line in the report saying which function it covered.
8. Run the package tests for every package in the table, then `go build ./... && go vet ./...`, then the CI gate.
