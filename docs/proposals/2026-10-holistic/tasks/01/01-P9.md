## Goal
A new CI gate fails when the number of production functions unreachable from every `main` goes UP, using a checked-in baseline. It fails only on a rise (D47); a bot lowers the baseline, humans never edit it down by hand. `knip --production` runs as a non-blocking report. The gate is wired into every runner that lists gates (Makefile `ci`, Woodpecker, `scripts/ci_remote.py`, GitHub `ci.yml`), not only one.

## Steps
1. Locally install the tool in a scratch GOBIN: `GOBIN=$TMPDIR/bin go install golang.org/x/tools/cmd/deadcode@v0.51.0`. Do not add it to `go.mod`. CI and the Makefile target obtain it with `go run golang.org/x/tools/cmd/deadcode@v0.51.0 ./...` (no install step). Output format (verify on the first run before writing the parser): grouped by package, a header line `package/path`, then indented lines `  file.go:LINE:COL: unreachable func: Name` (methods as `Type.Name`); the baseline stores identifiers, not LINE:COL.
2. Write the script, run it once to create the baseline from the tree AFTER the tier-1 PRs. Expect roughly 499 functions minus what P2, P4, P5, P6 removed; report the exact number.
3. Wire the four runners. Keep the gate name identical everywhere (`deadcode-ratchet`) so 07 G4's manifest can list it once.
4. Prove it: add a scratch file with an exported unused function, run the script, show it fails with the function name; revert the scratch file.
5. Document in the script header why GOOS/GOARCH are pinned and how the bot lowers the baseline (follow the errcheck script's header style).
6. Fragment: a new check stops dead code from growing back.
