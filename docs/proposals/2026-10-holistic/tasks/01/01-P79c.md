## Goal
With `verify_after_write` on (its default is already `true`), `tagger.WriteTagsSafe` re-reads the file after the atomic rename and compares every tag key it wrote. A mismatch returns `ErrVerifyAfterWrite` naming the differing keys and records a `FileEventObserved` provenance event with the diff. The read happens in the tagger layer because `fileops.WriteTagsSafe` only sees an opaque `writeFn`.

## Steps
1. Read both `WriteTagsSafe` paths in the tagger. Decide where the verification belongs so it runs once per write on the file that was actually written (`effectivePath`).
2. Write the failing test first (a writer that silently drops a key), watch it pass `WriteTagsSafe` unnoticed on `origin/main`, then add the verification.
3. Make the comparison tolerant of what taglib legitimately normalises (for example key case) and strict about missing or different values; document the rule in a comment.
4. On mismatch record the provenance event with the diff and return the typed error; the file stays as written (the write succeeded, verification failed), and the error tells the caller.
5. Run the tagger, metadata and metafetch tests; callers that previously got `nil` on a lossy write now see an error, so grep their error handling for swallowed errors (`_ =`) and report any that would hide the new error.
