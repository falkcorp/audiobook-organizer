## Goal
The SQLite activity backend (11 production files, 5,181 lines, and about 5,373 test lines), the Pebble-to-SQLite migration wrapper and its startup migration are deleted; Pebble is the only activity backend. `activity_backend: sqlite` in an old conf FAILS LOUDLY at startup (it must never silently run on Pebble with the SQLite file ignored). The 20 GB `activity.sqlite` stays on disk; nothing here deletes it. The commit before this PR is tagged `activity-sqlite-last`.

## Steps
1. DISCOVER AND SWEEP. The doc's file list is incomplete: live code names the SQL types. Start with `grep -rn "SQLActivityStore\|MigratingActivityStore\|SQLBackfillDone\|OpenSQLiteActivityStore\|LastActivityDBPath\|SetLastActivityDBPath\|ResolveActivityDBPath\|ActivityDBPath\|ActivityDBMoveOnChange\|activity-sql-migration\|sql_migration" --include=*.go internal cmd main.go` and also `--include=*.yaml --include=*.yml --include=*.md` outside `docs/proposals`. Every hit is either deleted, edited, or listed in your report with a reason it stays.
2. Confirm with the coordinator's prompt that `git tag activity-sqlite-last <sha of origin/main>` exists before you start; record the SHA in your report. Do not create tags yourself unless told to.
3. Make `register.go` reject `sqlite` first and get the build green with the SQL files still present; then delete files in dependency order, building after each step.
4. Check that no non-activity code needs the SQL driver or `database/sql`: `grep -rln "database/sql" --include=*.go internal` after deletion.
5. Write the config test: loading a config with `activity_backend: sqlite` makes startup return the error from step 3 (call the register function with that config) and a config with nothing set or `pebble` builds the Pebble store.
6. Run `go mod tidy` last; paste the `git diff --stat go.mod go.sum`.
7. Fragment: the SQLite activity backend is removed; a conf that still says `activity_backend: sqlite` now stops with a clear message; the old `activity.sqlite` file is left alone.

## Rollback
Revert the commit (the tag `activity-sqlite-last` marks the last SQLite-capable build). Returning to SQLite after a long Pebble-only period needs a catch-up op that does not exist, so a revert is only safe soon after the deploy.
