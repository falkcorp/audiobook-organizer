## Goal
Every browser request goes through `apiFetch` (or a `services/*` function that uses it), so an expired Cloudflare Access session surfaces as `ApiAuthRedirectError` instead of being read as success. The Users page stops ignoring failed deactivate and reactivate calls. An ESLint rule keeps raw `fetch` out of `web/src` except in `utils/apiFetch.ts`.

- `web/eslint.config.mjs` (flat config; the TS block starts at line 18).
- Raw `fetch(` sites outside `services/` and `apiFetch.ts` at HEAD (23, not the 22 the doc says; list in the Files table).

## Steps
1. Re-measure: `grep -rnE "\bfetch\(" web/src --include=*.ts --include=*.tsx | grep -v "\.test\."` and compare with the table. Report any difference.
2. Convert site by site. Keep behaviour: same URL, method, body and error text; `apiFetch` adds `credentials: 'include'` and the JSON content type for bodies. Where the old code passed `credentials` itself, drop it.
3. For the writes (`ChangeLog.tsx`, Users deactivate/reactivate/reset/invite) check `resp.ok` and throw or show the existing error UI.
4. Add the ESLint rule last, then run `cd web && npx eslint src` and fix what it finds; the rule must pass with zero raw `fetch` outside `apiFetch.ts` and tests.
5. Write the per-page tests. Use the existing test helpers; stub `globalThis.fetch` to return `new Response('<html>login</html>', {headers: {'Content-Type': 'text/html'}})` for an `/api/` URL and assert the page shows an error.
6. Fragment: an expired session now shows an error everywhere instead of looking like success.
