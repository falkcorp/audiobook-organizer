# Manual-mock inventory and remediation backlog

**Audit date:** 2026-08-16 · **Scope:** all Go test doubles in `internal/`, `cmd/`, `pkg/`
· **Status:** inventory complete for the named-pattern population; a quantified blind spot
remains (see [§2](#2-the-census-is-a-lower-bound)).

---

## 1. Executive summary

This repo mandates mockery-generated mocks and has a named prior incident behind that rule.
It also contains a second, contradictory rule saying the opposite. Meanwhile roughly a third
of the mock-generation config produces code nobody imports.

| Measure | Value |
|---|---|
| Interfaces configured in `.mockery.yaml` | **131** across 14 packages |
| Generated mock files / lines | **88** / **89,820** |
| Real generated mock types (excl. `_Call`/`_Expecter`) | **110** |
| — never referenced anywhere | **56 (51%)** |
| Hand-written doubles found by name pattern | **116** across **101** files |
| Additional doubles proven to exist beyond that pattern | **≥60** (see §2) |
| **Estimated true population** | **≈175** |
| Hand-written impls of one single interface (`registry.Reporter`) | **22** (15 test fakes + 7 prod adapters) |

**Four findings drive everything below:**

1. **Two live policies contradict each other** (§3). Until one governs, "N violations" is
   not a well-formed statement.
2. **The migration that would have fixed this was abandoned mid-flight** (§4). Commit
   `7f2a01e2` is titled "pt 1"; pt 2 never landed.
3. **CI cannot see any of this** (§5). Both mock gates verified that *listed* mocks are
   fresh; neither can detect an interface that was never listed. One of the two was inert
   for its stated purpose and was **deleted on 2026-08-17** (§5b) — but note the correction
   there: `registry.Reporter` is *not* an instance of this blind spot. It has no generated
   mock and needs none, because every one of its 22 non-production implementers must declare
   `RunPhase`, so widening the interface is a compile error in all of them at once. The
   compiler is a stronger gate than a freshness check; do not "fix" this by adding Reporter
   to `.mockery.yaml`.
4. **Over-generation is real and concentrated** (§6). 42% of the largest generated file is
   mocks nobody imports.

**Decision taken (2026-08-16): "C now, A later."** Adopt the threshold rule as the phase-1
cut; the org-wide "no hand-written mocks" rule is the declared destination. §7 defines both,
including a restatement of the destination rule that can actually be satisfied.

## 2. The census is a lower bound

The initial sweep matched type names containing `mock|fake|stub|spy|noop|dummy`. That found
**116 declarations across 101 files**. Two orthogonal instruments then proved the pattern
misses a large tail:

| Instrument | Result |
|---|---|
| Compile-time assertions (`var _ Iface = (*T)(nil)`) in `_test.go` | Surfaced `recordingReporter`, `w8MultiFileOrganizer`, `concurrencyTrackingOrganizer`, `chbfDecorator` — none name-matched |
| Every non-generated type in a `_test.go` with ≥1 method | **170** total; **93** name-matched; **77** did not |

Sampling the 77 shows the large majority are genuine doubles — `b3FaultStore` (11 methods),
`p2ProgReporter` (9), `resetAllTestReporter` (8), `lshTestReporter` (8), `concurrentReporter`
(8), `centralizationTestReporter` (8), `captureReporter` (8), `errWriteISBNStore` (5),
`blockingSource` (4), `countingSource` (3), `failingUpsertStore`, `salvageFailingStore`,
`pagingHazardStore`, and so on. Roughly 10 are not doubles (test harnesses such as `harness`,
`writeHarness`, `deepLinkHarness`, `absHarness`; error types `errString`, `stringError`;
fixtures `bookSigEnv`, `fileSet`).

> **Therefore: the true population is ≈175, not 116.** The naming convention caught about
> two-thirds. Every count in §8 applies to the **116-item named-pattern census only** and is
> explicitly a lower bound. Do not quote them as totals.

The lesson generalizes: **a naming-convention grep is not a census instrument.** Repos that
enforce a double-naming convention can use one; this repo does not have such a convention,
so a signature- or assertion-based sweep is the only sound method.

Commit `7f2a01e2` (April 2026): *"refactor(mocks): convert hand-written test doubles to

## 5. Finding 3 — CI cannot see any of this

### 5a. The never-listed blind spot

`make ci` runs two mock gates (one as of 2026-08-17 — see 5b):

- `mocks-check` — runs `mockery`, then `git diff --quiet` over `internal/**/mocks/**` plus
  the two in-package `_test.go` mocks. **This is a real gate.**
- `check-mock-fresh` — **deleted 2026-08-17**, see 5b. `make ci` now runs one mock gate.

Both answer *"are the mocks we generate up to date?"* **Neither can answer *"is there an
interface we should be generating and aren't?"*** Every one of the ~175 hand-written doubles
is therefore green by construction. This is the structural hole the entire inventory lives
in, and closing it (§9) matters more than any individual conversion.

### 5b. `check-mock-fresh` is inert — ✅ DELETED 2026-08-17

> **Resolved, and the original wording below was half wrong — corrected here so the
> sharper claim is the one that propagates.** The target was deleted, not repaired.
> It is *not* true that it "can never fail": `git diff --exit-code
> internal/database/mocks/` fires on **any** uncommitted edit under that directory, so
> it is a live *dirty-worktree* detector. What it cannot do is the job it was named
> for. Measured both ways on 2026-08-17:
>
> | probe | condition | `check-mock-fresh` | `mocks-check` |
> |---|---|---|---|
> | 1 | append a junk line to the committed `mock_store.go` | **exit 2 (fails)** | — |
> | 2 | add a method to the `Store` interface, leave the mock untouched | **exit 0, prints "Mock is fresh"** | **exit 2 (fails)** |
>
> Probe 2 is the failure mode the docstring named, and it is the one the target
> misses. Probe 1 is why "never fails" is falsifiable in one command — do not repeat it.
>
> **Coverage lost by deleting it: none.** Store/mock divergence is a *compile* error via
> the assertions at `internal/database/iface_assert.go:12` and
> `internal/database/mock_store.go:30`; `vet` (a `test-short` prerequisite, so already in
> `make ci`) runs over every package; and `mocks-check` goes red on probe 2 as well.
> Three independent gates already own it.

The original finding, for the record:

```make
check-mock-fresh:
	go generate ./internal/database/...
	git diff --exit-code internal/database/mocks/ || \
		(echo "ERROR: MockStore is stale. Run 'make generate' and commit." && exit 1)
```

**There are zero `//go:generate` directives anywhere in the repository** (verified: grep over
all `*.go`, count 0). So `go generate` is a no-op, nothing is rewritten, the diff is always
clean, and the check passes unconditionally. Its failure message instructs the reader to run
`make generate` — **a target that does not exist in the Makefile.**

Severity is low, because `mocks-check` genuinely enforces freshness. But this step has run in
every CI job since it was added and has never once been capable of failing. Either delete it
or give it a real directive.

> See [`2026-08-16-store-interface-decomposition.md`](2026-08-16-store-interface-decomposition.md) §3 and §8.

| | Lines | Share |
|---|---|---|
| All generated mock code, 16 directories | **89,820** | — |
| `internal/database/mocks/mock_store.go` | **52,384** | **58% of all generated code** |
| — `MockStore` alone | 23,536 | 45% of the file |
| — the ~~37~~ **42** unreferenced database mocks | ~~22,001~~ **40,569** | ~~42%~~ **76% of the file** |
| `internal/server/handlers/mocks` (next largest) | 13,747 | 15% |

`.mockery.yaml` generates a standalone mock for all **45** `internal/database` interfaces.
Only **3** are ever referenced: `MockStore`, `MockImportPathStore`, `MockOpsV2Store`.

**Two distinct causes, two different fixes:**

- **The 42 unused mocks (40,569 lines)** — delete their `.mockery.yaml` entries. Zero test
  impact; nothing imports them. Reversible at one YAML line each plus `make mocks`, so this
  cannot entrench anything.
- **`MockStore` at 23,536 lines** — not a mock problem. `database.Store` embeds 39
  sub-interfaces (~393 methods) and mockery emits a struct, an expecter, and one `_Call` type
  per method. The mock cannot shrink unless the interface does.

**These are related.** The 42 narrow mocks go unused *because* production constructors accept
`database.Store` rather than `BookReader` or `WorkStore`. Nobody reaches for `MockBookReader`
because no function accepts a `BookReader`. Narrowing parameters would make those mocks useful
*and* reduce `MockStore` usage — and it is a test-quality change, not just a bloat one: a
handler taking `BookReader` structurally cannot write to the database, and its test can prove
it. `internal/sweep` already does this correctly (`SweepTombstones(store database.BookStore)`).

**Splitting mocks into more packages does not reduce bloat** — it relocates lines. Package
splitting solves a different, real problem: **import cycles.** `internal/scanner/mocks`
imports `scanner`, so tests in `package scanner` cannot use `MockScanner` — which is precisely
why `fullMockScanner` and `mockScannerImpl` were hand-written. `.mockery.yaml` already solves
this twice via in-package `_test.go` generation (`.mockery.yaml:91-94`, `:109-118`).

## 7. Governing policy

### 7a. Phase 1 (in force now)

1. **Interface > 5 methods → must be generated.** This is `docs/CODING_STANDARDS.md`'s own
   number, so it contradicts neither existing document. Drift risk scales with surface area;
   the incidents actually suffered (`stubStore`/#234, #241) were on large store interfaces.
2. **Any interface hand-mocked in ≥3 files → must be generated regardless of size.** The cost
   here is copy-paste, not drift. `sdk.Registry` is 2 methods with 3 copies.
3. **Duplicating an already-generated mock → always fix.** The mock exists, is CI-maintained,
   and is currently dead. This bucket is free.
4. **Stateful doubles are deferred, not exempt.** Mockery emits *call-expectation* mocks;
   virtual time, CAS state machines, and conformance fixtures are not expressible that way.
   These are **`DEFERRED-TO-A`**, not "correct forever."

> The `>5` threshold is a **sequencing device, not a principle.** It exists to order work by
> risk and walks toward zero in phase 2.

### 7b. Phase 2 destination (A), restated so it can be satisfied

The org rule as written — *"do not hand-write mocks"* — **cannot be satisfied by this repo**:
third-party interfaces (`tag.Metadata`) are outside `.mockery.yaml`'s first-party scope;
"mock" is undefined, so production Null Objects and DTOs read as violations (11 of the 116
findings); and there is no exemption mechanism for doubles mockery cannot express. An
unsatisfiable rule cannot terminate a ratchet. Replacement text for
`docs/CODING_STANDARDS.md`:

> **Test doubles.** Any type in a `_test.go` file that exists to stand in for a **first-party
> interface** — declared under `github.com/falkcorp/audiobook-organizer/...` — must be
> generated by mockery and registered in `.mockery.yaml`. Hand-writing one is a build failure.
>
> **Out of scope** (not test doubles; the rule does not reach them):
> - Types implementing a **third-party** interface. Hand-write these with a
>   `// third-party interface: <pkg>.<Iface>` comment.
> - **Production** types on live code paths — Null Objects, adapters, DTOs, library interface
>   implementations. Being named `noopX` does not make a type a double; being referenced only
>   from tests does.
> - **Func-variable seams** — a struct whose method is assigned to a package-level `func` var
>   rather than satisfying an interface.
>
> **Exemption.** A double needing behavior mockery's call-expectation model cannot express —
> virtual time, a state machine whose state tests read back, a conformance fixture — may be
> hand-written **only** with an entry in `.mockery-allowlist.yaml` naming the type and the
> reason. **The allowlist may only shrink.**

Every clause maps to something a checker can evaluate. *"Do not hand-write mocks"* maps to
nothing.

### 9a. The ratchet — how phase 1 reaches phase 2

Without this, phase 1 completes and the population resumes growing under the exemption,
exactly as it did after `pt 1` in April 2026.

- Fail CI when a `_test.go` declares a type implementing a first-party interface that is
  absent from `.mockery.yaml` **and** absent from `.mockery-allowlist.yaml`.
- Seed the allowlist with the sub-threshold doubles plus the `DEFERRED-TO-A` set.
- **The allowlist may only shrink.** Phase 2 becomes "drive the allowlist to the carve-out
  set" — incremental, reviewable, and non-regressing.
- **Detect by signature or assertion, never by name.** §2 is the proof: a naming grep missed
  a third of the population.

## 10. Reproduction

```bash
# named-pattern census (LOWER BOUND — see §2)
grep -rnE '^[[:space:]]*type +[A-Za-z0-9_]*([Mm]ock|[Ff]ake|[Ss]tub|[Ss]py|[Nn]oop|[Dd]ummy)[A-Za-z0-9_]* +struct' \
  --include='*.go' internal/ cmd/ pkg/ > /tmp/all.txt

comm -23 /tmp/files.txt /tmp/gen.txt > /tmp/hand.txt          # 101 files / 116 decls

# the blind spot: every non-generated type in a _test.go with >=1 method
grep -rhE '^func \([a-zA-Z_][A-Za-z0-9_]* \*?[A-Za-z0-9_]+\)' --include='*_test.go' internal/ cmd/ pkg/ \
  | sed -E 's/^func \([a-zA-Z_][A-Za-z0-9_]* \*?([A-Za-z0-9_]+)\).*/\1/' | sort -u   # 170 total, 93 name-matched
```
