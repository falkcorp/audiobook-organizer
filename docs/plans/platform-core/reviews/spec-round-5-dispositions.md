# Spec review round 5 — dispositions

Inputs: `spec-round-5-{correctness,data-migration,frontend,modules-build,ops-rollback,security,simplicity}.md`.
Totals: **115 findings — 5 BLOCKER, 43 MAJOR, 67 MINOR.** All accepted; 0 rejected.
Distinct blockers per round: 20 → 10 → 9 → 6 → 5. Every round-5 blocker is a local consistency or timing defect;
none reopens an architectural decision.

## Round-5 resolutions (binding)

- **R5-1 Basic gate and HEAD precedence.** (a) The books legacy config store preserves HEAD's precedence for legacy
  keys until cutover: a value persisted through the UI wins over an environment default exactly as it does at HEAD,
  so compose's always-set `BASIC_AUTH_ENABLED=false` cannot switch off a UI-enabled gate (OPS5-1). (b) The four
  secrets HEAD already stores encrypted (OpenAI key, Google Books key, Hardcover token, Basic password —
  `internal/config/persistence.go:1955-1958`) are **not moved** during the extraction; the legacy store reads HEAD's
  encrypted rows. Only plaintext secrets are moved and sentinelled (R4-2), so a rollback never strands the Basic gate
  (OPS5-2). (c) The core Basic gate refuses "enabled with an empty password" (fail-closed, SEC5-4).
- **R5-2 No import cycles from the legacy stores.** Each legacy store implementation lives in a books package that
  may import what it needs (`internal/config`, the moved task store) without being imported back; the code the moved
  task store shares with the remaining store (migrations 62 and 66) moves with it or is reached through an interface,
  so nothing is skipped and nothing is recorded as applied without running. The package mapping's gate proves it.
- **R5-3 Write checks follow writer conversion.** A family refuses unchecked writes only from the stage at which its
  last writer is converted (COR5-1).
- **R5-4 Serialized where commit-time checks are required.** Every family whose store interface uses commit-time
  checks (`Transition`, `Advance`, …) is declared `Serialized` in 05-storage's table (DATA5-1).
- **R5-5 Served ledger keeps the previous record** and replaces it only after every boot step that reads it has
  committed (COR5-3, DATA5-6).
- **R5-6 Extension fingerprints cover security-relevant fields only** (not `last_used` and similar per-request
  fields); a revocation made by an older build is monotone (stays revoked); a key with no legacy-equivalent scope is
  written to the legacy row with a scope that grants nothing on an older build, never an empty list (DATA5-2/3,
  SEC5-1/2).
- **R5-7 Build identity.** Every build path (`make build`, goreleaser, the Docker stages) stamps the UI bundle's build
  ID through the npm build script itself, not a side script; the binary's own identity (used by updater, storage and
  backup) is a separate value and never the UI bundle's ID (FE5-1, FE5-3).
