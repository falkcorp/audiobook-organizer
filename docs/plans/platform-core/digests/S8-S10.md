# Digest S8–S10 — Backup/updater/health/metrics, UI shell, final cleanup

Normative digest for implementers. Source order: 09 §9.4 S8, S9, S10, §9.2.1, §9.2.2, §9.2.6, §9.5, §9.6, §9.10; 03 R4/R6; 04 §8.1; 05-backup, 05-updater, 05-health, 05-metrics, 05-realtime; 06 §6.6; 07 §7.4–§7.19. Where this file and a spec file differ, the spec file wins and the difference goes in the PR description. `[n]` points to Footnotes.

## 1. Goal

- **S8:** platform operations owned by core: backup (plaintext archives, catalogue, staged restore), the updater **moved, not rebuilt**, health with probes, a per-App metrics registry with the kernel's `/metrics`.
- **S9:** `@mediacore/shell` plus the books UI contribution; the shell owns `/`; gin's SPA serving is deleted.
- **S10:** delete what has run its window; no representation change, no mirror, no reconcile code, and **no upgrade floor of its own**.
- Release IDs (grammar of 09 §9.2.1): `S8`, `S9`, `S10`, each a single release. S8 lands live PR by PR: live PRs (the backup-catalogue PR among them) carry `Stage-Release: S8 1`; the flip PR (mounts the kernel `/metrics`, deletes gin's route and `internal/backup`'s staging) carries `Stage-Release: S8 flip` and sets `shipped_stage:` and `release:` to `S8`. S9: content PRs `Stage-Release: S9 1`; the flip is the steps 4–5 release PR that deletes gin's `NoRoute`/`setupStaticFiles` SPA serving (`Stage-Release: S9 flip`, both lines to `S9`). S10: the flip is the PR that deletes `internal/serviceregistry`, the first S10 deletion (`Stage-Release: S10 flip`, both lines to `S10`). Every commit also ends with `Co-Authored-By: Claude <noreply@anthropic.com>`; merge with `gh pr merge <n> --rebase`, never squash.
- Every flip needs the predecessor's soak row (14 days) and a green `make compat-rehearsal`. Cells: a/b whenever a UI call moves (S8 moved system/backup/update calls; S9); c (ABS) in S9; e (restore across builds) at S8. [1]

## 5. Behaviour rules

**S8: moving the updater (05-updater 5U.4, 5U.12)**
1. **Move, do not rebuild.** The S0-hotfixed updater moves into `core/updater` with **HEAD's pipeline**: download HEAD's raw asset `audiobook-organizer-<GOOS>-<GOARCH>` straight to `<exe>.new`. Exactly two additions to HEAD's pipeline: the `max_download` size cap and the `--version-json` self-test of the new binary (the new binary must print exactly `{app, version, commit, ui_build_id, binary_id}`, `app == AppID`).
2. Keep: exit 75 on restart; the one `.prev` slot shared with `make rollback`; semver comparison with local-build detection (a describe-suffixed version is "local build, not compared"; never a downgrade); the level and floor checks against the store's sidecars (`<exe>.new --print-upgrade-floor` against `<db>.storage-applied`, `stepping_stone_required`); the in-process restore-slot check through `CheckReader`; and **check-only unattended mode**: the scheduled apply and the maintenance-window step only check and notify (health `auto_update_paused`) for the whole extraction; a manual apply stays behind the credential guard. The `core.updater.check` task has a schedule key; `core.updater.apply` declares none (`TestApply_OnlyPathIsManualTask`).
3. **Deferred-build, must NOT ship at S8** (none is in HEAD's updater): archive download and member extraction, `checksums.txt` verification, the pre-update backup (`core.updater.require_backup`, `backup.Runner`), the container refusal, `restart_mode=exec`, signed manifests and trusted keys, the boot-attempt counter, automatic rollback by `updater.Boot` in boot phase P−1, the committed unit's binary-layout migration, the real-RC `--updater-check`, R-test cell (d). The committed unit keeps its root-owned binary directory, so a manual apply there reports `binary_not_writable` instead of failing half-way.
4. ABO's `main` passes its slug and binary name and keeps the default `RawBinary` namer. State S8 adds: `c/updater/seen` and the durable clock of `core.updater.check` (books' legacy `ClockStore`). Config: `auto_update*` become `core.updater.*` with aliases.

**S8: backup, health, metrics**
5. Archives are **plaintext** with the provenance MAC over a keyring-derived key; catalogue and staged restore are 05-backup's. Encryption is not built (it lands with the first app or cutover that can activate it). Archive format is one (ABO's legacy layout plus a manifest); every older build restores every archive it can open.
6. Staging checks the build's upgrade floors; a staged restore records the staging build and an expiry; a stale or foreign intent is rejected (moved aside, Degraded). `make rollback`, the updater and the `deploy` recipe refuse while one is pending or in flight. Applying a restore rewrites the **three** sidecars (`.storage-levels`, `.storage-applied`, `.storage-format`). The revocation journal is re-applied and post-restore revocations are written through books' legacy auth store into the legacy rows. The 05-config keyring export is the only export. Secret-class items and the config file follow 05-backup.
7. `/health` with its `ready` field is **permanent** (deploy scripts, Docker HEALTHCHECK); core adds `/livez`, `/readyz`; `health`, `metrics`, `livez`, `readyz` are non-SPA segments. Gin's `NoRoute` owns `/` until S9, so the same PR adds `livez` and `readyz` to gin's `nonSPASegments` (`internal/server/spa_fallback.go:74-83`): `/livez/` and `/READYZ` answer 404, not `200 text/html`.
8. Metrics: every ABO series keeps its HEAD name; the kernel's `/metrics` keeps HEAD's reach through `LegacyAmbientScopes` (every non-`Confined()` principal holds `core:metrics.read`; a worker-scoped key never does); the two process gauges stay books' gauges fed by the books status worker. New: `<namespace>_build_info{version}` (the binary's version, never the UI build ID) with the supported level vector; `deploy/prometheus` alert snippets for store level above supported (`<namespace>_storage_level`) and undecodable legacy rows above 0.
9. `core.system.status-changed.v1` (declared by `health` from S8) is native-stream only; it is never added to projection A.
10. Endpoints: native `/api/core/v1/{backup,update,system,health}`; aliases (window W): `/api/v1/backup` (4), `/api/v1/update` (3), `/api/v1/system` (7), `/api/health`, `/api/v1/health`. Permanent: `/health`, `/metrics`. Config: `backup_*` become `core.backup.*`.
11. Boot writers: any boot-time durable write added by an S8 PR extends 06 §6.5.1's writer table and `TestBootCrashMatrix`/`TestBootCrashMatrix_ABO` in the same PR.

**S9: shell**
12. One PR series (07 §7.19 step 4), then step 5, **shipped in one release** (a step-4-only release moves every URL with no redirect). Order inside the series: create `@mediacore/ui-kit` and `@mediacore/shell`, move shell-classified files into `core/web` with audiobook imports cut into books slots; `main.tsx` to `createShell` with the data router; **then** `renderWithProviders` onto `renderInShell`; delete `useUnsavedChangesBlocker`; the shell realtime client replaces `eventSourceManager` and the operations stream, and the Activity page moves to native REST and stream **together** (it stops importing `ops.ts`; `tools/cmd/opsgen` stays until the last `ops.ts` importer is native).
13. ABO's `vite.config.ts` adopts `mediacore({ appId: 'abo', themeStorageKey: 'app-theme-mode', defaultMode: 'dark' })` in the same PR as, or a PR before, the one that passes `UIBundle()` to `app.Options.UI`, because `MustFromFS` fails closed on a bundle without the preset's metas; the image job of that PR boots the embedded bundle. ABO's hand-written inline boot script (`web/index.html:13-30`) is deleted in the same PR (exactly one inline script in the built `index.html`). `UIBundle()` returns a placeholder on an API-only build, never a panic. `main.go` passes `app.Options.UI` and `app.Options.UIOptions`: `PageMiddleware` (Cloudflare service-token recovery from `internal/cfaccess`) and `ConnectSrcFrom` (the Access team host re-read per response), both reading an `atomic.Pointer` books fills in its Start hook, no-ops until then.
14. Books drops `ServesSPA`; gin's `NoRoute`/`setupStaticFiles` SPA serving and the gin `/api/v1/csp-report` handler are deleted **in the same PR**; `ui.Handler` mounts from this build.
15. `ui_route` recording is the kernel's: one `compat.Entry` per `UIDescriptor.LegacyRedirects`; books declares those redirects in the release that moves ABO URLs to `/books/...`. The list `manifest.gen.ts` exports is the same list.
16. Routes: module pages under `/books/...`; shell pages per `ui.ReservedSegments` (`/settings`, `/system/...`, `/users`, `/activity`, `/invite`, `/login/temp` with the token in the URL fragment). From this build core issues invite links as `/invite#token=…`, which the legacy SPA has read since S4 r2. Books' legacy manifest serves `GET /invite/{token}` (Public, `RateAuth`) with a 302 to `/invite#token=<token>` and `Referrer-Policy: no-referrer`; `invite` joins `login` in `LegacyMount.SPAShared`. That 302 is the only implementation for its window (S9 + max(W, invite TTL)). Legacy SPA paths (`/library`, `/authors`, `/series`, `/works`, `/playlists`, `/collections`, `/review`, `/versions`, `/fingerprints`, `/dedup*`) redirect client-side to `/books/...`, plus `/dashboard` to `/`, `/files` to `/books/files`, `/diagnostics` to `/system/diagnostics`, `/operations` to `/activity`, `/maintenance` to `/system`.
17. `localStorage` keys are **read in place, never moved, renamed or copied**: books keys keep their literal names in books' module; the seven shell-bound keys go through `createShell({ legacyStorageKeys })` typed by `LegacyShellKey`; `app-theme-mode` through the preset's `themeStorageKey`. No audiobook key name enters `core/web`.
18. Stale-build rule keeps running in `@mediacore/api-client`'s runtime (both bundles run it). A page load before books' Start serves `index.html` with no panic.
