# Digest S1 — Core module skeleton, leaf packages, staged restore

Normative digest of `docs/specs/platform-core/09-abo-on-core.md` §9.4 "S1" and what it points at. No review provenance in the body; `[n]` marks a footnote with the spec
sections and review IDs behind a rule. Precedence: 03 normative for names, paths and rules; 09 owns sequencing; the owning 05-*/06 file owns how a mechanism works; 04 is a
planning list (the stage PR's build and the guards of 03 §3.5 decide what moves). Counts are informative and regenerated at the stage's base commit [1].

## 1. Goal

- Prove the nested module with real code; move dependency leaves that have no data or API surface; fix the one defect every later rollback argument relies on (a restore must
  not extract over the live store).
- **Release ID:** `S1`. **Trailer** on every commit of an S1 PR that touches a non-doc file: `Stage-Release: S1 1`. **Flip PR: none**: S1 leaves `shipped_stage:` unchanged;
  its first PR sets `release:` to `S1` [2].
- User-visible: a restore now stages and takes effect at the next restart, which the service requests itself by exiting 75 (§9.2.1 row 10, release note in section 6). Metric
  names, scope names and every `le` value are byte-identical to S0.

## 2. Prerequisites

- S0 merged and **released**, and `ci/soak.txt` holds the current `S0` row at least 14 days old: `check_soak.py` refuses an S1 content PR (any `Stage-Release: S1 1` trailer)
  and the `release: S1` change before it.
- Owner checkpoints done: P15 (the unit's journal reaches back more than 14 days, so soak rows can be recorded), the S0 owner actions (sudoers lines, `deploy` recipe copied
  into `Makefile.local`), a fresh archive taken after the reference host ran S0 (needed later for staging).
- Owner action delivered by S1: copy the updated `deploy` recipe from `Makefile.local.example` into `Makefile.local` again.

## 4. Contracts

**4.1 `metrics.Options` (05-metrics §3), the constructor input ABO's façade fills at S1:**
```go
type Options struct {
	AppID string; ServiceName string
	MetricViews     map[string][]float64 // ABO passes telemetry.HistogramBuckets(): every le value stays HEAD's
	MetricNamespace string // default "mediacore"; ABO: "audiobook_organizer"
	MetricPrefix    string // default AppID; ABO: "audiobook_organizer"
	Modules         []string
	ServiceVersion, InstanceID, Environment string
	Prometheus bool; OTLP *OTLPMetrics; Tracing *OTLPTracing
	Redactor *log.Redactor; CardinalityLimit int // 0 = 2000
	PromRegisterer prometheus.Registerer; Logger *slog.Logger
}
```
`MetricViews` is installed as one explicit-bucket view per entry when the `MeterProvider` is built (an SDK view can be set only then). Core holds no app name (03 R1); the table is numbers keyed by names the app supplies.

**4.2 Restore swap shapes (05-storage §5S.3.15 `storage/restorejournal`; copied into `internal/backup` at S1 because the core package lands at S2b).** Intent, written to `<state_dir>/restore/pending.json`:
```go
type Intent struct {
	ID string `json:"id"`; Kind Kind `json:"kind"`; DBPath string `json:"db_path"` // absolute
	Targets []Target `json:"targets"` // absolute from/to
	StagedByBuild string `json:"staged_by_build"` // the binary ID
	PebbleOptions uint64 `json:"pebble_options"` // live open stamp; 0 = no store
	ExpiresAt time.Time `json:"expires_at"`; RequestedBy string `json:"requested_by"`; RequestedAt time.Time `json:"requested_at"`
	ArchiveID, Staging, InstallID, ManifestSHA256 string // restore kinds; json: archive_id, staging, install_id, manifest_sha256, omitempty
}
type Target struct{ From, To string }
const ( KindArchive Kind = "archive"; KindRevert = "revert"; KindCheckpoint = "checkpoint"; KindReset = "reset" )
type Record struct { At time.Time; Step string; Seq uint64; Actor, Note string; Sidecar *SidecarIdentity; Options uint64 /* … */ }
type SidecarIdentity struct{ Device, Inode, Size uint64; MtimeNs, CtimeNs int64 }
func CreateIntent(stateDir string, in Intent) error // temp file + fsync, link(2) to pending.json (EEXIST = slot taken), remove temp, dir fsync
```
ABO's staging sets `kind` to `archive` or `revert` (05-backup §5B.3.4 step 8). The error for a taken slot has the text "storage: a restore or factory reset is already staged or in flight" (`restorejournal.ErrSwapPending`, re-exported as `storage.ErrSwapPending` once `storage` lands at S2b).

**4.3 Staged-restore steps ABO's `internal/backup` implements (05-backup §5B.3.4, followed exactly):**
1. Refuse with the slot sentinel while `restore/pending.json` exists or any `restore/*/inflight.json` or `inflight-checkpoint.json` exists.
2. Verify the archive; check provenance; check compatibility (every owner level in the manifest ≤ the build's, `UpgradeFloor` against the archive's applied versions, **before
  extraction**, refusing an older archive with the stepping-stone message).
3. Pre-validate every rename: staging and each target on one filesystem, parent writable, target not a mount point or single-file bind mount.
4. Extract to `<db parent>/.mediacore-restore/<id>/staging/` on the DB's filesystem (fsync every file, then each directory).
5. Create `pending.json` through `CreateIntent` (expiry, `staged_by_build` = `buildid.Binary`, `pebble_options` = highest `OPTIONS-<n>`), then journal record `staged` in
  `restore/<id>/journal.json`.
6. Return 202 with `restart_required: true`; request a restart that exits **75**.

Boot (ABO's pre-`serve` swap, the S1 equivalent of P0a): reject a stale or foreign intent (`expires_at` passed, `staged_by_build` ≠ this build, or the live highest
`OPTIONS-<n>` ≠ `pebble_options`) by moving `pending.json` to `restore/<id>/rejected.json` and booting the untouched store `degraded` (`restore_rejected`). Otherwise: re-check
staging against the manifest; journal `rechecked`; **rename `pending.json` → `restore/<id>/inflight.json` after `rechecked` and before the first move of step c, never "when
the swap starts"**; rename live items to `previous/` (DB dir and its sidecars `.storage-levels`, `.storage-applied`, `.storage-format`, `.migration-checkpoint`); rename staged
items into place; rewrite the three sidecars from the staged store, journalling `sidecars` with the `.storage-format` stat identity and the staged directory's highest
`OPTIONS-<n>`; journal `swapped`; the terminal step is **`applied` right after the swap with no lineage write** (no `c/storage/boot` before S2b); the in-flight file is deleted
only at `applied` or `swapped_back`. Any failure after the in-flight rename swaps back (idempotent renames: rename only if the source exists and the destination does not). A
journal whose in-flight file exists is **never rejected**, whichever build boots it. No hook runs (there is none before S4 r2) [4].

## 5. Behaviour rules

1. **Lock discipline unchanged.** S1 writes no new store rows; `previous/` is retained (retention keys arrive at S2b).
2. **`make rollback`, `deploy` and the updater refuse while `restore/pending.json` or any in-flight file exists** (`restore_pending`, `restore_inflight`, the message names the
  kind). `ROLLBACK_IGNORE_RESTORE=1` (the one override, both recipes) passes `restore_pending` only; the staged intent is then rejected by the older build's open-stamp move on
  roll-forward; `restore_inflight` has no override ("boot the current build once to finish the swap"). `scripts/storage_format_guard.py` already probes these paths (S0).
3. **Deploy recipe.** The `deploy` recipe in `Makefile.local.example` refuses while a restore is staged or in flight, through the one ssh probe of §9.2.2.
4. **Restart.** ABO's staged restore requests its restart by exiting 75 (from S2 through 06's `Lifecycle.RequestRestart`, which exits `core.lifecycle.restart_exit_code`,
  default 75). A container started without a restart policy stays stopped until started again.
5. **Config stage 0 (ABO-local, no core needed).** Convert the 8 `config.AppConfig` writes that bypass `Mutate` onto `Mutate`; add `TestNoDirectAppConfigWrites` (AST: no
  assignment to `config.AppConfig` outside `internal/config`).
6. **Metrics.** Namespace and scope are injected; the ABO façade passes HEAD's histogram table as `MetricViews` and `telemetry.HistogramBuckets()`; no series is renamed or
  aliased. The seeded series contract test (`internal/telemetrypolicy`) is the normative per-stage check: its golden diff against the S0 build is empty (05-metrics §6).
7. **Guards.** `TestCoreImportsOnlyCore` (`go list -e -deps -test -json` per (GOOS, tag set), read as a union) and `TestCoreHoldsNoAppKeyNames` run over S1's moves into core.
  The core guard's positive control is now a named real edge (not only the synthetic graph).
8. **Concurrency rule (CLAUDE.md).** The moved leaves contain no library-scale loop; any new one declares parallelism. Do not add concurrency to moved code in the move PR.
9. **Toolchain.** `go build ./... && (cd core && go build ./...)` runs with the pinned toolchain (`$(make -s -C core print-toolchain)`).

## 6. Rollback costs (09 §9.2.1)

- S1 introduces **row 10** (staged restores): from S1 a restore only stages and applies at the next restart; the service requests the restart itself by exiting 75, so the
  committed unit and a container with a restart policy come back; while a restore is staged or in flight `make rollback`, `deploy` and the updater refuse;
  `ROLLBACK_IGNORE_RESTORE=1` passes a staged intent whose swap has not started and that intent is then rejected by the roll-forward boot (the admin's restore is discarded,
  not applied later). After a rollback to S0 with the override the staged intent stays in `restore/` until the next S1+ boot rejects it: the S0 updater refuses every manual
  apply until then, and the roll-forward `deploy` needs the override again.
- Release-note text (row 10): "A restore now takes effect at the next restart, which the service performs itself. A container started without a restart policy must be started
  again. Rolling back while a restore is staged cancels it; after such a rollback, updates from Settings are refused until the upgraded release has started once, and the
  upgrade itself needs the same override."
- Everything else: binary swap, no state written, no stored-format change.
