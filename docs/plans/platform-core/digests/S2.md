# Digest S2 — Composition root; core perimeter; `books` wraps the server (releases r1, r2, r3)

Normative digest of `docs/specs/platform-core/09-abo-on-core.md` §9.4 "S2" and what it points at (03, 04 §8.1, 05-http-api, 05-health, 05-logging, 05-metrics, 05-config, 06).
No review provenance in the body; `[n]` marks a footnote with spec sections and review IDs. Precedence: 03 normative; 09 owns sequencing; the owning 05-*/06 file owns how a
mechanism works; 04 is a planning list. Counts (routes, permission-less routes, importing files) are informative, measured at the evidence commit; checks use the values
generated at the stage's base commit [1].

## 1. Goal

- ABO's `main` becomes `app.New(ctx, opts, books.Module(store))` (at S2 books receives the store `serve` opened; from S2b the kernel's handle). Core owns process lifecycle,
  listeners, the typed services struct and the **perimeter**; ABO's whole gin engine is the books module's legacy mount, **permanently**. **Authentication and authorization do
  not change** (gin's `RequireAuth`, permission checks and credential guards stay as they are).
- **Releases, IDs and trailers** [2]:

| Release | Content | Flip PR (sets `shipped_stage:` and `release:` together; carries `Stage-Release: S2 flip`) | Trailer of its content PRs |
|---|---|---|---|
| `S2r1` | composition root, lifecycle, listeners, supervisor timeouts; perimeter still in gin | the PR that switches `main.go` to `app.New` | `Stage-Release: S2 1` |
| `S2r2` | perimeter move (05-http-api H0), except the Basic gate | the PR that removes the perimeter from gin | `Stage-Release: S2 2` |
| `S2r3` | logging stages 1–2, telemetry façade exporter deleted, `PromRegisterer` set | the PR that deletes the façade's exporter and sets `app.Options.PromRegisterer` | `Stage-Release: S2 3` |

- Each release waits for its predecessor's soak row (r1: `S1`; r2: `S2r1`; r3: `S2r2`); each carries the done-checks of its own rows below. Trailer grammar: `<stage>
  <n|flip>`, where `flip` marks the stage's flip PR and names the release the PR sets `release:` to.
- Release-note items (behaviour changes that must be listed): HTTP drain 30 s → `core.shutdown.http_drain` 10 s; stop order of 06 §6.5.2 with budget `core.shutdown.budget` 25
  s (8 s in a container with the key unset); new cross-origin protection for cookie-authenticated unsafe requests; row 12 text (section 7); log file path and levels (r3).

## 5. Behaviour rules — r1 (composition root, lifecycle, mount)

1. **No kernel storage at S2.** The kernel runs without P2/P4 and `Deps.Storage` is absent; `serve` opens the store, runs books' migrations, encryption and `loadConfigFromDB`
  through `internal/startup` before `app.New`. Books migrations 1..`LegacyCap` keep their bookkeeping (`db_version`, `migration_<n>`). No data or key change.
2. **Boot phases at S2 (06 §6.5.1):** P0 `config.NewStore` (EnvPrefix = `Options.EnvPrefix`); P1 `Manifest()` of every module (reserved IDs, `Options.ReservedAPINamespaces`,
  first segment of every `LegacyPrefixes`); **P3 attaches config's DB layer over `Options.LegacyConfigStore`** with DB-override precedence on unlocked keys only (HEAD's
  precedence for legacy keys: a stored value wins over an env default; config calls no `Open` at S2); P5 services; P6 `Register`; P7; P8 builds the root handler (the
  `ServesSPA` mount owns `/`; `ui.Handler` is not mounted and `app.Options` has no `UI` field until S9; gin's `NoRoute` keeps serving the SPA). Run: start hooks, workers,
  listeners, readiness.
3. **Manifest rules.** Every gin route registers as its own mux pattern, **except** each connected set of same-owner routes that ServeMux finds conflicting registers as one
  generalised pattern (`GET /api/v1/operations/{p4}/{p5}` and, in the ABS build, `GET /api/me/item/{p4}/{p5}` at the evidence commit), and only when every member carries the
  same `Perm`, `Guards`, `Public`, `RateClass`, `OwnAuth` with its `AuthMethod`, `BasicExempt` and `NoCompress`; any other conflicting set, and any set holding routes of more
  than one owner, fails manifest generation; `…/operations/v2/{id}` stays its own, more specific pattern; the operations set stays books' at every stage. The 36
  permission-less routes are annotated `AnyAuthenticated`; every `s.perm(atom)` route records `rbac.LegacyAtom(atom)` (accepted by `httpapi` at S2 only in `MountLegacy`
  manifests under `LegacyAuthGin`; evaluated from S4 r2). The legacy handler wrapper clears `r.Pattern` before gin, carries the matched pattern as
  `httpapi.MatchedPattern(ctx)`, and returns 404 when gin's `c.FullPath()` is not a member of that pattern.
4. **Lifecycle.** Stop order of 06 §6.5.2 within one budget `core.shutdown.budget` (25 s; restart-bound, not hot-reloadable; 8 s when `sysinfo.Info.Container` is set and no
  layer sets it); HTTP drain `core.shutdown.http_drain` 10 s. Start order: core background services → hooks → workers → derived components → (served-ledger commit, S2b) → bus
  → executor → scheduler → listeners → readiness. `Lifecycle.RequestRestart(reason)` exits `core.lifecycle.restart_exit_code` (default 75). A hook marked `ExtendsStart` calls
  `Deps.ExtendStart` per batch of progress.
5. **Supervisor settings ship in r1:** committed unit `TimeoutStopSec=60`, `KillMode=mixed` (operation-runner children are not signalled at t=0),
  `RestartPreventExitStatus=78`; `docker-compose.yml` `stop_grace_period: 60s` and `ABO_CORE_SHUTDOWN_BUDGET=25s`; plist `ExitTimeOut` 60; documented `docker run
  --stop-timeout 60`.
6. **State directory.** One resolver from S2 (`ResolveStateDir`): explicit flag or env value never falls back; else the compiled default when it exists or can be created; else
  `filepath.Dir(core.storage.path)` resolved from flags, env **and the operator YAML file** (HEAD's `internal/config/state_dir.go:143-153` rule), with HEAD's WARN. **No
  shipped file sets the canonical state-directory variable** (an `ENV` in a Dockerfile would make it explicit and defeat the fallback, so a container with `--db` on another
  volume would lose its keyring).
7. **Config sources.** The core loader reads the same sources as HEAD: YAML, env and the settings blob through `LegacyConfigStore`. A write through ABO's legacy config path
  (`PUT /api/v1/config`) makes the store's `Changed` fire and the loader republishes the changed live keys. Legacy env names and file keys are `Alias.BelowStored` from here.
  Canonical `core.*`/`modules.books.*` keys are accepted but undocumented. Flags `--port --host --tls-cert --tls-key --http3-port --external-url --read-timeout --write-timeout
  --idle-timeout --workers` feed `core.http.*` and `core.tasks.workers`.
8. **Metrics in r1–r2.** `app.Options.PromRegisterer` stays nil (a private, unserved registry); the S1 façade's provider keeps serving gin's `/metrics`; `ServedMeterProvider`
  hands httpapi's stage 2 that provider so no series is recorded that nobody scrapes. `otelgin` stays on the gin engine, configured as at HEAD (its tracer off), the one
  recorder of every request that reaches gin.
9. **Hello and generated spec.** `core/openapi/core.json` is emitted only by hello's `openapi` subcommand; a PR that adds a core route regenerates it in the same PR.
10. **Concurrency rule (CLAUDE.md).** No library-scale loop is introduced; the startup/serve paths keep HEAD's behaviour.

## 6. Behaviour rules — r2 (perimeter) and r3 (logging, telemetry)

**r2.** The perimeter moves to core stages 0–11 and is **removed from gin in the same PR**: logger, recovery, security headers, CORS, gzip (with HEAD's per-path exclusions,
05-http-api §4.2), tracing, HTTP metrics of core and module routes, and the `/api` rate limiter with per-route `RateClass`. **The Basic gate stays in gin until S3** (it needs
the Basic password, a legacy secret that core config cannot read before `secrets` exists); its per-route exemption stays gin's. Rules:
- **CSP:** the mount supplies `DefaultCSP` per response = today's `contentSecurityPolicy()` (inline-script hash and the Access team host stay); `csp.go` stays in ABO; stage 5
  writes `Reporting-Endpoints: csp="/api/v1/csp-report"` and `X-App-Build` on **every** response, 404 and 410 included; `dev` when nothing is embedded.
- **New (listed in the release note):** cross-origin protection for cookie-authenticated unsafe requests; non-browser clients (no `Sec-Fetch-Site`/`Origin`) are unaffected and
  **no credential type is exempt**; refusals before S4 go to the access log with a `security_event` attribute (audit starts at S4).
- **Client address:** stage 0 publishes it (`ClientAddrFrom`); ABO's `trustedClientIP` (bootstrap, invite and ABS limiters) starts from that value and keeps only its "local
  peer + verified Access assertion" branch.
- **HTTP metrics:** stage 2 records only core routes, module routes and the pre-mount refusals (row 12), into otelgin's instruments through `app.Options.HTTPMetricsScope`; a
  label set both produce is one series; HEAD's `WithoutScopeInfo` stays; pre-mount refusals carry no `http_route`.
- **Perimeter values saved only in the blob** (rate limit, CORS origins, log level) hold at boot and at runtime (`TestPerimeterHonoursBlobOnlyValues`).

**r3.** `app.InstallProcessDefaults` takes over the logger, error-handler, meter-provider, tracer-provider and propagator installs (core packages never call these; R5 exempts
only this helper and `main` packages); the façade's install code and exporter are deleted; the App provider's Prometheus exporter registers on `app.Options.PromRegisterer`
(ABO passes `prometheus.DefaultRegisterer`) so gin keeps serving `/metrics` from one registry until S8; the books telemetry vocabulary stays at its path. Logging stage 1 as
split (05-logging §11): `app.InstallProcessDefaults`, file output, deletion of `setupFileLogging` (`cmd/root.go:698-723`), the second `slog.SetDefault` and `log.SetOutput(aw)`
(`server.go:1134-1155`), **nothing else**: the activity `Writer`'s line parsing, `StandardLogger`'s system-log writes and HEAD's pruner stay until the S5 release that starts
`logjournal`; the activity `Writer` is fed by a books `Logging.Tap` at info through a `slog.TextHandler`. Stage 2: books shim over core handles. File output:
`core.log.output=file`, `core.log.file.path` set by the books module's defaults to a file under the state directory (a release-noted path change). `compat` does not land at S2
(nothing is aliased).

## 7. Rollback costs (09 §9.2.1)

- r1, r3: binary swap, no state written; the previous build serves the same paths and the previous UI bundle is served by whichever build runs.
- **Row 12 (from S2 r2): where a refused request is counted.** A legacy-path request a core stage answers before the mount (429 rate limiter, 413 body limit, CORS preflight
  answer, cross-origin refusal; from S3 a 401 of the Basic gate; from S4 a 401 or 403) is recorded in the same `http_server_*` families by stage 2 without an `http_route`;
  HEAD never recorded preflights or the Basic gate's 401, so those are newly counted; after a rollback below r2 otelgin records them again. `http_server_response_body_size`
  now counts uncompressed bytes (HEAD's gzip ran before otelgin).
- Release note (r2): "Requests refused before they reach a route (rate limited, too large, cross-origin preflights and refusals, the Basic gate's sign-in challenge and, from
  the identity release, requests that are not signed in) are now counted by the core server's HTTP metrics without an `http_route` label, instead of under the route they were
  sent to; preflights and Basic-gate challenges are counted for the first time. `http_server_response_body_size` now measures responses before compression."
