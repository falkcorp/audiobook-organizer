# Digest S5 — Tasks (T0+T1 flip through T8 floor release)

Normative digest for implementers. Source order: 09 §9.4 S5 and §9.4.1, then 03 R4/R6/R7, 04 §8, 05-tasks, 05-events, 05-metrics, 06 §6.6. Where this file and a spec file differ, the spec file wins and the difference goes in the PR description. Bracketed numbers `[n]` point to Footnotes.

## 1. Goal

- Ship **one task system**: v3 authoring on the v2 engine becomes `core/tasks`; `/api/core/v1/tasks` is the one API; every library-scale loop declares `tasks.Parallelism` (09 S5 Goal; 03 R7).
- Releases (09 §9.2.1 grammar): `S5r1` = **T0+T1 in one release, the flip**. `S5r2 … S5r<n>` = one release per later batch T2–T7. `floor` = T8, the floor release, the last S5 release: it ships before the S6 flip, and S6's predecessor is always `floor` (09 §9.2.1, §9.3).
- `ci/stage.txt`: the T0+T1 PR sets `shipped_stage: S5` and `release: S5r1`. Each later S5 release changes `release:` to the next `S5r<n>` in the PR its batch names (T7: the schedule-conversion PR). The T8 PR sets `release: floor`, which is never a `shipped_stage:` value. `compat-rehearsal` runs on both the T7 and the T8 PR. [1]
- Commit trailers on every commit of every PR below: `Stage-Release: S5 1` on T0+T1 content PRs, `Stage-Release: S5 flip` on the flip PR, `Stage-Release: S5 <n>` for T2–T7 (`n` = the release number), `Stage-Release: floor 1` for T8, `Stage-Release: none` for a PR touching no stage behaviour. Then `Co-Authored-By: Claude <noreply@anthropic.com>`. Merge with `gh pr merge <n> --rebase`; never squash (09 §9.2.1 trailer; PLANCOMMON).
- User-visible: executor swap (CPU budget, cancellation fix) over the same stored format; system-log entries written on S5+ are not shown by an older build (rollback row 6, §5).

## 5. Behaviour rules

**Executor and run store**
1. The store keeps HEAD's stored format. `Stores.Runs` is books' `internal/books/taskstore`: HEAD's opv2/opv3 store code with its dual write, HEAD's `opsMu`, moved unchanged in format. It is built **once per process** at P4c and handed to every user, books code included (5T.6.2; `TestLegacyStoresAreSingletons`).
2. Every run, clock, pause and stand-down write goes through `Executor.WriteRuns`/`Stager.WriteRuns`, which commits via `storage.CommitLocked(ctx, open(), storage.Sync, stage, runLocks...)` under `storage.RetryOnConflict`. `runLocks` is the kernel-resolved `RunLocks []storage.Lock` (the kernel asserts `legacy.WriteLock` on `Stores.Runs`, calls `WriteLocks([]string{legacy.LockRuns})`); the executor never imports `legacy`, names a lock or calls `WriteLocks`. The hold spans the first store read through the commit and is re-taken on every attempt. [2]
3. `WriteRuns` is not re-entrant (`ErrWriteRunsNested`). Staging methods check `storage.LocksHeld(b, opsMu)` on the batch they get and refuse with `legacy.ErrRunsNotLocked`. No `stage` calls a books method that takes `opsMu` itself. Core-side mutexes (dispatcher 50, ref-lock table 60, per-run writer 70, progress lock 80) are taken before `WriteRuns` or after it returns, never inside `stage`.
4. `Insert`/`Transition` return `ErrRunConflict` at staging when the read no longer matches `want`; they never retry; `WriteRuns` re-runs build-and-commit. `Prune` and `Recover` commit their own chunks under `CommitLocked`; `ReplaceRows` takes no run lock (HEAD's lock-free path) and is never called inside `WriteRuns`.
5. `Executor.Run` order: `PauseStore.Get`, then `Recover` if `Stores.Runs` implements `legacy.TasksRecoverer` (HEAD's every-boot `ReconcileOpsV3WithV2`; books' start hook ran it until this PR), then `StandDownStore.List` (surviving marker leaves its quiesced runs `interrupted_quiesced` for this boot, clears the marker, WARN), then the resume sweep over `Unfinished`, debounce reload, dispatcher (100 ms), watchdog (30 s), `core.tasks.workers` workers (default 8). Dispatch waits for each def's `Ready` signals via `health.Registry.Wait`; a `books.*` run that reads books is not dispatched before `books.memdb` is Up.
6. Shutdown: flip `shuttingDown`, cancel runs with `ErrShutdown`, wait `min(core.tasks.shutdown_drain (10 s), remaining budget)`, stamp the rest `interrupted`, revoke fences, return before storage closes. One `EXTEND_TIMEOUT_USEC` extension (at most `core.tasks.shutdown_extend_max`, 60 s) only for an `Uninterruptible` run under `NOTIFY_SOCKET`.
7. Boot writers: the def-snapshot upsert `c/tasks/def/<kind>`, `Recover`, the stand-down clear and the resume-sweep transitions are named in 06 §6.5.1's writer table and extend `TestBootCrashMatrix`/`TestBootCrashMatrix_ABO` in the same PR.
8. Parallelism: legacy `registry.RunItems` is re-implemented over `tasks.RunItems` with `Fixed(n, "legacy Concurrency")` from a non-zero `Concurrency`, or `Sequential("legacy zero Concurrency")`, a 1:1 map. Changing a def's parallelism is a separate PR under CLAUDE.md's concurrency rules, never part of T0+T1. `archtest.RunItemsDeclareParallelism` accepts only a constructor, a pass-through typed value, or a `//mediacore:required` field. [3]

**`WriteRuns` is the only commit path.** `OnTerminal(ctx, b, v)` runs inside the terminal CAS batch and the kernel binds it to notify at S7 (before S7 it is a no-op hook). After each commit the executor publishes `core.task.run-changed.v1`, `core.task.log-appended.v1`, and once per terminal `core.task.finished.v1`; it publishes nothing else and calls no ABO code.

## 6. Rollback costs (09 §9.2.1 rows)

Binary swap at every S5 release; the previous build reads every run, clock, pause marker and stamp in its own format (no stampede, no double fire, no prerequisite re-run).
- **Row 5:** a run of a task kind the older build does not register is dropped by its resume sweep and runs again on schedule after roll-forward; an `opstate:` to checkpoint move resumes from zero once (T2).
