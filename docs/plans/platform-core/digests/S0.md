# Digest S0 — Groundwork, guards, gates and build paths

Normative digest of `docs/specs/platform-core/09-abo-on-core.md` §9.4 "S0" and what it points at. It holds the rules an implementer must follow, with no review provenance;
`[n]` marks a footnote that names the spec sections and review IDs behind a rule. Precedence (09 header): 03 is normative for names, paths and rules; 09 owns sequencing and
windows; the owning 05-*/06 file owns how a mechanism works; 04 is a planning list. Counts quoted here are informative, measured at the evidence commit; a check uses the value
generated at the stage's base commit and the stage record (`docs/plans/platform-core/stage-ledger/S0.md`) records both [1].

## 1. Goal

- Make every later stage buildable, reversible, gated and measurable. S0 changes nothing in stored data shape and moves no ABO runtime package into core; it creates the nested
  module, the guards, the gates and the build paths.
- **Release ID:** `S0` (one release). **Trailer on every commit of an S0 PR that touches a non-doc file:** `Stage-Release: S0 1`. **Flip PR: none.** S0 leaves `shipped_stage:`
  at `pre-S0`; the PR that first commits `ci/stage.txt` is the one creation case and sets `release: S0` [2].
- **User-visible changes (each needs its release-note line, quoted in 09 S0 "User-visible changes"):** 1. Updater hotfix: unattended apply (scheduled apply and the
  maintenance-window step) becomes check-only; health reports `auto_update_paused`; Settings shows a banner; a manual apply refuses a release that is not newer, reports a
  describe-suffixed build as "local build, not compared" and refuses a store below the new binary's floor; a restart after an update exits 75. 2. The six early fixes (05-authn
  §11.1; ship here or earlier as ordinary fixes, not as a rollback floor). 3. Reload banner (`StaleBuildBanner`). 4. `/health` reports `version`; new flags `--version-json`,
  `--print-storage-levels`, `--print-upgrade-floor`. 5. `/api/<name>/v<N>/…` is reserved and no longer redirected to `/api/v1/`. 6. Every response carries `X-App-Build`. 7.
  New subcommands `staging-restore` and `staging-scrub`.
- Early-fix 5 note for the release text: "If Basic authentication is on without a saved password, save one before upgrading; if you are locked out, set `BASIC_AUTH_PASSWORD`
  and restart." [3]

## 4. Contracts

**4.1 `buildid` (03 §3.3; 03 §3.6 "Build identity").**
```go
package buildid
func Binary(version string) (string, error) // version + "+" + SHA-256 hex of the running executable; no ldflags, no .git
func Commit() string                         // debug.ReadBuildInfo vcs.revision
```
`Binary` is the binary ID. It is never the UI build ID. No Go link step receives any build value; delete
goreleaser's dead `-X main.commit` / `-X main.date` (`.goreleaser.yml:33-34`) in the PR that adds `--version-json`.

**4.2 `storage/keys` (05-storage §5S.3.3).** Exactly these signatures:
```go
type Seg []byte
func Str(s string) Seg; func Bytes(b []byte) Seg; func U64(n uint64) Seg; func Time(t time.Time) Seg
func Join(segs ...Seg) []byte; func Prefix(segs ...Seg) []byte
func Split(key []byte) ([]Seg, error); func PrefixEnd(prefix []byte) []byte; func ValidName(s string) error
```
Encoding: each segment `0x00 → 0x00 0xFF`, terminator `0x00 0x01`. Test: `TestJoinOrderMatchesSegmentOrder`.
Notation: `c/storage/served/<owner>/<level>` = prefix bytes `c/storage/` + `Join(Str("served"), Str(owner), U64(level))`.

**4.3 Guard types (05-storage §5S.3.7), implemented in `internal/database` at S0, moved into core `storage` at S2b.** `type Levels map[Owner]int`; `LevelTooNewError{Owner;
Store, Supported int; Source string}` (`"stamp"|"sidecar"|"legacy-stamp"`); `LegacyGuardProjection{StampKey, MarkerKey, SidecarSuffix string; LegacyMaxFormat int; Stage
func(ctx, r LegacyRange, b *Batch, value int, marker bool) error}` with `LegacyMaxFormat = 1` at the evidence commit (a raised store projects `LegacyMaxFormat+1`, which every
pre-guard build refuses); `StagingMarker{ArchiveSHA256, Nonce, BinaryID string; At time.Time}` (JSON `archive_sha256, nonce, binary_id, at`); `Duty`, `DutyJournal =
"journal"`, `Owed{Since, Detected time.Time}`.

**4.4 What the store records from S0 (09 §9.2.2 table).** Every boot is guard-aware:

| Record | Written | Rule |
|---|---|---|
| `c/storage/install` | first guard-aware boot | **before any other `c/` key**; on an empty store in one batch with every owner's level stamp at the build's level and every applied-step record below the lowest `Seed` step |
| served ledger `c/storage/served/<owner>/last` + duties; owed `c/storage/owed/<duty>` `{since, detected}` | every boot | `last` replaced only after books' store finished its startup steps; owed duties stay until their consumer commits |
| foreign-open record `c/storage/sidecar_identity` `{device, inode, size, mtime_ns, ctime_ns}` + staged `pending` | every boot; every sidecar rewrite in the same batch as its stamp | new identity staged as `pending`, committed with the served-ledger commit |
| Pebble open stamp `c/storage/pebble_options` `{num, pending}` | every boot lists the DB dir for the highest `OPTIONS-<n>` before `pebble.Open` | staged `pending`, promoted with the served-ledger commit |
| sidecars `<db>.storage-levels`, `<db>.storage-applied` | every boot rewrites from stamps and bookkeeping | applied sidecar lists `<owner> version <n>` per owner, header `install <install_id> epoch <n>`, written **after** the commit that applied the step |
| staging marker `<db>.staging` + `c/storage/staging` | `staging-restore` only, into its own copy | see 6.9 |

All owners are served at level 0; S0 raises no level; the legacy projection stays at format 1. Register reserved families `c/` and `m/` in `keyfamilies.go`. HEAD-era builds
ignore these keys (`TestLegacyToleratesNamespacedKeys`).

**4.5 Fast exits.** `--print-storage-levels` (one `<owner> <level>` per line), `--print-storage-format` (kept), `--print-upgrade-floor` (an `UpgradeRequirement` `{release,
owners:{<owner>:<version>}}`; empty until the floor release), `--version-json` printing exactly `{app, version, commit, ui_build_id, binary_id}`: `app` the app ID; `commit` =
`vcs.revision` suffixed `+dirty` when `vcs.modified`, `""` when absent; `ui_build_id` the embedded bundle's UI build ID (`dev` when nothing is embedded); `binary_id` =
`buildid.Binary(version)` [7].

**4.6 Release IDs, marker and ledger formats (09 §9.2.1).**
- Release grammar: `^(S0|S1|S2r[1-3]|S2br[12]|UI0|S3|S4r[12]|S5r[1-9][0-9]?|floor|S6|S7|S8|S9|S10|H1|H2|H3|H2H3)$`, ordered `S0 < S1 < S2r1 < S2r2 < S2r3 < S2br1 < S2br2 < S3
  < S4r1 < S4r2 < S5r1 < … < floor < S6 < … < S10`; `UI0` is off the chain.
- `ci/stage.txt`: `shipped_stage:` (`pre-S0` < `S2r1` < `S2r2` < `S2r3` < `S2b` < `S3` … `S10`, then `H1`…) and `release:`. **No `levels:` line, ever.**
- Trailer `Stage-Release: <stage> <n|flip>`, `<stage>` in `S0 S1 S2 S2b UI-0 S3 S4 S5 floor S6 S7 S8 S9 S10 H1 H2 H3 H2H3`; `<n>` is the release number within the stage (`S2b
  2` = `S2br2`); single-release stages use `1`; `Stage-Release: none` for feature work.
- `ci/soak.txt` row: `<release> <landing commit> <binary_id> <commit> <since UTC> <levels> <evidence SHA-256>`; empty at S0.
- `X-App-Build: <UI build ID>` on every response; `/health` gains a permanent `version` field; every boot logs INFO `boot binary_id=<id> release=<release:>` before the store
  opens and INFO `boot levels=<vector>` once boot steps ran.

## 5. Behaviour rules — guard, updater, API surface

1. **Guard open.** Refuse a store newer or older than the build (existing storage-format rule) and any owner level above the build's; write nothing before refusing. A sidecar
  unreadable or missing at open is rewritten from stamps with an error log. A store with no DB directory and no sidecars passes the pre-apply check (a new host can install any
  binary).
2. **Redirect.** `/api/*` → `/api/v1/*` 301 excludes `^/api/(core|[a-z][a-z0-9]{1,15})/v[0-9]+(/|$)` (`server_lifecycle.go:1798`). `TestNativePrefixesNotRedirected`;
  `TestCollidingNamespacesStillRedirect` unchanged; `curl -s -o /dev/null -w '%{http_code}' <abo-url>/api/core/v1/ping` returns 404.
3. **`X-App-Build` source.** ABO's `main` reads the UI build ID from the `<meta name="mediacore-build">` of the bundle it embeds (before S2); `dev` when nothing is embedded;
  `dev` never triggers the reload check.
4. **UI build-ID rule (one text, 07 §7.6.3).** Generated by `npm run build` itself (ABO's `vite.config.ts`): `BUILD_ID` from the environment when non-empty (must match
  `^[A-Za-z0-9._-]{1,64}$`, else `vite build` fails; `dev` in any case is reserved and fails; an empty value falls through); else, when `git status --porcelain
  --untracked-files=no` is empty, `<short sha>-<commit unix time>`; else `<UTC timestamp>-<8 random hex>`. Written only into the meta tag; no ldflags, no Vite `define`, no
  boot-time comparison. `TestBuildID_HeaderEqualsEmbeddedMeta` also asserts, for every `embed_frontend` artefact, that the meta is neither `""` nor `dev`. `buildId.test.ts`
  has the cases.
5. **Reload check.** `apiFetch` offers a reload when `X-App-Build` differs from the ID read once from the meta at page load, and when the header is missing on a 2xx/4xx
  response that carries a `Reporting-Endpoints` header naming a `csp` group (a pre-S0 server); a 502 or an access interstitial carries neither and never counts.
6. **Updater hotfix** (`internal/updater/updater.go`, `scheduler_maintenance_window_op.go:72-91`): restart exits **75**; keep the previous binary as `<exe>.prev` (do not
  delete `.old`); compare with `golang.org/x/mod/semver` and refuse a target that is not newer; a current version with a `git describe` suffix (`-<n>-g<hex>` or `-dirty`) is a
  local build: report "local build, not compared", and a manual apply refuses unless the operator names the version. Before the swap run `<exe>.new --print-storage-levels`
  (fall back to `--print-storage-format`) against the sidecar and `<exe>.new --print-upgrade-floor` against `<db>.storage-applied`; refuse `stepping_stone_required` naming the
  release the new binary prints. An empty floor passes without reading the sidecar; a non-empty floor with no sidecar refuses with "boot any release ≥ S0 once". Both
  unattended apply paths are check-only for the whole extraction; a manual apply stays available behind the credential guard and the same checks. The service user reads
  `restore/` directly, never through `sudo`.
7. **Boot refusal exit.** The floor-release refusal exits 78 and prints `install <release> first` last (the floor release itself is T8; S0 ships only the reader of this code
  in `deploy-wait-ready.sh`).
8. **Early fix 6** (`apiKeyMu`): every `apikey:` writer takes `apiKeyMu`; `TestLegacyRevokeRacesTouch_NeverUnrevokes`. The Basic gate refuses an empty stored password and lets
  `BASIC_AUTH_PASSWORD` apply while the stored one is empty, in memory only and logged. The Basic password is never moved. The revocation journal is not part of S0.
9. **No config data change** and no op-ID teach at S0. `internal/backup` writes `<archive>.manifest.json` (`legacy-abo/0`, carrying the writer's `binary_id`) beside every
  archive and removes it wherever it removes `<archive>.sha256` (retention, `DeleteBackupIn`).

at every stage. A staging copy is inert at every boot; the first boot is discarded by the boot-budget A/B. A production store never carries a marker.

## 7. Rollback costs (09 §9.2.1)

S0 introduces **no row** of the twelve-row table. Rollback is a binary swap; the state written (`c/storage/install`, served ledger, foreign-open record, open stamp, two
sidecars) is ignored by older builds. Consequences to state in the stage record: `make rollback` S0 → HEAD passes the guard (restore probe passes on a store that never staged
a restore); a second `make rollback` cannot go back past `.prev`; after a later S1+ rollback to S0 with `ROLLBACK_IGNORE_RESTORE=1`, the S0 updater refuses manual applies
