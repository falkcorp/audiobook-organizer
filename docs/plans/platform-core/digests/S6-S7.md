# Digest S6–S7 — Events/outbox/realtime, then integrations/library/index/notify

Normative digest for implementers. Source order: 09 §9.4 S6 and S7, §9.2.1 to §9.2.3, §9.10; 03 R4/R6; 04 §8; 05-events, 05-realtime, 05-metadata, 05-ai, 05-download, 05-library, 05-notify, 05-storage; 06 §6.6. Where this file and a spec file differ, the spec file wins and the difference goes in the PR description. `[n]` points to Footnotes.

## 1. Goal

**S6** ships one notify-only bus with one topic catalog, one durable outbox and one resumable, permission-filtered SSE hub; the three legacy SSE streams become core projections. No webhook is on the outbox until S7.
**S7** ships capability contracts in core with ABO's adapters behind them, one integration-instance registry over the one stored format, per-instance HTTP resilience, the search index behind `storage/index`, and notify v1 (mail and webhooks), built in one stage. `internal/plugin` is deleted.

Release IDs and trailers (09 §9.2.1; grammar `…|S6|S7|…`):
- `S6`: single release. Live PRs before the flip carry `Stage-Release: S6 1` (including the `c/outbox/` PR); they merge only after the predecessor's soak row (`S5` last release, ID `floor` if T8 has shipped, else the current `S5r<n>`) exists and pass the per-PR prev-build tests. The flip PR (deletes the S5 bridge, `registry.EventHub`, hub A and the v3 broker) carries `Stage-Release: S6 flip` and sets `shipped_stage:` and `release:` to `S6` together.
- `S7`: single release. Live PRs (including the `c/integrations/instances/` PR) carry `Stage-Release: S7 1`; the flip PR (deletes `internal/plugin`) carries `Stage-Release: S7 flip` and sets both lines to `S7`. S7's flip needs the `S6` row.
- Every commit also ends with `Co-Authored-By: Claude <noreply@anthropic.com>`; merge with `gh pr merge <n> --rebase`, never squash.
- Each flip PR needs a current predecessor soak row at least 14 days old and runs `make compat-rehearsal` (required check). S6 R-test cells: a, b, c (ABS). S7: a/b when a UI call moves. [1]

## 2. Prerequisites

- S5 shipped, and the predecessor row is current: the row of the release `release:` names when the first S6 PR merges. The release order is `S5r<n> < floor < S6` and a backwards `release:` move is refused, so T8's `floor` release, if it ships, ships before the S6 flip (this is read from 09 §9.2.1's order, not stated by 09 S6; see footnote [12]).
- S7 also needs S6's soak row, and `core.integrations.disabled` honoured by `providerhttp.Acquire` (staging boots of any S7+ binary carry it in the operator layer).
- S7 needs the outbox (S6) and `health` readiness core (S5). Notify needs `c/outbox/`; the updater (S8) later needs notify.
- Re-verify anchors at each stage's base commit; all counts are informative (14 alias counts, 12 event types, 18 versus 20 importers of `internal/plugin` are evidence-commit figures; the done-check uses the generated count).

## 5. Behaviour rules

**S6**
1. The bus is notify-only and lossy under its drop policy; durable intent goes through the outbox (05-events 5E.5.4). Outbox rows from S5 and earlier are untouched; nothing correctness-critical rides the outbox before S7.
2. Legacy streams `/api/events`, `/api/v1/operations/events`, `/api/v3/ops/events` are **core projections** of the one hub with their legacy framing. Books obtains each handler from `Registrar.Realtime().Projection(p)` in P6 and mounts it in its gin manifest at the legacy path (`AnyAuthenticated`, `NoCompress`; per-event topic filtering inside the hub), counted on surface `sse`. They are not `httpapi.Alias`es.
3. Projection A's topics are `core.task.*`, `books.book.changed.v1`, `books.system.status-ticked.v1` from S6 on and **do not change at S8**: `core.system.status-changed.v1` (declared by `health` from S8) is native-stream only and is never added, so stream A's `system.status` payload never changes and needs no ledger row. `system.status` frames stay byte-shape-equal to S5's.
4. The flip PR deletes the S5 bridge, `registry.EventHub`, hub A and the v3 broker in one change. Until then they stay (the PR that removes any of them earlier breaks stream parity).
5. UI: no change. The SPA keeps `eventSourceManager` on legacy URLs; the shell's realtime client replaces them at S9.
6. Rollback: binary swap. The `c/outbox/` rows are left unprocessed by S5.

**S7**
7. **No import, no mirror, no grant, no new field on a legacy row.** `integrations` serves ABO's existing instances (Deluge `download/deluge`, AI endpoints `ai/<id>`, metadata sources, each webhook URL as `notify/webhook-<n>`) through books' legacy store in `internal/books/configstore` over their blob fields and secret rows. A legacy-backed instance reads `Local=true`; no migration, nothing to confirm. `notify/email` is not legacy-backed (HEAD stores no SMTP setting): operator values are an in-memory overlay; a stored one is a native row.
8. Legacy-backed instances: a `Put` changing destination or secret fields, creating a legacy-backed instance, or setting `auth_ref` to an operator-held secret needs `ProtectAdmin`; a field HEAD's format cannot hold answers 422 `ErrFieldNotStorable`. With auth off, those rows stay editable as at HEAD (no integration needs an `ABO_CORE_*` name). Env-bound values (Deluge, OpenAI) are an in-memory overlay, never persisted.
9. Webhooks: `legacy_headers` on (`X-Audiobook-Event`, `X-Audiobook-Signature-256` kept); plus one global `Rule` for the configured event list mapped to `books.*` topics. Books publishes its 12 legacy event types through `module.Deps.Notify` (`Publish(ctx, b, n)`, outbox-backed, in the batch of the state change, refused for topics books does not own). Undelivered entries older than `core.notify.max_age` (default 24 h) are dead-lettered and counted.
10. `library`, `integrations/ai`, `integrations/providerhttp`, `storage/index` call books' `legacy.LibraryRootSource`, `ai.JobStore`, `providerhttp.GateStore`, `index.DirtySet` over `import_path:` (+ books root from the blob), `aijob:`/`aijob_batch:`/`aijob_payload:`, `provider_throttle:`/`provider_daily_budget:`, `idx:sidx:dirty:`. Books' scanner, autoscan and filesystem handlers update a root's `LastScan`/`BookCount` through the root store's **field-merge** method, never a whole-struct rewrite; the root store keeps books' memdb `import_paths` table current in the same code. That conversion is S7's flip PR.
11. No books row rewrite: books keeps `BookVersion.TorrentHash`/`BookFile.DelugeHash` and builds `download.ItemRef{Instance: <Deluge ref>, ID: …}` at the call site.
12. AI metrics: HEAD's AI families keep names and label values, recorded by **books' AI recorder** through `ai.WithObserver` (`Observer.Attempt`, per-HTTP-attempt `Observer.Transport`) as the one owner of every `ai_*`/`ai_dispatch_*` family. Moved files create none of HEAD's AI instruments; core records only `<namespace>_ai_*`.
13. No package-level throttle or quota map (`archtest.TestNoGlobals` on moved code). Per-instance resilience: one bucket, one breaker, one hold, one quota counter set per `Scope`.
14. Native `/api/core/v1/integrations/{kind}/...` and `POST /api/core/v1/integrations/{kind}/test`; aliases (window W): generic parts of `/api/v1/ai` (14), `/api/v1/deluge` (6), `/api/v1/metadata-sources`. Books Deluge behaviour routes stay on the legacy mount.
15. Config: `deluge_*`, `download_client`, `openai_*`, `ai_endpoints*`, `smtp_*`, `metadata_sources`, `plugins.webhook.*` stay in the blob as instance fields; window aliases for YAML/env names; `OPENAI_API_KEY`/`OPENAI_BASE_URL` stay permanent env aliases; `deluge_move_enabled` etc. move to `modules.books.download.*`.
16. Staging: from S7 a staging boot sets `core.integrations.disabled=true` in the operator layer (locks the key; `providerhttp` refuses every `Acquire` before dialling). Keyed on the binaries that boot the copy, not on the copy's age.
17. Release note (row 8): "Integrations created on this release do nothing after a rollback; events during the rollback are not delivered to them."
18. The search index format is unchanged (or rebuilt; it is derived data).

## 6. Rollback costs (09 §9.2.1 rows)

- **S6: none.** Binary swap; outbox rows are left unprocessed by S5; nothing correctness-critical rides the outbox before S7.
- **S7 row 7:** webhook deliveries pending in `c/outbox/` at rollback are not sent by the older build; on roll-forward they are delivered once or dead-lettered past `core.notify.max_age`. Release note: "Webhooks queued at rollback are delivered after the upgrade, or dropped after 24 h."
- **S7 row 8:** integration instances created natively on S7+ (a second webhook, mail target or download client in `c/integrations/instances/`) do not exist on the older build; events while rolled back are never queued for them. Release note as rule 17.
- A URL S6 changes is effective on roll-forward (legacy blob fields written in place, HEAD format).
