# Normative digest: S3, config and secrets (release `S3`)

Rules an implementer must follow. Sources are the spec files under `docs/specs/platform-core/`; a bare `§` is that file's section. Counts are informative and are
regenerated at the stage's base commit.

## Goal

- Ships: core `config` and core `secrets` become truth for reads and writes over books' legacy config store, in the one stored format of 09 §9.2.3, without changing how
  ABO stores settings or secrets. ABO's `internal/config` becomes the `Facade` over core handles; viper leaves the boot path (core `Load` plus aliases replace it);
  every write goes through `Store.Apply`; the Basic gate moves from gin into the core perimeter. Native apps get encrypted secrets; ABO's plaintext blob secrets stay
  plaintext until the secrets cutover H2. (09 S3 Goal, Releases, Mechanism)
- One release, the flip. Release ID `S3`. S3 lands dark behind its flip, so an RC cut between its PRs never runs half a stage.
- Flip PR: the façade PR. It sets `shipped_stage:` and `release:` to `S3`.
- Trailers: `Stage-Release: S3 1` on every commit of every PR that ships S3 behaviour (any PR touching a package 04 maps to S3) until the flip merges; `Stage-Release:
  S3 flip` on the flip PR. (09 §9.2.1 "The trailer")
- Release-note lines S3 must carry (texts owned by the cited section):
  - settings, secrets and canonical names (05-config §1.12.2 "Release note (S3)"): every setting and secret is still stored where earlier releases store it; a setting
    given only under an `ABO_CORE_*` name is not read by an older release; `ENABLE_AUTH` still loses to a saved sign-in setting; a legacy true/false variable for
    sign-in, the Basic gate or another admin-protected setting must be spelled `1 t T TRUE true True 0 f F FALSE false False` or startup stops; peer networks and tunnel
    connector addresses stay env and file only;
  - "A value such as `ENABLE_AUTH=yes`, which older releases silently read as off, now stops the service at start with a message naming it; use `true` or `false`." (09
    §9.2.5);
  - "API keys can no longer change integration URLs or credentials in Settings; use an interactive admin session." (09 §9.2.6);
  - "From this release `--log-level` and `--playlists` override the value saved in Settings." (09 §9.2.6);
  - the Basic gate's 401 is now counted by core's HTTP metrics without an `http_route` label (row 12 text, 09 §9.2.1).

## Behaviour rules

Decode parity (05-config §1.3.6; 09 §9.2.5)
1. A legacy env name or file key decodes with HEAD's per-type rule named by `Alias.Decode` before `Convert`; canonical names keep the strict decoder. Env names are
   case-sensitive and matched exactly; legacy file keys match case-insensitively; an empty env value is unset.
2. A legacy bool that `strconv.ParseBool` rejects is a boot error when its canonical key is under `core.auth.` or is `ProtectAdmin` or higher; the error names variable,
   spelling and canonical name. Elsewhere it reads `false` with one warning, as at HEAD.
3. `TestLegacyEnvDecodeMatchesHEAD` joins `extraction-gates`; HEAD's side is built from `PREV_REF`; the S3 PR commits its output as `testdata/legacy_decode.golden`,
   which later stages compare against.

Precedence and locks (05-config §1.3.5; 09 §9.2.5)
4. Every legacy env name and file key HEAD lets the blob override is `BelowStored`: it feeds the default layer, a stored value beats it even when equal to the default,
   it locks nothing. Canonical `ABO_*` names lock. The flag is generated from HEAD's lists and never applies to a `ProtectOperator` or `FileOnly` key.
5. `FileOnly` keys (HEAD `json:"-"` fields) are `ProtectOperator` while the legacy store is attached: never staged, never read from the DB layer. `core.auth.mode` keeps
   HEAD precedence: a stored `enable_auth` beats `ENABLE_AUTH` both ways; `ABO_CORE_AUTH_MODE` locks.
6. A `BelowStored` name of a `ProtectAdmin`+ key that differs from the stored value is listed in `AttachReport.Shadowed`, logged at warn, and health reports
   `config_legacy_name_shadowed` (carried by HEAD's degraded token list until S8). A compose default (`BASIC_AUTH_ENABLED=false`, `BASIC_AUTH_USERNAME=admin`) goes to
   `DeployDefaults` at info and raises no token.
7. An empty stored Basic password counts as no stored value: a non-empty `BASIC_AUTH_PASSWORD` is used in memory only, never written, with one warning; with neither,
   the gate is fail-closed.
8. `--log-level` and `--playlists` win over a stored value from S3.

Write path and storage (05-config §1.12.2; 09 S3 Mechanism, §9.2.3)
9. A key with `Alias.LegacyBlob` is read and written in place in `setting:config_blob`, legacy JSON shape. A key with no legacy name is stored under `c/config/`, never
   in a legacy row. A key never moves between the two.
10. Every secret stays where HEAD keeps it: the four encrypted rows (OpenAI key, Google Books key, Hardcover token, Basic password) in HEAD's cipher, in place; every
    other secret in the blob in plaintext. Nothing is moved into `c/secrets/`, copied, or replaced by a sentinel. `c/secrets/` and the keyring hold only secrets of keys
    with no legacy name. `Kept(name)` reports which names are legacy.
11. One commit batch per `Apply`: blob re-rendered from `GetForUpdate` bytes replacing only changed fields (an unset writes this binary's default and never removes the
    field), `c/config/` sets, staged secret writes; no audit record at S3 (rule 16). It commits through `storage.CommitLocked` holding the `SettingsLocks` the kernel resolved by calling
    `WriteLocks` with `legacy.LockConfigSettings`; config and secrets never call `WriteLocks`. Books' staging methods refuse a batch without the hold (`ErrNotLocked`).
12. The gap-fill write to `<db parent>/config.yaml` is a post-commit step the store registers with `storage.OnCommitted`; it renders from the rows read inside the hold.
    Core writes only the twelve settings and three encrypted secrets HEAD's `SaveConfigToFile` manages and keeps every other key. (`TestCoreWritesOnlyHEADGapFillKeys`)
13. Books' store is the only writer of the blob and the four rows (`TestOnlyLegacyConfigStoreWritesSettingsRows`, an instance of
    `TestLegacyFamiliesWrittenOnlyByLegacyStores`). `POST /operations/set-internal-flag` refuses any key of a store-interface family
    (`TestSetInternalFlagRefusesConfigRows`).
14. `legacy.ConfigOpener.Open` writes nothing and runs at P4d step 1(i), before `secrets.Open` at step 1(ii), so the legacy key material is captured as `k0-legacy`. The
    corrupt-secret repair never runs on a core build. The legacy key file, the keyring and `c/secrets/meta` are boot writers: add rows to 06 §6.5.1 and extend
    `TestBootCrashMatrix` and `TestBootCrashMatrix_ABO` in the same PRs.
15. No import, mirror, level step or contract exists for config. Storage levels stay 0; a rollback is a binary swap.
16. At S3 the committer logs each committed change at INFO after the commit (section, changed key names, actor = `Override.By`; never a value) and stages no audit
    record: `audit` first lands at S4 (04 §8.1; 06 §6.4.10). From S4 the same batch also stages the `core.settings.update` record (05-config §1.3.3).

Auth-off rules and `HEADAuthOffWritable` (09 §9.2.6; 05-config §1.3.1, §1.3.7, §1.12.1)
17. The S3 façade fills `config.Actor` from gin's request context with HEAD's rule: `Can("core:admin")` holds iff the permission set came from the seed `admin` role or
    auth is off; `Interactive` is `MayChangeCredentials()` or auth off; `Owner` is HEAD's owner proof.
18. The generator sets `HEADAuthOffWritable` on `enable_auth`, the three `basic_auth_*` keys and every integration-bound blob field of 05-config §1.12.3. It is honoured
    only while the app supplies a legacy config store and the key's value lives in a legacy row. With auth off the auth-disabled principal may then store them after the
    owner-trust-root check, into HEAD's fields (the password into HEAD's encrypted row). A native app never inherits it.
19. From S3 every integration-bound blob field (URL, host, credentials, headers, `auth_ref`, row creation) is `ProtectAdmin` for authenticated principals; a URL-origin
    change clears that instance's stored secret unless the same request re-supplies it. Auth-off installs keep editing those rows as at HEAD.

Basic gate (09 S3; 05-http-api §4.2 stage 8, §8.1)
20. Stage 8 exempts: Public probes; `OwnAuth` routes with a registered compat method; `BasicExempt` routes (`/api/health`, `/api/v1/health`); on the `/` owner the
    `BasicExemptAssets` set (the `/assets/` prefix, `/favicon.ico`, suffixes `.js .css .png .svg .woff2`). Everything else stays gated.
21. Username and password are compared in constant time. An empty username with a password set admits `:<password>` as at HEAD. An enabled gate with an unset, cleared,
    empty or unreadable password answers 401 on every non-exempt route and health reports `basic_gate_no_password`; a presented empty password never matches.
22. The password is a `secrets.Ref` resolved from HEAD's encrypted row through books' store. A gate enabled only in the blob turns stage 8 on even with compose's
    `BASIC_AUTH_ENABLED=false` set.

Deploy files (09 S3 "Deploy files")
23. Shipped unit, plist, compose and `local.conf.example` keep only permanent legacy names for keys that have one and use canonical names only for keys without a
    permanent alias. The four unread names (`AUDIOBOOK_ROOT_DIR`, `AO_DIR`, `AO_DB`, `OLLAMA_BASE_URL`) are deleted or, for `OLLAMA_BASE_URL`, replaced by the name ABO
    reads (owner decides). Compose passes `- BASIC_AUTH_ENABLED`, `- BASIC_AUTH_USERNAME`, `- BASIC_AUTH_PASSWORD` with no `${...:-false}` defaults. P4's scan covers
    the plist and compose files.

## Rollback costs

09 §9.2.1 rows from S3: 1 (settings reset), 2, 3.

| Row | Cost | Release-note text |
|---|---|---|
| 1 | an older build's settings reset leaves values that live only in core records; they return after roll-forward | "After a settings reset on an older release, reset again on the upgraded one." |
| 2 | settings that exist only on S3+ (keys with no legacy name) are ignored by an older build | "Settings that exist only on this release are not applied after a rollback; they return after the upgrade." |
| 3 | a setting given only under an `ABO_CORE_*` name is unread by an older release (canonical-only values are lost on rollback) | "A setting given only under an `ABO_CORE_*` name is not read by a release older than the one that introduced that name. Keep the stored setting (or, for a setting older releases read from the environment, its old variable) at the same value while you may roll back below it. With authentication off, set the Basic gate in Settings, not only through `ABO_CORE_HTTP_BASIC_GATE_*`, so that it stays on after a rollback." |

Everything else is a binary swap (the blob, plaintext secrets and four rows are current on every older build). Row 12 (09 §9.2.1) also starts here, for the Basic gate's 401.
