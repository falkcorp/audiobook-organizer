# Normative digest: S4, identity: auth engine, RBAC, audit (releases `S4r1`, `S4r2`)

Rules an implementer must follow. Sources are the spec files under `docs/specs/platform-core/`; a bare `§` is that file's section. Counts are informative and are
regenerated at the stage's base commit.

## Goal

- Ships one core identity resolver and authorizer for every surface (web, API keys, CF Access, OAuth, ABS); permissions namespaced on the API; admin is `core:admin`; an audit trail. S4 is the one
  stage in which the auth engine changes. Identity rows keep HEAD's representation. (09 S4 Goal)
- **r1 (`S4r1`), dark**: `auth` and `rbac` land with `auth.Store` and `rbac.Store`, their native implementations (hello's) and books' legacy implementations (`Manifest.LegacyStores.Auth`,
  `.Roles`), while gin's auth still decides every request. **r2 (`S4r2`), the flip**: P4d steps 2-4 and P7 seeding start, the `journal` duty is listed, `LegacyAuthCore`, native routes, aliases and UI
  go live, and ABO removes `app.Options.LegacyAuthGinUntil`.
- r1's first PR sets `release:` to `S4r1`; r1 is never a `shipped_stage:` value and has no flip PR. The r2 PR is the flip PR: it sets `shipped_stage:` to `S4` and `release:` to `S4r2`. S4 lands dark
  behind its flip.
- Trailers (09 §9.2.1): `Stage-Release: S4 1` on every commit of an r1 PR; `Stage-Release: S4 2` on r2 content PRs; `Stage-Release: S4 flip` on the r2 flip PR.
- Release-note lines: rows 3, 4 and 11 below (r2's notes carry row 11's text); "With authentication off, credential and backup routes now refuse requests; turn authentication on to use them."
  (09 §9.2.6; the backup half starts at S8); "A missing or wrong confirmation now answers 422 instead of 400." (reset paths, from r2); a note for `auth_disabled_remote` (text not fixed in 09).
  Row 12 (09 §9.2.1) applies too: a 401 or 403 of authentication is counted by core's stage 2 without `http_route`.

## Behaviour rules

r1, dark (05-authn §5; 06 §6.5.1)
1. Core writes no identity or role row. At P4d step 1c a read-only census reads every identity row through books' stores; undecodable rows are counted and listed for P1. Journal re-apply's auth kinds,
   `auth.PostRestore`, `auth.BootWrites` and P7 default-grant seeding are skipped, logged and counted. r1 lists no `journal` duty, so its interval becomes a `gap` line at the first r2 boot.
2. Through r1 books' start hook keeps HEAD's `seedRolesAndTokens` over books' own code: `auth.SeedRoles` (four seed roles), `auth.SeedSystemUser` (`_system`), the never-expiring-key stamp,
   `InitBootstrapToken` (a new token file and hash every start), the optional start-up read-only key. Its token-file writes (`.bootstrap-token`, `.readonly-key`) go through
   `legacy.ConfigOpenEnv.Files` with their 06 §6.5.1 labels. The r2 flip PR deletes it as P7 seeding and `auth.BootWrites` take over, and moves `seed.go` and `bootstrap.go`.
3. The r1 PR commits the frozen reach snapshot `internal/books/rbacreach/legacy_reach_v<release>.json` (a data directory, not a Go package), never regenerated from later builds. `ABO_CORE_AUTH_MODE` is
   read from r1. r1's SPA has no invite-fragment reader. Books supplies the same stores in r1 and r2, so `backends` is unchanged and r2 to r1 never meets `ErrLegacyStoreMissing`.

r2, the flip (05-http-api §8.1, §8.3; 09 S4)
4. `LegacyAuth` becomes `LegacyAuthCore`: stage 12 binds the principal, stage 13 enforces each manifest route's `Perm` and `Guards`. The same PR removes `LegacyAuthGinUntil` (an archtest fails if it is
   set after S4). The bridge never authenticates; its adapters enforce through `rbac.Require`, and every raw `auth.Can` becomes `legacyauth.Can(ctx, rbac.LegacyCheck(atom, readSide))` per the snapshot.
5. Legacy routes require the full legacy reach: a role principal needs `Catalog.LegacyReach(atom)`; a key of a legacy store passes iff the atom is in its stored atoms (or the list is empty) and its
   owner's roles satisfy that reach; the auth-disabled principal is judged against the atom's expansion. The legacy `/metrics` entry stays `AnyAuthenticated`.
6. P4d step 2 (revocation re-apply), 3 (post-restore hooks), 4 (`auth.BootWrites`: `_system`, expiry stamp, bootstrap token and file, read-only key, `AuthReconciler.Reconcile`) and P7 seeding start.
   Books' start hook no longer runs `ReconcileVerifiedEmails`. Seed roles are read-only (`ErrSeedRoleLocked`; `accept-seed` allowed); `admin` is locked; P7 writes HEAD's seed atoms (`TestLegacySeedAtomsEqualHEAD`).
7. Native routes under `/api/core/v1`: `/auth/*`, `/me`, `/users/*`, `/api-keys/*` (05-authn §4.13: `GET /api-keys`, the admin list, `core:users.manage`; `GET`/`PATCH`/`DELETE
   /api-keys/{id}`, the key's owner or `core:users.manage` with dominance), `/roles/*`, `/audit`, `/permissions`, `/settings`, `/settings/schema`, `/modules`, `/ui/diagnostics`, `/ui/csp-report`,
   `/system/factory-reset`. Aliases from r2: `/api/v1/auth/*` (22), `/api/v1/users/*` (15), `/api/v1/me`, `/api/v1/setup`, `/api/v1/config` (2), `/api/v1/preferences` (3); the gin routes they replace are
   deleted in the same PR except the unmapped one. Every `core.json` regeneration lands in the PR that adds the route.
8. Alias targets: `POST /api/v1/auth/api-keys` to `POST /api/core/v1/me/api-keys`, or with body `user_id` to `POST /api/core/v1/users/{id}/api-keys` (selector `user_id`); `GET /api/v1/auth/api-keys` to
   own `GET /api/core/v1/me/api-keys`, or with `all=true` to `GET /api/core/v1/api-keys` (05-authn §4.13; selector `all`), chosen only for a principal holding `core:users.manage`, because
   HEAD answers a non-admin's `all=true` with its own list; `GET`/`PATCH`/`DELETE /api/v1/auth/api-keys/:id` to `/api/core/v1/api-keys/{id}` (one target). An unmapped field is 400 `legacy_field_unsupported`. `PUT /api/v1/auth/me/password` is
   not aliased: it stays one gin route, with and without `user_id`, calling the dominance-checked `auth.Service`.
9. Factory reset: `POST /api/core/v1/system/factory-reset`, `core:admin` + `Guards.Interactive` + `Guards.Owner`, receives `storagehttp.Stager`. `kind` defaults to `factory`; a missing `confirm` is 422;
   `delete_library_files: true` is 422 `library_files_confirm_required`, nothing staged, unless `library_root` and `library_file_count` match a fresh preflight; success is 200 `{reset_id, message}`.
   Aliases: `POST /api/v1/system/factory-reset` passes `delete_library_files: true` and `library_confirm=legacy` (HEAD's wipe); `POST /api/v1/system/reset` passes `reset_kind=store`; each lists `kind`,
   `delete_library_files`, `library_root`, `library_file_count` in `Selector`, keeps HEAD's `{data: {message}}` shape and answers 422 where HEAD answered 400. The same PR deletes `legacy.Maintenance`,
   `module.StorageHandles.Maintenance` and the gin handlers; through r1 the gin routes call `legacy.Maintenance.StageFactoryReset`.
10. Invite links keep the `/invite/<token>` path form until S9 (`InviteLinkPath`). The r2 SPA adds a reader only for the fragment form: guard `pathname === '/invite' || pathname.startsWith('/invite/')`,
    and `<Route path="/invite" element={<AcceptInvite />} />` prefers `#token=` and strips it with `history.replaceState`.
11. Temp-login: core issues `/login/temp#token=...`; books' manifest rewrites `GET /auth/temp-login?token=` to a 302 to `/login/temp#token=<token>` with `Referrer-Policy: no-referrer`; the legacy SPA
    gets a `/login/temp` route in its unauthenticated and authenticated branches that reads the fragment, strips it and calls `POST /api/core/v1/auth/temp-login/consume`.
12. UI, same build: auth, users and config calls use generated operations; the five hard-coded permission constants and the `APIKeysTab` scope list come from `GET /api/core/v1/permissions`; an ESLint
    `no-restricted-syntax` rule fails any string literal passed to `usePermission`/`useAction`/`hasPermission`, assigned to a `permission` or `*_PERMISSION` property, or used in the key-scope list unless
    it comes from `manifest.permissions` or the generated client; the Users page gains role management.
13. Role-name checks become permission checks at every site of 05-rbac §4.6's inventory (`RequireAdmin`, `adminRole`, `handlers/user.go:285,453`, `mergeActor`, repairs owner apply, `plan.go:342`,
    `ActorIsAdmin`): `Can(core:admin)` key-scoped, or the account's roles compiled role-only. No `RoleName("admin")` test remains. Merge POSTs keep `Guards.Interactive`.

Stored data (09 §9.2.3; 05-authn §11)
14. Rows are HEAD's: raw `sess:` sessions; HEAD's one-time tokens and invites; `abk_` keys holding explicit non-empty legacy atoms (a set that is not a union of whole atoms is 422 `no_legacy_atom`, no
    row); roles legacy atoms only; restrictions are HEAD's fields (`status`, `revoked_at`, blanked hash). No `mck_` key, hashed session, fingerprinted record or grant. User IDs unchanged. New core rows:
    `c/audit/` (append-only) and, from r2, `c/backup/`. A row a store cannot decode is restricted per principal, health reports Degraded naming it, boot continues.
15. Restore (row 11): from r2 the post-restore hook runs with no coverage for a staged restore of any archive made before S8, after an in-place restore during a rollback, and after a `gap` line: every key
    reads HEAD's `"inactive"`, every session and one-time token is deleted.

Identity locks via `CommitLocked` (05-authn §3.4; 09 §9.2.3, §9.9)
16. Books' identity store implements `legacy.WriteLock`. The kernel calls `WriteLocks` at P4c with the six names and hands `auth` the result as `Deps.Locks` and `RestoreDeps.Locks`; `auth` never imports
    `legacy` or calls `WriteLocks`. HEAD's `apiKeyMu`, `inviteMu`, `userWriteMu`, `sessionWriteMu`, `bootstrapMu`, `userMergeApplyMu` span core's commit. Mapping: `PutUser` `LockUsers`; session writes
    `LockSessions`; key writes `LockAPIKeys`; invites, identities, allow-list `LockInvites` (an account-creating accept adds `LockUsers`); bootstrap `LockBootstrap` (the redeem adds `LockUsers`,
    `LockAPIKeys`); `RevokeSignInsBefore` `LockSessions`+`LockInvites`+`LockBootstrap`; `StageMerge` `LockMerge`; `Reconcile` `LockInvites`+`LockUsers`+`LockAPIKeys`; temp-login none.
17. Every batch with an identity write (auth's writes, the post-restore hook, `BootWrites`, journal re-apply, the caller of `StageUserMerge`) is built and committed inside `storage.CommitLocked`. Staging
    methods take no mutex: they check `storage.LocksHeld(b, l)` and refuse with `storage.ErrNotLocked`. No `stage` function calls a books method taking a covered mutex (`MarkInviteEmailSent`,
    `RecordInviteGuestPolicy`, `RehashUserPassword`). One instance per legacy store family. Rank order `userMergeApplyMu` < `bootstrapMu` < `inviteMu` < `userWriteMu` < `sessionWriteMu` < `apiKeyMu` <
    `configBlobSaveMu` < `opsMu`; `counterMu` is not one of them.
18. Early fixes hold through core: fix 6 (revoke vs touch), fix 2 (an empty effective key cannot mint), fix 3 (a revoked key is terminal), fix 4 (`Can(core:admin)` key-scoped), fix 1 (no token in the
    session list); fix 5 is the S3 Basic gate.

Config, auth-off and `HEADAuthOffWritable` (09 S4 Config, §9.2.5, §9.2.6; 05-authn §4.11; 05-config §1.3.7)
19. Aliases `oauth_*`, `cf_access_*`, `basic_auth_*`, `enable_auth`, `owner_email` map to `core.auth.*` (owner and CF keys to `modules.books.identity.*`) and decode with HEAD's rules (the S3 corpus is
    generated from the alias table). Sign-in keys are `ProtectAdmin`; owner-trust-root keys (`core.auth.mode`, provider `allowed_emails` and `allowed_domains`, `core.auth.owner.required`,
    `modules.books.identity.{owner_email,cf_access_team_domain,cf_access_aud}`) are `ProtectOwner`. `enable_auth` and `ENABLE_AUTH` keep HEAD's behaviour exactly (a stored value beats the
    environment both ways); `ABO_CORE_AUTH_MODE` is an additional canonical name that locks.
20. Auth-off: the synthetic principal holds no `AuthRequired` or `Sensitive` scope and no admin flag; always-authenticated admin kinds answer 401. From r2 every `Guards.Interactive` route refuses it.
    Legacy routes and adapted op starts keep HEAD's auth-off reach (expansion); in-handler sites carry an `auth_off: pass|deny` column and a `deny` site keeps denying.
21. `core.auth.disabled_allow_remote` defaults to `true` for ABO (`DefaultDisabledAllowRemote`); health reports Degraded `auth_disabled_remote` with a Settings banner, carried by HEAD's degraded token
    list until S8.
22. `HEADAuthOffWritable` keys on ABO (`core.auth.mode`, `core.http.basic_gate.{enabled,username,password}`, every integration-bound field) stay writable by the auth-disabled principal after the
    owner-trust-root check, into HEAD's fields. Every other `ProtectAdmin` or `ProtectOwner` key is refused (403) with auth off through the `/api/v1/config` alias.

Ambient scopes and confinement (09 §9.2.6; 05-rbac §6.3)
23. ABO passes `LegacyAmbientScopes` = `core:self`, `core:metrics.read`, `books:reading`; never stored. `Compile` decides `Confined()` first, then adds them after the key intersection to a principal that
    is not confined. For a key the test is its effective set: owner role atoms intersected with the expansion of the key's atoms (empty list means the role set), never the owner alone. `Freeze` refuses
    the option on a native role store and any scope that is `Sensitive`, `AuthRequired`, `Confining`, `*:settings.manage` or `*:integrations.manage`. `core:system.status` is not ambient. From S8 `/metrics`
    requires `core:metrics.read`, held through the ambient scopes. `TestWorkerKey_NoAmbientScopes` runs at every stage from r2.

Process
