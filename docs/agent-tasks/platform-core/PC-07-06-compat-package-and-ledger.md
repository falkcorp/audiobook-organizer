## Code contract (09 §9.2.9, copied exactly)

```go
package compat

type Surface string // "http", "config", "env", "rbac_atom", "task_kind", "sse", "webhook", "ui_route"

type Gate uint8
const (
	GateWindow    Gate = iota
	GatePermanent
)

type Entry struct {
	Surface   Surface
	Legacy    string
	Canonical string
	Ledger    string // row ID in the merged ledger
}

type Ledger struct{ /* unexported */ }
func (l *Ledger) Register(e Entry) (*Handle, error) // ErrDuplicate, ErrUnknownSurface, ErrNoLedgerRow
func (h *Handle) Use(entry string)
```

Add (names coined here, mark them in doc comments): `func Build(appLedger []byte, namespace string, reg
prometheus.Registerer) (*Ledger, error)` (merges `appLedger` with the embedded `core-ledger.md`; a row ID in
both returns `ErrDuplicateRow`), `func (l *Ledger) Seal()` (the kernel calls it before listeners open;
`Register` after it returns `ErrSealed`), and `func (l *Ledger) Rows() []Row` for the tests. Sentinels:
`ErrDuplicate`, `ErrUnknownSurface`, `ErrNoLedgerRow` (spec), `ErrDuplicateRow`, `ErrSealed`, `ErrNonRowContent`
(coined). `Use` increments `<namespace>_compat_legacy_use_total{surface,name,entry}` (labels per 09 §9.10's
metric table), lock-free, never fails, never persists.

## Ledger grammar (decided here; 09 §9.2.9 lists the columns but not the Markdown form)

- A ledger section is a level-2 heading that starts with `## Surface ledger — ` followed by a stage name
  (`S2b`, `S3`, …). Everything outside such sections (the existing v1.1.0 shim notes) is ignored by the parser.
- Inside a ledger section the only allowed lines are: blank lines, one table header, its separator row, and
  table rows. Any other line (prose, a list, a boot-budget figure, a nested heading) makes the parser fail with
  `ErrNonRowContent` naming the line number: that is `TestCompatLedgerHoldsOnlyRows`.
- Table header, exactly, in this order: `| ID | Surface | Legacy name | Canonical name | Flip PR | Shipped
  (release, date) | Earliest removal | Gate | State | Removal PR |`. `ID` is the row ID that `Entry.Ledger`
  names (Planner notes). `Surface` is one of the eight values; `Gate` is `window` or `permanent`; `State` is
  `aliased`, `gone`, `retired` or `removed`; dates are `YYYY-MM-DD`; empty cells are `—`.
- `core/compat/core-ledger.md` uses the same grammar under `## Surface ledger — core` and holds only
  `permanent` rows.

At S2b no surface is registered by any code yet (config and env aliases land at S3), so both ledgers ship
with their headers and **zero rows**; `docs/compat-surfaces.md` gets an empty `## Surface ledger — S2b`
section. Do not invent rows.

## Tests (spec names first)

- `TestCompatLedgerCopyFresh` (root, `internal/books`): `internal/books/compat-surfaces.md` is byte-equal to
  `docs/compat-surfaces.md`; failure message says `run make compat-ledger`.
- `TestCompatLedgerHoldsOnlyRows` (root): the embedded copy parses with no `ErrNonRowContent`; a fixture with a
  prose line inside a ledger section fails.
- `TestCompatLedgerMatchesCode` (root): boot ABO's app in a test (`app.New` with the books module, no
  listeners), take every `Entry` registered, and assert the merged ledger's rows in state `aliased` (and every
  `permanent` row) equal the registered entries by `Ledger` ID, both directions.
- `TestNoContractBeforeSunset` (root): a `window` row in state `aliased` or `gone` whose entry the code no
  longer registers fails while today is before its earliest removal date; a `permanent` row must always be
  registered.
- `TestCoreLedgerRowsPermanent` (name coined here; the row's "a core-fragment row with a window gate fails"):
  parse `core-ledger.md`; any `window` row fails; a fixture with one fails.
- `core/compat` unit tests: duplicate `Register` → `ErrDuplicate`; unknown surface; missing row; row ID in both
  fragments → `ErrDuplicateRow`; `Register` after `Seal` → `ErrSealed`; `Use` increments the counter with the
  three labels under the given namespace and is safe under `-race` from 64 goroutines.

## Planner notes

- **Row ID column.** 09 §9.2.9 lists the ledger's columns without an ID, but `Entry.Ledger` is "row ID in the
  merged ledger" and a duplicate ID across fragments is a boot error. The brief adds an `ID` first column.
- **Counter labels.** 09 §9.2.9's code comment says `{surface,name}`; 09 §9.10's metric table and the digest say
  `surface`, `name`, `entry`. The brief follows the table.
- **Files missing from the row:** `core/app/options.go` (`Options.CompatLedger`), `core/kernel/` (build and seal
  the ledger before listeners), `internal/books/compat.go` (the embed), the metrics golden.
- **The S2b ledgers have zero rows**; the spec does not say which surfaces exist at S2b. The checks start with
  empty sets and gain rows from S3.
- **Header versus byte copy.** The generated copy must be byte-equal to `docs/compat-surfaces.md`, so its
  `file:` header names the source path. The header checker may need an exemption for this one generated file.
- **Constructor and seal names** (`Build`, `Seal`, `ErrDuplicateRow`, `ErrSealed`, `ErrNonRowContent`) are coined.
