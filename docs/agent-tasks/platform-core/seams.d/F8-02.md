# F8-02 seams and coined names

internal/updater/updater.go ==> core/updater/updater.go

F8-02 moved the R0 updater into `core/updater`, added the `core/updater/github` source, the three task definitions, the four unmounted routes in `core/internal/updaterhttp`, `FetchRelease`, the offline command `updater fetch-release`, and the `RELEASE=` branch of `make rollback-restore`. The row is dark: `/api/v1/update/*` answers as before and nothing in ABO mounts a core route. Everything not listed here follows 05-updater §5U.3 to §5U.12 as written.

## Names beyond the spec

| Name | What it is |
|---|---|
| `updater.Option`, `New(opts, deps, ...Option)` | The spec's `Deps` holds concrete service types and has no input for settings, version, state dir, database path or secrets. `New` takes functional Options for them (`WithVersion`, `WithStateDir`, `WithDBPath`, `WithSettings`, `WithMetrics`, `WithExecutableForTest`, `LegacySkipSelfTest`). |
| `updater.TagSource` | Optional extension of `Source`: `Release(ctx, version)`. `Source{Latest, Open}` cannot fetch a named tag, which `FetchRelease` needs; a Source without it makes `FetchRelease` fail with a refusal. The github source implements it. |
| `updater.Binder`, `updater.Env` | How the kernel hands the updater its settings, secrets and state directory at boot. |
| `updater.NewReaderCheck`, `ReaderCheckOptions` | The in-process port of the rollback guard's decision (see TODO "R1-21 follow-up"). Its first caller is the updater's apply and rollback. It refuses a staged swap (`restore_pending`), where the guard script lets a pending intent pass, as 05-updater §5U.12 requires. |
| `Updater.Install(ctx, version)` | Deprecated entry for the gin path: check, download, swap, no restart, no self-test (`LegacySkipSelfTest`). An AST test pins that nothing in core calls it; F8-04b deletes it with the gin routes. |
| `updater.FoundTopicSpec()`, `FoundPayload` | `core.update.found.v1`. Not yet in `kernel.coreTopics`. |
| `internal/updater.CoreOptions()`, `AppID = "abo"` | ABO's `updater.Options`: app id (equal to `books.AppID`, held by `TestAppIDIsTheBooksAppID`), binary name, the GitHub source, `ModeCheck`, and HEAD's asset name `audiobook-organizer-<os>-<arch>` (core's `RawBinary` default). Used by the gin adapter only. |
| `internal/updater.FetchOptions()`, `ReleasedAsset` | `CoreOptions()` with `AssetName` set to goreleaser's raw-binary name `audiobook-organizer_<Title(os)>_<x86_64\|arm64>`, which every published release carries and HEAD's name never matched. `books.OfflineOptions()` passes it as `app.Options.Updater`. `TestReleasedAssetMatchesGoreleaser` renders `.goreleaser.yml`'s template for the build matrix and compares; `TestFetchOptions_FindsThePublishedAsset` fetches against a release that publishes only that name. |
| `github.AllowInsecureHTTP()` | Test-only option of the GitHub source. Without it the base URL and the asset URL must be https and a redirect to another scheme is refused (`CheckRedirect` on a copy of the bound client, before the client's own policy). |
| `updater.DownloadIdleTimeout` (30 s), `updater.DownloadMaxDuration` (15 min) | Bound every core download (`Install`, `Apply`, `FetchRelease`): no byte for 30 s, or 15 min in all, cancels the transfer's context and deletes the partial file. |
| `app.Options.Updater *updater.Options` | Added here; `books.OfflineOptions()` sets it to `FetchOptions()`. F8-04b hands the served App an Options value too and picks its asset name (see the TODO fragment `updater-asset-name-f8-04`). |
| `updater fetch-release --version <tag> --out <path>` | Always listed; at run time it errors when `opts.Updater` is nil. 512 MiB cap, no store read, writes `<path>.part` then renames, runs the result with `--version-json` first. |
| `tasks.Permissions.OwnerRouteOnly string` (out of the brief's file set: `core/tasks/perms.go`, `core/internal/taskhttp/start.go`, `definitions.go`, `start_test.go`, `docs/specs/platform-core/05-tasks.md`) | A reviewed reason a kind is started only through its owner's route. `taskhttp.startRun` refuses it with 403 `tasks.owner_route_only` after the `Start` check, and `can_start` is false in the listing. Set on `core.updater.apply` and `core.updater.rollback`, whose routes need an interactive session on top of `core:admin` (HEAD's `credRoute` on `/update/apply`); the generic route checked only `Perms.Start`. `TestUpdaterTaskStartGatesMatchTheRoutes` ties the routes' `interactive` guard to the flag. The executor does not check it: the kernel's `Starter`, which the owner routes use, goes through `Client.Start`. A module or kernel caller of `Client.Start` is unaffected. |
| `install-staged prev` (root helper op) | `deploy/rollback-helpers/rollback_helper.py`: installs the staged binary as `<bin>.prev`, replacing any `.prev`; it leaves the staged copy, which the recipe deletes (`discard_fetched`). Granted by the existing bare `install-staged` sudoers line. |

## Decisions

- The develop channel stays in ABO. Core's check serves stable only, so the gin path calls `CheckWith` for stable and keeps its own develop branch.
- HEAD's 30 s HTTP client timeout is kept on the gin path: the adapter's default client (30 s per request, the asset download included, as in R0) is bound into the source, and the check also runs under a 30 s context. Core's own downloads (`FetchRelease`, the task path) use the idle and overall bounds above instead.
- The self-test is valid only for releases v0.224.0 and later (the first with `--version-json`); the gin path therefore skips it, and `fetch-release` runs it.
- A cancelled self-test is reported as `selftest_failed`.
- The check creates a write-probe file in the executable's directory to refuse an unwritable directory before downloading.
- The rollback recipe fetches to the helpers' `stage_bin`, not to `<prev>.fetched` as the brief said: the deploy user cannot write the bin directory. The fetch runs with a scratch `ABK_STATE_DIR` and `HOME` (`mktemp -d`), because a non-service user cannot create the service's state directory.
- `core/updater` names no app: its fixtures are Gotham's, and `TestCoreHoldsNoAppKeyNames` and the archtest stay green. The brief's grep for `audiobook-organizer` in core finds 0.

- `go.mod` (out of the brief's file set): `golang.org/x/mod` moves to `// indirect`, because its only direct user in the root module was the updater's semver code, which now lives in core. `go mod tidy -diff` (`make tidy-check`) demands it.
- `Updater.Install` stays `Deprecated:`; the adapter's one call carries `//lint:ignore SA1019` with the reason, so a second caller is still flagged.

## Owner-hands

The `install prev` operation is in a root-owned helper. The deploy host needs the bundle reinstalled (`docs/system/deploy-and-gpu-ops.md`, "Rollback helpers") and `stage_bin` set in `/etc/audiobook-organizer/rollback.conf` before `make rollback-restore RELEASE=<tag>` can finish. Until then the recipe refuses before it changes anything.

## Trust note

`fetch-release` downloads from the real release source over https, enforced: an http base URL or asset URL, or a redirect to http, is refused. This build has no checksum or signature for the asset (archive download, checksums and signed manifests are deferred, 05-updater §5U.3), so the `--version-json` self-test and the level comparison are the only checks on the fetched binary.
