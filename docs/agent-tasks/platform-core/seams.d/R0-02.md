# R0-02 seams and coined names

Names this task added that later rows may rely on (implementation plan §(n) rule 5).

| Name | Where | What it is |
|---|---|---|
| `database.ErrAPIKeyRevoked` | `internal/database/pebble_store_auth.go` | Sentinel (`errors.New("api key is revoked")`) that `PebbleStore.SetAPIKeyStatus` returns for a transition to `active` on a row whose `Status` is `revoked` or whose `RevokedAt` is set. It writes nothing. `PATCH /api/v1/auth/api-keys/:id` maps it to 409 with `errors.Is`. |
| `TestLegacyAPIKeyAuth_RevokedAtRefusedWhateverStatus` | `internal/server/middleware/auth_revoked_test.go` | Unit test: the web key path (`handleAPIKeyAuth`) and the ABS key path (`ResolveAPIKey`) each refuse a row with `Status: "active"` and `RevokedAt` set, and accept the same row with `RevokedAt` nil. |

## Rules later rows inherit

- Every writer of an `apikey:` row takes `PebbleStore.apiKeyMu`: `CreateAPIKey`, `SetAPIKeyStatus`,
  `SetAPIKeyExpiry`, `TouchAPIKeyLastUsed`, and user merge's owner rewrite (`ApplyUserMergeOps`).
  `RevokeAPIKey` goes through `SetAPIKeyStatus` and must not take the lock itself (`sync.Mutex` is not
  re-entrant). `apiKeyMu` is never held while taking another store lock. A new writer of the family takes
  the same lock.
- `POST /api/v1/auth/api-keys` from an API-key caller (`auth.MethodAPIKey`) answers 403 when `scopes` is
  empty. The check runs after the expiry clamp, so a key with nothing to clamp to is still refused for that
  reason first.
- A nil caller permission set is the empty set for every caller: no requested scope passes the subset check.
