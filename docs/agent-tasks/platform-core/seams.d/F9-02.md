# F9-02 seams and coined names

Names and obligations this row leaves for later rows (implementation plan §(n) rule 5). F9-03 reads it.

## Slice 0: web/ resolves @mediacore/shell and @mediacore/ui-kit

| Name | Where | What it is |
|---|---|---|
| `@mediacore/shell`, `@mediacore/ui-kit` | `web/package.json` (`file:../core/web/packages/...`, like `@mediacore/api-client`) | Symlinked into `web/node_modules/@mediacore/`; their `dist/` is built by `scripts/ci/build_web.sh deps` and, for a bare `npm ci` in web/, by `scripts/ci/ensure_core_web.sh`, in the order api-client, ui-kit, shell. |
| `resolve.dedupe: SINGLETONS` | `web/vite.config.ts`, `web/vitest.config.ts` | The list exported by `@mediacore/shell/vite` (the one core's presets and `core/web/scripts/check-singletons.mjs` use). The linked packages' real path is under `core/web`, which has its own `node_modules`; without it a second React, react-router, MUI or emotion is bundled. |
| `define: { MEDIACORE_CORE_VERSION }` | `web/vitest.config.ts` only | vitest reads the shell from source (the `development` condition), and the shell reads this build-time global. The `mediacore()` preset defines it for builds and `vite serve`. |
| `web/src/test/coreWebWiring.test.tsx` | web | Proves resolution and one React / one MUI+emotion: it fails with "Invalid hook call" and a default-spacing assertion when the dedupe is removed. |

Obligations for F9-03:

- Replacing `resolve.dedupe` in `web/vite.config.ts` with `mediacore(...)` also supplies the `development` conditions and `MEDIACORE_CORE_VERSION`: delete the `define` in `web/vitest.config.ts` only if vitest then gets the same define another way, and keep a `resolve.dedupe: SINGLETONS` in `web/vitest.config.ts` (the preset is not loaded there).
- Run `node core/web/scripts/check-singletons.mjs web/dist` on the first build whose entry imports the shell: nothing imports it before then, so the check has nothing to read today.
