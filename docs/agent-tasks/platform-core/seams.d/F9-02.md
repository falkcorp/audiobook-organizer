# F9-02 seams and coined names

Names and obligations this row leaves for later rows (implementation plan §(n) rule 5). F9-03 reads it.

## Slice 0: web/ resolves @mediacore/shell and @mediacore/ui-kit

| Name | Where | What it is |
|---|---|---|
| `@mediacore/shell`, `@mediacore/ui-kit` | `web/package.json` (`file:../core/web/packages/...`, like `@mediacore/api-client`) | Symlinked into `web/node_modules/@mediacore/`; their `dist/` is built by `scripts/ci/build_web.sh deps` and, for a bare `npm ci` in web/, by `scripts/ci/ensure_core_web.sh`, in the order api-client, ui-kit, shell. |
| `resolve.dedupe: SINGLETONS` | `web/vite.config.ts`, `web/vitest.config.ts` | The list exported by `@mediacore/shell/vite` (the one core's presets and `core/web/scripts/check-singletons.mjs` use). The linked packages' real path is under `core/web`, which has its own `node_modules`; without it a second React, react-router, MUI or emotion is bundled. |
| `define: { MEDIACORE_CORE_VERSION }` | `web/vitest.config.ts` only | vitest reads the shell from source (the `development` condition), and the shell reads this build-time global. The `mediacore()` preset defines it for builds and `vite serve`. |
| `web/src/test/coreWebWiring.test.tsx` | web | Proves resolution and one React / one MUI+emotion: it fails with "Invalid hook call" and a default-spacing assertion when the dedupe is removed. |

Obligations for F9-03:

- Replacing `resolve.dedupe` in `web/vite.config.ts` with `mediacore(...)` also supplies the `development` conditions and `MEDIACORE_CORE_VERSION`: delete the `define` in `web/vitest.config.ts` only if vitest then gets the same define another way, and keep a `resolve.dedupe: SINGLETONS` in `web/vitest.config.ts` (the preset is not loaded there).
- Run `node core/web/scripts/check-singletons.mjs web/dist` on the first build whose entry imports the shell: nothing imports it before then, so the check has nothing to read today.


## Slices 1 to 6: the layout cut into frames, books slots, and the move into core/web

The layout is cut dark: every old path under `web/src/components/layout/` still exports the same names, and `Sidebar`, `TopBar`, `MainLayout`, `UserMenu` and `OperationsIndicator` there are bindings of the shell's frames to the books data. Nothing in `App.tsx` changed.

| `TopBarFrame`, `ConnectionFeed`, `ConnectionState`, `MainLayoutFrame` | same | Top bar with `center` / `actions` / `account` slots and a `connection` feed prop; the page layout over `navItems`, a `topBar` render prop and `banners`. |

Obligations for F9-03:

- Layout duplication. The shell scaffold (`shell/src/app/MainLayout.tsx`, `nav/ShellNav.tsx`) still renders its own layout and its own local `UserMenu`; ABO's real layout is now the frames above. At the flip, point `createShell` at `MainLayoutFrame` and delete the scaffold, rather than keeping both.
- The nav gap. `NavContribution.to` is a `PageId` (or `{page, search}`) with no `matchPath`, no `matchSearch` and no collapsible group, so ABO's sidebar cannot be expressed as `NavContribution`s yet. `SidebarItem` carries those fields. Mapping `booksNavItems` onto `NavContribution` (and extending `NavContribution` or `ShellNav` for groups and match rules) is F9-03's job; do not drop the Library group's selection rule (`isSubItemSelected`).
- `web/src/components/layout/Sidebar.tsx` is referenced only by its own test now (`MainLayout` renders `SidebarFrame` directly). Delete it with the other old-path files.
- The old-path files (`SidebarFrame.tsx`, `sidebarSelection.ts`, `TopBarFrame.tsx`, `MainLayoutFrame.tsx`, `UserMenuFrame.tsx`, `OperationsIndicatorFrame.tsx`, `operationProgress.ts`) are one-line re-exports from `@mediacore/shell`. Re-point their importers (the books slot files and the bindings) and delete them.
- `modules/books/layout/legacyAuth.ts` (`toShellAuth`) exists only to feed `UserMenuFrame` from the legacy `AuthContext`; delete it with the legacy `AuthProvider`.
- Operations status mismatch. The legacy `ActiveOperation.status` is `queued | running | completed | failed | canceled ...`; the shell store's rows carry core's run states (`succeeded`, `timed_out`, `waiting_deps`, `awaiting_decision` ...). `booksRunStatus` (books) and `shellRunStatus` (shell) are the two `RunStatusModel`s; the books one and `useBooksOperationsFeed` go with the legacy store. Moving callers off `completed` is F9-03's, and `OperationsIndicator.tsx`'s Review and Undo buttons in `useBooksRowActions.tsx` test `op.status === 'completed'`: they need `succeeded` once the feed is the shell's.
- Badge semantics. The bell badges `alerts` only. The shell store's default `notifyLevel` raises an alert only for `awaiting_decision` (core's run payload carries no notify level), so a running run does not badge under the default, as a legacy `notify_level` 0 run does. The host must pass `notifyLevel` to `createOperationsStore` for the badge to match today's behaviour.
- `UserMenu` needs `onSaveProfile` and `onChangePassword`; core's client has no route for either yet (`shell/src/api/interim.ts`). The books binding uses `api.updateMe` and `api.changePassword`.
- Bundle. The old-path re-exports mean the running SPA's entry now imports `@mediacore/shell` at runtime (the shell is `sideEffects: false`). On this slice's `vite build` of web/ the check passed (`8 singletons, one copy each, across 36 sourcemaps`); run it again on the first real build after the flip.
- taskKinds and activityPanes. `modules/books/layout/taskKinds.ts` labels 10 legacy def ids (11 kinds) and `taskKinds.core.test.ts` checks them against `internal/books/cutover/kindrename`. The legacy label keys `metadata_fetch`, `ol_dump_import`, `dedup-scan` and `dedup-acoustid-scan` have no def id match and are not carried; add them with a def id. There is no `activityPanes` entry from this row: a pane is a prop-less lazy tab of the Activity page, and the per-operation panel needs an id (it is `renderActivity`). The panes come with the `ActivityLog.tsx` cut (F9-04 and F9-05), and their ids from the books manifest.
