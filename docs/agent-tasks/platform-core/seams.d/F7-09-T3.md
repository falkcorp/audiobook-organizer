# F7-09 T3 seams and coined names

This file lists what F7-09 slice T3 added to `core/integrations`, `core/integrations/ai`, `core/internal/integrationhttp` and `core/storage`, the readings it took, and what F7-09 must do to wire it. T3 ships dark: no production code installs a validator, passes `Options.Probed` or builds a Router.

## Names beyond the spec

| Name | What it is |
|---|---|
| `integrations.SettingsValidator`, `Registry.SetValidator(kind, v)` | A kind's own rule over an instance's settings, installed once per kind. A second install, a nil validator and an invalid kind are `ErrInvalid`. Valid before or after `Load`. |
| `integrations.ImportValidator(reg)` | An `ImporterOption`. The importer runs the kind validator over each imported record. |
| `integrations.Options.Probed func(Ref, Health)` | Called on every probe result, in `observe`, after the `HealthChanged` block. `HealthChanged` still fires only on a status move. |
| `ai.Router.ObserveProbe(ref, h)` | The consumer of `Options.Probed`: a `HealthOK` probe of an ai instance calls `ClearBench`. |
| `ai.RouterOptions.ValidateEndpoints` | Installs `Router.ValidateEndpoint` as the ai kind's validator. Temporary: see the first obligation below. |
| `integrationhttp.ErrHoldChanged` | Now `= providerhttp.ErrHoldChanged` (one value). `*providerhttp.Registry` serves the hold route with no wrapper. |

## Readings taken

- **The validator runs on Put, Test and import; never on the serve path.** A stored row is served whatever a validator would say of it (M1.4 step 2), so installing a validator refuses no existing instance. Put and Test share `shape()`, which now also runs the kind's validator over the effective non-secret layer, after the schema check. A refusal wraps `ErrInvalid` and the validator's own error, so the instance routes answer 422 `validation_failed` and store nothing.
- **An import is judged only when its adapter is registered and of the record's kind.** Otherwise it is kept and reported, as before. The validator is handed the non-secret fields and no stored row. A refusal stages nothing and returns an error wrapping `ErrInvalid`; M6 quarantines on an importer error.
- **`ClearBench` no longer clears a quota bench still in force.** The probe is `GET /v1/models`, which succeeds on a spent balance. A quota bench past its window is cleared, a failure bench is cleared, and a real successful call (`markSuccess`) still ends every bench. This is a behaviour change in a shipped function, but nothing in ABO calls `ClearBench` yet (ABO builds no Router before F7-09).
- **`Registry.validators` has its own lock (`vmu`).** The ai Router is built from the Registry, so the validator is installed after construction and `r.mu` (the writer mutex) is the wrong guard.
- **`specProblems` checks `Spec.Derived`.** Each entry through `DerivedIndex.Validate()`, a name declared twice, and any declaration on a core subsystem (`DB.Derived` issues handles to modules only). This closes the F7-07 seam that said `specProblems` did not call `Validate` yet. It changes what `Open` accepts: a spec that declared a bad entry used to boot and now fails with a `SpecError`. No spec in the repo declares one (the three declarations are on module owners with valid entries).

## What F7-09 must do

1. **Delete `RouterOptions.ValidateEndpoints` and make the ai validator unconditional.** The option exists only because installing the validator by default would change what a Put accepts before the flip. It must not outlive the flip: the point of the hook is that nobody has to remember to turn validation on. In the same change, remove the `if opts.ValidateEndpoints` guard in `NewRouter`, delete `withEndpointValidation` from `ai/harness_test.go`, and update `TestNewRouter_ValidationIsOptIn`.
2. **Rewrite the 7 ai tests that store retired or wildcard ticks through `Put`.** With validation unconditional they fail at the Put. Each must build its row through an importer built without `ImportValidator` (the importer is the path for rows that predate the rule), or assert the refusal instead:
   - `TestRouter_WildcardRejectedOnPut` (router_test.go)
   - `TestRouter_DefaultDenyEmptyTicks` (router_test.go)
   - `TestCatalog_UnknownTickKept` (catalog_test.go)
   - `TestOpenAICompat_ARouterCooldownEndsWithTheHold` (openai_egress_test.go)
   - `TestOpenAICompat_HealthProbeEndsAHold` (openai_egress_test.go)
   - `TestOpenAICompat_RetryAfterIsHonouredUpToTheRoutersCap` (openai_egress_test.go)
   - `TestOpenAICompat_GateAndAdapterAgreeOnQuota` (openai_egress_test.go)

   The last four only Put a capability that was never registered (`gotham.riddle`); registering it first is the whole fix there. The first three exist to prove the router ignores a row that holds a tick the rule would refuse, so they need the importer path.
3. **Wire `Options.Probed` with a closure.** `Router.ObserveProbe` needs the Router and the Router needs the Registry, so `integrations.New(Options{Probed: func(ref, h) { router.ObserveProbe(ref, h) }})` with `router` assigned after `NewRouter` (guard the nil window, or install it under a mutex).
4. **Build the M6 importer with `ImportValidator(reg)`.** The validator is looked up when a record is imported, not when the importer is built, so the order of construction does not matter, but `NewRouter` must have run before M6 imports its first ai record or that record is judged by nothing.
5. **Keep `Options.Probed` cheap.** It fires on every probe, not only on a status move; `ObserveProbe` is one map lookup under the bench mutex.

## Production data the flip has to survive

Can production store a retired or wildcard tick through `Put` today? Not through the HEAD write path: `config.validateAIEndpoints` (`internal/config/ai_endpoints.go`, called from `update_service.go` on a PUT that carries `ai_endpoints`) refuses a wildcard (`"wildcard ... is not allowed"`) and an unknown capability (`"unknown capability ..."`). It runs only on a PUT that carries the key, on purpose: the comment on it says rows stored by a newer binary, with capability IDs this one does not know, must not block an unrelated save, and `AIEndpoint.UnknownCapabilities` exists to report them. So an `ai_endpoints` row can still hold an unknown tick when it was written by a newer or different binary, by a capability retired after the row was stored, or by any path that skips the PUT (a config file, a restore). A wildcard can only arrive that way. HEAD concurrency 0 is valid ("0 means 1") and M6 already maps it with `max(ep.Concurrency, 1)`.

I could not read the production rows (no prod access in this task), so this is from the code, not a count. What it means for the flip:

- **M6 would quarantine a whole endpoint for one retired tick.** `ImportValidator` makes the importer refuse the record, and M6 quarantines the member on an importer error. The ai validator refuses an unknown or wildcard tick. HEAD's rule for the same row is "selection ignores it and the status API reports it", and the spec says unknown ticks are kept and ignored. So an endpoint with `["gotham.riddle", "retired.capability"]` serves at HEAD and would be quarantined after the flip, taking its known capabilities with it.
- **Needed before the flip, one of:** (a) M6 drops the unknown and wildcard ticks from `settings["capabilities"]` before building the record and reports each dropped tick in its migration report (the tick is ignored at HEAD anyway, so nothing that served stops serving), or (b) the ai validator, when called for an import, accepts unknown ticks and only refuses wildcards. (a) keeps the Put rule strict and the stored rows clean, and is the recommendation. Either needs a census first: a dry run of M6 over the production `ai_endpoints` listing every tick `UnknownCapabilities` reports and every `*`. That dry run is the owner-side gate for this flip; it must not be skipped because the unit tests pass.
- **A row that is already in the registry (imported before the validator existed, or by an importer without the option) is served as it is.** The serve path never validates. Its first Put after the flip is refused until the operator removes the bad tick, which is the intended behaviour.
