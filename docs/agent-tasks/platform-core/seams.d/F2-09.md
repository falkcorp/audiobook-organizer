# F2-09 seams and coined names

## Names beyond the spec

| Name | What it is |
|---|---|
| `config.Section[T].Path()` | Coined by the brief. The kernel reads a section's path through it. |
| `Section[T].spec()` (unexported) | Applies the recorded options to a fresh `sectionSpec`. F3-01's `Register` reads a section through an interface with this method. The struct's fields are `path`, `defaults`, `opts`, as 05-config 1.3.1 names them. |
| `coreSections() []any` | Coined by the brief. One `config.Define` value per core section; F2-16 hands it to the store. |
| Test names | `TestCoreSections_EveryOwnerKeyDeclared`, `_PathsValid`, `_NoOverlap` (named by the brief), plus `_NoLaterRowsKeys`, `_TagVocabulary`, `_ReloadAndProtection`, `_Defaults`, `_JSONShape`, `_CoreModulesIsKeyedByModuleID`, `TestDefine_*`. |

## Readings the brief left open

| Topic | Reading |
|---|---|
| Leaf path convention | A struct field with a `json` name is a segment; a struct recurses; every other type, a list and a map included, is one key (05-config 1.3.6). `TestCoreSections_EveryOwnerKeyDeclared` uses it, so F2-04's `windows` map and its schedule fields stay inside the exclusions. |
| `core.modules.<id>.enabled` | The section `core.modules` is `map[string]moduleSettings` (module ID is data, each value holds the one `reload:"boot"` key), so the file form `core: {modules: {books: {enabled: false}}}` matches the owner table. A map-typed section root is the one place the walker expands a map under an `<id>` placeholder. Its declared default is the empty map: the kernel resolves each manifest's `DefaultEnabled`. F3-01 must accept a map-typed `T` for this section, or ask for a change here. |
| Template defaults | `<AppID>_session`, `logs/<app-id>.log`, the compiled state directory, `<state_dir>/storage/main.pebble`, `<db parent>` and the user agent default to `""`: the app fills them at registration, and a literal template must never become a cookie name or path. `core.backup.dir` (`backups`) and `core.diagnostics.dir` (`diagnostics`) are literal relative names in the tables, so they are kept. |
| Host-dependent defaults | `min(4, NumCPU)` and `NumCPU` are computed when `coreSections()` runs. `core.http.rate_limit.burst` is `max(per_minute/5, 10)` at the default per_minute, 20. |
| `core.storage.*` and `core.index.*` protection | 05-storage 5S.7 has no Protection column; its note says every key is `ProtectOperator`, and the `core.index` rows share the table, so all 19 carry `protect:"operator"`. Reload follows the Hot-reload column. |
| `core.library.roots` and `core.library.mappings` | `[]json.RawMessage`. The element types (`RootSpec`, `Mapping`, 05-library 5L.3) are not in `core/library` yet and 05-library gives them no JSON tags; inventing both would be a stand-in. No row in the platform-core inventory owns typing them in this file, so one is owed. |
| `core.tasks.kinds` | `map[string]tasksKindDial`, with `{parallelism_cap: int}` as the table states. `tasks.Kind` and `tasks.KindDial` replace both when `core/tasks` exists; no row is named for that either. |
| Option records | `EnvBinding` is attached to the four OTel names 05-metrics 10 lists (`core.metrics.otlp.{endpoint,interval,insecure}`, `core.tracing.otlp.endpoint`), because the owner table names them. `FailClosed` is attached to nothing (F3-02). |
| `core.log` | `log.Settings` with `log.DefaultSettings()`: the type 05-logging 3 names and R1 already declared in `core/log` (L0, which cannot import config). One type per section, no kernel duplicate. `core.log.journal` and `core.log.schedules` are kernel structs until F5-15 swaps them to the logjournal types (`core/internal/logjournal` does not exist at this base). |
| `core.auth.oidc.providers` | Entries are a local struct with the fields the table lists. `allowed_emails` and `allowed_domains` carry `protect:"owner"` on the element, the list `protect:"admin"`. |

## Differences from the plan commit's counts

05-library 5L.7 has 13 `core.` rows at this base; the brief says 12 and the plan commit `ac4368bdb` had 11. Rows `core.library.protected_paths` and `core.library.schedules.transfer_recover` were added to the spec after it. Both are handled: the first is declared, the second is F2-04's. Every other table matches its brief count (05-tasks counts 18 rows with the rule row).

## Not declared, found while checking the rename table

05-config 1.12.3's rename table targets two keys that no owner table declares: `core.ai.journal_retention` (marked coined, class k) and `core.http.public_base_url` (marked coined, class o). `TestRenameTable_EveryKeyRegistered` (F3-06) needs both registered. Neither is in this brief's scope; a row, or an owner table entry, is owed before F3-06.
