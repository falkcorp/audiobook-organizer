# F7-01 seams and coined names

This file lists what the core integrations registry PR (#4592, re-cut of #4587; 05-metadata M1) added beyond the Go blocks of M1.3: the readings it took where the spec or the brief is silent or contradicts itself, and the seams later rows build on. Everything not listed here follows the spec as written.

## Seams later rows must honour

| Seam | What F7-01 does | Who builds on it |
|---|---|---|
| `NativeImporter` signature | `NativeImporter(ks storage.Keyspace, opts ...ImporterOption) Importer`. The spec names only the keyspace. The audit store comes in through `ImportAudit(rec AuditRecorder)`, and it is required: without it every `ImportInstance` fails, because an import is never unaudited. | F7-08 (books' M6 step) receives the importer; F7-09 (the kernel) builds it with `ImportAudit(<the App's audit logger>)`. |
| `InstanceID` grammar | `InstanceID.Validate` requires `[a-z][a-z0-9-]{0,31}`. The spec's grammar is `[a-z0-9][a-z0-9-]{0,31}`, but an instance's secrets are named `integrations.<kind>.<instance>.<field>`, and a `secrets.Name` segment must start with a letter (05-config §2.3), so an ID like `0dark` could hold no secret. Put and the importer refuse such an ID with `ErrInvalid`, and the operator overlay drops and logs a path that names one. | **F7-08 must normalize** a pre-core instance ID that starts with a digit (for example by prefixing a letter) before importing it, and write the secrets under the normalized name. The spec should be amended to match. |
| The importer never sets `Malformed` | `ImportInstance` clears `StoredInstance.Malformed` and never sets it. `Malformed` means "the stored value cannot be decoded", and a row this importer encodes always decodes. A record whose settings fail the adapter's schema, or whose adapter this binary lacks, is imported as given; the Registry reports it at `Load` as `HealthMisconfigured` (`ReasonInvalidSettings` / `ReasonAdapterNotInBinary`). The spec's "imported with Malformed set" is not what happens. | F7-08: a migrated record that fails the schema is kept and reported, not quarantined. |
| Origins are signatures of the **effective** destinations | `SecretsOrigin`, `LocalOrigin` and `OperatorSecretOrigin` are recorded from, and compared against, the effective view: the stored layer with the operator overlay applied, with scheme, host and port taken from every layer. A signature is `key=origin` pairs in key order, space-separated, one pair even for a single destination (`url=http://192.0.2.1:80`, `host=smtp://192.0.2.2:25`, `alt_url=http://192.0.2.1:80 url=http://192.0.2.3:80`); none (every destination at the adapter default) renders as `adapter-default`. The key is never dropped: see the invariants below. An empty `SecretsOrigin` means "never recorded" and serves no stored secret, so the importer refuses a record that holds a `secrets.Ref` without one. A write that moves no destination keeps the stored secrets with their `SecretsOrigin` as it was (see the next row); only a write that moves a destination, or supplies a secret, records today's. A URL field's origin is `scheme://host:port` with the scheme's default port filled in. The host-and-port pair (`host` + `port`) renders as `smtp://host:port` (M1.3); either part may be empty (the adapter's default), but not both. | F7-08's cutover step computes these fields for migrated rows the same way, with the operator overlay in effect at the time; a mismatch withholds stored secrets and `Local` until a `Put`. |
| Stored secrets bind to the destination, whichever layer moved it | A stored secret is served only while the effective destinations equal `SecretsOrigin`. An operator overlay that moves the destination withholds it, but does not delete it. A `Put` that moves no destination and supplies no secret value (a rename, an echoed mask) keeps every stored secret it does not clear, with its `SecretsOrigin` as it was, so removing the operator value serves the secret again (M1.4 step 2, "removing the operator value reverts to the stored row"). A `Put` that supplies a secret while the stored ones are withheld records today's destination for the new secret and drops the withheld ones beside it. `Test` builds its slot by the same rule. A withheld stored secret is reported as `integration_secret_withheld_destination_moved: <fields>`: `HealthMisconfigured` when the field is required (a static finding, no probe), `HealthDegraded` after the probe when it is optional (down and misconfigured answers stay as they are). The operator's fix is to re-enter the secret or to restore the destination. A draining (swapped-out) instance reads a stored secret only while the committed row still carries the `SecretsOrigin` it was built against; that check and the secret read run under a read lock that every commit-and-publish takes for writing. The invariant this relies on: after `Load` only the Registry rewrites a row (`instancestore.Import` is create-only and refuses a row that exists with other content), so the row check cannot be overtaken by an outside row write, and an outside write of a secret under an `integrations.*` name changes no row and no destination: it is a rotation at the same destination. | Operators changing a destination by env see the new reason and re-enter the secret, or remove the env value (release note, F7-09). |
| `OperatorSecretOrigin` is recorded per destination | An admin `Put` records, for each destination it chooses in whole or in part, that destination's effective origin, which may join the admin's port to the operator's host (R8-5). For a destination the operator supplies whole, the admin chose nothing: the operator's own origin is served by the operator rule, and the stored value under the lock is unseen and not editable. The admin `Put` then carries the entry an earlier admin `Put` recorded for it, and records none if there is none, so a manager's URL hidden under the operator's value is never approved by an admin rename. A non-admin `Put` keeps every entry whose destination it does not move, as before. | **Residual, pinned by `TestOperatorSecret_AdminSaveDuringOperatorHostReplacesApproval`:** the host-and-port pair has one entry. When the operator sets the host beside an admin's port, an admin `Put` must record the joined origin (`smtp://<operator host>:<admin port>`) to serve the password at all, and that replaces the entry for the admin's own host. Once the operator removes the host, the password is withheld at the admin's host until an admin saves again. Removing it needs more than one approved origin per field (a `StoredInstance` schema change, F7-08 impact); not done here. |
| `Local` is one signature | `LocalOrigin` is the signature of every effective destination the grant was made for, and `Local` holds only while the effective signature equals it. An operator value that moves one destination therefore voids `Local` for all of them while it is set (an operator-supplied destination is trusted anyway, by its source), and an admin `Put` with `Local` set during the overlay rebinds `LocalOrigin` to the overlaid signature, so `Local` is void at the stored destinations once the overlay is removed, until an admin saves again. A non-admin `Put` keeps the stored `LocalOrigin`. | **Residual, not raised in review and not changed:** the shape of R8-5's per-field question applied to `Local`. The right fix is a per-destination `LocalOrigin` map (like `OperatorSecretOrigin`), a `StoredInstance` schema change that F7-08 would have to populate; it is the owner's call. |
| Destination fields must be visible | `Register` refuses an adapter whose settings schema has a destination-named property that is neither a URL-typed string (`schema:"format=uri"`) nor a part (`host`, `port`) of a `host`+`port` pair. A name is destination-named when it, or a `_`/`-` separated part of it, is `url`, `uri`, `endpoint`, `host`, `hostname`, `webhook`, `href`, `server`, `proxy`, `address`, `addr`, `ip`, `domain` or `port` (plurals included), or ends in `url`/`uri`. So a port beside a URL, or alone, is refused: it could move the dialled destination without changing an origin. It also refuses any secret, URL-typed or destination-named property below the top level. A prefixed pair such as `smtp_host`/`smtp_port` is refused. The list is a heuristic over names; it cannot see a destination hidden in a field named otherwise (for example a `dsn`). | F7-02 … F7-05 kind and adapter authors: name destination fields accordingly (`base_url` with `format=uri`; core.email's pair as `host`/`port`). **F7-05 (notify/email):** a sender or recipient field cannot be named `*_address`/`*_addr`; use `from`, `to`, `sender` or `*_email`. A recipient list of objects with an `address` member is refused too. |
| M1.10 "Trust carried over" needs `SecretsOrigin` | M1.10's list sets `Local`/`LocalOrigin` and `OperatorSecretOrigin` for migrated instances but not `SecretsOrigin`, and the importer refuses a record that holds a `secrets.Ref` without one. | **F7-08** sets `SecretsOrigin` for every migrated instance that holds a secret: the signature of its effective destinations (stored values with the operator overlay in effect at cutover), rendered as the row above says, or `adapter-default` when none is set, always with its keys (`url=http://192.0.2.1:80`, never the bare origin; a row written with a bare origin is refused by the importer and never matches). `LocalOrigin` uses the same rendering (a signature, not "the origin of its configured URL-typed field" when there are several); `OperatorSecretOrigin` stays a per-key map. The spec should list `SecretsOrigin` beside them. |
| Brief step 7, "wire on hello/coretest": **deferred** | Nothing in `examples/hello`, `core/coretest` or the kernel changes. The brief's Files table names no hello, coretest or kernel path. The members the wiring needs (`Registrar.Adapter`, `Deps.Integrations`, `app.Options.Adapters`) don't exist yet. Registering the `c/integrations/` storage owner (`instancestore.StorageSpec`, baselined as dead code until then) and constructing the Registry are kernel boot calls in `core/kernel/boot.go` and `kernel.go`, files F7-09 owns in W37. The package runs on hello-prefixed fake adapters (`integrationstest`) over an in-memory store in its own tests. | **F7-09** (its step 1 adds the F7 members to `core/module/*` and the boot calls). A hello adapter that exercises the wiring belongs in that PR. |
| Archtest scope | `archtest.IntegrationsDescriptorCallers` loads the core module only. A `NewDescriptor` call in ABO (`internal/`, `cmd/`) is not seen. | **F7-09**, when ABO first imports `mediacore/integrations`, extends the guard (or adds a root `internal/arch` twin) to ABO's packages. |
| The health task | `ProbeAll` is the body of `core.integrations.health`. The task is not registered, `health.changed` is not published, and the scheduled-run clause of `TestRegistry_DisabledMakesNoOutboundCall` is not tested here. | F7-09 with F2-03/F2-04 (task registration and schedule). |
| `Env.Paths` | Omitted; no M1 kind needs it. | F7-06. |
| Version reset across a delete (ABA) | A re-created row starts again at version 1, so a writer holding version 1 of a deleted row can overwrite the new one. This is documented on `InstanceStore`, not prevented. | F7-10's routes, if a client must not write over a re-created instance. |

## Invariants later changes must keep

| Invariant | Why | Pinned by |
|---|---|---|
| **Signatures must carry keys.** `signature` renders every destination as `key=origin`, also when there is one, and `LocalOrigin`, `SecretsOrigin`, the audit `destinations` / `previous_destinations` strings and the slot fingerprint all use it. Any rule that compares destinations compares whole signatures (or per-key maps, as `OperatorSecretOrigin` does), never bare origins. | A bare origin under one key equals the same origin under another key (`url` against `alt_url`), and a URL `smtp://h:25` equals the host-and-port pair `h:25`. A stored secret or `Local` grant bound to one would be served at the other: with `url` unset the adapter's default URL, which nobody approved (SEC-15, R12). The key format is free to change: the registry was never merged and no production rows exist. | `TestBind_*` in `destination_key_test.go`, `TestSignature`, `TestSignatureOneToOne` |
| A signature is one-to-one with the origin map it renders: a key matches `[a-z][a-z0-9_-]{0,63}` (`analyze` refuses any other URL field name), and no origin holds white space (`originOf` and `hostPortOrigin` render such a value as `malformedOrigin`). | Signatures are compared as whole strings and split at the first `=` and at spaces; a value holding either would let two different destination sets sign alike. | `TestSignatureOneToOne` |
| **Only the Registry rewrites an integration row after `Load`.** `instancestore.Import` is create-only and refuses a row that exists with other content. | `secretFor` checks the committed row's `SecretsOrigin` and reads the secret under `secretsMu`, and every commit-and-publish takes it for writing; that sequence is atomic only if no other writer can change the row between the check and the read. An outside write of a secret under an `integrations.*` name changes no row and no destination, so it is a rotation at the same destination. | `TestRegistry_DrainingLeaseNeverReadsTheMovedSecret` in `origin_test.go` |

## Names beyond the spec

| Name | What it is |
|---|---|
| `integrations.New(Options) (*Registry, error)`, `Options` | Builds a Registry; does no I/O. `Options` carries the store, batch factory, secrets, audit, outbound factory, the `ReleaseAuthHold` and `HealthChanged` callbacks, settings, the operator-only instances (`OperatorInstances`), metrics scope, logger and clock. |
| `(*Registry).Register(prefix string, ds ...Descriptor)` (the module's adapter-ID prefix), `Load(ctx, overlay)`, `SetOverlay(ctx, overlay)`, `ProbeAll(ctx)`, `Close(ctx)` | Registration before Load, the store read with the first overlay, the config hot swap, the health task's body, and the drain at shutdown. `SetOverlay` after `Close` is `ErrClosed`. |
| `Settings` | The live `core.integrations` section the Registry reads on each call (M1.7 defaults). |
| `SecretStore`, `AuditRecorder` | The narrow views of core secrets and the audit logger the Registry and importer call. |
| `Trust`, `OutboundSpec` | What providerhttp's egress guard and gate receive per instance. |
| `Tester` | The kind's extra test hook `Test` calls after `Health`. |
| `Kinds()`, `ImporterOption`, `ImportAudit` | The closed kind set; the importer's options. |
| `ErrInvalid`, `ErrForbidden`, `ErrVersionConflict`, `ErrUnavailable`, `ErrClosed` | Sentinels for 422, 403, 409, a store or secrets read failure, and a closed Registry. |
| `ReasonStoredSecretWithheld` (`integration_secret_withheld_destination_moved`) | The health reason of a kept stored secret the effective destinations withhold. |
| `integrationstest`: `Fixture`, `Harness`, `Batcave()`, `Fake`, `FakeInstance`, `FakeTester`, `Outbound`, `Sent`, `Checker`, `As`, `Manage`, `Admin`, `CredentialField`, `CredentialHeader` | The store suite's harness and the fake adapter/outbound used by the tests. |
| `archtest.IntegrationsDescriptorCallerFindings(dir)` | The guard's finding list, for the self-test. |
| `core/internal/instancestore`: `Owner`, `StorageSpec`, `New`, `Store`, `Row`, `RowKey`, `ErrVersionMismatch` | The native store's keyspace implementation. |
