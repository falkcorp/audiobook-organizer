# F5-10 seams and coined names

What the dark conversion of maintenance file group 5 (14 definitions in `itunes_clone_into_library.go`, `itunes_playlist_import.go`, `itunes_regroup.go`, `library_state_repair.go`, `mark_missing_files.go`, `merge_same_path_dupes.go`, `metadata.go`, `metadata_cache_reap.go`, `missing_file_audit.go`, `missing_file_repair.go`, `missing_file_repoint.go`, `move_book_file_rows.go`, `narrator_purge_empty.go`, `narrator_split_joined.go`) added beyond 05-tasks and the F5-10 brief, the readings it took where they say nothing, and what F5-18 must do with them. Everything not listed follows the brief as written, and the layout copies F5-08's (`kinds_t6_g3.go`).

## Names beyond the spec

| Name | Where | What it is |
|---|---|---|
| `t6g5Kinds`, `t6g5KindList` | `kinds_t6_g5.go` | The group's list function (file order) and the package-level function that names it, so tasklint's registration-root rule counts the group. F5-18 replaces both with its `Registrar.Tasks` call and deletes `var _ = t6g5KindList`. |
| `t6g5Deps`, `t6g5Writer`, `t6g5Store` | `kinds_t6_g5.go` | The owner-declared dependencies (R10), composed of small embedded interfaces. `NewWriter` builds the writer per run over `rc.Writer()`; `ScanKey` is the library scan's stand-down key. |
| `headT6g5Writer`, `headT6g5Store` | `kinds_t6_g5.go` | The HEAD adapters over `p.deps`; each method calls what HEAD's body called, in the same order. |

## Deviations from the brief

1. **Cores are plain package functions**, not `(p *Plugin)` methods, so R10 is structural. Shells (`(p *Plugin) runX`, `(p *Plugin) xKind`) stay methods. The HEAD-signature wrappers that only tests called (`planMarkMissingFiles`, `planMergeSamePathDupes`, `planMetadataCacheReap`, `planMissingFileRepoint`, `auditMissingFiles`, `classifyMissingRows`, `moveBookFileRows`, `mbfEnv`, `regroupSDKReporter`, `t6g5Progress.Step/Finalize`, `t6g5OpsStore`, `t6g5SeqPool`) are deleted: their tests call the `...Via` cores through env builders in `kinds_t6_g5_envs_test.go`, and the move kind's HEAD-shell tests run `moveBookFileRowsDef().Run`. `t6g5PlanMissingFileRepair` is the former `...Via` form, renamed with the group prefix.
2. **Extra files** beyond the brief's list: `kinds_t6_g5_atoms_test.go`, `export_t6g5_test.go` (the settings.manage scopes are copied because `internal/books` imports this package), `kinds_t6_g5_envs_test.go`, `kinds_t6_g5_native_test.go`, `kinds_t6_g5_units_test.go`, this note, `scripts/deadcode-baseline.txt` (rows removed with the wrappers) and `testdata/fixer_stores_allowlist.txt` (two sink entries removed with `t6g5OpsStore` and the chapters accessor).
3. **Re-signed internal helpers.** Several helpers (the repoint planner, the move-book-file-rows helpers, the regroup snapshot and apply, `applyRegroupGroup`, `mbfPlanOne`, `mbfResolveOwners`, `applyLibraryStateRepair`, `libraryStateRepairScope`, `bookAuthorNamesForSplit`, `libraryStateRepairStore`) now take a narrow reader or reporter instead of `*Plugin` or the wide store. `mbfProgress` is gone: the HEAD move shell sets `env.Progress` from `t6g5MbfHeadProgress`, which logs a failed progress write the way HEAD did. The regroup user-state methods the apply reaches are the narrow `t6g5RegroupUserState`/`t6g5RegroupStateProbe` interfaces; `(*Plugin).t6g5RegroupUserStateFor` is nil-deps-safe. The clone store keeps only the `OpsStore` narrowing its readers need.
4. **Shared batch-write bodies.** `writeBookFileBatch` and `prewriteHeartbeat` (`bookfile_batch_write.go`) are thin wrappers over `writeBookFileBatchVia` and `prewriteHeartbeatVia`, which take a liveness/progress sink; `t6g5WriteBookFileBatch` and `t6g5PrewriteHeartbeat` call the same bodies with the env as the sink. One body carries one set of tests (the abort-after-N-rows rule, the per-row stamp). The report-path helpers are still re-declared as `t6g5` variants, for a later unification.
5. **Clone `icStore` keeps its field names** (`OpsStore`, `ChapterReader`) because existing tests build it with a keyed literal; forwarding methods carry the rest.
6. **Clone mode.** A native preview clears apply/rollback/repair whatever params say; a live run must name exactly one, else it is refused. The native decode refuses only `dry_run` and `dryRun` for clone: `apply`, `rollback` and `repair` are HEAD's own selectors (the shell's `LiveOneOf`), not the run's mode.
7. **Regroup writer** carries only `t6g5RegroupUserState` (`NewUserStateProbe`, `CarryStateThenHardDelete`, `HardDeleteWithoutUserState`), the three calls the empty-book delete makes. The merge store's other methods are not reachable from a native run, and the compiler enforces it: `UserProgress` is no longer on the writer.
8. **Dropped HEAD fields.** `FormerIDs` on four definitions, `Liveness`, `Cancellable`, `Plugin` and the metadata refresh's `0 6 * * *` schedule have no native counterpart here; the native kind takes `sched(kind)` and F5-18 decides.
9. **No kind in this group checkpoints.** None calls `Checkpoint` or `Restore`, so there is no restore test; each ResumeDrop kind is re-run from the start by design.
10. **Identifier prefix.** Every new top-level name carries `t6g5`. Renamed to meet that: `t6g5MbfHeadProgress`, `t6g5RegroupUserState`, `t6g5RegroupStateProbe`, `t6g5ApplyRegroupPlan`, `t6g5PlanMissingFileRepair`. The method that returns the `t6g5RegroupUserState` interface is `(*Plugin).t6g5RegroupUserStateFor`, so it no longer shares its name with its result type.
11. **Fallbacks kept from HEAD.** `t6g5HeadOpID` falls back from the reporter's ID to the run context's; the clone user-state lookup keeps HEAD's fallback.

## Readings taken

- **Resource names.** Only the constants of `pkg/ops/effects.go` are used, written as `string(ops.ResX)` in every `Effects` and in the test tables, so a coined name does not compile (`TestT6G5Effects_NoResourceNameLiteral` also fails on a literal in a non-test file of the package): `books`, `book_files`, `authors`, `external_ids`, `user_state`, `metadata_cache`, `operations`, `files`. Stores with no constant are declared under the nearest one, not coined: `narrators`, `book_narrators` and `chapters` under `books`; `user_preferences` and `user_playlists` under `user_state`. **Narrator writes (`CreateNarrator`, `DeleteNarrator`, `SetBookNarrators`) are stamped `books`.** The first mapping hides which table a purge or split touches and the second makes playlist-import's whole write set `user_state`; both are accepted (PR body, Review decisions).
- **Known cost of the `user_state` mapping.** Playlist-import now waits behind every `user_state` writer (clone, regroup, merge-same-path-dupes and main's dedup-books, merge-chapter-groups, backfill-itunes-positions), and they wait behind it. The conflict is false (the merge user-state store never touches playlists); correctness is unchanged.
- **Clone declares `files`.** A live clone apply reflinks audio into the library tree (`CloneBookIntoLibrary`, the mixed kind's `Reflink`) and rollback removes the clone files, so clone must not run beside another bytes-on-disk writer (the empty-folder sweep, organize-mess cleanup). **F5-18 obligation:** the plain `os.Remove` calls that delete clone files (mixed-apply cleanup, rollback's file removal and its empty-directory removal in `itunes_clone_into_library.go`) run outside the writer seam and so outside the fence. They must go through the writer, or be covered by the `files` declaration at the point the fence lands; as it stands a fence landing between the last writer call and those removes does not stop them. The report TSVs other kinds write do not count, as `relink-report` declares nothing.

- **Stand-down.** A live run of clone, mark-missing, repoint, move-book-file-rows, purge, split (`t6g5NativeLease`) and metadata-refresh (`t6g5NativeHold`) refuses without a configured scan key ("no scan stand-down key configured") rather than writing unguarded. playlist-import, regroup, repair-library-state, merge-same-path-dupes and metadata-cache-reap take no stand-down, as at HEAD, and a native run of them does not either.
- **Concurrency.** Loops with HEAD `Concurrency: n` become `tasks.Fixed(n, reason)`, the missing-file stat sweeps and the clone repair keep their pools; zero stays sequential.

## Writer stamping contract (method to resource)

F5-18's one books writer must stamp each `t6g5Writer` method with exactly these resources, or a live run is refused with `ErrOutsideEffects`. The table is `t6g5SpyWrites` in `kinds_t6_g5_native_test.go`, which `TestT6G5Spy_MapsEveryWriterMethod` keeps equal to the interface; every live native test checks the resources the spy recorded are a subset of the kind's declared write set. A method with no resource writes nothing of its own.

| Method | Resources |
|---|---|
| `CarryStateBeforeHardDelete`, `CarryStateBetweenLiveBooks`, `CarryStateThenHardDelete`, `ImportSmartPlaylists`, `SetUserPreferenceForUser` | `user_state` |
| `CloneBookIntoLibrary` | `books`, `book_files`, `files` |
| `Reflink` | `files` |
| `CreateBook`, `UpdateBook`, `ModifyBook`, `RecomputeBookAggregates`, `SaveChaptersForBook`, `CreateNarrator`, `DeleteNarrator`, `SetBookNarrators` | `books` |

| `DeleteBookFilesByIDs` | `book_files` |
| `ModifyBookFile`, `MoveBookFilesToBook`, `MoveBookFilesToBookBulk`, `UpdateBookFiles` | `book_files`, `books` |

| `ReassignExternalID` | `external_ids` |
| `RecordOperationChange` | `operations` |

| `HardDeleteWithoutUserState`, `InvalidateAuthorsCache`, `NewUserStateProbe` | none: the first runs the caller's delete (which arrives as `DeleteBook`) after a read-only user-state check, the second drops an in-memory cache, the third reads |

## What F5-18 must wire

- `r.Resources(...)` registrations for the books module, so the registration check (`writes resource kind ... which module books did not declare`) passes for every kind of this group: `books`, `book_files`, `authors`, `external_ids`, `user_state`, `operations`, `files` and **`metadata_cache`** (written by `metadata-cache-reap`; not in F5-18's ten kinds or F5-01's six additions, so it is the one most likely to be missed).

- `t6g5Deps.Store`, `NewWriter` (the writer methods are the ones `t6g5Writer` lists; the user-state calls go through the merge lock) and `ScanKey`.
- Delete `t6g5KindList` and its blank-identifier line.
