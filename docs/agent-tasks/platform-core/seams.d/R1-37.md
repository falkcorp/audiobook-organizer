# R1-37 seams and coined names

This file lists what the coretest harness PR added beyond 06 §6.4.8 and 03 R6: names the spec does not have, readings it took where the spec or the brief is silent, the members that check only what exists at R1, and the seams later rows (R1-15, R1-20, F2-16, F3, F4-08) build on. Everything not listed here follows 06 §6.4.8's code contract as written: `Harness`, `New`, `Boot`, `Option`, `WithModules`, `WithDisabled`, `WithConfig`, `WithUser`, `Harness.App`, `Harness.As`, `Harness.Anonymous`, `Client`, `Client.Do`, `Client.GetJSON`, `AssertPermission`, `AssertRoutesHavePermissions` and `AssertModuleInert`.

## Names beyond the spec

| Name | What it is |
|---|---|
| `archtest.RoutesHavePermissions(t testing.TB, routes iter.Seq[httpapi.RouteInfo])` | 03 R6 and 05-http-api §12 name it without a signature; the brief coins this one. It walks the route records of a built router and fails `t` once, listing every offender as `METHOD PATTERN (owner, name): reason`. |
| `app.App.Routes() iter.Seq[httpapi.RouteInfo]`, `kernel.Kernel.Routes()` | Added to 06 §6.4.5 and §6.4.6 (and the §6.4.10 R1 row) in this PR, by coordinator decision. `*app.App` exposed no router, so `AssertRoutesHavePermissions(t, h)` could not walk "the built router". Each is one delegating line appended to its file. `ContractGoldens(t, r *httpapi.Router)` will need a route source too; it can take this one. |
| `core/coretest/logcapture`: `logcapture.Capture`, `logcapture.New(tb)` | R1-09's `coretest.LogCapture` and `coretest.NewLogCapture`, moved and renamed. Supersedes R1-09's seams row for `coretest`. See "The log capture move" below. |

## The log capture move

`coretest.New` returns an `*app.App`, so `coretest` imports `app`, and through it `kernel`, `module`, `httpapi`, `log`, `metrics`, `rbac`, `auth`, `ui` and `version`. An internal test of any of those packages that imports `coretest` is then an import cycle, and Go refuses to build it. `app/statedir_test.go`, `kernel/kernel_test.go` and `kernel/supervisor_test.go` imported `coretest` for `NewLogCapture`. R1-15's `coretest.MetricsProvider(t, opts app.Options)` imports `app` as well, so the cycle comes from the spec's own signatures, and whichever of R1-15 and R1-37 merges first runs into it.

The capture now lives in the leaf `core/coretest/logcapture`, which imports only the standard library. Its five importers changed one import line and the call sites: `core/app/statedir_test.go`, `core/kernel/kernel_test.go`, `core/kernel/supervisor_test.go`, `core/examples/hello/hello_test.go` and `core/health/flight_test.go`. `coretest` keeps no alias, because an alias would bring the cycle back for anyone who used it from an internal test. **Rule for later rows:** an internal test of a package in `coretest`'s dependency closure uses `logcapture`, never `coretest`. `go -C core test -count=1 -run '^$' ./...` compiles every test package without running any, and it catches a violation.

## Spec readings

| Topic | Reading |
|---|---|
| Authentication at R1 | The brief's check, `git grep -n 'PrincipalFrom(' -- core/httpapi`, counts 1. That count is misleading. `route.go:225` only copies the bound principal into `In.Principal`. The router authorises nothing from it, and `Router.checkPerm` refuses every non-Public native route at `Build` (`ErrNoAuthService`). So the brief's "0 hits" case applies. `WithUser` records the principal. `As` and `AssertPermission` fail the test with `coretest: <member> needs core authentication, which lands at R2's identity flip`. `Anonymous` works. |
| `WithDisabled` | The spec has it write `core.modules.<id>.enabled=false` into the boot record. R1 has neither config nor a boot record, and the kernel reads only `Manifest.DefaultEnabled`. So the harness hands `app.New` the module wrapped to return its manifest with `DefaultEnabled: false`. `App.Modules` reports the reason `"default"`. An ID that `WithModules` did not pass makes `Boot` return an error. |
| `WithConfig` | No config layer exists until F3. `Boot` refuses a non-empty map with `coretest: WithConfig needs core config, which lands at F3 (keys …)` instead of ignoring it, because a setting the App never reads would let a test pass for the wrong reason. |
| Module wrapper | Only a module that boots disabled is wrapped (`watchedModule`): one that `WithDisabled` names, or one whose own manifest says `DefaultEnabled: false`. The second case goes slightly beyond the review's "wrap only the `WithDisabled` IDs", so that `AssertModuleInert` can check the `Register` cell for a module that disables itself. An enabled module goes to `app.New` as the value the test passed. The wrapper serves the manifest, flipped when `WithDisabled` names it, and records whether `Register` ran. The kernel calls only `Manifest` and `Register`. A later optional module interface that the kernel type-asserts of a disabled module must be forwarded through the wrapper. A nil module goes to `app.New` as given, so the kernel's `*module.ValidationError` reports it. |
| Storage, state directory, shutdown | R1 has no storage, so the harness has no in-memory Pebble. `Options.StateDir` is a `t.TempDir()` that no phase reads yet. `Args` and `Env` are empty and non-nil, so nothing reads the process's flags or environment. `New` registers no `t.Cleanup`, for three reasons. `app.New` starts no hook, worker or listener. `Run` would open a listener, which I3 forbids. And `*app.App` has no method that closes what boot built. So the metrics Provider that P5 built stays open until the App is garbage-collected. It is pull-only, a Prometheus registry of its own, so it holds no goroutine and touches no process global. `TestHarness_NoProcessGlobals` measures this: 20 boots leave the goroutine count and Prometheus's default registry unchanged. Core cannot reach otel's global setters at all: the otel root package is not on `archtest/thirdparty_allow.txt`. |
| `TestBootZeroModules` | R1 mounts no core route: `/readyz` and `/api/core/v1/modules` come with their own rows. "Serves `/api/core/v1/*`" is therefore checked as core's claim dispatching: `GET /api/core/v1/health` gets core's problem+json 404. The "health ready" half waits for the row that mounts `/readyz`. |
| `AssertModuleInert` cells at R1 | (1) The App reports the module disabled. (2) The kernel never called its `Register` (06 §6.3 A5); this is checked for a wrapped module, so no hook or worker was recorded. (3) No `App.Routes()` entry is the module's. (4) Only when (1) to (3) find the module not live, every probe answers exactly 404. The probes are `GET` and `POST` on `/api/<id>/`, `/api/<id>/v1/` and each `Manifest.LegacyPrefixes` entry, plus `<prefix>x` for a subtree. When the module is live, no request is sent, because its handlers would run. The assertion never calls module code. A first version listed the module's native routes through `app.Describe`. The independent review rejected that: `Describe` re-runs `Register`, shares the `StateDir`, and fails at R1 on any non-Public native or legacy route (`TestDisabledModuleInert_PermissionedRoute` is the regression test). So a test probes the native routes it knows, as `TestDisabledModuleInert` probes hello's greeting. The spec's other cells are absent, not stubbed: task kinds and schedules, held runs (F2-16), `GET /api/core/v1/modules`, `RecordingFS`, the outbox backlog, the op-ledger gate, and an unchanged keyspace (R1-20). |
| `RateExempt` on legacy routes | 05-http-api §3 says `RateExempt` is "rejected for non-Public routes" on the native `Route`. §8.2's `LegacyRoute.RateClass` is "RateDefault iff the gin chain includes the API rate limiter today, else RateExempt", whatever the requirement, and R1-13's seams leave legacy `RateExempt` rows to R1-14. So the gate refuses `RateExempt` on native and raw routes, Public ones included, because only the infra probes and the SPA handler may be exempt. It accepts `RateExempt` on legacy routes. Under the brief's literal rule ("`RateExempt` on a non-Public route fails" for every kind), ABO's manifest would fail on 2 rows with ABS off (`GET /api/events` and `GET /metrics`, both `AnyAuthenticated`) and 66 with ABS on (those two plus the 64 ABS `OwnAuth` routes). Under this reading it passes with ABS both off and on. That was measured with a throwaway test over `legacyManifest(false/true)`, which is not committed. |
| "A legacy route missing from its manifest" (I4) | Every legacy `RouteInfo` comes from the manifest, so at the `RouteInfo` level a route that the manifest does not cover is one with no requirement. It fails the "no permission" rule. Whether gin and the manifest agree is `(*Server).LegacyManifest`'s drift check (R1-14). |
| Fixtures for I4 | `Router.Build` refuses a native route with no permission or with `RateExempt`, so no router with those defects can be built. The fixtures are `RouteInfo` values, which is what `Routes()` yields. |
| Infra routes and the legacy allowlist | An `Infra` route must be `RateExempt` and require `rbac.Public`, `rbac.AnyAuthenticated` or a set of permissions (05-http-api §4.2). A legacy route is checked against an allowlist, so a requirement kind the list does not name fails, including any future kind. Without `OwnAuth` the list is `Public`, `AnyAuthenticated`, a set of permissions or a legacy atom. With `OwnAuth` the requirement must be `Delegated` and the route must name an auth method. |
| Public routes | A `RouteInfo` does not say whether a Public route was allowed to be Public, so the gate accepts `rbac.Public` on any route, a legacy one included. For a module's native route, `Build` checks it (`ErrPublicNotAllowed` against `Manifest.PublicRoutes`). For a legacy route, the app's own reviewed list does: ABO's `TestPublicRoutesGolden` (`internal/server/legacy_manifest_test.go`, over `testdata/public_routes.golden`) enforces the reviewed Public list. |
| `ContractGoldens` | SPEC-GATED. `grep -c -E '^\s*(Examples?\|Example[A-Z][A-Za-z]*)\s\|func Examples?\(' docs/specs/platform-core/05-http-api.md` prints 0: no `Route` or `RouteOption` field declares request and response examples. |
| `TestSpecGoBlocksCompile` (step 6) | The generated boot program was a `main` that called `app.New`. `coretest.New` needs a `testing.TB`, so each module package now gets a generated `boot_test.go` with `func TestBoot(t *testing.T) { coretest.New(t, coretest.WithModules(m.New())) }`, run with `go test -count=1 -run '^TestBoot$'`. The control snapshots still pass. The reserved-ID refusal reaches the output through `New`'s `t.Fatalf`. |
| `Client` | `Do` serves a copy of the request. Each of `RemoteAddr` (`192.0.2.1:1234`, the RFC 5737 documentation address), `Host` (`example.com`) and `RequestURI` that is empty is filled the way `httptest.NewRequest` fills it. The caller's request is not modified. |

## Seams for later rows

- **R1-15:** in your internal tests of `app` and `kernel`, use `logcapture.New(t)`, not `coretest`. Your `core/coretest/metrics.go` (`MetricsProvider`) joins package `coretest` unchanged. `App.Routes()` and `Kernel.Routes()` are one appended line each in your files. Your move commit 9a5d61dbd matches this PR's byte for byte, but as one commit its rename similarity is 73%, below `check_commits_build.py`'s 90%. This PR splits the move into a pure rename commit plus a separate rename-of-names commit.
- **R1-37 follow-up (after R1-15):** `internal/books/routes_permissions_test.go` boots ABO's real App and runs `archtest.RoutesHavePermissions(t, app.Routes())`.
- **R1-20 (storage):** give the harness its in-memory store (`vfs.NewMem`) through the `app.Options` field R1-20 adds, add `Harness.Storage()` once a `storage.Inspector` type exists, and add `AssertModuleInert`'s unchanged-keyspace cell.
- **R1-20 (#4453):** eight of its files call `coretest.NewLogCapture`. Rebasing over this PR, they become `logcapture.New` from `github.com/falkcorp/mediacore/coretest/logcapture`, and the type becomes `*logcapture.Capture`. An internal test of a package that `coretest` depends on (`storage` is not one yet) must use `logcapture`, never `coretest`.
- **F2-16:** `WithRuns`, `RunTask`, `RunResult` and the held-runs cell of `AssertModuleInert`.
- **F3 (config):** `WithConfig` becomes the overrides layer, and `WithDisabled` writes the boot record (the reason becomes `"config"`). Delete both refusals.
- **F4-08 (identity flip):** fill the bodies of `As` and `AssertPermission`, carry the seeded principal on `Client` (a new unexported field) through `auth.WithPrincipal` in `Do`, and keep the signatures. `As` keeps its unknown-user failure. `TestAssertPermission_Hello` becomes the two-request form of 06 §6.4.8 over a fixture route with a real permission, a user lacking it (403) and a user holding exactly it (neither 401 nor 403). `AssertModuleInert`'s probes stay anonymous: an anonymous 404 is what G1 needs, and 401 or 403 would fail them. `As` calls `Fatalf` on the TB the harness was booted with (`h.tb`), not on the caller's. A subtest that calls it on a harness its parent booted fails with "subtest may have called FailNow on a parent test", so any per-request failure F4-08 adds must not go through `h.tb`. A client method that can fail takes the caller's `testing.TB`, as `GetJSON` does.
- **The row that gives the App a close path, or lets it Run in process without a listener:** register `t.Cleanup` in `New` to close or stop it.

## Decisions (coordinator, 2026-11-07)

- **Log capture move:** accepted. R1-15 was told to use `logcapture.New(t)` in its internal tests of `app` and `kernel`.
- **`App.Routes()` and `Kernel.Routes()`:** accepted. 06 §6.4.5 gains `App.Routes`, §6.4.6's `kernel` row names `Kernel.Routes`, and the §6.4.10 R1 row lists `Routes`. `TestSpecGoBlocksCompile` still passes, and `regen.py` leaves the hello snapshot unchanged.
- **`RateExempt` on legacy routes: a deviation from the brief.** The brief says "`RateExempt` on a non-Public route fails" for every kind of route. The spec wins: 05-http-api §8.2's `LegacyRoute.RateClass` allows `RateExempt` on a legacy route whatever its requirement. So native and raw routes fail on `RateExempt`, and legacy routes may use it. Measured over ABO's manifest (`legacyManifest(false/true)`, throwaway test, not committed): 0 failures under the spec's rule, with ABS off and on. Under the brief's rule there would be 2 with ABS off (`GET /api/events`, `GET /metrics`) and 66 with ABS on (those 2 plus the 64 ABS `OwnAuth` routes).
- **Step 5** (`internal/books/routes_permissions_test.go`) becomes a small follow-up PR after R1-15 merges. R1-37 merges without it.

- **Independent review (2026-11-07), fixed in this PR:** `AssertModuleInert` no longer calls `app.Describe` and sends no request to a live module (M1, M2). The infra rule, the legacy allowlist, nil modules going to `app.New`, wrapping only disabled modules, the `Client` fields, a LegacyAuthCore fixture mount, the `TestPublicRoutesGolden` note, the SPA message naming the rate class, and the cleanup and F4-08 seam wording are in. The review's probes are now `TestDisabledModuleInert`, `TestDisabledModuleInert_PermissionedRoute`, `TestAssertModuleInert_FailsOnEnabled`, `TestHarness_InSynctestBubble`, `TestHarness_NoProcessGlobals`, `TestHarness_ParallelBoots` and the infra and SPA rows of `TestRoutesHavePermissions_RejectsFixtures`.
