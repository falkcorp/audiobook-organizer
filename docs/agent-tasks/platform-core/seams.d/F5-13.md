# F5-13 seams and coined names

F5-13 converts the 45 T7 definitions (44 in `internal/server`, 1 in `internal/scheduler`) to native `books.<ID>` kinds, plus `books.library.scan-full` beside `books.library.scan`: 46 native kinds. They are dark: nothing registers them before the tasks flip (F5-18). This file lists the readings the row took where the brief is silent, the helpers it added, and what later rows build on.

## Seams

- Each package has its own `kinds_t7.go` foundation: `t7Env` (log, progress, cancel, op id, result, items, checkpoint), `t7Hold` and `t7StandDown`, `t7Deps`, `t7Common(head, sched)` and the list function `t7KindList(s, deps, sched)` with a `t7Kinds` method. The scheduler's copy is smaller (it needs one kind) and is a copy, not a shared package: a shared package needs an `internal/arch` layer entry. Drift protection is each package's hand-written `TestT7*KindsMatchHEADDefs` (expectations are not derived from the helpers) and `TestKindAtomScopes_MatchBooksAtomTable` in each package, which compares the scope table the copy keeps (`t7AtomScopes`) with `books.AtomTable` (an external test: `internal/books` imports both packages, so the table cannot be read from them).
- Every definition is split: `<x>Def()` holds HEAD's literal (so `t7Common` derives title, help, timeout, key, priority, resume, permissions and readiness from it), the HEAD shell's Run calls a shared core, and `<x>Native(deps, sched)` is the native shell over the same core. A core reaches stores and writers only through its env.
- Coarse writer and store methods. Where a definition drives an engine in another package or a Server helper, the core calls one method and HEAD's implementation calls the existing function. F5-18's native writer must implement each, over the run's gated writer:
  - Library, files and batch: `OpenBatchApply`, `RunQueuedApply`, `OpenAdvance`, `FetchForBookIDs`, `FetchAll`, `EnqueueContinuation`, `RunHarvest`, `FinishHarvest`, `PerformScan`, `PerformOrganize`, `Transcode`, `RecordVersion`, `FetchBookByTitle`.
  - Authors: `MergeAuthors`, `AuthorMergeDone`, `AuthorsResolved`.
  - Dedup: `ScanBookDuplicates`, `ScanSeriesDuplicates`, `FilterReviewedAuthorGroups`, `PreviewSeriesDedup`, `MergeBooks`, `CleanupMergeCandidates`, `CombineBooks`, `ApplySeriesDedup`, `PruneSeries`, `MergeSeries`, `NormalizeSeries`, `InvalidateSeriesCache`, `OrganizeBook`, `WriteBackBooks`, `InvalidateDedupCache`.
  - Reconcile: `RunReconcileScan` (store), `ExecuteReconcile` (writer).
  - Scheduler: `Ready` and `RunUpgrade` (writer).
- The scan kinds (`dedup.book-scan`, `dedup.author-scan`, `dedup.series-scan`) publish their result to the dedup list cache and write an activity row in HEAD. Natively they drop both and return the result from the Task. The cache feed is a flip or handler decision (F5-18), not this row's.
- Native `dedup.series-dedup` Preview reads through the store side: no writer is built and no activity row is written (HEAD wrote one for a preview).
- `dedup.series-normalize` declares `Writes(series)` as HEAD does, but its organize and write-back also write books and files. Kept 1:1 with HEAD (R7); declare the larger set when the write set is next reviewed.
- `t7ScanController` adapts a `t7StandDown` to `dedup.ScanStandDownController`, which `dedup.DedupSeries` and `MergeSeries` take and acquire and renew themselves. HEAD passes the server (which is the controller); a native run passes the adapter over `rc.StandDown`.
- A native run may lose the result when `Run` returns an error: HEAD stored a report and then failed the run (scan-apply, purge, reconcile apply). The kernel may discard a result returned with an error; F5-18 must decide whether those kinds return the result and no error.
- `folder-auto-scan` starts a goroutine that calls `CheckBookDuplicates` after the core returns, as HEAD does. Natively that is a write through the run's writer after the run has ended. Not changed here.
- `diagnostics.ai-analyze` has a 25h HEAD timeout; the kernel refuses a Timeout over `tasks.MaxTimeout` (24h), so `t7Common` clamps it.
- Counter labels that read running counters are dropped natively (the kernel's per-item label is pure), as in F5-11.
- `sdk.NewProgress` now takes a `sdk.ProgressSink` (the two methods it calls) instead of the concrete reporter interface, so a native env can feed it.
- `t7Store` and `t7Writer` are composed from sub-groups (`t7StoreLibrary` into files, AI and batch, and the same for the writer) to stay under the interface-width ratchet (8 elements).
- `internal/books/testdata/tasklint_exempt.d/F5-13.txt` is deleted, as the brief says. The brief's acceptance line "no added or modified entry file" cannot hold: `F5-18.txt` listed `internal/server/batch_apply_refusal.go`, a file F5-13 now fixes, and `TestTasklint_F518ListsOnlyFlaggedFiles` fails on a line for a file with no finding ("delete the line"). That one line is removed (verified: restoring it fails the test).
- The deadcode ratchet: 90 new identifiers (the foundations and the natives, unreachable from every `main` until F5-18 registers them) are added to `scripts/deadcode-baseline.txt` as a sorted union, as F5-09 and F5-11 did.
- No resource name was coined. Every effect uses a resource declared in `pkg/ops/effects.go`.
