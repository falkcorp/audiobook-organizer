# F5-12 seams and coined names

F5-12 converts the 15 T6 group 7 maintenance definitions to native `books.<HEAD ID>` kinds (`internal/plugins/maintenance/kinds_t6_g7.go`). They are dark: nothing registers them before the tasks flip (F5-18). This file lists the readings the row took where the brief is silent, the helpers it added, and what later rows build on. The row deletes `internal/books/testdata/tasklint_exempt.d/F5-12.txt`; tasklint finds nothing in the group (the one finding the group had was the series-denumber delete, `deleter.DeleteSeriesIfUnreferenced`, which now goes through `env.Writer`).

## Names beyond the spec

| Name | Where | What it is |
|---|---|---|
| `t6g7Kinds`, `t6g7KindList` | `kinds_t6_g7.go` | The group's list function (file order) and the package-level function that names it, so tasklint's registration-root rule counts the group. F5-18 replaces both with its `Registrar.Tasks` call and deletes `var _ = t6g7KindList`. |
| `t6g7Deps`, `t6g7Store`, `t6g7Writer` | `kinds_t6_g7.go` | The owner-declared dependencies (R10). `t6g7Store` and `t6g7Writer` are composed by embedding each definition's own narrow reads and writer interface. Overlapping methods carry identical signatures (a compile error otherwise). |
| `t6g7Env`, `t6g7Hold` | `kinds_t6_g7.go` | The hooks both shells fill the same way (live, log, progress, cancel, items, checkpoint, stand-down) and the scan stand-down a live run holds. |
| `t6g7HeadEnv`, `t6g7NativeEnv`, `t6g7NativeStandDown` | `kinds_t6_g7.go` | HEAD builds the env from its reporter; native from the `RC`. The native `Lost()` is always false: the kernel fences the writer instead. |
| `t6g7DecodeStrictNative` | `kinds_t6_g7.go` | Refuses `dry_run`, `dryRun` and `apply` in any case (the mode comes from the start request), then runs HEAD's `decodeStrictParams` (unknown fields, duplicate keys, trailing data). |
| `t6g7NeedDep`, `t6g7NewWriter` | `kinds_t6_g7.go` | A native shell refuses at the top when a dep it needs is nil; the writer is built only for a live run, so a Preview never holds one. |
| `seriesDenumberReads`, `seriesDenumberWriter`, `seriesDenumberEnv`, `seriesDenumberHead` | `series_denumber_op.go` | The series-denumber core's reads, its four writes, its env, and HEAD's adapter over `OpsStore` that resolves each capability through `database.AsCapability` as HEAD always did. |
| `seriesDenumberStoreReady` | `series_denumber_op.go` | The three-capability probe an undoable apply needs, behind `SeriesApplyReady()` on the reads interface. |

## Seams

- One shared core per definition serves two shells. HEAD's v2 shell keeps its HEAD-facing signature (every HEAD test passes unchanged); the native shell is a `tasks.TaskSpec`. A core reads only through `env.Reads` or `env.Store` and writes only through `env.Writer`.
- Effects come from the one shared table (`internal/maintenance/resources/resources.go`, via `t6WriterResources`). New rows this row added: `RecordPathChange` and `RecordMetadataChange` (both write `books`: the path-history and metadata-history rows). Each new writer method has its row, its pin in `resources_test.go` and a pinned kind row in `kinds_effects_pinned_test.go`. The pinned rows are appended, not reordered.
- Report files. series-phantom, rewrite-path-prefix, repoint-missing-to-folder-audio and series-denumber write their report TSV in Preview too, so they declare `files` (as HEAD wrote them in a dry run).
- Preview that reads: repoint-unrecorded-renames and series-phantom Preview run a read-based dry decision (HEAD's dry run did the same); neither builds a writer.
- Resume (standing ruling: Restart maps to Continue only if HEAD reads a checkpoint on restart, else FromZero; Drop maps to Drop). Priority, Timeout and ProgressTimeout copy HEAD; `ConcurrencyKey` is `books.` plus HEAD's key. `TestT6G7Kinds_MatchHEADDefs` writes the expected policy out per kind and compares every field.
- Progress labels that read a running counter are dropped natively, because the kernel's label is pure and cannot read a counter: title-repair, tag-backfill, version-group-primary-repair, rewrite-path-prefix and all three repoint-missing phases. HEAD's pools still show them. A seam, not a regression of the HEAD shells.
- F5-18 must fill `t6g7Deps`: `AgreedChapterTitle`, `StandDownKey`, `ResolveReportPath`, `InvalidateSeriesCache`, `ChapterProber`, `RootDir`, `NewWriter`, `Store`. `Store` must resolve the capability reads and fail closed when one is absent: the retired-aware `GetAllBookFilesCoreIncludingRetired`, `GetAllSeriesBookRefCounts` (the unfiltered count), the per-series `GetSeriesBookRefCount`, `GetBooksBySeriesIDsAllVersions`, `SeriesApplyReady` and `ListActiveOperationsV2`. The writer must provide `DeleteSeriesIfUnreferenced` (the store's check-and-delete under the book write locks, not a count followed by `DeleteSeries`).
- user-merge: effects are `user_state` only, and `ManualRetryCount` has no native equivalent.
- bulk-write-back: `RunBulkWriteBack` is a delegated opaque pass (one call into the write-back engine), so its effects are the engine's declared set, not a traced one.
- vgpr (version-group-primary-repair): HEAD waits for the stand-down (`AcquireStandDownWaiting`); native uses `rc.StandDown`. The history rows are `RecordMetadataChange`, a `books` effect. `vgApplier.reporter` is a dead field at HEAD (pre-existing; mentioned only).
- rewrite-path-prefix: the native decode is strict; the `RecordPathChange` row is `books`.
- repoint-missing-to-folder-audio: the native shell reads the iTunes roots and the path mapping from global config (no deps seam). The doc comment that says the repointed rows are "enqueued for iTunes write-back" (`repoint_missing_to_folder_audio.go`, near lines 79-83 and 451) is not backed by an enqueue call in that file; the claim is unverified there and left as it was.
- repoint-unrecorded-renames: HEAD's `GetBookFileByID` adapter (`repointUnrecordedRenamesHeadStore`) reads the row through `ModifyBookFile` with a callback that returns `ErrSkipBookFileWrite`, as HEAD's dry run always did (read under the row's stripe, nothing written); native uses the narrow read on `env.Store`.
- series-denumber: the native result is `struct{}` (HEAD's result is the report file). The apply loop stays sequential: it is order-dependent (a plan's books, the base it folds into and the delete of its emptied source depend on the plans before it) and it mutates `targets`, `states` and `run.members`. `loadBookLocks` keeps its own errgroup. A group-partitioned parallel apply is filed in `todo.d/`.

## Deviations

- `standDownForApply` in `series_denumber_op.go` now returns a `t6g7Hold` instead of `t6g1Hold`; only a test discards its value.
- `applySeriesDenumber`, `moveVersion`, `restoreVersion`, `readTargetState` and `planSeriesDenumber` take the narrow reads or writer instead of `OpsStore`; `applySeriesDenumber` is a free function.
- Commit f14a2450e's subject says "2 of 11 remaining". It should read "6 of 15 done at that point"; the count was written before the group's size was fixed at 15. The PR body says so.
- Schedules dropped: HEAD defs' schedules have no native counterpart here; the shell takes one through `sched` and F5-18 supplies them.

## Follow-ups

- F5-18 removes the HEAD v2 shells, the `seriesDenumberHead` and sibling adapters, the `var _ = t6g7KindList` line and the dark baseline lines for the native helpers.
- Sequential full-library loops left sequential here, with their own `todo.d` fragments: title-backfill and tag-backfill (their per-book work is a store read and write, in `title_backfill.go` and `tag_backfill.go`), and the series-denumber apply (above).
- `scripts/deadcode-baseline.txt` gains 46 lines (a sorted append), all unreachable until F5-18 registers the group: the 15 `*Native` shells, `t6g7Kinds`, `t6g7KindList` and the native helpers, the `t6g7ReporterSink` and `t6g7OpsProgress` methods, and three HEAD-signature wrappers that only HEAD tests call (`buildUnknownAuthorAudit`, `planRewritePathPrefix`, `Plugin.repairReviewStatusIndex`). Deleting those three instead means editing about 25 HEAD test call sites to call the cores, as F5-10 did; this row kept HEAD's test-facing signatures unchanged. F5-18 deletes the HEAD shells and these lines together.
- The wiring that builds `t6g7Deps` from the server (F5-18) is not proven here; the tests use fakes.
