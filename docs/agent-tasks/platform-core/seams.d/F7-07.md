# F7-07 seams and coined names

This file lists what `core/storage/derived.go`, `core/storage/index` and `core/internal/bleveindex` added beyond 05-storage 5S.3.8 and 5S.3.9, the readings F7-07 took where the spec or the brief says nothing, and the seams F7-08 (the migration of ABO's search onto it) and F7-09 (the kernel wiring) build on. Everything not listed here follows the spec as written.

## Names beyond the spec

| Name | What it is |
|---|---|
| `storage.Generation`, `Derived.Touch`, `Derived.Current` | The token is the store epoch (8 bytes) followed by the last touch value (8 bytes), so an artifact of another store generation never equals the current token. |
| `storage.StampArtifact`, `storage.ArtifactAccepted`, `storage.ArtifactGenerationFile` | The two helpers a Snapshot and a Load hook use to make the generation rule real. Zero, absent, malformed stamps and a zero current are rejections, never errors. |
| `storage.WriteFileDurable` | Temp file, fsync, rename, directory fsync. The one writer of the stamp and of the index markers. |
| `storage.Spec.Derived []DerivedIndex` | The one change to `spec.go`. |
| `index.Owner`, `index.StorageSpec()`, `index.DirtySet`, `index.Mark` | `c/index/` is Serialized as a whole, because a mark is written and cleared under a precondition. |
| `bleveindex.Options` fields `SearchTimeout`, `MaxTermSearchers`, `PassBudget`, `Workers`, `Interval`, `Chunk` | `Workers` and `Interval` are the readers of `core.index.reconcile.workers` and `.interval`; the three others are engine limits with defaults (`DefaultSearchTimeout` 30s, `DefaultMaxTermSearchers` 1024, `DefaultPassBudget` 10s). F7-09 may expose them as config keys. |
| `bleveindex.ErrNotReady`, `ErrNotQuiescent` | `Engine.CopyTo` refuses an index that is not Ready, and one with pending marks. A backup retries after a reconcile pass. |
| `bleveindex.RebuildKind` = `core.index.rebuild`, permission `core:system.manage` | The spec names no kind. `Engine.RebuildTask` carries `//tasklint:constructor` and an allowlist entry in `archtest/tasklint/core_test.go`, deleted by F7-09 when it registers the kind (tasklint reports an entry that matches nothing). |
| `Engine.Stats`, `Engine.PendingRebuilds` | Gauges and the rebuild list for F7-09. `PendingRebuilds` lists every Degraded index as well as the Rebuilding ones that have not been rebuilt in this process. |

## Readings taken

- **The generation names the source, not the index content.** The reconciler indexes a mark without touching the generation, so an artifact is only as complete as the dirty set was empty when it was taken. `CopyTo` therefore holds the index's `op` lock (the writer lock) plus `i.mu.RLock` for the whole copy, refuses unless the index is Ready, reads the generation first, refuses while any mark is pending, copies, and stamps the generation it read first.
- **The markers are durable and the mapping marker carries a fingerprint.** The `.rebuilding` and `.mapping` siblings are written with `storage.WriteFileDurable`. The mapping marker is `MappingVersion`, a newline, and a SHA-256 of the field declarations (name, kind, analyzer, store, facet), not of bleve's marshalled mapping, so a bleve upgrade does not force a library-scale rebuild but a `Fields` edit that forgot the version bump does.
- **A Degraded index is repairable.** An open that fails with the `.rebuilding` marker present recreates the directory (nothing in it was ever complete). One that fails without it stays Degraded and is never deleted unasked; the rebuild task recreates it, and `PendingRebuilds` lists it.
- **Query cost is bounded in the engine, not by the caller's good manners.** Every Search, Count and Facets call carries bleve's term-searcher cap and, when its context has no deadline, a default timeout. A query tree is bounded in nodes (1024), depth (32) and text (4 KB). A query string is parsed before it runs and refuses regular expressions and wildcards that start with `*` or `?`. A sort key must name a field of the Spec, `_score` or `_id`.
- **The reconciler isolates a poison mark.** A chunk whose batch fails is applied one document at a time; the refused documents stay pending and counted, and the pass reports an error only when every document failed. A panic in a module's `Document` or `Rebuild` callback is a failed load, not a crash. A pass spends at most `PassBudget` on one index (after at least one page) and the loop starts the next pass at once.
- **An index is published to the engine after its open finished.** The reconciler, `Stats` and `CopyTo` never see a half-open index; a second open of a key being opened is `ErrAlreadyOpen`.

## Seams for F7-08 and F7-09

- **Every write to an indexed entity goes through `MarkDirty`**, in the same batch as the write: a single `Set`, a `Delete`, and also `DeleteRange` and a bulk import, which touch many ids at once and must mark each one (or an index rebuild must follow). A write that skips it leaves a document the index never learns about, and the generation does not move for it either.
- **The reconciler nudge fires before the batch commits.** `Batch` has no commit hook, so `MarkDirty` wakes the loop when the mark is staged; a pass that runs before the commit finds nothing and the interval picks the mark up. A storage commit hook would make the nudge exact and let `core.index.reconcile.interval` be long.
- **`CopyTo` holds the `op` lock and `i.mu.RLock` for the whole copy.** Searches continue (they take only the read lock); `Close` and a rebuild wait, and a reconcile pass skips the index until the copy ends. A multi-gigabyte index makes that a long wait, so a backup should copy at a quiet time or the engine should copy from a snapshot of the segment files.
- **No cross-process lock.** Two processes opening the same index directory (a second instance, an offline tool against a running server) corrupt it. The engine takes no lock of its own, so whatever lock the kernel holds on the data directory is the only guard.
- **`MarkDirty` has no context.** It uses `context.Background()`, because a `Sequence` refill commits itself; a hung store hangs the writer. The contract's signature is fixed by 5S.3.8.
- **A module registers `Spec.Derived` through the manifest.** `DB.Derived` validates lazily and `DerivedIndex.Validate()` exists, but `specProblems` in `migrate.go` does not call it yet, because F7-07 may not touch other storage files. F7-09 wires the registration-time check (empty Version, duplicate names, a core owner).
- **Analyzers.** Only `standard` and `keyword` are supported; a module-registered analyzer needs a registration surface the contract does not have.
- **Rebuild drops and recreates.** A search during a rebuild answers from what it holds (State is Rebuilding); callers fall back until the rebuild finishes.

## Found, not changed

- After a restart that follows a completed rebuild but precedes the first drain, the in-memory state is Ready while marks are pending; the marks are durable and drain, so a miss in that window is a stale answer, not a lost document.
- **The `op` lock is context-aware.** `opLock` (`oplock.go`) is a one-slot channel semaphore: `CopyTo` and the rebuild select on their context while waiting, so a backup or rebuild with a deadline gives up instead of blocking behind a long pass. A reconcile pass uses the non-blocking `TryLock` and skips an index that is busy.
- **Poison marks and the pass budget.** A pass that yields its `PassBudget` stores `resumeAfter` and the next pass starts there; at the end of the set it wraps to the head. A mark whose document fails is retried on an in-memory backoff (`backoff.go`: 2s doubling to 5min, cleared on success and when a full pass finds the set empty). An entry belongs to the mark it failed on: it stores the mark's token, `due` holds back only a mark with that token, and a failure of a mark with another token (the entity was written again) starts the count at 1, so the owner fixing the data is never made to wait out the old window. The table is bounded by `Options.MaxBackoffEntries` (`DefaultMaxBackoffEntries`, 65536) and never wipes itself: a full table drops the entries whose window is over (a sweep, at most once per 2s), and if it is still full a new failing mark is simply not recorded and is retried on every pass, while every entry already there keeps backing off. With more than the cap of marks failing at once, only the overflow is retried hot. The backoff is lost on restart, which retries every poison mark once. When a chunk's batch fails, the reconciler first asks the index whether it takes a write at all (`probeWrite`: a batch that deletes an internal key that does not exist, touching no document), and only then looks at the documents. A probe that fails means the index is failing (closed, its writer broken): the pass returns the error, no mark is blamed (no backoff, no refusal counted) and the documents are not retried one by one against a dead index. A probe that goes in means the batch failed because of a document in it: each document is applied alone, and every one that does not go in is a refused document, whether one document of the chunk went in or none did, a lone refused mark included. A refused document stays pending, is counted (`failures`) and logged, and backs off keyed on its token exactly as a document that cannot load does; it does not fail the pass. The classification is the index's own answer to a write, never the number of documents that failed, because bleve's `Batch` error cannot be told from a document's by type (only `Batch.Index`'s mapping errors are known to be a document's).
- **Query cost.** A `Not` node is charged 64 nodes of the 1024 budget (`notCost`), including the negation inside a query string, because bleve evaluates it as a match-all minus the operand. One budget covers the whole query: the strings of its `QueryString` leaves are parsed in the translation (`translateNode` carries the shared counter and the leaf's depth into `translateString`) and add their cost to the counter `checkShape` started, so N string leaves cost the sum of their parsed sizes, never N separate budgets.
- **Copy destinations.** The destination of `CopyTo` must be absent or an empty directory, never a directory holding another index or a stale generation stamp. A failed copy removes a directory it created, or empties one it was given. Markers and the stamp are written 0600.
