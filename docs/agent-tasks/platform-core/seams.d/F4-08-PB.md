# F4-08 pre-PR P-B seams and coined names

This file covers the labelled-filesystem seam for `core/backup/journal`: what it added beyond 05-backup §5B.3.6 and 06 §6.5.1 P4d step 2, the decisions it took, and what it leaves for F4-08.

Everything here is dark. Production keeps plain `os` with byte-identical behaviour: the same modes, the same fsync points, the same rename atomicity. Nothing opens the journal component at boot until F4-08 binds it.

## Names beyond the spec

| Name | What it is |
|---|---|
| `journal.FS`, `journal.FSFile`, `journal.OSFS()` | A stdlib-only filesystem interface for the journal's file writes, and its `os` implementation. `TestJournalImportsOnlyAllowed` limits the journal to `entity`, `storage`, `storage/restorejournal` and the standard library, so the interface cannot name `vfs.FS`; the bridge lives outside the package. |
| `journal.WithFS(fs)`, `journal.FSOption` | A variadic option on the free functions `ReadFile`, `CreateBased`, `ReadLocation`, `WriteLocation`, `MoveFile`, `RemoveMoved`. Every existing call site compiles unchanged and gets `OSFS()`. |
| `FileOptions.FS`, `ComponentOptions.FS` | The filesystem of the stateful types. Nil means `OSFS()`. `FileOptions.wrap` (the line-file failure seam the unit tests use) is unchanged and still works. |
| `journal.RemoveMoved(path, opts...)` | The labelled `os.Remove` of the old journal once `backup.location.json` points at the moved one. The kernel's raw call becomes this (F4-08). |
| `journal.Label*`, `journal.FSLabels()` | The 20 stable writer labels, under the prefix `journal.`. `FSLabels` lists them for the writer table. |
| `journalfs.From(ctx)` (`core/internal/journalfs`) | The bridge. No seam, a seam without a filesystem, or `vfs.Default` returns `journal.OSFS()` itself; an in-memory filesystem (plain, errorfs-wrapped or crashable) returns a memory-backed `journal.FS` whose writes go through the seam and carry the open region's label; any other filesystem is refused, so a write can never go past the recorder unseen. |
| `crashmatrix.Row.Unbound`, `crashmatrix.JournalUnreachedLabels()`, `LabelKernelJournalAside`, `LabelKernelJournalAsideSync` | `Unbound` is why no boot reaches a row's writer yet. `Unobserved` never reports an Unbound row's label as missing, and reports one a fixture does reach as stale. That catches only a row a fixture reaches, so a row no fixture reaches is not Unbound: its labels are allow-map entries with a reason (`JournalUnreachedLabels` is those entries for the three non-default branches, which hello's and books' fixtures merge into their allow maps), and `TestJournalRowsAreUnboundUntilF408` fails while any row is Unbound once `core/kernel` imports `core/internal/journalfs`. The two kernel labels are reserved for the set-aside's two raw calls. |
| `bootseamtest.Options.MixedSeeds`, `MixedPercent`, `Clone.Mixed`, `Recorder.Settled()` | Opt-in. `MixedSeeds` takes one more clone per seed at every kill point the options take a clone at: a mixed-persistence clone in which each unsynced directory entry and data block is kept with probability `MixedPercent` (default 50). A test that does not set it sees the clones it always saw, so no other package's cells change. `Settled()` is the minimal clone a crash just after the last operation leaves, which the pre-call clones cannot show. |

## Decisions

1. The in-memory adapter models what Pebble's `vfs.File` lacks:
   - An append is a `WriteAt` at the end.
   - The flock is a lock set shared by every adapter of one boot. It lives on the new `bootseam.Seams.Shared` (a `*bootseam.Shared`, a keyed store; nil in every production boot), which `Recorder.Seams()` sets on every `Seams` it makes: that call builds a new `Seams` each time, and two `From` values over one boot must exclude each other, as two opens do in one process (`TestMemFS_LockIsOneSetPerFilesystem`). It is not a package variable (03 R5 forbids one; `TestNoInitOverCore` failed on the first, filesystem-keyed form). A hand-built `Seams{FS: mem}` with no `Shared` cannot carry the state, so each `From` over it gets its own: take the `Seams` from a `Recorder` when more than one adapter is built in a boot. A second open of a locked journal is `ErrLocked`, and the path is free again after `Close`.
   - A truncate, and an `O_TRUNC` open of an existing file, replace the file with a fresh one at the same name. Pebble's `MemFS` has no in-place truncate, so "truncate the existing node" cannot be implemented to the letter; the replacement is made to behave like `ftruncate` where a crash can tell them apart. The file is durable at its own `Sync` and a truncate never fsyncs the directory (`TestMemFS_TruncateIsDurableAtTheFileSync`): a minimal clone keeps the old file until the `Sync`, and a mixed clone keeps either, the two outcomes of a real crash. The replacement's directory entry is made durable by that `Sync`, unrecorded (it is not an operation of the journal's), with two limits. The adapter tracks the entries of files it created or renamed that no `SyncDir` has covered, and the `Sync` leaves those unsynced: a rollback of a new journal's header must not make its name durable ahead of `journal.dirsync` (`TestMemFS_RollbackOfANewJournalDoesNotMakeItsNameDurable`). And Pebble's `MemFS` can only sync a whole directory, so a `Sync` that does sync the entry also makes the directory's other unsynced entries durable, which a real fsync does not.
2. Crash cells run on the minimal clone **and** on mixed-persistence clones. The minimal clone keeps only what was synced, which for a sequence whose only directory fsync is its last operation is always the pre-state. The mixed ones (sixteen seeds, `mixedSeeds` in `cells_test.go`; a failure in one may not recur on a rerun with the same seed, because Pebble's `CrashClone` draws from the generator while ranging over a directory's children, a Go map) are where a torn file, an entry without its data, and a rename that outlived its contents appear. Every cell counts the outcomes its clones reach and fails when an arm it is written for is never taken (`reached.require`), and takes a settled clone after the call returns, which asserts what the call acknowledged (the new location file, the destination, the appended line, the first-opened journal) and is not counted in the arms or in the kill-point guards. Mixed clones are opt-in per test (`Options.MixedSeeds`); only the journal's cells use them.
3. A label is a region around the operation, closure-scoped and never exited twice (the labeller's exit is not guaranteed idempotent). Cleanup that follows a failed step runs after the failed step's region closes, under its own label (`journal.location.cleanup`, `journal.move.cleanup`, `journal.base.create`'s remove), so the matrix can fail a cleanup on its own.
4. `journal.move.clear` is reached only when a temporary copy an earlier attempt left exists; the site test plants one.
5. `Remove` of a missing name is `os.ErrNotExist` in the adapter: errorfs answers nil for a missing name before the in-memory filesystem is asked, and `RemoveMoved` documents `ErrNotExist` as the caller's "already done", so the adapter stats first and returns the error `os` gives.
6. The writer-table rows sit after the "P4d 1" row, in the new phase "P4d 2". The three rows the first boot with a revocation reaches (open, append, location) are Unbound with a reason that names F4-08. The three that run on a non-default branch of the re-apply (`CreateBased`, `MoveFile`/`RemoveMoved`, the kernel's set-aside) are not Unbound: their labels are allow-map entries in the hello and books fixtures, one reason per label.
7. `MoveFile` opens its source under its own label, `journal.move.source`, not the first-open label: the open creates a missing file (it is `OpenFile`'s), and a source that vanished between the existence check and the open would otherwise be recorded as a first open.

## F4-08 wiring obligations: kernel journal-file write sites

`core/kernel` is untouched by this PR. These are the raw `os` calls and unlabelled journal calls F4-08 must route through the seam. Each has a row in `crashmatrix.Rows()`: Unbound while no boot reaches it, an allow-map entry once F4-08's fixtures are what it waits for.

| Site | What F4-08 does |
|---|---|
| `core/kernel/restore_reapply.go:281` `journal.ReadLocation(in.StateDir)` | Pass `journal.WithFS(journalfs.From(ctx))`. |
| `core/kernel/restore_reapply.go:439` `journal.MoveFile(recorded, in.JournalPath, in.Keys)` | Pass the same option. |
| `core/kernel/restore_reapply.go:454` `journal.ReadFile(path, in.Keys)` | Pass the same option. |
| `core/kernel/restore_reapply.go:479` and `:486` `os.Lstat` (regular-file check, aside-name probe) | Read-only. Route through the filesystem so a memory-backed boot sees the same files; no label. |
| `core/kernel/restore_reapply.go:491` `os.Rename(path, aside)` | A labelled rename under `crashmatrix.LabelKernelJournalAside`. |
| `core/kernel/restore_reapply.go:494`, `:504-510` `syncDirOf` | A labelled directory fsync under `crashmatrix.LabelKernelJournalAsideSync`. |
| `core/kernel/restore_reapply.go:498` `journal.CreateBased(path, in.Keys, hdr, head)` | Pass the same option. |
| `core/kernel/restore_reapply.go:1270` `comp.WriteLocation(ctx, desc, pair)` | Set `ComponentOptions.FS` where the component is built. |
| `core/kernel/restore_reapply.go:1274` `os.Remove(moved)` | Replace with `journal.RemoveMoved(moved, journal.WithFS(...))`. |
| `core/kernel/restore_hooks.go:364` `journal.ReadFile(path, keys)` in `restoreAborted` | Pass the same option. |
| `OpenFile` of the journal component | Set `ComponentOptions.FS` (and `FileOptions.FS` where `OpenFile` is called directly). |

The filesystem each time is `journalfs.From(ctx)`, the ctx being the boot's. Pass one `From` value per boot. The lock set is shared across `From` calls over one recorder's `Seams` (their `Shared`), but one value keeps every journal open of the boot on the same adapter.

The component-backed sites depend on `ComponentOptions.FS`, which `NewComponent` has no non-test caller to set yet: F4-08 sets it at the `NewComponent` call it adds, or every site below stays on `os`.

| Site | What F4-08 does |
|---|---|
| `core/kernel/restore_reapply.go:1265` `AdvanceServedBoot` | Reached through the component: set `ComponentOptions.FS` where `NewComponent` is called. |
| `core/kernel/restore_reapply.go:320` `Bind` | Same. |
| `core/kernel/restore_hooks.go:379` `AppendLine` | Same. |

When F4-08 wires these, it must (1) drop the `Unbound` marks (the test above fails otherwise), (2) put every label no fixture reaches in the fixtures' allow maps with its own reason, and drop the entries of `JournalUnreachedLabels` its scenarios reach (a reached entry is reported stale). The tripwire (`TestJournalRowsAreUnboundUntilF408`) sees only a direct import of `journalfs` from a `core/kernel/*.go` file: if F4-08 wires the seam through another package (a kernel subpackage, a boot helper, an option built elsewhere and passed in), it stays silent, so wire it from the kernel's own files or widen the tripwire to the transitive imports (`go list -deps`) in the same PR.

## Follow-up (not in this PR)

`MoveFile` creates a missing destination directory with `MkdirAll` and fsyncs only the leaf (`move.go`); the parents it created are never fsynced, and the kernel then writes `backup.location.json` pointing at the new path and removes the source. This PR keeps behaviour, so it is a todo fragment (`todo.d/2026-11-19-f4-08-movefile-mkdir-parent-fsync.md`), with a crash cell over a fresh destination directory.

Separately, once F3-07 merges, `core/internal/journalfs` and `statefs` (F3-07's labelled state filesystem) should share one labelled-FS helper: both adapt the boot's seam filesystem to a package-local interface and both model the same missing `vfs.File` operations. This PR mirrors `statefs`'s shape on purpose so the merge is mechanical.

## Verification notes

`make lint-deadcode-ratchet` needed no baseline lines: no `main` imports `core/internal/journalfs` yet, so deadcode does not load it. F4-08's import is what brings it into the ratchet, and the identifiers it uses are then reachable.
