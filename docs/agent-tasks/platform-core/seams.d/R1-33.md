# R1-33 seams and coined names

| Name | What it is |
|---|---|
| `shutdownBudgetEnv`, `shutdownBudgetFromEnv(lookup)` in `cmd/root.go` | The R1 reading of `ABO_CORE_SHUTDOWN_BUDGET`. Unset or empty gives 0 (core's default); a positive `time.ParseDuration` value is returned; anything else is an error naming the variable. F3 deletes both with `R1Values`. |

## The wire

R1-15 merged first, so this PR makes the wire. `serve`'s run function calls `shutdownBudgetFromEnv(os.LookupEnv)` before the store opens and returns `serve: ABO_CORE_SHUTDOWN_BUDGET: <reason>` on an invalid value. The result travels as `books.ServeInputs.ShutdownBudget` (new field), which `books.Options` passes to `r1Values`, which sets `app.R1Values.ShutdownBudget` (`core/app/options.go`). Unset or empty is 0, so core's 25 s default applies. F3 deletes `shutdownBudgetEnv`, `shutdownBudgetFromEnv` and the `ServeInputs` field with `R1Values`.

## Stop-window arithmetic

The production systemd unit's `TimeoutStopUSec` is 90 s. The worst case is the 25 s budget plus the store's 10 s drain (`DefaultCloseDrainTimeout`), 35 s, which fits under compose's 60 s, launchd's 60 s and systemd's 90 s. The `TimeoutStopSec` wording in `cmd/serve_app.go` is owned by an R1-15 follow-up PR and is not touched here.
