# F5-01 seams and coined names

What the dark conversion of the 34 maintenance jobs added beyond 05-tasks, the readings it took where the brief or the spec says nothing, and what F5-18 (the flip) must do with them. Everything not listed follows the brief as written.

## Names beyond the spec

| Name | Where | What it is |
|---|---|---|
| `jobs.Store` | `internal/maintenance/jobs/kinds.go` | The method set of `maintenance.JobStore`, declared here so F5-18 can delete `internal/maintenance`. Built from copies of `JobStore`'s group interfaces (`storeBookStore`, `storeBookFileStore`, ... eight embeds), because `interfacebloat` counts declared entries and the baseline is 0. `var _` lines both ways pin equal method sets. |
| `jobs.KindDeps{NewStore}` | same | `NewStore(w tasks.Writer) Store`: the job's store view for one run. `w` is `rc.Writer()`, which core makes nil for a ReadOnly kind (5 jobs); those jobs write nothing. A nil `NewStore`, or a nil `Store`, fails the run before the job starts. |
| `jobs.Kinds(deps, sched)` | same | One definition per `maintenance.All()` job, in that order. `sched` is rule R9's schedule hook (nil: none). |
| `kindFor`, `kindShell.run`, `rcProgress`, `rcCheckpointer`, `checkpointerFrom`, `withCheckpointer`, `refuseModeKeys`, `resultBox` | same | The shell. `checkpointerFrom(ctx)` is nil under HEAD's wrapper, so the two checkpointing jobs keep calling `operations.SaveCheckpoint`/`LoadCheckpoint` there. |
| `jobWrites` | same | Rule R7's "Writes found": per job, the books resource kinds it writes (below). |
| `signalMemDB` (`books.memdb`) | same | The readiness component every kind waits for (rule R5, `NoWarmupWait` false on every job). |
| `jobs.AdvertisedDryRunDefault(job)` | `internal/maintenance/jobs/advertised_dryrun.go` | The one reader of a job's advertised `dry_run` default. The HTTP dispatcher resolves an omitted `dry_run` against it and the shell declares a job ReadOnly exactly when it is false. The dispatcher's former copy is deleted; the opmode single-spelling allowlist entry moved to this function. |
| `var _ = Kinds` (`kindsRoot`) | same | See "tasklint" below. F5-18 deletes it. |
| `metadata.WriteSingleTagContextVia(ctx, rec, path, tag, value)` | `internal/metadata/taglib_exported.go` | The one single-tag writer: it records the file's new hashes through `rec` (a `fileops.BookFileHashRecorder`), the store the caller was handed; nil records nothing. `WriteSingleTag` and `WriteSingleTagContext` (which recorded through the installed package store) and their `writeSingleTagWithTaglib` twins in both build variants are deleted; nothing but tests called them. |

## What F5-18 must do

1. **Delete `var _ = Kinds`** in the same change that passes `jobs.Kinds(...)` to `Registrar.Tasks`, and delete `internal/maintenance` and HEAD's wrapper.
2. **Register the readiness component `books.memdb`** with the health registry. The kinds name it in `Common.Ready`; nothing in ABO registers a component of that name yet.
3. **`NewStore` must return a value that satisfies every capability the jobs reach by runtime assertion on their store**, directly or through `database.AsCapability`'s decorator walk, or the job refuses or silently skips: `database.AsSyncIdentityStore` and `AsSyncFileStore` (backfill-sync-ids, merge/scan chapter groups), `database.AsBookmarkStore` (backfill-itunes-positions, chapter groups), `dedup.Store`, `chapterBlockerStore`, `chapterDirLister`, `chapterActiveOpsStore` (merge-chapter-groups), `hbDeferredStore` (backfill-file-hashes), `aggregatesBackfillMarker` (recompute-book-aggregates; without it the job takes its fallback loop and skips the sentinel), `database.NewPebbleMetricsStoreFromStore` (sweep-pebble-metrics-ttl; nil means "not Pebble", a silent no-op) and `fileops.BookFileHashRecorder` (scan-composer-tags; without it a live run is refused). A writer-routing wrapper must keep those reachable (embed the store, or implement `Unwrap`).
4. **Core drops a failed run's result.** The shell returns `(result, err)`, but `core/tasks`'s erased `Run` returns `nil, err` when `err != nil`. HEAD stores a failed run's result on its row: merge-chapter-groups persists a cancelled merge's outcomes and journal IDs on purpose. The shell writes the payload to the run log at WARN so it is not lost, but the row has none. Fixing it is a `core/tasks` API decision (keep the result of an erroring `Run`); not taken here.
5. **Schedules** stay F5-14's; `Kinds` sets `Common.Schedule` from the hook only.
6. **Declare six more resource kinds in `r.Resources(...)`.** F5-18's brief lists ten (`books`, `book_files`, `authors`, `series`, `review_items`, `embeddings`, `operations`, `catalog`, `fingerprint_index`, `aux_stores`). The maintenance kinds' `Effects` name eleven books kinds, six of them not in that list: `external_ids`, `user_state`, `settings`, `files`, `sync_identity` and `metrics`. A kind whose Effects name an undeclared resource is refused at registration, so F5-18 must add all six (and drop none of the ten: `books`, `book_files`, `authors`, `series` and `operations` are used here too).
7. **Front-door params check.** HEAD's dispatcher calls a job's `ParamsValidator` before it queues a run and answers 400. core has no start-time hook for it (`Common` carries none), so the shell calls the validator first thing in `Run`, before it asks for a store, and the run fails with the same error. Only merge-chapter-groups implements it. A start-time hook in core would turn that into a 400 again; that is a core API decision, not taken here.

## Readings the brief left open

- **Retention has no checkpoint call.** The brief names three checkpointing jobs. `retention-and-hygiene` has only a comment naming `operations.SaveCheckpoint`; the brief's `grep -ln` matches it. Two jobs switch (`backfill-file-hashes`, `recompute-book-aggregates`); the retention job's policy is `ResumeRestart` with no checkpoint, which maps to `ResumeContinue` and re-runs from the start, as at HEAD.
- **Permissions are written in `kinds.go`, not read from the atom table.** `internal/books` imports this package through its import graph, so `AtomTable()` is unreachable. All 34 jobs require `settings.manage` (no job implements `PermissionAware`); the eight scopes are copied and `TestJobKinds_MatchHEADWrapper` (an external test, which may import `internal/books`) fails when they drift from the table. A job asking for any other permission gets the zero requirement and is refused at registration, never a guessed scope.
- **ReadOnly is the five jobs HEAD gives no preview**, not "no write capability": every job inherits `library.write` from `DefaultPolicy`, so that test would match none. The five (relink-report, scan-chapter-groups, scan-duplicate-files, scan-duration-mismatch, scan-metadata-hash-dups) advertise `dry_run=false` and write nothing; a preview of one is refused ("preview not supported; start with mode live"), per rule R7's live-only rule.
- **Mode.** `Mode` has two values. `dryRun = mode != ModeLive`, so an unset mode never writes.
- **repoint-version-primary has one switch.** HEAD needs `dry_run=false` and `apply=true` (a live run without `apply` is a report that says it wrote nothing). Native, the shell derives `apply` from the mode (live: true, preview: false) and refuses an `apply` key in params in any spelling, like `dry_run`, so a live run cannot be a silent preview. Whether a job has an apply switch is read from the `json` tags of its `Policy().Params`, not from its ID. HEAD's wrapper keeps the two-switch rule until F5-18 deletes it.
- **Resume.** HEAD's `ResumeRestart` maps to `ResumeContinue` only for the two jobs whose code restores a checkpoint (`backfill-file-hashes`, `recompute-book-aggregates`). The other five (`bulk-deluge-import`, `cleanup-empty-folders`, `refetch-missing-authors`, `retention-and-hygiene`, `scan-composer-tags`) never checkpoint: HEAD re-enters them from the top, which is `ResumeFromZero` (same RunID, from zero), so that is what they declare, rather than `ResumeContinue` with the `//archtest:resume-from-zero` directive. `TestKindShell_ResumeContinueMeansCheckpoint` derives the checkpointing set from the code and fails on drift.
- **Failed-run result.** The shell logs a failed run's dropped result at WARN as its size only (`result_bytes`), never the payload: the payload is the job's own data and can be megabytes. The row still has none (core drops it, `core/tasks/erased.go`); see the follow-ups below.
- **tasklint.** `tasklint` does not load test files and a list function counts as a registration root only when some loaded declaration references it. Nothing calls `Kinds` before the flip, so `var _ = Kinds` is the reference. Without it every `tasks.Task` site is `unregistered-kind`. With it the package passes with `F5-01.txt` deleted: `writer-bypass` and `store-capture` see nothing because a job's `Run` is an interface call the analyzer does not follow, so rule R10 item 3 was done by reading (below).
- **Resources** are `tasks.Res("books", kind)` with kinds named as `pkg/ops` names them (`books`, `book_files`, `authors`, `series`, `external_ids`, `user_state`, `operations`, `settings`, `files`) plus two coined here, `sync_identity` (backfill-sync-ids, merge-chapter-groups) and `metrics` (sweep-pebble-metrics-ttl).
- **Progress** is under one mutex (counters and the report together), so a report never carries a count older than one already sent.
- **Concurrency.** The shell owns no loop, so rule R4 applies to nothing here and every job's own pool is unchanged. `registry.RunItems` calls inside jobs keep their `Concurrency` as HEAD set them.

## Rule R10 item 3: the store audit

Found by reachability over each job's `Run` (every function it statically calls, closures included): every write-named method called through an interface, and every package-level variable holding a store. One job reached a store other than its argument:

- **scan-composer-tags** wrote tags through `metadata.WriteSingleTagContext`, which records the new file hash and any failed-verification provenance through `metadata.packageHashStore` (installed at startup). It now calls `WriteSingleTagContextVia` with `store.(fileops.BookFileHashRecorder)`, and refuses a live run whose store is not one. `packageSafeWriteDeps` (the Deluge protected-path guard) is also package-level but holds no store of the books store package; it is unchanged.

No other job reaches a store through a variable.

## Dropped HEAD fields (rule R5)

Every job's HEAD def carries `Plugin: "maintenance"`, `Cancellable: true`, `Isolate: false`, `Liveness: LivenessManual` and `Capabilities: [library.read, library.write]` (`DefaultPolicy`), none carried. `ConcurrencyKey` is the derived `maintenance.<id>` for 33 jobs (the zero native key, `Key(Kind)`) and `library.scan` for merge-chapter-groups (`books.library.scan`). No job sets `ProgressTimeout`, `DependsOn`, `Dedupe*`, `Batchable`, `NotifyLevel`, `Schedule`, `Triggers` or `FormerIDs`. `Preview` is carried as the ReadOnly/preview split above; repoint-version-primary's second mode key (`apply`) stays a param, as its `Policy().Params` declares it.

## Follow-ups outside this row

- **core drops a failed run's result** (`core/tasks/erased.go`, the erased `Run` returns `nil, err`). HEAD keeps it on the row; merge-chapter-groups relies on that for a cancelled partial merge. A core API decision.
- **The retention-and-hygiene opstate sweep treats native run ids as orphans.** Phase (3) of that job deletes every `opstate:<id>` blob whose operation is in neither of HEAD's operation keyspaces (`opStateStillNeeded`). A native run's id is in neither, so any `opstate:` row written for one is swept as orphaned. Owner of the fix: F5-03 (the retention run-history half); it must teach the sweep core's run ids before F5-18 registers the kinds.
