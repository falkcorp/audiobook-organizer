# R0-03 seams and coined names

Names this task added that later rows may rely on (implementation plan §(n) rule 5).

| Name | Where | What it is |
|---|---|---|
| `middleware.APIKeyMayActAsAdmin(c *gin.Context) bool` | `internal/server/middleware/auth.go` | Whether the request's credential may use the admin role (05-authn §11.1 item 4). An API key bound on the context (`CurrentAPIKey`) passes only when its scopes are empty or hold every atom of `auth.All()`. With no key bound, it passes unless the recorded method is `auth.MethodAPIKey` (fail closed). A bound key is judged by its scopes whatever method the request records; the brief's sketch checked the method first, which gives the same answer on every path that exists today. |
| `adminKeyScopeRefusal` (unexported const) | `internal/server/middleware/auth.go` | `RequireAdmin`'s 403 message for an admin whose key fails the rule: `"admin role required: this API key's scopes do not include every permission"`. The no-role 403 (`"admin role required"`) and the no-user 401 are unchanged. |
| `TestLegacyRequireAdmin_HonoursKeyScopes` | `internal/server/middleware/auth_admin_scope_test.go` | `RequireAdmin` and the gate `adminRole` hands out with auth on, across the credentials: one-atom, `users.manage`-only and all-but-one keys refused; every-atom key, empty-scope key and session pass for an admin; a non-admin never passes; an `api_key` request with no key bound is refused. Also through `RequireAuth`'s real key path. |
| `TestUserMerge_ScopedAdminKeyRefused` | `internal/server/handlers/user_merge_scope_test.go` | The handler half: `mergeActor` (`GET /users/merges`, `GET /users/:id/footprint`), `SetUserEmail` and `inviteTokenVisible`. F4 re-points it onto core. |

## Rules later rows inherit

- Every role-name admin check calls `APIKeyMayActAsAdmin` next to its role test: `RequireAdmin` (and so
  `adminRole`, `adminGate`, admindebug's write group), `inviteTokenVisible`, `SetUserEmail`, `mergeActor`.
  A new role-name check does the same; `auth.Can(users.manage)` is not a substitute.
- A users.manage-only key of an admin no longer reaches the master-list routes (`wire_master_list_routes.go`
  mounts them behind `adminRole`). Use a key with every atom, or an empty-scope key, for admin automation.
- The ABS surface binds `auth.MethodAPIKey` without putting the key on the gin context, so
  `APIKeyMayActAsAdmin` refuses an ABS-presented key outright. No ABS route has an admin check today; a row
  that adds one must bind the key (or its scopes) first.
