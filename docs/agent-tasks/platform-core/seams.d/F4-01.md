# F4-01 seams and coined names

What the core rbac PR (`core/rbac/store.go`, `service.go`, `seeds.go`, `core/rbac/rbactest/`, `core/internal/rbacstore/`) added beyond 05-rbac v1.13.8 §3.4, §4 and §9 to §12, the readings it took where the brief or the spec says nothing, and what F4-02, F4-06, F4-08 and F4-09 must know. Everything not listed here is 05-rbac as written. The PR is dark: nothing in ABO or the kernel calls it.

## Deviations from the brief

1. **`Deps.Compile func(CompileInput, *Catalog) Checker`**, not the brief's `func(CheckerInput, *Catalog) Checker`. The spec settled the brief's planner note ("how role permissions reach `Deps.Compile`") after the brief was written: `CompileInput{CheckerInput; RolePatterns []Permission}`, the union of the known roles' patterns, sorted and de-duplicated, resolved by `Service.Compile` from its role cache at the current generation. `authz.Compile` never reads the store. Tested by `TestCompile_ResolvesRolePatterns` and the CompileInput cells of `TestWorkerKey_Confined`. The `Compile` line is formatted on one line for F4-09's re-verify grep.
2. **`rbactest.ReachSnapshot` and `rbactest.RowRuleSuite` are not built.** Brief step 6 predates the spec revision whose review history says "Deleted: … the row rule and reach snapshot" (05-rbac, review history, the R2 cutover rewrite). 04 §8's mention of `RowRuleSuite` in the `rbac/rbactest` row is stale. `rbactest` holds `StoreSuite` (with the importer cases), `Harness`, `Fixture` and the synthetic `Catalog`.
3. **Core seeds three roles, not four.** `admin`, `editor` and `viewer` are core's; `fp-worker` is books' `RoleSeed`, admitted through the module's imported role IDs (§4.9, 06 §6.4.2), and reaches the store through the same merge once F4-08 declares books' manifest. `TestWorkerKey_Confined` declares a `books` module with that seed.
4. **Paths beyond the row's file list** (added to `inventory.json`, `check_waves.py` PASS): the `core/rbac/*_test.go` files; `core/internal/archtest_layers_test.go` (`"internal/rbacstore": 4`, R4: the layer of the public package it implements); and the four test files of the cycle fix in the next item (`core/storage/nobatch_test.go`, `core/audit/actions_test.go`, `core/backup/journal/file_test.go`, `core/backup/journal/imports_test.go`). They sit under W24 rows' directories; no W25 row names them (check 3 PASS). The review fixes added `core/rbac/catalog.go` (F2-08's, W24, merged): `Catalog.Expand` now matches wildcards through `rbac.Covers` (item 6).
5. **Import cycle fix.** `archtest` (non-test) imports `rbac` and `httpapi` for `RoutesHavePermissions`, and `rbac` must now import `storage`, `audit` and `backup/journal` (the spec's `Store`, `Deps.Audit` and `Deps.Revocations` types). Three in-package tests imported `archtest`, which closed a cycle, so `go vet ./...` and `go test ./archtest/` failed to load. They now run from external test packages: `core/storage/nobatch_test.go` (`package storage_test`), `core/audit/actions_test.go` (`package audit_test`), and `TestJournalImportsOnlyAllowed`, moved from `core/backup/journal/file_test.go` to a new `core/backup/journal/imports_test.go` (`package journal_test`). **Rule for later rows:** no in-package test of a package in rbac's dependency closure (storage and its leaves, metrics, audit, backup/journal, entity, log) may import `archtest`. Use an external test package.
6. **One matching predicate, `rbac.Covers`.** The T4 review found `GrantsAdmin` matched only `core:admin` and `core:*` literally, so a custom role holding `core:admin.*` (which §4.2's grammar allows and which expands to `core:admin`) escaped the last-admin rule and the importer's SEC-12 refusal, and read as confinable. `Covers(pattern, scope)` is now the one implementation of §4.2's matching rule; `Catalog.Expand` (F2-08's file, behaviour unchanged, `TestCatalog_ExpandPattern` still passes) and `GrantsAdmin` both use it, and `TestCovers_AgreesWithExpand` pins them together.

## Readings where the spec is silent

- **Escalation on a role edit.** The actor must hold every permission in the old set and in the new set. An edit acts on every holder, so removing a scope is checked the same way as granting it (§4.7 rule 2's reading, applied to edits). `DeleteRole` needs the role's permissions. `AcceptSeed` needs the resulting set. A refusal emits `core.permission.deny` with reason `scope_escalation` and target `{core, role, <name>}`, and stages nothing.
- **`holds`: what holding a role pattern means (F4-09 must keep this).** For a concrete scope, it is `actor.Has(p)`. For a wildcard, it is `actor.Has(p)` or `actor.Has(core:admin)`, and also `actor.Has(c)` for every scope the wildcard expands to now, so §4.4's Sensitive-before-admin rule covers what the pattern grants. A malformed pattern is never held. **`Checker.Has` of a pattern must return true only when the principal holds that pattern, or a wider one, literally.** Without that, a holder of every `gotham:*` scope could grant `gotham:*`, which also grants scopes declared later.
- **CanAssign / Dominates.** Both check each scope with `holds`. An interactive admin passes everything. A non-interactive admin fails a role holding a Sensitive scope. Both refuse a role name nobody defined unless the actor holds `core:admin` (`CanAssign`: `ErrEscalation` wrapping `ErrUnknownRole`; `Dominates`: `ErrDominance` wrapping `ErrUnknownRole`). `Dominates` used to skip an unknown target role because it grants nothing today; the review made it fail closed, since the name is a claim on whatever role is created under it later and an actor that cannot see what the target holds does not dominate it. A nil actor or an unfrozen service is refused.
- **Last admin (§4.6) as rbac enforces it.** A role write that takes `core:admin` (or any pattern that covers it: `core:*`, `core:admin.*`) from some role must leave at least one active user holding a role that still grants it, when one held it before. It counts distinct active holders through `Holders`. Role writes are serialised by a service mutex (load, check, stage, commit, cache), and a Commit that fails on `storage.ErrConflict` reruns the whole decision, up to 3 attempts. The last conflict is returned as `ErrVersionMismatch`. **auth's own last-admin rule (demoting or disabling a user, F4-02) is auth's to write.** It must read the role definitions the same way, and rbac's `GrantsAdmin` is the predicate.
- **DeleteRole** refuses a role held by any user, active or not (`ErrRoleInUse`). Reassign-on-delete is not in the spec's signature and is not built. F4-05's route answers 409.
- **Seed merge (§4.8).** `SeedDigest` is the sha256 of the sorted `SeedPermissions`, per the field comment. On every boot the merge recomputes the state and writes a role only when something changed (permissions, pending set, digest, title, description, the locked flag or the `Confined` flag), so it is idempotent. `PendingSeed` is recomputed each time as the restricted additions in seed minus effective, which drops a pending scope that the release withdrew. Withdrawals apply at once and are journalled `role.narrowed`. Title and description follow the seed. `admin` is rewritten to exactly `{core:admin}`, locked, whatever its stored origin. A stored row under any other seed name that is not a seed role, or a seed row that does not decode, fails `CommitSeeds` and so the boot. A seed role whose module is no longer declared stays stored and read-only.
- **Confinement in the merge (F4-01's addition).** At `Freeze`, a seed role is confined when its `RoleSeed` names a Confining scope concretely or is `Confined` (a wildcard such as `books:fingerprint.*` that today expands only to Confining scopes). A confined seed role must hold only concrete Confining scopes in its final seed, `DefaultGrants` included (`ErrConfiningSeed`). So a wildcard-only worker seed is refused: the wildcard would reach whatever non-Confining scope a later release declares under it. (Before the review only the concrete case was caught.) In the merge, confinement is a **stored, sticky flag**, `Role.Confined` (coined, below), not a reading of the current permissions against the current catalog. A release whose seed for the role is confining (the rule above) sets it, on create or on an existing role. Nothing a later release does clears it; only an `AcceptSeed` that lands a scope reaching a declared non-Confining scope does, because an administrator then chose to end the confinement (accepting only Confining scopes keeps it). While the flag is set, every addition that is not a concrete Confining scope waits in `PendingSeed`. **Confining additions wait too**, as does every Sensitive, AuthRequired or `*:settings.manage` / `*:integrations.manage` addition: §4.8's restricted list (`flagRestricted`) holds them for every existing role, flagged or not, so re-adding the worker scope to an emptied worker role is pending as well. The flag closes every path the review probes found where a worker role left confinement with no admin accepting it: a wildcard seed that emptied the role followed by a plain seed; an empty seed followed by a plain seed; a release that stopped declaring the worker scope; and a release that flipped the worker scope to `Confining: false` followed by a plain addition. A plain module role is never flagged, so a release that renames all its scopes lands the new ones at once. The round-1 inference rule (`confinedForMerge`, "confined unless its effective set shows otherwise") and its cost, an admin accept for every emptied or renamed plain role, are gone. Tests: `TestSeed_NoNonConfiningScopeOnConfinedRole` (the release swap and the four escape paths); `TestSeedMerge_ConfinedFlagIsSticky` (created flagged, the Confining flip, emptied then the worker scope re-added, a confining release flags an existing plain role, `AcceptSeed` clears or keeps the flag, a renamed plain role); the `TestSeedMerge_Idempotent` property again requires every pending scope to be a restricted addition.
- **Freeze** validates everything (each declaration call also returns its own errors), builds the catalog from `CoreScopes()` plus the module specs, computes the seeds, and loads the stored roles into the role cache. An undecodable row is logged and skipped, grants nothing, and does not stop the boot (§6.3). Other store errors fail. **Imports must come before `Freeze`**, because the cache is loaded there and `ImportRole` writes bypass the service. The cutover runs at P4b, before `Freeze` at P5 (06 §6.5.1), and `Freeze` now seals the store's importer (`ImportSealer`, above), so an import that would land after the load is refused with `ErrImportRejected` and `ErrFrozen` instead of sitting in the store unseen until a restart (`TestImporter_SealedAtFreeze`).
- **Compile fails closed** without calling `Deps.Compile` before `Freeze`, and for key scopes §4.5 forbids (a non-nil empty list, a wildcard, a malformed scope). In both cases it returns a checker that holds nothing and is `Confined()`. A nil checker from `Deps.Compile` is replaced the same way and not cached. Unknown but well-formed key scopes are passed through for authz to deny. The cache key length-prefixes each part and keeps a session (nil scopes) apart from a key. It is a 16-shard LRU of `ceil(size/16)` entries per shard.
- **Can** requires both `Has(s)` and `Satisfies(Need(s))`. `RequireAll()` with no scope, or with a malformed one, denies.
- **Revocation journal.** If `Append` fails, the change still commits and `Gap(b, at)` is staged. If `Gap` fails, the change fails. `OnChange(generation)` runs after the commit, outside the locks.
- **Audit records carry literal actions.** `(*Service).record(ctx, b, audit.Event)` takes the whole event, and every call site builds it as a composite literal with a string-literal `Action` (`core.role.create`, `core.role.update`, `core.role.delete`, `core.role.update_seed`, `core.role.accept_seed`). audit's `TestAuditAction_Grammar` therefore sees every action rbac records and checks it against §7.1's table; it counted 8 Event literals in core after the change. Before the review the action went through a `string` parameter, which the scanner cannot see. Keep it that way in later rows that add an action.
- **Role cache concurrency.** `Compile`, `CanAssign` and `Dominates` read the role map under `rolesMu.RLock`. `apply` updates the map and bumps the generation in one `rolesMu.Lock` section, so no reader can cache old patterns under the new generation. `TestRoleCache_ConcurrentReaders` exercises this under `-race`: four readers against 200 narrow and widen cycles.

## F4-09 must know

`CompileInput.RolePatterns` is sorted and de-duplicated and includes `core:admin` (or `core:*`, `core:admin.*`) when a role holds it. Decide "holds core:admin" and wildcard matching with `rbac.Covers` / `rbac.GrantsAdmin`. `Scopes` is nil for a session and never empty or wildcard by the time it reaches you. `Checker.Has(pattern)` must follow the contract above. `TestWorkerKey_Confined` in `core/rbac/compile_test.go` holds rbac's cells. Add the checker cells in `core/internal/authz`.
