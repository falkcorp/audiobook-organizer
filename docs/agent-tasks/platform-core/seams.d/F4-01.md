# F4-01 seams and coined names

What the core rbac PR (`core/rbac/store.go`, `service.go`, `seeds.go`, `core/rbac/rbactest/`, `core/internal/rbacstore/`) added beyond 05-rbac v1.13.8 §3.4, §4 and §9 to §12, the readings it took where the brief or the spec says nothing, and what F4-02, F4-06, F4-08 and F4-09 must know. Everything not listed here is 05-rbac as written. The PR is dark: nothing in ABO or the kernel calls it.

## Deviations from the brief

1. **`Deps.Compile func(CompileInput, *Catalog) Checker`**, not the brief's `func(CheckerInput, *Catalog) Checker`. The spec settled the brief's planner note ("how role permissions reach `Deps.Compile`") after the brief was written: `CompileInput{CheckerInput; RolePatterns []Permission}`, the union of the known roles' patterns, sorted and de-duplicated, resolved by `Service.Compile` from its role cache at the current generation. `authz.Compile` never reads the store. Tested by `TestCompile_ResolvesRolePatterns` and the CompileInput cells of `TestWorkerKey_Confined`. The `Compile` line is formatted on one line for F4-09's re-verify grep.
2. **`rbactest.ReachSnapshot` and `rbactest.RowRuleSuite` are not built.** Brief step 6 predates the spec revision whose review history says "Deleted: … the row rule and reach snapshot" (05-rbac, review history, the R2 cutover rewrite). 04 §8's mention of `RowRuleSuite` in the `rbac/rbactest` row is stale. `rbactest` holds `StoreSuite` (with the importer cases), `Harness`, `Fixture` and the synthetic `Catalog`.
3. **Core seeds three roles, not four.** `admin`, `editor` and `viewer` are core's; `fp-worker` is books' `RoleSeed`, admitted through the module's imported role IDs (§4.9, 06 §6.4.2), and reaches the store through the same merge once F4-08 declares books' manifest. `TestWorkerKey_Confined` declares a `books` module with that seed.
4. **Paths beyond the row's file list** (added to `inventory.json`, `check_waves.py` PASS): the `core/rbac/*_test.go` files; `core/internal/archtest_layers_test.go` (`"internal/rbacstore": 4`, R4: the layer of the public package it implements); and three test moves forced by an import cycle, next item.
5. **Import cycle fix.** `archtest` (non-test) imports `rbac` and `httpapi` for `RoutesHavePermissions`, and `rbac` must now import `storage`, `audit` and `backup/journal` (the spec's `Store`, `Deps.Audit` and `Deps.Revocations` types). Three in-package tests imported `archtest`, which closed a cycle, so `go vet ./...` and `go test ./archtest/` failed to load. They now run from external test packages: `core/storage/nobatch_test.go` (`package storage_test`), `core/audit/actions_test.go` (`package audit_test`), and `TestJournalImportsOnlyAllowed`, moved from `core/backup/journal/file_test.go` to a new `core/backup/journal/imports_test.go` (`package journal_test`). **Rule for later rows:** no in-package test of a package in rbac's dependency closure (storage and its leaves, metrics, audit, backup/journal, entity, log) may import `archtest`. Use an external test package.

## Coined names (F4-08 wires them)

| Name | What it is |
|---|---|

| `Deps.Holders Holders`, `Holders.HoldersOf(ctx, b, roles) ([]Holder, error)`, `Holder{UserID, Active}` | Who holds a role. Used by the last-admin rule and by `DeleteRole`'s role-in-use rule. rbac never imports auth, so the kernel implements this over auth's user records. **It must read every user row it reports through `b` (`GetForUpdate`, or an `Expect` on the row)** so that a demotion committed in auth after the read fails the role write's Commit (`storage.ErrConflict`), and the write retries against the new state (§9). | `(*Service).CommitSeeds(ctx) error` | P7's seed commit (06 §6.5.1; 05-rbac §5): it merges every seed role computed at `Freeze` in one batch. Before `Freeze` it returns `ErrNotFrozen`. A second call writes nothing. |

The package-level `Require` has no receiver, so on an unbound context it still denies but records nothing. |

## Readings where the spec is silent

- **Escalation on a role edit.** The actor must hold every permission in the old set and in the new set. An edit acts on every holder, so removing a scope is checked the same way as granting it (§4.7 rule 2's reading, applied to edits). `DeleteRole` needs the role's permissions. `AcceptSeed` needs the resulting set. A refusal emits `core.permission.deny` with reason `scope_escalation` and target `{core, role, <name>}`, and stages nothing.
- **`holds`: what holding a role pattern means (F4-09 must keep this).** For a concrete scope, it is `actor.Has(p)`. For a wildcard, it is `actor.Has(p)` or `actor.Has(core:admin)`, and also `actor.Has(c)` for every scope the wildcard expands to now, so §4.4's Sensitive-before-admin rule covers what the pattern grants. A malformed pattern is never held. **`Checker.Has` of a pattern must return true only when the principal holds that pattern, or a wider one, literally.** Without that, a holder of every `gotham:*` scope could grant `gotham:*`, which also grants scopes declared later.
- **CanAssign / Dominates.** Both check each scope with `holds`. An interactive admin passes everything. A non-interactive admin fails a role holding a Sensitive scope. `CanAssign` refuses a role name nobody defined (`ErrEscalation` wrapping `ErrUnknownRole`) unless the actor holds `core:admin`. `Dominates` skips an unknown role of the target, because such a role grants nothing. A nil actor or an unfrozen service is refused.
- **Last admin (§4.6) as rbac enforces it.** A role write that takes `core:admin` (or `core:*`) from some role must leave at least one active user holding a role that still grants it, when one held it before. It counts distinct active holders through `Holders`. Role writes are serialised by a service mutex (load, check, stage, commit, cache), and a Commit that fails on `storage.ErrConflict` reruns the whole decision, up to 3 attempts. The last conflict is returned as `ErrVersionMismatch`. **auth's own last-admin rule (demoting or disabling a user, F4-02) is auth's to write.** It must read the role definitions the same way, and rbac's `GrantsAdmin` is the predicate.
- **DeleteRole** refuses a role held by any user, active or not (`ErrRoleInUse`). Reassign-on-delete is not in the spec's signature and is not built. F4-05's route answers 409.
- **Seed merge (§4.8).** `SeedDigest` is the sha256 of the sorted `SeedPermissions`, per the field comment. On every boot the merge recomputes the state and writes a role only when something changed (permissions, pending set, digest, title, description, or the locked flag), so it is idempotent. `PendingSeed` is recomputed each time as the restricted additions in seed minus effective, which drops a pending scope that the release withdrew. Withdrawals apply at once and are journalled `role.narrowed`. Title and description follow the seed. `admin` is rewritten to exactly `{core:admin}`, locked, whatever its stored origin. A stored row under any other seed name that is not a seed role, or a seed row that does not decode, fails `CommitSeeds` and so the boot. A seed role whose module is no longer declared stays stored and read-only.
- **Confinement in the merge (F4-01's addition).** §4.9's rule refuses a `RoleSeed` that names a Confining scope concretely unless every scope of its final seed (`DefaultGrants` included) is concrete and Confining (`ErrConfiningSeed`). A wildcard is refused too, because it could reach a non-Confining scope later. Separately, the merge holds a non-Confining addition to a stored role that is confined, or that a release emptied of its last Confining scope while unrestricted scopes wait. So a release that replaces `fp-worker`'s seed with an unconfined one never makes the role unconfined without an admin's acceptance (`TestSeed_NoNonConfiningScopeOnConfinedRole`, release-swap case).
- **Freeze** validates everything (each declaration call also returns its own errors), builds the catalog from `CoreScopes()` plus the module specs, computes the seeds, and loads the stored roles into the role cache. An undecodable row is logged and skipped, grants nothing, and does not stop the boot (§6.3). Other store errors fail. **Imports must come before `Freeze`**, because the cache is loaded there and `ImportRole` writes bypass the service. F4-06 and F4-08 order the cutover step accordingly, or restart after it.
- **Compile fails closed** without calling `Deps.Compile` before `Freeze`, and for key scopes §4.5 forbids (a non-nil empty list, a wildcard, a malformed scope). In both cases it returns a checker that holds nothing and is `Confined()`. A nil checker from `Deps.Compile` is replaced the same way and not cached. Unknown but well-formed key scopes are passed through for authz to deny. The cache key length-prefixes each part and keeps a session (nil scopes) apart from a key. It is a 16-shard LRU of `ceil(size/16)` entries per shard.
- **Can** requires both `Has(s)` and `Satisfies(Need(s))`. `RequireAll()` with no scope, or with a malformed one, denies.
- **Revocation journal.** If `Append` fails, the change still commits and `Gap(b, at)` is staged. If `Gap` fails, the change fails. `OnChange(generation)` runs after the commit, outside the locks.

## F4-09 must know

`CompileInput.RolePatterns` is sorted and de-duplicated and includes `core:admin` when a role holds it. `Scopes` is nil for a session and never empty or wildcard by the time it reaches you. `Checker.Has(pattern)` must follow the contract above. `TestWorkerKey_Confined` in `core/rbac/compile_test.go` holds rbac's cells. Add the checker cells in `core/internal/authz`.

## F4-08 must know

At P5, call `rbac.New(ctx, Options{CacheSize, Source: app.BinaryID}, Deps{Store, Compile: authz.Compile, Audit, OnChange, Revocations, Log, Metrics, NewBatch, Holders})`, then `Declarer(manifest.ID, manifest.ImportedRoleIDs...)` per manifest, then `Freeze`. Call `CommitSeeds` at P7. auth's middleware calls `Bind`. Register `rbacstore.StorageSpec()` under `rbacstore.Owner`.
