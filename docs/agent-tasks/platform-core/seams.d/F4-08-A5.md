# F4-08 A5: crash-matrix regions on the identity boot's commits

This slice puts a `bootseam` region around each new store commit of the identity boot, following the `tasks.def.upsert` region in `core/kernel/tasks.go`. It also adds the writer-table rows for them in `core/coretest/crashmatrix/rows.go`, as one block marked Unbound with a reason that names F4-08.

All of it is dark. `bootseam.Region` returns a no-op exit when the context carries no Seams. Only `core/coretest` and its sub-packages call `bootseam.With` (`archtest.BootseamHookCallers`), so no production boot records anything. No production boot reaches these commits until F4-08 wires P4d and P7.

## Decisions

- **The outer label wins.** The kit's recorder keeps the outermost region. A kernel region that wraps a call which also writes the journal file records that file write under the kernel label. The calls involved are `AppendLine`, the journaled append inside `RestrictLastAdmins`, and `AdvanceServedBoot` when it rewrites `backup.location.json`. Journal writes outside these regions keep their own file labels. F4-08 should decide whether a kill inside one of these regions must also be tested at the inner journal label. If so, split the region so that it ends before the file write.
- **One region per commit, not per helper.** `commitTail` gets two regions, one per `RetryOnConflict`, so a crash between auth's batch and rbac's batch is its own cell.
- **Unbound, one block.** The rows are appended as a single block at the end of `Rows()`, so a re-cut of another PR's table edits conflicts trivially. `TestIdentityBootLabelsAreUnboundRowsNamingF408` (new, `identity_rows_test.go`) pins three things: every label is in exactly one row, and that row is Unbound with a reason naming F4-08.

## Left for F4-08 (B9)

These commit sites are not labelled. The brief's list did not name them:

- the fail-closed passes (`failClosedIfBehind`, `failClosedOnce`) and the queue's fail-closed pass
- the broken-journal latch that `failClosedOnce` writes
- the hooks' commit of the held head (`restore_hooks.go` `CommitHead`) and `MarkHooked`
- the `restore_aborted` line (`restoreAborted`)
- the writes of the restore hooks themselves (each module's hook)

When F4-08 binds the rows, it drops the Unbound marks. It must also allow, with a reason, each label that no fixture reaches. `TestJournalRowsAreUnboundUntilF408` will fail if the kernel imports journalfs while any row is still Unbound.
