# R1-06 seams and coined names

Names this task added that later rows may rely on (implementation plan §(n) rule 5).

| Name | Where | What it is |
|---|---|---|
| `make -C core version-check` | `core/Makefile`, in `ci` | Runs `scripts/ci/check_core_version.py`: `version.Version` is at least the newest `refs/core-checkpoints/v0.*`, hello's `MinCoreVersion` is at most `Version`, every `core/web/packages/*/package.json` version equals `Version`. A checkpoint fetch failure fails the check (fail closed). |
| `make -C core script-test` | `core/Makefile`, in `ci` | `python3 -m unittest discover` over `core/scripts/ci` (`pytest` is not installed on the runners). A new core CI script ships its `test_*.py` beside it and is picked up. |
| `make -C core tools` | `core/Makefile` | Installs the pinned `apidiff`, `govulncheck` and `staticcheck` from `core/tools/<x>/` into `core/bin/` (ignored). |
| `make -C core readiness` | `core/Makefile` | Report-only SC1, SC5, SC6 and SC9. Writes only under `$(READINESS_OUT)` (default `core/.ci/readiness/`): one `scN.json` per criterion, then `readiness.json` and `readiness.md`. Exits 0 whatever the verdicts; a crashed script fails it. |
| `SC1_FIRST_CHECKPOINT` | `core/Makefile` variable | The first checkpoint that starts SC1's count (release R2's, 12 SC1). Unset, SC1 cannot be met. |
| `core_ci_lib.py` | `core/scripts/ci/` | Shared helpers: `Semver`, `read_version`, the checkpoint ref functions (`fetch_checkpoints`, `list_checkpoints`), `Result` with the statuses `PASS`, `FAIL`, `NOT_APPLICABLE`, `ERROR`, and `finish(result, out_dir, report_only)`, the one place a status becomes an exit code. |
| `refs/core-checkpoints/v0.Y.Z` | git refs, not tags | Recorded by `core-checkpoint`; fetched explicitly with `+refs/core-checkpoints/*:refs/core-checkpoints/*`. |
| `core-checkpoint` | `release-prod.yml` job; `.github/workflows/scripts/core_checkpoint.py` | `needs: release`, `continue-on-error`, `contents: write` and `issues: write`. Records the ref when `core/` changed and `Version` was bumped; otherwise opens or updates one issue labelled `core-version-bump-needed`. Refuses a constant that is not `0.Y.Z`. |
| `split-readiness.yml` | `.github/workflows/` | Nightly: `measure` (no secrets) then `fold` (environment `ci-bot`), which keeps one PR on branch `bot/split-readiness`. |
| `readiness:latest` and `readiness:history` markers | `docs/plans/platform-core/split-readiness.md` | The only two regions `scripts/ci/fold_split_readiness.py` rewrites. |

## Rules later rows inherit

- A readiness script takes `--out DIR` and `--report`, and ends in `core_ci_lib.finish`; none of them calls `sys.exit` with a verdict of its own.
- Not measurable is `NOT_APPLICABLE`, never `PASS` (SC6 until the coredoc generator lands).
- F3 and the split drop the root-side pieces together: `split-readiness.yml`, `core_consumer_smoke.py`, `web_build_against_tarballs.py`, `fold_split_readiness.py` (12 §12.8.2).
