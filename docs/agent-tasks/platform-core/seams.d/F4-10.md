# F4-10 seams and coined names

Names this task added that later rows may rely on (implementation plan §(n) rule 5).

| Name | Where | What it is |
|---|---|---|
| `Router.checkCoreFixed` | `core/httpapi/corefixed.go` | Build's refusal, called once from `Router.Build` before `checkClaims`: `ErrPrefixCollision` for a fixed-group route that is not an entry of `CoreExactPatterns()`, and for a legacy manifest route that overlaps (`overlaps`, method and path) an entry a fixed-group route serves. The second half runs only once a fixed-group route serves the entry, so a router with no fixed-group route is unchanged (STOP 4). |
| `isCoreExact(e, bases)`, `isFixedRoute(e, bases)`, `Router.fixedBases()` | `core/httpapi/corefixed.go` | The exemption predicate `nativeNodes` (`legacy.go`) calls to leave an entry out of the shadow graph, the fixed-route test, and the bases of the valid fixed groups. A fixed route is a native `core` route whose pattern lies under a fixed base; no field on `Group` or `routeEntry` carries it. |
| `coreFixedPrefix` | `core/httpapi/corefixed.go` | Key prefix `"core-fixed "` of a fixed group in `Router.groups`, so one base returns one group and no module ID can collide with it. |
| `Router.checkFixedBase` | `core/httpapi/corefixed.go` | A base that is not a clean literal path below `/` (empty, `/`, relative, trailing slash, wildcard, dot segment), or that lies in core's own `/api/core/` space, is recorded as `ErrPrefixCollision` (the sentinel an invalid claim gets) and refuses every route on the group through `Group.err`. Follows `ModuleGroup`, which records a bad ID through `claim` and does not panic. |
| `TestCoreFixedBase_Invalid`, `TestCoreFixedBase_SameBaseSameGroup` | `core/httpapi/corefixed_test.go` | Cells beyond the brief's three names; named `TestCoreFixedBase_` so the brief's `TestCoreFixedGroup_` count of 3 holds. |

## Readings the brief left open

- The group claims nothing (`CoreGroup` claims `/api/core/`; this does not claim its base), so no claim exemption was needed: the only exemption is the shadow graph's.
- `isCoreExact` takes the fixed bases as well as the route, because a fixed route is recognised by its pattern's base (the brief's signature `isCoreExact(route)` had nowhere to read the bases from).
- `legacy.go` (`nativeNodes`) is the second file touched beside `router.go`: the shadow graph lives there, not in the file that defines `Build`.
- Not changed: `Router.policyOf` (stage 5's policy for an answer given before routing) still maps a path under `/api/v1/` to the legacy owner's policy, so a CORS preflight to a fixed path would carry the legacy mount's CSP. The two routes are GET navigations, so no preflight is expected; F4-05 or F4-08 can revisit.
