# F5-07 seams and coined names

What the dark conversion of the maintenance plugin's second group of 13 definitions (9 files) added beyond 05-tasks, the readings it took where the brief says nothing, and what F5-18 (the flip) must do with them. Everything not listed follows the brief as written.

## Names beyond the spec

| Name | Where | What it is |
|---|---|---|
| `t6g2Env` | `kinds_t6_g2.go` | The one env every core takes: log, progress, checkpoint, `Items` (the pool), `Store`, `Writer`, `ReportPath`. A core uses the fields it needs. |
| `t6g2Items`, `t6g2Loop` | same | The pool seam. **Deviation from rule R2's sketch:** the cores' loops differ in what they hand a pool (resume watermark, checkpoint callback, collect-or-fail, progress numbering), so a core describes its loop in a `t6g2Loop` and the shell binds the worker count (`Parallelism`). HEAD's shell binds `opsregistry.RunItems`; the native shell binds `tasks.RunItems`. |
| `t6g2Store`, `t6g2Writer`, `t6g2Deps` | same | Rule R10's interfaces. Both are built from embedded group interfaces (`interfacebloat` counts declared entries). Reads live on the store, every write on the writer. `t6g2Store` also carries `Describe()` and `Supports(capability)`, which replace HEAD's `database.AsCapability` probes in the cores. |
| `t6g2Deps.ReportPath` | same | **Field beyond the brief's `Store` and `NewWriter`.** book-shape-report writes a TSV under the library root. A file write is not a `tasks.Writer` write and no Effects resource names it, so the path resolver is a dependency of its own. The native kind refuses to start without it. |
| `t6g2Meta` | same | One definition's `Common`, spelled once so the kind and the parity test read the same table. |
| `t6g2Watermark`, `t6g2NativeItems` | same | `tasks.RunItems` has no hook for a contiguous-completion checkpoint, which `opsregistry.RunItems` has. The watermark tracker reproduces it (guarded on the watermark, serialized). Native items ignore `t6g2Loop.Label`: `tasks.RunItems` has no per-item label. |
| `head*` adapters (`headT6G2Env`, `headT6G2Items`, `headT6G2Store`, `headT6G2Writer`, `headT6G2Wire`) | same | HEAD's shell side of the env: every method calls exactly what HEAD's body called. F5-18 deletes them with the v2 defs. |
| `t6g2*Kind`, `t6g2*Meta`, `t6g2*Parallelism`, `run*Core` | one per file | Per definition: the native kind, its `Common`, its worker count (where HEAD has a pool) and the shared body. |
| `var _ = t6g2KindList` | `kinds_t6_g2.go` | Keeps `tasklint`'s unregistered-kind rule satisfied until F5-18 passes the list to `Registrar.Tasks`. F5-18 deletes it. |

Existing helpers keep their signatures where a test or another file calls them (`buildFolderBookFiles`, which its tests and `retired_claims_test.go` drive); each is a thin wrapper over the env-taking variant. Helpers with no outside caller were re-signed in place (`judgeAcoustIDPage`, `deleteAcoustIDOrphans`, `restoreRecoverableFields`, `pathClaimantsOf`, `buildOneFolder`). Wrappers whose only callers were tests (`bootWalkRun`, `verifyBookAtPathIndex`, `buildBookShapeReport`, `yielded`, `backfillBookAtPathIfNeeded`) were deleted and their tests retargeted to the `t6g2*` / `*Core` functions.

## What F5-18 must do

1. **Delete `var _ = t6g2KindList`** in the change that passes `p.t6g2Kinds(...)` to `Registrar.Tasks`, and delete the v2 defs and the `head*` adapters.
2. **Wire `t6g2Deps`.** `Store` serves the reads; `NewWriter(w tasks.Writer)` returns a `t6g2Writer` whose every method writes through `w`; `ReportPath` resolves a report file under the library root.
3. **`ClassifyBookSigMigration(id)` is a store read, `MigrateBookSigToSidecar(id)` a live-only writer call.** The executor's `Writer.Do` returns `ErrPreview` in a preview without running its function, so a preview cannot classify through the writer. The store's `ClassifyBookSigMigration` must run the same classification a live migration would, writing nothing (HEAD's adapter calls `MigrateBookSigToSidecar(id, true)`). `RepairBookHashIndex`'s preview reads through `Store.CheckBookHashIndex` for the same reason.
4. **Declare four more resource kinds** in `r.Resources(...)`: `external_ids`, `settings`, `files` and `chapters` (the last is coined here: chapters-backfill writes only the `chapters:` keyspace and HEAD's comment refuses to call that `books`). A kind whose Effects name an undeclared resource is refused at registration. `books` and `book_files` are already on the list.
5. **Register `books.memdb`** with the health registry if F5-01 has not (every kind waits on it, rule R5).
6. **Core drops a failed run's result**, as F5-01's note records: build-folder-book-files returns its report with its error and HEAD stores it on the row; the native row has none. A `core/tasks` decision.
7. **Schedules** stay F5-14's.

## Readings the brief left open

- **Permissions** are the eight scopes of the `settings.manage` atom, copied. `internal/books` imports this package, so a test here cannot import `AtomTable()` (an import cycle) and the brief allows no extra file for an external test. `TestT6G2Kinds_MatchHEADDefs/start_requirement_is_the_settings.manage_atom` parses `internal/books/atoms.go` instead and fails when the scopes drift.
- **ReadOnly** is verify (`book-atpath-index-verify`) and book-shape-report. The shape report writes a TSV, which is a file write outside any resource; it is declared ReadOnly as HEAD declares it, and the file goes through `t6g2Deps.ReportPath`.
- **Write sets HEAD left undeclared** were found by reading what each body writes (the PR lists them with counts). The books resource kinds are `books`, `book_files`, `external_ids`, `settings`, `files` and `chapters`.
- **Live-only writers** (HEAD has no Preview and the body writes): the four boot passes and `book-atpath-index-backfill`. A preview run is refused with `"<kind>: preview not supported; start with mode live"`.
- **Mode.** `dryRun = mode != ModeLive` for every kind with a preview, so an unset mode never writes. The native params refuse `dry_run` and `dryRun` (and `apply` for build-folder-book-files and chapters-backfill) in any case; the run's mode decides.
- **book-hash-index-repair `ensure` with a preview is refused.** HEAD forced a live run for `ensure`. A native run's mode comes from the start request, so the kind refuses the combination instead of overriding the mode.
- **book-hash-index-repair is `ResumeFromZero`.** HEAD says `ResumeRestart` but nothing in the body checkpoints.
- **`ResumeAsk` stays for malformed-m4b-transcode** (HEAD's reasoning: a re-encode is not safe to repeat unasked).
- **Checkpoint shapes are HEAD's.** bookfile-acoustid-index-repair and chapters-backfill checkpoint their own params struct, as HEAD does; the native shell restores only the cursor and counts and takes the mode from the run.
- **Parallelism copies HEAD** (rule R4): external-id-backfill fixed 1, movement-atom-cleanup and malformed-m4b-remux fixed 4, malformed-m4b-transcode fixed 2, the five pool-per-CPU kinds `cpu`, book-shape-report `fixed(concurrency)` when the param is set else `cpu`. The kinds with no pool (verify, backfill, hash repair, recovery audit) declare none.
- **Hash repair is `ResumeFromZero` (ruling n15).** Non-checkpointing kinds map `ResumeRestart` to `FromZero`, as F5-06 does; HEAD's `restartWithoutCheckpoint` guard entry for it stays.
- **Progress numbering of a native boot walk.** The walk reports its own absolute `(processed, total)` through `env.Progress`; the native pool is given `ProgressBase = ProgressOffset + ResumeFrom` and `ProgressTotal = the original length`, so both writers use one numbering. A resume past the end reports the full bar with the note `resumed: all items already complete`, as HEAD's `RunItems` does. HEAD's boot shell muted the pool's own progress (`quietReporter`); the native pool cannot be muted, so it is aligned instead.
- **`env.Checkpoint` is set only by shells that checkpoint** (the four boot passes, bookfile-acoustid-index-repair, chapters-backfill), so the resume-restart guard still sees which HEAD defs call `reporter.Checkpoint`.
- **Boot-pass Effects include `books` where the pass reaches it**: malformed-m4b-remux and build-folder-book-files rewrite book aggregates (`RecordRewrite` and `BatchCreateBookFiles` both end in `RecomputeBookAggregates`).
