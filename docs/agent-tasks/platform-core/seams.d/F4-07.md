# F4-07 seams and coined names

This file lists what the reach oracle's books half (`scripts/r2corpus/record_r0_reach.py`, `scripts/r2corpus/dump_r0_routes.py`, `internal/books/rbacreach/`, `internal/books/cutover/reach_*_test.go`) added beyond 05-rbac section 12 and the brief, the readings F4-07 took where they say nothing, the differences the oracle found that no expected row covers, and what F4-08 must do. Everything not listed here follows the spec as written.

## Names beyond the spec

| Name | What it is |
|---|---|
| `internal/books/rbacreach/{principals,verdicts,routes}.json` | The recorded R0 answers: 37 principals, 572 routes, 234 task definitions, the awaiting run and the census. Data only; no Go file (`find internal/books/rbacreach -name '*.go'` is empty). Each carries a `_header` object in place of a comment header. |
| `scripts/r2corpus/r0config/edit_config.go.txt` | A Go helper the recorder builds against the repo's `go.mod` (same pebble) to rewrite keys of the throwaway copy's stored `config_blob`. A `.txt` so it is not a Go file in the module. |
| `record_r0_reach.py` flags `--check`, `--reuse-auth-on` | `--check` re-derives the data and exits 1 on any differing cell; `--reuse-auth-on` re-runs only the auth-off boot from a saved `auth-on.partial.json` (never committed). |
| `reachCell`, `reachExpect`, `reachClassify`, `reachGateProblems` | The diff's cell, an expected-difference row (asserts both letters, must match at least one cell), the classifier, and the text a failing gate prints. |
| `TASK-START <def>` and `TASK-APPROVE <def>` | Pseudo-routes: the recorded task starts and approvals enter the same diff as routes, so an expected row can name them. |

## Readings taken

- **The oracle is in `internal/books/cutover`, not `internal/books`.** The brief names `internal/books/reach_oracle_test.go`. The M3 rig (`newIDRig`, `idAtoms`, `idSnap`) is a test fixture of package `cutover`; a test in `internal/books` cannot reach it. The command line of the brief is `go test ./internal/books/cutover -run TestIdentityCutover_ReachOracle`.
- **The R0 side is recorded on a GitHub-hosted ubuntu runner with the pinned `Linux_x86_64` v0.223.0 asset.** The Darwin arm64 asset is not used. A temporary push-triggered workflow did the recording and is deleted in this PR; `scripts/r2corpus/record_r0_reach.py` is the reproducible entry point, and `--check` reruns it. The recorder was run to a full determinism check: two runs of the same commit gave the same letters on every route.
- **The route dump is generated from the v0.223.0 tag's source** (`dump_r0_routes.py`), not from a running binary. 572 routes, the number 05-rbac names.
- **`ENABLE_AUTH` and `ENABLE_RATE_LIMIT` do not reach a store that has a `config_blob`.** R0 reads the stored config after the environment. The recorder therefore spreads its probes over loopback source addresses (one per request, so the limiter stays on as shipped) and edits the stored keys (`edit_config`): `enable_auth=true>false` for the auth-off boot only, and two flags for both boots.
- **Two flags are turned on in both boots.** `fingerprint_remote_workers_enabled` (R0's `flagGuard` answers 404 ahead of authentication on `/api/v1/fingerprint/worker/*` while it is off, so no principal's reach there was observable) and `deluge_discovery_enabled` (the two discover handlers answer 403 from inside the handler while it is off, which a probe reads as a denial for everyone, the admin's session included).
- **A probe is a request that fails after authorization when authorized.** A 401 or 403 is a denial and any other status below 500 is an allow. A 429, a 5xx and a connection error are recorder failures, never verdicts, except the routes listed in `OK_5XX` with R0's own message (the handler's outbound call fails after the authorization decision). A listed route must also show a denial for some principal, so a 5xx cannot hide a decision that never ran. `POST /audiobooks/bulk-write-back` is timing-dependent (202 or 500 by whether an earlier probe's run holds the op's concurrency key) and is listed for that reason.
- **Census.** Users, books and task definitions are counted before and after the pass, and a canary request per principal follows; a changed census or a dead server fails the run. The census counts the corpus's seven books through `GET /api/v1/audiobooks/count`; R0 wraps bodies in `{"data":...}`, so the first version of the census read no count at all and the run did not fail (fixed, with a test that a non-integer count fails the run).
- **Probes start real runs.** The recorder's task starts send an empty parameter list that fails validation after authorization; none starts a run. The one awaiting run (`repairs.plan`) is created once and approved by none.
- **The test-local evaluator replica (SEC-26).** Core's `authz` is importable only by `auth`, the executor and the kernel (`archtest.NoSystemPrincipalOutsideKernel`), and nothing outside core builds an `rbac.Service` before F4-08 wires one. `reach_eval_test.go` is a test-local copy of `Compile`, `AuthDisabled`, `Has` and `Satisfies`, written from `core/internal/authz/authz.go` (the replica is checked against it by reading, not by import). A fault in the copy shows as a cell that differs from R0 and is on no row, so it cannot hide; what the copy cannot show is a fault core and the copy share. F4-08 replaces it with the registered path.
- **The seed roles and catalog are written in `reach_spec_test.go`.** Books declares no catalog and no `DefaultGrants`, so the spec's tables (05-rbac 4.8 for the roles, 6.1 for the scopes, their implications and flags) are the source. The rig's `idSeedRoles` and `idCatalog` (F4-06) differ from the spec: the editor lacks `books:delete` and `books:request.approve` and holds `books:collections.manage`, and `books:admin.debug` lacks `AuthRequired` and `Sensitive`. `TestReachSpec_*` pin the oracle's copy to the spec. F4-06's rig is not changed here.
- **`Guards.Owner`.** Core ships no `OwnerVerifier`, so by 05-authn 4.8 an owner-guarded route falls back to `Interactive` plus `core:admin`. The replica models exactly that (`TestReachGate_OwnerGuardFallsBackToInteractiveAdmin`).
- **Task starts and approvals.** A start is `scan.trigger`'s route floor then each of the definition's own permissions resolved through the atom table, as R0's handler does; an approval is the route's `library.view`, the definition's approver permission, and a verified method (the auth-disabled principal has no user). The recorder does not start tasks as the auth-disabled principal, so those cells have 36 letters, not 37. An approval's R0 letter is A once it reaches the approver check (R0 answers 400 to the probe's invalid decision); N means the run was not readable by the caller and carries no reach information.
- **The random native roles half (05-http-api 8.1) is not recordable.** R0 has no role CRUD route, so no R0 baseline exists for a random native role; the half belongs to a core test over core's own routes.
- **ABS-delegated routes (`OwnAuth`) are excluded and counted.** Their authorization is the ABS handler's own token check, outside the router's decision.
- **In-handler checks behind 404 lookups.** A probe with a dummy path id that a handler turns into a 404 before its own permission check cannot show that check. The recorder's `uniform_not_found` list names every route whose 404 was identical for all principals; none of them is a decision.
- **Rows are asserted on both letters** and fail if they match nothing (`TestReachClassify_*`). Two kinds are kept apart: `reachExpected` (clauses of 05-rbac) and `reachRecorderLimits` (a refusal that is the handler's answer to the probe, not the router's reach).
- **Pinned one-sided routes.** R0 only: `GET /` (the SPA handler, outside the manifest) and the two HEAD reset routes (`POST /system/factory-reset`, `POST /system/reset`, deleted at F4, 05-rbac 6.2). R2 only: `POST /admin/guest-service-tokens/:userId/reissue`, newer than the R0 tag (no baseline). `TestReachOracle_RoutesOnOneSideAreExactlyThesePinned` fails on any other.
- **`playlists.create` is unenforced.** Books' table gives it a zero route requirement, so no route reads it; `TestAtomTable_Golden` and `TestIdentityFixture_MatchesTheAtomGolden` pin the row. `requests.create` and `requests.approve` are likewise named by no manifest route.

## Ruled

The oracle reported three differences between R0 and R2 that were on no expected row of 05-rbac section 12 (STOP 2). The spec's owner ruled on each on 2026-11-13: the oracle was right on all three, and none is an R2 security bug. The spec and the oracle were changed together, so the oracle is green with 217 differing cells, all claimed by a row, and no row unused.

**F-1. An `fp-worker` user's keys scoped outside the worker scope lose every authenticated-only route (96 cells: 3 principals on 32 routes). Ruled: listed, spec amended.** `key:fp-worker:view`, `key:fp-worker:settings` and `key:fp-worker:users` reach the `AnyAuthenticated` routes at R0 because `workerOnly` reads an empty effective set as not worker-only (`internal/server/middleware/auth.go:271-274` @v0.223.0), although the guard confines a user holding only the fp-worker role. After M3 the key's checker is empty (the `fp-worker` role holds no ambient scope) and it reaches no route; R2 closes that gap on purpose. 05-rbac 6.3 (keys and ambient bullets), 6.1 (`playlists.create` notes), 12 (the oracle row and `TestWorkerKey_Confined`) and 09 9.2.6 (recorded changes) now say so. The expected row is "05-rbac 6.3" over `reachAuthenticatedRoutes()` (the manifest's `KindAuthenticated` routes). The playlist-writes test now covers viewer sessions and keys whose compiled checker holds a non-`Confining` scope, so it requires a non-empty set.

**F-2. A role holding every atom, and an admin-owned `users.manage` key, gained `GET /cache/stats/keys` (3 cells). Ruled: a fix, in this PR.** The route needs `books:admin.view` (`internal/server/legacy_manifest.go`, was `core:system.view`), which matches R0's `adminRole` reach exactly. 05-rbac 6.2 and 6.1 are corrected (`core:system.view` is status detail and sysinfo; `books:admin.view` is the debug reads and ABO's cache key listing), and the "reviewed gain" row is gone from 12 and from `reachExpected`.

**F-3. An admin's every-atom or empty-list key loses the three debug edit routes (6 cells). Ruled: `books:admin.debug` stays `Sensitive`, the loss is listed.** `PATCH /admin/debug/books/:id`, `PATCH /admin/debug/book-files/:id` and `POST /admin/debug/edits/:edit_id/undo` are interactive-only from R2 (4.4 rule 1): an admin's key, the bootstrap key included, no longer reaches them. 05-rbac 6.2, 6.3 and 6.1 (every-atom row), 12, 05-authn 6 (bootstrap item 2) and 09 9.2.6 now say so. The expected row is "05-rbac 6.2 / 4.4 rule 1".

**Follow-ups from the rulings, not in this PR.** F4-06's `m3.reportKey` should report a key whose base set is empty and whose owner's closure holds no ambient scope (`OutcomeReported`, warning "a key's scopes lie outside its owner's roles, which hold no ambient scope; it reaches no route after the cutover"). The admindebug local-path containment fix is a separate PR by another builder.

**Pinned from spec text, not from code (not proven).** `reachHandlerAdmin` (`reach_oracle_test.go`) pins three routes (`GET /users/:id/footprint`, `GET /users/merges`, `PUT /users/:id/email`) as refusing a caller without `core:admin` in the handler, as 05-rbac 4.6 and 12 state the migrated merge handler and `SetUserEmail` do. Without the pin the oracle shows five cells on the first two and one on the third (`session:custom-all`, `key:admin:users`, `key:custom-all:every`, `key:custom-all:empty`, `authoff`: D at R0, A at the route level). The handler code that makes it true is written by the handler migration (04) and F4-08; until then the pin is the oracle's claim about it. `Guards.Owner` is modelled as the 4.8 fallback (`Interactive` plus `core:admin`) for the same reason.

**Recorder limits (`reachRecorderLimits`, 96 cells), not changes of policy.** `POST /login` and `POST /auth/refresh` (74 cells): Public routes whose handler answers 401 to the probe's dummy credentials for everyone. `POST /auth/api-keys/:id/rotate` (21 cells): a retired route (410) behind a conditional credential guard that refuses a key whose target it cannot show is its own user's; the probe's id is unknown. `POST /api/v3/ops/runs/:id/approve` (1 cell): R0's handler refuses the auth-disabled principal for want of a user. Each is asserted on both letters and fails if it stops matching.

**Not in the oracle.** Handler-level 403s the probe cannot tell from a denial are only found when a principal that must pass (the admin session) is denied: that is how the two Deluge discover routes (a disabled-by-default flag) were found and the recording changed. A handler 403 that every principal shares and an admin would not reach is not detectable from the router's answers alone.

## Obligations on F4-08

The brief's second half, "plus every core route of F4-05", and spec step 5 (the auth-disabled principal against **every core route**, 09 section 9.2.6) need core's registered router; they are not here. The expected-difference clauses that live on core routes (§4.11 (b), (c) and (d) for core's own credential-metadata and backup routes, §6.2's tightened `settings.manage` system routes, the `core:system.status` readiness reach of `editor` and `viewer`, dominance and `CanAssign` on `core:users.manage`, the deleted reset routes' successor) are asserted when that half exists; a row with no cell to match fails, so none can be written early.
- **Reconcile the route count.** R0's router dump has 572 routes; the books manifest has 495 and core's routes 574 in the F4-05 count. The books half compared 501 manifest routes (plus the 68 delegated routes it counted and left out).
- **Replace the replica** with the registered path (`rbac.Service` over M3's output, books' `s.perm` adapter, the real stage 13), and delete `reach_eval_test.go`.
- **Flip only when both halves pass.** The mount switch to `LegacyAuthCore` waits on the books half (this file's oracle, green) and the core half.
- **F4-06's rig fixtures** (`idSeedRoles`, `idCatalog`) should be replaced by the spec's, as `reach_spec_test.go` writes them.
