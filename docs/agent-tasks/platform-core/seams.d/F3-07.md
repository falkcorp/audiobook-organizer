# F3-07 seams and coined names

Written by the slice (a) builder; later slices append.

## Names beyond the spec

| Name | What it is |
|---|---|
| `module.Manifest.Rewrite *storage.RewriteStep` | Declares M8. 06 §6.4.2 lists no member for it, and `kernel.DataMigrationsConfig.Rewrite` is a separate field from the migration list (a `RewriteStep` is not a `DataMigration`), so the app needs a place to say it. A manifest field matches the brief ("books.Module()'s manifest"). At most one manifest declares it; the kernel appends it after every migration. Coined by F3-07 (slice a). |
| `module.SettingsSection.Path()`, `.Register(config.Registry)` | The kernel-only half of `Settings[T]`: P3 registers each enabled module's sections through it and gets the typed handle back as `any`. |
| `module.SettingsProblems(Manifest) []Problem` | P1's static check of `Manifest.Settings`: `ProblemSettingsNamespace` for a path outside `modules.<ID>`, a prefix lookalike (`modules.bat` is not under `modules.batcave`), a duplicate, or a section not built by `Settings`. |
| `module.RegistrarConfig.Settings map[config.Path]any` | What `Setting[T]` reads: a declared path maps to the kernel's live handle, or to nil where no live handle exists (Describe, a boot without core config), which yields a defaults-holding handle. A path absent from the map is undeclared (`ProblemSettingsUndeclared`). |
| `module.ErrImporterNotBound` | What a late-bound importer returns before the kernel binds it. The kernel builds the migration list at P2 and the importers' stores open at P4b, so `Manifest.Cutover` receives forwarding values. |
| `kernel.CoreKeys()` | Every key core's own sections declare, from a defaults-only store (no environment, no file, no database). `coreSections()` is unexported and ABO's gate tests live in the root module. |
| Test names | `TestRenameTable_CoreKeysRegistered`, `TestRenameTable_CoreCoinedRowsDeclared`, `TestRenameTable_RefuseVerdictsMatchConfig` (the core half of `TestRenameTable_EveryKeyRegistered`; the books half is slice b), `TestCoreKeys_*`, `TestSetting*`, `TestSettings*`, `TestDeps_ZeroSecretsScopeRefusesNotPanics`. |

## Readings the brief left open

| Topic | Reading |
|---|---|
| `core.ai.journal_retention` | `config.Duration`, default 30 days (HEAD's `ai_journal_retention_days` default is 30), `ReloadLive`, `ProtectNone` (class `k`, like `core.tasks.history_retention`). 0 keeps entries forever, as at HEAD. HEAD bounded the value to 0..36500 days; `schema` has no duration bounds, so the bound is not declared here: the books module that reads the handle owns it (05-ai §4 step 5: core/ai has no journal). |
| `core.http.public_base_url` | `string`, default `""`, `ReloadLive`, `ProtectAdmin`, `schema:"format=uri"`. The owner tables give the coined row no class. `ProtectAdmin` follows its sibling `core.auth.oidc.redirect_base_url`: HEAD kept it file-only (`json:"-"`), so storing it makes it settable through the API, and the value decides where an invitation link lands. Loosening later is a one-line change; tightening after a release is not. |
| Rename-table `admin` column and the refuse verdict | The golden had `public_base_url` at `admin=false`, so its retired names (`public_base_url` file key, `PUBLIC_BASE_URL` env) judged `warn`. `config` judges `refuse` for a key at `ProtectAdmin` or above, so the new `TestRenameTable_RefuseVerdictsMatchConfig` failed on exactly this row. The row is now `admin: true` and the golden regenerated (version 1.3.0): a host that still sets `PUBLIC_BASE_URL` is refused at boot with the canonical name in the message, like every other admin key. The deploy files carry canonical names already (slice 8). |
| Dynamic rename-table targets | One prefix is matched by an explicit reviewed list (`core.tasks.windows`: the members of the windows map, 4 targets), requiring at least one registered key at or under it, and `core.auth.oidc.<id>.client_secret` is matched against the list key `core.auth.oidc.providers` (the entry's secret, `secret:"bind"`). |
| Dark gate | One explicit bool on `kernel.Config` and `app.Options`, default off (not yet added; it arrives with the first config-boot commit). hello and coretest set it, ABO leaves it off, and `offline_open` must not clear it. It is named "delete in (e)": the header of `kernel/config.go` says the gate is the presence of the wiring, not a flag, and the flag departs from that only until the flip. `R1Values == nil` cannot be the gate: the crash-matrix injector wraps `R1Values` for every app. |
| Late-bound importers | `Manifest.Cutover(imp)` is called while the migration list is built at P2 and again, with the same values, by P1's owner check; the stores exist only after P4a/P4b. `lateImporters` (`kernel/cutover_importers.go`) returns forwarding values that refuse with `module.ErrImporterNotBound`; `migrateStorage` binds `Kernel.importerCfg` and `importerSec` immediately before `db.Migrate`. Both fields are nil until the gated config boot wires them, so every Cutover step still refuses today. An offline open shares `storageOptions` and never binds, so it can plan the list and no step it runs writes through an importer. |
| M8 wiring | `dataSteps` passes `Manifest.Rewrite` as `DataMigrationsConfig.Rewrite` and the same ID as `restoreswap.Options.RewriteStep` for both P0a's swapper and the offline one; a Rewrite alone (no migration) still builds the runner; a Rewrite with no state directory refuses at `storageOptions`. A disabled module's migrations and Rewrite stay in the plan. |
| Core M7 half | `storage.CoreLevelStep` and a core `Spec.Level` bump are NOT registered in slice (a): the brief says "registered when a manifest declares a cutover", and registering it earlier would raise core's level on every boot. Slice (d). |

## OWNER-04 P4: the five unmapped env names

The owner's recorded comment (issue 4382) names `AUDIOBOOK_ROOT_DIR`, `OTEL_SERVICE_NAME`, `ABK_PPROF_ADDR`, `TMPDIR` and `SQLITE_TMPDIR`. State in the repo at this slice:

| Name | State |
|---|---|
| `AUDIOBOOK_ROOT_DIR` | Already removed from every deploy file (deploy slice). Nothing reads it. |
| `TMPDIR`, `SQLITE_TMPDIR`, `OTEL_SERVICE_NAME`, `ABK_PPROF_ADDR` | Already allowlisted in `deployfiles_test.go` (the runtime list and `deployFileKeptProcessNames`), so the deploy-files test passes. |

Not resolved, and not invented here: 05-config §1.12.4 does not list `OTEL_SERVICE_NAME`, `TMPDIR` or `SQLITE_TMPDIR`, its runtime list is exactly `HOME`, `GOMEMLIMIT`, `GOGC`, `TZ`, `NOTIFY_SOCKET`, and `ABK_PPROF_ADDR` has no canonical key anywhere in the spec. The OWNER-04 text recommends rename-table rows for some of them while the brief's coordinator note says each gets a row; the two disagree, and a row needs a canonical path nobody has named. The owner or coordinator decides: (1) leave the five on the deploy-file allowlist as now, (2) add `ABK_PPROF_ADDR` to the rename table under a path to be named, with the other three on the runtime list in 05-config §1.12.4.
