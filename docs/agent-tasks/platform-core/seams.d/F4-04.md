# F4-04 seams and coined names

This file covers what the "events bus and catalog, backup/journal" PR added beyond 05-events §5E.3 and 05-backup §5B.3.2 and §5B.3.6. It lists:

- names the spec does not have;
- the decisions the row took where the spec or the brief is silent, or offers a choice;
- the two security-review fixes made in the PR;
- how the brief's test names map to tests;
- what it left for later rows.

Everything here is dark. No module declares a topic or a subscription, nothing in `boot.go` or `kernel.go` builds the bus, and nothing opens the journal or registers `journal.StorageSpec()`. F4-08 wires the bus and the `c/backup/` spec, and F4-11 wires the journal.

## Names beyond the spec

| Name | What it is |
|---|---|
| `events.BusOptions{Logger, Metrics, QueueSize, Origin}`, `events.NewBus` | The bus constructor. The spec names the `Bus` but not how it is built. `QueueSize` is `core.events.queue_size` (0 means 256). `Metrics` is the core `events` scope (nil means a no-op meter). `Origin` reads a publish's actor and task run ID from its context. It stays nil until auth (F4-08) and tasks (F5) own those values, so `Envelope.Actor` and `RunID` are empty for now. |
| `(*Bus).Declare(moduleID, ...TopicSpec) error`, `(*Bus).DeclareDisabled(moduleID)`, `(*Bus).Subscribe(moduleID, ...Subscription) error`, `(*Bus).Freeze()`, `(*Bus).Catalog()` | The registration side the kernel calls at P7. The spec puts this behind `Registrar.Topics` and `Registrar.Subscribe` without naming the bus methods. Every declare comes before any subscribe, because subscription targets are checked when `Subscribe` is called. `Freeze` is idempotent. `Catalog` returns the read-only `events.Catalog`. |
| `events.ErrTopicName`, `ErrDuplicateTopic`, `ErrTopicNamespace`, `ErrNoPermission`, `ErrForeignScope`, `ErrSchemaRequired`, `ErrBadSchema`, `ErrRealtimeOnDurable`, `ErrSubscriptionName`, `ErrDuplicateSubscription`, `ErrInvalidSubscription`, `ErrTopicUndeclared`, `ErrDurableTopic`, `ErrForeignTopic`, `ErrPayloadType`, `ErrFrozen`, `ErrClosed`, `ErrNotFrozen`, `ErrOpen` | The registration and lifecycle sentinels. §5E.7 says these refusals fail boot but names no errors. Each refusal wraps exactly one sentinel and formats any cause with `%v`, never a second `%w`. That keeps each refusal one leaf of the joined error, so the kernel's `leaves()` turns it into one problem. `TestKernelEvents_ProblemKinds` caught a refusal that used two `%w` verbs and split into two problems, the second of which had lost its sentinel. |
| `kernel.kernelEvents`, `newKernelEvents`, `coreTopics`, `defaultCloseDrain`, `eventKinds`, `eventProblems` (all unexported) | The kernel's dark half of the bus lifecycle: `declareCore`, `declare`, `declareDisabled`, `subscribe` (id `""` is core), `freeze`, `scope` (= `module.Deps.Events`), `catalog`, `open`, `close`. `close` is bounded by `min(core.events.close_drain, ctx)`. The comment on `kernelEvents` lists the order F4-08 follows. Sentinels map to problem kinds as follows: `ErrTopicNamespace` and `ErrForeignTopic` go to `ProblemTopicNamespace`; `ErrTopicUndeclared` and `ErrDurableTopic` go to `ProblemTopicUndeclared`; `ErrForeignScope` goes to `ProblemPermissionNamespace`; anything else is `ProblemInvalidRegistration`. `coreTopics()` returns nil, because each core topic registers only when its owner lands (§5E.3.1). |
| `journal.Owner = "core/backup"` | The owner the kernel registers `StorageSpec()` under, per 06 §6.4.10's F4 row. |
| `journal.FileOptions{Path, Keyspace, Source}`, `journal.OpenFile(ctx, FileOptions)`, `journal.File` | The file-backed `RevocationJournal`. The spec names no constructor. |
| `journal.ErrCorrupt`, `journal.ErrClosed`, `journal.ErrLocked` | `ErrCorrupt` covers lines that do not decode, a seq out of order, and a file that ends below the store's committed `journal_head`. `ErrLocked` means another `File` holds the file. |

## Decisions

- **Subscription names.** A name is `<moduleID>.<name>` with the declaring module's own prefix, and is unique per bus.
- **Queueing before `Open`.** Events published between `Freeze` and `Open` are queued, not dropped. They are delivered from `Open` on. §5E.6 says only "no delivery before Open".
- **`Coalesce`.** The first event of a key opens its window, and the latest event of that key is delivered when the window ends. The flush is trailing, and an empty key is delivered uncoalesced. A window that is not positive makes the subscription invalid.
- **Drop reasons.** `mediacore_events_dropped_total{reason}` takes `queue_full`, `encode` and `closed`. `encode` covers a raw subscriber whose payload fails marshalling or the declared schema, and a typed subscriber whose payload type does not match.
- **Merge hook.** Not added. §5E.5.1's coalescing row mentions an optional `Merge` hook that would carry `BookChangeCoalescer`'s rule (deleted supersedes updated, created stays created). §5E.3.2's API block declares no such option, so `Coalesce` is latest-wins only. A consumer that needs the merge rule (the realtime hub, F6-02) adds the option and its test.
- **Journal keys.** The journal uses raw byte keys relative to the keyspace: `journal_head`, `served_boot` and `journal_gap/<since>`. It does not use `storage/keys` or `codec`, because the brief's import rule allows only `entity`, `storage` and `storage/restorejournal`. `<since>` is fixed-width UTC RFC 3339 with nanoseconds, so gap keys sort by time. The gap value is `{since, reason: "append_failed"}`.
- **Journal format.** The header line is `{"seq":0}` and nothing else, because its fields are F4-11's. Lines are a snake_case `wireLine`, encoded only by `encodeLine` and `encodeHeader`. `openJournal` is the only place the file is opened, and `writeLine` is the only writer. Mode is 0600 with `O_APPEND`.
- **Broken journal.** An append whose line cannot be cut back durably marks the journal broken, and every later `Append` fails so the callers record gaps. Reopening the file recovers it.

## Security-review fixes (made in this PR)

1. **Encode drops log no payload (MEDIUM).** A raw subscriber's encode drop used to log the schema validator's error text, and that text can quote the failing value. The event now keeps only a fixed cause word: `marshal`, `schema` or `payload_type`. The drop warning carries `topic`, `subscriber`, `reason` and `cause`, never the error or the value. §5E.10 gives the drop metric only `{topic, subscriber, reason}`, and §5E.5.1 asks only for a WARN at most once per subscriber per minute, so the warning carries the metric's labels plus the cause word. `TestOnRaw_EncodeDropLogsNoPayload` publishes a sentinel value that fails the schema and asserts it never reaches the log. Publish rejections log only fixed text, module IDs and Go type names. **Still open:** the handler-panic log carries the recovered panic value with the stack, as §5E.5.1 asks ("logged with stack"). A handler that panics with a payload value would put that value in the log. Leaving it to the reviewer: the alternative is to log only the panic's type.
2. **The journal never numbers at or below the store's head, and has one writer (MEDIUM).** `OpenFile` used to number from the file alone. An emptied, truncated or recreated file therefore restarted below `c/backup/journal_head`, and its lines got seqs that consumers had already applied and skip. A second opener could reuse seqs too.
   - **Spec ruling.** §5B.3.6's "Format and integrity" row requires every line's `seq` to be the previous line's + 1, so numbering on from `head + 1` would forge the chain. §5B.5's failure table treats "chain broken or truncated below the live store's head" as one condition: app open, coverage closed, `revocation_journal_broken`. So `OpenFile` reads `journal_head` (a committed read through the keyspace) and refuses a file whose last seq is below it with `ErrCorrupt`, writing nothing. It does not renumber. What the boot does next is F4-11's P4d step 2 (rename aside, start a new journal with a `gap` line, report health), as is the install check.
   - **`Append`.** `Append` now reads the head with `GetForUpdate` before it writes. A head at or past the next seq marks the journal broken (`ErrCorrupt`), so no seq at or below the head is ever assigned. Before this fix, the head read came after the write.
   - **The lock.** The file is held with `flock(2)` `LOCK_EX|LOCK_NB` from open to `Close` (`ErrLocked`). The lock belongs to the open file description, so a second opener is refused whether it is in this process or another. `storage.LockSwapShared` is bound to `<state_dir>/swap.lock`, and pebble's `vfs.Default.Lock` would be a direct third-party import that the brief's allow-list forbids. So this is stdlib `syscall.Flock` under swaplock's build tags (`lock_flock.go`). Elsewhere `lockJournal` fails closed with `errors.ErrUnsupported` (`lock_other.go`); the release targets are linux and darwin.
   - **For F4-11.** The lock is on the journal's own descriptor. F4-11's retention rewrite (temp file + rename) and the directory move must hand the lock over, or lock a sidecar, because a rename replaces the inode the lock is on. A refused `OpenFile` may leave an empty file it created.
   - **Tests.** `TestOpenFile_RefusesFileBehindHead` (empty, header-only, truncated and deleted files), `TestAppend_NeverAtOrBelowHead` and `TestOpenFile_SecondOpenerRefused`. `TestJournal_AppendBeforeCommitHeadMonotone` used to assert the fail-open case (a head of 99 kept while lines were appended under it). It no longer does.

## Brief test names

All 18 names in the brief exist under those names: the `TestTopicName_*`, `TestCatalog_*`, `TestBus_*` and `TestOnRaw_*` tests and `TestNoGlobals_EventsOutbox` in `core/events/`, and `TestJournal_*` and `TestJournalImportsOnlyAllowed` in `core/backup/journal/`. Tests added beyond the brief:

- `core/events/`: `TestSubscribe_Rules`, `TestPublish_RejectedCountedLoggedOnce`, `TestKeyFilter`, `TestEventsMetrics_SeriesGolden`, `TestOnRaw_EncodeDropLogsNoPayload`.
- `core/backup/journal/`: `TestStorageSpec_SerializedKeysAndPrefixes`, `TestOpenFile_HeaderAndRecovery`, `TestOpenFile_RefusesFileBehindHead`, `TestAppend_NeverAtOrBelowHead`, `TestOpenFile_SecondOpenerRefused`.
- `core/kernel/`: `TestKernelEvents_Lifecycle`, `TestKernelEvents_ProblemKinds`, `TestKernelEvents_CloseBoundedByCloseDrain`.
