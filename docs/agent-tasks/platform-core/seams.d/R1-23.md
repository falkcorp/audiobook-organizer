# R1-23 seams and coined names

This file covers what the "storage flip: strict claims" PR added beyond 05-storage §5S.3.4, §5S.3.5, §5S.3.7, §5S.9.3 and §5S.9.4, 04 §4.5 and 06 §6.11.1. It lists:

- names the spec does not have;
- the decisions the row took where the spec or the brief is silent, or wrong;
- every `old ==> new` path;
- what it left for later rows, with the fragment that tracks each item;
- the seams later rows build on.

From this row the kernel opens ABO's one Pebble store at P2. Books reaches its rows only through strict claims on `storage.LegacyRange`, and `serve` runs no pre-server step of its own.

## Names beyond the spec

| Name | What it is |
|---|---|
| `database.BooksOwner` (`"books"`), `database.BooksClaims()`, `database.BooksSpec()` | Books' storage declaration. The claims are generated from `keyfamilies.go` (every family `ClaimReadWrite`, `c/` and `m/` skipped) and stay in `internal/database/booksclaims.go`, not the brief's `internal/books/claims.go`: `internal/database` owns the family registry, and books may not be imported by it. `BooksSpec()` builds new bookkeeping on each call, so two opens never share a version source. |
| `database.LegacyCap` (66) | The last HEAD-style step. `TestNoNewLegacyMigrations` pins it. |
| `database.NewBooksStore(r storage.LegacyRange)` | Books' constructor in the served app. The spec (05-storage §5S.9.3 row "NewPebbleStore(path) / InitializeStore / globalStore") names it `database.NewPebbleStore(h module.StorageHandles)`. It takes the `LegacyRange` because `internal/database` may not import `mediacore/module` (internal/arch `moduleAppImporters`), and it has its own name because `NewPebbleStore(path)` still has 6 production and 397 test callers. |
| `database.OpenStandalone(path, StandaloneOptions{FS, StateFiles})`, `InitializeStoreWith` | The standalone opener (CLI commands, `pid-census`, tests): `storage.Open`, `Prepare` and `Migrate` with books as the only owner, then the store over books' range and HEAD's open-time repairs. It warms memdb at once (`warmNow`), as HEAD's open did. `NewPebbleStore` and `NewPebbleStoreInMemory` call it. |
| `(*PebbleStore).RunBootRepairs(ctx)`, `AttachStorageAdmin`, `CommittedWrites()` | `RunBootRepairs` runs HEAD's open-time writers (journal clock, ident-index stamp, `ReconcileOpsV3WithV2`, `ReconcileVerifiedEmails`) and starts the deferred memdb warmup. `CommittedWrites` is the count of commits through books' range; tests use it to prove `Register` writes nothing. |
| `database.ValidateDatabaseType` | HEAD's database-type check, now run in `books.Options` before anything opens. |
| `database.NewOwnedGatedDB`, `(*GatedDB).SyncWAL`, `Barrier`; `GatedBatch.Apply`, `Len`, `Count`, `Empty`, `Indexed` | The parts of `GatedDB`'s Pebble-shaped API the store uses, mapped onto `LegacyRange` in `legacyrange.go`. A closed store's `SyncWAL` is a no-op (`ErrClosed` means there is nothing left to sync). |
| `books.Module()` (no store), `books.StateFiles(stateDir, dbPath)` | The module and its state-file table: `encryption_key` (where `InitEncryption` would read it) and `gap_fill` (`config.yaml` beside the database). The pre-migration checkpoint copies both. |
| `books.deferredSettings` (unexported) | An overlay over the settings store. The settings load reads its own writes (secrets encrypted into the overlay), and `apply()` replays the writes in order once, in the `books.repairs` start hook. It stops at the first failure with an error that names the key. |
| `app.Options.StorageStateFiles`, `kernel.Config.StorageStateFiles`, `kernel.Config.StorageClaimsShadow` | The app's state files, and the shadow dial `<PREFIX>_CORE_STORAGE_CLAIMS_MODE=shadow` (for ABO, `ABO_CORE_STORAGE_CLAIMS_MODE`), passed through to `storage.Open`. |
| `app.App.StorageAdmin()`, `kernel.(*Kernel).StorageAdmin()` | Release R1 only: the admin surface books' census, compaction stats and Pebble collector use. |
| `storage.Admin.EngineSample()`, `storage.EngineSample`, `storage.EngineLevels`; `Admin.Tables(ctx, TablesOptions)`, `storage.TableInfo`; `Admin.Flush` | Engine counters for ABO's Pebble collector, the sstable list for its census, and a flush before the census reads table properties. Each runs under a lease, so none can race `Close`. |
| `storage.FSOf(vfs.FS)`, `(*DB).ClaimViolations()`, `storage.ClaimViolation{Owner, Op, Mode}`, `ShadowViolations`, `ClaimsShadow` | The FS adapter tests use, and the counts behind `<namespace>_storage_claim_violations_total{owner,op,mode}`. |
| `app.FastExit(args, stdout, mods...)` | Answers `--print-capabilities`, `--print-storage-format` and `--print-storage-levels` before the host parses its command line. It handles a flag only when it is the sole argument. |

## Decisions and deviations

Each took the recommended option; the owner was asleep and the coordinator asked for no gates.

| # | Decision |
|---|---|
| D1 | HEAD's pre-server steps leave `serve` (06 §6.11.1 step 2). The store open, upgrades and checkpoint move to the kernel (P2, P4a, P4b), and `initializeStore` leaves `startup.Table`. `EnsureSecureStateDir` runs in `books.Options`. The key guard, `initEncryption`, the settings load with its env sync, and `config.Validate` run in books' `Register` (`bootSettings`), each Fatal as before. They run in `Register` and not in a start hook because `NewServer` reads the effective config, and `Register` builds the server the legacy mount needs before P7. |
| D2 | `Register` commits no write (05-storage §5S.4 step 12). The settings load runs over `deferredSettings`, and its writes commit in the `books.repairs` start hook (`apply()`, then `RunBootRepairs`), after Run's served write. `TestBooksConstructorWritesNothing` proves this under the production loader. |
| D3 | Fail-closed settings writes (behaviour change). HEAD logged a failure to save the blob's new layout, the maintenance-window marker or a reset of an unreadable secret, and served on, and the same upgrade ran again on every boot. Now `apply()` returns the error and the boot fails. |
| D4 | `Module()` fixes the manifest's legacy prefixes from the environment's `ABS_API_ENABLED` before the store opens, and `Register` refuses a boot whose loaded settings disagree (`errABSFlagDrift`). The real loader cannot cause that: `applyEnvAuthoritativeConfig` reapplies viper's value over the blob (`internal/config` `TestABSConfig_BlobCannotEnableOrCredentialTheABSAPI`). The check is defensive. |
| D5 | ABO resolves its own state directory and passes it as `Options.StateDir`. `books.Options` refuses when core's `ResolveStateDir` would name a different one. It also refuses an empty `database_path`, and runs `ValidateDatabaseType` before anything opens. |
| D6 | The memdb warmup is deferred to `RunBootRepairs` (`warmDeferred`), so a boot that fails between `Register` and the start hooks leaves no goroutine reading the store the kernel is closing. The repairs hook's `Stop` closes books' store, and the kernel closes the core DB after every module has stopped. |
| D7 | Projection kept (09 §9.2.2 "R0 and R1 raise no level"): every owner's level is 0, `<db>.storage-format` stays HEAD's 1, and the `db_version` row keeps its record ID. So `scripts/storage_format_guard.py` and `make rollback` are unchanged. |
| D8 | `--print-storage-levels` prints JSON (`{"books":0,"core":0}`), as the brief's code contract and the image probe require. §5S.3.7's table says "`<owner> <level>` per line"; this follows the brief. The brief's acceptance line `--print-storage-levels --db "$(mktemp -d)/x.pebble"` cannot pass as written: §5S.3.7 says the flag reads manifests only and opens nothing, and a fast-exit flag must be the sole argument, so `--db` is read as an unknown command. The flag alone exits 0 with the JSON, and every caller (the image probe, `make rollback`) passes it alone. |
| D9 | R0 is `v0.223.0` (STATE.md, W03 OWNER-02). `TestR0OpensR1Store` downloads the release archive and checks it against pinned SHA-256 values, or uses `ABO_R0_BINARY`. CI's `boot-crash-matrix-abo` job builds the binary from the tag when the download fails. |
| D10 | `TestBootCrashMatrix_ABO` is partial. It boots books' storage declaration with a no-op `Register` (books' `Register` and `NewServer` share process globals the kit's concurrent boots would collide on). It covers every writer label from P0a up to Run's start step (0) over 7 fixtures, and `TestBootCrashMatrix_ABOCoversEveryWriter` lists the labels no fixture reaches, with reasons. Books' start-hook writes have no writer label in core yet. Tracked in `todo.d/2026-11-08-crash-matrix-abo-start-hooks.md`. |
| D11 | `TestBooksWritesEveryFamily` is driven by the family registry. It writes and deletes a probe in each of more than 200 families, then saves the settings and writes an import root's scan statistics, all under strict claims. |
| D12 | `Migration.Down` removed. Core storage never runs it: 66 entries (64 `nil`), `migration059Down`, `migration065Down` and `setVersion`, which only `migration065Down` called. `migration065Down`'s notes on what happens to opv3 records while an older binary runs (still true for a rollback to R0) moved onto `migration065Up`. 04-package-mapping.md:1332's `export_test.go` row for `migration065Down` is now moot. |
| D13 | The store-reference ratchet went from 28 to 26 (`store_consumers_test.go`). The bad-stamp storage-format test reads the sidecar. serve takes the telemetry snapshot before `app.New`. |
| D14 | R1-20's hand-off, "handles that refuse writes until the start of `Run`" (seams.d/R1-20.md, Served write row), was not built. It is not in this row's brief, and it changes `core/kernel` while R1-17 and R1-18 are both editing it. Books' side holds already (D2). The measured cost (seven write checks in core storage, the kernel's handle constructor, five core fixtures that write before `Run`, ABO's composed harness, and a fail-closed production risk) is written into TODO.md's existing entry "R1-23: enforce 'a module constructor writes nothing'". Recommended as its own row after R1-17 and R1-18. |
| D15 | Core's coverage floor starts at 80.8. The short suite measured 81.5 % under `-race` on darwin, over current main (R1-17's `internal/httpmw` is at 61 %; without this branch's lines core is at 81.4 %), and 0.7 points of headroom covers the variance between darwin and linux runs. The branch's own added core statements are 89 % covered: `Admin.Tables` has its own tests (`tables_test.go`), and the kernel's `StorageAdmin` and claim-violations counter are exercised by `core/app`'s storage tests, which a per-package profile credits to `app`, not `kernel`. An 82.0 floor from an earlier measurement (82.7 %, before the rebase onto R1-17 to R1-19) failed on the rebased tree. `test-short` writes `coverage.out` in its single pass, and `coverage-floor` fails below the floor or when the profile, the file or a readable number is missing. |
| D16 | Shard weight `internal/books: 55`: its measured `-short -race` elapsed time, against a 10 s default that would have misplaced it. |
| D17 | Rebased over R1-18's logging (#4476). Its `books.ServeInputs.StateDir`, which `serve` filled from its own `EnsureSecureStateDir`, is gone: `serve` no longer resolves the state directory. `books.Options` resolves it once and passes it to both `Options.StateDir` and `logSettings`, so the log file `logs/abo.log` stays under the state directory. R1-18's `TestServe_PassesTheStateDirForTheLogFile` is replaced by its own `TestFileOutputUnderStateDir`, which now sandboxes the state directory through `bootComposedIn`. `TestServeStartupLinesGoToStdoutBeforeTheApp` keeps its assertion. The lines it checks now come from inside `app.New` (the kernel's P2 to P4b, before P5 installs the pipeline), so its stubbed `runApp` logs them. The key guard, encryption init and settings load run at P6 under the App's pipeline. |
| D18 | Two smaller merge consequences. First, `OpenStandalone` drops its `logger.Sanitizing` wrap because R1-18 deleted the wrapper (093280a0d). Core storage's messages are constant strings, and slog's text output quotes attribute values even under the stock default. Second, the op in `TestOpLogger_CapturedDuringRegisterKeepsLevelAndOpID` is `NoWarmupWait`. The memdb warmup starts in the `books.repairs` start hook (D6), and `bootComposed` runs no start hook. A warmup that never started holds every other op at the dispatcher's D44 gate, which is the fail-closed reading. App.Run runs the hook, so production is unaffected. |
