# R1-15 seams and coined names

This file lists what the composition-root PR added beyond 06 §6.4.5, §6.5.2 and §6.11.1, 05-metrics §6, 05-logging §3 and 05-rbac §6.1: names the spec does not have, readings it took where the spec or brief is silent, the risks it leaves, and the seams later rows (R1-16, R1-17, R1-18, R1-23, F2, F3, F4) build on.

## Deployability

**Verdict: deployable: shim parity test.** `TestPerimeterShim_ParityWithHEAD` sends every kind of answer through HEAD's listener stack and through R1's (peer gate, perimeter shim, kernel, books' mount) and compares status, headers and body. It covers an engine route, the SPA, gin's and the kernel's legacy 404, the /api redirect, an unmatched method, core's group, health, the Engine.IO probe and CORS preflights. It runs open, behind the Basic gate, and from an allowed and a denied peer. `TestPerimeterShim_UnmatchedMethodMatchesGin` repeats the unmatched-method scan through the shim, OPTIONS included. `TestComposedApp_UnmatchedMethodMatchesGin` runs it against the real composed App. Parity holds everywhere but one place. Under `/api/core/` the kernel answers core's problem 404 where HEAD's NoRoute wrote its legacy 404. Status and perimeter headers still match there, and no ABO client calls that group.

Two risks are not perimeter parity, so the verdict does not cover them. They are listed under **Risks** below: the 60 s hook start timeout and the periodic HNSW export.

## Names beyond the spec

| Name | What it is |
|---|---|
| `app.Options.ProcessDefaults` | The composition root will call `InstallProcessDefaults`. New then installs the OTel SDK's value-dropping logger and its rate-limited error handler **before** it builds the Provider. It fails with `ErrProcessDefaultsTaken` when another App holds them, and puts them back when boot fails. books sets it. Why: building the resource and an OTLP exporter makes the SDK read `OTEL_*` from the environment. The SDK reports bad input raw, through those two globals, and `OTEL_EXPORTER_OTLP_HEADERS` can carry a credential. HEAD's InitOTEL installed its sink first for the same reason. |
| `kernel.Config.BeforeTelemetry func(*slog.Logger) error` | The P5 hook `ProcessDefaults` uses: it runs after logging is built and before `metrics.New`, with core's `otel` logger. Describe never calls it. |
| `app.installOTelDiagnostics` / `otelDiagnostics` | The SDK-logger and error-handler half of the seven process installs, shared by New's early install and `InstallProcessDefaults`. `TestNoGlobals`' exemption is now per function: this one may call `otel.SetLogger` and `otel.SetErrorHandler`, and `InstallProcessDefaults` may call the other five setters and restore's getters. `processErrorHandler.complete` marks a set that `InstallProcessDefaults` has completed. That is how a second install by the same App is refused, with no package state. |
| `app.InstallProcessDefaults`, `ErrProcessDefaultsTaken` | 05-logging §3's seven installs and restore. `TestInstallProcessDefaults_RestoreAndExclusive` and `TestFamilyTaken_ThroughGlobalProvider` are the spec's tests. |
| `app.Options.R1Listen` / `R1Server`, `R1Telemetry`, `LogOutput`, `(*App).Metrics()` | R1-only fields. R1Listen opens start step 7's listener with ABO's HEAD stack: the kernel still decides when, and drains it first. R1Telemetry carries the OTLP push, the span exporter and the environment into the kernel's Provider until F3, so production tracing survives. LogOutput is the pipeline's output. `Metrics()` is the composition root's handle on the served registry (05-metrics §6 R1 row). The kernel fails boot on `metrics_family_taken` raised during New or before the listener opens. |
| `books.Module(store)`, `Options(mod, ServeInputs)`, `Attach(mod, app)`, `Release(mod)`, `Stopped(mod)`, `ServeInputs` | The composition root's glue. `ServeInputs` is serve's listener flags plus the telemetry config snapshot. `Attach` binds the App's Provider registry as the served `/metrics` one and points the App's log output at the activity feed. `Release` tears down a server that `Register` built but no hook started. `Stopped` is what serve waits on before closing the store, because the kernel abandons a stop hook at the budget without stopping it. |
| `books.Atom`, `AtomTable()`, `RouteRequirement(req)`, `resolveRoutes` | 05-rbac §6.1 as books' code. `RouteRequirement` resolves a manifest row's `rbac.LegacyAtom(a)` to the atom's AllOf requirement, and returns false for `playlists.create` and for an atom outside the table. `Register` runs the manifest through `resolveRoutes` before `MountLegacy`, so every `s.perm(atom)` route mounts with the native requirement the table gives its atom, as 05-http-api §8.1's R1 row and `httpapi.LegacyRoute.Perm`'s doc require. An atom that does not resolve fails Register, like the drift check above it. `TestManifest_SPermRoutesCarryAtomRequirement` checks both `resolveRoutes` and the routes the booted App mounted (`App.Routes()`), and runs `archtest.RoutesHavePermissions` over the booted router. |

R2 moves them into `atoms.go`. **Owner choice:** keep this, or approve a baseline block that puts them in `atoms.go` now. |
| `server.R1Listener`, `(*Server).StartHook`, `StopHook`, `R1Listen`, `LegacyHandler`, `LegacyRoutes(abs)`, `AttachMetrics`, `ActivityLogWriter`, `ReleaseUnstarted`, `Stopped` | HEAD's `Server.Start` split into the pieces the kernel drives (the server refactor commit's message has the step order). `ReleaseUnstarted` is a no-op once StartHook has begun. `Register` stores the server before its checks, so `Release` also tears it down when Register fails. `peerGatedHandler` is deleted: HEAD's listener was its only caller, and the R1 listener gates the shim instead. |
| `server.LegacyPrefixes(abs)`, `LegacyTopSegments()`, `LegacySPAShared()` | One source for the mount's claims and segments. books' Manifest and Register read them, and so does R1-14's `booksMount` test fixture. `LegacyTopSegments` is `nonSPASegments`, sorted. |

## Readings and decisions

| Topic | Reading |
|---|---|
| NewServer in Register | `Register` must do no I/O (06 §6.4.1). The brief says `books.Register` builds today's `*server.Server`, and books has no other place to build the engine `MountLegacy` needs before P7. So Register runs `NewServer`, which opens the service container and sets package globals (the scanner's store, the global store). Consequence: `app.Describe` over books would do that I/O. ABO calls Describe nowhere today. R1-23 and the rows that split the server retire the exception. |
| A built server nobody starts | Building in Register opens a window HEAD did not have: boot can fail after the server exists. That covers app.New refusing at P7, `InstallProcessDefaults` or `Attach` failing, and Run failing before the start hook. serve calls `books.Release` on every path out, and Release closes `Stopped`. |
| Claims | books declares the subtree of every manifest route's first segment (or `/api/<seg>/`), plus every top segment and `login`, whether or not a route sits there. The kernel requires each TopSegments and SPAShared entry to be a declared prefix (P7), and an unmatched path under a claim gets the legacy 404 HEAD's NoRoute gave. `/socket.io/` is claimed with no route, so the Engine.IO probe keeps HEAD's legacy 404. |
| ReservedAPINamespaces | Every unversioned `/api/<seg>` the ABS surface can register, ABS on or off, so no module takes a name that enabling ABS would need. |
| HNSW stop export (decision 1) | A periodic export runs every 10 minutes when the graph changed (`ExportIfDirty`, on bgWG). The stop-time export runs only when what is left of the budget covers the last export's duration plus a margin. Otherwise an INFO line gives the snapshot's age. The 25 s budget is not raised. A snapshot is written only from a complete graph (`ErrHNSWIncomplete`). HEAD exported a partially hydrated graph with the current truth count, so the next boot took it as fresh. **Delta replay is not done.** coder/hnsw v0.6.1 corrupts on Delete and re-Add of a key, the crash class `safeAdd`/`safeDelete` contain. A replayed graph could then serve FindSimilar from a corrupted index or panic inside it. |
| Event streams (decision 2) | The pre-drain step broadcasts the shutdown event and then closes `/api/events` and the ops event streams (`endStreamsOnShutdown`, `closeOpsV3Streams`), so they do not hold the drain. |
| Listener (decision 3) | R1Listen keeps HEAD's stack: HTTPS with HTTP/2, HTTP/3 with Alt-Svc, the port-80 redirect, the TLS fallback and the peer allow-list. **After R1-17, HTTP/3 and the port-80 redirect have no owner.** Core's listener carries neither, and no row in the plan adds them. |
| Alt-Svc | HEAD added Alt-Svc with a middleware registered on the engine at listen time, which gin applies to the NoRoute chain only. The engine still does that. The shim adds the same value to the kernel's own answers, except the /api redirect's 301 (HEAD's redirect middleware ran first). Routed answers never carried it, in HEAD or now. |
| OPTIONS | The shim sends every OPTIONS straight to the engine, whose CORS middleware answered all of them in HEAD. So OPTIONS skips the kernel's dispatch, its access log and its HTTP instrumentation until R1-17's stage 6. |
| Telemetry (decision 5) | serve snapshots the config right after the store opens, where HEAD's InitOTEL read it: before the stored settings and env overrides apply. The OTLP endpoints, interval and environment come from where they always did (`TestServe_TelemetryReadBeforeStoredSettings`). The tracer is the App's SDK provider whenever `OTEL_EXPORTER_OTLP_ENDPOINT` is set (`TestR1Telemetry_TracerFromEnv`). The startup table's InitOTEL row and its degraded `metrics` token are gone. **A Provider that cannot be built now fails `app.New`**, where HEAD's InitOTEL degraded and served on. |
| Activity feed (decision 6) | In HEAD, NewServer made a text handler over the activity writer slog's default. `InstallProcessDefaults` now installs the App's logger instead, so the App's `LogOutput` is pointed at the same writer (`logTee`) to keep the Activity page's scheduler and operation lines. R1-18's activity tap replaces the tee. |
| Kernel accessors (decision 7) | `Kernel.Provider`, `RootLogger` and `CoreLogger` exist for package app (`InstallProcessDefaults`, `Metrics`). A `metrics_family_taken` raised during New or before the listener opens fails boot. |
| init() overrides (decision 8) | The operations registry's and the updater's `init()` service-container overrides moved into server.go's container. `cache.go` and `cache_snapshotter.go` read the served registry. With serviceregistry out of `pkg/plugin/sdk`'s closure, the sdkguard snapshot shrinks. |
| Master-list rows | 05-rbac §6.1 gives `users.manage` the route requirement `AllOf(core:users.manage, core:roles.view)`. §6.2 gives the four master-list routes (adminRole plus `s.perm(users.manage)`) `AllOf(core:users.manage, books:admin.view)`. R1-14's manifest records §6.2's value, so those four rows are not `LegacyAtom` rows. `TestManifest_SPermRoutesCarryAtomRequirement` pins them by method and path. F4 must decide whether the route needs `core:roles.view` too, the union of both rows. |
| MethodSpec | books registers `books.abs` with the name only (AppHandoff and the rest nil). R1 records the declaration for P7's OwnAuth admission; R2 fills it. |
| Manifest fields left empty | `PublicRoutes` is empty, because the legacy Public rows are keyed by method and path and `public_routes.golden` gates them (R1-14). No native route exists. `SPAOptions.BasicExemptAssets` is unset; the engine's own Basic gate exempts its assets until R1-17. |
| Core's family contract | The series contract test scrapes the served `Provider.Handler()` (`TestContractScrapesServedHandler`), and its golden is unchanged. Core's own families (`audiobook_organizer_kernel_*`, `target_info`) and the OTel-recorded families without the namespace (`http_server_*`, `ai_*`) are outside ABO's legacy series contract. |
| Tests that need a fresh process | `TestABOMetricsGatherNoDuplicate` and `TestServeComposition_HostileOTLPEnvNeverLogged` re-run themselves in a child test process (`inFreshProcess`). OTel's global delegate binds instruments made before the first `SetMeterProvider` to the first provider set, and ABO's recorders are made once per process. In a shared test binary, a later App would not get them. Production has one App per process. |
| Coordinator tests vs the brief | The brief's `TestBooksDisabledInert` predates R1-37, so it said `coretest.AssertModuleInert` would not exist. R1-37 merged first, so the test uses the harness and AssertModuleInert over the real module, plus checks that Register never ran and no server was built. `TestOnlyCompositionRootImportsModule` reads the real graph through `core/archtest`, which R1-37 also edits; this PR's change to it is the third-party allowlist (the otel root package, logr, stdr) and `core_test.go`'s exact-path form. |

## Risks

| Risk | Cost of the fix |
|---|---|
| **60 s hook start timeout.** The kernel abandons a hook Start after `startTimeout` (60 s, `core.lifecycle.start_timeout`) and fails boot. books' StartHook is HEAD's start up to the listener (op registration gate, container start, op catalog gate, search index, warmers), which ran unbounded in HEAD. It has not been measured at prod's size. `Deps.ExtendStart` is a no-op until R1-16 wires sdnotify into core. | Measure StartHook on prod before deploying. If it can exceed 60 s, either make the kernel honour `ExtendStart` in `startHooks` (a core change, plus a kernel test) or move the slow steps after readiness. |
| **Periodic HNSW export.** At prod's size an export took about 40 s before the buffering fix. It now runs every 10 minutes while the graph changes, on bgWG. | Measure the buffered export's duration on prod. If it is still long, raise `hnswSnapshotInterval` or export only on idle. |
