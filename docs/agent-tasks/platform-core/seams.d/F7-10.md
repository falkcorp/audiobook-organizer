# F7-10 seams and coined names

This file lists what the integration instance routes PR (05-metadata M1.3 "HTTP surface", package `core/internal/integrationhttp`) added beyond the spec's Go blocks: the readings it took where the spec or the brief is silent, the one interface change made after review, and the seams later rows build on. Everything not listed here follows the spec as written. The package is dark: nothing imports it until F7-09 mounts it.

## Amendment after review: the hold route does not probe

`HoldReleaser` started as one method, `ReleaseHold(ctx, scope)`, and the route read the instance's hold from `Registry.Health`. That was wrong for two reasons. `Health` probes the remote, and for a disabled or misconfigured instance it answers a static finding with a nil `Hold`, so the hold of such an instance could not be released. Then a first rewrite read the scope with `HeldScope` and released it with `ReleaseHold(scope)`, which is not atomic: a hold set between the two calls is released unseen. The interface is now the atomic pair F7-02 builds on `providerhttp.Registry`:

```go
type HoldReleaser interface {
	HoldFor(ref integrations.Ref) (integrations.Hold, bool)           // gate state only; never probes, builds a client or sends
	ReleaseHoldIf(ctx context.Context, expect integrations.Hold) error // releases expect only while it is still the hold in force
}
```

The route never calls `Registry.Health`. It reads the hold with `HoldFor` and releases exactly that hold with `ReleaseHoldIf`.
- No hold (or a hold with no scope) is 204 and `ReleaseHoldIf` is not called; the call is idempotent. A released hold is 204 too.
- `ReleaseHoldIf` nil when no hold is in force any more (it ended in the gap) is 204: the goal is met.
- A different hold in force releases nothing; `errors.Is(err, ErrHoldChanged)` gives 409 `hold_changed` with fixed text and no hold text. The operator reads the instance's health again and decides again.
- An instance that does not exist is 404. The route is not `RateExpensive`: it sends nothing to the remote.

## Seams later rows must honour

| Seam | What F7-10 does | Who builds on it |
|---|---|---|
| `HoldReleaser` and `ErrHoldChanged` | The interface has `providerhttp.Registry`'s `HoldFor` and `ReleaseHoldIf` signatures; the hold is `integrations.Hold`. This package cannot import `providerhttp` until F7-02 (#4610) has merged, so it declares `integrationhttp.ErrHoldChanged` for the route to recognise (`errors.Is`), standing for `providerhttp.ErrHoldChanged`. The tests run against a fake with the same semantics (`ReleaseHoldIf`: same hold in force released, none in force nil, a different one `ErrHoldChanged`). | **F7-09** (or a follow-up once both have merged): redeclare `var ErrHoldChanged = providerhttp.ErrHoldChanged` here (one line) or wrap the registry so its error maps to this one, and add `var _ integrationhttp.HoldReleaser = (*providerhttp.Registry)(nil)`; pass the `*Registry` as `holds`. |
| Typed nil at `Register` | The route nil-checks `reg`, `holds` and `auditLog` to fail closed (503). `holds` and `auditLog` are interfaces, so an interface holding a nil pointer is not nil and passes the check, then fails or panics at the call. | **F7-09** must pass an untyped `nil` or a real value, never a typed-nil `*providerhttp.Registry` or logger. |
| `integrations.ManagePerm` | F7-10 exports F7-01's `managePerm` as `integrations.ManagePerm` (one line in `registry.go`, the Registry uses it) and declares its manage routes with it, so the router and the Registry cannot name different permissions. A test pins the text in the route table and by behaviour (a principal holding exactly it can write and release). | None. |
| The hold route checks the permission itself | Brief deviation (m2). Every other route leaves the permission to the router and the Registry's write check. The hold route has no Registry write behind it, so it checks `Perms != nil && Perms.Has(manage)` after the principal check and answers 403 otherwise. Read routes are unchanged. | Stage 13 (F4-08) enforces `Perm` for every route; this is the backstop for a mounting mistake. |
| Permission before existence | `PUT` and the instance test run the same check before the 404 pre-check, so a caller without manage cannot tell a missing instance from an existing one. Create, delete and the unscoped test already get this from the Registry, whose write checks come first. | None. |
| The test is audited after it runs | `core.integration.test` carries the result, so the record is written after `Registry.Test`. By then the credentialed probe has been sent: a failed record answers 503 and withholds the result, it cannot unsend the probe. Only a nil audit logger stops a test before the probe. The comments on `Register` and `runTest` say so. | **Owner decision.** Recording an attempt before the probe needs a Registry change (it would have to audit `Test` itself, or take a pre-record hook), which is F7-01's file and a larger change. |
| `PUT` is a complete replace | `name`, `enabled`, `priority`, `local` and `limits` are required (a pointer each; absent and `null` are both a 422), so a client cannot reset them by leaving them out. `limits: {}` means inherit everything and is stored as no limits. GET always answers `limits` (`{}` when none). The route decodes **strictly**: an unknown key, also inside `limits`, is a 400, so a misspelt `secrets` is never silently dropped. A GET answer edited and sent back is still valid because `kind`, `origin`, `secrets_set`, `locked`, `stored` and `updated` are declared read-only members of `IntegrationInstanceReplace` (accepted, never read). They are documented in the route `Doc` and the type comment, **not** marked `readOnly` in the schema: `core/internal/jsonschemax`'s tag pass has no such keyword, and adding one is a change to that shared L0 package. | The web client (F7-09 onwards) edits the GET answer and sends it back. A `readOnly` schema keyword would be a `jsonschemax` change. |
| Credential-bearing URLs are withheld | The Registry refuses userinfo when a URL-typed field is written, but an operator-layer value is not a Put. The settings view screens three kinds of field and no other, so free text such as a message template is answered as stored and a GET-edit-PUT keeps it. (1) A field an operator value locks (`Locked`) gets the **aggressive text check**: any string, or map key, in which any `//` (not only the first) opens an authority containing `@` (whitespace does not exempt it, a backslash counts as a slash, an unparsable URL is still caught). It withholds some harmless locked text (a sentence holding `//x ... a@b`); that is the price of failing closed, because the type of a locked field is not known to the view. (2) A field the adapter schema types as a URL (`format: uri`, on the property or its `items`) gets **the Registry's own rule**: `url.Parse`, unsafe when `User != nil`, and a value that does not parse is withheld. So `https://h/cb?next=https://u@x` and `https://h/a//b@c` are answered unchanged and round-trip. (3) **Every string-valued setting of an instance whose adapter this binary does not have** (or whose schema cannot be read) is treated as URL-typed, with the same parse rule; such an instance cannot be edited, so nothing is lost by it. A value of a kind that cannot be walked (a struct, a function, a map not keyed by strings), or nested deeper than 64 or larger than 65536 nodes (so a hand-built cycle ends the walk), is withheld under either check. A screened field is left out **whole**. A locked field may be omitted from a PUT, so the answer still round-trips, and a field that kept only some elements could not (409 `field_locked`). Read callers still see locked values that pass the check: 05-metadata M1.3 has the API return the effective instance with `Locked` naming each locked field, and withholding locked values from `core:integrations.read` callers is not in the spec (decided with the coordinator, 2026-11-11). | None. |
| A withheld URL field cannot be cleared by omission (422 `withheld_field`) | A stored, unlocked, URL-typed field the view withholds (a legacy value with userinfo, written before the Registry refused it) is not in the GET answer, so a GET-edit-PUT omits it. `PUT` is a complete replace, so omission clears the field, and the Registry then sees the instance's origin change and drops every stored secret. `PUT` therefore computes the withheld fields with the function the view uses and answers **422 `withheld_field`** (fixed text, `fields[].field` = `/body/settings/<field>`) when the body does not name one; nothing is written. A body that names the field, with a clean URL, with `null` (an explicit clear) or with any other value, goes on to the Registry, which judges it. A locked field is not in this check (it may be omitted by rule). | None. |
| `HoldFor` must resolve the scope from the persisted instance policy | Cross-PR (m9). The hold route releases `HoldFor(ref)`'s hold. F7-02's `providerhttp.Registry.HoldFor` must resolve the hold's scope from the persisted instance policy (the stored row, which this PR's routes edit), not from the build history of the client last built, or a hold on an instance whose policy changed since its last build is released under a stale scope. | **F7-02** (#4610). |
| 404 for a missing or non-grammar instance | Path kinds and IDs are checked before any Registry call and the path value is never echoed. | None. |

## Names beyond the spec

| Name | What it is |
|---|---|
| `integrationhttp.Register(g, reg, holds, auditLog)` | Registers the ten routes on the core group. |
| `integrationhttp.HoldReleaser` | The two-method seam above. |
| `IntegrationInstance`, `IntegrationInstanceBody`, `IntegrationInstanceReplace`, `IntegrationLimits`, `IntegrationAdapter`, `IntegrationTestResult`, `IntegrationHold`, `IntegrationHealth` | The wire types. Their names carry the `Integration` prefix because an OpenAPI component is `<module>.<TypeName>` and every core capability shares the `core` owner. |
| Error codes `field_locked`, `version_conflict`, `integrations_disabled`, `permission_denied`, `not_found`, `unavailable` | Fixed texts; the Registry's message is never returned, and a 422 keeps no cause. |
