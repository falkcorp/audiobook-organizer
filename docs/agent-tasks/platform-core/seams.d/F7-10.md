# F7-10 seams and coined names

This file lists what the integration instance routes PR (05-metadata M1.3 "HTTP surface", package `core/internal/integrationhttp`) added beyond the spec's Go blocks: the readings it took where the spec or the brief is silent, the one interface change made after review, and the seams later rows build on. Everything not listed here follows the spec as written. The package is dark: nothing imports it until F7-09 mounts it.

## Amendment after review: the hold route does not probe

`HoldReleaser` started as one method, `ReleaseHold(ctx, scope)`, and the route read the instance's hold from `Registry.Health`. That was wrong for two reasons. `Health` probes the remote, and for a disabled or misconfigured instance it answers a static finding with a nil `Hold`, so the hold of such an instance could not be released. The interface is now:

```go
type HoldReleaser interface {
	HeldScope(ref integrations.Ref) (scope string, ok bool) // answers from the gate; never probes, sends or waits on the network
	ReleaseHold(ctx context.Context, scope string) error
}
```

The route never calls `Registry.Health`. With no hold it answers 404 `no_hold` and calls nothing, so a 204 always means a hold was released. An empty scope from `HeldScope` counts as no hold (releasing `""` could mean every hold).

## Seams later rows must honour

| Seam | What F7-10 does | Who builds on it |
|---|---|---|
| `HoldReleaser` has no implementation yet | Neither `HeldScope` nor `ReleaseHold` is on `providerhttp.Registry` today. The route is tested against a fake that counts calls. | **F7-02** adds both to `providerhttp.Registry` (`HeldScope` over `Holds()` and `GateFor`; it must not probe). **F7-09** passes that `*Registry` as `holds`. |
| Typed nil at `Register` | The route nil-checks `reg`, `holds` and `auditLog` to fail closed (503). `holds` and `auditLog` are interfaces, so an interface holding a nil pointer is not nil and passes the check, then fails or panics at the call. | **F7-09** must pass an untyped `nil` or a real value, never a typed-nil `*providerhttp.Registry` or logger. |
| `core:integrations.manage` is written twice | `integrations.managePerm` is unexported (F7-01), so the package declares `permManage` with the same text. A test pins the two by behaviour: a principal holding exactly `permManage` can write through the Registry and release a hold. | **F7-01** follow-up: export it as `integrations.ManagePerm` and delete `permManage` here (a one-line export and one const removed). |
| The hold route checks the permission itself | Brief deviation (m2). Every other route leaves the permission to the router and the Registry's write check. The hold route has no Registry write behind it, so it checks `Perms != nil && Perms.Has(manage)` after the principal check and answers 403 otherwise. Read routes are unchanged. | Stage 13 (F4-08) enforces `Perm` for every route; this is the backstop for a mounting mistake. |
| Permission before existence | `PUT` and the instance test run the same check before the 404 pre-check, so a caller without manage cannot tell a missing instance from an existing one. Create, delete and the unscoped test already get this from the Registry, whose write checks come first. | None. |
| The test is audited after it runs | `core.integration.test` carries the result, so the record is written after `Registry.Test`. By then the credentialed probe has been sent: a failed record answers 503 and withholds the result, it cannot unsend the probe. Only a nil audit logger stops a test before the probe. The comments on `Register` and `runTest` say so. | **Owner decision.** Recording an attempt before the probe needs a Registry change (it would have to audit `Test` itself, or take a pre-record hook), which is F7-01's file and a larger change. |
| `PUT` is a complete replace | `name`, `enabled`, `priority`, `local` and `limits` are required (a pointer each; absent and `null` are both a 422), so a client cannot reset them by leaving them out. `limits: {}` means inherit everything and is stored as no limits. GET always answers `limits` (`{}` when none), and the route is `Lenient`, so a GET answer edited and sent back is a valid body: `kind`, `origin`, `secrets_set`, `locked`, `stored` and `updated` are accepted and ignored. The cost of `Lenient` is that a misspelt optional key (`settings`, `secrets`) is ignored rather than refused. | The web client (F7-09 onwards) edits the GET answer and sends it back. |
| Userinfo is withheld from settings | The Registry refuses userinfo in a Put, but an operator-layer value is not a Put. The settings view leaves out any string (also inside maps and lists) whose authority part carries `@` (`scheme://user@host`, `//user@host`), whether or not it parses. An operator-locked field may be omitted from a PUT, so the answer still round-trips. | None. |
| 404 for a missing or non-grammar instance | Path kinds and IDs are checked before any Registry call and the path value is never echoed. | None. |

## Names beyond the spec

| Name | What it is |
|---|---|
| `integrationhttp.Register(g, reg, holds, auditLog)` | Registers the ten routes on the core group. |
| `integrationhttp.HoldReleaser` | The two-method seam above. |
| `IntegrationInstance`, `IntegrationInstanceBody`, `IntegrationInstanceReplace`, `IntegrationLimits`, `IntegrationAdapter`, `IntegrationTestResult`, `IntegrationHold`, `IntegrationHealth` | The wire types. Their names carry the `Integration` prefix because an OpenAPI component is `<module>.<TypeName>` and every core capability shares the `core` owner. |
| Error codes `no_hold`, `field_locked`, `version_conflict`, `integrations_disabled`, `permission_denied`, `not_found`, `unavailable` | Fixed texts; the Registry's message is never returned, and a 422 keeps no cause. |

## Deferred, not in this PR

- `integrations.checkURL` quotes the submitted URL in its error text; the route maps every 422 to fixed text, so nothing leaks here, but the Registry's own log and error text still carry it: F7-01 (fix in progress as `fix/core-integrations-url-error-no-echo`).
