# F5-18j seams and coined names

F5-18j retires the legacy author-junction rows (`author_books_legacy:<authorID>:<bookID>`), the author to books index's copy of `Book.AuthorID`, so a book-row write is no longer an `authors` write. Spec: `docs/plans/platform-core/F5-18-prep-split-proposal.md`, "F5-18j". Obligations: O25, O36. Owner rule: author and narrator are ordered credit lists, always; the credit list (`book_authors:<bookID>`) is the author source.

This row changes LIVE behaviour (the store's book write path and the index read gate) and adds a data-deleting maintenance op that has NOT run anywhere but tests. The op runs on prod only after the owner's go; the plan is at the end.

## What changed

- **Nothing stages the legacy family.** `CreateBook` and `updateBookLockedMode` (which `UpdateBook` and `ModifyBook` share) no longer stage `author_books_legacy:` keys; `DeleteBook` drops only the credit keys (`stageAuthorBooksDelete(batch, id, creditIDs)`). `TestBookWrites_TouchNoAuthorsFamilyKey` (`internal/books/store/author_books_legacy_retired_test.go`) runs every book-row write that used to stage a legacy key (CreateBook with an AuthorID, UpdateBook changing and leaving the AuthorID, ModifyBook setting, clearing and setting it again, RecomputeBookAggregates) and asserts the authors-family key set is byte-for-byte unchanged. It failed red before the store change (`CreateBook with an AuthorID changed an authors-family key`, the staged `author_books_legacy:1:<id>`).
- **Nothing reads it.** The index reader and `ReconcileAuthorBooksIndex` are credit-only (`internal/books/store/pebble_store_author_books_index.go`, header comment). The only code that names the prefix is the retirement op's store half.
- **The index's trust moved from a persistent sentinel to the process.** The listing scan, memdb and every merge/relink getter still link a book through `Book.AuthorID` as well as its credit row (retiring `Book.AuthorID` itself is the credit-list plan's PR 4 to 6, `docs/plans/2026-10-04-author-narrator-credit-lists-audit.md`). A credit-only index agrees with that scan only while every listable book's AuthorID is in its credit row, and writers outside the store still set an AuthorID without a credit, so a check from an earlier boot says nothing about the writes since. The reader now uses the index only after THIS process's reconcile finished clean (`authorBooksVerifiedThisBoot`): every credit row decoded, and no listable (live, primary or unversioned) book carries an AuthorID its credit row does not name. Reconcile reports `uncovered_books` and a sample in its `author-books-index: complete:` log line and returns an error naming `maintenance.credits-backfill` when any are found. Cost: each boot answers cold author listings by the scan until its reconcile finishes (a full pass over credit and book rows on a CPU-sized pool, `runAuthorBooksPass`).
- **The v1 sentinel is deleted in the open repairs, before the first write, and again at reconcile start** (`dropAuthorBooksSentinelV1` from `runOpenRepairs`, `system:backfill:author_books_index_v1_done`; r1 m2). Rollback safety: a pre-F5-18j binary trusted its index without reconciling whenever that sentinel carried its own build identity, and after this build has run the legacy family is no longer maintained, so it would answer from rows that miss every book written since. Without the sentinel the old build scans until its own boot reconcile has rewritten every absent key from `Book.AuthorID`.
- **`authors` left the book write.** `internal/maintenance/resources/resources.go`: `bookW` is `{books, metadata_cache, indexes}`; `CreateBook` is `{books, indexes}`. Every row derived from them narrowed with them (25 `rowsPinned` rows, including the four the spec names: `ModifyBook`, `UpdateBook`, `CreateBook`, `RecomputeBookAggregates`). Methods that really write credits (`SetBookAuthors`, `ModifyBookAuthors`, `ModifyBookCredits`, author create/merge/delete) keep `authors`.
- **Declarations followed.** 19 native kinds dropped `ResAuthors` from their declared Effects (`kinds_effects_pinned_test.go`: 25 pinned kinds narrowed, 14 + 11), and 18 maintenance jobs dropped it from `jobWritesPinned` (`internal/maintenance/jobs/writes_trace_test.go`). The Effects-equals-union tests (every kind's declared set is the union of its writer methods' rows) are the net: a kind that still calls a credit method keeps `authors` or fails.
- **The retirement op**, `maintenance.author-books-legacy-retire` (native kind `books.maintenance.author-books-legacy-retire`, `internal/plugins/maintenance/author_books_legacy_retire.go`), described below.
- `pkg/ops/effects.go`: the `ResIndexes` comment named `author_books_legacy:` as a live row-family index; it now names `author_books:` and says the retired family is `authors`, which is what the op declares.

## The retirement op

Store half: `CheckAuthorBooksLegacyRetire(ctx, progress)` (the preview) and `RetireAuthorBooksLegacy(ctx, progress)` (the delete) on `*PebbleStore`, `internal/books/store/pebble_store_author_books_legacy_retire.go`. Op half: the HEAD def plus the native kind over the t6g2 machinery, on the `book-hash-index-repair` template (check on `t6g2IndexReads`, delete on `t6g2IndexWriter`, capability `t6g2CapAuthorBooksLegacyRetire`).

- **Preview by default** (owner rule 2026-09-25, `opmode.DryRunParams`): the check and the counts, nothing written. A preview that finds blocking books lists them and SUCCEEDS.
- **The check** runs over every `book:` row in every state (trashed and non-primary included, unlike reconcile's listable-only check, because the legacy row of a trashed book is still the last index entry naming its author). A book blocks when it has an AuthorID and: it has no credit row (`no_credit_row`), its credit row does not name the AuthorID (`not_in_credits`), or its credit row does not decode (`unreadable_credits`). Sub-counts: `listable` and `naming a missing author` (the AuthorID has no `author:` row; `maintenance.author-id-repair` handles those). A stale legacy key (book gone, or AuthorID moved on) never blocks; an undecodable book row never blocks (it has no AuthorID anyone can read) and is counted.
- **The refusal lives in the delete call.** `RetireAuthorBooksLegacy` runs the same check first and, when anything blocks, deletes nothing and returns `ErrAuthorBooksLegacyRetireRefused` with the report. Nothing can delete without the check. The op logs each blocking sample as a `blocking:` line and the summary at error level, and fails.
- **Idempotent and resumable** (`ResumeRestart` / `tasks.ResumeFromZero`): the delete is by prefix in `Sync`-committed chunks of 512 (`authorBooksBatchRows`); a cut-short run leaves fewer rows and the next deletes the rest; a run over a retired store counts zero and logs a tagged no-op.
- **Bounded pool:** the book-row check runs on the store's CPU-sized errgroup pool (`runAuthorBooksPass`'s shape: one decode and one point read per row). The delete is a sequential prefix walk (no per-item work worth a pool).
- Declares `Writes {authors}`, `Reads {books, authors}`, `CapLibraryRead` + `CapLibraryWrite`, 60 min timeout, low priority. Shared table row: `RetireAuthorBooksLegacy: {authors}`.
- Registration: `plugin.go` def list, the t6g2 kind list, `op_ids.golden` (appended), `write_op_modes.golden` (`preview`), the kindrename registry golden and `map_gen.go` (regenerated, `UPDATE_KINDRENAME_REGISTRY=1` then `go generate`), the kindrename tally (books rule 225 to 226, total 269 to 270), the effects pin, the t6g2 parity row and `t6g2HeadLive`, and the conformance count (13 to 14). `internal/books/rbacreach/verdicts.json` is a recording of the R0 release binary and does not list ops added after R0; the cutover suite passes without an entry.

Tests: `author_books_legacy_retired_test.go` (store: preview writes nothing, delete leaves every non-legacy key byte-identical, idempotent re-run, refusal in both modes with the exact class counts over a fixture of every blocking class plus the non-blocking ones, progress phases) and `author_books_legacy_retire_test.go` (op: preview for no params, `{}`, `dry_run:true`, `dryRun:true`; `dry_run:false` deletes then is a tagged no-op; refusal names the book and deletes nothing while the preview over the same store succeeds; a store without the capability is refused up front), plus the t6g2 parity, shell and conformance rows.

## Seams

- **`MetafetchApplyRows` follows the narrowed `bookW` (`internal/books/writer/rows.go:55`).** `writer.MetafetchApplyRows` keeps its own copy of the book write, and `TestMetafetchApplyRows_ModifyBookRulePinned` (`gate_test.go`) requires its ModifyBook-derived rows to equal the shared table's. With the shared `bookW` narrowed here, the copy drops `ops.ResAuthors` too: `bookW := {books, metadata_cache, indexes}`, landed as this branch's top commit by the F5-18c builder on the owner's decision, so `internal/books/writer` is green on this branch alone. (An earlier revision of this file said the edit was not on the branch and the test red until F5-18c removed it; that is no longer true.)
- **F5-18c collision, semantic.** `t6g2IndexReads` gained `CheckAuthorBooksLegacyRetire` and `t6g2IndexWriter` gained `RetireAuthorBooksLegacy` (`kinds_t6_g2.go`). F5-18c's native `t6g2Deps` implementor must provide both (over `*PebbleStore` through `database.AsCapability[authorBooksLegacyRetirer]`, as the head adapters do), or the kind refuses with "store ... has no author_books_legacy: rows to retire".
- **Trust follows the writes (r1 M1).** A clean reconcile trusts the index for this process only until a write could uncover a book: `createBook`/`updateBookLockedMode` read the credit row once when a listable row gets a new AuthorID (or a book with one becomes listable) and revoke when it is not credited; `SetBookAuthors`, `ModifyBookAuthors` and `ModifyBookCredits` revoke whenever an author is dropped. Revocation runs before and after the commit and moves a generation the reconcile checks, so an overlapped reconcile does not grant trust; the reader re-loads the flag after its snapshot. A memdb warmup that ends unpublished (init, warm or publish failed) withdraws it for good. No key is written. **Cost:** nothing restores trust before the next clean reconcile, and the usual import order (CreateBook, then SetBookAuthors) revokes it on the first new book, so after any import the warmup-window listings scan; once memdb publishes it answers instead. A store run with memdb disabled scans author listings from the first uncredited write until the next boot (a follow-up could keep an exact uncovered set instead of a flag). `deleteBook` revokes nothing: it removes the row and the credit row in one batch under both stripes, and a credit write after it only leaves extra keys.
- **What an uncovered listable book costs after deploy.** Reconcile's coverage check fails, the index stays untrusted for that boot, and cold author listings during the ~130 s warmup use the pre-index two-scan path: slower, never wrong. The fix is `maintenance.credits-backfill`, not this op.
- `maintenance.credit-census` classes `author_id_join_empty` and `author_id_not_in_join` are the same two conditions as the op's `no_credit_row` and `not_in_credits`, so the census is the full list behind the op's sample. Check the census scope (listable or every state) before comparing counts; the op counts every state.
- `keyfamilies.go` still registers `author_books_legacy:` (under `authors`): the rows exist on prod until the op runs, and the store-key diff must still classify them. Unregistering it is a follow-up after the prod run shows zero rows.

## Mutation run

19 hand-written mutants (15 store, 4 op), applied one at a time against targeted `-run` sets; **19/19 killed**.

- Store: refusal threshold (`Blocking > 1`), apply ignoring the refusal, preview deleting, listable-only check, unreadable credits not blocking, not-in-credits not counted, CreateBook and UpdateBook staging legacy keys again, trust ignoring uncovered books, uncovered counting no-credit-row only, uncovered ignoring the listable filter, reader ignoring per-boot trust, v1 sentinel not dropped, any credit covering, trust stored unconditionally.
- Op: preview/apply swapped, refusal swallowed, blocking samples dropped, no-op tag on every live run.
- First run 17/19. The threshold mutant survived because every refusal test had several blocking books; `TestRetireAuthorBooksLegacy_OneUncreditedBookRefuses` now kills it. The listable-filter mutant failed to build (it left `row` unused); rewritten as `(row.listable() || true)` it is killed by three tests.
- r1 M1 trust series: 17 more mutants, **16/17 killed**. Killed: revoke leaving the flag set, revoke not moving the generation, no check when a book becomes listable, the check ignoring the new row's listability, a pending credit row ignored, a missing credit row counted as credited, the drop check looking at additions, SetBookAuthors never revoking (ModifyBookAuthors shares that path), ModifyBookCredits never revoking, the update and create paths never revoking, reconcile ignoring the generation, reconcile ignoring an unpublished warmup, the unpublished flag not sticking, warmup failure keeping trust, and open repairs keeping the v1 sentinel. The generation mutant first failed to build (it left `gen` unused); rewritten as `Load() < gen`, it is killed by `TestAuthorBooksTrust_WriteDuringReconcileWithholdsTrust`. **Survivor, race-only:** removing the reader's second trust load after `NewSnapshot`. That load matters only when a revoke lands between the first check and the snapshot, which no sequential test can line up. Also untested deterministically: dropping only the pre-commit revoke or only the post-commit one (removing both is killed), and the NewMemStore-failure and publish-false abandon paths. Those paths share `abandonAuthorBooksTrust` with the warmup-failure path, and that path is killed.

## Prod run plan (owner go required; nothing here has run on prod)

Placeholders: `$AO` is the server's base URL (port from the server's `.env`), `$KEY` an `abk_` API key sent as a Bearer token (`.claude/.api-token`; the server-bootstrap skill renews it).

1. **Before deploying the PR**, run the read-only census and note the two counts:
   `curl -sS -X POST -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' -d '{}' "$AO/api/v3/ops/defs/maintenance.credit-census/runs"` (a read-only op: no mode), then read the run (`GET $AO/api/v3/ops/runs/<run_id>`) for `author_id_join_empty` and `author_id_not_in_join`. Both zero: the deploy keeps the index trusted. Either non-zero: the deploy is still correct, but every boot answers cold author listings by the scan until `maintenance.credits-backfill` has written the missing credits (that op is owner-gated on its own).
2. **Deploy** (the coordinator's usual deploy, `make deploy` from the untracked `Makefile.local`). Check the boot log line `author-books-index: complete: ... uncovered_books=N ... trusted=<bool>`: `uncovered_books` should match step 1's listable count, and `trusted=true` when it is 0.
3. **Preview the retirement:** `curl -sS -X POST -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' -d '{"mode":"preview"}' "$AO/api/v3/ops/defs/maintenance.author-books-legacy-retire/runs"`. Read the summary line: `<B> book rows ...; <n> blocking (no credit row <a>, not in credits <b>, unreadable credits <c>; ...); <L> legacy rows; preview, nothing deleted ...`. Expected first result: `blocking > 0` (credits-backfill left its held and review classes), with `a` and `b` at least the census figures (the op also counts trashed and non-primary books). The `blocking:` lines name sample books.
4. If anything blocks: resolve with `maintenance.credits-backfill` (and `maintenance.author-id-repair` for `naming a missing author`), each under its own owner go, then repeat step 3 until `0 blocking`.
5. **Owner go, then delete:** the same call with `{"mode":"live"}`. Expect `<L> legacy rows; <L> deleted`, with `L` equal to the last preview's (nothing creates legacy rows any more, so it cannot grow). A refusal here deletes nothing and fails with the list.
6. **Verify:** repeat step 5; expect `0 legacy rows` and a tagged no-op line. Spot-check a few authors' listings right after a restart (inside the warmup window) against the same listings after warmup.

**Rollback.**
- Of the op: none needed for the current build, which never reads the family. The data is reconstructible, not lost: any pre-F5-18j build rewrites every legacy key from `Book.AuthorID` in its boot reconcile. The ZFS snapshots on the host also hold the pre-run store.
- Of the deploy: revert to the previous binary. Because this build deleted the v1 sentinel, the old binary does not trust its index on first boot; it answers by the scan until its own reconcile has rewritten every absent legacy and credit key, then trusts it again. No manual step.
