# F5-18d seams and coined names

F5-18d gives the native runs' state a home in the tasks run store (`docs/plans/platform-core/F5-18-prep-split-proposal.md`, row d). Obligations: O5, O6, O10, O11, O12. The whole row is dark tier. The books-side work (O6, O10 to O12) is dark: no native books kind is registered live. `authority_build.go` and `credits_backfill.go` are live through their HEAD shells, and those shells' behaviour is unchanged. O5 changes the core executor, and it is dark too: no core kind is registered with a running executor today (only `examples/hello` calls `r.Tasks`). When the flip registers them, a failed, timed-out or canceled run keeps the non-zero result it returns. At least nine core kinds return a result beside an error and so start storing one: the executor's task prune (`core/internal/executor/prune.go`), the log-journal prune, the storage tasks, the bleve index rebuild, the library transfer recovery, the backup, the AI batch and batch-poll tasks, and the updater. No reader in core treats a present `Result` as success; the one consumer, `tasks.NativeStores` (`core/tasks/native.go`), stores it as given. The comments and the jobs shell's WARN that said core drops a failed run's result are corrected in this row.

## What was built

- **O5 (core).** A failed, timed-out or canceled run keeps the non-zero result it returned beside its error. `core/tasks/erased.go` `failedResult` encodes the result unless it is the zero value, and `core/internal/executor/attempt.go` `finish` stores it on those states. Before this, a failed run dropped its result. `tasks.Outcome`'s doc now says success is decided by `State`, not by whether a result is present. `TestFailedRun_KeepsANonZeroResult` covers three cases: a task, a zero result (stores none) and a batch `Finish`. `TestTimedOutAndCanceledRuns_KeepANonZeroResult` covers the timed-out and canceled branches. `attempt.go` is not in the proposal's file list for d. It is the one place a terminal record is written, so the seam could not be closed without it (flagged in the PR for the owner).
- **O6.** The native authority-build apply reads its plan from the tasks run store. `t6g1Deps.PlanRuns` (`authorityRunReader`, which is `Get`) replaces `PlanReader`. `nativeAuthorityPlans` and `loadNativeAuthorityPlan` refuse anything other than a succeeded Preview of the same kind whose result is a dry run with a digest. The HEAD shell still calls `loadAuthorityPlan` through `env.Plans`. The planted-v2-row test is replaced by `TestT6G1Kinds_AuthorityBuildAppliesANativePreviewsOwnPlan`, plus a refusal table.
- **O10.** The native credits backfill keeps its class id lists as its own run rows. `runRowStore` adapts `database.OpRowStore` onto `ReplaceRows`/`Rows` with this mapping: ID to ID, Index to Class, Data to State. A row whose data is not JSON is refused. `runClassLists` reaches the unchanged `database.SaveClassLists`, `ClearClassLists` and `ClassListSummary.Page` through that adapter. Because it never goes through the Writer, a Preview keeps its lists with no unfenced writer call. Core's closed-ledger rule refuses the rows once the run is terminal, and `TestRunRowStore_ClassListsAreTheRunsOwnRows` pins that. The lists are stored after the run's work ends, which on a cancel or a timeout is after `rc.Context()` is done, so the native shell gives `runRowStore` `context.WithoutCancel(rc.Context())` (as core's fixer stores its plan rows); a stopped run still keeps its lists as rows. Whatever happens to the rows, the result a run returns never carries the lists: when they cannot be stored, the result is `res.summary(nil)`, the counts and samples without the lists or a row summary. With O5 a failed run's result is kept on its record, and a library-scale run's lists are megabytes. `TestT6G3_CreditsBackfillNativeAStoppedRunKeepsItsListsAsRowsNotInItsResult` and `...WhoseListsAreNotStoredReturnsNoLists` cover a canceled and a timed-out run each (review M1).
- **O11.** `nativeCBLedger.others` pages `List(RunQuery{Kinds: credits-backfill})` 1000 at a time until a page comes back empty, with no cap. It returns every other run that did not succeed, using the record's `Finished` as `endedAt`. `nativeCBFingerprint` is built from State, Attempt, FenceEpoch, Yields, Started, Finished and Done. Every later claim, abandon, resume, progress step or end moves it.
- **O12.** A judgement is stored by the judging run, in its own result (`creditsBackfillResult.JudgedSources`: source run id to fingerprint). The same listing reads it back, so no row is ever written under a closed run. A run that judges and then fails keeps its judgements through O5 (`withJudged`). A stored result that does not decode fails the apply closed and names the run.
- `cbLedger` is the seam: `cbOpsLedger` holds HEAD's listing and marker code (moved, not changed), and `nativeCBLedger` holds the native one. `t6g3CreditsBackfillCoreEnv` gains `ClassLists` and `Ledger`; when either is nil, HEAD's behaviour applies. `t6g3Deps.Runs` (`cbRunStore`: `List`, `ReplaceRows`, `Rows`) and a `runs` parameter on `newT6G3Deps` are added. When `Runs` is nil the credits backfill is refused. `t6g3CapClassLists` is removed along with its only reader.

## Seams for F5-18

- **Run store.** `tasks.RunStore` is frozen by the API-stability gate, so the owner side declares narrow interfaces (`authorityRunReader`, `cbRunStore`). The flip must pass the kernel's `NativeStores.Runs` to both `t6g1Deps.PlanRuns` and `newT6G3Deps(..., runs)`.
- **Reading a native run's class lists.** `internal/server/handlers/operations/handler.go` reads the class page from the v2 row store. For a native run it must read the run's rows instead, for example `ClassListSummary.Page(runRowStore{...})`. The run store has no point read and no prefix scan of rows, so each page decodes every row of the run: a few hundred rows for a library-scale result. A point read on `tasks.RunStore` is behind the API-stability gate, so adding one is an owner decision. Filed in `todo.d/2026-11-20-f5-18d-run-row-point-read.md`.
- **Judgements are durable only at run end.** HEAD wrote each judged marker the moment it judged a run. A native judgement lives in the judging run's result, which is stored only when the run ends with that result. A judging run that dies before its end is stored loses every judgement it made: a restart-guard failure, an `interrupted_dropped` run, or an end that is never committed. The next apply then judges those runs again. That is safe (judging re-reads the run's journal and finds what the first pass deleted already gone) but repeats the work. F5-18 decides whether that is acceptable or whether a judging run needs a durable per-judgement write, which `tasks.RunStore` does not offer today: the judged runs are terminal and refuse rows, and a running run's own rows hold its class lists.
- **Pruning judgements.** `core.tasks.prune` deletes terminal runs by age. `others()` lists every run that did not succeed, including queued, waiting and interrupted ones, which prune never deletes, while the judging run is terminal and is pruned by age. A judged run that stays interrupted therefore outlives its judgement, and the next apply judges it again (safe, as above). A pruned run's journal rows remain (opchange: is never pruned), so it can still be reverted. The records it may have left are no longer looked for, which is also true of a discarded v2 operation.
- **HEAD markers and M4.** Today the native lister reads only native runs, so markers HEAD wrote on v2 operations are not seen. Once M4 converts v2 operations into native runs, it reads them, and two things break. HEAD's judged marker is an op row whose data is the raw fingerprint string, not JSON, so M4 (`internal/books/cutover/m4/convert.go` `rows`, `reasonRowBlob`) quarantines every HEAD credits run that was ever judged. And M4 decodes `opv2:rowix:` as JSON `{"class":...}` while HEAD writes the raw class key, so every converted class-list row loses its `Class`. Filed in `todo.d/2026-11-20-f5-18d-m4-credits-marker-and-rowix.md`.
- **Zombie attempts and the class-list rows (review n3).** Core's `ReplaceRows` checks only that the run has not ended, not the attempt or the fence. The fixer checks `a.fenced` first (`core/internal/executor/fixer.go:167`). So a fenced zombie attempt of a credits run can still replace the live attempt's class lists. The attempt nonce in `database.SaveClassLists` makes a mixed set fail closed (`ErrClassListIncomplete`) rather than read wrong, and HEAD's op rows were not fenced either. No code change; a fence check on run rows is core's to add if F5-18 wants it.
- **ErrPreview and a kept result (review n4).** `failedResult` also keeps `r` when the body returns `(r, ErrPreview)`, which `outcome()` maps to succeeded (`core/internal/executor/attempt.go:582`). Such a run used to store no result and now stores whatever `r` was. It is latent and untested: no maintenance Task body returns `ErrPreview`, and the authority-build Preview never writes. No code change.
- **The writer's op-row methods.** `booksT6G3Writer.ReplaceOpRowsPrefix`, `SaveClassLists` and `ClearClassLists` stay on the writer, still unfenced, but no native kind calls them now. `t6g3Writer` only gains methods (rule R10 item 2). Removing them, along with their shared-table rows if nothing else uses them, is F5-18's decision. `TestBooksT6G3Writer_EmptyRowMethodsStayUnfencedAndTheCoreOwnsTheMode` now asserts that the credits backfill's Preview reaches none of them.
- **Deadcode.** 13 identifiers stay dark (14 before review m1 removed `nativeCBLedger.carry`) until F5-18 wires the deps and are baselined in `scripts/deadcode-baseline.txt`: the native ledger, the run-row adapter, `withJudged`, and the native plan loader.
