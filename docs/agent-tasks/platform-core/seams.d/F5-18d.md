# F5-18d seams and coined names

F5-18d gives the native runs' state a home in the tasks run store (`docs/plans/platform-core/F5-18-prep-split-proposal.md`, row d). Obligations: O5, O6, O10, O11, O12. The books-side work (O6, O10 to O12) is dark: no native books kind is registered live. `authority_build.go` and `credits_backfill.go` are live through their HEAD shells, and those shells' behaviour is unchanged. O5 is NOT dark. It changes the core executor, which already runs core's own kinds in production (the task and log-journal prunes, the bleve rebuild, the storage tasks, the scheduler window). A failed, timed-out or canceled run of those now keeps a non-zero result it returns, and none of them returns one with an error today. No reader in core treats a present `Result` as success; the one consumer, `tasks.NativeStores` (`core/tasks/native.go`), stores it as given.

## What was built

- **O5 (core).** A failed, timed-out or canceled run keeps the non-zero result it returned beside its error. `core/tasks/erased.go` `failedResult` encodes the result unless it is the zero value, and `core/internal/executor/attempt.go` `finish` stores it on those states. Before this, a failed run dropped its result. `tasks.Outcome`'s doc now says success is decided by `State`, not by whether a result is present. `TestFailedRun_KeepsANonZeroResult` covers three cases: a task, a zero result (stores none) and a batch `Finish`. `TestTimedOutAndCanceledRuns_KeepANonZeroResult` covers the timed-out and canceled branches. `attempt.go` is not in the proposal's file list for d. It is the one place a terminal record is written, so the seam could not be closed without it.
- **O6.** The native authority-build apply reads its plan from the tasks run store. `t6g1Deps.PlanRuns` (`authorityRunReader`, which is `Get`) replaces `PlanReader`. `nativeAuthorityPlans` and `loadNativeAuthorityPlan` refuse anything other than a succeeded Preview of the same kind whose result is a dry run with a digest. The HEAD shell still calls `loadAuthorityPlan` through `env.Plans`. The planted-v2-row test is replaced by `TestT6G1Kinds_AuthorityBuildAppliesANativePreviewsOwnPlan`, plus a refusal table.
- **O10.** The native credits backfill keeps its class id lists as its own run rows. `runRowStore` adapts `database.OpRowStore` onto `ReplaceRows`/`Rows` with this mapping: ID to ID, Index to Class, Data to State. A row whose data is not JSON is refused. `runClassLists` reaches the unchanged `database.SaveClassLists`, `ClearClassLists` and `ClassListSummary.Page` through that adapter. Because it never goes through the Writer, a Preview keeps its lists with no unfenced writer call. Core's closed-ledger rule refuses the rows once the run is terminal, and `TestRunRowStore_ClassListsAreTheRunsOwnRows` pins that.
- **O11.** `nativeCBLedger.others` pages `List(RunQuery{Kinds: credits-backfill})` 1000 at a time until a page comes back empty, with no cap. It returns every other run that did not succeed, using the record's `Finished` as `endedAt`. `nativeCBFingerprint` is built from State, Attempt, FenceEpoch, Yields, Started, Finished and Done. Every later claim, abandon, resume, progress step or end moves it.
- **O12.** A judgement is stored by the judging run, in its own result (`creditsBackfillResult.JudgedSources`: source run id to fingerprint). The same listing reads it back, so no row is ever written under a closed run. A run that judges and then fails keeps its judgements through O5 (`withJudged`). A resumed run's record still holds an earlier attempt's result (a resume does not clear it), so the ledger carries those judgements into the new attempt's result (`carry`) and does not drop them. A stored result that does not decode fails the apply closed and names the run.
- `cbLedger` is the seam: `cbOpsLedger` holds HEAD's listing and marker code (moved, not changed), and `nativeCBLedger` holds the native one. `t6g3CreditsBackfillCoreEnv` gains `ClassLists` and `Ledger`; when either is nil, HEAD's behaviour applies. `t6g3Deps.Runs` (`cbRunStore`: `List`, `ReplaceRows`, `Rows`) and a `runs` parameter on `newT6G3Deps` are added. When `Runs` is nil the credits backfill is refused. `t6g3CapClassLists` is removed along with its only reader.

## Seams for F5-18

- **Run store.** `tasks.RunStore` is frozen by the API-stability gate, so the owner side declares narrow interfaces (`authorityRunReader`, `cbRunStore`). The flip must pass the kernel's `NativeStores.Runs` to both `t6g1Deps.PlanRuns` and `newT6G3Deps(..., runs)`.
- **Reading a native run's class lists.** `internal/server/handlers/operations/handler.go` reads the class page from the v2 row store. For a native run it must read the run's rows instead, for example `ClassListSummary.Page(runRowStore{...})`. The run store has no point read and no prefix scan of rows, so each page scans every row of the run: a few hundred rows for a library-scale result.
- **Pruning judgements.** `core.tasks.prune` deletes terminal runs by age. A judging run always starts after the runs it judges have ended, so prune removes a judged run no later than its judge, and a judgement is never lost while the run it covers is still listed. A pruned run's journal rows remain (opchange: is never pruned), so it can still be reverted. The records it may have left are no longer looked for, which is also true of a discarded v2 operation.
- **HEAD markers.** Markers HEAD wrote on v2 operations are not carried over to native runs. v2 operations are not native runs, so the native lister never reads them. Bringing them across is M4's to do.
- **The writer's op-row methods.** `booksT6G3Writer.ReplaceOpRowsPrefix`, `SaveClassLists` and `ClearClassLists` stay on the writer, still unfenced, but no native kind calls them now. `t6g3Writer` only gains methods (rule R10 item 2). Removing them, along with their shared-table rows if nothing else uses them, is F5-18's decision. `TestBooksT6G3Writer_EmptyRowMethodsStayUnfencedAndTheCoreOwnsTheMode` now asserts that the credits backfill's Preview reaches none of them.
- **Deadcode.** 13 identifiers stay dark until F5-18 wires the deps and are baselined in `scripts/deadcode-baseline.txt`: the native ledger, the run-row adapter, `withJudged`, and the native plan loader.
