# F7-05 seams and coined names

This file lists what the core notify PR (05-notify, dark) added beyond the Go blocks of the spec: the readings it took where the spec or the brief is silent or contradicts itself, the places it differs from the brief, and the seams later rows build on. Everything not listed here follows the spec as written. The feature is dark: nothing constructs a `notify.Service` yet, so no code path in a running app changes.

## Deviations from the brief

| Deviation | Why | Who must know |
|---|---|---|
| The importer set was 8 files, not 6. `phone_app_steps.go`, `phone_app_steps_test.go` and `guest_key_reissue_test.go` import the mail package since the brief was written; `guest_service_tokens.go` no longer does. All 8 were re-pointed (`internal/server/server.go` by import line only, alias `imail`). | The brief's table was stale. The move is a pure import rewrite. | F4-02 (shares `server.go`): the only change there is the import path. |
| `core/outbox` gained a handler retry hint: `outbox.RetryAfter(d, err)` and `outbox.RetryFree(d, err)` (new `core/outbox/retry.go`, `deliver.go` v1.1.0). This is outside the brief's file table. | Notify needs a retry the handler steers: honour a receiver's Retry-After, and keep an entry pending, without spending an attempt, while integrations are switched off. The outbox had only "fail" and "permanent". The change is additive: an error with no hint behaves as before. | Any later outbox consumer may use it. A permanent error beats a hint; a hinted retry still dead-letters at the consumer's `MaxAttempts`; a free retry never counts. |
| Delivery is a plain `outbox.Consume` with `Unordered()` and a high `MaxAttempts` ceiling. `core.notify.max_attempts` and `core.notify.max_age` are enforced by the handler, not by `ConsumeIntoTask`. | The handler must decide per class (a disabled channel keeps its entry past the attempt count; an old entry is expired even while disabled). The outbox's own cap is a ceiling only. | F7-08 and F7-09 wire the config values into `notify.Config`. |
| `Notification` has an `App` field (the app ID, stamped by Publish). | A webhook receiver serving several apps needs to tell them apart. | F7-08. |
| The gate is acquired inside each adapter: webhook sends through `env.HTTP` (which gates and applies the egress guard), email takes `env.Gate`. The consumer does not acquire it. | A gate acquired in the consumer would cover the SMTP dial but not tell the adapter's own refusal apart from a remote answer. | |
| Three different answers to "switched off". (a) `Publish` stages nothing for an instance that is disabled when the notification is published, and counts it in `targets_total{result="disabled"}` (a new result value; a rule whose every channel is off stages nothing and does not count `no_rule`). (b) An instance disabled after its entry was staged is a counted retry at delivery: it retries on the outbox's backoff and dead-letters at `max_attempts`, where an operator can retry it. (c) Only the global `core.integrations.disabled` switch is `RetryFree`: nothing was tried, the entry stays pending and keeps its attempts, and it still expires at `max_age`. `ErrNotConfigured` is retryable and counted. | An instance that is off must not park entries for a day, uncounted, on a partition other channels share (the retry list holds 64 per partition). The global switch is an operator pause of every channel, not a verdict on one. | Anyone wiring an enable/disable control: disabling a channel drops its in-flight entries to a counted retry, so they dead-letter rather than wait. |
| `deliver` decides on the relay's context, not the send's. If the relay's ctx is done (shutdown), the error is handed back untouched and no attempt is used, on the lease path and the send path alike. Otherwise a cancellation or deadline the adapter reports is the send's own timeout (a receiver that hangs): it is read as a transient failure, counted, and dead-lettered at `max_attempts`. | An adapter classifies against the send ctx, where its own `send_timeout` looks like a cancellation; deciding there made a hung receiver retry until `max_age`. | Any new adapter: return the error you got, do not translate a timeout into success or into a permanent failure. |
| Waits are bounded in the handler for every adapter. A receiver's Retry-After is clamped to the instance's `retry_after_max` (else the adapter's, else 5 minutes), and no wait, a provider hold included, runs past the entry's remaining `max_age` (one second minimum): the next attempt then finds it expired and dead-letters it. | `Retry-After: 31536000` is a legal header value, and `outbox.RetryAfter` itself is unbounded. | |
| The handler's context is capped by `core.outbox.handler_timeout` (30s), above `send_timeout` (15s). | The send gets its own deadline inside the handler's. | |
| `core.email` `to` is a list sent as one SMTP transaction, through the additive `Message.AlsoTo` in `core/integrations/notify/mail`. The mail package also gained `ErrTLSRequired` and `ErrAuthUnavailable` sentinels so a refusal classifies without matching text; the refusals keep their original admin-facing wording (the STARTTLS and `SMTP_USERNAME` hints) through a small `sentinelError` that wraps the sentinel. `NewChannel` validates its recipient list and returns an error (an empty list used to panic); it has no caller yet. | The 05-notify layout names several recipients; HEAD's sender took one. | |
| Webhook `Headers` is a list of `{Name, Value}`, not a map. The reserved-header refusal is a generated schema `pattern` on the name plus a build-time check. | A JSON schema map cannot carry a key pattern. The schema tag is about 2.4 KB. The framing headers (Host, Content-Length and the like) are refused only at build, so `Put` accepts them and the first send reports the instance misconfigured. | F7-10 owns the Put-time refusal (no code here): an operator who saves a `Host` header should hear it at save, not on the first notification. |
| Email settings fields are not named `*_address` or `*_addr`. | F7-01's destination-name heuristic treats those names as destinations. The sender and recipients are `from` and `to`. | |
| `synctest` is not used. `TestDeliver_RetryAfterHonoured` and `TestDeliver_EntryOlderThanMaxAgeDeadLettered` run on an injected offset clock (real time plus an advance) with short real delays. | No core test uses synctest, and the relay's rotation clamp (under 24h) limits mid-run clock jumps. | |
| `TestDeliver_BrokenChannelAlertsOtherChannels` is read as: a channel that fails authentication dead-letters after one attempt, does not loop or block another channel, and a notifiable "channel broken" event published afterwards reaches other channels through their rules. | The kernel's actual publication of `core.integration.health.changed.v1` is F7-09's. | F7-09 owns that publication. |

## Seams later rows must honour

| Seam | What F7-05 does | Who builds on it |
|---|---|---|
| `notify.New(ctx, notify.Options{...})` | Builds the Service and loads its rules. A rule store that cannot be read fails `New` (serving an empty set would drop every notification). `Options` needs `Catalog`, `Outbox`, `Registry` and the `c/notify/` keyspace opened for `notify.Owner`. | F7-09 builds it at boot and calls `Service.For(module)` for each module's `Publisher`. |
| `Service.Publish(ctx, batch, n)` | Resolves the targets from the rules and stages one outbox delivery per target in the caller's batch, so the notification commits or fails with the state change it describes. With no matching rule nothing is staged. | Every notifying module (through `For`). |
| `notify.NativeImporter(ks, opts...)` with `WithCatalog` | The importer validates a rule against the catalog and fails closed (`ErrNoCatalog`) when none is given. | F7-08 and F7-09 must pass `WithCatalog` when they register the importer. |
| Webhook secrets | `secret` signs (HMAC-SHA256 over `<t>.<delivery>.<url>.<body>`, header `X-Mediacore-Signature`), `token` is a bearer. A configured secret that cannot be read fails the send; the body is never sent unsigned. | Receivers recompute and compare in constant time and reject an old `t`. |
| Adapter errors | Webhook and email errors carry no URL, remote body or secret text, because a dead-letter row persists the error text. | Any new notify adapter. |
| Stage key | The delivery's partition key is the instance ref. The outbox hashes a key into 16 partitions, so two channels can share one, and the consumer is `Unordered()`: the key keeps one channel's backlog together, it does not isolate it. | See "Known limits" for the retry-list cap. |
| Rule changes and a running service | `NativeImporter`'s `ImportRule` writes the rule store; it does not refresh a running `Service`'s loaded set. `Service.PutRule` does. | F7-08 must reload (or construct the Service after) the import, or imported rules do nothing until restart. |
| Test support | `notifytest.FakeNotifier` and `notifytest.RuleStoreSuite`; `coretest.FakeNotifier` (alias) and `coretest.WebhookReceiver`; `coretest.MailRecorder` (the old `mailtest.Recorder`). | F7-08 (migration), F7-09. |

## Known limits and follow-ups

| Item | Detail | Owner |
|---|---|---|
| SMTP has no dial guard | The email adapter is admitted by the gate but the SMTP dial is not covered by providerhttp's egress guard (which wraps HTTP only). An SMTP host that resolves to a private address is not refused. **This is a hard precondition of the F7-09 flip:** `core.email` must not be reachable by an operator while it is open (so a private-address SMTP host cannot be reached from a core install), unless the F7-09 PR lands the guard or removes `core.email` from the registered adapters until it does. | F7-01 or providerhttp (a dial hook an adapter can use), before F7-09. |
| Unordered retry list is capped at 64 | The outbox keeps at most 64 retrying entries per partition, so a downed channel with more than 64 retrying deliveries can head-block other deliveries on its partition. The stage key (the instance ref) limits this to one channel's own traffic. | Outbox follow-up if a channel can plausibly queue more. |
| providerhttp hold policy | A transient 5xx from a webhook holds the scope for 30 minutes (other transient answers for 5); a retry inside the hold is refused locally (`ReasonHold`) and `deliver` waits until `Until` through `refusalWait`. | A notify-specific `HoldPolicy` in the webhook Descriptor, if 30 minutes is too long for a notification channel. |
| Dead-letter gauge | `mediacore_notify_dead_letters{instance}` scans at most 10 pages of 500 dead letters (`ListDead` has no consumer filter, so other consumers' dead letters share the budget). A scan that reaches the end is exact. When the budget runs out the outbox's own count of the consumer's dead letters gives the total and the difference is reported as `instance="unattributed"`, so the series sum to the real count; that outbox count is itself capped by its status bound, so under a very large backlog the sum is a floor. | An outbox per-consumer dead-letter listing would make the per-instance tally exact at any size. |
| Metrics are counted at stage time | `published_total` and `targets_total` move when the delivery is staged, not when the caller's batch commits; a caller whose batch fails to commit has still counted. | |
| `Health` does not probe | Webhook and email `Health` report OK; `Test` sends a test notification. | F7-10 may add a probe. |
| A fourth ULID copy | `ulid.go` repeats the ULID builder that events, outbox and tasks each carry. | A shared core helper in a cleanup row. |
| No package-level mutable state | `severityNames`, `ruleCodec` and `summary` are functions so the NoInit guard has nothing to flag. | |
