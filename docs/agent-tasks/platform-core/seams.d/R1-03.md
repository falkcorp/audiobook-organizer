# R1-03 seams and coined names

Names the per-module CI PR added beyond what the brief spells out, that later rows may rely on (implementation plan §(n) rule 5). Everything not listed here is 09 §9.4 R1's CI classification, 12 §12.3.11 or 03 §3.2 item 4 verbatim.

## Make targets (`core/Makefile`)

| Name | What it is |
|---|---|
| `errcheck-ratchet`, `interface-width` | Core's halves of the two root ratchets, driven by `core/scripts/ci/check-errcheck-ratchet.sh` and `check-interface-width.sh` against `core/.errcheck-baseline` and `core/.interface-width-baseline`. Both stay in `core ci`, so an export of `core/` runs them. |
| `pprof-check` | `go vet -tags pprof ./...` plus `go test -tags pprof -run Pprof -count=1 ./...` inside core. |
| `mocks-check`, `web-test`, `coverage-floor` | Core halves of rows that have no subject yet. Each prints "not applicable" or "no floor yet" and exits 0, and **exits 1 once its subject appears unwired** (a `core/.mockery.yaml`, a `core/web` directory, a `core/.ci/coverage-floor.txt`). The row that creates the subject wires the target; it cannot ship without. |
| `test-nightly` | Core's non-short tests under `-race`; the nightly job runs it. |

## Gates (`ci/gates.txt`)

`core-errcheck`, `core-interface-width` (ratchets, lower command `bash core/scripts/ci/check-*.sh --measure`), `core-pprof`, `core-mocks`, `core-coverage-floor` (checks). Job column `core-job` for all five. `scripts/tests/test_run_gates.py` reads a ratchet's script from its lower command, so a core script is covered the same way as a root one.

## Short-test shards (`scripts/ci/short_test_shards.py`)

| Name | What it is |
|---|---|
| `--shard core/N` | The one core shard (shard index N+1); `core/4` in the matrix. Core package keys in `short_test_weights.json` and in plans are prefixed `core/`. |
| `Package.module`, `load_packages()`, `module_lister()` | A package knows its module. Core is listed with its working directory set to `core/`, because a root-side `go list` cannot resolve core's own requirements. |
| `stale_weights()` | `--check` fails with `::error::<key>: weight entry in <file> but not in go list ./... of any module` for a weight entry no module lists. |
| `plan_calls()`, `Call` | One `go test` per module; the core call runs as `go -C core test`, writes no coverprofile, and a core-only shard writes no `--out`. |

## Workflows

`core-nightly` (display name "Core nightly tests") in `nightly.yml`. `ratchet-lower.yml` may now lower the two core baselines. The `core/4` matrix leg of `ci.yml` uploads no artifact, so the coverage job merges four profiles as before.

## Deadcode ratchet

`CORE_FILTER` in `scripts/deadcode-ratchet.py`: deadcode's `-filter` replaces its default (the root module only), so the ratchet passes the union of the root module and core's `internal/` and `kernel/` trees. Core's `examples/hello` main is added as a root only when that directory holds Go files. `scripts/deadcode-baseline.txt` is unchanged.

## Not in this PR

| Member | Why |
|---|---|
| A `core/.golangci.yml` | The two core scripts write their own temporary config (golangci-lint walks up into the root `.golangci.yml` otherwise). A checked-in core config would replace both; it was outside the brief's file list. |
| A core leg for `memory-leak-scan` and for `test-native-taglib` | Neither has a core subject yet (`core/web` is R1-30, no core package carries `native_taglib`). |
| `core/.errcheck-baseline` below 1 | One finding stands: the unchecked `f.Close` at `core/buildid/buildid.go`. The baseline records it; fixing it lowers the baseline in the PR that fixes it. |
