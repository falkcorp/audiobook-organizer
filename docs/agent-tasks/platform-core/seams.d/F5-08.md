# F5-08 seams and coined names

What the dark conversion of maintenance file group 3 (14 definitions in `cleanup.go`, `clear_apply_rename_failures.go`, `combine_journal_check.go`, `compact_activity_log.go`, `cover_ops.go`, `credit_census.go`, `credits_backfill.go`) added beyond 05-tasks and the F5-08 brief, the readings it took where they say nothing, and what F5-18 must do with them. Everything not listed follows the brief as written.

## Names beyond the spec

| Name | Where | What it is |
|---|---|---|
| `t6g3Kinds`, `t6g3KindList` | `kinds_t6_g3.go` | The group's list function (file order) and the package-level function that names it, so tasklint's registration-root rule counts the group. F5-18 replaces both with its `Registrar.Tasks` call and deletes `var _ = t6g3KindList`. |
| `t6g3Deps`, `t6g3Writer`, `t6g3Store` | `kinds_t6_g3.go` | The owner-declared dependencies (R10). Both are composed of small embedded interfaces (the repo's `interfacebloat` limit is 8 entries). `t6g3Deps.NewWriter` builds the writer per run over `rc.Writer()`; `t6g3Deps.GuardTags` is the credits backfill's franchise-tag reader. |
| `headT6g3Writer`, `headT6g3Store` | `kinds_t6_g3.go` | The HEAD adapters over `p.deps`: each method calls what HEAD's body called, in the same order. |
| `t6g3Base` | `kinds_t6_g3.go` | The env part both shells fill the same way (`Live`, `Log`, `Progress`, `OpID`, `Writer`, `Store`). Each def's env embeds it. |
| `t6g3ItemsOpts`, `t6g3ItemsFunc` | `kinds_t6_g3.go` | The engine-neutral loop. HEAD maps to `registry.RunItems`, native to `tasks.RunItems`. |
| `t6g3CBEngine`, `t6g3CBHold`, `t6g3CBStoreView` | `credits_backfill.go` | The credits backfill's engine seam (log, progress, checkpoint, stand-down, pool) and the store its run sees: reads from `t6g3Store`, writes through `t6g3Writer`. |
| `t6g3Capability`, `Store.Can` | `kinds_t6_g3.go` | Reads a store may lack (narrator name index, ops lister, op rows, class-list rows). Absent ones answer `errT6g3NoCapability`; the core asks `Can` first where HEAD branched on `database.AsCapability`. |

## Deviations from the brief

1. **Cores are plain package functions, not `(p *Plugin)` methods.** A function with no receiver cannot reach `p.deps`, so R10 is structural rather than a review rule. Shells (`(p *Plugin) runX`, `(p *Plugin) xKind`) stay methods.
2. **Three new test files** (`kinds_t6_g3_atoms_test.go`, `export_t6g3_test.go`, `kinds_t6_g3_paths_test.go`) and this note are outside the brief's file list. `internal/books` imports `plugins/maintenance`, so the settings.manage scopes are copied into the group and an external test compares them with `books.AtomTable()`.
3. **`Items` carries options** (`t6g3ItemsOpts`: label, collect, per-item timeout), because HEAD's loops differ in them.
4. **ReadOnly kinds declare no reads** (R7): HEAD's `Reads: [books, authors]` on the census and combine-journal check are not carried.
5. **Every native writing kind decodes `json.RawMessage` params** and refuses a mode key (`apply`, `dry_run`, `dryRun`, case-insensitive) through the one helper `t6g3RefuseModeKeys`, rather than silently ignoring it. The shells with no params of their own (purge, tombstone, temp-file, transcode, cleanup-activity-log, cleanup-old-backups, trash-cleanup) call it first, before the live-only guard; a required field (`older_than_days`) is still refused when missing.
6. **Cover ops carry the `workers` param.** HEAD sized both pools from it, so the native shells declare `tasks.Fixed(workers, ...)` per run: folder-cover-backfill and the preview of cover-text-read default to `clamp(2 x NumCPU, 1-32)`, HEAD's default; the live cover-text-read pool defaults to the vision pool's capacity, as HEAD did, and is itself the cap on concurrent reads (no semaphore inside an item, where the item timeout would already be running). These are IO-bound loops, so the `Fixed` count is the owner's declared bound, not `Fixed(NumCPU)`. The credits backfill's loops use the kind's CPU parallelism instead.
7. **Credits backfill `verifyPriorAttempts` keeps its `errgroup`** (bounded by `workers`); only its stand-down beat goes through the engine.
8. **Class lists and the result.** HEAD stores the summary through the reporter and clears the class lists if that fails. The native kind returns the summary and has no later point at which to clear them, so a failed result store after a successful class-list save leaves the rows until the operation is discarded. The core still clears them when `StoreResult` is supplied (the HEAD shell).
9. **Stand-down key is owner-declared.** `t6g3Deps.StandDownKey` replaces the constant the native credits backfill used; an apply with the key empty is refused before any write.
10. **Both credits shells share `t6g3CreditsCoreEnv`**, which sets `Workers: runtime.NumCPU()` for the run's own errgroups (the native kind used to leave it unset, which clamps to one).
11. **`compactRecordEnv` is a small group-neutral interface** (`Log`, `Progress`, `CompactActivityEntries`) that `compactAndRecordCore` takes; nothing in the core is typed `t6g3`, because F5-11's nightly-compact calls the same core. `headCompactRecordEnv` (reporter and `p.deps`) and `t6g3CompactRecordEnv` (run log, progress and the writer) implement it. The core's comment keeps HEAD's invariant: one shared body, so a liveness or result-shape fix lands on every caller. The Effects resource for the activity store is `activity`. The HEAD log lines keep their slog attributes (`t6g3Base.Log` takes `...slog.Attr`).
12. **Trash cleanup stores its result before its first log line**, as HEAD did (`trashCleanupEnv.StoreResult`); the persist error joins the cleanup error at the end.
13. **Effects name every resource the writer touches, using only the `pkg/ops/effects.go` constants.** The credits backfill writes `books` (with the narrator records and joins), `authors` and `operations` (its class lists and judged markers are op rows in the operation store) and reads books, authors and series; purge-deleted adds `activity`. A test records every write through a spy, maps each writer method to its resource, and fails if a recorded resource is outside the declared write set or a method has no mapping.
14. **The HEAD adapters capture the store once** (`headT6g3Writer{p, store}`, `headT6g3Store`), so the fixer-stores allowlist needs no entry for them.

## Readings taken

- **Resource names.** No new names: every Effects resource is a constant in `pkg/ops/effects.go`. Three mappings are the closest constant rather than an exact one, flagged for F5-06 (which owns additions): trash cleanup's version rows are under `books` (was `book_versions`), the cover-text read's stored text is under `metadata_cache` (was `cover_text`), and the credits backfill's op rows (class lists, judged markers) are under `operations` (that constant is documented as the undo journal; these rows live in the same operation store). Narrator records and joins are under `books` (was `narrators`). `files` stays only where bytes on disk change (purge-deleted never deletes `book_file` rows).
- **Names left unprefixed on purpose.** `compactAndRecordCore`, `compactRecordEnv`, `headCompactRecordEnv`, `compactActivityLogPlan` and the progress helpers `compactProgressVia`, `maintenanceProgressVia` are group-neutral (F5-11 calls them) and keep their names; everything else the group added carries the `t6g3` prefix.
- **Readiness.** Every kind waits on the component `books.memdb` (HEAD `NoWarmupWait` false); F5-18 registers it.
- **Stand-down key.** The native credits-backfill apply holds `rc.StandDown(deps.StandDownKey)`; F5-18 declares the scan kind's key, and a wrong key holds nothing.
- **Liveness.** HEAD's cover-text read stamped liveness before each model read; the native engine has no such clock (the def sets no progress timeout) and the stamp is dropped.
- **Core drops a failed run's result** (`core/tasks/erased.go`), so the census and credits backfill results are lost on an error; the failure is logged with its size only.
- **Ambient reads kept.** `os.Stat` in the transcode sweep, `appdirs.Current()` in the file writers, and the package seams `newCoverTextReader` and `coverTextNow` are read by the cores unchanged.
- **Scan check kept as a read.** The live folder-cover run refuses while a library scan is queued or running by reading the operation queue through `Store.ListActiveOperationsV2`. That guard goes dead once the scan is native (see the F5-18 obligations below); it must move to `NotWhile`/`StandDown`.

## What F5-18 must wire

- `t6g3Deps.StandDownKey` (the scan kind's key; empty refuses a live credits apply).
- `t6g3Deps.Store` (including the raw key reads, op rows, narrator name index, ops lister and narrator reference capabilities, and the operation queue) and `NewWriter` (including `SetRaw`, `ModifyBook`, `ModifyBookCredits`, `ReplaceOpRowsPrefix`, `SaveClassLists`, `ClearClassLists`, `InvalidateAuthorsCache`) and `GuardTags`.
- The cover-text reader, still the package seam `newCoverTextReader`.
- Delete `t6g3KindList` and its blank-identifier line.

## F5-18 obligations (four, none enforced by a gate today)

1. **Native credits preview must keep the class lists.** `SaveClassLists` and `ClearClassLists` must be real writes in a preview: `rc.Writer()` intent-recording (`core/tasks/rc.go`) must let them through. HEAD's dry run keeps the lists and `TestT6G3_CreditsBackfillHeadShellDryRunWritesNoBook` pins that; a native preview that drops them loses the result's paged id lists.
2. **The ops lister must return native runs.** `otherCreditsBackfillOps` filters `row.DefID == "maintenance.credits-backfill"`; native runs are of `books.maintenance.credits-backfill`, so the lister must return them, with their judged markers under the native run id, or the leftover/judged logic stops seeing earlier attempts.
3. **The folder-cover scan guard goes dead once the scan is native.** It reads the v2 operation queue for `DefID == "library.scan"` (`cover_ops.go`, `fs_regroup_xml.go`); a native scan never appears there, so the guard must move to `NotWhile`/`StandDown`. This is a must, not a may.
4. **Delete the journal-direct-writers allowlist entry** (`internal/arch/journal_direct_writers_test.go`, the F5-08 entry) once F5-18 wires a real writer for `CreateOperationChange`; the entry only exists because the HEAD adapter writes the journal directly. That also closes the allowlist's stale-entry finding.
