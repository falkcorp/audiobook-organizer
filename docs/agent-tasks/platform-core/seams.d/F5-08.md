# F5-08 seams and coined names

What the dark conversion of maintenance file group 3 (14 definitions in `cleanup.go`, `clear_apply_rename_failures.go`, `combine_journal_check.go`, `compact_activity_log.go`, `cover_ops.go`, `credit_census.go`, `credits_backfill.go`) added beyond 05-tasks and the F5-08 brief, the readings it took where they say nothing, and what F5-18 must do with them. Everything not listed follows the brief as written.

## Names beyond the spec

| Name | Where | What it is |
|---|---|---|
| `t6g3Kinds`, `t6g3KindList` | `kinds_t6_g3.go` | The group's list function (file order) and the package-level function that names it, so tasklint's registration-root rule counts the group. F5-18 replaces both with its `Registrar.Tasks` call and deletes `var _ = t6g3KindList`. |
| `t6g3Deps`, `t6g3Writer`, `t6g3Store` | `kinds_t6_g3.go` | The owner-declared dependencies (R10). Both are composed of small embedded interfaces (the repo's `interfacebloat` limit is 8 entries). `t6g3Deps.NewWriter` builds the writer per run over `rc.Writer()`; `t6g3Deps.GuardTags` is the credits backfill's franchise-tag reader. |
| `headT6g3Writer`, `headT6g3Store` | `kinds_t6_g3.go` | The HEAD adapters over `p.deps`: each method calls what HEAD's body called, in the same order. |
| `t6g3Base` | `kinds_t6_g3.go` | The env part both shells fill the same way (`Live`, `Log`, `Progress`, `OpID`, `Writer`, `Store`). Each def's env embeds it. |
| `t6g3ItemsOpts`, `t6g3ItemsFunc` | `kinds_t6_g3.go` | The engine-neutral loop. HEAD maps to `registry.RunItems`, native to `tasks.RunItems`. |
| `cbEngine`, `cbHold`, `cbStoreView` | `credits_backfill.go` | The credits backfill's engine seam (log, progress, checkpoint, stand-down, pool) and the store its run sees: reads from `t6g3Store`, writes through `t6g3Writer`. |
| `t6g3Capability`, `Store.Can` | `kinds_t6_g3.go` | Reads a store may lack (narrator name index, ops lister, op rows, class-list rows). Absent ones answer `errT6g3NoCapability`; the core asks `Can` first where HEAD branched on `database.AsCapability`. |

## Deviations from the brief

1. **Cores are plain package functions, not `(p *Plugin)` methods.** A function with no receiver cannot reach `p.deps`, so R10 is structural rather than a review rule. Shells (`(p *Plugin) runX`, `(p *Plugin) xKind`) stay methods.
2. **A third and fourth new test file** (`kinds_t6_g3_atoms_test.go`, `export_test.go`) and this note are outside the brief's file list. `internal/books` imports `plugins/maintenance`, so the settings.manage scopes are copied into the group and an external test compares them with `books.AtomTable()`.
3. **`Items` carries options** (`t6g3ItemsOpts`: label, collect, per-item timeout), because HEAD's loops differ in them.
4. **ReadOnly kinds declare no reads** (R7): HEAD's `Reads: [books, authors]` on the census and combine-journal check are not carried.
5. **Native params are `json.RawMessage` for `clear-apply-rename-failures`, `compact-activity-log`, the cover ops and the credits backfill**, so a mode key (`apply`, `dry_run`, `dryRun`, case-insensitive) is refused rather than silently ignored and a required field (`older_than_days`) is still refused when missing.
6. **Cover ops: the `workers` param is not carried.** A Task's pool is its declared `Parallelism`. folder-cover-backfill is `Fixed(2 x NumCPU, clamped 1-32)`, HEAD's default. cover-text-read is the same fixed pool; HEAD sized its live pool to the vision pool's capacity, so the native live run caps its concurrent reads at `reader.Capacity()` with a semaphore instead.
7. **Credits backfill `verifyPriorAttempts` keeps its `errgroup`** (bounded by `workers`); only its stand-down beat goes through the engine.
8. **Class lists and the result.** HEAD stores the summary through the reporter and clears the class lists if that fails. The native kind returns the summary and has no later point at which to clear them, so a failed result store after a successful class-list save leaves the rows until the operation is discarded. The core still clears them when `StoreResult` is supplied (the HEAD shell).

## Readings taken

- **Resource names.** New names to declare in F5-18's resource table: `activity`, `book_versions`, `cover_text`, `narrators`, `operations` (`books`, `files`, `external_ids`, `authors` and `user_state` already exist). The credits backfill's book writes include the author and narrator join rows, counted under `books`.
- **Readiness.** Every kind waits on the component `books.memdb` (HEAD `NoWarmupWait` false); F5-18 registers it.
- **Stand-down key.** The native credits-backfill apply holds `rc.StandDown(tasks.Key("books.library.scan"))`. F5-18 confirms the scan kind's key; a wrong key holds nothing.
- **Liveness.** HEAD's cover-text read stamped liveness before each model read; the native engine has no such clock (the def sets no progress timeout) and the stamp is dropped.
- **Core drops a failed run's result** (`core/tasks/erased.go`), so the census and credits backfill results are lost on an error; the failure is logged with its size only.
- **Ambient reads kept.** `os.Stat` in the transcode sweep, `appdirs.Current()` in the file writers, and the package seams `newCoverTextReader` and `coverTextNow` are read by the cores unchanged.
- **Scan check kept as a read.** The live folder-cover run refuses while a library scan is queued or running by reading the operation queue through `Store.ListActiveOperationsV2`; F5-18 may replace it with `NotWhile`.

## What F5-18 must wire

- `t6g3Deps.Store` (including the raw key reads, op rows, narrator name index, ops lister and narrator reference capabilities, and the operation queue) and `NewWriter` (including `SetRaw`, `ModifyBook`, `ModifyBookCredits`, `ReplaceOpRowsPrefix`, `SaveClassLists`, `ClearClassLists`, `InvalidateAuthorsCache`) and `GuardTags`.
- The cover-text reader, still the package seam `newCoverTextReader`.
- Delete `t6g3KindList` and its blank-identifier line.
