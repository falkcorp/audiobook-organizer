# F7-09 T6 seams: books-search-native

T6 is `internal/books/searchindex/**`: books' index declaration, document builder, query translator, the derived-index catalog with the hnsw hooks, and the native half of `TestBooksIndexRebuiltAtCutover`. It is dark. Nothing outside its tests calls it and `internal/search` is untouched. Every item below marked "switch at the fold" is a stand-in or a refusal the fold removes once core's missing surfaces land.

## Switch at the fold

| Gap | What T6 does now | What the fold does |
|---|---|---|
| No public engine fixture. `core/internal/bleveindex` cannot be imported from this module. | `searchindextest.Opener` is a bleve stand-in that mirrors core's translation of `index.Query` and its layout `<db parent>/index/books/books.bleve`. It has no dirty set, facets or reconciler. | Delete `searchindextest/opener.go`; run `RunBooksIndexRebuiltAtCutover` over core's public engine fixture. |
| No module analyzer. HEAD's `book_en_nostop` (stemming, `_` splitting, stop words kept) cannot be registered. | Free-text fields use `standard`. A stemmed query ("halloweens") and a quoted phrase containing a stop word answer differently from HEAD. The recorded R0 answers do not depend on either. | Register `book_en_nostop` and set it on the free-text fields in `Fields()`; bump `MappingVersion` (the engine rebuilds). |
| No case-insensitive keyword. HEAD's "keyword" fields (tags, format, genre, language, library_state, isbn10/13, asin) are analysed with the standard analyzer, not as whole values. | Declared `Text` + `standard`, so a term matches by word as in HEAD. Values are not lower-cased at build. | Switch to the case-insensitive keyword kind only with a `MappingVersion` bump and a decision on `tag:` (HEAD resolves `tag:` through `GetBooksByTag`, not the index). |
| No per-field boost. | A boosted clause (HEAD's free-text field weights, `field:term^3`) is a query string per term, escaped. Unboosted clauses use `index.Match`. | Emit boosted `index.Match` once core carries a boost. |
| No wildcard operation, and the engine refuses leading `*`/`?`. | A leading wildcard is `ErrNotExpressible`, never downgraded to a prefix. Trailing and inner wildcards go through a query string. | Use the wildcard operation; decide whether a leading wildcard stays refused. |
| No match-all. | `MatchAllQuery()` is `Not(Term(format, <absent term>))`; `Translation.MatchAll` says when to use it or list from the store. | Use core's match-all if it adds one. |
| No `_all` field. | An unfielded term fans out as an OR over every text field. | Same, unless core adds `_all`. |
| Per-user terms under OR or NOT (HEAD's `Mixed` query) need the viewer's rows per book. | `ErrNotExpressible`; the caller serves the live path. Per-user terms under AND are returned in `Translation.PerUser` for the Go-side filter, as in HEAD. | Decide with F7-09 T7 whether the mixed shape moves into a post-filter. |

## Other readings T6 took

- **The translator is built on `search.TranslateQuery`.** It maps HEAD's bleve query tree onto `index.Query`, so every date, duration, tag and per-user rule is HEAD's own. When the fold retires `internal/search` the translation rules move into this package (the parser and `Translation` split first). `Document` likewise calls `search.BookToDocWithRelations`, which reads the description length limit from the global config; the fold passes the limit in.
- **A relation read that fails fails the rebuild.** HEAD's startup backfill indexes the chunk with partial relations and relies on the reconciler. A derived-index rebuild has no reconciler behind it, so a document with a silently missing author is worse than a retried rebuild.
- **`Catalog` and the build tasks.** T6 exports declarations and hooks only. `Registrar.DerivedIndex` is slice B3, not on main, and the `<module>.derived.<name>.build` tasks (`datamigrate.DerivedBuildTask`) need the existing warmup and hydrate code, so the fold builds them. Only hnsw has an artifact. memdb is rebuilt from rows at every boot and chromem persists itself as written, so both declare no hooks (the kernel rebuilds them).
- **`Blocking`.** memdb is `Blocking: true` (every list read serves from it); books, hnsw and chromem are not (their searches degrade to a fallback). This is a reading, not a recorded decision; the fold confirms it.
- **hnsw `Load`** refuses a snapshot whose import left it pending a reconcile, or empty. The store reports a discarded inconsistent snapshot as a successful import of an empty graph, which only a count check tells apart.
- **Regex searches** (`^The `) are the filter layer's: HEAD applies them in Go after the index answers. The harness skips them by name and requires at least one query to run.
