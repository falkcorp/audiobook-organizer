# F6-05 seams and coined names

What F6-05 added beyond the spec text of 05-logging §5 ("Live tail"), the readings it took where the brief is silent, the one approved exception to its file list, and what F6-03 (the kernel wiring) must know. The PR is dark: nothing in `core/kernel` declares `core.log.recorded.v1` or calls `logjournal.StartTail`.

## Shape

- `logjournal.TailSpec(otherUser)` is the catalog entry the kernel declares under owner `core`: Realtime, never Durable, `Permission: core:system.manage`, with a `Visible` and a `Redact` that carry the other-user rule. `logjournal.StartTail(l, bus, settings)` registers a second log tap named `journal-tail` (its own goroutine and bounded queue; drops count under that tap name). It is a second tap and not a hook in the journal tap, so F5-15's `tap.go` is untouched and a slow bus costs the journal nothing.
- `logjournal.RecordView` is the wire payload. It has the same members as `loghttp`'s `recordView`; `loghttp`'s own test (`TestJournalTail_SameViewAsQuery`) pins that the two agree. The two types are duplicates: `loghttp` imports `logjournal` and could use `RecordView` directly, which is a follow-up edit to `routes.go` that no row owns.
- With authentication off nothing holds `core:system.manage` (it is AuthRequired), so the tail delivers nothing: the same deliberate tightening as the query route.
- F6-03 must: declare `logjournal.TailSpec(pred)` with `pred` the module-registered `Registrar.LogOtherUserData` predicate (nil when none is registered), subscribe it with the hub, and call `StartTail` after the logger and bus exist, with the journal's own settings.

## Approved exception: the predicate's input is one normalised record (STOP 2)

The brief says the tail applies the other-user predicate "exactly as F5-19's query route calls it". Measured with a recording predicate, it did not: the route handed the predicate the store's record (typed values, logged order, a repeated key kept), while the tail can only rebuild a record from the wire view (every value text, keys sorted, a repeated key collapsed to its last value). A predicate that switched on `Value.Kind()` could under-flag on one surface, and one that called `Value.Int64()` would panic (the hub withholds on a panic).

The coordinator approved option 2: both surfaces now hand the predicate `log.PredicateInput(rec)`, one function in `core/log/otheruser.go`, so there is one normalisation and not two copies that happen to agree. Its contract is documented on `log.OtherUserPredicate`: text-only values, flat dotted keys, sorted by key, the last value of a repeated key wins.

Files outside F6-05's brief file list that this exception edits:

- `core/log/otheruser.go` (the contract text and `PredicateInput`), with a new `core/log/otheruser_test.go`.
- `core/internal/loghttp/routes.go` (F5-19's file): `q.Hide` calls the predicate through `log.PredicateInput`. Nothing else in that file changed.

Every production implementation of the predicate was checked first: there is none in the repository. `Registrar.LogOtherUserData` (`core/module/registrar.go`) only stores a predicate a module hands it, and no module registers one yet (06's books module will). The only implementations are test doubles (`namesSelina` and the recording predicates in `core/internal/loghttp` and `core/internal/logjournal` tests, `core/module/module_test.go`), none of which reads a value's Kind or a typed accessor. The 06 books predicate must read attributes as text; `TestPredicateInput` and `TestJournalTail_PredicateSeesSameRecordAsQuery` pin what it will be shown.

F5-19 has no seams file in `seams.d`, so the note for its `routes.go` edit lives here.
