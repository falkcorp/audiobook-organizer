# F8-04 seams and fold obligations

F8-04 is landing in slices; every slice so far is dark. This file records what the diagnostics prune task, the `/metrics` mount and the diagnostics adapters (A3 to A5, PR #4815) leave for the fold, so the obligations live somewhere a reviewer of the fold reads and not only in code comments. It does not replace `seams.d/F8-03.md`, whose "Follow-ups for F8-04a" still apply.

## Rules the fold must keep

- **Retention is a function, read live.** `healthhttp.Deps.Retention` is `func() time.Duration`, called once per download. A zero or negative result and a nil function are the 24 h default (`diagnostics.DefaultRetention`), the same rule `OpenBundle`, `Prune` and `PruneTask` apply. A retention read once at registration would serve a bundle after a hot-reload that lowered it had let the prune delete it.
- **Partials outlive a short retention.** `diagnostics.Prune` deletes a `.zip.tmp` only when it is older than `max(retention, ExportTimeout)` (30 minutes); the export is ReadOnly, so nothing keeps it from running while the prune does. If the config key (F3-07) ever gets a floor, it is a second guard, not a replacement.
- **`/metrics` takes the default path.** A non-default `core.metrics.path` is still compressed correctly (promhttp gzips for the client and stage 9 passes a handler-set `Content-Encoding: gzip` through), but the exact-pattern exemption in `httpapi.Router` is for `/metrics` only.
- **Empty version.** `registerBuildInfo` labels an empty or blank version `dev`; the fold passes the real one.

## Obligations that land at the fold

1. **The chain half of `TestInfra_MetricsRequiresScope`** (05-http-api §12). `TestMetricsMount_RequiresMetricsRead` and `TestMetricsMount_RealCheckers` cover the handler's own gate. The half that runs through stages 10 to 13 needs a router with an auth service, which `Build` requires for a non-Public route, so it cannot exist until the fold builds one: 401 with no credential, 403 without `core:metrics.read`, and `/livez` and `/readyz` Public.
2. **A `build_info` cell in `TestKernelFamiliesGathered`.** The test filters the served families by the kernel and storage scope prefixes, which do not select `<namespace>_build_info`, and `kernel_families.golden` is untouched by A4. When boot calls `mountMetrics` the test must assert the family separately.
3. **Delete the tasklint exemption.** Remove the `//tasklint:constructor` directive on `diagnostics.PruneTask` and its entry in `core/archtest/tasklint/core_test.go` once the kernel registers the kind.
4. **Delete the 29 deadcode baseline lines** A3 to A5 added to `scripts/deadcode-baseline.txt`: 22 `core/internal/healthhttp.*` (`Register`, `RegisterProbes`, `newAPI`, `authorise`, `holds`, `malformed`, `unavailable`, `userAgent`, `decodeOptional`, `errRunNotFound`, `caller.actor` and the eleven `api.*` methods), the four `core/kernel.diagnostics*` adapters, and `core/kernel.metricsGate`, `mountMetrics` and `registerBuildInfo`. Regenerate the file with the repo tool, not by hand.
