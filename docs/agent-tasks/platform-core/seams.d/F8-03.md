# F8-03 seams and coined names

This file covers what the "core health completed, dark" PR added beyond 05-health §5H.3 to §5H.10, the readings it took where the spec or the brief is silent, the one STOP that fired, and what it left for F8-04. Everything is dark: ABO's `/health`, `/api/health`, `/api/v1/health` and `/api/v1/system/status` are unchanged, `core/kernel/boot.go` is not edited, and nothing mounts the new routes.

## The STOP that fired

The brief says to STOP if `Registry.Snapshot` already exists. It did (F2-10 left it in `registry.go`). The option taken was to extend the stub rather than stop: `Snapshot`, `ComponentState` and `Live` moved into the new `snapshot.go`, and `registry.go` was modified although the brief's file table does not list it. The registry's F2 behaviour is unchanged where `registry_test.go` pins it; the one visible change is below (probe panics and timeouts).

## Deviations and readings

- **Import limits.** The health root imports `internal/sdnotify` (and `events`, `rbac` where used), beyond the spec header's list. It does not import `library` or `health/sysinfo`; the container default for the stop budget is a bool parameter, not a call into sysinfo.
- **Probe reasons.** `probe_panicked` is renamed `check_panic` (spec §5H.5) and `check_timeout` is added. A probe that answers after its deadline is now Down `check_timeout`, and `Register`'s synchronous first probe is bounded too. `registry_test.go` was updated for both. One exception, added in review round 2 and a LIVE boot change (core.storage registers at every boot, `kernel/boot.go`): a Register-time probe that overran its timeout and then answers is accepted, so core.storage whose engine ping is slow at boot becomes Up instead of staying Down for good and starving the tasks executor that waits on it. It applies only until `StartChecks` has run, and only while the component's result is still that Register's `check_timeout` (a `Report` in between is newer and wins). When an answer and the deadline are ready together, the answer is kept if the probe returned before the deadline and counted as a timeout if it returned after; that tie only arises on real-time descheduling, so it has no deterministic test.
- **Readiness tokens.** `core.kernel:starting` and `core.kernel:stopping` appear only when a `Startup` is attached or `BeginShutdown` has been called. `PublicTokens` generalises a posture reason to `down` or `unknown`, so no posture token reaches an unauthenticated body.
- **`CoreStartupSteps()`** returns seven rows: EnsureSecureStateDir, guardAgainstKeyRegeneration, initEncryption, loadConfigFromDB, config.Validate, opRegistrationGate and http. HEAD's other steps (settingsWrites, container.Start, opCatalogGate, searchindex) are module rows for F8-04, not core's. `Startup.Run` does not call `ExtendStart` itself; the kernel's step function does, so the once-per-step rule is the caller's. `TestStartup_ExtendPerStepNeverTimer` drives the real table with the real `SystemdNotifier` over a fake notify socket (one datagram per asking step, none for a silent or failing one, none between steps), and `TestStartup_ExtendNeverOnATimer` holds the idle-hour half in fake time.
- **"Wire on hello/coretest".** Read as tests only: the routes are exercised through the real `httpapi` router in `healthhttp`'s tests; `hello` and `coretest` are not edited.
- **Diagnostics core sections.** The producers are injected through `CoreSources` because kernel wiring is F8-04. The `core.config` source must hand the exporter `diagnostics.Secret` / `Redacted` placeholders (typing is the source's job; the pattern layer is the net, not the plan). Every core section uses `core:system.manage` as its Perm; the spec is silent. Section writers run one after another because the zip writer is not concurrent.
- **Unknown requested section names** fail at run time in `Exporter.plan`, not at the route, because the route does not know the module sections.
- **Release trailer.** Commits carry "Claude Sonnet 5.5" per the harness, not the rules file's "Opus 5.5".
- **Platform files.** `core/health/sysinfo` has darwin, linux, windows and other host files. Darwin is tested; linux and windows are `go vet`-checked only; real systemd was not run. `GOOS=freebsd go build` fails in `core/library` before this PR.

## Review round 2 (PR #4658)

The Opus review found four MAJOR, eight MINOR and four NIT items; all sixteen are fixed in this PR. What each left behind:

- **Download gate (MAJOR).** The download route now requires an interactive method (`Method.Interactive()`, which is `MethodSession` only), not merely a method that may change credentials (`MayChangeCredentials()` also admits a delegated session); an API key or a delegated session gets 403 `interactive_required`. Only the download route uses this gate; the shared router Guards are unchanged.
- **Key redaction (MAJOR).** Map keys are redacted as well as values: `scrub` and `walkObject` rebuild an object with sorted, redacted keys. Keys that collapse to the same text get a `#2`, `#3` suffix, and a key is judged for the deny list by its original text. Each change counts as a pattern redaction.
- **Paths (MAJOR).** Absolute paths are redacted (`paths.go`): a path under a known root becomes `<root:NAME>/rest`, any other absolute path becomes `<path>`. `Config.Roots []PathRoot` supplies the roots, so **F8-04 must pass the library roots**; with none, every absolute path is `<path>`. It applies to values, `Writer.File` lines, manifest `errors[]` and keys. Limitation: a path outside every root that contains a space is cut at the first space (a root whose own path has spaces is matched whole); a Windows path is matched by drive letter and ignores case against a Windows root.
- **Stop budget (MAJOR).** `StopBudget.Run` no longer trusts a phase to honour its context: a bounded phase runs on its own goroutine and `Run` returns at the phase deadline, abandoning the phase as `runCheck` abandons a probe (05-health §5H.9). The error wraps `ErrPhaseAbandoned` and the context error (so `errors.Is(err, context.DeadlineExceeded)` still holds), the duration is recorded as `shutdown_phase_seconds`, and `WithLog` supplies a logger for the abandonment. `PhaseStorage` stays synchronous and is never abandoned. A panic in a phase is returned as its error. No new metric family: the golden lists eight and the spec lists exactly those. Six 15 s phases on a 25 s budget used to take 1m30s; the test pins at most 25 s. The kernel does not call `StopBudget` yet, so this is dark.
  - **Storage close beside an abandoned phase.** Read from `core/storage/db.go`: `DB.Close` sets `closed` first, so any new `lease()` or `handle.check()` answers `ErrClosed` at once, then drains the engine's leases up to `core.storage.close_timeout` before syncing the WAL and closing. An abandoned phase that is mid-operation holds its lease, so it delays the close by up to that timeout (the close does not deadlock), and one that starts an operation after the flag gets `ErrClosed` rather than touching a closed engine. If the drain times out the engine stays open and `Close` may be called again. What is not proven: a phase that holds a raw engine handle outside a lease; no such caller exists in `core/storage`, but nothing enforces it.
- **Late Register-time answer (MINOR).** See Probe reasons above; this is the live change.
- **Startup tokens (MINOR).** `setStartupPending` and `setStartupTokens` (a union, sorted) each touch one half of the registry's startup state, so a degraded step racing `Complete` can no longer put `core.kernel:starting` back.
- **Metrics attach (MINOR).** The attached registry is an `atomic.Pointer`; `TestHealthMetrics_AttachRacesCollection` runs an attach against a collection under `-race`.
- **Posture tokens (MINOR).** `isPostureReason` covers `backup_`, `keyring_` and `derive_key_`; `TestPostureTokensGolden` pins all 37 tokens the specs name.
- **Permission counts (MINOR).** A `Source` is now `func(ctx, Viewer) (any, error)` and may return `diagnostics.Filtered{Value, Omitted}`; the omitted rows count under the permission layer (`OmitRows`, `RowOmitter`). F8-04 sources that filter by permission should return it.
- **Retention (MINOR).** `OpenBundle(root, file, retention, now)` refuses a file older than retention with `ErrExpired` (410); zero retention means `DefaultRetention` (24 h). `healthhttp.Deps.Retention` and `Deps.Now` carry it; **F8-04 wires `Retention` from the config key**.
- **Request-time permissions (MINOR), then clamped (HIGH, found by automated review after the push).** `ExportParams.Perms []string` (JSON `perms`, never omitted) is the requester's permission snapshot taken when the run is requested. It can only NARROW: task params are client-supplied, so a snapshot is never trusted to grant. `Exporter.viewer` always resolves the actor through `ViewerFor` and a permission is held only when the actor holds it now AND the snapshot lists it (`nil` means no snapshot, an empty non-nil slice means a snapshot of nothing; an actor `ViewerFor` cannot resolve fails the run closed). `PermsOf` and `ViewerOf` build and read the snapshot. `Exporter.Export` also refuses a run whose `ActorID` differs from the executor-stamped `rc.Actor().UserID` (`ErrActorMismatch`); a run with no stamped person is refused too (round 3: it fails closed, since comparing nothing to a claimed `ActorID` proves nothing). No system actor starts this kind today; one that needs to needs its own rule in `checkStampedActor`.
- **Readiness order (MINOR).** `TestKernel_ReadyzFlipsBeforeHTTPDrain` runs the kernel's own `beginHealthShutdown` ahead of a real `PhaseHTTPDrain` and checks, from inside the drain, `/readyz` 503, `STOPPING=1` sent and one `ready:false` published. The health-package test still pins the registry and supervisor half.
- **Nits.** `Bundle.Stream` rewrites the manifest for the view (dropped sections leave the section list and their `errors` and `truncated` entries; they are named in `omitted`; an `omitted-at-download.json` entry records them). A second `StartHeartbeat` is inert. The dead `:unknown` check in `PublicTokens` is gone.

Still true after round 2 (and after round 3): `core:system.status` (the status topic's permission) is used but not declared in the RBAC catalog; F8-04 declares it with the core catalog. The `core.diagnostics.prune` task and the retention config keys are still unbuilt.

## Review round 3 (PR #4658)

The delta review found two MAJOR, five MINOR and four NIT items, and the automated review two MEDIUM redaction bypasses in the round's own paths work; every one is fixed in this PR.

- **Admin bundle (MAJOR).** `authz.Compile` gives an administrator the `core:admin` flag and nothing else concrete, so `PermsOf` is `["core:admin"]` and an exact-name `ViewerOf` dropped every section. `ViewerOf` now admits every scope on a held `core:admin` (the checker's own rule). `Exporter.viewer` still intersects with `ViewerFor`, so a Sensitive scope for a non-interactive key and a scope the catalog does not declare stay refused. `TestDiagnostics_AdminSnapshotKeepsEverySection` runs the real `authz.Compile` admin seed, a non-interactive admin key and a forged admin snapshot over a viewer.
- **JSON log lines (MAJOR).** A `core.logs` line that is a JSON object is decoded and walked like any JSON value, then written back compact with its members in key order (not the handler's order); other lines keep the text rule, whose run now ends at a `\"` escape. Deny-listed member names now apply to log lines too.
- **Whole-value paths (MINOR, then MEDIUM).** A JSON string that is one clean absolute path (no later path start, no `: `, no double quote or backtick; a trailing or doubled separator, a `/./` segment or a space in a name does not make it prose) is replaced whole, so a path with spaces does not leak its tail; any other value that merely starts with a path goes to the text rule. An apostrophe is allowed in a clean path (`Bruce's Music`); a quoted second path is caught by the later-path-start rule. Deviation from the review's "no quote": an apostrophe in a file name would otherwise leak the rest of it.
- **Dot-dot (MEDIUM, automated).** A path is named from its cleaned form: `/srv/lib/../../home/x` starts with a root and is `<path>`, `/srv/lib/../vault/x` is `<root:vault>/x`, and only the cleaned tail is written, so no `..` survives (a trailing `/..` segment is kept inside the token instead of being trimmed as punctuation). A route prefix does not shelter a `..` either. Cost: the tail of a path under a root is written cleaned (`/a/./b/` is `/a/b`).
- **Routes (MINOR).** Router-mounted routes (`/api/`, `/public/`, `/livez`, `/readyz`, `/metrics`) are left as written. Cost: a real directory named `/api` at the filesystem root is not redacted.
- **UNC, root punctuation, markup (MINOR/NIT, then MEDIUM).** `\\host\share` starts a path; `/srv/lib.` is `<root:lib>.`; a closing tag (`</div>`) is not a path; `<` and `>` stay path boundaries (`<b>/home/bruce/x` is redacted) except the `>` of a configured root's `<root:NAME>`, so a second pass is a fixed point (the placeholder test compares in place, so a line of `>` is linear, not quadratic). The redactor never writes a path after `<path>`, so that placeholder is not skipped.
- **Stop budget grace (MINOR).** `abandonGrace` is a fixed 50ms after the phase's context ends, replacing one `runtime.Gosched` (8 to 12 of 200 runs reported a phase that honoured its context as abandoned). The overrun is bounded: abandoned bounded phases take their slice plus 50ms, at most 6 x 50ms = 300ms past the total, and the storage close starts that much later. The honoured-deadline tests are exact under `synctest` and `-count=200` passes.
- **Unstamped actor (MINOR).** Fails closed; see the request-time permissions bullet above.
- **Late-answer duration and comment (NIT).** `acceptLate` records the probe's own duration (start to answer) in the metric and the component state; the comments say the guard is open while no loop runs, which includes after `StopChecks`.
- **Storage close timeout (observation).** `core.storage.close_timeout` (30s) is longer than the 25s budget; `PhaseStorage` is never abandoned, so F8-04 must clamp the close to `Remaining()` (a `todo.d` entry carries it).

## Review round 4 (PR #4658)

The second delta review (range 0ceb05e0b..650fe1463) found two MAJOR, four MINOR and four NIT items; every one is fixed in this PR, each with a test that fails on 650fe1463 (`paths.go` restored from that commit for the path tests, a one-line mutant for the key and actor ones).

- **Query strings (MAJOR).** A route is still left as written, but only its path part. Past `maxNest` (3) a query is `<query>`. Cost: a rewritten query value is written decoded, not re-encoded. `TestDiagnostics_QueryStringIsValuesNotRoute`.

## Review round 5 (PR #4658): the grammar the path rule redacts

Rounds 3 to 5 each fixed the string the review reported, and the next review found the same shape one byte over. This section writes the grammar down first; the code, the adversarial table (`paths_adversarial_test.go`) and the fuzz target (`FuzzRedactPaths`) are held to it. Where a clause says "fail closed", an input the rule cannot parse is replaced, never passed through.

**G1. Path start.** An absolute path starts at `/x` (a doubled `//x` counts), at a drive `C:\` or `C:/`, or at a UNC `\\host`, either at the start of the text or after a boundary byte. Every byte that is not part of a name is a boundary (a name byte is a letter, digit, mark or `._~-`), with five exceptions that keep the output a fixed point and leave markup and URLs alone: the `>` closing a configured root's own placeholder, the `/` of `</tag>`, a `/` after `/` (the path is the first of the run), the `//` after a scheme, and a backslash escape that is itself a boundary. A single-segment candidate (`/15`, `/*`, `/-`, `/50%`, `/(write)`) is a path only if its segment starts with a letter, digit, `_`, `.` or `~` and holds a letter: `*/15 * * * *`, `*/*`, `+/-`, `50%/50%` and `(read)/(write)` are not paths, while `a*/home/bruce/x` (two segments) is.

**G2. Path end.** A path run ends at whitespace, a quote, a backtick, `, ; ) ] } < > |` or NUL; in a POSIX path also at a backslash escape of a control character or a code point. Trailing `.` and `:` are punctuation unless the final segment is dots. Under a configured root the root is matched whole (it may hold spaces); below it and outside every root a space ends the path (the documented free-text limit; a whole JSON value is not cut).

**G3. Name.** A path is written `<root:NAME>/rest` when its cleaned form (both the `/` reading and, for a POSIX path holding a backslash, the `\` reading) is under a configured root, `<path>` otherwise.

**G4. Route.** A token that starts `/api/`, `/public/`, `/livez`, `/readyz` or `/metrics` and whose path part (before the first `?` or `#`), percent-decoded and cleaned both ways, is still a route (`isRoute`) is a request target, not a file. A route is not cut at path delimiters: in text its extent runs to whitespace or a control byte and nothing else (round 7, G9: a quote, backtick or `\"` escape does not end it), minus, for a token with no `?` or `#`, the trailing punctuation (`' ) ] } , ; | !`, quotes, backticks and `.`/`:` outside a dot segment) which goes back to the surrounding text; a token with a query is not trimmed; in a whole JSON value (a value that is one route, with or without prose after it) it is the entire string. A token that starts like a route and is not one (a bad escape, a `..` out of the subtree, `/livez/x`) is an ordinary path.

**G5. Inside a route (round 6).** The path part (before the first `?` or `#`) is left as written except that it is percent-decoded to a fixed point (leniently: a valid `%XX` decodes, a bad one stays, within five layers) and read again as text, where a `//` is a path start (`/api/v1/x//Users/bruce`, `/api/v1/x/%2FUsers%2Fbruce`). A part still changing after five layers is written `<value>`. A part with no path is kept as written; one with a path is written percent-encoded (allowlist `A-Za-z0-9-._~/:<>`, every other byte `%XX`) when it was decoded, and as the rewritten text when it was not. **The query and fragment are opaque.** Everything from the first `?` or `#` to the end of the token is one fixed placeholder, `?<query>` or `#<fragment>`: no split on `&`, `=` or `;`, no decoding, no per-value judgment, no depth cap. A `#` after a `?` is part of the query. The round-5 per-value query judgment, its decode layering and its `<query>` depth cap are deleted, because splitting is exactly what a raw delimiter in a directory name defeats (G8). Cost: the bundle no longer shows any query parameter (`sort=title`, `page=2`, a configured root's `<root:lib>` inside a `path=`). There is no unredacted view to leave unchanged: every bundle is redacted the same way for everyone (see Round 8). Past `maxNest` a path text with a path start is `<path>`.

**G6. Fail closed (round 6).** Anything that does not parse as above is replaced: a bad escape in a route's path part is not a route (so `<path>`), a route or URL path part still decoding after five layers is `<value>`, a token that still decodes after the bound (G7) is `<path>`, nesting past `maxNest` with a path start is `<path>`, a panic is `[REDACTED]`.

**G7. Where the path rule decodes (round 6, a coordinator ruling; it was a known limit in round 5).** Two rules. (1) **A full URL** (`scheme://host/path?query`, any scheme but `file`, recognised wherever its scheme starts if the byte before is not a scheme byte) keeps its authority, has its path part judged as a route's is (G5), and has its query and fragment opaque as in G5. A whole JSON value that starts as a URL with a `?` or `#` in its first whitespace-delimited chunk is one URL to its end, as a value that is one route is, so a raw space in its query is part of it. (2) **Outside routes and URLs**, a token (the text from a token start, which is the text start or the byte after whitespace, a control byte, `"` or a backtick, past any opening `'([{<`, to the next whitespace, quote or backtick, minus trailing closing punctuation) that holds a percent-encoded separator (`%2F`, `%2f`, `%5C`, `%5c`) is decoded leniently, one layer at a time; at the first layer whose text holds an encoded separator and whose decoded text holds an absolute-path start (G1), the whole token is `<path>`, the opening punctuation kept. A token that is still decoding after six layers is `<path>` (fail closed). A token with no encoded separator at any layer (`see 50%25 done`, `application%2Fjson`, `rate=50%25,/Users/x`, where the raw path is judged by G1 alone) is not judged whole. Over-redaction is accepted: the whole token goes, so `x=a%2F/home/bruce/y` loses its `x=a` too. Bounded to tokens that carry an encoded separator, linear (each layer is one pass, at most six). `TestRedactPaths_EncodedPathOutsideARouteIsRedacted` pins it, and the generator plants encoded forms in text.

**G8. Query delimiters (round 6, a coordinator ruling; it was a known limit in round 5).** A raw `&`, `#`, `=`, `;`, `?` or `%` in a directory name used to split a route's query and leave the part after the delimiter, a relative path with no leading slash, in the output. The query is opaque (G5), so nothing splits: `/api/v1/x?path=/Users/a&b/Gordonx/Books` is `/api/v1/x?<query>`. `TestRedactPaths_RawQueryDelimiterInANameIsRedacted` pins ten shapes and asserts the marker does not survive; the planted-marker generator and the fuzz target now plant such names raw, in every route, URL and fragment context (the skip that had kept G8 a limit is gone).

**G9. A query runs to whitespace (round 7, a coordinator ruling; it was the open finding of round 6).** Inside a route or URL, once `?` or `#` is seen the opaque `?<query>` / `#<fragment>` runs to the next whitespace or control byte (or the end of the input) in every context, free text included. A raw `"`, backtick, `'`, `)`, `]`, `>`, `,` or a JSON-escaped `\"` does not end it. The path part before the `?` runs to the same end (see Review round 7, neighbour a). `TestRedactPaths_QueryRunsToWhitespaceWhateverItHolds` pins the table; the planted-marker generator and the fuzz target plant those bytes raw in every route, URL and fragment context.

**Round 5 deviations and not proven.**

- Relative paths (no leading slash, no drive, no UNC) are not paths under G1 and are not redacted anywhere; that was true before round 5 and the grammar now says so.
- Free-text roads cut a path at the G2 delimiters, so a directory name that holds one of them (`x'y`, `x,y`) in a bare path in prose (not in a route, not a whole JSON value) is redacted only up to the delimiter. Routes and whole values are not cut. No producer writes such text today; if one does, it needs a structured field, not a wider scan.
- Windows drive roots (`C:\...` under a configured root) cannot be exercised against a real volume on darwin; the tests cover the string forms only.
- `Build` now holds the actor check (`checkStampedActor`); `Export` no longer repeats it. The error count (`countBundle("error")`) moved with it, so a refused `Export` still counts once.
- The fuzz target ran 60 s (184k executions) clean at the last commit after the two findings below were fixed (a nested route decoded before it was judged; `absolutePath("")` indexed past the end). CI runs the seed corpus only. Round 6 supersedes this: see the Round 6 section.

### The invariant

**S1, share-safety of the downloaded bytes (round 8, replacing the round 7 wording).** For every byte sequence a diagnostics download returns (JSON values and keys, text-file lines, manifest text, zip entry names), no part of an absolute filesystem location that appeared in the input survives. That covers raw, percent-encoded at any depth, JSON-escaped (`\/`, `\u002F`, `\\u002F`) and HTML-entity-encoded (`&#47;`) forms, and it covers the location **as the filesystem names it**, including spaces, tabs, quotes, commas and other punctuation inside its names. An absolute location is any of: a POSIX `/...` path; a drive path with or without a separator (`C:\`, `C:/`, `C:rel`); a UNC or device path (`\\host`, `\\?\`, `\\.\`); a rooted backslash path (`\Users\...`); a tilde-user path (`~name/...`); the path part of a URL whose scheme names a filesystem (`file`, `smb`, `nfs`, `sftp`, `afp`, `ftp`). The only allowed survivors are the placeholders `<path>` and `<root:NAME>` for a configured root (whether the library-relative tail under a root may survive is an owner ruling, m3 below). In scope: home directory and profile names, volume and mount names, every path component outside a configured root, and the encoded forms of all of these. Out of scope unless the owner rules otherwise: a bare username outside a path, hostnames in URLs (G7 keeps the authority), base64 or hex blobs.

**The current scanner does NOT meet S1** (Round 8 lists the open leaks). What it is tested against is narrower: `TestRedactPaths_NoPathByteSurvivesProperty` plants a marker in a path built from independent parts (a prefix from `propPrefixes`, a context from `ctxs`, a spelling from `forms`, a name from `allNames`, a wrapper and a suffix), at a fixed seed (60,000 samples in CI; `PATHS_PROP_SEED` and `PATHS_PROP_N` widen it by hand: seeds 1, 2 and 3 at 400,000 samples were clean at round 7), and fails if the marker is readable, raw or decoded, on any of the four roads. That is the scanner's own extent rules (a path ends at the first whitespace in a route or URL, G9; at the first G2 delimiter in a bare path in free text; at the end of a whole value) checked against its own tables. It is a regression net for the grammar, not a proof of S1: a path with a space in a directory name is cut at the space by those rules, and the property does not call the tail a leak.

**Design assessment (for the Opus review).** The scanner can meet the invariant only as long as each rule's edge case is found by a test, and it has not been closing them by construction: rounds 5 to 7 each found a hole at a seam between two rules (a token extent, a boundary exemption, an authority cut, a decode layer). The reason is structural: a path is found by asking "does an absolute path start here, judged against the byte before it" at token starts, and every exemption (a placeholder's `>`, a closing tag's `/`, a scheme's `//`, a name byte, a G2 delimiter, a quote) is a place where the answer differs between the raw text and its decoded form or between two starts in the same run. A structure that meets the invariant by construction: (1) cut a line into whitespace-delimited runs; (2) judge each run once, as a whole, at every decoding layer, for any absolute-path start at any byte, the single exemption being the redactor's own output form (a raw `<root:NAME>/` tail); (3) when a start is found, replace from its offset (mapped back through the decode) to the end of the run, never at a delimiter; a run with no start is left alone, and routes and URLs keep their structured treatment (query and fragment placeholders) only as a presentation of runs that have none. The cost is more over-redaction in compact JSON and CSV runs (`"p":"/Users/x","q":1` loses `,"q":1`) and the same single limit as today, whitespace inside a directory name. I did not start that rewrite: it replaces `scanPaths`, `tokenAt`, `pathAt`, `urlText`, `afterCut` and the `judged` and `cut` bookkeeping, and the review that followed decided it: the scanner is replaced, not patched further, by F8-03b (Round 8).

- **Flag for owner.** (1) A rooted path with a backslash and no drive (`\Users\bruce`, and `%5CUsers%5Cbruce`) is not a path under G1, so neither form is redacted. (2) Whitespace in a directory name (space, tab, line break) ends any token in free text, and a route's or URL's query only in the places a whole value does not read it whole; the fix is to read a route's query to the end of the line, at the cost above. (3) A bare, non-route path in free text is cut at its G2 delimiters, so a directory name holding a quote or a bracket in prose (not in a route, not a whole JSON value) is redacted only up to that byte; no producer writes such text today.
