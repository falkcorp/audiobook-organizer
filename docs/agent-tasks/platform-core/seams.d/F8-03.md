# F8-03 seams and coined names

This file covers what the "core health completed, dark" PR added beyond 05-health §5H.3 to §5H.10, the readings it took where the spec or the brief is silent, the one STOP that fired, and what it left for F8-04. Everything is dark: ABO's `/health`, `/api/health`, `/api/v1/health` and `/api/v1/system/status` are unchanged, `core/kernel/boot.go` is not edited, and nothing mounts the new routes.

## The STOP that fired

The brief says to STOP if `Registry.Snapshot` already exists. It did (F2-10 left it in `registry.go`). The option taken was to extend the stub rather than stop: `Snapshot`, `ComponentState` and `Live` moved into the new `snapshot.go`, and `registry.go` was modified although the brief's file table does not list it. The registry's F2 behaviour is unchanged where `registry_test.go` pins it; the one visible change is below (probe panics and timeouts).

## Deviations and readings

- **Import limits.** The health root imports `internal/sdnotify` (and `events`, `rbac` where used), beyond the spec header's list. It does not import `library` or `health/sysinfo`; the container default for the stop budget is a bool parameter, not a call into sysinfo.
- **Probe reasons.** `probe_panicked` is renamed `check_panic` (spec §5H.5) and `check_timeout` is added. A probe that answers after its deadline is now Down `check_timeout`, and `Register`'s synchronous first probe is bounded too. `registry_test.go` was updated for both. One exception, added in review round 2 and a LIVE boot change (core.storage registers at every boot, `kernel/boot.go`): a Register-time probe that overran its timeout and then answers is accepted, so core.storage whose engine ping is slow at boot becomes Up instead of staying Down for good and starving the tasks executor that waits on it. It applies only until `StartChecks` has run, and only while the component's result is still that Register's `check_timeout` (a `Report` in between is newer and wins). When an answer and the deadline are ready together, the answer is kept if the probe returned before the deadline and counted as a timeout if it returned after; that tie only arises on real-time descheduling, so it has no deterministic test.
- **Readiness tokens.** `core.kernel:starting` and `core.kernel:stopping` appear only when a `Startup` is attached or `BeginShutdown` has been called. `PublicTokens` generalises a posture reason to `down` or `unknown`, so no posture token reaches an unauthenticated body.
- **`CoreStartupSteps()`** returns seven rows: EnsureSecureStateDir, guardAgainstKeyRegeneration, initEncryption, loadConfigFromDB, config.Validate, opRegistrationGate and http. HEAD's other steps (settingsWrites, container.Start, opCatalogGate, searchindex) are module rows for F8-04, not core's. `Startup.Run` does not call `ExtendStart` itself; the kernel's step function does, so the once-per-step rule is the caller's. `TestStartup_ExtendPerStepNeverTimer` drives the real table with the real `SystemdNotifier` over a fake notify socket (one datagram per asking step, none for a silent or failing one, none between steps), and `TestStartup_ExtendNeverOnATimer` holds the idle-hour half in fake time.
- **"Wire on hello/coretest".** Read as tests only: the routes are exercised through the real `httpapi` router in `healthhttp`'s tests; `hello` and `coretest` are not edited.
- **Diagnostics core sections.** The producers are injected through `CoreSources` because kernel wiring is F8-04. The `core.config` source must hand the exporter `diagnostics.Secret` / `Redacted` placeholders (typing is the source's job; the pattern layer is the net, not the plan). Every core section uses `core:system.manage` as its Perm; the spec is silent. Section writers run one after another because the zip writer is not concurrent.
- **Unknown requested section names** fail at run time in `Exporter.plan`, not at the route, because the route does not know the module sections.
- **Release trailer.** Commits carry "Claude Sonnet 5.5" per the harness, not the rules file's "Opus 5.5".
- **Platform files.** `core/health/sysinfo` has darwin, linux, windows and other host files. Darwin is tested; linux and windows are `go vet`-checked only; real systemd was not run. `GOOS=freebsd go build` fails in `core/library` before this PR.

## Review round 2 (PR #4658)

The Opus review found four MAJOR, eight MINOR and four NIT items; all sixteen are fixed in this PR. What each left behind:

- **Download gate (MAJOR).** The download route now requires an interactive method (`Method.Interactive()`, which is `MethodSession` only), not merely a method that may change credentials (`MayChangeCredentials()` also admits a delegated session); an API key or a delegated session gets 403 `interactive_required`. Only the download route uses this gate; the shared router Guards are unchanged.
- **Key redaction (MAJOR).** Map keys are redacted as well as values: `scrub` and `walkObject` rebuild an object with sorted, redacted keys. Keys that collapse to the same text get a `#2`, `#3` suffix, and a key is judged for the deny list by its original text. Each change counts as a pattern redaction.
- **Paths (MAJOR).** Absolute paths are redacted (`paths.go`): a path under a known root becomes `<root:NAME>/rest`, any other absolute path becomes `<path>`. `Config.Roots []PathRoot` supplies the roots, so **F8-04 must pass the library roots**; with none, every absolute path is `<path>`. It applies to values, `Writer.File` lines, manifest `errors[]` and keys. Limitation: a path outside every root that contains a space is cut at the first space (a root whose own path has spaces is matched whole); a Windows path is matched by drive letter and ignores case against a Windows root.
- **Stop budget (MAJOR).** `StopBudget.Run` no longer trusts a phase to honour its context: a bounded phase runs on its own goroutine and `Run` returns at the phase deadline, abandoning the phase as `runCheck` abandons a probe (05-health §5H.9). The error wraps `ErrPhaseAbandoned` and the context error (so `errors.Is(err, context.DeadlineExceeded)` still holds), the duration is recorded as `shutdown_phase_seconds`, and `WithLog` supplies a logger for the abandonment. `PhaseStorage` stays synchronous and is never abandoned. A panic in a phase is returned as its error. No new metric family: the golden lists eight and the spec lists exactly those. Six 15 s phases on a 25 s budget used to take 1m30s; the test pins at most 25 s. The kernel does not call `StopBudget` yet, so this is dark.
  - **Storage close beside an abandoned phase.** Read from `core/storage/db.go`: `DB.Close` sets `closed` first, so any new `lease()` or `handle.check()` answers `ErrClosed` at once, then drains the engine's leases up to `core.storage.close_timeout` before syncing the WAL and closing. An abandoned phase that is mid-operation holds its lease, so it delays the close by up to that timeout (the close does not deadlock), and one that starts an operation after the flag gets `ErrClosed` rather than touching a closed engine. If the drain times out the engine stays open and `Close` may be called again. What is not proven: a phase that holds a raw engine handle outside a lease; no such caller exists in `core/storage`, but nothing enforces it.
- **Late Register-time answer (MINOR).** See Probe reasons above; this is the live change.
- **Startup tokens (MINOR).** `setStartupPending` and `setStartupTokens` (a union, sorted) each touch one half of the registry's startup state, so a degraded step racing `Complete` can no longer put `core.kernel:starting` back.
- **Metrics attach (MINOR).** The attached registry is an `atomic.Pointer`; `TestHealthMetrics_AttachRacesCollection` runs an attach against a collection under `-race`.
- **Posture tokens (MINOR).** `isPostureReason` covers `backup_`, `keyring_` and `derive_key_`; `TestPostureTokensGolden` pins all 37 tokens the specs name.
- **Permission counts (MINOR).** A `Source` is now `func(ctx, Viewer) (any, error)` and may return `diagnostics.Filtered{Value, Omitted}`; the omitted rows count under the permission layer (`OmitRows`, `RowOmitter`). F8-04 sources that filter by permission should return it.
- **Retention (MINOR).** `OpenBundle(root, file, retention, now)` refuses a file older than retention with `ErrExpired` (410); zero retention means `DefaultRetention` (24 h). `healthhttp.Deps.Retention` and `Deps.Now` carry it; **F8-04 wires `Retention` from the config key**.
- **Request-time permissions (MINOR), then clamped (HIGH, found by automated review after the push).** `ExportParams.Perms []string` (JSON `perms`, never omitted) is the requester's permission snapshot taken when the run is requested. It can only NARROW: task params are client-supplied, so a snapshot is never trusted to grant. `Exporter.viewer` always resolves the actor through `ViewerFor` and a permission is held only when the actor holds it now AND the snapshot lists it (`nil` means no snapshot, an empty non-nil slice means a snapshot of nothing; an actor `ViewerFor` cannot resolve fails the run closed). `PermsOf` and `ViewerOf` build and read the snapshot. `Exporter.Export` also refuses a run whose `ActorID` differs from the executor-stamped `rc.Actor().UserID` (`ErrActorMismatch`); a run with no stamped person (a system actor) has nothing to compare and is still limited by `ViewerFor`. Residual: the download route binds to `ActorID` from the stored run record, which for a system-started run is the claimed one; no system actor starts this kind today.
- **Readiness order (MINOR).** `TestKernel_ReadyzFlipsBeforeHTTPDrain` runs the kernel's own `beginHealthShutdown` ahead of a real `PhaseHTTPDrain` and checks, from inside the drain, `/readyz` 503, `STOPPING=1` sent and one `ready:false` published. The health-package test still pins the registry and supervisor half.
- **Nits.** `Bundle.Stream` rewrites the manifest for the view (dropped sections leave the section list and their `errors` and `truncated` entries; they are named in `omitted`; an `omitted-at-download.json` entry records them). A second `StartHeartbeat` is inert. The dead `:unknown` check in `PublicTokens` is gone.

Still true after round 2: `core:system.status` (the status topic's permission) is used but not declared in the RBAC catalog; F8-04 declares it with the core catalog. The `core.diagnostics.prune` task and the retention config keys are still unbuilt.

## Follow-ups for F8-04

1. Boot wiring: call `registerCoreComponents`, `startHealthLoops` and `beginHealthShutdown` from `Boot` and `Shutdown`, in the order the stop budget names; build the registry with `NewRegistryWith`.
2. Call `reg.SetStatusPublisher(health.PublishStatus(<core events scope>))` once the bus is open (the topic is already in `coreTopics()`).
3. `Registrar.StartupSteps` and `Registrar.Diagnostics` in `core/module/`, then run `archtest.StartupSteps` over `kernel` and `module` against `CoreStartupSteps()` plus the module rows. It cannot run on real core yet: nothing calls `Startup.Run` outside the tests, and the guard refuses a tree with no `Run` call rather than pass vacuously. The guard is syntactic: an identifier receiver counts only when its own function (or a package var) declares it a `*health.Startup`, a field receiver only when a struct of the package declares a `Startup` field of that name; a `Startup` reached through a helper's return value is not seen, so F8-04 should keep it in a field or a local.
4. Mount `healthhttp.Register` and `RegisterProbes`; supply the real `Enqueuer` and `Runs`, `Deps.Retention` and `Deps.Now`, the library roots as `diagnostics.Config.Roots`, and the requester's snapshot as `ExportParams.Perms` on the enqueue path (the start handler already sets it; it only narrows). Declare `core:system.status` in the RBAC catalog.
5. Register the `core.diagnostics.prune` task (schedule key `core.diagnostics.schedules.prune`) and the config keys for retention, log lines, task runs and max file bytes.
6. Delete `diagnostics.InterimExport`, and retire `/health` and `/api/health` once ABO's callers move to `/livez` and `/readyz`; add `/livez` and `/readyz` to the gin SPA fallback's reserved segments.
