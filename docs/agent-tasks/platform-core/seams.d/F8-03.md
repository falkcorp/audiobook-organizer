# F8-03 seams and coined names

This file covers what the "core health completed, dark" PR added beyond 05-health §5H.3 to §5H.10, the readings it took where the spec or the brief is silent, the one STOP that fired, and what it left for F8-04. Everything is dark: ABO's `/health`, `/api/health`, `/api/v1/health` and `/api/v1/system/status` are unchanged, `core/kernel/boot.go` is not edited, and nothing mounts the new routes.

## The STOP that fired

The brief says to STOP if `Registry.Snapshot` already exists. It did (F2-10 left it in `registry.go`). The option taken was to extend the stub rather than stop: `Snapshot`, `ComponentState` and `Live` moved into the new `snapshot.go`, and `registry.go` was modified although the brief's file table does not list it. The registry's F2 behaviour is unchanged where `registry_test.go` pins it; the one visible change is below (probe panics and timeouts).

## Deviations and readings

- **Import limits.** The health root imports `internal/sdnotify` (and `events`, `rbac` where used), beyond the spec header's list. It does not import `library` or `health/sysinfo`; the container default for the stop budget is a bool parameter, not a call into sysinfo.
- **Probe reasons.** `probe_panicked` is renamed `check_panic` (spec §5H.5) and `check_timeout` is added. A probe that answers after its deadline is now Down `check_timeout`, and `Register`'s synchronous first probe is bounded too. `registry_test.go` was updated for both.
- **Readiness tokens.** `core.kernel:starting` and `core.kernel:stopping` appear only when a `Startup` is attached or `BeginShutdown` has been called. `PublicTokens` generalises a posture reason to `down` or `unknown`, so no posture token reaches an unauthenticated body.
- **`CoreStartupSteps()`** returns seven rows: EnsureSecureStateDir, guardAgainstKeyRegeneration, initEncryption, loadConfigFromDB, config.Validate, opRegistrationGate and http. HEAD's other steps (settingsWrites, container.Start, opCatalogGate, searchindex) are module rows for F8-04, not core's. `Startup.Run` does not call `ExtendStart` itself; the kernel's step function does, so the once-per-step rule is the caller's and `TestStartup_ExtendPerStepNeverTimer` pins the table's side.
- **"Wire on hello/coretest".** Read as tests only: the routes are exercised through the real `httpapi` router in `healthhttp`'s tests; `hello` and `coretest` are not edited.
- **Diagnostics core sections.** The producers are injected through `CoreSources` because kernel wiring is F8-04. The `core.config` source must hand the exporter `diagnostics.Secret` / `Redacted` placeholders (typing is the source's job; the pattern layer is the net, not the plan). Every core section uses `core:system.manage` as its Perm; the spec is silent. Section writers run one after another because the zip writer is not concurrent.
- **Unknown requested section names** fail at run time in `Exporter.plan`, not at the route, because the route does not know the module sections.
- **Release trailer.** Commits carry "Claude Sonnet 5.5" per the harness, not the rules file's "Opus 5.5".
- **Platform files.** `core/health/sysinfo` has darwin, linux, windows and other host files. Darwin is tested; linux and windows are `go vet`-checked only; real systemd was not run. `GOOS=freebsd go build` fails in `core/library` before this PR.

## Follow-ups for F8-04

1. Boot wiring: call `registerCoreComponents`, `startHealthLoops` and `beginHealthShutdown` from `Boot` and `Shutdown`, in the order the stop budget names; build the registry with `NewRegistryWith`.
2. Call `reg.SetStatusPublisher(health.PublishStatus(<core events scope>))` once the bus is open (the topic is already in `coreTopics()`).
3. `Registrar.StartupSteps` and `Registrar.Diagnostics` in `core/module/`, then run `archtest.StartupSteps` over `kernel` and `module` against `CoreStartupSteps()` plus the module rows. It cannot run on real core yet: nothing calls `Startup.Run` outside the tests, and the guard refuses a tree with no `Run` call rather than pass vacuously. The guard is syntactic: an identifier receiver counts only when its own function (or a package var) declares it a `*health.Startup`, a field receiver only when a struct of the package declares a `Startup` field of that name; a `Startup` reached through a helper's return value is not seen, so F8-04 should keep it in a field or a local.
4. Mount `healthhttp.Register` and `RegisterProbes`; supply the real `Enqueuer` and `Runs`.
5. Register the `core.diagnostics.prune` task (schedule key `core.diagnostics.schedules.prune`) and the config keys for retention, log lines, task runs and max file bytes.
6. Delete `diagnostics.InterimExport`, and retire `/health` and `/api/health` once ABO's callers move to `/livez` and `/readyz`; add `/livez` and `/readyz` to the gin SPA fallback's reserved segments.
