# F9-04 seams, deviations and what F9-03 must know

F9-04 (cut the shell-classified pages, dark) was built against a base where its predecessors had not landed: F9-05's providers and utils, F9-02's `web` to `@mediacore/shell` wiring (its slice 0) and the R2 flips whose native routes the pages call. What this row built, and what it left, follows. Everything not listed here is the brief as written.

## Deviations from the brief (all approved by the coordinator, 2026-11-20)

1. **Only in-place cuts, no moves into `core/web`.** At `5b6125e7d` and after, `core/web/packages/shell/src/pages/` does not exist, the generated core `paths` is empty (`core/web/packages/api-client/src/generated/core.ts`), and every page still calls `/api/v1/...` through `services/api` or `apiFetch`. A `git mv` into the shell would make a shell page call a HEAD route, which the shell may not do (I1, I5). So each slice cuts the books piece of one page into `web/src/modules/books/pages/` and leaves the shell half in place, composed by an ABO binding at the old path. The shell half moves in a later row, when the flips and F9-05 are on main.
2. **`Login`, `AcceptInvite`, `Setup` and `NotFound` do not move.** F9-01 already ships shell twins (`core/web/packages/shell/src/auth/{LoginPage,InvitePage,SetupPage,TempLoginPage}.tsx`, `app/Page.tsx` `NotFoundPage`) over the native routes. Moving ABO's pages would duplicate them. F9-03 must compare the two sets and port any behaviour the ABO page has that the twin lacks (parity gaps are listed per page below as they are found), then delete ABO's four pages with the re-export files.
3. **One file per books widget, named after the page piece.** The contribution objects (`WidgetContribution` and the other slot types) are not written yet: `web` cannot resolve `@mediacore/shell` until F9-02's slice 0 merges, and the types are copied from the shell, never redefined in ABO. Each books piece is written in the shape its slot needs (a component that takes no props), so the contribution is one `lazy: () => import(...)` line per piece once the types resolve.
