# F8-01 seams and coined names

This file covers what the "core backup, dark" PR added beyond 05-backup §5B.3 and §5B.10: names the spec does not have, the readings it took where the spec or the brief is silent, the security-review fix made in the PR, how the brief's test names map to tests, and what it left for later rows. Everything is dark: ABO's backup, its routes and its R1 extractor are unchanged (I8), `internal/backup` is not imported, and no kernel boot path builds a `backup.Svc`. The only live change is `storage restore-offline --archive` (below).

## The restore-option gate (coordinator security finding)

`core.backup.stage-restore` has `Perms.Start` of `core:backup.restore` only. A task body that passed `Foreign`, `ReplaceConfig`, `AcceptUnreadableSecrets` or `AllowWeakVerify` to `StageRestore` would have bypassed the route's interactive-owner (and, for `Foreign`, `core:admin`) guard. The gate is in `StageRestore` and `RevertLastRestore` themselves, not in their callers:

- `authorizeOptions(ctx, opts)` runs first, before the backup resource is taken (the metric records "rejected"). Any of those four options needs `RestoreProof{Owner: true}` on the context; `Foreign` also needs `Admin: true`.
- The route (`backuphttp`) is the only code that sets the proof, after its own authorise step: `Owner: true` (its guard already required the interactive owner) and `Admin` from `holds(core:admin)`. The task body never sets it, so the task path refuses the privileged options (`TestStageTaskRefusesPrivilegedOptions`).
- A plain restore and `Restart` need no proof from the package: who may stage one is the caller's gate (the route's `core:backup.restore` plus its owner guard, the task's `Perms.Start`).

A caller added later cannot forget the check, because the check is not the caller's. Tests: `TestRestoreOptionsGate`, `TestPlainRestoreNeedsNoProofFromThePackage`, `TestRevertGate`, `TestStageTaskRefusesPrivilegedOptions`, and the route tests assert the proof the route passes.

**Residual, for the owner.** A plain restore reached through the task path is gated only by `core:backup.restore` (Sensitive, AuthRequired) per the spec's task row, with no owner assurance, where the route also has the owner guard. Making the task path owner-gated would mean only the route may enqueue it. `Restart` is left ungated on purpose: it only asks for the restart the staged restore already needs.

## Readings the spec leaves open

| Topic | Reading |
|---|---|
| Strict manifest | `ParseManifest` uses `DisallowUnknownFields`: a newer additive field (for example `encrypted`) must refuse, never be read as plaintext. The MAC is over the canonical re-marshal with the MAC field cleared, compared with `hmac.Equal`. |
| Catalogue source of truth | The archive's own first-entry manifest, not the `.manifest.json` sidecar (a sidecar can be swapped under another archive's ID or provenance). Verify compares the sidecar with the archive and fails on a difference. |
| Legacy first entry | HEAD's archives begin with the store directory's own entry, so a first entry of another type is classified `ErrManifest` ("not a mediacore-backup/1 archive") and the caller tries the legacy scan. |
| Tar entries | Only regular files (and directories in a legacy archive); symlinks, hard links, devices, FIFOs, sparse maps, absolute names, `..`, doubled separators, backslashes and NULs are refused. Header sizes are checked against `Limits` before any buffer is sized. Files are created `O_EXCL` 0600 and directories 0700 from the start. |
| Retention and the floors | The count bound includes the floor-protected archives, so the newest verified archive can outlive a newer unverified one (floor 1 of §5B.3.5). Retention runs before the space check. |
| Config on restore | A config file archived redacted (`ConfigFileHasSecrets()`) is never swapped in: it is staged to `config.restored` for the operator. `ReplaceConfig` swaps only an unredacted copy. |
| `Requires` data-migration floors | Not provable from the manifest. The Inspector's `storage.Open` of the staged store applies them; its `ErrKeyspaceTooNew` is mapped to `ErrBackupTooNew` after extraction, not before. `ErrUpgradeFloor` is raised from the manifest before extraction. |
| Derived items | `DerivedGeneration` is a seam. `StorageInspector` does not fill `StoreInfo.Generations` until F7-07's generation API exists; `TestDerivedItemsGenerationChecked` drives the check through a wrapping Inspector. |
| Intent IDs and TTL | `<yyyymmddThhmmssZ>-<8 hex>`; the default TTL is 24 h (`core.storage.swap.intent_ttl` at F8-04). |
| Platforms | Core builds for Windows (`GOOS=windows go build ./...` is clean) and the backup package keeps it so. Free space comes from `library.Stats` (Bavail, with its Windows implementation). The same-device proof (`Stat_t.Dev`) exists on unix only (`disk_unix.go`); on any other platform `osDevice` returns an error, so create and staging refuse rather than assume one device. `backuparchive.OpenRegular` has the same split (`open_unix.go`/`open_other.go`). |
| `Rewrap` | Re-MACs under the active key with a new ID and deletes the original only when no retention floor protects it. Only an `Own` archive is re-signed (`ErrForeignArchive` otherwise). |

## Offline restore (`storage restore-offline --archive`)

- `backup.ExtractStore(ctx, archive, storeDir)` has `kernel.Config.ArchiveExtract`'s signature. A mediacore-backup/1 archive is read through its manifest (the manifest sidecar must equal the archive's, every entry must be listed and match its size and SHA-256 as it streams) and **only `db/` is written**, so an `--into` copy never receives the config or boot-record entries. A legacy-abo/0 archive is scanned end to end, then extracted with its top-level directory stripped. A `.sha256` sidecar, when present, must match (unreadable or malformed refuses too); an archive named by hand with no sidecar extracts, as HEAD's did, and the kernel opens the extracted store read-only with this build's guard before it stages anything.
- **Provenance is not checked offline.** The command is the state directory's owner at a terminal with the service stopped and `--accept-loss` (the kernel refuses anything else), which is the authority to replace the store by hand. The spec's `[--foreign]` flag and an offline MAC check would need the kernel seam to carry provenance and the keyring-derived key; they are not in the brief's flag list (`--archive`, `--keyring`, `--gap-fill`, `--accept-loss`) and are not built. The staged restore is the provenance gate.
- `--keyring <file>` and `--gap-fill <file>` (archive only; a checkpoint holds its own copies) are staged under the state-file labels `keyring` and `gap_fill` and replace the live file of that label at the path the app declared in `StorageStateFiles`, else `<state dir>/secrets.keyring` and `<db parent>/config.yaml`. The replaced files are set aside in `previous/` like every replaced state file; a source with no such file never removes or replaces the live one (DATA-11). The keyring must be a regular, non-empty, mode-0600 file of at most 1 MiB, never a symbolic link. With `--into` both are copied to `<into>.state/<label>`.
- A legacy archive restored without `--gap-fill` warns what then migrates empty and that its encrypted rows are read with the host's `.encryption_key`. The warning does not list HEAD's setting keys: the managed set is HEAD's to change, and a list here would go stale.
- `app`: an app that sets no `R1ArchiveExtract` now extracts through `backup.ExtractStore` (was: `--archive` refused). ABO sets its own until its R2 flip, so ABO's behaviour is unchanged (I8).

## Left for later rows

- **F8-04** (wires the Service): compose `backup.Recheck` with the swapper default; build the `Keyring`, `Markers`, `Inspector` (with `Generations` from F7-07) and `Stager` adapters; supply `Progress` from the run context; register the `backup` scope and `backuphttp.Register`; extend `TestLegacyArchiveRestoreThenMigrate` to the migrated store.
- **Retention's journal trim.** `journal` has no trim function today, so `Options.PruneJournal` is a seam that nothing implements. Retention calls it when set; the revocation journal keeps growing until F4-11's follow-up or F8-04 adds the trim.
- **Offline restore of the config file and boot record from an archive** (spec §5B.3.4, "from an archive, the config file and boot record when they are not redacted copies"). `kernel.Config` has no config-path fields and `ArchiveExtract`'s signature is fixed by ABO's R1 seam, so the offline path cannot place them. Cost: one optional kernel seam (or two `Config` fields) naming those paths, and `ExtractStore` writing the two entries to a side directory. Not built here.
- **Offline provenance and `--foreign`**, and the offline secrets-coverage check (the keyring covers the archive's secret records, step 5): the second needs F3-07's offline secrets bring-up. See above.
