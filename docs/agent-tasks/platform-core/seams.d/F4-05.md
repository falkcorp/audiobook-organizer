# F4-05 seams and coined names

What F4-05 added beyond 05-authn §4.13, 05-rbac §7 and §8, 05-config §1, 05-http-api and 07 §7.5 and §7.6, the readings it took where the brief or the spec says nothing, and what F4-08 and the follow-ups must know. The PR is dark: nothing imports `internal/authhttp`, `rbachttp`, `audithttp`, `confighttp`, `storagehttp`, `modulehttp` or `uihttp` before F4-08 (the kernel), and `httpapi.Router.Build` refuses every non-Public native route until stage 13 and its Deps exist.

## httpapi additions (used first by F4-05)

| Name | What it is |
|---|---|
| `httpapi.HandleRaw(g, route, RawDoc, http.Handler)`, `RawDoc{Request, Success, Status, Query}`, `httpapi.BodyOf[T]()` | A route whose handler writes its own response: the sign-in routes set a cookie, the OIDC routes redirect, the export streams, the OpenAPI document is served as its own bytes. It goes through the same Build checks as `Handle` (name, Perm, pattern, Public list, JSON names) and is documented in OpenAPI from `RawDoc`. `RouteKindRaw` existed as a constant only. **F6-02 (eventhttp) assumes `HandleRaw` and `RawDoc` exist: if its branch also adds them, one of the two PRs must rebase onto the other.** |
| `httpapi.WriteError(w, r, err, log)`, `httpapi.DecodeJSON(w, r, limit, dst)` | A raw handler answers an error as a problem, and decodes a body by the rules of a typed handler (415, 413, 400 unknown field or trailing data, 422 wrong type). |
| `(*Error).WithRetryAfter(d)`, `httpapi.Throttled(retryAfter)` | 429 `throttled` with `Retry-After`. |
| `schemaOverrides` composes `config.Overrides()` | `config.Duration` and the other settings types render in a served OpenAPI document as in the settings schema (05-http-api SIMP3-1). It was documented and not done. |

## authhttp

- **Registration shape.** `Build` cannot accept a non-Public native route at this base, so the package is tested as F7-10 is: route-table tests over `Router.Routes()`, `TestRegister_BuildFailsOnlyForWantOfAuth` (one `ErrNoAuthService` per non-Public route and nothing else), the Public subset built and served through the real chain, and handler tests that run each handler behind its own `guard` (the route's Perm, `Interactive`, `Owner` and user-required rule, checked in handler code in the order stage 13 will). When F4-08 lands stage 13 the handler copy stays: it is cheap and makes a route mounted bare refuse what its row says.
- **`GET /users/invites`** (`core:users.manage`, user required) is added: the table lists no read of the open invites, and the invite list needs one. It never returns a token or a link.
- **`PATCH /me`** has no Service writer at this release. `authhttp.Profiles` is a local one-method interface; nil answers 501 `profile_edit_unavailable`. An implementation must clear `EmailVerified` on an e-mail change, hold the account e-mail lock around the uniqueness check and revoke what the old address granted, as HEAD's `UpdateMe` does. F4-08 supplies it (it needs `auth.Service` to export the e-mail lock seam F4-03 added).
- **Refusal codes the spec does not name.** `interactive_required` (403, a route needs an interactive sign-in and the caller used a key or auth-off), `owner_required` (403), `authentication_required` (401, from the spec), `link_invalid` (401: every way a temp-login, reset or invite token can be bad, spent, expired, stale, or its user gone or restricted is this one answer), `setup_closed` (403: setup is closed, or needs a token and has none), `user_exists`, `stale_account`, `bad_request`, `not_found` (the one answer for a missing user, key, session or invite and for one the caller may not see).
- **Keys by ID.** `GET /api-keys/{id}` is the owner's, or a manager's who dominates the owner; anyone else gets the answer a missing key gets. A write on another user's key goes to the Service, which answers a non-dominating manager `dominance_required`, and the route audits that refusal (`core.permission.deny`) where it writes it.
- **OIDC callback failures.** A provider refusal, a missing code, a failed exchange, an unverified or disallowed e-mail, an inactive or reset-required account and a failed hand-off mint redirect to `/login?error=<code>` (`oauth_denied`, `oauth_no_code`, `oauth_exchange_failed`, `oauth_not_authorized`, `oauth_code_mint_failed`: HEAD's codes). `oauth_state_invalid` (400), `email_in_use` (409), an unknown provider (404) and an unavailable store (503) are answered inline. The binding cookie (`<session cookie name>_oidc`, HttpOnly, SameSite=Lax) is cleared whatever the outcome. The callback and both start routes are `RateAuth`; `TestOIDCCallback_RunsBehindTheAuthRateLimit` proves a spent budget answers 429 before the Flow runs (the F4-03 review's hard gate). The route tests use a fake `Flow`: the redirect-URI allowlist, PKCE and state checks are `auth/oidc`'s own tests.
- **The "prove the password in the same flow" link** that F4-03.md leaves optional is not built: core's rule stays the stricter refusal (`email_in_use`).
- **One-time credentials** (an API key, a bootstrap key and generated password, an invite link, a temp-login or reset link) are returned once by the call that creates them. No list or read returns one, no sign-in returns a session token in its body, and no password or token a caller submits is echoed or logged (`TestSubmittedSecretsAreNeverEchoedOrLogged`).

## rbachttp and audithttp

- `GET /permissions` (AnyAuthenticated) is in 05-rbac §4.7 and not in the F4-05 brief rows: not built; assign it. `?reassign=` on `DELETE /roles/{name}` is not built (an F4-01 seam): a role in use is 409 `role_in_use`.
- `Route.ETag` is declared and not implemented, so role writes bind `If-Match` themselves: absent is 428 `precondition_required`, malformed 422 `invalid_version`, stale 412 `precondition_failed`.
- **Audit visibility is default-deny.** `audit.VisibilityOf(action)` classifies every action of the §7.1 table as `VisibleToAll` or `UserScoped`; an action not in the table is `VisibilityUnknown`. A `core:users.manage` holder sees every record; any other `core:audit.view` holder sees only `VisibleToAll` ones. This is stricter than 05-rbac §7.6 as first written (`core.auth.*` and `core.user.*` about another user) and than HEAD's activity-log rule, and 05-rbac §7.6 now states it. Consequences: a user no longer sees their own sign-in rows through `/audit`, and **a module's own audit actions (`books.user.merge`) are withheld from viewers who lack `core:users.manage` until a module can classify its actions** (the manifest has no field for it). Both are one-line changes if the owner wants either shown. `TestCoreActions_EveryActionIsClassified` fails a new table entry nobody classified.

## confighttp and storagehttp

- `PATCH /settings` carries no `Guards.Interactive`: 05-authn §4.11 would refuse the auth-disabled principal on every Interactive route, while 05-config §1.3.7 gives it reach to the keys below `ProtectAdmin`. Protection is per key, through `config.Actor.Interactive` (the method's `MayChangeCredentials`) and `Actor.Owner`.
- `*config.Store` exports no per-section read permission. `confighttp.Deps.ReadPerm` (`SectionReadPerm`) is kernel-supplied; nil, an unknown section or a principal with no checker reads nothing. F4-08 supplies it from the section registrations.
- `httpapi.Problem` has no extension members, and the spec names `locked_by`, `need` (403) and `library_root`/`library_file_count` (reset 422). `PATCH /settings` and `POST /system/factory-reset` are `HandleRaw` routes with a local problem writer. If `httpapi.Problem` grows an extension field, both packages shrink.
- A secret key's `Effective` is never sent; its metadata is `set`, `source`, `updated_at`, `updated_by`, `unavailable`. The fingerprint and key ID are left out: 05-config's façade text lists the fingerprint, and it is a hash.
- Factory reset: `Guards{Interactive, Owner}` on the route, and the handler checks 401, `core:admin`, interactive, owner, then availability (503) last. The owner check is conditional on `Deps.OwnerRequired` (`core.auth.owner.required`; nil means required). The request is audited (`core.system.factory_reset`) before it is staged, and an audit failure is 503 with nothing staged. `module.WithResetPlanKept` lives in L7 and cannot be imported at L6: **the kernel's `Stager` must call it** (`PLATFORM-CORE-R1-25-RESET-PLAN-KEPT`).
- F4-08 must give the auth-off principal the audit actor `UserID "auth_disabled"`, or the config committer refuses the commit.

## modulehttp and uihttp

- The spec's `/openapi/{owner}.json` is not a ServeMux pattern (`{owner}.json` is a bad wildcard segment): the route is `GET /openapi/{file}` and the handler requires the `.json` suffix. It is registered Public through `HandleRaw` and the handler applies `core.http.openapi.public` per request (hot-reloadable, so `Route.Perm` cannot carry it): flag true serves anyone; false, no principal is 401 and a principal that does not satisfy AnyAuthenticated is 403. The access check runs before the owner lookup, so an anonymous caller cannot enumerate owners. The document's operation carries `x-mediacore-permission: public`.
- `modulehttp.ModulesView` returns plain structs because `module` (L7) cannot be imported; the kernel adapter fills `Enabled` and `UI` and the core version. `disabled_modules` is emitted only for a caller holding `core:admin`.
- Kernel wiring: create the core `ui` scope once and pass the same `*metrics.Scope` to both `Register` calls (and to F9-01). `uihttp/testdata/series.golden` holds all three families; `ui_manifest_requests_total{outcome}` takes `ok`, `admin`, `unauthenticated`, `error`.
- `POST /ui/diagnostics` has no Interactive guard (07 §7.5.2 names AnyAuthenticated and "rate-limited"); its body `{kind, module?}` is a reading of the metric labels, mapped through closed sets.
