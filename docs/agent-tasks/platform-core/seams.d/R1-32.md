# R1-32 seams and coined names

This file lists what the log redactor and span redaction PR added beyond 05-logging §3, §6 and §10 and 05-metrics §3, §8, §11 and §12: names the spec does not have, readings it took where the spec or brief is silent or contradictory, and deliberate widenings toward fail-closed. Everything not listed here follows the code contract as written: `Redactor`, `NewRedactor`, `PathRule`, `Attr`, `URL`, `Path`, `String`, the four list functions with their verbatim contents, and `metrics.Options.Redactor`.

## Spec readings

| Topic | Reading |
|---|---|
| Invite rule and core's route | 05-logging §2 and §3 describe `RedactInvitePath` as matching "any `invite`/`invites` segment followed by another segment, at any position". At the base it does not. Its happy path is anchored to ABO's prefix table (`inviteTokenPrefixes()`), and the any-position check only feeds the fail-closed branch, so `/api/core/v1/auth/invites/<token>` passed through unchanged (probed at `52af3560e`). The brief requires the rule's `Fn` to be `RedactInvitePath` with no copied algorithm, and `TestRedact_CoreInvitePath` requires the core route redacted. The fix adds `{"api","core","v1","auth","invites"}` to `inviteTokenPrefixes()` in `core/log/redact_path.go`, with test rows. A generic any-position matcher was rejected because it would redact a dot-walked path positionally instead of failing closed to `/[REDACTED]`. `/books/invite/<x>` therefore stays unredacted, as at HEAD. Lead-approved. ABO's middlewares call the same function, so they now redact the core route too. |
| `DefaultRedactKeys()` stays verbatim | The brief's STOP condition forbids a default list that differs from 05-logging §3, so the security-review additions go into the matching rule and unexported lists instead (next table). |
| Deny-list matching | The spec says "case-insensitively after stripping `-`, `_`, `.`". It is read as whole-key equality on the normalised key. The redundancy in the list (`credential` and `credentials`, `token` and `accesstoken`) implies equality, not substring. The widenings in the next table are added on top. |
| Replacement text | `[REDACTED]` (05-logging §3, `TestRedact_TempLoginTokenQuery`), not HEAD's bare `REDACTED` (`middleware.RedactedValue`, unchanged). |
| `secrets.Value` | `core/secrets` does not exist in R1. `TestRedact_SecretsValue` uses a test type whose `LogValue` returns `[REDACTED]`, and a comment says the `secrets.Value` cell joins it at F3. |
| Counter name | 05-metrics §11's `mediacore_metrics_span_redactions_total` is `<namespace>_metrics_span_redactions_total{kind}`. The instrument is `<namespace>.metrics.span_redactions`, unit `{redaction}` (bracket units add no suffix). It is created on the meter `<namespace>.metrics`, the meter a `Core("metrics")` scope would use, through the family-checking `MeterProvider`, not through a `Scope`. That keeps the `core:metrics` scope key free for R1-15 (`otlp_export_failures_total`), and the instrument identity is the same whichever creates it first. |
| Counter only with tracing | It is created only when `Options.Tracing != nil`, so a Provider without tracing (ABO's metrics half) serves no new series, and `internal/telemetrypolicy`'s seeded golden is unchanged. ABO's tracing half has no meter reader (`Prometheus: false`), so in ABO the counter is recorded but not served until R1-15 merges the two Providers. |
| Wrap point | `newTracerProvider` takes the span redactor as a required parameter (nil is refused with the same error as `New`), and `sr.wrap(exp)` is the only exporter handed to `sdktrace.WithBatcher`. `New` refuses `Tracing != nil && Redactor == nil` before building anything. |

## Names beyond the spec

| Name | What it is |
|---|---|
| `log.RedactionKind` with `RedactKey`, `RedactURL`, `RedactPath`, `RedactValuer` and `String()` | A bit set of what a redaction replaced. The labels are the `kind` values of 05-logging §9 and 05-metrics §11. The span exporter needs it to label its counter, because `String` returns only a string. `Logging.Counters()` (R1-36) can use the same values. |
| `(*Redactor).StringKinds(key, value) (string, RedactionKind)` | `String` plus the kinds replaced, empty when the value is unchanged. `String` is `StringKinds` without the kinds. An already-redacted value (`[REDACTED]`) reports nothing. |
| `[REDACTED:depth]` | Replaces the part of a `KindAny` value beyond the walk bounds (depth 8, 4096 nodes). Counted as kind `valuer`. |
| `[REDACTED:panic]` also for an endless LogValuer | A LogValuer chain still unresolved after 100 calls (slog's own bound) fails closed with the panic text instead of slog's error value. A panicking `String`, `Error` or `MarshalText` on a `KindAny` value gives the same text. |
| `(*Redactor).KeyDenied(key string, kind slog.Kind) bool` | Whether the key rule replaces a value of that kind under that key whole: an exact deny-list match for any kind, a credential-suffix match for any kind but a scalar (bool, int, uint, float, duration, time). The span exporter needs it for the attribute types that have no text (BOOL, INT64, FLOAT64 and their slices, MAP, SLICE). `Attr` and the walk use the same rule. |
| Text cap, 64 KiB (`maxRedactTextBytes`, unexported) | `StringKinds`, `URL` and the text scan examine at most 64 KiB. Text beyond it is not examined and is replaced with `[REDACTED]`, counted as kind `key`. The scans are linear; the cap keeps the constant small for request and upstream text. |
| `[REDACTED]` for a LogValuer in an unexported field | The walk cannot call `LogValue` through an unexported field (reflect refuses), and the TextHandler would print its raw fields, so it fails closed, counted as kind `valuer`. |
| Span value depth 8 (`maxSpanValueDepth`, unexported) | MAP and SLICE attribute values nested deeper fail closed to `[REDACTED]`. |
| `errNoRedactor` (unexported) | The refusal error: `metrics: Options.Tracing is set but Options.Redactor is nil: spans would export credentials unredacted`. Not exported, because 05-metrics names no sentinel for it. |

## Widenings toward fail-closed (three security review passes and the independent review of #4436, lead-directed)

| Where | Behaviour |
|---|---|
| Key rule (`matchKey`, `KeyDenied`) | A key matches **exactly** when the normalised whole key, or its last dot-separated segment, is on the deny-list: `DefaultRedactKeys()`, the extra keys, and `builtinCredentialKeys()` (`proxyauthorization`, `xapikey`, `cfaccessjwtassertion`, `cfaccessclientsecret`, `bearer`: ABO's `credentialHeaders` in `internal/server/middleware/recovery_redact.go` and its `secretPairRE` names). It matches by **suffix** when it ends in a `credentialSuffixes()` entry (`token`, `tokens`, `secret`, `secrets`, `password`, `passwords`, `passwd`, `passphrase`, `apikey`, `secretkey`, `accesskey`, `authorization`, `cookie`, `cookies`, `privatekey`, `credential`, `credentials`, `sessionid`, `bearer`, `jwtassertion`, `jwt`) and not in a `harmlessSuffixes()` entry (`haspassword`, `hastoken`, `hassecret`, ...). An exact match replaces a value of any kind. A suffix-only match replaces any value except a scalar (bool, number, duration, time), so `prompt_tokens`, `cf_cookie_len` and the presence flags `cf_cookie`, `cf_authorization`, `cf_client_secret`, `query_token`, `is_secret` pass when logged as bools or numbers. The same key logged as a string is still replaced (`slog.String("is_secret", "false")` becomes `[REDACTED]`): text can carry a credential, and the rule does not guess. HTTP Digest's `response`, `nonce` and `cnonce` were global keys after the third pass. The independent review removed them, because they wiped every `response` attribute (`response="200 OK"`, a `Response` struct field). They are now redacted only inside a Digest credential, by the auth-scheme scan. A bare `key` suffix is not denied: ABO logs `cache_key`, `dedup_key` and similar. |
| Query names | A query or fragment parameter is replaced when its name (one percent-decoding, any case) is in `DefaultRedactQuery()` or is denied by the key rule (`client_secret`, `session_id`, `x-api-key`). |
| Separators | `&` and `;` both split a query. The fragment is masked like a query (`#token=`). |
| Nested URLs | Another parameter's value that holds a URL or path (`?next=/invite/<t>`, `?redirect_uri=https://...?token=`) gets URL handling, two levels deep. The value is first percent-decoded up to `maxDecodeRounds` (3) times while it changes, so `?next=%2Finvite%2F<t>` and the double-encoded `%252F` form are seen. A value that would still decode after the last round fails closed to `[REDACTED]`. An invalid escape is decoded leniently (`unescapeLenient`: the invalid escape stays as written) rather than skipping the value as opaque, because an opaque value would pass a path hidden behind one bad escape. An encoded value that needed any redaction is replaced whole with `[REDACTED]`. At the depth limit a value that still holds a URL or path fails closed to `[REDACTED]`. Text before a `<scheme>://` counts as a prefix only when it holds no `/`, `?` or `#`, so `/c?n=https://...` is a path whose query holds a URL. `maskQuery` splits segments with `strings.IndexAny`, which also clears CodeQL's `go/index-out-of-bounds`. |
| Userinfo with an unencoded `/`, `?` or `#` | When the authority (up to the first `/`, `?` or `#`) has no `@` but a port that is not all digits (`bruce:pa`, which no real host has), the password ended it early: everything up to the last `@` in the rest is userinfo and is removed. A valid numeric port is left alone. |
| Decoded `?` and `#` in a path | When the path before the first `?` or `#` is clean, the path rules run again over the whole remainder with those characters as path text, so a decoded `/invite/?<t>` or `/invite/#<t>` is still redacted. Any query left after that is still masked. |
| Text scan (any string not under a URL key) | (1) Each whitespace-separated token is checked for a URL or path. One starts at the token, at a `<scheme>://`, or at a `/` right after a quote, bracket, `=` or `:`, and the URL treatment goes from there. This covers a span name `GET /invite/<t>`, an error's `Get "https://...?token=..."`, `<url>`, `next=/path` and `"/path"`. A token with no URL that percent-decodes, up to `maxDecodeRounds` times, to a URL or path needing redaction is replaced whole (`%2Finvite%2F<t>` in an error message). (2) Pairs: one forward pass, linear in the input (`scanPairsN` counts its steps, and `TestRedact_PairScanIsLinear` holds it under 8 steps per byte at 1 MiB). Every `=` or `:` is a candidate. The name is found by stepping back over spaces, one quote (and a backslash before it) and name characters, so JSON `"name":"value"`, `\"name\":\"value\"` and `name = value` all count. Any whitespace may follow the separator, a newline included (YAML). The value is then read as follows. A quoted value runs to its matching unescaped quote. A bracketed or braced value runs to its matching closer, nesting counted, which covers `%v` of an `http.Header`, `url.Values` or `map[string][]string`. A name ending in `cookie`, `cookies` or `authorization` takes the rest of the line. Any other value runs to whitespace, a quote, or a closer that closes nothing it opened, so `,`, `&` and `;` tails stay inside it. An unterminated quote or bracket runs to the end of the line. Only a value starting with the literal `[REDACTED` is skipped, so redacting twice changes nothing. After whitespace, a plain first word that is itself a field name and a separator is read as the next pair (an empty `%+v` field). That reading never applies to a cookie list. (3) Auth schemes: `Bearer <credential>` is redacted anywhere. `Basic`, `Negotiate` and `Digest` are redacted only in header context: at the start of the text, after a quote or `[`, or after an `...Authorization` or `...Authenticate` name and `:` or `=`. They also need a credential-shaped value. For `Basic` and `Negotiate` that is a token68 of at least 8 characters that is not a plain word and ends at whitespace, `,`, `;`, a quote, a closer or the end. For `Digest` it is an auth-param (`username=`). The credential runs to the end of the line, or to the closing quote or `]` when the word follows an opening one. The scheme word stays. "Basic Economics: A Citizen's Guide", "How to Negotiate Anything", "digest rollup ..." and "failed to compute digest of ..." pass unchanged. Under a URL key, and under `url.query` after its parameters are masked, the text scan runs after the URL treatment. |
| `KindAny` values | The value is walked within the bounds above. At every level, in order: a nested `slog.LogValuer` is resolved (a panicking or endless one gives `[REDACTED:panic]`) and replaced by its value, because the handlers print a nested value's fields and never call `LogValue`; one behind an unexported field fails closed (above). `*url.URL` and `url.URL` get the URL treatment. A value with printing methods has every text a handler can print scanned: `AppendText`, `MarshalText`, a `Format`/`Error`/`String` result, `MarshalJSON`, and a marshal method's error text. The TextHandler prefers `AppendText` and then `MarshalText`; the JSONHandler prefers `MarshalJSON` even over `Error`. When any of those texts needs redaction, the value is replaced by the TextHandler's text, redacted, so no handler calls the method that would print another. An `error` or `TextMarshaler` stops there, because both handlers print it only through its methods. Any other value with methods (a `Stringer`, a `json.Marshaler` alone) also has its fields walked, because one of the handlers prints them. Pointers and interfaces are followed. Strings and `[]byte` get the text scan. Map entries (any key type, keyed by its printed form; `http.Header` and `url.Values` included) and struct fields go through the key rule. Exported fields are keyed by the json tag name and denied when either the json name or the Go name is denied. Unexported fields and `json:"-"` fields are walked under their Go name, because the TextHandler's `%+v` prints them (the third pass skipped `json:"-"` and only `%+v`-scanned unexported fields; both are fixed). Slices and arrays recurse. A non-zero value under a denied key becomes `[REDACTED]`, except a scalar under a suffix-only match; a zero value hides nothing and is kept. A changed value is replaced by the redacted text (a leaf) or by the rebuilt `map[string]any` or `[]any`, keeping unchanged branches as they were (an unexported one as its `%+v` text). When the walk changes nothing, the printed texts of the whole value (or `%+v` for a composite without methods) get the text scan, and a redacted text replaces the value. Cost: a `KindAny` attribute pays a reflection walk, and a value with printing methods pays one call per method (a `time.Time` field pays four). R1-36 may cache by type if that shows up. |
| Span exporter | Beyond the span name and URL-keyed attributes (05-metrics §3), every attribute value is redacted. STRING and STRINGSLICE values go through `StringKinds`. BYTESLICE is scanned as text. MAP values are recursed into under each entry's key, and SLICE values under the slice's key, to depth 8, then fail closed. BOOL, INT64, FLOAT64 and their slices follow `KeyDenied`. A MAP or SLICE under a denied key becomes `[REDACTED]`. An attribute type the exporter does not know fails closed to `[REDACTED]`. Event names, event and link attributes, and the status description get the same treatment, because they carry error text. A span with nothing to redact is passed on as the same value. |
| Path rules | A module `PathRule` whose `Fn` panics fails closed to `/[REDACTED]`. A rule with a nil `Fn` redacts nothing and is skipped at `NewRedactor`, which cannot return an error; kernel registration should refuse one (R1-36 / 06). |

## Gaps recorded

- Span resource attributes are not redacted. They come from configuration (service name, version, instance ID, environment), not from requests.
- In ABO the span redaction counter is not served until R1-15 (above).
- The text scan's remaining misses are filed in `todo.d/2026-11-07-core-redactor-review-followups.md`: XML element values, `--password <t>` argv, `?apikey[]=`, hash-router fragments (`#/cb?key=`), the node budget charged for primitive leaves, `normKey` allocations, the slog group recursion depth, the typed-nil error, and `Record.Message` (R1-36).
- **R1-18 must rename or allow** two ABO attribute keys that this Redactor replaces once R1-18 routes ABO's logging through it, because they are exact or string-valued credential matches. This row does not edit ABO call sites. (a) `internal/server/middleware/absauthprobe.go:116` logs `"bearer", bearerKind`: a label for which bearer form a request used, not a credential, but `bearer` is an exact deny-list key (ABO's own `secretPairRE` name), so the label becomes `[REDACTED]`. (b) `internal/server/absauth/audit.go:114` logs `"service_token", ...` as a string: the service-token identifier the audit trail pairs with the user. It ends in the `token` suffix, so it becomes `[REDACTED]`. R1-18 should rename both keys (for example `bearer_kind`, `service_token_id`) or add them to an explicit allow-list, after confirming the second is not a secret.
- The counter's identity (meter `<namespace>.metrics`, unit `{redaction}`, its description) is fixed here. R1-15's `otlp_export_failures_total` must use the same meter, and any later re-creation of this instrument, through a `Scope` or not, must pass identical options, or it is refused with `ErrFamilyTaken`.
