# R1-17 seams and coined names

This file lists what the perimeter PR added beyond 05-http-api §3, §4.2, §8.2 and the R1 row of §13: names the spec does not have, readings it took where the spec or the brief is silent, the risks it leaves, and the seams later rows (R1-18, R1-19, F3, F4) build on. Everything not listed here follows the spec as written: stages 0-7 and 9 around the router, stages 10 and 11 in each route wrapper, `TrustedPeer`, `ClientAddrFrom`, `RequestID(ctx)`, `LegacyMount.DefaultCSP`, `CSPReport` and `BuildID`, and `LegacyRoute.NoCompress`.

old ==> new: none. No package moved. `internal/httputil` stays in ABO (below).

## Names beyond the spec

| Name | What it is |
|---|---|
| `httpapi.Options.PeerAllowlist` | Stage 0's allow-list (`core.http.peer_allowlist`). §3.5's `Options` lists `TrustedProxies` but no allow-list field. |
| `httpapi.CORSOptions{AllowedOrigins}` | §3.5 names the type without fields. One field: `core.http.cors.allowed_origins`, which is also stage 7's trusted-origin list. |
| `httpapi.LimitOptions{RateLimitEnabled, RateLimitPerMinute, RateLimitBurst, RateLimitMaxClients, JSONMaxBytes, UploadMaxBytes}` | §3.5 names the type without fields. One field per §10 key. A zero number means core's default. |
| `httpapi.Deps.TracerProvider`, `Propagator`, `Redactor` | What stage 2 needs to record a server span, and what stages 2 and 4 need to redact the URL. The kernel fills them from the App's `metrics.Provider` and its one `log.Redactor`. |
| `(*httpapi.Router).SetPerimeter(o Options) error` | 05-config §1.12.1's "one pointer the kernel sets before step (7)". It replaces the perimeter fields after `Build`, and the next request sees them. The kernel calls it at start step 7 with the values `app.Options.R1Values` returned. |
| `kernel.R1Values.ClientIPHeader`, `app.R1Values.ClientIPHeader` | The header stage 0 believes from `TrustedProxies`. R1-15's `R1Values` carried the trusted proxies but not the header they set. ABO passes `CF-Connecting-IP`, the header HEAD's `client_trust.go` read. |
| `core/internal/httpmw` (layer 6) | Stage implementations: `Chain`, `Deps`, `Settings`, `State`, `Policy`, `RouteSpec`, `AccessMessage`. They are core-internal, so not public API. `Deps.PolicyOf func(*http.Request) *Policy` gives an answer written before routing (stage 6's preflight, stage 7's refusal, a stage 3 panic) the policy of the path's owner, so a books path gets `DefaultCSP` and `Reporting-Endpoints` even when the router never ran. `TestCSP_DefaultPerOwner` covers it. |
| `core/httpapi/perimeter` | `doc.go` and the stage-order golden (`TestChain_OrderGolden`). It has no exported names. |
| ABO `(*server.Server).LegacyPerimeter() (csp func(*http.Request) string, report, buildID string)` | What `books` hands `MountLegacy`: `contentSecurityPolicy`, `/api/v1/csp-report` and the build ID read from the embedded `index.html`. It is a new exported name, recorded as a deviation from the brief's code contract (which allows no new exported name outside §3 and §4.2). The alternative was exporting three package-level functions. |
| ABO `buildIDFromIndex`, `spaBuildID` (`csp.go`) | `setSPAInlineScripts` already parses the embedded `index.html`, so it also reads `<meta name="mediacore-build" content="...">` once. A missing tag gives `""`, and stage 5 then writes `dev`. |
| ABO `apiGroupHookForTest`, `chainHandlers` (`server_lifecycle.go`) | A test-only hook in production code. `TestLegacyManifest_MatchesGinRoutes` (through `rateLimitedRoutes`) needs the set of routes HEAD's `apiRateLimiter` covered (the gin `/api/v1` and `/api/v3` groups), and the limiter that used to mark them is gone. It is nil outside tests. |

## Readings and deviations

| Topic | Reading |
|---|---|
| One commit for every stage group | The brief asks for one commit per stage group. The stages share one `Chain`, one carrier (`State`) and one writer, and none of them builds alone. Part 1 adds all of them in core. Part 2 switches ABO over and deletes gin's chain. They squash to one commit before the PR, so the gin removal and the stages land together (§13 R1: "removed from gin in the same PR"). |
| `http_route` on a refusal | 09 §9.2.7 says a request refused by the rate or body limit carries no `http_route`. 05 §4.2 puts stages 10 and 11 in the route wrapper, after the mux matched, so the route is known. This follows 05: a 429 or 413 carries its route's pattern. A refusal of stages 0, 6 or 7, or an unrouted 404, carries none. The release note says so. |
| HSTS | 05 §4.2 sends it only over TLS or when a trusted proxy says https. HEAD believed `X-Forwarded-Proto: https` from any peer. This follows the spec. In production behind the tunnel, HSTS needs `TUNNEL_CONNECTOR_ADDRS` (Risks). |
| Body limits for the legacy mount | `MaxBody: -1` on the legacy mount, so stage 11 does not cap it. HEAD's gin groups set per-path limits (the 20 GB OpenLibrary import, the 8 MiB fingerprint-worker routes) and a 413 envelope that do not fit stage 11's two classes. gin's `bodyLimitMiddleware` stays until F3. |
| The Basic gate | It stays in gin (stage 8, until F3). The perimeter shim is reduced to the Basic gate on core's own unrouted answers (301, 404, 405) plus `Alt-Svc`. A Basic refusal there is logged and counted with core's status, not the shim's 401: stages 2 and 4 wrap the shim. On a routed request, gin's 401 is what stages 2 and 4 see. |
| 429 and 413 from core | They are not Basic-gated, because stages 10 and 11 run before the legacy handler. HEAD's limiter ran after the Basic gate. With Basic on, an unauthenticated flood now gets 429 instead of 401. |
| Peer refusals | 403 problem+json (`peer_refused`), where HEAD wrote plain text. The parity test records the body difference. |
| Spans | Named `METHOD route` (`GET /api/v1/audiobooks/{id}`), as otelgin named them with gin's pattern. Unrouted spans are named after the method alone. |
| `url.path` and the access log | Stage 2's `url.path` and stage 4's `path` go through `redactedPath`, which applies the Redactor's path rules and then its URL rules to the decoded path. A credential after a `?` sent as `%3F` (`/x/cover%3Ftoken=...`) is masked. HEAD's gin logger masked it (`RedactLogRequestPath`, now deleted as dead code). HEAD's otelgin `url.path` did not, so the span side fixes a leak HEAD had. `TestAccessLog_RedactsPathCredentials` and `TestStage2SpansCarryNoQueryCredentials` cover both. |
| `internal/httputil` | Not moved. 04 §8.2, 05 §8.4 and the code contract disagree on where it goes, and the code contract allows no new exported name. |
| CORS dev origins | HEAD allowed the Vite dev server's origin in gin debug mode. Core has no debug mode, and the dev server proxies `/api` (same-origin to the browser), so the rule is dropped. |
| Writers and flush errors | Every stage writer implements `FlushError`, so a handler's `http.ResponseController` flush gets the connection's error through the stages (before, the stages answered `nil`). `http.Flusher.Flush` has no result, so a failed flush is kept and returned by the next `Write`, the way net/http reports one. `TestFlush_ErrorCrossesTheStages` covers both, with and without gzip. |
| Refused peers | Stage 0 is outermost, so its 403 carries neither `X-App-Build` nor `X-Request-ID`. The spec's "every response" list (§4.2 stage 5) does not name it. The release note says so. |
| Core counters | `audiobook_organizer_http_{inflight_requests,panics,rate_limited,cross_origin_rejected,peer_refused}` are new families from core's `mediacore.http` scope. They are not in ABO's series golden, which covers ABO-owned families. The three `http_server_*` rows of that golden now name `httpapi` as their source. |
| Dashboards and rules | `git grep -n 'http_server_\|http_route' -- deploy/` finds nothing, so no dashboard or rule changed. |

## Risks

| Risk | Cost of the fix |
|---|---|
| HSTS and per-visitor rate limiting depend on `TUNNEL_CONNECTOR_ADDRS` in production. Without it, HSTS is no longer sent behind the tunnel (HEAD sent it on any `X-Forwarded-Proto: https`), and the `/api` limiter keys on the connector, as HEAD's did. | Set `TUNNEL_CONNECTOR_ADDRS` in `deploy/local.conf` before deploying. `deploy/local.conf.example` leaves it commented out, so check the live file. No code change. Cloudflare can also add HSTS at the edge. |
| `X-App-Build` is `dev` until R1-19 makes the npm build write the meta tag. | R1-19. Clients treat `dev` as unknown, never as a mismatch. |
| Access lines stay off the Activity feed only because stage 4 logs through core's `http` scope: `books.logTee`'s `scopedLine` (R1-15 review M2) sends every record with `module=` right after its message to stdout. | R1-18 replaces `logTee`. It must keep core's scoped records, `httpmw.AccessMessage` among them, out of the feed. |
| A setting saved through `PUT /api/v1/config` for the perimeter keys takes effect at the next restart. | F3 makes them hot-reloadable core keys. The release note says so. |

## Seams for later rows

- **R1-18 (logging stages):** `books.logTee` (in `internal/books/options.go`) keeps core's access records out of the Activity feed through `scopedLine`, because stage 4 logs through core's `http` scope (`module=core`). When you replace `logTee`, keep records whose message is `httpmw.AccessMessage` (`"http access"`) on stdout only. `TestLogTee_AccessLinesStayOffTheActivityFeed` sends a request through the composed App and pins this.
- **R1-19 (build identity):** `X-App-Build` reads `<meta name="mediacore-build" content="...">` from the embedded `index.html` through `buildIDFromIndex` in `internal/server/csp.go`. Generating the tag in the Vite build is all that is left. `TestBuildIDFromIndex` covers the parse.
- **F3 (config flip):** the Basic gate moves to stage 8 and the shim goes with it. gin's body limits become stage 11 classes, and `MaxBody: -1` on the legacy mount goes. `SetPerimeter` becomes the reload path for the perimeter keys. Delete `apiGroupHookForTest` once the manifest's `RateClass` is checked another way.
- **F4 (identity flip):** stages 12 and 13 run for the legacy mount. `client_trust.go` moves to core; its `trustedClientIP` already starts from `ClientAddrFrom`.

## Deployability

Deployable after R1-15 and R1-16, with `TUNNEL_CONNECTOR_ADDRS` set first (Risks). Rollback is a binary swap: no stored data changes.
