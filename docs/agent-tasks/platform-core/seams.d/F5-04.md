# F5-04 seams: dedup plugin definitions become books kinds, dark

29 of the brief's 32 definitions are native kinds. Three are not (below). Nothing registers the kinds before F5-18; HEAD's v2 definitions keep running over the same shared cores.

## Not converted (STOP items, owner or F5-18 to decide)

- `dedup.check-book`: it declares `Requires` and `Batchable`, and core's `tasks.Common` has no `Requires` field at this base. Converting it would drop the dependency gate. Needs a core change first.
- `dedup.split-book-scan` and `dedup.split-book-bulk-merge`: both write `split_book_candidate:` rows, a main-store key family (`internal/books/store/keyfamilies.go`). No `pkg/ops` resource names it, and filing it under `embeddings` would be a guess. Fix: add a resource constant (and list it in `taskResourceKinds()` in `internal/books/module.go`), or approve `ResEmbeddings`. Bulk-merge also writes books, book_files, authors, metadata_cache, indexes, external_ids and operations through `MergeSplitBookClusterRechecked`, which is wider than HEAD's declaration (books, book_files). Both need one narrow env method each over the wide `dedupengine.Store`; keep the bulk-merge item loop sequential.

## Shape

- `env.go` is the engine-neutral seam: `kindEnv` (Live, Logger, Progress, Log, Canceled, Items, SetResult, Reporter, Checkpoint, Restore) is filled by `headEnv` (HEAD's Reporter) or `nativeEnv` (the `tasks.RC`). It is the only non-test file besides the HEAD def files that imports `pkg/plugin/sdk`; the `kinds*.go` files do not.
- Each group has its deps struct in `kinds_<group>.go` (`ScoringKindDeps`, `EmbeddingKindDeps`, `LabelKindDeps`, `IndexKindDeps`, `ChainKindDeps`), aggregated by `KindDeps`; `(*Plugin).Kinds(deps, sched)` lists them. F5-18 wires the stores, the gated writers behind each `NewWriter` and the engine behind each `NewEngine`.
- A native Preview run is HEAD's dry run where HEAD has one. Where HEAD has none the native shell refuses Preview (`kindLiveOnly`). Mode keys (`dry_run`, `dryRun`, `apply`) in params are refused, never dropped.
- A def's HEAD `DefaultPriority` unset is `PriorityLow` (registry zero value), not Normal.

## Engine writes are the engine's (rule R10 gap)

Engine-backed kinds (scoring group, breakdown-backfill, embed-scan and others) call methods on the wide dedup engine, which writes candidates, labels and merges through its own stores, where tasklint cannot see them. The native shell builds the engine with `NewEngine(rc.Writer())`, so F5-18 must make those writes go through the run's gated writer. Effects were derived by tracing each engine method to `pkg/ops` resources (cited per kind in a comment). In Preview the engine kinds are handed a nil writer, so the dry run's no-write guarantee is the engine's own `apply=false`.

## Effects choices to review

- Dedup candidate and label rows live in the embedding keyspace and are declared as `ResEmbeddings`.
- `dedup.llm-review` also declares `ResEmbeddings` for its ai_jobs row write: no `ResAIJobs` constant exists. Precedent: `ResReviewItems` for the author dedup batch in `maintenance/dedup_ops.go`.
- `dedup.window-index-build` adds `ResSettings` to HEAD's declaration (the body writes the flag); its ConcurrencyKey is `books.dedup.window-index`.
- `dedup.run-all` and `dedup.label-refinement` are ReadOnly: a write set overlapping a child's would make the kernel refuse the wait as self-blocked.
- No `AlsoDeletes` anywhere (tasklint wants an owner review for each).

## Child waits

- `run-all` and `label-refinement` start children with `rc.Enqueue` and wait with `rc.Await` on native kinds (`books.dedup.*`, `books.acoustid.scan`). HEAD keeps `childop`. The live loop is two drivers over shared plan, step table, validation, preview and result type.
- `run-all` Resume is Continue (HEAD Restart, checkpoint read on restart); Timeout 24h is the kernel cap. The native run does not mirror the child's row progress onto the parent bar (progress is per step); HEAD does.
- Children start in an explicit mode: `run-all` Live with params `{}`; `label-refinement` Preview with params `{}`, so it stays report only (HEAD enqueued with empty params for the same effect). Native `rebuild-gold-labels` and `calibrate-composite` Preview must therefore stay HEAD's report-only default.
- The `Help` text of `run-all` still mentions `{"dry_run":false}` (verbatim from HEAD, rule R5); natively the mode is the start request's.
- `lsh-index-build` enqueues `books.acoustid.fingerprint-rescan` for books with no print and does not await it, as HEAD did. The child inherits the run's mode (Live).

## Parallelism

- Pools declared with `tasks.CPU()` where HEAD used `runtime.NumCPU()`; embed-scan keeps its routed pool as `Fixed(4, ...)`.
- Engine-internal pools (`Engine.FullScan`, `AutoResolveCertain`, signature scan) are outside this package's cores; the cores have no loop and no `Par` row. `AutoResolveCertain` merges sequentially (cap and soft-delete re-read), so no partition was added.
- Sequential loops kept, each with a reason comment, and worth a follow-up: ISBN index write tail (one Sync commit per book), purge-legacy-fp mark loop, rebuild-gold-labels diff and reinsert loop.
- Behaviour-neutral speedup on the v2 path: `collectCalibrationPairs` now fans out over a CPU pool (`collectCalibrationPairsVia`), results assembled in input order.
- Counter-style progress labels (candidate-status index, window-index, lsh) are HEAD-only; the native pool's label is pure.
