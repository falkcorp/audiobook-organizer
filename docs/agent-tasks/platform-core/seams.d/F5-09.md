# F5-09 seams and coined names

What the dark conversion of the 14 maintenance definitions of T6 group 4 added beyond the brief, the readings it took where the brief says nothing, and what F5-18 (the flip) must do with them. Everything not listed follows the brief as written.

## Names beyond the brief

| Name | Where | What it is |
|---|---|---|
| `t6g4Base` | `kinds_t6_g4.go` | The part of every per-definition env that does not vary. R2 lists `Log/Progress/Touch/SaveCheckpoint/LoadCheckpoint/Writer/Store/Each`; `Logger`, `SetItem`, `Canceled` and `OpID` were added because the bodies call `reporter.Logger()`, `SetCurrentItem`, `IsCanceled` and `registry.ReporterOpID`, and the helpers beneath them take an `sdk.Reporter` that HEAD's tests pin (R2 item 4). `Log` takes slog attributes, as `reporter.Log` does. |
| `t6g4Base.reporter(ctx)` | same | An `sdk.Reporter` over the env, for those helpers. It adds no behaviour; `TouchLiveness` and `OpID` make `registry.TouchLiveness` and `registry.ReporterOpID` reach the env. |
| `t6g4Base.Each`, `t6g4EachOpts`, `t6g4CPU` | same | The loop runner. HEAD's shell backs it with `registry.RunItems`, the native shell with `tasks.RunItems` (R4: n>1 is `tasks.Fixed(n)`, 0 or 1 is `Sequential`, `t6g4CPU` is `tasks.CPU()`). `CheckpointFn` is not carried: `registry.runItemsPar` never calls it. |
| `t6g4Store`, `t6g4Writer` | same | Small embedded groups (the repo's `interfacebloat` limit is 8 declared entries). `t6g4Store` also answers a few non-store reads the bodies make of the plugin deps: `RootDir`, `HasAIParsing`, `HasDedupEngine`, `FileProvenanceAvailable`, `HasOperationQueue`, `FileIntroWritesAvailable`, `DeferAggregatesAvailable`. Where HEAD resolved a capability with `database.AsCapability`, the writer resolves it lazily and is a no-op (`PutFileIntroStats`, `PutTranscribeStats`) or errors (`errT6G4StoreLacks`) where HEAD's body did. |
| `t6g4Deps{Store, NewWriter, Scan}` | same | `NewWriter(rc.Writer())` is what F5-18 wires to `internal/books/writer` (which does not exist yet). `Scan` is optional: nil means no scan stand-down for fs-regroup-xml. |
| `<kind>Kind` constants, `<id>NativeParams`, `<id>Result`, `<id>Env`, `run<Id>Core` | one set per file | R2. Each v2 `Run` is now a shell that resolves the store, decodes params and the mode, and calls the core. |
| `t6g4View` | same | The general read-write view a core hands to a helper that took one `database.Store` slice. `dedupeRowsView` and `fsRegroupView` are the narrower ones. |
| `...Via` helpers | `dedup_ops.go`, `file_intro_clear.go`, `duration_backfill_unknown_rows.go`, `fs_regroup_xml.go`, `dedupe_book_file_rows_crossfolder.go` | The existing helper keeps its signature as a wrapper; a `...Via` twin takes the seams (R10 item 3). |
| `var _ = (*Plugin).t6g4Kinds` | `kinds_t6_g4.go` | The tasklint registration root. F5-18 deletes it with the `Registrar.Tasks` call. |

## Readings the brief did not settle

- **`dry_run` is refused by the native shell** for every kind whose HEAD params carry `dry_run`/`dryRun`/`apply`: the mode comes from the start request (R2 item 3). The marker fields exist only so the run can refuse them with a named error.
- **Live-only writers** (ai-dedup-batch, extract-wav-clips) error with "preview not supported; start with mode live" when the mode is not live (R7).
- **Write sets were widened where HEAD left them undeclared** (R7 "Writes found"). file-intro-transcribe: HEAD's comment says declaring books/book_files would queue acoustid.backfill behind the whole multi-day run; the native kind declares `book_files` and `books` because the body writes them, and F5-14/F5-18 must decide the queueing consequence. intro-transcribe declares `books` (HEAD) plus `book_files` (timeout strikes). ident-index writes resource `books`.
- **file-intro-transcribe Timeout** is clamped from HEAD's 30 days to `tasks.MaxTimeout` (24h); the native kind is `ResumeContinue`, so a timeout at the cap continues where the run stopped.
- **duration-backfill** keeps HEAD's own producer/worker/collector goroutine pool for the book grain, so the native kind declares no loop parallelism for it; the unknown-rows grain runs on `Each`.
- **intro-transcribe** drops HEAD's `CheckpointFn` (never called at page concurrency 6). `LastBookID` stays a start param.
- **fs-regroup-xml** needs `fsRepairStore` and `merge.BookWriter`; `fsRegroupView` satisfies them with four stubs that refuse (`UpdateBook`, `DeleteBook`, `MoveBookFilesToBook`, `ReassignExternalIDs`) because the body reaches none of them live.
- **dedup-exact-triage** reaches its service through the store/writer seam (`DedupTriagePreview`, `DedupTriageApply`).
- **Dropped schedules**: ai-dedup-batch (`0 0 * * *`) and integrity-check (02:30) keep their schedule only on the v2 definition; the native kind takes `Schedule` from the hook (R9), owned by F5-14.
- **Commit trailer**: the session reminder names Claude Sonnet 5.5; the builder rules say Opus 5.5. The session reminder was followed.

## What F5-18 must do

1. Delete `var _ = (*Plugin).t6g4Kinds` in the change that passes `t6g4Kinds(...)` to `Registrar.Tasks`.
2. Wire `t6g4Deps.NewWriter` to `internal/books/writer`; every `t6g4Writer` method is one the cores call, and the capability-dependent ones (file-intro stats, transcribe stats, the whisper journal, fingerprint carry-over) must answer as HEAD's adapter does.
3. Register readiness component `books.memdb`.
4. Delete HEAD's v2 definitions and the `Run` shells with the engine.

## Not provable without the real tools

Nothing here runs ffmpeg, whisper, taglib or a real store. The tests run each native shell against recording fakes: they prove which methods a core calls and through which seam, not what the real writer does.
