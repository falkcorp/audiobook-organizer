# F5-09 seams and coined names

What the dark conversion of the 14 maintenance definitions of T6 group 4 added beyond the brief, the readings it took where the brief says nothing, and what F5-18 (the flip) must do with them. Everything not listed follows the brief as written.

## Readings the brief did not settle

- **`dry_run` is refused by the native shell** for every kind whose HEAD params carry `dry_run`/`dryRun`/`apply`: the mode comes from the start request (R2 item 3). The marker fields exist only so the run can refuse them with a named error.
- **Live-only writers** (ai-dedup-batch, extract-wav-clips) error with "preview not supported; start with mode live" when the mode is not live (R7).
- **Effects use only `pkg/ops` constants** (coordinator ruling): `t6g4Res` takes `ops.Resource`, so a coined name does not compile. Stores with no constant are mapped to the nearest one or left undeclared, and each is a review decision: ai-dedup-batch's `ai_jobs` row is declared `review_items` (`operations` is the undo journal only); the file-provenance ledger is declared `book_files` (the export also declares `files` for its JSONL); a dedup candidate row lives in the embedding store, so dedup-exact-triage declares `embeddings`. Left undeclared: `stats:transcribe`, `stats:transcribe-files` and the whisper result journal. The coordinator adds `ops.ResAIJournal` (`ai_journal`, from F5-06) to the kinds that write the journal (transcribe-book-intros, transcribe-file-intros) when the rows stack; this branch cannot reference it.
- **HEAD fields dropped per kind**: schedules (below); `CheckpointFn` on intro-transcribe; HEAD's `DependsOn` becomes `NotWhile` (R5; only dedupe-book-file-rows has one, and a `library.scan` dependency adds the scan-full companion).
- **Write sets were widened where HEAD left them undeclared** (R7 "Writes found"). file-intro-transcribe: HEAD's comment says declaring books/book_files would queue acoustid.backfill behind the whole multi-day run; the native kind declares `book_files` and `books` because the body writes them, and F5-14/F5-18 must decide the queueing consequence. intro-transcribe declares `books` (HEAD) plus `book_files` (timeout strikes). ident-index declares `books` (HEAD) plus `indexes` (the ident: rows). dedupe-book-file-rows adds `books`, `fingerprint_index` and `operations`; fs-regroup-xml adds `external_ids` and `operations`; duration-backfill adds `books`.
- **file-intro-transcribe Timeout** is clamped from HEAD's 30 days to `tasks.MaxTimeout` (24h). HEAD never checkpoints this op, so its restart is a run from zero. The native kind is `ResumeContinue` because it yields (below), not because HEAD checkpoints: that is a deliberate deviation, and the conformance table records it as `yieldsNatively`.
- **file-intro-transcribe yields before its deadline** (review M4). No core hook was added: the native shell reads the run context's deadline, and once less than `fileIntroYieldMargin` (5 minutes) is left it stops starting batches, checkpoints a cursor (run id, batches done, the last group of the completed prefix, the run's counters), resets the bar to the exact prefix and returns `tasks.ErrContinueInPlace`. The next attempt reuses the run id and counters, reports from the batches already done, and (only for a forced `only_missing=false` run) skips the completed prefix by key. The margin is best effort: HEAD gives a batch no item timeout, a whisper outage retry can wait about 10 minutes and a scan-busy pause is unbounded, so a batch already running can outlive it; the run context then ends and the executor's timeout and resume path takes over, as before. The check applies only after one batch has completed in the attempt (the executor's progress proof).
- **duration-backfill book pool** is a seam (review MINOR 12): HEAD runs `Workers` goroutines, the native shell declares the loop `Fixed(workers)` so the operator's `parallelism_cap` applies. The loop's own progress is parked at the end of the bar (`ProgressBase = total`, `ProgressTotal = total + workers`) so the per-worker items do not move the book count. A worker that panics ends the run with an error instead of hanging it (the producer selects on the pool's context). The unknown-rows grain runs on `Each`.
- **capture and export Timeout** are 120 minutes, stated explicitly (review MINOR 13); HEAD declares none.
- **Help text** of most kinds is reworded beyond the mode-key sentence the brief required, where HEAD's Description names a param the native shell refuses; the conformance test derives which kinds from HEAD's text.
- **intro-transcribe** drops HEAD's `CheckpointFn` (never called at page concurrency 6). `LastBookID` stays a start param.
- **fs-regroup-xml** needs `fsRepairStore` and `merge.BookWriter`; `t6g4FSRegroupView` satisfies them with four stubs that refuse (`UpdateBook`, `DeleteBook`, `MoveBookFilesToBook`, `ReassignExternalIDs`) because the body reaches none of them live.
- **dedup-exact-triage** reaches its service through the store/writer seam (`DedupTriagePreview`, `DedupTriageApply`).
- **Mode-key refusal and live-only writers**: every native writing shell refuses `dry_run`, `dryRun` and `apply` (case-insensitive) by name, and fs-regroup refuses a live apply when `deps.Scan` is nil. A native shell with its own checkpoint (ai-dedup-batch, file-intro-transcribe) restores HEAD-shaped bytes where HEAD wrote any.
- **Removed F5-18 exemptions**: two `tasklint_exempt` lines that this row no longer needs were removed with the owner's approval (commit 4ff960801).
- **Dropped schedules**: ai-dedup-batch (`0 0 * * *`) and integrity-check (02:30) keep their schedule only on the v2 definition; the native kind takes `Schedule` from the hook (R9), owned by F5-14.
- **Commit trailer**: the session reminder names Claude Sonnet 5.5; the builder rules say Opus 5.5. The session reminder was followed.

## What F5-18 must do

1. Delete `var _ = t6g4Kinds` in the change that passes `t6g4Kinds(...)` to `Registrar.Tasks`.
2. Wire `t6g4Deps.NewWriter` to `internal/books/writer`; every `t6g4Writer` method is one the cores call, and the capability-dependent ones (file-intro stats, transcribe stats, the whisper journal, fingerprint carry-over) must answer as HEAD's adapter does.
3. Register readiness component `books.memdb`.
4. Delete HEAD's v2 definitions and the `Run` shells with the engine.
5. Delete this row's `scripts/deadcode-baseline.txt` lines (23: the `Kind` constructors, `t6g4Kinds`, `t6g4NativeBase`, `t6g4Par`, `t6g4Res`, `t6g4RunEach`, `t6g4RefuseModeKeys`, `t6g4RequireLive`, `t6g4StartRequirement` and `durationPoolOn`); they are reachable once `Registrar.Tasks` registers the kinds, and the ratchet then reports them as no longer unreachable.

## Not provable without the real tools

Nothing here runs ffmpeg, whisper, taglib or a real store. The tests run each native shell against recording fakes: they prove which methods a core calls and through which seam, not what the real writer does.
