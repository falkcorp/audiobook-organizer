# F7-09 T2 seams and coined names: the SMTP dial guard

This file lists what the F7-09 T2 PR (TODO-F7-05-SMTP-DIAL-GUARD, a hard precondition of the F7-09 flip) added beyond the brief, the readings it took, and what F7-09 must do. The change is core-only and dark: nothing constructs a `notify.Service` or registers `core.email` in this application yet, so no running code path changes.

## What it is

| Name | Where | What it does |
|---|---|---|
| `integrations.GuardedDialer` | `core/integrations/dial.go` | An optional capability of a `Gate`: `DialContext(ctx, network, addr) (net.Conn, error)`. It is not a method of `Gate` (the interface has fakes everywhere and an HTTP-only adapter never dials). |
| `integrations.GuardedDial(g Gate, ref Ref)` | same | The dial an adapter hands its connection code: `g`'s `GuardedDialer`, or, when `g` offers none (nil included), a dial that refuses with a `ClassRefusedLocal` `*Error` wrapping `integrations.ErrNoEgressGuard`. There is no unguarded fallback. |
| `integrations.ErrNoEgressGuard` | same | The cause of every "nothing can guard this connection" refusal: a gate with no guarded dial, no gate, a Registry with no outbound layer (`noGate`, with `errNoOutbound` as the reason), and a sender given no dial. `errors.Is(err, ErrNoEgressGuard)` holds for each. |
| `guardedGate.DialContext`, `noGate.DialContext` | same file | The Registry's own gate wrappers (they wrap every gate in `Registry.env`) forward the dial, with the `core.integrations.disabled` check first, or refuse. Without this a type assertion on `Env.Gate` would silently find nothing. |
| `(*providerhttp.gate).DialContext` | `core/integrations/providerhttp/egress_dial.go` | Chooses the guard exactly as `transport.pick` does for an HTTP request (the private-capable guard only when `g.private(host:port)` holds, that is the instance's `Trust` or `lan_allow`; the public-only guard otherwise and always for `EgressPublicOnly`), then calls that transport's own `DialContext`. There is no second policy engine. A guard refusal is returned as the same `*integrations.Error` an HTTP request gets (`ClassRefusedLocal`, `ReasonEgress`, cause `ErrBlockedAddress`), with the `egress` refusal metric. |
| `mail.SMTPConfig.Dial`, `mail.DialFunc` | `core/integrations/notify/mail/mail.go` | The connection function of the sender, the only place it touches the network. **nil refuses** (`ErrNoEgressGuard`, before any connection): there is no unguarded default. |
| `mail.PlainDial` | same | The explicit unguarded dial, a plain `net.Dialer`. Only for a sender whose host an operator alone can set. Its one caller is the invite flow's relay (`internal/server/invite_guest_access.go`), so production behaviour is unchanged. |
| `mail.SenderFactory`, `mail.NewChannel(ref, gate, mk, to)` | `core/integrations/notify/mail/email.go` | `NewChannel` no longer takes a pre-built `Sender` (its dial was discarded, so an "email instance" around a plain-dial sender had no guard). It takes a factory that is handed the instance's guarded dial on every send, and a sender that opens connections must use it as its `Dial`. |
| `endpoint()` default for `smtp` | `core/integrations/providerhttp/transport.go` | An `smtp://host:` origin (the origin of a host-and-port instance whose port is unset, `fields.go` `hostPortOrigin`) now normalises to `host:587`, the port the sender dials for `Port == 0`. Before, it normalised to `host:80`, so a Local instance with no port set would have been refused. |

## What the guard enforces

The guard is `providerhttp.Dialer.DialContext` (`egress.go`), unchanged. It resolves the host once, refuses the whole dial when any answer is blocked, and dials the literal address it checked, so there is no second lookup after the check (the DNS-rebinding window of resolve-then-dial-by-name stays shut: `egress.go`, the `ips` loop then `d.dial(ctx, network, net.JoinHostPort(ip.String(), port))`).

- Refused unless the instance is trusted: loopback, RFC 1918, RFC 4193 (unique local), CGNAT, the unspecified addresses, and (always) link-local, multicast, the reserved, benchmarking, NAT64, 6to4 and the IPv6 documentation range (`2001:db8::/32`; the IPv4 TEST-NET ranges are admitted on purpose, and the tests use them as public stand-ins). A single blocked answer among several refuses the dial; so does an empty answer.
- Admitted for private space: only the destination the instance's `Local` was granted for (`smtp://host:port`, an unset port standing for 587), or an entry of `core.integrations.egress.lan_allow`. Never the metadata endpoints (`169.254.169.254`, `100.100.100.200`, `fd00:ec2::254`), whatever the trust.
- Fails closed: a resolver error is returned and nothing is dialled; a malformed address (no host or no port) is refused before a lookup; a done context or the global disabled switch stops the dial before a lookup.
- The refusal names neither the host nor the address (the guard logs them at Debug). `channel.Send` returns the guard's own `*integrations.Error` rather than rebuilding one from the sender's text, which carries the host and port. A refusal is a local verdict on the destination, so it feeds neither the breaker nor a hold (`CountsAgainstRemote` is false for it), and `notify`'s delivery treats it as one a person must fix (`refusalWait` says no wait lifts it: permanent). The `Ticket` that `Acquire` returned gives back the bucket token it took when `Done` is given that refusal, as a refused HTTP attempt does (the refund belongs to the reservation, inside the ticket's once: a dial with no `Acquire` returns nothing, and several dials under one `Acquire` return at most its one token); the daily quota is not refunded (`Acquire` keeps no counter, and `core.email` declares no quota), a departure from HTTP that matters only to an adapter that declares one.

## What F7-09 must do

1. Pass `Outbound: providerhttp.Registry.Outbound` to `integrations.New` (its gates implement `GuardedDialer`), with `providerhttp.Options.LANAllow` reading `core.integrations.egress.lan_allow`.
2. Register `mail.Descriptor()` for `core.email`.
3. **The R2 invite sender must be built through the guarded dial of the `notify/email` instance, never through `PlainDial`.** Today the invite flow's host is `smtp_host`, which is environment-only (an operator sets it; `PUT /api/v1/config` refuses it by name), so `internal/server/invite_guest_access.go` passes `mail.PlainDial` and says why. From R2 the kernel builds that sender from the effective `notify/email` settings (05-notify section 10, 05-authn 4.13), and that host is an instance field a `core:integrations.manage` holder who is not an admin can set (only `Local` needs admin). A sender that keeps `PlainDial` there is an unguarded SMTP dial aimed by a non-admin. The PR that moves the host must, in the same change, do one of:
   - set `SMTPConfig.Dial` to `integrations.GuardedDial(env.Gate, ref)` from the leased instance's `Env`;
   - send through the leased `core.email` Notifier; or
   - build the channel with `mail.NewChannel(ref, gate, factory, to)` and a factory that passes the dial it is handed into `SMTPConfig.Dial`.

   A sender with no `Dial` refuses (`ErrNoEgressGuard`), so forgetting a dial fails closed; the one way to get this wrong is to write `PlainDial` beside a host that is no longer operator-sourced, and the comment at the call site names this note. This is also filed as `TODO-F7-09-INVITE-SENDER-GUARD` with its acceptance test (an invite send to a host that resolves to a private address, with no `Local` and no `lan_allow`, refused before any connection). An operator-sourced destination is trusted without `Local` (`effective.go`, `opDest`), so the operator's loopback relay still works through the guarded dial.

It must not wrap the gate `Outbound` returns in a type that hides `DialContext` (a wrapper that does refuses every send, by design, with `ErrNoEgressGuard`; the Registry's own wrapper forwards). A Registry built with no `Outbound` refuses every email send at `Acquire`.

## Left unguarded on purpose

- A direct caller of `mail.NewSMTPSender` that passes `PlainDial` (today only the invite flow, see obligation 3) dials its host as written. `coretest.MailRecorder` is a `Sender` that never dials and goes through `NewChannel`'s factory, ignoring the dial it is handed.
- The SMTP port is not restricted. The guard judges addresses, as it does for HTTP; a port allow-list is a policy decision nobody has made.
