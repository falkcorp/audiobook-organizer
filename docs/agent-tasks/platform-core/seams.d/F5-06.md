# F5-06 seams and coined names

F5-06 converts the 14 T6 group 1 maintenance definitions to native `books.<ID>` kinds (`internal/plugins/maintenance/kinds_t6_g1.go`). They are dark: nothing registers them before the tasks flip (F5-18). This file lists the readings the row took where the brief is silent, the helpers it re-signed, and what later rows build on.

## Seams

- `t6g1Deps` is wider than the brief's two fields. Besides `Store` and `NewWriter` it carries the services the bodies reach: `NewMetadataFetcher` and `NewTranscriptionRunners` (both built over the run's gated writer, so a fetch or apply write does not go around it), `ManualOnly`, `ActivityFilter`, `PlanReader`, the `Invalidate*Cache` hooks, `AIJournalRetentionDays` and `StandDownKey`. F5-18 fills them.
- `StandDownKey` empty refuses a live apply that needs the stand-down. A native apply never runs without the lease; F5-18 sets the key of the library scan kinds. The native stand-down `Lost()` reports false: a lost lease is caught by the writer fence, which fails the next write.
- Composite author-merge writes (`MoveCredits`, `MergeDeleteAuthor`, `RenameAuthorJournaled`, `JournalStep`) are one gated write each. The undo ledger rows they journal commit with the change, as at HEAD.
- Coined write-set resource names: `aux_stores` (the AI journal and the authority lists) and `operations` (the activity filter state and the undo ledger). The write set of a kind that drives a service (resolve-production, auto-match-transcribed) is the service's upper bound: books, authors, operations, plus series for resolve-production.
- Native params drop `dry_run` and `apply`: the run's mode carries them (Preview reports, Live applies). A Live-only kind (activity filter backfill, prune AI journal) refuses Preview with `<kind>: preview not supported; start with mode live`.
- Native checkpointing (activity filter backfill, auto-match-transcribed) restores only the fields of HEAD's params the body needs, through `rc.Restore` and `rc.Checkpoint`.
- Schedules are not carried: split-scan's HEAD cron (`0 2 * * 1`) comes from the `sched` hook the flip passes.
- Reporting differs from the v2 shell: the native progress is `ProgressBase` and `ProgressTotal` through `rc.Progress()`, and the label is pure label.
- `author-purge-empty` aborts on `ErrFenced` rather than counting it as a failed delete.

## Deviations

- Re-signed internal helpers (no test or other file called them): `ingestLibraryExport`, `ingestCatalogRaw`, `logUndecodable`, `logAuthorityReport`, `authorityProgress`, `authorityRefusals`, `runActivityFilterIndexReconcile` (now `...Core`), `activityFilterIndexProgressTo`, `previewAuthorSplit`, `authorIDRepairDangling`, `authorIDRepairDuplicates`, `authorIDRepairCanonical`, `authorPathLinkBuildIndex`, `authorPathLinkScope`, `authorPathLinkApplyOne`, `isRealAuthor`. The brief says only add; these were the narrowest way to route every write through the env writer. Helpers with callers (`mergeAuthorInto`, `authorIDMergeOne`, `unlinkAndDeleteAuthor`, `newAuthorPathLinkCreator`, `authorPathLink`, `authorIDRepair`) keep their signatures as thin wrappers.
- `author_strip_merge_relink.go` is untouched: `t6g1RelinkStore` routes its three writes through the gated writer.
