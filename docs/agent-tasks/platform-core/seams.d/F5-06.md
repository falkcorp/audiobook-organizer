# F5-06 seams and coined names

F5-06 converts the 14 T6 group 1 maintenance definitions to native `books.<ID>` kinds (`internal/plugins/maintenance/kinds_t6_g1.go`). They are dark: nothing registers them before the tasks flip (F5-18). This file lists the readings the row took where the brief is silent, the helpers it re-signed, and what later rows build on.

## Seams

- `t6g1Deps` is wider than the brief's two fields. Its `Stores` and `NewWriters` are structs of one narrow store/writer group per kind (no aggregate interface exists, so the interface-width ratchet holds). Beyond them it carries the services the bodies reach: `NewMetadataFetcher` and `NewTranscriptionRunners` (both built over the run's gated writer, so a fetch or apply write does not go around it), `ManualOnly`, `ActivityFilter`, `PlanReader`, the `Invalidate*Cache` hooks, `AIJournalRetentionDays` and `StandDownKey`. F5-18 fills them.
- Unwired hooks refuse, they do not panic. A Live run whose `InvalidateDedupCache` (all six cache-hook kinds) or `InvalidateAuthorsCache` (conjunction, duplicate-merge, id-repair, path-link) is nil is refused before the first write (`t6g1RefuseUnwired`, `cacheWires`); a Preview run never calls them. `prune-ai-journal` refuses when `AIJournalRetentionDays` is nil. F5-18 must set every hook.
- `StandDownKey` empty refuses a live apply that needs the stand-down. A native apply never runs without the lease; F5-18 sets the key of the library scan kinds. The native stand-down `Lost()` reports false: a lost lease is caught by the writer fence, which fails the next write.
- Composite author-merge writes (`MoveCredits`, `MergeDeleteAuthor`, `RenameAuthorJournaled`, `JournalStep`) are one gated write each. The undo ledger rows they journal commit with the change, as at HEAD.
- Coined write-set resource names: `aux_stores` (the AI journal and the authority lists) and `operations` (the activity filter state and the undo ledger). The write sets of the two kinds that drive a service are traced, not guessed. `auto-match-transcribed` ends in metafetch's `ApplyMetadataCandidateWithOptions`, so it declares books and authors (the book row and credits, a new author row when the name is new), book_files (segment titles), operations and aux_stores (the change record and the fetched-metadata state) and books again for the shared-hash duplicate flag. `resolve-production-authors` is the same fetch plus series. The two read-only reports keep `ReadOnly(Res(authors))`: they read the author table and nothing else, and an empty read set would let the executor schedule them against an author rewrite.
- Native params drop `dry_run` and `apply`: the run's mode carries them (Preview reports, Live applies). A native writing kind does not drop them silently, it refuses them: every one of the 12 writing params types (and the two split/resolve empty types) decodes through `t6g1RefuseModeKeys`, which rejects `dry_run`, `dryRun` and (for activity, prune, purge and strip) `apply` in any case, because `tasks` decodes native params with plain `json.Unmarshal` and a dropped `{"dry_run":true}` would turn a dry-run start into a live write. A Live-only kind (activity filter backfill, prune AI journal) refuses Preview with `<kind>: preview not supported; start with mode live`.
- Native parallelism is the kind's declared `tasks.Parallelism`, never a resolved NumCPU wrapped in `Fixed` and never a clamp of a non-positive count. `t6g1NativeItems` takes the declared value and ignores `t6g1ItemsOptions.Concurrency`, which only HEAD's pool reads. activity backfill: `Fixed(workers)` when the param is set, else CPU; authority-build: `Fixed(min(n, 32))` when the param is set, else CPU; id-repair and path-link: CPU; split: `Fixed(4)`; resolve: `Fixed(workers)`; auto-match: `Fixed(1)`. The kinds with no pool declare none (their HEAD loops were sequential on purpose).
- Native checkpointing (activity filter backfill, auto-match-transcribed) keeps HEAD's checkpoint struct (it carries more than a position) and stores it through `rc.Checkpoint`/`rc.Restore`; the pool tracks HEAD's contiguous watermark itself. The restore reads the bytes HEAD wrote (`activityFilterIndexBackfillParams`, `autoMatchTranscribedParams`). auto-match's per-item checkpoint is HEAD's sequential `CheckpointFn` (restored on `t6g1ItemsOptions`), not the watermark state.
- Every non-checkpointing kind maps HEAD's `ResumeRestart` to `ResumeFromZero` and `ResumeRequeue` to `ResumeFromZero`: with no checkpoint, a restart is a start from the beginning.
- Schedules are not carried: split-scan's HEAD cron (`0 2 * * 1`) comes from the `sched` hook the flip passes.
- Reporting differs from the v2 shell: the native progress is `ProgressBase` and `ProgressTotal` through `rc.Progress()`, and the label is pure label. `prune-ai-journal` stores its result through `env.StoreResult` in the HEAD shell, as before; the native result is the task result.
- `author-purge-empty` aborts on `ErrFenced`, from the delete and from the journal row before it, rather than counting it as a failed delete.

## Deviations

- Re-signed internal helpers (no test or other file called them): `ingestLibraryExport`, `ingestCatalogRaw`, `logUndecodable`, `logAuthorityReport`, `authorityProgress`, `authorityRefusals`, `runActivityFilterIndexReconcile` (now `...Core`), `activityFilterIndexProgressTo`, `previewAuthorSplit`, `authorIDRepairDangling`, `authorIDRepairDuplicates`, `authorIDRepairCanonical`, `authorPathLinkBuildIndex`, `authorPathLinkScope`, `authorPathLinkApplyOne`, `isRealAuthor`. The brief says only add; these were the narrowest way to route every write through the env writer. `authorPathLink`, `authorIDRepair` and the HEAD shells keep their signatures.
- Deleted as dead after the re-signs (staticcheck U1000 flagged them; nothing called them, tests included): `authorPathLinkStore`, `authorPathLinkAuthorStore`, `authorPathLinkBookStore`, `newAuthorPathLinkCreator`, `authorityExportItem`. The brief says never delete; keeping them fails the package's staticcheck gate.
- Deleted as test-only HEAD wrappers, with their tests retargeted to the `*Via`/`*Core` functions they wrapped (coordinator decision, the wrapper was kept alive for tests only): `mergeAuthorInto`, `authorIDMergeOne`, `unlinkAndDeleteAuthor` and `buildAuthorityLists`, and seven `*Parallelism` functions no native kind uses (prune, conjunction, duplicate-merge, purge-empty, strip-merge, title-fragment, whitespace). Their doc comments moved onto the `*Via` functions.
- `author_strip_merge_relink.go` is untouched: `t6g1RelinkStore` routes its three writes through the gated writer.
- Test-only identifiers renamed to carry the `t6g1` prefix (`gateWriter`, `authorityKV`, `errReconcileWithForce` became `t6g1GateWriter`, `t6g1AuthorityKV`, `errT6g1ReconcileWithForce`).
- Three extra test files beyond the brief's list: `export_t6g1_test.go`, `kinds_t6_g1_drift_test.go` (external package `maintenance_test`, because `internal/books` imports this package and an in-package test cannot import it back; it reads `tasks.CommonOf(d).Perms.Start` for every kind and asserts `Kind() == rbac.KindAllOf`) and `kinds_t6_g1_live_test.go` (a live run per writing kind through a counting writer over a real store, the two HEAD-checkpoint restores, the mode-key and unwired-hook refusals, the fenced purge journal and the pool's actual parallelism). The drift test is named outside the `TestT6G1Kinds_` prefix so that prefix still counts exactly the in-package tests.
- `scripts/deadcode-baseline.txt` gains `internal/plugins/maintenance` identifiers for the dark kinds (the 14 native shells, their parallelism functions, the `t6g1*` plumbing and the `UnmarshalJSON` methods and params types of the native shells), the F5-02 precedent for dark code. The exact count is the diff of that file against main in this PR. F5-18 deletes the identifiers it makes reachable or removes; the bot prunes the rest.

## Follow-ups

- F5-18 removes the HEAD v2 shells and the `t6g1Head*` adapters.
- The wiring that builds `t6g1Deps` from the server (F5-18) is not proven here; the tests use real stores and fakes.
