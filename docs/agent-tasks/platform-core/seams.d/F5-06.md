# F5-06 seams and coined names

F5-06 converts the 14 T6 group 1 maintenance definitions to native `books.<ID>` kinds (`internal/plugins/maintenance/kinds_t6_g1.go`). They are dark: nothing registers them before the tasks flip (F5-18). This file lists the readings the row took where the brief is silent, the helpers it re-signed, and what later rows build on.

## Seams

- `t6g1Deps` is wider than the brief's two fields. Its `Stores` and `NewWriters` are structs of one narrow store/writer group per kind (no aggregate interface exists, so the interface-width ratchet holds). Beyond them it carries the services the bodies reach: `NewMetadataFetcher` and `NewTranscriptionRunners` (both built over the run's gated writer, so a fetch or apply write does not go around it), `ManualOnly`, `ActivityFilter`, `PlanReader`, the `Invalidate*Cache` hooks, `AIJournalRetentionDays` and `StandDownKey`. F5-18 fills them.
- Unwired hooks refuse, they do not panic. A Live run whose `InvalidateDedupCache` (all six cache-hook kinds) or `InvalidateAuthorsCache` (conjunction, duplicate-merge, id-repair, path-link) is nil is refused before the first write (`t6g1RefuseUnwired`, `cacheWires`); a Preview run never calls them. `prune-ai-journal` refuses when `AIJournalRetentionDays` is nil. F5-18 must set every hook.
- `StandDownKey` empty refuses a live apply that needs the stand-down. A native apply never runs without the lease; F5-18 sets the key of the library scan kinds. The native stand-down `Lost()` reports false: a lost lease is caught by the writer fence, which fails the next write.
- Composite author-merge writes (`MoveCredits`, `MergeDeleteAuthor`, `RenameAuthorJournaled`, `JournalStep`) are one gated write each. The undo ledger rows they journal commit with the change, as at HEAD.
- Write-set resource names are the `pkg/ops/effects.go` constants only; no catch-all. The earlier `aux_stores` name is gone. The mapping: activity-filter-index-backfill writes the Pebble activity store, so `activity` (it was `operations`, which is the undo journal only); prune-ai-journal writes the `aijournal:` keys, so the new `ai_journal`; authority-build writes the `ref_*` keys, so the new `authority_lists`; auto-match-transcribed and resolve-production-authors write through metafetch's apply and declare `metadata_cache` (the candidate cache and fetched-metadata rows) and `field_states` (the per-field state snapshot) in place of `aux_stores`, plus `operations` for the metadata change record. No existing constant describes the AI journal (it is not the undo journal) or the authority lists (not `catalog`, which is the author catalog, `cat:*`), so this row adds `ResAIJournal` and `ResAuthorityLists` to `pkg/ops/effects.go` with doc comments; the owner reviews them in the PR body. The write sets of the two kinds that drive a service are traced, not guessed: `auto-match-transcribed` declares books and authors (the book row and credits, a new author row when the name is new), book_files (segment titles), operations, metadata_cache and field_states, and books again for the shared-hash duplicate flag; `resolve-production-authors` is the same fetch plus series. The two read-only reports keep `ReadOnly(Res(authors))`: they read the author table and nothing else, and an empty read set would let the executor schedule them against an author rewrite. F5-18 must declare `ai_journal` and `authority_lists` in `r.Resources(...)` (its brief lists `aux_stores`, which no kind uses now) and tag the activity-index writes `activity`.
- Native params drop `dry_run` and `apply`: the run's mode carries them (Preview reports, Live applies). A native writing kind does not drop them silently, it refuses them: all 12 writing params types (split and resolve, which carry no fields, included) decode through `t6g1RefuseModeKeys`, which rejects `dry_run`, `dryRun` and `apply` in any case from the one list `t6g1ModeKeys`, because `tasks` decodes native params with plain `json.Unmarshal` and a dropped `{"dry_run":true}` or `{"apply":false}` would turn a dry-run start into a live write. There is no per-kind exception: none of the 12 has a native param by those names. A Live-only kind (activity filter backfill, prune AI journal) refuses Preview with `<kind>: preview not supported; start with mode live`.
- Native parallelism is the kind's declared `tasks.Parallelism`, never a resolved NumCPU wrapped in `Fixed` and never a clamp of a non-positive count. `t6g1NativeItems` takes the declared value and ignores `t6g1ItemsOptions.Concurrency`, which only HEAD's pool reads. activity backfill: `Fixed(workers)` when the param is set, else CPU; authority-build: `Fixed(min(n, 32))` when the param is set, else CPU; id-repair and path-link: CPU; split: `Fixed(4)`; resolve: `Fixed(workers)`; auto-match: `Fixed(1)`. The kinds with no pool declare none (their HEAD loops were sequential on purpose).
- Native checkpointing (activity filter backfill, auto-match-transcribed) keeps HEAD's checkpoint struct (it carries more than a position) and stores it through `rc.Checkpoint`/`rc.Restore`; the pool tracks HEAD's contiguous watermark itself. The restore reads the bytes HEAD wrote (`activityFilterIndexBackfillParams`, `autoMatchTranscribedParams`). auto-match's per-item checkpoint is HEAD's sequential `CheckpointFn` (restored on `t6g1ItemsOptions`), not the watermark state. The native cadence differs from HEAD's `registry.RunItems`: HEAD throttles on watermark distance, skips a value it already wrote and flushes at the end; the native pool throttles on completion count (every `CheckpointEvery`), rewrites an unchanged watermark while a gap is open and has no final flush. The native value is never ahead of the truth (`TestT6G1Kinds_WatermarkIsTheContiguousPrefix`, `TestT6G1Kinds_ActivityBackfillWritesAContiguousCheckpoint`), so a resume can only redo windows, never skip one.
- Every non-checkpointing kind maps HEAD's `ResumeRestart` to `ResumeFromZero` and `ResumeRequeue` to `ResumeFromZero`: with no checkpoint, a restart is a start from the beginning.
- Schedules are not carried: split-scan's HEAD cron (`0 2 * * 1`) comes from the `sched` hook the flip passes.
- Reporting differs from the v2 shell: the native progress is `ProgressBase` and `ProgressTotal` through `rc.Progress()`, and the label is pure label. `prune-ai-journal` stores its result through `env.StoreResult` in the HEAD shell, as before; the native result is the task result.
- `author-purge-empty` aborts on `ErrFenced`, from the delete and from the journal row before it, rather than counting it as a failed delete.

## Deviations

- Re-signed internal helpers (no test or other file called them): `ingestLibraryExport`, `ingestCatalogRaw`, `logUndecodable`, `logAuthorityReport`, `authorityProgress`, `authorityRefusals`, `runActivityFilterIndexReconcile` (now `...Core`), `activityFilterIndexProgressTo`, `previewAuthorSplit`, `authorIDRepairDangling`, `authorIDRepairDuplicates`, `authorIDRepairCanonical`, `authorPathLinkBuildIndex`, `authorPathLinkScope`, `authorPathLinkApplyOne`, `isRealAuthor`. The brief says only add; these were the narrowest way to route every write through the env writer. `authorPathLink`, `authorIDRepair` and the HEAD shells keep their signatures.
- Deleted as dead after the re-signs (staticcheck U1000 flagged them; nothing called them, tests included): `authorPathLinkStore`, `authorPathLinkAuthorStore`, `authorPathLinkBookStore`, `newAuthorPathLinkCreator`, `authorityExportItem`. The brief says never delete; keeping them fails the package's staticcheck gate.
- Deleted as test-only HEAD wrappers, with their tests retargeted to the `*Via`/`*Core` functions they wrapped (coordinator decision, the wrapper was kept alive for tests only): `mergeAuthorInto`, `authorIDMergeOne`, `unlinkAndDeleteAuthor` and `buildAuthorityLists`, and seven `*Parallelism` functions no native kind uses (prune, conjunction, duplicate-merge, purge-empty, strip-merge, title-fragment, whitespace). Their doc comments moved onto the `*Via` functions.
- `author_strip_merge_relink.go` is untouched: `t6g1RelinkStore` routes its three writes through the gated writer.
- Test-only identifiers renamed to carry the `t6g1` prefix (`gateWriter`, `authorityKV`, `errReconcileWithForce` became `t6g1GateWriter`, `t6g1AuthorityKV`, `errT6g1ReconcileWithForce`).
- Three extra test files beyond the brief's list: `export_t6g1_test.go`, `kinds_t6_g1_drift_test.go` (external package `maintenance_test`, because `internal/books` imports this package and an in-package test cannot import it back; it reads `tasks.CommonOf(d).Perms.Start` for every kind and asserts `Kind() == rbac.KindAllOf`) and `kinds_t6_g1_live_test.go` (a live run per writing kind through a counting writer over a real store, the two HEAD-checkpoint restores, the mode-key and unwired-hook refusals, the fenced purge journal and the pool's actual parallelism). The drift test is named outside the `TestT6G1Kinds_` prefix so that prefix still counts exactly the in-package tests.
- `scripts/deadcode-baseline.txt` gains `internal/plugins/maintenance` identifiers for the dark kinds (the 14 native shells, their parallelism functions, the `t6g1*` plumbing and the `UnmarshalJSON` methods and params types of the native shells), the F5-02 precedent for dark code. The exact count is the diff of that file against main in this PR. F5-18 deletes the identifiers it makes reachable or removes; the bot prunes the rest.

## Dropped HEAD fields

Per brief R5, the HEAD `OperationDef` values the native kinds do not carry. `Plugin` was `"maintenance"` on all 14. `FormerIDs` was `scheduler.author-split-scan` on author-split-scan and `scheduler.resolve-production-authors` on resolve-production-authors (the flip carries them as the kind's former ids). `Liveness` was `LivenessManual` on 11 (activity-filter-index-backfill, author-split-scan, resolve-production-authors, author-conjunction-repair, author-duplicate-merge, author-id-repair, author-path-link, purge-empty-authors, author-strip-merge, the title-fragment report and the whitespace-collision report), `LivenessRunItems` on authority-build and auto-match-transcribed, and `LivenessNone` on prune-ai-journal; the native pool's own liveness replaces them. Dropped params fields are listed in the PR body.

## Follow-ups

- F5-18 removes the HEAD v2 shells and the `t6g1Head*` adapters.
- F5-18 OBLIGATION, authority-build plan lookup. A native Preview returns `ApplyParams{"plan_op_id": <RunID>}`, but the Live run reads its plan through `deps.PlanReader`, which needs a v2 operation row (`DefID == "maintenance.authority-build"`, completed, `ResultData` set). A native run's result is in the tasks run store, so once `PlanReader` is wired to the operation store every native apply of a native dry run fails "plan op <RunID> not found". Production behaviour is unchanged while the kinds are dark; F5-18 must back the lookup with the tasks run store (kind `books.maintenance.authority-build`, completed outcome) and replace `TestT6G1Kinds_AuthorityBuildAppliesFromAPlantedV2PlanRow`, which plants a v2 row to stand in for it, with a test that feeds a native Preview's own result to the Live run. Filed as a `todo.d` fragment.
- F5-18 OBLIGATION, Help text. The native Help is verbatim HEAD (brief R5), so it tells the caller to "pass apply=true" (purge, strip) or "dry_run=false" (split, resolve, conjunction, duplicate, id-repair, path-link, authority, auto-match), keys the native kinds refuse. F5-18 rewrites the Help to name the run mode when it removes the v2 shells. Same `todo.d` fragment.
- authority-build's `tasks.CPU()` pool can exceed HEAD's `authorityMaxConcurrency = 32` cap on a host with more than 32 cores; negligible.
- The wiring that builds `t6g1Deps` from the server (F5-18) is not proven here; the tests use real stores and fakes.

## Round 4 additions

- F5-18 must register every resource name this row uses in `r.Resources(...)`: `activity`, `metadata_cache`, `field_states`, `ai_journal` and `authority_lists` (the five this row adds to the registry; `books`, `book_files`, `authors`, `series` and `operations` are in the brief's list already). The same step must register `sync_identity`, `metrics` (F5-01's jobs, now constants), `cover_text` (F5-08) and `file_provenance` (F5-09 and F5-07's quarantine path); the last two are added here and unused by any F5-06 kind. This row adds six constants in all: `ai_journal`, `authority_lists`, `sync_identity`, `metrics`, `cover_text`, `file_provenance`.
- Every Effects resource name is written `string(ops.ResX)`, never a literal; `TestT6G1Kinds_EffectsNamesAreConstantsNotLiterals` scans the package for a `tasks.Res` literal. F5-01's `jobWrites` and the repairs fixer kinds were switched from literals to the same constants (values unchanged).
- A kind's declared WriteSet equals the union of its writer interface's methods through `t6g1WriterResources`, plus an explicit per-kind list of resources written outside the interface (`TestT6G1Kinds_WriteSetEqualsTheWriterInterfaceUnion`). only resolve and auto-match have an outside entry (their whole set, metafetch's apply). `DeleteAuthor` and `MergeDeleteAuthor` map to `books` as well as `authors`: both run the store's `deleteAuthor`, whose primary-author repoint calls `ModifyBook` on each affected book (author_primary_repoint.go), so the gated writer's tag map must put them under `books`.
- Every read dependency is write-free (`TestT6G1Kinds_ReadDependenciesHaveNoWriteMethods`), and each kind's writer group is read from its shell (`t6g1KindWriterFields`), not copied.
- Auto-match's owner-manual refusal now requires Files, Authors and Tags, as HEAD wires them (Series is filled in-run).
- The first test that runs the real metafetch apply (resolve, auto-match) through an Effects-enforcing writer is an F5-18 obligation; the gated writer's tag map must put `AddBookTagWithSource` under books, `RecordMetadataChange` under operations and `metadata_state:` writes under field_states.
- Auto-match-transcribed keeps `last_book_id` as a start param (stack review C9, fixed). The native params type had dropped it on the reasoning that `rc.Restore` carries the checkpoint, but HEAD also honours it with no checkpoint (a start that names the last finished book resumes after it). The native params now carry `last_book_id`; a restored checkpoint that names a last book replaces it, as HEAD's registry merges the checkpoint over the params; an empty checkpoint value leaves the param in force. Pinned by `TestT6G1Kinds_AutoMatchHonoursLastBookIDStartParam`.
- Authority-build decodes strictly as HEAD does (stack review C6, fixed): after the mode-key refusal the native params go through `decodeStrictParams`, so an unknown key, a case-variant duplicate (`plan_op_id` / `Plan_Op_ID`) and trailing data are refused before the run reads anything. Pinned by `TestT6G1Kinds_AuthorityBuildRefusesLooseParams`.

## Shared writer table and progress labels (stack review D3, C1)

Group 1's `t6g1WriterResources` is now a view of the stack-wide `t6WriterResources` (`internal/plugins/maintenance/kinds_resources.go`; the rows and the one-resource-per-write F5-18 obligation are in `seams.d/F5-10.md`, "One table for six groups"). ModifyBook and ModifyBookCredits carry `metadata_cache` and `indexes` (the store stamps the cache when a title or an author changes, an AuthorID going from nil to set counts, and stages the `ident:` rows), so the kinds that change a book's author through them declare both. Effects that changed: `author-split-scan`, `author-duplicate-merge`, `author-conjunction-repair`, `author-id-repair`, `author-path-link`, `purge-empty-authors` and `author-strip-merge` gain `metadata_cache` and `indexes`; `resolve-production-authors` and `auto-match-transcribed` gain `indexes` (`t6g1OutsideWriterSeam` lists it for the two whose book write is a seam outside the writer).

Progress labels follow the one rule of groups 1 to 6 (`seams.d/F5-11.md` recorded it first): `tasks.ItemsOptions.Label` is pure and rendered before the item runs, so the native pool carries only an index-only label. `t6g1ItemsOptions` gains `PureLabel func(i, total int) string`, handed to HEAD's `RunItems` as its label and to the item-only native label (the item is the index); `Label` keeps HEAD's counter-reading label and the native pool drops it. Every label group 1 has today reads a counter (`author_id_repair.go`, `author_path_link.go`, `author.go`, `auto_match_transcribed.go`, `authority_build.go`, `activity_filter_index_backfill.go`), so none uses `PureLabel` yet and the native group 1 loops show no per-item note; `TestT6G1Items_PureLabelCrossesAndCounterLabelDoesNot` pins both behaviours. A seam, not a regression of the HEAD shells. The larger fix, a core `ItemRC.Note(...)` hook called after the item, would bring the counter text back and is not done here.
