# F7-03 seams and coined names

This file lists what the core AI router PR (05-ai, built dark) added beyond the Go blocks of the spec: the readings it took where the spec or the brief is silent or contradicts itself, the defects its own tests found, and the seams later rows build on. Everything not listed here follows the spec as written. Nothing in this PR is registered, wired or reachable from ABO (I7).

## Seams later rows must honour

| Seam | What F7-03 does | Who builds on it |
|---|---|---|
| `Registrar.AICapability` is not added | F7-09 owns `registrar.go`. The catalog API is `Router.RegisterCapability(module, spec)`, `FreezeCatalog`, `Lookup`, `Catalog`, `HasCapability`, `HasApplyKind`. A `Capability` is `{id; r *Router}`, so a handle from another router answers `ErrUnknownCapability`. | **F7-09** adds `Registrar.AICapability` over `RegisterCapability`, freezes the catalog after every module's `Register`, and builds the Router with `RouterOptions{Registry, Disabled, Config, Jobs, NewBatch, Stager, Metrics, Now, Logger}`. |
| The endpoint settings carry list fields the schema cannot check | `EndpointSettings` is embedded in the adapter's `Settings`; there is no schema-merge API. Wildcard ticks, unknown ticks, an unsettable locality and an unknown declared feature cannot be expressed in the schema, and the Registry has no per-kind validation hook, so `Router.ValidateEndpoint` must be called on every Put. | **F7-09** calls `ValidateEndpoint` from the kernel's ai Put path. **The correct fix is larger:** a Meta/descriptor validation hook in `integrations` (F7-01's files), about 40 lines plus the `inventory.json` procedure, which removes the kernel's duty to remember the call. Needs the lead's decision. |
| Settings keys that differ from HEAD | `Locality` is a string kind (`auto` \| `local` \| `cloud`), not the spec's `uint8`: `config.SchemaFor` reflects the Go kind, so `uint8` rendered "integer 0..255" and refused `"local"`. `EndpointSettings.HostRoots` is stored as `root_paths`, not HEAD's `host_roots`: the Registry refuses a settings key naming a destination word (`host`) that is not a URL field (SEC-15). | **F7-08 must map** HEAD's `host_roots` to `root_paths` and whatever locality value HEAD stored (if any) to the string form when it imports endpoints; this PR did not inspect HEAD's representation. The spec's `Locality uint8` should be amended. |
| Batch jobs: who writes what | The poll (`BatchPollTask` body) moves Pending to Submitted, Submitted to Applying (staging the module's apply run in the same commit through `Stager.WriteRuns`/`StartIn`), and reaps Pending jobs with no remote batch after 1h as Failed. It never calls a handler and never raises attempts. The apply run (`BatchApplyTask`) raises `ApplyAttempts` through its own same-state compare-and-set, fails the job past `BatchMaxApplyAttempts`, calls the handler, and completes the job in its own commit. Cancel re-reads once and cancels from the new state. | Modules write one `BatchHandler` per batch capability and pass `BatchApplyTask(c, h, effects)` to `Registrar.Tasks`. **The handler must be idempotent**: a job completes in a separate commit from the handler's writes, so a crash between them replays it. `BatchApplyTask` declares no `Res("core","ai")`. |
| An ambiguous submit | `SubmitBatch` writes the job row before any remote call. A submit whose outcome is unknown returns `ErrSubmitUnconfirmed` wrapped with the job ID, and the job stays Pending; the poll reconciles it by `JobTagKey` through `FindBatches`. | F7-08 and F7-10's routes show the job ID to the operator; they do not retry the submit. |
| Importer | `NativeImporter(ks, opts ...ImporterOption) Importer`, `ImportJob(ctx, b, j)` in any state, each write expecting the job absent; identical content is a no-op, other content is `storage.ErrImportConflict`. `ImportWithCatalog(CatalogView)` imports a job naming an unregistered capability or apply kind as Failed with a note row, never dropped. | **F7-08** (books' M6 step) receives the importer and passes the router as `CatalogView` after the catalog is frozen. |
| The kernel's boot calls | `ai.Owner` with `ai.StorageSpec()` (jobs and the open index are Serialized, so a write without its Expect is refused by storage); `Provider.Core("ai", ai.ScopeKeys()...)`; `Router.Close`; `Router.RefreshCaps`. | **F7-09**. |

## Defects the PR's own tests found (fixed here)

| Found by | Defect | Fix |
|---|---|---|
| The schema probe | `Locality` rendered as an integer range and refused its own names. | String kind with `schema:"enum=auto\|local\|cloud"` (above). |
| The Registry harness | A real Registry refused the adapter's schema: `host_roots` names a destination. A real Registry would have refused the real OpenAI adapter's `Descriptor()` too. | `root_paths` (above). |
| `TestQualityError_ClassWinsAndUnwraps` | `QualityError` documented ClassBadOutput but `integrations.ClassOf` read Unknown, because integrations cannot import ai. | `QualityError.Unwrap()` returns `[]error` carrying an `*integrations.Error{Class: ClassBadOutput}`; `errors.Is` still reaches the wrapped cause. |
| The adapter wire tests | A 2xx the SDK could not decode was class unknown, and a 200 with a non-JSON content type (a url pointing at a web page) was a bare string error. | Decode errors are read by type and are `bad_output`; a body cut off mid-stream is `transient`; a response guard returns a typed `bad_output` that names the content type, never the body. Result files are exempt. |
| The adapter wire tests | Transcribing with an empty or unknown MIME failed inside the SDK's form encoder. | `audioUpload` always sends a valid content type (`audio/mpeg` for the mp3 default). |
| The adapter wire tests | A query or fragment in the `url` setting was dropped by the SDK, so a credential pasted there would be stored in plaintext and never sent. | `baseURL` refuses it with the reason. |
| `TestOpenAICompat_PrivateHostNeedsLocal` | `Health` reported every locally refused call as "misconfigured: secret missing", which misdirects an operator who forgot `Local`; an unreadable key was reported as the server rejecting it. | The adapter tells its own unreadable key (`errKeyUnreadable`) from a gate refusal and names the refusal. The Deluge adapter has the same all-refusals-are-a-missing-secret mapping; it is another row's code and is not touched here. |
| `aitest.JobStoreSuite`'s first draft | "Exactly one of the racing writers commits" failed on goroutines released together: a same-state write that commits before another writer reads is a valid serial order (the later writer reads the committed row and its `from` is still true). | See the invariants below. |
| The root bypass guard (`internal/aidispatch/guard_test.go`) | The guard walks the whole repo, `core/` included, so the adapter's SDK import and its `.Chat.Completions.New`, `.Embeddings.New`, `.Audio.Transcriptions.New`, `.Files.New` and `.Batches.` calls failed `TestGuard_NoAIBackendCallsOutsideTheDispatcher`. | `core/integrations/ai/openai/` is added to `guardExemptDirs`, the permanent list, not the ceiling-capped ratchet allowlist. Core enforces the same boundary itself (`NoAISDKOutsideAdapters` fails on any other importer and fails when the adapter stops importing the SDK). `TestGuard_ExemptDirsAreExact` pins the exemption to that one directory, so every rule still applies to the rest of `core/`. |
| `scripts/ci/check_module_skew.py` | The `openai-go` require pulled `tidwall/match` v1.1.1 into core while the root module resolves v1.2.0. | `core/go.mod` pins `tidwall/match` v1.2.0 (indirect). |

## Invariants later changes must keep

| Invariant | Why | Pinned by |
|---|---|---|
| Every job write is a `Transition` or a `Create` staged in the caller's batch with an Expect on the row it read; the store has no other writing method and no lock. | Two writers of one job conflict at commit instead of losing a write; a cancel is never reverted by a same-state write (R6-1, I4). | `TestNativeJobStore_BlindWriteRefused`, `aitest.JobStoreSuite` (`overlapping_windows_one_wins`), `TestAIJobPollVsCancelOneWins`, `TestAIJobApplyVsCancelOneWins`, `TestAIJobSameStateWriteVsCancelOneWins` |
| "Exactly one commits" holds where the read-to-commit windows overlap, and the suite forces the overlap. Free-running writers are asserted only to serialize: some writer commits, at most one changes the state, and the stored state is that writer's. | Without a forced overlap the assertion is a race against the scheduler, and a correct store fails it. | `overlapping_windows_one_wins` and `concurrent_transitions_serialize` in `aitest/jobstore.go` |
| Only `integrations/ai/openai` imports `openai-go`; every SDK error leaves it as an `*integrations.Error`. | The SDK's wire shapes and version stay out of every caller. | `archtest.NoAISDKOutsideAdapters`, `TestResponses_UndecodableAnswersAreBadOutput`, `TestErrors_Classification` |
| No package-level state in `integrations/ai`, `aitest` or the adapter except sentinel errors; no `init()`. | HEAD's dispatcher kept its bench and counters in globals, shared by two apps in one process (R5, I5). | `TestNoGlobals` |
| The `ai` scope exports the section 8 families and label sets, histograms without `instance`. | Rule C5; the series are a published contract. | `TestAISeries_Golden`, `testdata/series.golden` |
| A mutation of any of these paths fails a named test: the Expect or the state precondition of `Transition`, the cancel's re-read, a second handler call, the terminal checks of the apply and completion paths, the poll's transition, the quota marker's `code` field, and the adapter's decode, guard, content-type, url and health rules. | The tests were run against 13 such mutants and all were killed. | the tests above |

## Not done, or not proven

- **The live conformance run has not been executed.** `TestConformance_Live` (behind `MEDIACORE_LIVE_AI=1`) compiles and skips; no Ollama, llama.cpp or transcription server was available. Spec section 11 item 1 relies on that run to measure each server's structured-output support, so features stay operator-declared until someone runs it.
- **The dialect fixtures are not captures.** They are written from each server's documented response shapes (`openai/testdata/dialects/README.md` says so) and exercise extra and missing fields and an empty transcript. Replace a file with a real capture by saving the server's body for that route unchanged.
- After a quota failure the gate holds the instance, so the cleanup `DELETE` of an uploaded batch input file is refused locally and the file stays at the provider (`TestSubmitBatch_CreateFailureDeletesTheUpload`). A later run could list and delete files tagged by purpose.
- Two files owned by other rows are edited at build, and both paths are in F7-03's `inventory.json` row (`check_waves.py` passes): `core/archtest/tasklint/core_test.go` (F2-11's file) gains one `Constructors` entry for `BatchApplyTask`, and `internal/aidispatch/guard_test.go` gains the adapter directory in `guardExemptDirs` (see the defects table).
