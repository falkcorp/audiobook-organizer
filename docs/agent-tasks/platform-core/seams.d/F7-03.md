# F7-03 seams and coined names

This file lists what the core AI router PR (05-ai, built dark) added beyond the Go blocks of the spec: the readings it took where the spec or the brief is silent or contradicts itself, the defects its own tests found, and the seams later rows build on. Everything not listed here follows the spec as written. Nothing in this PR is registered, wired or reachable from ABO (I7).

## Seams later rows must honour

| Seam | What F7-03 does | Who builds on it |
|---|---|---|
| `Registrar.AICapability` is not added | F7-09 owns `registrar.go`. The catalog API is `Router.RegisterCapability(module, spec)`, `FreezeCatalog`, `Lookup`, `Catalog`, `HasCapability`, `HasApplyKind`. A `Capability` is `{id; r *Router}`, so a handle from another router answers `ErrUnknownCapability`. | **F7-09** adds `Registrar.AICapability` over `RegisterCapability`, freezes the catalog after every module's `Register`, and builds the Router with `RouterOptions{Registry, Disabled, Config, Jobs, NewBatch, Stager, Metrics, Now, Logger}`. |
| The endpoint settings carry list fields the schema cannot check | `EndpointSettings` is embedded in the adapter's `Settings`; there is no schema-merge API. Wildcard ticks, unknown ticks, an unsettable locality and an unknown declared feature cannot be expressed in the schema, and the Registry has no per-kind validation hook, so `Router.ValidateEndpoint` must be called on every Put. | **F7-09** calls `ValidateEndpoint` from the kernel's ai Put path, with `TestAIInstancePut_WildcardCapabilityRefused` (a wildcard `PUT` through the kernel answers 422) as its acceptance test; the obligation and the test are in the F7-09 brief. **The correct fix is larger:** a Meta/descriptor validation hook in `integrations` (F7-01's files), about 40 lines plus the `inventory.json` procedure, which removes the kernel's duty to remember the call. Needs the lead's decision. |
| Settings keys that differ from HEAD | `Locality` is a string kind (`auto` \| `local` \| `cloud`), not the spec's `uint8`: `config.SchemaFor` reflects the Go kind, so `uint8` rendered "integer 0..255" and refused `"local"`. `EndpointSettings.HostRoots` is stored as `root_paths`, not HEAD's `host_roots`: the Registry refuses a settings key naming a destination word (`host`) that is not a URL field (SEC-15). | **F7-08 must map** HEAD's `host_roots` to `root_paths` and whatever locality value HEAD stored (if any) to the string form when it imports endpoints; this PR did not inspect HEAD's representation. The spec's `Locality uint8` should be amended. |
| Batch jobs: who writes what | The poll (`BatchPollTask` body) moves Pending to Submitted, Submitted to Applying (staging the module's apply run in the same commit through `Stager.WriteRuns`/`StartIn`), and reaps Pending jobs with no remote batch after 1h as Failed. It never calls a handler and never raises attempts. The apply run (`BatchApplyTask`) raises `ApplyAttempts` through its own same-state compare-and-set, fails the job past `BatchMaxApplyAttempts`, calls the handler, and completes the job in its own commit. Cancel re-reads once and cancels from the new state. | Modules write one `BatchHandler` per batch capability and pass `BatchApplyTask(c, h, effects)` to `Registrar.Tasks`. **The handler must be idempotent**: a job completes in a separate commit from the handler's writes, so a crash between them replays it. `BatchApplyTask` declares no `Res("core","ai")`. |
| The router owns an endpoint's cooldown; the gate's hold is sized under it | The adapter's `Descriptor()` sets `Limits.Holds` to 30s for transient, transport, rate-limited and quota failures, 5m for auth, and caps every hold, a `Retry-After` included, at `Max` 5m (`ai.DefaultCooldownBase`, `ai.DefaultCooldownMax`, exported for this). `Health`, `Test`, `CancelBatch` and the cleanup of a batch's input file pass through an active hold (`providerhttp.WithBypassHold`); `Caps`, the router's refresh, does not. | **F7-09** wires `Router.ClearBench(ref)` into the `core.integrations.health` task on a `HealthOK` probe (05-ai section 4 step 4), without clearing a quota bench: `GET /v1/models` succeeds on a spent balance. `TestAIHealthTaskClearsTheBench` in the F7-09 brief. |
| An ambiguous submit | `SubmitBatch` writes the job row before any remote call. A submit whose outcome is unknown returns `ErrSubmitUnconfirmed` wrapped with the job ID, and the job stays Pending; the poll reconciles it by `JobTagKey` through `FindBatches`. **Ambiguous is every class but a refusal or a request never sent** (`ai.NotAccepted`): a 5xx, a cut connection, a canceled caller, and a 2xx the adapter could not decode or that carried no batch ID. | F7-08 and F7-10's routes show the job ID to the operator; they do not retry the submit. |
| Importer | `NativeImporter(ks, opts ...ImporterOption) Importer`, `ImportJob(ctx, b, j)` in any state, each write expecting the job absent; identical content is a no-op, other content is `storage.ErrImportConflict`. `ImportWithCatalog(CatalogView)` imports a job naming an unregistered capability or apply kind as Failed with a note row, never dropped. | **F7-08** (books' M6 step) receives the importer and passes the router as `CatalogView` after the catalog is frozen. |
| The kernel's boot calls | `ai.Owner` with `ai.StorageSpec()` (jobs and the open index are Serialized, so a write without its Expect is refused by storage); `Provider.Core("ai", ai.ScopeKeys()...)`; `Router.Close`; `Router.RefreshCaps`. | **F7-09**. |

## Defects the PR's own tests found (fixed here)

| Found by | Defect | Fix |
|---|---|---|
| The schema probe | `Locality` rendered as an integer range and refused its own names. | String kind with `schema:"enum=auto\|local\|cloud"` (above). |
| The Registry harness | A real Registry refused the adapter's schema: `host_roots` names a destination. A real Registry would have refused the real OpenAI adapter's `Descriptor()` too. | `root_paths` (above). |
| `TestQualityError_ClassWinsAndUnwraps` | `QualityError` documented ClassBadOutput but `integrations.ClassOf` read Unknown, because integrations cannot import ai. | `QualityError.Unwrap()` returns `[]error` carrying an `*integrations.Error{Class: ClassBadOutput}`; `errors.Is` still reaches the wrapped cause. |
| The adapter wire tests | A 2xx the SDK could not decode was class unknown, and a 200 with a non-JSON content type (a url pointing at a web page) was a bare string error. | Decode errors are read by type and are `bad_output`; a body cut off mid-stream is `transient`; a response guard returns a typed `bad_output` that names the content type, never the body. Result files are exempt. |
| The adapter wire tests | Transcribing with an empty or unknown MIME failed inside the SDK's form encoder. | `audioUpload` always sends a valid content type (`audio/mpeg` for the mp3 default). |
| The adapter wire tests | A query or fragment in the `url` setting was dropped by the SDK, so a credential pasted there would be stored in plaintext and never sent. | `baseURL` refuses it with the reason. |
| `TestOpenAICompat_PrivateHostNeedsLocal` | `Health` reported every locally refused call as "misconfigured: secret missing", which misdirects an operator who forgot `Local`; an unreadable key was reported as the server rejecting it. | The adapter tells its own unreadable key (`errKeyUnreadable`) from a gate refusal and names the refusal: the egress guard is misconfigured, a hold, an open breaker or a spent daily quota is degraded. The Deluge adapter has the same all-refusals-are-a-missing-secret mapping; it is another row's code and is not touched here. |
| The Opus review (MAJOR-1), reproduced through the real adapter and Registry | The adapter left `Limits.Holds` at the gate's defaults, so one 503 held the endpoint for 30 minutes (a rate limit 15m, quota 4h) under a router that benches for 30s: at +2m the call was refused locally (`refused by the hold gate`, one request ever sent), and the router's cooldown never ran. A `Retry-After` is not clamped by the gate, only by `Holds.Max` (24h by default). The gate also held `insufficient_quota` as a burst-limit 429 while the adapter and router called it quota, and `Health` after it reported "misconfigured". | `Descriptor()` sets the hold policy (above); `providerhttp`'s daily-quota markers gain `insufficient_quota` and `credit_balance_exhausted`, the words `ai.IsQuotaMarker` shares between the router and the adapter; `Health` and `Test` pass through a hold. `TestOpenAICompat_ARouterCooldownEndsWithTheHold`, `_RetryAfterIsHonouredUpToTheRoutersCap`, `_GateAndAdapterAgreeOnQuota`, `_HealthProbeEndsAHold`. |
| The Opus review (MINOR-1), reproduced with the probe | A failed batch create deleted its uploaded input file whatever the failure: a 2xx cut off mid-body or empty was deleted although the batch may exist and be reading that file, and the router's `definite()` called every BadOutput a refusal, failing a job the provider had accepted. | The file is deleted only on proof the batch was not created (a 4xx, a request never sent, a reply that is not the API's, the new `notAPIError`); an unreadable 2xx or one without a batch ID is `bad_output` and ambiguous, and `ai.NotAccepted` is the one predicate both sides read. `TestSubmitBatch_CreateFailureDeletesTheUpload` has a row per failure shape; `TestNotAccepted`. |
| The Opus review (MINOR-3, 4, 5; NITs) | `Health` called an open breaker or a hold "misconfigured"; one damaged job row stopped the poll from advancing every job listed before it; the kind-cap test waited a fixed 50ms and the slot-release test covered two of the exits; `BatchResult.Err` carried a provider's text unbounded; the swallowed cleanup error was never logged. | `Health` maps a hold, breaker or quota refusal to degraded and only the egress guard to misconfigured; `PollBatches` advances the jobs listed before the damage and returns the error; the kind-cap tests use the outcome-based barrier described in their comments and cover every exit once a slot is taken; `BatchResult.Err` goes through `detail()`; the cleanup error is logged at debug. |
| Mutation runs of this round's tests | The first draft of `TestRouter_KindCapProductionSetter`'s barrier passed with the kind cap deleted: the refused calls carried a canceled context, the Registry refuses a lease on one, so they never reached the gate whether or not the cap worked. | The refused calls now run under a deadline instead of a cancellation, and the slot accounting is pinned without any goroutine in `slots_test.go`; with the cap ignored the test fails 10 of 10 runs. |
| `aitest.JobStoreSuite`'s first draft | "Exactly one of the racing writers commits" failed on goroutines released together: a same-state write that commits before another writer reads is a valid serial order (the later writer reads the committed row and its `from` is still true). | See the invariants below. |

## Invariants later changes must keep

| Invariant | Why | Pinned by |
|---|---|---|
| Every job write is a `Transition` or a `Create` staged in the caller's batch with an Expect on the row it read; the store has no other writing method and no lock. | Two writers of one job conflict at commit instead of losing a write; a cancel is never reverted by a same-state write (R6-1, I4). | `TestNativeJobStore_BlindWriteRefused`, `aitest.JobStoreSuite` (`overlapping_windows_one_wins`), `TestAIJobPollVsCancelOneWins`, `TestAIJobApplyVsCancelOneWins`, `TestAIJobSameStateWriteVsCancelOneWins` |
| "Exactly one commits" holds where the read-to-commit windows overlap, and the suite forces the overlap. Free-running writers are asserted only to serialize: some writer commits, at most one changes the state, and the stored state is that writer's. | Without a forced overlap the assertion is a race against the scheduler, and a correct store fails it. | `overlapping_windows_one_wins` and `concurrent_transitions_serialize` in `aitest/jobstore.go` |
| Only `integrations/ai/openai` imports `openai-go`; every SDK error leaves it as an `*integrations.Error`. | The SDK's wire shapes and version stay out of every caller. | `archtest.NoAISDKOutsideAdapters`, `TestResponses_UndecodableAnswersAreBadOutput`, `TestErrors_Classification` |
| No package-level state in `integrations/ai`, `aitest` or the adapter except sentinel errors; no `init()`. | HEAD's dispatcher kept its bench and counters in globals, shared by two apps in one process (R5, I5). | `TestNoGlobals` |
| The `ai` scope exports the section 8 families and label sets, histograms without `instance`. | Rule C5; the series are a published contract. | `TestAISeries_Golden`, `testdata/series.golden` |
| A mutation of any of these paths fails a named test: the Expect or the state precondition of `Transition`, the cancel's re-read, a second handler call, the terminal checks of the apply and completion paths, the poll's transition, the quota marker's `code` field, and the adapter's decode, guard, content-type, url and health rules. | The tests were run against 13 such mutants and all were killed. The second review round added 15 more, each killed by a named test: the hold bypass removed from `Health`, from the input-file cleanup and from `CancelBatch`; the input file always deleted; the guard's `notAPIError` ignored; the result error left unscrubbed; `Holds` removed from the descriptor; `Holds.Max` removed; the breaker mapped to misconfigured; the gate's quota words removed; `BadOutput` put back into `NotAccepted`; the poll returning at the first listing error; the kind slot released only on success; the router ignoring the kind cap; the slot accounting ignoring it. | the tests above |

## Not done, or not proven

- **The live conformance run has not been executed.** `TestConformance_Live` (behind `MEDIACORE_LIVE_AI=1`) compiles and skips; no Ollama, llama.cpp or transcription server was available. Spec section 11 item 1 relies on that run to measure each server's structured-output support, so features stay operator-declared until someone runs it.
- **The dialect fixtures are not captures.** They are written from each server's documented response shapes (`openai/testdata/dialects/README.md` says so) and exercise extra and missing fields and an empty transcript. Replace a file with a real capture by saving the server's body for that route unchanged.
- **`HoldPolicy.Persist` is a dead flag, so the adapter's `Persist: false` changes nothing.** `providerhttp` writes every hold to the store unconditionally (`placeHold`, `releaseIfStarted`) and merges the field with an OR (`scope.go`), so `false` cannot be expressed, and the contract says "default true" on a plain bool. A hold therefore survives a restart; what keeps that harmless is that every hold the adapter asks for expires within five minutes. This is F7-01's defect (`integrations.HoldPolicy` and `providerhttp`), not fixed here: the correct fix is a real choice (a `NoPersist` field or a tri-state, merge semantics, a test) or deleting the field, and it touches F7-01's files and the inventory. Filed as a todo fragment.
- A batch create that is ambiguous leaves its uploaded input file at the provider: the job row has nowhere to record the file ID, so the tag reconcile adopts the batch but nothing deletes a file whose batch never existed. A later run could list and delete files by purpose.
- `JobStore.Open` ends at the first damaged job row, so the jobs after it in ID order are not polled until the row is repaired; the jobs before it now are. The complete fix is for `Open` to yield the error for that row and continue, which makes the error non-terminal for every consumer (the poll and two `aitest` suites). Filed as a todo fragment.
- A `HealthOK` probe will clear the gate's hold but not the router's bench until F7-09 wires `Router.ClearBench` into the health task, and that call must leave a quota bench alone (the F7-09 brief says how).
- Four files owned by other rows are edited at build, and all their paths are in F7-03's `inventory.json` row (`check_waves.py` passes): `core/archtest/tasklint/core_test.go` (F2-11's file) gains one `Constructors` entry for `BatchApplyTask`, `internal/aidispatch/guard_test.go` gains the adapter directory in `guardExemptDirs` (see the defects table), and `core/integrations/providerhttp/classify.go` and its `transport_test.go` (F7-01's files) gain the two AI quota words and their `TestClassify` rows. The providerhttp change is the only one of this round outside the AI packages: it affects any integration whose 429 body contains those words, which today is only an AI endpoint.
