# R1-34 seams and coined names

This file lists what the explicit-list PR added beyond 06 §6.11.1 steps 2-3 and §6.11.2: names the spec does not have, readings it took where the spec or brief is silent, and the seams later rows (F3-07, F5-18, F7-09, F8-04, R3-05) build on.

## Names beyond the spec

| Name | What it is |
|---|---|
| `serviceregistry.NewContainerFrom(defs ...ServiceDef)` | The only constructor. `NewContainer` is deleted, so `NewContainerFrom()` is the empty container. Every def passed is in the build set, so `(*Container).Include`, which only named a service to build, is deleted too (it had no caller outside its own test); `Override` is unchanged and still adds its name to the build set. It panics on an empty `Name`, a nil `Build` or a duplicate name, as `Register` did. The factory list is the container's own `defs` map. The package holds no mutable package-level state. |
| `ServiceDefs() []serviceregistry.ServiceDef` | One per registering package (20 of them). |
| `serverServiceDefs()`, `batchPollerServiceDefs()` | `internal/server`'s two contributions (`registry_wire.go`, `batch_poller_register.go`), unexported because they are in package server. |
| `serviceDefs(databasePathSet bool)` (`internal/server/registry_wire.go`) | The one explicit production list, in 06 §6.11.2's package order. The four `activity` defs are in it only when `databasePathSet`. `NewServer` passes `config.AppConfig.DatabasePath != ""`. |
| `defsReachableFrom` (test helper, `registry_wire_dedup_score_config_test.go`) | Cuts the defs a root reaches through `Needs` out of `serviceDefs`, leaving out the overridden names. A test that builds part of the production list needs it, because every def handed to `NewContainerFrom` is built, where the group-based container used to pull in only a closure. |

## Readings and decisions

| Topic | Reading |
|---|---|
| **batchpoller (brief and spec disagree)** | `batch_poller_register.go`'s def has never carried `Groups`, so HEAD's `IncludeGroup` never built it and `wireServerFromContainer`'s `TryGet[*BatchPoller]` always missed: `s.batchPoller` is nil in production and `registerBatchPollerHandlers` never runs. The brief says every def carries one of five groups and the list is "all 43 defs", and that the production set must equal HEAD's. 06 §6.11.2 and the defect table say the explicit list fixes the defect as a side effect. Both cannot hold, because every def in a list is built. This row keeps the brief's invariant: `serviceDefs` filters `batchpoller` out by name (one `slices.DeleteFunc`), and `TestServiceDefs_BuildsHEADSet` fails if it comes back. **Decided (coordinator): keep the filter; the open question is tracked in `todo.d/2026-11-08-batchpoller-never-built.md`.** The alternative was: delete that filter and its test assertion to build the poller (with OpenAI parsing configured it then starts and registers handlers for `author_dedup`, `author_review`, `pipeline`, `aijobs` and `embed_async` that HEAD never registered in production), or leave it for F5-18, which constructs it explicitly. |
| Count at this base | 39 `Register` calls in 22 files (R1-15 had removed the operations registry's and the updater's). The container resolves 45 names with DatabasePath set (38 defs plus the seven overrides) and 41 without. The brief's "43" and "3 overrides" predate R1-15, which added `ophub`, `opregistry`, `updater` and `updatescheduler` as overrides. `TestServiceDefs_BuildsHEADSet` builds the container with all seven. |
| Acceptance grep for `func ServiceDefs()` | 20, not 22: the two in package server are unexported, as the brief's step 3 says. |
| Where the list lives | `internal/books` builds no container at this base (`git grep 'serviceregistry.NewContainer' -- internal/books` is empty); `NewServer` does, so `serviceDefs` sits in `internal/server/registry_wire.go` as the brief's "Where the one explicit list lives" says. `internal/books/module.go` is untouched. |
| `Groups` | Still data on each def, as the brief says. No container reads it. Step 4 deletes it with the defs. |
| `typed_accessor_regression_test.go` | Needed no port: it scans source text and calls nothing from the deleted API. |
| `internal/plugin/register_test.go` | Builds from `plugin.ServiceDefs()` itself rather than a local copy of the eventbus def: the copy existed only because the global map had to be reset. |
| `internal/opscatalog` | The link check now looks for a package-level `func ServiceDefs() []serviceregistry.ServiceDef` and requires `serviceDefs` to call it (it still requires `Ops(...) ops.Bundle` packages to be in `All` and linked). `internal/server` no longer counts as a registering package, since its two functions are unexported and the package is the binary's own. |

## Risks

| Risk | Cost of the fix |
|---|---|
| `internal/server`'s `serviceDefs` imports every plugin package, so a new registering package is in no container until someone adds it there. Before, a blank import was enough. | None left: `TestCatalogLinkedIntoBinary` parses `serviceDefs` in `registry_wire.go` for `pkg.ServiceDefs()` calls and requires every package under `internal/` that exports `ServiceDefs` to appear there. Being linked into the binary by something else no longer satisfies it (the earlier leg was vacuous under explicit lists). Mutation-checked: deleting `quarantine.ServiceDefs()` from the list turns it red while the package stays linked. |
