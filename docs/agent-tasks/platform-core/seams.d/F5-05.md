# F5-05 seams: acoustid, metafetch, itunes and deluge definitions become books kinds, dark

16 of 16 definitions are native kinds: acoustid 8, metafetch 3, itunes 1, deluge 4. Nothing registers the kinds before F5-18; HEAD's v2 definitions keep running over the same shared cores.

## Not converted

None.

## Shape (same as F5-04)

- Each package has one core per definition and two shells: HEAD's v2 `Run` over `sdk.Reporter`, and the native `tasks.Task`. They meet in `kindEnv` (`env.go`). `kinds*.go` do not import `pkg/plugin/sdk`; `env.go` is the sdk-facing half. itunes has no env: its one definition is the "not implemented" refusal, so its core is a function returning `errNotImplemented`.
- Rule R10: the cores reach the store and the writer only through `env.Store` and `env.Writer`. A native run never writes through the read store. Tasklint cannot see these packages' captures (it passes with the exemption file deleted and with it present, 0 failing and 30 exempt both ways), so the `WritesThroughShell` tests and the mutation runs are the guard.
- F5-18 must supply each package's `KindDeps`. itunes' is an empty struct.
- Registration roots: `var _ = kindList` and `var _ = (*Plugin).Kinds` in each package's kinds file; F5-18 deletes them.
- Test-only shims: the HEAD-named methods that the older tests still call (acoustid's `backfillPages`, `backfillBook`, `planWindowBackfill`, `WorkerHub.attach` and friends; deluge's `linkRunOptions`; metafetch's `applyOrigin`) moved to each package's `kinds_shims_test.go`, so production keeps no dead code and `lint-deadcode-ratchet` needs no baseline line. Definition-only wrappers (acoustid `cursorIsStale`, `planOne`, `windowStateOf`, `storeWindows`, `storeFailure`; deluge `resolveRound`, `relinkStates`, `timeNow`; metafetch `logReport`) were deleted.

## New resource

- `ops.ResASINMisses` (`asin_misses`) covers the `asinbackfill:miss:` and `asinbackfill:isbnmiss:` marker rows that asin-backfill writes. It is in `taskResourceKinds()`. `internal/maintenance/resources` is not edited here: its bare `DeleteRawBatch` row maps to authority_lists, which is wrong for the metadata-cache sweep, so the metafetch test pins pcache-sweep's resource literally. Whoever merges second between this and F5-04 (`ResSplitBookCandidates`) re-cuts `pkg/ops/effects.go`, `internal/books/module.go` and the `require.Len(t, valid, N)` in `kinds_t6_g1_test.go`.

## Effects choices to review

- asin-backfill widens HEAD's declared `[books]` to books, authors, metadata_cache, indexes and asin_misses (found by reading the code).
- acoustid declares only what it writes, read from the code: scan `embeddings`; backfill `books, book_files` (HEAD-declared); fingerprint-rescan, reset-all, lsh-backfill, lookup-online and fingerprint-duration-repair each the wider sets listed in the PR; window-backfill `fingerprint_index` only. HEAD declared Writes on only 1 of the 8.
- deluge: path-update declares `files` though its write is a Deluge `move_storage` RPC outside the store; link-backfill declares `book_files` though the writer's `ModifyBookFile` recomputes the wider aggregate; centralize declares the wider set (authors, book_files, books, files, indexes, metadata_cache).
- calibrate-scoring and itunes position-sync are ReadOnly; protected-paths-sync is ReadOnly (refreshes an in-memory cache).

## Mode

- Params may not carry `dry_run`, `dryRun` or `apply` (acoustid also `live`); they are refused case-insensitively, never dropped. The mode comes from the start request.
- Live-only (a native Preview is refused): acoustid scan, backfill, fingerprint-rescan, reset-all, lsh-backfill, lookup-online; deluge centralize. A Preview is HEAD's dry run for acoustid fingerprint-duration-repair and window-backfill, deluge path-update and link-backfill, and metafetch asin-backfill, pcache-sweep and calibrate-scoring.

## Resume

- Continue: acoustid backfill (restores HEAD's `BackfillParams` checkpoint), acoustid window-backfill (cursor only), metafetch asin-backfill (the restored checkpoint overlays the params).
- FromZero: deluge centralize and link-backfill (HEAD read no checkpoint back; centralize's checkpoint is counts only and the pending query is the resume state), acoustid lookup-online, itunes position-sync.
- Drop: everything else.

## Parallelism

- Every loop has an explicit `RunItemsOptions.Concurrency`. acoustid: backfill, rescan, duration-repair and window-backfill `Fixed(workers)`; lsh-backfill `CPU()`; reset-all a CPU pool for the slow pass and `Sequential` for the candidate-delete chunks; scan and lookup-online serial as at HEAD. metafetch: calibrate `CPU()`, asin `Fixed(workers)` (default 4, 1..8, Audible's token bucket is the throttle), pcache `Fixed(8)`. deluge: centralize `Fixed(4)` over disjoint book/hash groups, link-backfill `Fixed(linkWorkers)` (max 8), path-update `Sequential` (one book's versions).

## Behaviour differences, native vs HEAD

- A native run that errors drops its result; HEAD persists a partial link-backfill result.
- Counter-style progress labels (asin-backfill, link-backfill) exist only in HEAD's pool: the kernel's label is pure.
- asin-backfill drops HEAD's 15 minute `MinCheckpointInterval`.
- Native pools report through `ItemsProgress`, not the bar `sdk.Progress` writes; pcache's pointer pages gain item frames natively.
- Not carried: Liveness, Plugin, Cancellable, Isolate, Capabilities, Preview param specs, deluge path-update's trigger and protected-paths-sync's schedule.
- asin-backfill's `NotWhile` (`books.catalog.harvest-authors`, `books.identification.advance`) is mapped from HEAD's DependsOn by R3; those two IDs belong to other rows and are checked by core only for syntax.
- asin core logs through the global `logger.New("asin-backfill")`, not `env.Logger`.
- itunes position-sync keeps failing with `errNotImplemented`; it is declared ReadOnly.
- acoustid window-backfill's native timeout is `tasks.MaxTimeout` (24h); HEAD's definition said 72h. A pass longer than 24h ends `timed_out` natively. F5-18 decides: accept, add a near-deadline cutoff like deluge's `linkCutoff`, or raise the kernel cap (todo.d `ACOUSTID-WINDOW-BACKFILL-TIMEOUT`).
- The acoustid window hub writes remote results through the run's writer from worker-API request goroutines, off the run's own goroutines; F5-18 confirms the gated writer accepts that while the run is attached (todo.d `ACOUSTID-HUB-WRITES-OFF-RUN-GOROUTINES`).

## Known mutation survivors

- acoustid K4 (a null no-op unmarshal) and deluge K16 (the same shape) and metafetch's calibrate `headEnv(reporter, false)` flag are equivalent. acoustid C20 is a mutant of window_backfill.go code that this row did not change.
