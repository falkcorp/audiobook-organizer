# F5-18b seams and coined names

F5-18b builds the run-time write fence for a store call that writes several resources (owner decision 2026-11-18: run-time fence only, no compile-time narrow writer types per kind). It is dark: nothing on a live path calls any of it until F5-18 wires the kinds. The obligations: O9, O17, O26, O27.

## What was built

- `tasks.Write.Resources` (`core/tasks/writer.go`) is the stamp set. `Write.Stamps()` is `Resource` (when set) then `Resources`, repeats dropped; a zero ref inside `Resources` is kept so the fence refuses it. `Resource` stays for callers that name one resource (`core/outbox`, `core/updater`, taskstest), and `Resources` is `omitempty`, so the persisted intent of a one-resource write encodes as before.
- `tasks.CheckWrite(kind, declared, write)` is the one fence predicate: it refuses an empty stamp set, any undeclared stamp and a zero stamp, wrapping `ErrOutsideEffects` and naming the kind and every refused stamp. `tasks.Covers` is its membership test (a declared ref with no ID covers every ID of its module and kind; a declared ref with an ID covers only that ID, and not the whole kind). `core/internal/executor/writer.go` calls `CheckWrite` in the same place the old single check ran (after the writable check, before `renewHolds` and the intent, in Preview and Live); `declared()` in `start.go` now delegates to `Covers`.
- `internal/books/writer`: `Gate` (`New(w, rows)`, `Stamp`, `Do`) turns one store method call into ONE `Writer.Do` stamped with the method's whole row, named `books.<Method>` (a raw write is `books.SetRaw/<family>`). A method with no row is refused (`ErrNoRow` and `ErrOutsideEffects`) without calling fn. A method whose row is empty writes no Effects resource, so fn runs with no `Do` and NO fence (no writable or permit check, no Preview check, no intent). That is not "writes nothing": the shared table has seven such methods and four of them write. `HardDeleteWithoutUserState` (a wrapper over a closure whose writes are their own calls), `NewUserStateProbe` and `InvalidateAuthorsCache` (an in-memory cache) write nothing themselves; `MarkBookAggregatesBackfillDone` (the `system:backfill:` sentinel) and `ReplaceOpRowsPrefix`, `SaveClassLists` and `ClearClassLists` (op rows) write ledger and store-maintained rows that belong to no Effects resource. Those pass unfenced and the CALLER owns the mode and the permit (for example `internal/maintenance/jobs/recompute_book_aggregates.go` checks the mode first); behaviour is as before the gate. None is a `metafetch.Store` method and the metafetch tests require every gated method to have a non-empty row. **F5-18c obligation:** the group writers are built on `Gate`, so each group must decide whether its empty-row methods may stay outside the fence or need a stamp of their own (a `Gate.Do` of an empty row is not a fenced write); `TestGate_UnknownEmptyAndPreview` pins today's behaviour, including that the run's Preview does not stop one. `SharedRows()` is `resources.Table()`; `Merge` unions tables and fails when two disagree.
- `internal/books/writer/writertest.Writer`: the Effects-enforcing `tasks.Writer` the native kinds' tests run over. `core/internal/executor` is internal to the core module and cannot be imported, and `taskstest.FakeRun.Writer()` is nil, so every ABO test host brought a writer of its own that checked nothing. This one calls `tasks.CheckWrite`, the same function the executor calls.
- `internal/books/writer/metafetchgate.Store` wraps a `metafetch.Store`: all 33 write methods are one gated call each, the 35 read methods are promoted, and the read capabilities the fetch service's consumers resolve are forwarded (`capabilities.go`, round 3). `metafetch.NewService(metafetchgate.Wrap(ctx, inner, writer.New(w, rows)))` is the fetch service F5-18's native writer builds per run over the run's writer.

## Seams

- 15 `metafetch.Store` writes had no row in the shared table: the 14 methods of `writer.MetafetchApplyRows()` plus `SetRaw` (the shared table has no unqualified `SetRaw` row; the raw writes are qualified by key family in `writer.RawFamilies()`). If F5-18 routes the rejection helpers through the gate it adds `rejected_candidate:` to `RawFamilies` with the resource it decides on; until then both keys are in no family and are refused (`TestRejectionKeysAreInNoRawFamily`).
- O9 result: the real apply of `resolve-production-authors` and of `auto-match-transcribed`, over a real store and the real `metafetch.Service`, was not refused. - The gated store is opaque to capability lookups, so its capabilities are classified, not remembered (round 2, m2; round 3, M1). `metafetchgate.Store` embeds `metafetch.Store` and has no `Unwrap`, so `database.AsCapability` finds only the wrapper's own method set (the hazard class of `internal/books/store/store_capability.go`). Code the fetch service hands its store to resolves optional capabilities that way, and a capability the wrapper lacks reads, to that code, as a store without it. Round 2 pinned four WRITE capabilities as hidden and listed them as the whole set; it was not: the apply's author resolution (`authorcredit.ResolveBook`, `service_apply.go`) resolves four optional READ capabilities, and hiding them silently changes what the apply writes (a two-part credit with an alias-only part mints one combined author row instead of linking both authors; a title-named part is not dropped; the provider-credit and outside-series evidence is gone). Round 3 classifies every capability the consumers resolve, in `TestStoreCapabilitiesAreClassified` (`capabilities_test.go`), and `TestEveryCapabilityTheConsumersResolveIsClassified` scans the source of the consumer packages (metafetch, organizer, tagger, fileops, foldernames, versionprimary, authority, authorcredit, each with every package below it) and fails on a site that is in no row, or a row no site uses any more. Round 4 closed the scan's blind spots (m2): it records `AsCapability[T]` calls, calls of the store-package helpers that resolve one (under whatever name the file imports the store package), BARE type assertions and type-switch cases (`assert x.(T)`, `switch x.(T)`: through the opaque wrapper they see what `AsCapability` sees), and treats as a helper any store function that names `StoreUnwrapper` (`AsSeriesRefGetter` walks decorators by hand and never calls `AsCapability`), any `As*` function that type-asserts, and anything calling one, to a fixed point. The eight bare assertions the consumers make today are not on a store (two context values, two metadata-source checks, a cache, the title source's cache key, the authority provider, an authority listing) and are listed with their reasons in `nonStoreAssertions`; a new bare assertion fails until it is a row or listed there. The scan's own behaviour is tested on source it is given (`TestScanSeesEveryShapeOfResolution`, `TestHelpersOfRecognisesEveryShapeOfResolver`, `TestParseTreeDescendsIntoSubpackages`). Its limits: the package list is the one-hop set (what metafetch hands the store to, plus every call a consumer makes into `dedup`, `scanner`, `merge`, `undo`, `operations` and `catalog`, checked by hand to not be given the fetch store); a capability resolved by reflection (`MethodByName`) or through a generic wrapper local to a consumer is not a shape it knows (the second still fails loudly: its `AsCapability[T]` sink is in no row). `authorcredit`'s four interfaces are exported (`TitleSource`, `HistorySource`, `AliasFinder`, `AuthorBooksSource`) and the wrapper asserts at compile time that it still satisfies each, so a change to what authorcredit asks of a store is a build error in `metafetchgate` and not a capability that quietly stops matching a private copy. The classes:

Two differences from a bare store without the capability. (1) A consumer that tells "no capability" from "capability, empty answer" (authorcredit adds its by-author evidence source when the capability is present) now gets the source with an empty answer, which contributes no evidence, as the absent source does. (2) `authorcredit.TitleSource` is synthesized: the wrapper always has `GetAllSeries` and the promoted `GetAllBooksCore`, so it is a `TitleSource` even over an inner store with neither layer offering one; the bare store would have no title index (the title check is skipped), the wrapper builds a books-only index and the check runs.   - The two file-work reads (`RetiredBookFileReader`, `FileHashHolderLookup`) are pure reads and are forwarded rather than left hidden: hiding them made a collision lookup or an organize refuse through the gate that the ungated service would have completed.
