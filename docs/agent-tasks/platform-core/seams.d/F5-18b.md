# F5-18b seams and coined names

F5-18b builds the run-time write fence for a store call that writes several resources (owner decision 2026-11-18: run-time fence only, no compile-time narrow writer types per kind). It is dark: nothing on a live path calls any of it until F5-18 wires the kinds. The obligations: O9, O17, O26, O27.

## What was built

- `tasks.Write.Resources` (`core/tasks/writer.go`) is the stamp set. `Write.Stamps()` is `Resource` (when set) then `Resources`, repeats dropped; a zero ref inside `Resources` is kept so the fence refuses it. `Resource` stays for callers that name one resource (`core/outbox`, `core/updater`, taskstest), and `Resources` is `omitempty`, so the persisted intent of a one-resource write encodes as before.
- `tasks.CheckWrite(kind, declared, write)` is the one fence predicate: it refuses an empty stamp set, any undeclared stamp and a zero stamp, wrapping `ErrOutsideEffects` and naming the kind and every refused stamp. `tasks.Covers` is its membership test (a declared ref with no ID covers every ID of its module and kind; a declared ref with an ID covers only that ID, and not the whole kind). `core/internal/executor/writer.go` calls `CheckWrite` in the same place the old single check ran (after the writable check, before `renewHolds` and the intent, in Preview and Live); `declared()` in `start.go` now delegates to `Covers`.
- `internal/books/writer`: `Gate` (`New(w, rows)`, `Stamp`, `Do`) turns one store method call into ONE `Writer.Do` stamped with the method's whole row, named `books.<Method>` (a raw write is `books.SetRaw/<family>`). A method with no row is refused (`ErrNoRow` and `ErrOutsideEffects`) without calling fn. A method whose row is empty writes nothing itself, so fn runs with no `Do` and no fence: the shared table has seven such methods (`HardDeleteWithoutUserState`, `NewUserStateProbe`, `InvalidateAuthorsCache`, `MarkBookAggregatesBackfillDone`, `ReplaceOpRowsPrefix`, `SaveClassLists`, `ClearClassLists`); none is a `metafetch.Store` method and the metafetch tests require every gated method to have a non-empty row. `SharedRows()` is `resources.Table()`; `Merge` unions tables and fails when two disagree.
- `internal/books/writer/writertest.Writer`: the Effects-enforcing `tasks.Writer` the native kinds' tests run over. `core/internal/executor` is internal to the core module and cannot be imported, and `taskstest.FakeRun.Writer()` is nil, so every ABO test host brought a writer of its own that checked nothing. This one calls `tasks.CheckWrite`, the same function the executor calls.
- `internal/books/writer/metafetchgate.Store` wraps a `metafetch.Store`: all 33 write methods are one gated call each, the 35 read methods are promoted. `metafetch.NewService(metafetchgate.Wrap(ctx, inner, writer.New(w, rows)))` is the fetch service F5-18's native writer builds per run over the run's writer.

## Seams

- 15 `metafetch.Store` writes had no row in the shared table. Their rows are traced by hand in `writer.MetafetchApplyRows()` (14 methods) and `writer.RawFamilies()` (the raw key-value writes, qualified by key family), and each is checked against the real store's key diff in `TestF518b_LocalRowsCoverWhatTheStoreWrites`. They belong in `resources.Table()`; `internal/maintenance/resources/resources.go` is outside this row's files, so they are kept here, and `TestMerge_And_MetafetchApplyRows_AgreeWithTheSharedTable` fails if one ever differs from the shared row. Moving them is then a deletion. The rows: AddBookTagWithSource and RemoveBookTagsByPrefix `books`; CreateSeries `series`; Upsert/DeleteMetadataFieldState `field_states`; RecordMetadataChange `operations` (as F5-06 filed it); PutMetadataCache `metadata_cache`, `indexes`; RecordPathChange `books`; FlagMetadataHashDuplicate and SetLastWrittenAt the whole book write; MarkNeedsRescan and PatchBookFileFields the book write plus `book_files`; Set/DeleteUserPreference `user_state`.
- The shared table's unqualified `DeleteRaw` (`user_state`) and `DeleteRawBatch` (`authority_lists`) rows describe other callers. metafetch's raw writes are the fetch cache (`metadata_fetch_cache:`, `pcache:`: `metadata_cache`) and candidate rejections (`metadata_rejection:`: `books`), so the decorator stamps those by key family and refuses a key in no family, and a `DeleteRawBatch` that spans families, instead of borrowing the unqualified rows. A new raw write fails closed.
- O9 result: the real apply of `resolve-production-authors` and of `auto-match-transcribed`, over a real store and the real `metafetch.Service`, was not refused. Stamped resources: `authors`, `series` (resolve only; the second kind's apply is limited to title and author), `books`, `indexes`, `metadata_cache`, `operations`, `field_states`. All are inside both kinds' declared `Effects`, and every resource the store diff shows changed was stamped. No Effects were narrowed or widened. What the test cannot show: `book_files` is declared by both kinds but this apply never wrote it, and file work after an apply (below) is not wired, so a path that does run it (tags, cover, rename via the file pipeline: `user_state` checkpoints and `files`) may stamp `user_state` or `files`, which neither kind declares. That is the first thing to check when F5-18 wires file work; do not narrow or widen the declarations before then.
- Unfenced writes: the gate covers writes through `metafetch.Service`'s store. Not behind it: file work after an apply (`FinishApplyFileWork`: cover download, rename, tag writing) which the tests leave unwired; activity-log writes; the post-apply duplicate check goroutine (`CheckBookDuplicates` after `folder-auto-scan`, already noted in F5-13); the cache invalidation hooks; and the search reindex, which is in memory.
- `metafetch.Store` read methods are promoted from the embedded inner store, so a write added to the interface later would be promoted ungated. `TestEveryStoreMethodIsClassified` lists every method as gated or read and fails until a new one is classified; `TestNoGatedMethodReachesTheStoreWhenTheWriterRefuses` calls every gated method over a nil inner store and a refusing writer.
- Import shape: the generic gate is in `internal/books/writer` and imports no `internal/metafetch`; the metafetch decorator is its own package. `internal/metafetch`'s import closure already reaches `internal/operations/opswriter`, which F5-18c renames into `internal/books/writer`: if `writer` imported metafetch, that move would be an import cycle. Keep it this way. Layer entries: `writer` and `metafetchgate` 3, `writertest` 0 (`internal/arch/layering_test.go`).
- The store-diff helper `t6g5KeyFamilyResource` (`kinds_t6_g5_storediff_test.go`, another row's file) has no resource for the key families `metadata_change:` (`operations`), `series:` (`series`) and `preference:` (`user_state`). The F5-18b tests map them locally (`f518bExtraFamilies`); they belong in that map.
- The real-kind tests live in package `maintenance` because they reuse `t6g1Host`, `t6g1LiveProbe` and the `t6g5` store-diff helpers. They build the two fetch adapters themselves (a few lines each, as `server.FetchMetadataByTitle` and `ApplyTranscriptionCandidate` do) because `internal/server` cannot be imported from the plugin's tests. `ApplyTranscriptionCandidate`'s read-side guards write nothing and are not repeated.
- Deadcode: the new exported identifiers are reachable from tests only (nothing in a `main` calls them until F5-18), and are baselined in `scripts/deadcode-baseline.txt`, as F5-09, F5-11 and F5-13 did.
- Compile-time narrow writer types (the TODO-F5-10-NARROW-WRITER-TYPES entry) were not built, as decided.

## Proves

- Every row of the method tables: declared whole it is admitted as one write stamped with the whole row; declared minus any one resource it is refused naming that resource, fn not called, nothing recorded (`TestGate_EveryRowIsFencedOnEveryResource`, over `resources.Table()` plus the local rows).
- The three blind spots: `TestF518b_BlindSpot_WriteThatChangesNoKey`, `_DeleteOfAnAbsentKey`, `_KeyCreatedAndDeletedInOneWindow`: each shows the key diff empty on a real store and the gate refusing; `TestF518b_OneTagPerWriteAdmitsWhatTheWholeRowRefuses` shows the old single-tag stamp admitting a ModifyBook a kind declared only `books` for.
- The executor's fence: `TestWriter_FenceChecksEveryStamp` (12 cells, Preview and Live; undeclared first, middle, last, alone, other module, empty, zero ref), `TestWriter_IntentRecordsEveryStamp`, `TestWriter_FenceHonoursIDRefs`.
- Both kinds through the enforcing writer, and `TestF518b_EveryStampedResourceIsLoadBearing` (removing any stamped resource from the declaration makes the apply refuse).
- Mutants (each run in place against the targeted tests, the file restored after, `git diff` of the sources empty):
  - the fence (`core/tasks/writer.go`, `core/internal/executor/writer.go`): 16 of 16 killed.
  - `internal/books/writer/gate.go` and `rows.go`: 28 of 28 killed. Three of the 28 (an unknown method passing through to fn, Merge ignoring a conflict, PatchBookFileFields losing its book writes) did not compile in the first pass, so they were re-written as mutants that compile and re-run: all three are killed. The first pass ran only the writer package's tests and six survived it. Four (PutMetadataCache losing `indexes`, RecordMetadataChange or CreateSeries stamped as `books`, AddBookTagWithSource stamped as `metadata_cache`) are killed once the maintenance row-truth test runs against the real store. Two needed a stronger test, as did the re-written PatchBookFileFields mutant: MarkNeedsRescan losing `book_files` and PatchBookFileFields losing its book write both survived the row-truth test, because its file sat at a path the book did not own (the store mirrors the rescan flag onto a file row only when the book owns exactly that one file) and the patch left the book's size aggregate unchanged. The cases now build the one-file book and the stale aggregate, and `mustWrite` names `book_files` and `books`; both are killed. SetLastWrittenAt narrowed to `books` is the one mutant no behaviour of the real store can kill: the row is wider than what its closure touches by the shared table's rule (a ModifyBook call lists everything ModifyBook can write), so it is killed only by `TestMetafetchApplyRows_ModifyBookRulePinned`, which pins the rule. That test is a pin of the convention, not of the store.
  - `internal/books/writer/metafetchgate/store.go`: 12 of 12 killed (a method stamped as another method; a raw write named for the wrong kind; DeleteRaw stamped as SetRaw; a batch spanning families allowed; the empty-batch path removed; the run context dropped; a write that bypasses the gate; a wrong subject kind; a wrong subject id; the nil guard removed; a raw family matched by substring). Three survived the first pass (the two subjects and the substring match) and are answered by `TestGatedMethodsStampTheSubjectTheyAreAbout` and `TestRawKeyFamilyIsAPrefixNotASubstring`; the stamp-name check is in `TestNoGatedMethodReachesTheStoreWhenTheWriterRefuses`.
