# F2-10 seams and coined names

This file lists what the health readiness core PR added beyond 05-health §5H.3.1's Go block, the readings it took where the spec or the brief is silent, and the seams later rows build on. Everything not listed here follows §5H.3.1 as written.

## Names beyond the spec

| Name | What it is |
|---|---|
| `health.NewRegistry()` | The constructor the brief coins. |
| `health.InvalidReason` | The fixed Reason (`invalid_reason`) that replaces a Reason outside `[a-z0-9_]{1,40}`. |
| `health.Status.String()` | Lower-case status name. |
| `kernel.buildHealth(store enginePinger) (*health.Registry, kernelReporters, error)`, `kernelReporters{Storage, Secrets}`, `enginePinger` | The kernel-side registration F2-16 calls at boot once the store is open. `enginePinger` is satisfied by `*storage.Admin` (`storage.DB.Admin()`). |
| `system.HealthPostureTokens(r *health.Registry) []PostureToken` | The bridge. A provider handed to `WithPostureTokens` / `Server.SetPostureTokens` appends it to its own tokens. |

## Readings

| Topic | Reading |
|---|---|
| Reason grammar | Clamped, not refused: `Reporter.Report` has no error return, and a component must still be able to say Down. The text of a bad Reason is dropped, never copied into `Detail`. |
| `ComponentID` grammar | `Register` refuses an ID that is not two or more dot-separated segments of `[a-z0-9_-]` starting with `[a-z0-9]`. The spec states only the `"<moduleID>.<name>"` shape. |
| Readiness tokens | A Readiness component that is not Up or Degraded, and a Critical one that is Down, give `"<component>:<reason>"`; an empty Reason is `down` (Down) or `unknown` (Unknown). A Critical component that is Unknown does not hold readiness; the spec says "Down => not ready". |
| `Live()` | True while the registry exists: no heartbeat before F8. |
| `Snapshot()` | Exported with the spec's shape, because the bridge enumerates components with it. `Startup` stays empty; the HTTP use is F8's. |
| Probe at `Register` | One synchronous call under `Check.Timeout` (5s default; `core.health.check_timeout` is F8's key). A panic yields Down `probe_panicked`. Never called again before F8's loop. |
| `Wait` on an unregistered ID | Blocks, so a later `Register` can still release it. A satisfied `Wait` returns nil even on a cancelled context. |
| The bridge | `HealthPostureTokens` puts each component's Reason in `degraded` and `degraded_details` with the component ID as `Subject`. `Detail` is not copied: it needs F8's redaction first. |

## Seams for later rows

- **F2-16:** call `buildHealth(admin)` after the store opens (`k.store.db.Admin()`), keep the registry and `kernelReporters` on the kernel, and compose `system.HealthPostureTokens(registry)` into the provider `internal/books` hands `Server.SetPostureTokens` (`internal/books/options.go`, `Attach`). Neither is wired at F2-10, so nothing is raised in production.
- **F3 (IMPL-12):** a component holds one `Result`, so one Reason at a time. `core.secrets` can therefore carry `secrets_undecryptable` or `secrets_keyring_not_exported`, not both at once, and `PostureToken` has no `orphaned_refs` field for `storage_quarantine`. If F3-03 needs both secrets tokens live together, or the `orphaned_refs` count on the authenticated route, `Result` and `PostureToken` grow there; the golden test's F2 cells are one cell per secrets token for this reason.
- **F8:** the probe loop replaces the register-time call; `Snapshot` gains its HTTP route; `Detail` goes through redaction before it joins `degraded_details`.
