# F6-03 slice E4 seams (dark kernel realtime hub)

What slice E4 (#4817) built, where it differs from the F6-03 pre-scope, and what the wiring slice (G2) must know. A separate file from `F6-03.md` (E6a, #4814) so the two PRs never touch the same file.

## Shape

- `core/kernel/realtime.go` is dark: `newKernelRealtime(cat, settings func() realtimeSettings, a realtimeAuth, p, l, now)` builds the hub; `subscriptions()`, `run` and `closeOnShutdown` are the P7, Run and listener hooks. The order G2 follows is on the `kernelRealtime` type comment.
- `realtimeAuth` is `realtime.Revalidator` plus `Refresh`; `*auth.Service` satisfies it (compile-time assertion). The hub's `Deps.Refresh` is `auth.Service.Refresh` passed through as is; the kernel has no refresh logic of its own (seams.d/F4-08-refresh.md).
- `core/internal/httpmw/writer_chain_test.go` pins that `SetWriteDeadline` and `Flush` reach the connection through the perimeter chain (`Chain.Outer` and `Chain.Route`, four hookWriters and the gzipWriter) over HTTP/1.1 and HTTP/2, and that the deadline is enforced. It does not cover the router and route group (todo.d, G2).

## Declared mismatches and their rulings

1. **Missing control topics are an error, not a warning** (ACCEPTED). The pre-scope's 11-19 correction says `Hub.Subscriptions` only warns. It returns an error unless `AllowNoControlTopics` is set; the kernel keeps the flag off and surfaces the error as a core `ProblemInvalidRegistration`.
2. **ring_size 4096 is a floor, a stopgap** (round 1, m1). E4 does not edit `core_sections.go` (#4765 does), so `realtimeOptions` raises any `core.realtime.ring_size` below 4096 to 4096. Raising the section default (1024, or unset) logs at info; overriding any other configured value logs a warning naming the configured and used sizes. todo.d: raise the default to 4096 in `core_sections.go` and the 05-realtime §8 row after #4765, then delete `realtimeRingFloor` and `realtimeRingDefault`.
3. **`core.realtime.max_coalesce_keys` is not consumed** (round 1, m3). The bus's coalescer has no key bound and the hub no option for it. todo.d, owned by `core/events`.
4. **Compat and identity-extension principals are refreshed by auth** (round 1, M1; fixed in this PR). The first cut refused every principal but session, key and auth-off, because auth kept a compat key's ID unexported. With production's `ext:cfaccess` extension at Order 150, ahead of the session authenticator, every Cloudflare Access stream would have ended `credential_revoked` at its first heartbeat. Now `auth.Service.Refresh` rebuilds every method auth builds, never widening (seams.d/F4-08-refresh.md).
5. **No mount helper** (ACCEPTED). `eventhttp.Register` on `CoreGroup` is G2's.

## Hot reload (round 1, m2)

`max_clients`, `max_per_bucket`, `write_timeout` and `retry_after` carry no `reload:"restart"` tag, so they must reach a running hub. The kernel sets `realtime.Options.Live` to a closure over the section getter (as `newKernelOutbox` reads outbox settings on each use). The hub resolves each field per use: zero is the default, out of range keeps the value it was built with and warns at most once a minute. The hub passes the three broker limits to `sse.Options.Limits`, which the broker reads at each `Subscribe` (caps), before each write (deadline) and at each interrupt (grace), never under its own lock or a stream's write lock. Lowering a cap ends no open stream; it applies to the next one. `ring_size`, `client_buffer` and `heartbeat` stay restart-only.
