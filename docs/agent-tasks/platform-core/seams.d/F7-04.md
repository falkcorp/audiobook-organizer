# F7-04 seams and coined names

This file lists what the core download contract and Deluge adapter PR (05-download phase 1) added beyond the Go blocks of the spec: the readings it took where the spec or the brief is silent or contradicts itself, and the seams later rows build on. Everything not listed here follows the spec as written.

## Seams later rows must honour

| Seam | What F7-04 does | Who builds on it |
|---|---|---|
| Path mapping is download-local | 05-download §4.4 has the Pool apply `library.PathMapper` through `Env.Paths`. `library.Path`, `library.PathMapper`, `library.Mapping` and `ErrUnmapped` do not exist yet (F7-06 and the library rows after it), and F7-01 left `Env.Paths` out. So `core/integrations/download` carries its own `LocalPath` (a string type, zero value = unmapped), `Mapping{Remote, Local, Fold}`, `PathMapper` (`ToLocal(source, remote)`, `ToRemote(source, local)`), `Mappings func(source string) []Mapping`, `NewMapper`, `Source(id) = "download:<id>"` and `ErrUnmapped`. The semantics are the spec's: longest prefix, separator boundary, Fold for Windows remotes, no mapping means unmapped. There is **no** identity-under-root fallback: that needs the library roots of F7-06. `Item.LocalPath` and `File.LocalPath` are `download.LocalPath`, not `library.Path`. | **F7-06 / F7-09** re-type `LocalPath` as `library.Path` and either feed `Mappings` from `core.library.mappings` (Source `download:<instance>`) or replace `PathMapper` with the library's. If F7-06 ships its own mapper, delete the duplicate here. |
| `Pool` construction | `NewPool(reg *integrations.Registry, PoolOptions{Paths, CapsTTL, Parallelism, Metrics, Now, Logger}) (*Pool, error)`. The spec shows Pool as per-App and leaves construction to the kernel. `CapsTTL` defaults to 1 hour; the key `core.download.caps_ttl` is **not** declared (no `core.download.*` key exists in phase 1), so the kernel passes the value. `Parallelism` (default 4) bounds `Relocate`'s fan-out over instances. | F7-09 builds the Pool, wires `module.Deps.Downloads`, and passes `Paths` and `Metrics` (`p.Core("download", "adapter", "instance")`). |
| `Pool.Items` is per instance | `Pool.Items(ctx, ref, filter)` reads one instance (the spec's signature). Cross-instance discovery (the ABO discovery label, 05-download §10) is the caller looping `Instances(proto)`. | F7-08/books. |
| `Instances(proto)` learns protocols lazily | The signature has no ctx, so the Pool cannot fetch Caps there. It learns an adapter's protocol from the first `Caps` any call fetched (`Files`, `Relocate`), and lists an instance whose adapter has not answered yet for every protocol. Phase 1 has torrent adapters only, so the answer is exact today. A protocol 0 lists every instance. | The phase-2 monitor (which polls Caps up front) or an F7-09 warm-up makes it exact for mixed protocols. |
| `RawUnknownState` | The adapter holds no metrics handle (an `Env` carries none), so an adapter marks an item whose state its table does not know with `Item.Raw[download.RawUnknownState] = <client's value>` (and reports `StateWarning`). The Pool counts those in `mediacore_download_unknown_state_total{adapter}`. | Every download adapter; `coretest.DownloadConformance` pins it. |
| Health is read-only | 05-download §4.1 says the Deluge health check is `web.connected` "and connect to the first host when false". `Instance.Health` must not change the remote, so `Health` logs in and reports a Web UI with no daemon as `HealthDegraded`; connecting to the first host (`web.get_hosts`, `web.connect`) is in `Tester.Test`, which `Registry.Test` runs. | F7-10 (routes) shows the degraded reason; an operator presses Test to connect. |
| `daemon_password` is declared and unused | The spec names `daemon_password` as a secret field of the Deluge adapter and the migration (§10) moves HEAD's `download_client.torrent.deluge.password` into it. Phase 1 does not read it: the Web UI connects to its daemon with the host entry it stores. It is declared so F7-08's migration has the field to write. | F7-08. |
| No identity password default | HEAD defaults the Web UI password to `deluge` when none is set. The adapter requires `password` (a secret field without `omitzero`) and sends nothing when it is missing: the instance reports `HealthMisconfigured`. | F7-08 migrates the password explicitly. |
| `TestDeluge_PrivateHostNeedsLocal` | providerhttp (F7-02) does not exist, so the egress guard's refusal cannot be exercised. The test pins the half F7-04 owns through a real Registry and the `integrationstest` outbound fake: the adapter's `Meta.Egress` is `EgressConfigured`, a private origin is absent from `OutboundSpec.Trust.PrivateOrigins` until an interactive admin sets `Local`, and every request leaves through the injected `integrations.HTTP` to the configured origin's `/json`. | **F7-02** adds the refusal half (a private address with no `Local` fails in the guard) against `core.deluge`. |
| The adapter uses `env.HTTP.Do` with its own cookie jar | `integrations.HTTP.Client()` is documented "for SDKs" and returns a client without a jar, so the adapter keeps one cookie jar per instance and attaches the session cookie itself, sending through `Do` so the gate and egress guard apply. No `http.Client.Timeout` is set; each call has a 30 second context limit (= `Meta.Limits.Timeout`). | F7-02 may add a jar to the guarded client; the adapter then drops its own. |

## Hardening recorded after the security scan

- `PathMapper.ToRemote` appends host segments in the client's syntax, so each must be one plain name there (Windows remote: no `.`, `..`, backslash, slash, colon or NUL; POSIX remote: no `.`, `..` or NUL); the result is parsed back and must keep the mapping root and add exactly those segments. `ToLocal` joins client segments through `joinUnder`, which refuses `.`, `..`, NUL, separators and (on a Windows host) backslash and colon, and checks the result is the Local root plus exactly those segments. A refusal is `ErrUnmapped`.
- The Deluge client sends through a copy of `env.HTTP.Client()` (same transport, so the gate and dial guards apply) with `CheckRedirect` returning `http.ErrUseLastResponse` and no jar; an `HTTP` that offers no `*http.Client` is used through `Do`, and its own redirect policy then applies. Any non-200 answer, a 3xx included, is a `statusError`; the Location is never followed or reported. No text of an `auth.login` answer is kept in any error (status excerpt, decode excerpt and parser text, RPC message are all dropped). For every other method the whole body (and an RPC error message, and a result excerpt) is scrubbed of the password before it is cut to the 200-byte excerpt: the plain form, JSON string escapes (with and without HTML-safe escaping), HTML entities, URL query and path encoding, those applied twice, and lowercase percent-hex. The password is read from core secrets when an excerpt is built, not retained; if it cannot be read no text is kept.
