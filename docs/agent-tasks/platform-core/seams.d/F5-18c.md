# F5-18c seams and coined names

F5-18c builds the books module's dependency values for the converted maintenance groups, dark: nothing calls a builder until F5-18 hands its result to a group's Kinds function. Obligations: O1 (wiring half), O2, O15, O16, O21, O29 (partly: see "Not done").

## What was built

- `internal/plugins/maintenance/deps_gate.go`: the shared pieces of every builder. `booksGate` wraps one `writer.Gate`; a nil run writer (a ReadOnly kind) becomes `noRunWriter`, which refuses every gated write wrapped in `ErrOutsideEffects`; `srcCap` resolves one optional capability through the decorator chain or names the one a store lacks; `reportPathOver` is the confining report-path resolver (`library.ReportPathNotify`) for a library root.
- `deps_t6g2.go`, `deps_t6g3.go`, `deps_t6g4.go`, `deps_t6g6.go`: `newT6G<k>Deps`. Each store serves the group's reads and resolves optional capabilities per call; each writer makes every method one gated call stamped with the method's whole row. A nil input leaves the dependent field unset (g2 `Store`/`NewWriter`, g3 `NewWriter`, g4 `Store`/`NewWriter`/`Stats`, g6 `NewWriter`/`ResolveReportPath`), so the group's own refusal fires.
- g4 `Stats` is a best-effort sink over the `FileIntroStatsStore` and `TranscribeStatsStore` capabilities, built only when a source exists. `TestBooksT6G4Deps_NilStatsStaysNilSoRegistrationStillRefuses` pins that `t6g4Kinds` still refuses a nil `Stats` through the builder (the named `TestT6G4Kinds_RegistrationRefusesNilStats` is unchanged).
- `deps_jobs.go`: `newJobsDeps(src) (jobs.KindDeps, error)`. `booksJobsStore` satisfies `jobs.Store`: 41 reads through an embedded read-only interface (`jobsReads`, no method of which has a row), 27 gated writes, and the capabilities the jobs package asserts on its store, implemented on the wrapper. The capabilities are resolved once at build; a source that lacks any gets no `NewStore` and an error naming them, which fails every run before the job starts.
- `metafetchgate.Store` embeds the inner store through the unexported alias `innerStore` (the #4772 r4 minor); the no-hand-back test covers fields.
- Deadcode: the builders, the gate helpers and the store and writer methods are reachable from tests only until F5-18 calls them; the new identifiers (43 g2, 56 g3, 120 g4 and g6, 57 jobs) are baselined in `scripts/deadcode-baseline.txt`, as F5-09, F5-11, F5-13 and F5-18b did. F5-18 deletes the lines as it wires them.

## Decisions

- Context. The `t6gNDeps.NewWriter(w)` factory carries no run context, and several writer methods take none. Those methods gate on `context.Background()` (`runless()`). The executor's writer refuses on the attempt's own stop, fence and hold, not on the context it is handed, so the stopped-run refusal does not depend on it. Threading `rc.Context()` into `NewWriter` would re-sign the factory of five groups and every test that builds one; it was not done.
- Error-less methods. A write method with no error result cannot return a refusal. The builder logs the refusal and the method returns the zero value (`gateQuiet`; g3 `ActivityFlushOp`, `CleanupOrphanedTempFiles`, `CleanupStaleTempFiles`, `InvalidateAuthorsCache`, g6 `HealWhisperJournal`).
- Empty-row methods stay unfenced (`Gate.Do` runs fn with no `Do`) and the caller owns the mode check. g3 has some (pinned by `TestBooksT6G3Writer_EmptyRowMethodsStayUnfencedAndTheCoreOwnsTheMode`); g2 has none (`TestBooksT6G2Writer_EveryCallIsOneStampedWrite`). The jobs store's `MarkBookAggregatesBackfillDone` is one: the job marks only after a live run.
- `SaveClassLists` stores the class lists in a preview, unfenced, as before the gate: the credits backfill derives `Apply` from the live mode, so the judged-marker write (`ReplaceOpRowsPrefix`) is unreachable in a preview.
- O29, "embed or `Unwrap`": F5-18b settled it as no `Unwrap` (a bypass; `TestNoMethodHandsBackTheInnerStore` pins it). The jobs wrapper follows it, which is why the capabilities are implemented on it instead of reached through `AsCapability`.
- Group 6 and group 4 builders take `OpsStore` (the narrowed ops interface) as their source and resolve what is not on it through capabilities.
- g6's iTunes heal writes delegate to `reconcile.NewHeadHealWriter`, a "Head"-named export in the reconcile package, because `collapseHealDuplicates` and `healTrack` are unexported. F5-18 must check it survives the HEAD adapter deletion.
- `OpenWhisperJournal` (g4) and `HealWhisperJournal` (g6) stamp at open only: the journal's own appends are not individually fenced.
- Raw writes on the jobs store. `SetRaw` has no row (a different key family on every interface) and bare `DeleteRaw` is `user_state`. The wrapper picks the row from the key's prefix (`jobsRawFamilies`: the merge package's combine journal, undo-applied, group redirect, pending user-state repair and survivor-reconcile prefixes, and retention's dead `book:series:` and `book:author:` indexes) and refuses a key in no family. The prefixes are copied from unexported constants in `internal/merge`; nothing but review keeps them equal.

- `MetafetchApplyRows` `bookW` drops `ops.ResAuthors` (`internal/books/writer/rows.go`), so it matches the `ModifyBook` row F5-18j (#4792) narrows in the shared table (the store no longer stages `author_books_legacy:` rows). `TestMetafetchApplyRows_ModifyBookRulePinned` fails on this branch alone and passes once #4792's `resources.go` is applied (checked by overlaying its file); whichever of the two PRs lands second needs no further edit. F5-18j's seam file should carry the same sentence.

## Not done in this row

- The jobs store's capability set is partial. Implemented: `SyncIdentityStore`, `SyncFileStore`, `BookmarkStore`, `ModifyBookFileDeferAggregates`, the aggregates sentinel, `SeriesUnreferencedDeleter`, `SeriesDeleteReadiness`, `SnapshotPrunePlanner` and `BookFileHashUpdater` (scan-composer-tags' recorder). Missing, so a job that needs one does not work on this wrapper: the chapter-group set merge-chapter-groups asserts (`UserProgressMerger` and its `playCountMarkStore`, `ListUserPlaylists`, `LiveBookPathsUnderDir`, `ListActiveOperationsV2`, and `dedup.Store`, 52 methods of which 15 write) and the assertions inside `internal/merge` on the store it is handed (`syncMergeClearer`, `syncRedirectClearer`, `UserPositionReplacer`, `UserBookStateDeleter`, `StrictUserLister`, `UserPositionTimestampWriter`, `ExternalIDReassigner`, `JournalPointerWriter`, `opChangeScanner`, `pendingRepairScanner`, `rawGetter`, `rawDeleter`, `BookmarkCopier`). The list is derived by grep of the jobs package and `internal/{merge,dedup,fileops,versionprimary}`; it is not proven closed. A `jobs.Store` write method can only be added with a row in the shared table.
- `sweep-pebble-metrics-ttl` cannot work on this wrapper. It builds its store with `database.NewPebbleMetricsStoreFromStore(store)`, which needs `AsPebbleStore`, i.e. an `Unwrap` chain to the raw store, and the sweep then writes through that store, unstamped. `TestBooksJobsStore_NoUnwrapAndNoPromotedStore` pins that it resolves nothing and the job would skip. The fix is a narrow sweeper capability the job takes from its store (a change in `internal/maintenance/jobs`, outside this row's files).
- The per-job proof that each job's declared Effects contain the row of every method it calls is the jobs package's `TestJobWrites_TraceMatchesCode` (`jobTraces` is unexported); this row proves each wrapper write is one stamp of its own row, admitted under exactly that row and refused under an empty declared set.
- The deps builders for groups 1 (`NewWriters`) and 5 (`ScanKey`), the other plugins' `KindDeps` and the T7 `t7Deps`: not in the plan's Covers list for this row; the parent brief's commit 1 says "every".
- The `opswriter` rename is left to F5-18 commit 1: `opswriter.New` collides with the new gate's `writer.New`, it has 11 live non-test importers, and it is not dark.
- The O29 half about the live write table being wrong (three jobs write book rows and declare only book files) is not addressed.
- The F5-18a seam file is not on this branch.
