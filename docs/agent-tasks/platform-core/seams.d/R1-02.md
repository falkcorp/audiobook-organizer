# R1-02 seams and coined names

Names the required-check PR added that later rows may rely on (implementation plan §(n) rule 5).

## Required checks (the job `name:` is the check name the ruleset requires)

| Name | Where | What it is |
|---|---|---|
| `extraction-gates` | `.github/workflows/extraction-gates.yml` | Terminal job, `if: always()`: fails when any job in its `needs` is `failure` or `cancelled`; `skipped` is success. **A later row that adds a gate job adds it to this job's `needs`**; `test_extraction_gates_terminal_job_fails_on_failed_or_cancelled` fails when one is missing. R1-10, R1-23, F2-14 and F2-15 are those rows. |
| `check-commits-build` | `.github/workflows/extraction-gates.yml` | The one gate job at this PR (`timeout-minutes: 30`). Not itself a required check name. |
| `extraction-gates-changes` | `.github/workflows/extraction-gates.yml` | The workflow's own copy of the `changes` classifier (job id `changes`), named apart from ci.yml's `Changes`. The `Classify changed paths` step is a verbatim copy; `test_extraction_gates_copy_is_identical` fails when the two differ. |
| `vet-darwin`, `vet-integration` | `.github/workflows/ci.yml` | Required PR jobs, each `make <target>`, `if: needs.changes.outputs.go == 'true'`, `timeout-minutes: 15`. |

## Make targets, scripts, gates

| Name | What it is |
|---|---|
| `make vet-darwin` (new), `make vet-integration` (now per module) | Loop over `GO_MODULE_DIRS` with `go -C $d vet`; `vet-darwin` sets `GOOS=darwin CGO_ENABLED=0` and never `embed_frontend`. Both are `make ci` prerequisites. |
| `scripts/ci/check_commits_build.py [--base REF] [--head REF]` | Exit 0 nothing to check or all good, 1 a commit fails to build or a move is below 90 %, 2 could not run. `--base` defaults to `origin/main`, then `main`. A moved file is a rename into `core/` that git detects in a commit (default 50 % floor) or in the PR's net `-M90%` diff; a moved file whose arrival commit shows no rename is reported at 0 %. |
| `ci/gates.txt` rows `vet-darwin`, `vet-integration`, `commits-build` | `check`, `own-job`. `own-job` now means a `ci.yml` or `extraction-gates.yml` job. |

## Tests

| Name | Where | What it is |
|---|---|---|
| `test_required_workflows_have_merge_group`, `REQUIRED_CHECKS` | `scripts/tests/test_ci_classifier.py` | Fails when a workflow that defines a job named in 09 §9.2.1's list lacks `merge_group` in its `on:`. `REQUIRED_CHECKS` already names `unit-lifecycle` and `docker-image`: R1-04 and R1-28 satisfy it by giving their workflow the trigger. |
| `markdown_inputs(root)`, `inputs_without_a_case(root, script)` | `scripts/tests/test_ci_classifier.py` | The scan for Markdown files a Go test reads or embeds. A row that adds one adds its `go=true` case to the classifier in **both** ci.yml and extraction-gates.yml. |
| `gate_runs_in(gate, workflows, module_dir)` | `scripts/tests/test_run_gates.py` | Resolves a gate's command (`make [-C dir] target` or a script) to a workflow step, directly or through a make target's recipe or prerequisites. Used for `own-job` and `core-job` gates. |
