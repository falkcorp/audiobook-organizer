# F4-03 seams and coined names

What F4-03 added beyond 05-authn §4.7, §3.3 and §6, the readings it took where the brief or the spec says nothing, and what F4-05 and F4-08 must know. The PR is dark: no route serves `core/auth/oidc`, nothing registers `cfaccess.Extension`, and ABO's sign-in behaves as at HEAD.

## Coined names

| Name | What it is |
|---|---|
| `auth.ErrExtensionUnavailable` | What an `Authenticator` returns when it could not decide (its IdP's keys, its backend). Stage 12 opens to the next method, warns with the extension name only, and counts `mediacore_auth_extension_errors_total{extension}`. Any other extension error is a refusal; `ErrStoreUnavailable` is still 503. This closes the gap F4-02.md's last metrics paragraph records, so that paragraph is superseded: **F4-08's `mediacore.auth` scope must declare the label key `extension`** (the family is open-labelled and not seeded, so `testdata/series.golden` is unchanged). |
| `(*auth.Service).LockEmails() (unlock func())`, `NoteUserCreated()` | The account-write seam `oidc` shares with `CreateUser`: the e-mail mutex every creator holds around "no other account holds this address verified", and the first-run flag. Nothing else of `Service` is exposed. `oidc.AccountLock` is the interface over them. |
| `oidc.Flow`, `New(ctx, Deps)`, `Start(StartRequest) (*Started, error)`, `Callback(CallbackRequest) (*Completed, error)`, `Reload`, `Providers` | The sign-in. F4-05's routes call `Start` and `Callback`: `Started.Binding` goes in a short-lived HttpOnly SameSite=Lax cookie for `MaxAge` seconds and comes back as `CallbackRequest.Binding`; the route clears it whatever the outcome. `Completed` is a session (`Session`, `Return`) or, for an app hand-off, a `Location` with no session. Errors are `oidc.Err*` sentinels (match with `errors.Is`; `ErrBadRedirect` is answered inline with 400, never by redirecting to the URI) plus `auth.ErrEmailInUse`, `ErrInactiveUser`, `ErrResetRequired`, `ErrStoreUnavailable`, `ErrBadInput`. |
| `oidc.Deps{Settings, Keys, Resolver, Sessions, Handoff, HasUsers, CallbackBase, Audit, HTTPClient, Log, Clock}` | `Settings func() Settings` is read per request (`redirect_base_url` changes at once; a provider-set change at the next `Reload`). `Keys` is a `KeyDeriver` (`*secrets.Store`); the state key is `DeriveKey("mediacore/auth/oidc-state/v1")`. `Handoff` is `MethodSpec.AppHandoff` of the module's compat method. `CallbackBase` is `auth.Options.OIDCCallbackBase`, default `/api/core/v1/auth/oidc`. |
| `oidc.ProviderConfig`, `Policy`, `Settings`, `Resolver`, `ResolverDeps`, `NewResolver`, `Resolver.Resolve(ctx, Policy, Claims)` | Config with its client secret already resolved (`core.auth.oidc.<id>.client_secret`, bound by the F3 sibling work), redacted in every rendering. `Resolve` is the one admission and linking gate; an extension with its own identity source (Cloudflare Access) calls it with a `Policy` of its own. |
| `oidc.StateCodec`, `Payload`, `StateTTL`, `StateKeyInfo`, `CodeChallengeS256` | The signed state: `ID, State, Verifier, Nonce, Provider, Return, IssuedAt, AppRedirectURI, AppChallenge, AppState`. |
| `cfaccess.Extension(ExtensionConfig) (auth.Extension, error)`, `AccountResolver`, `OrderCFAccess` (150), `ErrKeysUnavailable` | F4-08 registers the result in `app.Options.Authenticators` with `ExtensionConfig{Verifier, Resolver: *oidc.Resolver, Policy{Provider: "cfaccess", ...}, OwnerEmail}`. |
| `cfaccess.Hooks{KeyPresented, BindUser, Permissions}`, `middleware.CFAccessHooks` | What the gin binder takes from the gin chain so `internal/cfaccess` never imports `internal/server/middleware`. Deleted with the binder at F4-08. |

## Readings where the spec is silent

- **The OIDC move is a new package, not a rename.** `core/auth/oidc` is written against `auth.Store` and `*slog.Logger`; HEAD's `resolve.go`, `state.go`, `providers.go` and `oauth.go` (which depend on `internal/database` and `internal/logger`) remain, behaviour unchanged, as `internal/legacyoauth` for the gin chain until F4-08 deletes them (the brief's STOP 3: no change to ABO sign-in before F4-08). The old tests moved with them.
- **Layer values.** §8.2 places `internal/cfaccess` at layer 5, but `internal/httputil` is a layer-0 leaf at BASE and the layering test computes 3, so `layerOf` carries 3 for `internal/cfaccess` and `internal/legacyoauth` until httputil moves.
- **Link rule.** Only a holder whose address we verified blocks or takes a link; an unverified holder blocks nothing (the verified provider identity wins the address, and displacement is audited). "Prove the password in the same flow", the other reading of "never takes a password account", is F4-05's to add if wanted; core's rule is the stricter refusal (`email_in_use`, sign in and link from the profile).
- **Trust.** `link_existing_by_email` governs both linking and displacement: an untrusted provider never takes or un-mails an account.
- **PKCE and nonce are new** (HEAD's GitHub flow had no PKCE; HEAD sent no nonce). They exist only in core's providers; the legacy chain is unchanged.
- **Linked sign-ins take no e-mail lock.** \`Resolver.Resolve\` decides a sign-in of an already linked subject, whose account needs no write, without \`LockEmails\` (\`linkedFast\`); only an unseen subject, or a linked account that needs its address marked verified, takes the lock. Once F4-08 registers the Cloudflare Access extension, every browser request it authenticates runs \`Resolve\`, and it must not queue behind account creation. Its cost is two store reads per request (identity, user) plus admission (a domain or address match, or one \`InviteAllowed\` read when the allowlist misses); if that is too much for stage 12, F4-08 can put a short TTL cache in front of the extension.
- **Shared files touched.** \`core/archtest/thirdparty_allow.txt\` gains \`github.com/coreos/go-oidc/v3\`, \`github.com/go-jose/go-jose/v4\` (the fake providers' signer, tests only) and \`golang.org/x/oauth2\`; \`scripts/deadcode-baseline.txt\` gains the three \`internal/cfaccess\` identifiers of the dark extension (F4-08 registers it); \`internal/arch/layering_test.go\` swaps \`internal/oauth\` for \`internal/legacyoauth\` and \`internal/cfaccess\`. core's \`go-jose\` is v4.1.6 and the root's \`go-jose\` moved from indirect to direct for the extension's tests. Nothing in \`core/secrets\`, \`core/kernel\`, \`core/config\` or core/auth's \`templogin.go\`, \`bootwrites.go\`, \`users.go\`, \`sessions.go\` was edited.
- **Single use is per process** (an in-memory, bounded set of spent state ids). A replay after a restart still fails at the provider, whose code is single use.
- **Login audit** is the async `core.auth.login` Emit (success only); a refused link audits `core.identity.link` as denied with reason `email_in_use`.
- **Cloudflare Access invalid token is a 401 from stage 12**, per §3.3. Cost to know at F4-08: an expired `CF_Authorization` cookie riding along with a valid session cookie now refuses the request until Access re-authenticates, where the gin binder fell through. A valid token for an identity the app does not admit still falls through, as the binder did.
- **`internal/auth/owner.go` did not move** (STOP 2); see the `todo.d` fragment `F4-03-OWNER` for the cost.
- **No end-to-end ABO to `auth.Service` test**: `core/internal/authstore` is not importable from ABO. The extension is tested through `Authenticate` with a real verifier over a fake team domain; stage 12's handling is tested in `core/auth` (`TestStage12_ExtensionUnavailableOpensToNextMethod`).

## F4-05 and F4-08 must know

- F4-05 serves `oidc.Flow`; `TestOIDC_AppHandoffMintsABSCode` is F4-08's (needs the routes and the ABS redemption).
- F4-08 registers `cfaccess.Extension` (needs a `*oidc.Resolver` built with `ResolverDeps{Store, NewBatch, Audit, Roles: rbac, Accounts: *auth.Service}`), declares the `extension` label key, and deletes `internal/legacyoauth` and the gin binder.
