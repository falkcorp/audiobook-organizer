# R1-25 seams and coined names

This file covers what the "offline restore and reset" PR added beyond 05-storage §5S.3.12 and §5S.3.15, 05-backup §5B.3.4, 05-updater §5U.12 and 06 §6.4.5, §6.4.6 and §6.5.2. It lists:

- names the spec does not have;
- the decisions the row took where the spec or the brief is silent, or offers a choice;
- the files it touched outside its inventory;
- how the brief's test names map to tests;
- what it left for later rows, with the fragment that tracks each item.

From this row nothing restores or resets the live store while the service runs. A restore from Settings stages an archive restore in the one journaled swap slot and the service exits 75. `storage restore-offline` and `storage reset` run with the service stopped. Every target is checked at staging. Every CLI command that opens the store goes through `app.OpenOffline`.

## Decisions

Each took the recommended option. The owner asked for no checkpoints.

- **D1. The live restore stages through `restorejournal`, not the kernel's swapper.** The kernel's offline stager refuses a store that a process holds, and the live restore runs inside the process that holds it. `backup.StageRestore` writes the same intent that the offline stager writes: `KindArchive`, the staged store as the one Target, `StagedByBuild` (the kernel's binary ID), `InstallID`, `ArchiveID` and a 24 h expiry. The next boot's P0a applies it. Its order:
  1. a listing lookup;
  2. verify without a sidecar is refused before any work;
  3. a slot read;
  4. `ValidateTargets`, then `Validate` over the set-asides and the placement;
  5. extraction;
  6. `VerifyStore`;
  7. `BeforeStage`;
  8. a synced journal directory;
  9. `CreateIntent`.

  Every refusal removes what it made. The stager touches neither the live store nor its settings.
- **D2. Verification.** A sidecar that exists is always checked. With verify, the extraction must have checked one: a sidecar removed after the listing refuses (`ErrVerificationUnsupported`). The sidecar is read once, in the extraction (`extractStore` reports whether it verified).
- **D3. The restart.** The handler answers 202, then calls `Lifecycle.RequestRestart`, so the stop order drains the listener and the 202 reaches the client before exit 75. The SPA does not reload. The server's `system.shutdown` event shows the reconnect overlay, which reloads once the server answers again.
- **D4. `target_path` is refused (400)**, and the error names `storage restore-offline --archive <file> --into <dir>`. A restore into another directory while serving has no swap to run.
- **D5. An offline restore supersedes a pending live restore.** This follows 05-storage §5S.3.12 "In place": the pending intent is journaled `rejected`, never run as a second swap. `storage reset` refuses a pending intent (`TestSwapSlotExclusive`).
- **D6. The standalone opener refuses, rather than completing, a staged or in-flight swap** (the brief allowed either). It has no P0a, and the error names the fix: boot the app once. `cmd/pid-census` and the tools keep `StateDir` empty. The op runner's child passes it (fragment `2026-11-09-r1-25-child-mode-pending-swap.md`).
- **D7. `VerifyStoreOpens` uses books as the only owner.** At R1, ABO has one owner with storage.
- **D8. The HNSW clean-stop marker** is removed before every swap this row stages. The offline commands remove it through `R1BeforeSwap`, the live stager through `BeforeStage`. #4496 had not merged, so `MarkDiverged` does not exist at this base (fragment `2026-11-09-r1-25-hnsw-clean-stop-cross-seam.md`).
- **D9. `pebble-inject-skip` became `transcode-skip`.** TestLayering lets only `.`, `cmd` and `internal/books` import `mediacore/app`, so the separate `main` could not open through `app.OpenOffline`. The cobra subcommand writes the same `transcode_skip_<hash>` rows through `openCLIStore`.
- **D10. A read-only books store closes cleanly.** `syncWALForShutdown` maps `storage.ErrReadOnly` from a read-only legacy range to nil (`TestReadOnlyBooksStoreClosesClean`). Every read-only CLI open hit this.
- **D11. R1-23's fragment `2026-11-08-r1-23-standalone-opener-pre-boot-swap.md` is deleted**, because step 7 closes it.
