# F2-05 seams and coined names

This file lists what `core/internal/taskhttp`, `core/examples/hello/count.go` and the executor's window-start guard added beyond 05-tasks and 05-http-api, the readings F2-05 took where the spec or the brief says nothing, and the seams later rows build on. Everything not listed here follows the spec as written.

## Names beyond the spec

| Name | What it is |
|---|---|
| `taskhttp.New(Deps) (*Server, error)` | The constructor. `Deps` is `Client`, `Approver`, `Runs`, `Definitions`, `Config`, `Audit`, plus optional `VerifiedMethod` and `Log`. A missing required dependency is refused at `New`, so no route serves with a nil sink. |
| `taskhttp.Route{Method, Path, Name, Summary, Perm, Handler}`, `Server.Routes()`, `Server.Handler()`, `taskhttp.BasePath` | The 19 routes of 5T.3.10 as data, plus a bare mux for tests. |
| `taskhttp.Principal(ctx)` | Has the type of `executor.Options.Principal`; resolves the caller from `auth.PrincipalFrom`. A principal with no checker resolves to one that holds nothing, never to "no identity". |
| `taskhttp.DefaultVerifiedMethod` | Only an interactive session verifies (SEC-24). |
| `executor.Options.WindowMembers func(window string) []tasks.Kind` | The window-start guard's member lookup (below). |
| `tasks.Actor.AuthMethod` for API keys | `token`, the vocabulary of `tasks.Actor`; the principal's own `api_key` is not used. |
| Problem codes | `tasks.mode_field_unsupported`, `tasks.invalid_idempotency_key`, `tasks.verified_method_required`, `tasks.audit_failed`, `tasks.no_schedule`, `tasks.schedule_locked`, `tasks.invalid_params`, plus one per executor sentinel (`internal/taskhttp/problem.go`). |
| `hello.PermAdmin` (`perms.go`) | `hello:admin`. **Seam:** the hello manifest's `Permissions` row declares it with `PermRead` and `PermSettings`; that row moves the constant into `hello.go` and deletes `perms.go`, so `count.go` stays byte-identical to the 06 6.12.3 snapshot. |

## Readings taken

- **Plain `net/http` handlers, not `httpapi` typed `Handle`.** `httpapi`'s `Router.Build` refuses every non-Public native route with `ErrNoAuthService` until core auth lands, a typed `Handle` cannot set a response header (`Idempotent-Replayed`) or choose between 202 and 200, and `HandleRaw` (05-http-api 3.1) is not implemented. `httpapi` is also outside this row's files and in the same layer. **Seam:** F2-16 adapts each `Route` to `HandleRaw` when it implements it. Each handler re-checks its own floor and per-definition rules, so a mount that skips the router's check still fails closed.
- **Start answers 202 with `Location`; a replay or a dedupe fold answers 200.** `Idempotent-Replayed: true` is sent only when the request carried a key. A dedupe fold on a keyed first request cannot be told from a replay.
- **`dry_run` and `dryRun`** at the top level or inside `params` are `400 tasks.mode_field_unsupported`, checked before the strict decode. The body is `{mode, params, priority}` only: an actor, trigger, parent or plan_ref in it is a 400, and the trigger is always `manual`.
- **Approve, decide and cancel-by-another are audited after the action** (`core.task.approve`, `core.task.reject`, `core.task.cancel`). The executor has no audit seam, so the write is not atomic with the move: an audit failure answers `500 tasks.audit_failed` with the action standing, and says so. Only the executor could make it atomic (05-rbac 7.1 says fail closed); that is a follow-up. Refusals this package decides emit a Denied record. A schedule edit is audited as `core.settings.update` by `config.Apply`.
- **Verified method.** The default rule is fail closed. The app-extension and API-key-names-scope cells need identity data this package cannot see and are injected through `Deps.VerifiedMethod` (F4-05). The route's permission cells for sessions and keys are `t.Skip`ped "needs core auth (F4-05)".
- **Window-start guard (executor).** A manual start of a `core.window.<name>` kind runs its members as their own modules' system actors, so `core:tasks.manage` alone would reach every member's scope. `prepare` now refuses (`ErrNotPermitted`) unless the caller holds every member's `Perms.Start`. It fails closed: no `WindowMembers`, or a member with no definition, refuses. It does not read the request's trigger, and a start with no caller (the scheduler's) is unaffected. **Seam:** F2-16 must set `Options.WindowMembers` to the scheduler's member lookup and `Options.Principal` to `taskhttp.Principal`; an executor with a nil `Principal` skips every permission check, the guard included.
- **Rows route** strips the `plan:` prefix and skips rows outside the plan, as F2-03's seam says. The log route takes `limit` only: a `LogLine` carries no cursor.
- **Pages after the definition View filter can be short**, so `next_after` appears only on a full page.

## Found, not changed

- `PATCH /schedules/{kind}` by a `core:tasks.manage` holder can put any kind into a window or schedule it; scheduled runs execute as module system actors. The spec lets `tasks.manage` edit schedules, so this is a delayed form of the privilege the window guard closes for a manual start.
- Window membership is checked at start only; a member added before the run executes is not re-checked.
- Idempotency records (`idem/<kind>/<key>`) are not scoped per actor: another caller's repeated key on the same kind replays the first run, and the body is then View-gated by `Get`, falling back to `{id, kind}`.
- Free text other than `RunView.Current` (log messages, item errors) is not redacted.
