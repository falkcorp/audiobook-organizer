# R1-05 seams and coined names

Names, readings and drift the web-build-entry-point PR added beyond the brief (implementation plan §(n) rule 5).

## Names

| Name | Where | What it is |
|---|---|---|
| `scripts/ci/build_web.sh deps` | | POSIX `sh`. Root is two levels above the script, not the working directory, so it works from any directory and in a Docker stage that copies it to `/build/scripts/ci/`. Always passes `--no-audit --no-fund`. Exit 2 on any other argument list. |
| `npm_config_ignore_scripts`, `npm_config_prefer_offline` | callers | How a site keeps a flag the script does not pass: npm reads `npm_config_*` from the environment, so it reaches every npm call the script makes. `vulnerability-scan.yml` sets the first on its step; both Dockerfiles set the second inline on the `RUN`. No site keeps its own `npm ci`, so the brief's exception list is empty. |
| `make web-deps` (phony) and `$(WEB_DEPS_STAMP)` | `Makefile` | Phony target over the stamp file `web/node_modules/.web-deps.stamp`. Stamp inputs: `web/package-lock.json`, `core/web/package-lock.json` when present, `scripts/ci/build_web.sh` (not in the brief: a changed script must reinstall), and every `core/web/packages/*/src/*` file. |
| `make web-install` | `Makefile` | Now a recipe-less alias of `web-deps`. |
| `frontend-lint-build`, `frontend-test` (display names `Frontend Lint & Build`, `Frontend Unit Tests`) | `ci.yml` | ABO-local replacements for reusable-ci-minimal's two frontend jobs. Neither check name is in ruleset 26660812, and the old names carried a `Minimal CI /` prefix, so nothing that required them by name breaks. Whether to require the new names is the owner's call. |
| `NoOtherNpmCiSitesTest` | `scripts/tests/test_build_web.py` | `NoOtherNpmCiSitesTest` fails if any Dockerfile, workflow, `Makefile`, Woodpecker file or `ci_remote.py` runs `npm ci` outside a comment. |

## Drift from the brief

- **Site count: 11, not 12.** `.woodpecker/checks-build.yaml:87` is the twelfth. PR #4439 deletes that workflow, so this PR does not edit it; the GitHub workflows are now the only place the web build is wired. The guard test excludes that one file by name until #4439 merges; drop the exclusion afterwards. Moved lines: `ci.yml:414` (knip), `e2e.yml:179`, `Makefile:219`, `Dockerfile:18`, `Dockerfile.build-cgo:17`, `ci_remote.py:516`.
- **`.github/ghcommon-ref.txt` is `016cd02a4`, not `861d4e83c`.** The verification step ran against `016cd02a4`.
- **`frontend-enabled: false` is not an off switch.** `reusable-release.yml` resolves a false (or absent) `*-enabled` boolean to `auto`, so detection still runs `build-frontend`. That job calls `gha-release-frontend`, which auto-detects `web/`, runs its own `npm ci`, lint, tests (both `continue-on-error`), `npm run build`, and uploads a `frontend-build` artifact. `create-release` then deletes the JS, CSS, HTML and image files from the downloaded artifacts: the release ships the Go binary with the UI embedded. So both release callers drop `frontend-enabled: true` and add `frontend` to `disabled-languages` (`python,docker,frontend` and `python,frontend`), the only way to say "never". Node for `pre-build-script`: `gha-release-go` runs it and installs no Node, so it is the runner image's, exactly as before this PR.
- **`reusable-ci.yml` has no frontend switch** (no `run-frontend` input; only `reusable-ci-minimal.yml` has one), at the pinned ref and at github-common `main`. So `frontend-ci.yml:64` and `nightly.yml:31` still call it and its `frontend-ci` job still runs `npm ci` in `web/` through `gha-ci-workflow-helpers`. Only the path filters changed for `frontend-ci.yml`; `nightly.yml` is untouched (its `force-all` forces that job and turning it off would drop the Go suite too). **Not done, needs a github-common change:** an input that skips the frontend half, or one that runs a pre-install script, plus the `ghcommon-ref.txt` bump (07 §7.3.2's alternative). It must land before R1-30 makes `web/` depend on `core/web`, or Frontend CI and the nightly run fail from that PR.
- **Dependabot lists `/core/web` before it exists** (R1-30 creates it). Whether a missing directory in `directories` fails only that directory's job or the whole npm group was not confirmed. If the npm updates error until R1-30, drop the entry here and add it there.
- **`extraction-gates.yml` changed** (not in the brief's list): its `Classify changed paths` step is a verbatim copy of `ci.yml`'s, and `scripts/tests/test_ci_classifier.py` fails when they differ. Added to R1-05's row in `inventory.json` (its other owners sit in W06, W08, W15, so W11 stays disjoint) and `check_waves.py` passes.
- **`ci.yml` `reusable-ci-minimal` caller:** `node-version` and `frontend-working-dir` were dropped along with the frontend half (only the frontend jobs read them).
- **Jobs without `setup-go` call the script, not `make web-deps`** (`knip-report`, the new frontend jobs, `security.yml`'s npm submission, `vulnerability-scan.yml`'s npm audit): the Makefile's parse-time `go env` lines run under `GOTOOLCHAIN=go1.27.3` and would download that toolchain just to install npm packages. `binary-smoke.yml` and `e2e.yml` have Go and call `make web-deps`.
- **`web-dev`** depends on `web-install` (the install half), which is `web-deps` today because the script has one subcommand; R1-30 owns splitting them if `core/web` needs a build-free install.
- **The Dockerfiles' four-step `core/web` order** stays R1-30's, as the brief says.
- **`ci_remote.py`:** the `web-test` leg is just `make web-test` (its `web-deps` prerequisite installs in the job's fresh worktree).
- **Docker not exercised:** the local engine answers HTTP 500 (as in R1-04). The substitute ran the real script with real npm in a temp tree laid out like the frontend stage (`/build/scripts/ci/build_web.sh`, `/build/web` with the manifest and lockfile only) and `npm_config_prefer_offline=true`: exit 0, `node_modules` populated. The `docker-image` check on the PR is the first real image build.
- **Dry-run RC:** `prerelease.yml` has no dry-run path, so the first post-merge RC is the check: watch that `Build Frontend Components` is skipped, the pre-build script succeeds, and `git status --porcelain` is empty after it.
