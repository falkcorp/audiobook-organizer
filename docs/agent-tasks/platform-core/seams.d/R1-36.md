# R1-36 seams and coined names

This file lists what the core/log `Logging` pipeline PR added beyond 05-logging §3, §4, §6, §7 and §10: names the spec does not have, readings it took where the spec or brief is silent, and the seams later rows (R1-13, R1-15, R1-18, F3-07, F5-15) build on. Everything not listed here follows the code contract as written: the level constants and `ParseLevel`, the `Key*` constants, `Format`, `Settings`, `FileSettings`, `DefaultSettings`, `Options`, `Logging` and its eleven methods, `Record`, `WithAttrs`/`AttrsFrom` and `RotatingFile`.

## Names beyond the spec

| Name | What it is |
|---|---|
| `log.Counters{Records, Dropped, Redactions}` | The brief coins the fields. `Records map[string]map[slog.Level]uint64` is module, then level, then records written (`mediacore_log_records_total{level,module}`). `Dropped map[string]uint64` is sink to records lost: `"primary"` (always present) and each tap name (`mediacore_log_dropped_total{sink}`). `Redactions map[string]uint64` is `RedactionKind` label (`key`, `url`, `path`, `valuer`, all four always present) to count (`mediacore_log_redactions_total{kind}`). Every map is a fresh copy. The metrics bridge (R1-18) renders a level below debug with the pipeline's rule (`TRACE`, `TRACE+n`). |
| `logger.InfoCtx`, `WarnCtx`, `ErrorCtx`, `DebugCtx` (`internal/logger/ctx.go`) | Names fixed by the brief. They log through `slog.Default()` with `sanitizeLogLine` on the message and on every string value (context attrs included, resolved first), and append `log.AttrsFrom(ctx)` after the call's args. The record's source position is the helper's caller. |
| `opContext` (`internal/server/opcontext.go`, unexported) | The books-side stand-in for the deleted `log.OpContext`: fields `ID`, `Type`, `Status`, `Entities`, methods `AddEntity` and `SetStatus`, and a `LogValue` that returns the group `opID`, `opType`, `opStatus` and `entities` (JSON, only when non-empty). It is carried as `log.WithAttrs(ctx, slog.Any("", op))`. A mutex makes `LogValue` safe against concurrent `SetStatus`/`AddEntity`, which HEAD's `OpContext` was not. 05-tasks' run attrs replace it (05-logging §11 item 2). |

## Spec readings

| Topic | Reading |
|---|---|
| `SetLevels` and unknown keys | I2 says unknown keys are "ignored" and also that "a scope created later still resolves through the current table". Both hold: `SetLevels` stores the whole table, and `unknown` is the sorted list of keys that name no scope created so far. A key counts as known when a scope with that exact key exists, or (for a bare module key) any scope of that module exists. Unknown keys change no existing logger. `Options.Levels` at `New` is the same table, which is what lets the kernel set `books.scanner` before the books module asks for its logger. |
| `Level(scope)` | Returns the scope's gate when the scope exists. Otherwise it returns the resolution a scope created now would get (module = text before the first `.`). |
| `Record.Message` redaction | The R1-32 follow-up list left the key to this row. The message goes through `Redactor.StringKinds("", msg)`: the empty key matches no key rule, and the text scan (URLs, paths, `key=value` pairs, auth schemes) runs. The kinds are counted. The same redacted message goes to the primary output and to every tap. |
| One redaction path (security review) | A logger's `WithAttrs` values and `WithGroup` names are kept unredacted. At `Handle` they are assembled with the record's attrs into the tree a `slog.Group` value of the same shape would make, and that tree goes through `Redactor.attr` top-level attr by top-level attr. So `WithGroup("password")` with any member, or `WithGroup("a").WithGroup("token")`, is redacted exactly like `slog.Group("password", ...)` (`TestHandler_WithGroupRedactedLikeGroupValue`). As a result, a logger's attrs are redacted and counted per record, not once at `With` time, and a `LogValuer` among them is resolved at log time. A group with no members is dropped before redaction, as the stdlib handlers drop it, so an unused denied group prints nothing. |
| Placement of context attrs and IDs | Record attrs nest inside the logger's open groups, as slog requires. The context's attrs (`WithAttrs`) and `trace_id`/`span_id` stay top-level, after the logger's and the record's attrs, where the journal and a log search look for `run_id` or `trace_id`. The primary line is `module`, `subsystem` (when set), the logger's attrs and groups, the context's attrs, then the IDs. |
| Trace and span IDs | They come from `trace.SpanContextFromContext(ctx)`, only when it is valid, and are not passed through the redactor. They are otel's hex strings, not caller text. The context's attrs, which are caller text, are redacted. |
| `Record.Attrs` | Everything but module, subsystem and the IDs, resolved, with groups preserved. Empty attrs are dropped, empty-key groups inlined and empty groups dropped, as the stdlib handlers print them. Each tap gets its own top-level slice. Nested group values are shared and must not be modified. |
| `Options.Now` | When set, it stamps every record (primary and taps) and drives the stderr rate limit. When nil, the record keeps slog's own time. |
| `New` validation | `Output` nil, a `Format` other than text or JSON, or a nil `Redactor` is an error. R1-32's contract does not say nil means `NewRedactor(nil)`, so nil is refused. There are no sentinel errors, because 05-logging names none. |
| Levels below debug | `LevelTrace` renders as `TRACE`. Any other level below debug renders as `TRACE+n` relative to trace, rather than slog's `DEBUG-n`. |
| Primary write error | `Handle` returns nil after a primary write fails: logging never fails its caller (05-logging §6). The record is counted under `Dropped["primary"]` and still goes to the taps. At most one stderr line per minute is written. A line that fails to reach stderr gives back that minute's budget. |
| `Tap` edge cases | `queue < 1` is treated as 1. A nil `fn`, or a `Tap` after `Close`, starts nothing and returns a no-op `stop`. Taps that share a name share one drop counter. A panic in `fn` is recovered and counted as a drop for that tap, so a broken tap cannot crash the process. `fn`'s context is cancelled by `stop` and by `Close`'s deadline. |
| Drop summary | When a tap has dropped records, the next `offer` queues a summary record ahead of the record that found space: module `core`, subsystem `log`, message `"<N> dropped"`, attrs `sink=<name>`, `dropped=<N>`, level `max(warn, the tap's min)`. If the summary does not fit, that record is dropped too and the count carries forward. Every drop is reported by exactly one summary. |
| `stop()` vs `Close(ctx)` | `stop()` removes the tap, discards what is still queued, cancels `fn`'s context and joins the goroutine. It must not be called from `fn`. `Close(ctx)` stops fan-out, lets every tap deliver its queue concurrently, and returns nil when all are done. If `ctx` expires first, it cancels every tap's context and returns `ctx.Err()` without joining. Each goroutine then exits after its current `fn` call. The primary output keeps working after `Close`, because the kernel owns and closes it. A second `Close` returns nil. |
| `RotatingFile` | `OpenRotatingFile` refuses an empty or absolute name and any `..` element before `os.Root` sees it. It creates missing parent directories inside the root (`Root.MkdirAll`, 0750), so `logs/<app-id>.log` needs no kernel mkdir. Rotation closes the live file, removes every `name.N` with N >= maxFiles-1 (this also clears leftovers from a larger earlier `max_files`), shifts the chain, renames the live file to `name.1` and reopens. With `maxFiles` 1 the live file is removed and recreated. After any failed step the live name is reopened for appending, so writing continues to the current file. The next attempt waits one minute, and stderr gets at most one warning per minute. A single write larger than `maxBytes` goes to the file whole. `Close` is idempotent, and later writes return `os.ErrClosed`. |
| Redaction counting | One attribute (or the message) adds one to each kind its `Redactor.attr` call reported, however many values inside it were replaced. The pipeline calls the unexported `attr` (same package) for the kinds and does not change `redactor.go`. |

## Seams for later rows

- **R1-15 / R1-18: remove the helpers' own `AttrsFrom` append.** Until `app.InstallProcessDefaults` points `slog.Default()` at the App pipeline, the default handler does not read `log.AttrsFrom`, so `logger.InfoCtx` and friends append the context's attrs themselves. Once the default handler is the pipeline, the pipeline appends them as well, and each attribute appears twice unless the helpers' append is removed in the same PR.
- **The op-attrs window (R1-15).** Between this merge and R1-15, a record that bypasses the step-6 helpers (a direct `slog.*` call or a `logger.Logger` printf call inside an op) lacks the op attrs, because HEAD's default handler does not read `AttrsFrom`. The R1 freeze does not cover this: if OWNER-01 overrode it (09 §9.2.1, R1-35 then sets `''`), a production minor in this window logs those records without op attrs.
- **R1-13 kernel.** `log.New(Options{...})` needs a non-nil `Redactor`, built from `NewRedactor(core.log.redact_keys, modulePathRules...)`. The kernel converts `Settings.Level` and `Levels` with `ParseLevel` (config validation rejects a bad string, 05-logging §6), opens the output (`OpenRotatingFile(stateRoot, settings.File.Path, MaxSizeMB<<20, MaxFiles)` for `output=file`, filling `Path` with `logs/<app-id>.log` when empty), and calls `Close(ctx)` last.
- **F3-07 live reload.** `SetLevels(root, per)` returns the unknown keys for the caller to warn about. The API has no way to swap the `Redactor` (`redact_keys` live). Because a logger's attrs are redacted per record through `l.redactor`, a later swap needs only an atomic pointer swap of that field.
- **F5-15 journal tap.** Use `Tap("journal", min, core.log.journal.queue_size, fn)`. Records are already redacted, `Record.Attrs` follows the reading above, and drops show under `Dropped["journal"]`.
- **Layer guard control.** `core/internal/archtest_layers_test.go`'s in-module control is now `metrics -> log` (the span exporter's `log.Redactor`), because this PR removed `health -> log`. The health test still imports `log`, as a test-only edge.
