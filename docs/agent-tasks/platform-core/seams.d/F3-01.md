## Readings the brief left open

| Topic | Reading |
|---|---|
| A tag inside a key's value | **Refused.** The coordinator's HIGH finding: a `protect`, `reload` or `sensitive` tag inside a list, map, array or pointer element, or inside a struct that encodes itself, was ignored, because config protects whole keys. With `core.auth.oidc.providers` tagged only per element, that was an auth bypass. `Register` now walks into each key's value and refuses, with `ErrInvalid`, any tag stricter than the key's own. The alternative, raising the key to its strictest nested tag, was rejected because it is silent: a declaration would quietly mean something other than what it says. The key must carry the tag itself. |
| `core.auth.oidc.providers` | `protect:"owner"` on the whole list. An admin who could repoint an entry's `issuer` or `client_id` while its `allowed_emails` name the owner could mint the owner's identity, so the owner-trust root covers the whole entry, not only `allowed_emails`/`allowed_domains`. 05-authn §8 (its table row, the §4.8 owner-trust-root list and `TestOwnerTrustRootKeysAreOwnerProtected`'s row) and 05-config §1.3.7's owner row are edited to match in this PR. F2-09's seams still say the list was `admin`; that file is F2-09's record and is left as written. |
| Secret changes and snapshots | A secret write never republishes a snapshot and never wakes `OnChange`: the snapshot holds a `Ref` (a name), whose value resolves on read. `KeyState.Secret` (the Meta) is refreshed after the commit. |
| `AfterCommit` timing | Hooks run after the store mutex is released, in registration order, for every section whose stored value changed (`Pending` included). So a hook may call `Apply`. A hook's error or panic becomes `*PostCommitError` in `Result.PostCommit`; it never vetoes. |
| Undecodable stored row | A row that does not decode quarantines **every** row of its section. It is never handed to the build, where a missing value would read as JSON `null` and decode to the zero value instead of the default. |
| Boot-record value that does not decode | Kept in the record, ignored, reported in `KeyState.Quarantined`, and raises `config_boot_record_quarantined`. |
| Secret key `KeyState.Source` | Read from the secret's Meta when the index is built (`SourceOverride` when stored, `SourceEnv` when Meta says env, else `SourceDefault`), because the build runs before `refreshSecrets`. |
| Sensitive keys in errors | A `sensitive` key's `*FieldError` carries a fixed message, never the validator's text: jsonschema echoes the rejected value, and these errors reach logs and the quarantine report. |
| `json.RawMessage` in schemas | `storeOverrides()` renders it as `{}`. It is a standard-library type with no owner in 05-config §1.10.2's table, and httpapi adds its own entry, so it stays out of `config.Overrides()`. `jsonschemax.Base` is its rightful owner; a one-line move is owed there (both would then drop their copy). |
| Operator layers before F3-02 | `Options.Environ` is not read: the env layer is F3-02's. A configured `Options.FilePath` is refused (`unbuiltFile`), never silently ignored. The layers that reach a store are the explicitly set flags. F3-07 must not wire the kernel's config boot before F3-02. |
| `TestSource` | `export_test.go`'s test-only operator layer. Like F3-02's sources, it returns only the paths the store can place (a registered key, an entry under a map section, a passthrough path); `Unfiltered` hands everything over so the store's own refusal can be tested. |
| ABO's `EnsureSecureStateDir` | Re-pointed onto `config.ResolveStateDir`, keeping ABO's env name, its memoisation and its warning attributes. Its own `state_dir_test.go` passes unchanged. |
| `core/app.ResolveStateDir` | Delegates to `config.ResolveStateDir` (the coordinator's call), so core/app, the kernel and ABO share one rule. Three behaviours change, all toward HEAD: an explicit value is trimmed and cleaned; the database-directory fallback is used only when it can be created (otherwise the default's error); and on an error the directory that could not be used is returned with it. All three callers (`core/app/app.go` `New` and `storagePath`, `internal/books/options.go` `storeLocation`) check the error first, so none relied on the old `""`. `TestStateDirFallbackMatchesHEAD_AppResolver` asserts agreement on all 60 rows; the old resolver fails 40 of them. |

## Dark wiring and its gate

`core/kernel/config.go` (`bootConfig`, `loadConfig`, `buildConfigStore`, `attachConfig`, `configMetrics`, `configOwnerSpec`) is called from nowhere in boot, and `storageOwners` does not list `configOwnerSpec`. So ABO's boot reads no DB layer through core and writes no `c/config/` row. The gate is the presence of F3-07's wiring (the calls, and the owner in `storageOwners`), not a flag.
