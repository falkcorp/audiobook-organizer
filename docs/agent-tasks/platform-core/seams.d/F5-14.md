# F5-14 seams, rulings and open blockers

F5-14 ([brief](../F5-14-schedules-oracle-no-catchup-storm.md)) was stopped at its base checks on 2026-11-20 and split:
a **pre-slice** on main (this file's first two sections, the core schedule change and the HEAD clock seam) and
**F5-14 proper**, which stacks on F3-07 (#4765) and handles the open blockers below.

## Owner ruling 2026-11-20: "Allow both in core"

Under HEAD's shipped defaults five `TaskDefinition`s tick on an interval **and** sit in `maintenanceOrder`, and
HEAD fires each on either: `tombstone_cleanup` (24h, order 7), `reports_prune` (24h, 15), `purge_deleted` (6h, 8,
plus `RunOnStart`), `cleanup_activity_log` (24h, 10) and `ai_journal_prune` (24h, 11). Core's `ScheduleConfig`
allowed exactly one of `Every`, `DailyAt`, `Cron` and `Window`, so that cadence was not expressible. The owner
ruled to extend core rather than change the cadence:

| Rule | Where |
|---|---|
| `ScheduleConfig.Validate` accepts `Every` with `Window`; refuses `Window` with `DailyAt` or `Cron`, more than one of `Every`/`DailyAt`/`Cron`, and an enabled value with no timing | `core/tasks/schedule.go` |
| An `Every`+`Window` value is polled on its interval **and** is a member of the window, under a schedule hash of its own (`every`, `window`); a window-only member's own clock is still not polled | `core/internal/scheduler/clock.go` `effectiveOf`, `scheduler.go` `pollEntry` |
| Never two runs for one due moment: a start (interval fire or window member start) that finds a run of the kind active folds into it (the executor's existing fold; HEAD's `isTaskRunning` skip). The window does **not** stamp the member's interval clock, as HEAD's window did not touch `scheduled_interval_last_tick:*`, so a member whose interval run finished before the opening runs again in the window | `core/internal/scheduler/window.go` `runWindow` (unchanged), tests in `window_every_test.go` |
| A window member's `OnStart` fires at boot (HEAD's `RunOnStart` on `temp_file_cleanup`, window only, and `purge_deleted`, interval and window). Before the pre-slice core skipped `OnStart` for every window member | `core/internal/scheduler/scheduler.go` `Boot` |
| 05-tasks §5T.3.8: the `ScheduleConfig` comment and the window-membership conversion rule (`Every`, `Window`, `Order`), with a review-history entry | `docs/specs/platform-core/05-tasks.md` |

## HEAD clock seam (coordinator ruling b, 2026-11-20)

`internal/scheduler.SchedulerDeps` gains three optional fields so F5-14's oracle drives HEAD's own due rules
instead of a model of them. Nil is the old behaviour (`time.Now`, `time.Local`, `time.NewTicker`).

| Field | Read by |
|---|---|
| `Now func() time.Time` | `claimIntervalRun`'s now, `runDailyAtCheck`, the full-sweep clock (`tasks.go`), the maintenance window's hour and its once-a-day date (`saveLastMaintenanceRun`, `hasRunToday`), the `lastRun` stamp, and the ops.Schedule loop (`v3Scheduler.now`) |
| `Location *time.Location` | the DailyAt timer's zone, the maintenance window's hour and date, `v3Scheduler.loc` |
| `Tick func(d) (<-chan time.Time, func())` | every timer `Start` builds: interval, DailyAt and maintenance checkers and the ops.Schedule loop. `WaitForOperation` keeps its own timer |

Stepping recipe (`internal/scheduler/clock_seam_test.go` `fakeClock.step`): hand each checker an unbuffered
channel, move the fake clock, send the tick, then send it again at the same instant. The checker takes the second
tick only after acting on the first, and a repeated check at one instant is idempotent, so the step returns with the
first tick's work done.

## Open blockers F5-14 proper handles (on top of F3-07)

**Blocker 4: gates that sit outside the schedule key.** The oracle cannot derive a definition's cadence from its
`modules.books.scheduler.schedules.<entry>` key alone:

- the maintenance toggles: HEAD's `maintenance.<field>` flags gate several definitions' `IsEnabled`; after F3-07
  they are `modules.books.maintenance.<field>`, not part of any schedule key;
- `scan_on_startup` becomes `modules.books.scan.on_startup` and drives `library_scan`'s `RunOnStart`, outside its
  schedule key;
- M2 drops `scheduled.*.on_startup`: `convertSchedule` (`internal/books/cutover/rename_convert.go`) reports it as
  dropped because `ScheduleConfig` has no on-start field, so a user-set `on_startup: true` has no R2 equivalent
  unless the kind declares `.OnStart()` or a `.When` reads another key;
- `.When` gates every fire (interval, window start and `OnStart`), so a gate translated as `.When` must match
  HEAD's `IsEnabled` on all three paths, not only the interval one;
- the `ScheduleFor` hook takes no deps, but several definitions' enable logic reads `HasDedupPlugin`,
  `HasActivitySvc` and `HasMetadataFetchSvc`; the oracle needs them passed in or modelled as `.When`.

**Blocker 5: `cadence.golden` is rendered from test deps.** `internal/scheduler/testdata/cadence.golden` is
written by `TestCadenceGolden` from `NewTaskScheduler(reachabilityTestDeps())`, whose config is the zero
`config.AppConfig`, not the shipped `SetDefault` values. Its `library_scan` line reads interval `0s`, disabled,
where the shipped defaults are 360 minutes and enabled. It pins "no timer changed" but is not a statement of
the shipped cadence, so F5-14 must not use it as the oracle's expected values; F3-07's `schedulerDefaults()`
(the 16 `scheduled.*` keys) is the source.

**Prerequisite.** F3-07 (#4765) creates `internal/books/config.go` and its `schedulerDefaults()`; F5-14's
`internal/books/schedules.go` builds on it and lands after it (coordinator ruling a, 2026-11-20).
