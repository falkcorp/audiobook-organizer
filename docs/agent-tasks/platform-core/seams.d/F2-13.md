## Rules later rows inherit

- **No undecodable `setting:` row and no ill-typed or invalid settings-blob field can sit in a store R0 boots on.**
  R0 refuses to boot on an undecodable `setting:` row (`collectSettings`), on a blob field whose JSON type does
  not match its config field (`internal/config/persistence.go` at the tag), and on a value its validator rejects
  (an unknown `backup_compression`). M2's quarantine cases are therefore a secret whose ciphertext does not
  decrypt (`corrupt-settings-secret`) and a blob field no rename-table row names (`blob-field-unmapped`), and
  M6's integration case is a field that is not a URL, kept and reported (`integration-field-invalid`, 05-metadata
  M1.10), not quarantined. M6's undecodable rows are `corrupt-import-root` and `corrupt-aijob`.
- **R0 answers on the overlay are R0's degraded reads.** R0's `GetAllImportPaths` errors on the torn
  `import_path:9`, so the library answer's import-root request on the overlay records R0's error; role, AI job,
  syslog and v3 run listings skip undecodable rows.
- **`corrupt-run` relies on M4 not rebuilding a run from its opv2 mirror.** The run's `opv3:run:` row is torn
  while its progress row and `opv2:` mirror stay intact and current, so HEAD's `ReconcileOpsV3WithV2` neither
  rebuilds nor deletes it. If F5 decides M4 rebuilds an undecodable v3 run from the mirror, this case's outcome
  changes to `imported`.
- **R0's merge-journal statuses are `applying`, `applied`, `undoing`, `undone`.** The spec's "done" is `applied`.
  The unfinished journals were written by HEAD's own `usermerge.Service` with a canceled context (cancel at the
  first `merging` step; undo with a pre-canceled context), not hand-encoded.
- **`stopping{watchdog}`:** 05-tasks §5T.8.3 maps it to `failed` (reason watchdog); R0's own `StopTerminal`
  says `timed_out`. The manifest records the spec's mapping.
- **The overlay's API keys have no usable secret.** Each was minted through `database.GenerateAPIKeyToken` and
  the raw token discarded; only stage 1's fixture keys can authenticate a replay.
- The program opens the store copy with `database.NewPebbleStore` and writes through HEAD's writers wherever one
  exists; a value no writer produces (a status no handler accepts) is HEAD's own type JSON-encoded and written
  with `SetRaw`; a corrupt row is a torn JSON prefix ending in `,"torn":`.
