# F5-18m seams and coined names

F5-18m hardens the maintenance jobs' write-set oracle (obligations O33, O34, O38 of the F5-18 prep split). It is test tooling: nothing it changes runs in a production binary. This file lists the readings the row took where the brief is silent, the files it touched beyond the oracle and its tests, and what later rows build on.

## Seams

- `kinds.go` and `kinds_writes.go` are part of this row's files. O38's second half (`FailJobWritesWith` unsafe under `t.Parallel`) cannot be fixed inside the test files: the helper swapped `jobWritesFor`, which `Kinds` read. The coordinator approved an injection seam (`kindsWith` plus a derivation parameter on `effectsFor`); the row built it as a parameter on `effectsFor` and an unexported `KindDeps.writes` field instead of a new `kindsWith`, because `make lint-deadcode-ratchet` rejects a new production function that no main reaches (`kindsWith`, `kindForWith` and `effectsWith` were all new, and the ratchet forbids adding them to the baseline by hand), while a parameter and a field add no identifier. `Kinds` and `kindFor` keep their signatures; `kindFor` reads `deps.writes` and falls back to `jobWritesFor` when it is nil; `effectsFor(writes, jobID)` takes the derivation (its two test callers pass `jobWritesFor`). `jobWritesFor` stays a plain `sync.OnceValues` (typed `writesDeriver`) and is never reassigned. `KindsWithFailingWrites(err)` in `export_writes_test.go` replaces `FailJobWritesWith`. `TestJobWrites_FailingDerivationIsNotSharedAcrossParallelTests` interleaves failing and real `Kinds` builds under `t.Parallel`; run under `-race` against the old swap it reports seven data races and four wrong results, and against the field none. F5-18 leaves `KindDeps.writes` nil.
- The walk is VTA over every function of the module (and every synthetic wrapper), seeded by CHA, the precedent in `tools/fixerstores`. Three rules keep a context-insensitive graph from reporting writes a job does not make. (1) A call through a function value is resolved by the graph only when the value is read from a field, a package variable, a slice or a call result and no caller supplies it (`oracleGraphResolves`); a parameter's callees under VTA are every function any caller passes there (`registry.RunItems` would hand every job every other job's callback), so a callback is read where its caller mentions it. (2) Every function a body mentions as a value is walked there (callbacks handed to code outside the module). (3) An interface call whose implementations are all module code the walk follows is judged by what those bodies do, not by the interface method's name (`byBody`); any other implementation (the store, code outside the module) leaves the call judged by name as before.
- CHA stands in only where VTA has no callee for a call on a module-declared interface (the value comes from wiring outside the loaded program). It is not used for interfaces of the standard library or a dependency: every type in the module implements `error` or `io.Closer`.
- An instance of a generic function, and the closures inside it, have no package; they are classified by the package of the generic they were made from (`oracleOwner`), so `slices.Backward[...]` is the standard library's whatever instantiated it.
- The scan stand-down hold's heartbeat (`ScanStandDownHold.Checkpoint`, which renews the lease in the settings table) is liveness infrastructure and is not walked (`oracleNotWalked`), as the progress and activity sinks already are (`oracleNotAWrite`); walking it gave two jobs a `settings` write they do not make.
- `traceInert` is keyed by the full call key (`<receiver>.<method>`, `STOREFN.<name>` or `STORECONCRETE.<receiver>.<method>`), the same keys as `traceAliases`. The eleven bare names became eleven keyed entries; `TestTraceWriteName_InertIsKeyedByReceiver` proves another receiver's method of the same name is classified again, and `TestJobWrites_ClassificationTablesAreLive` fails on an alias or inert entry no job reaches.
- The two hand aliases the old walk needed, `tagger.LibraryImporter.ImportPath` and `jobs.checkpointer.Save`, are removed: the walk reaches what they stood in for.
- The oracle has its own fixture (`testdata/oraclefix`, a module-path-shaped copy of the store package and a `fix` package of roots), because the jobs hold no write reached through a name the oracle cannot classify: a walk that stopped following interfaces would still pass every job-level test. `TestOracleWalk_NeedsTheCallGraph` runs the same roots over an empty graph and shows the three graph shapes find nothing, so the sensitivity of the main test is itself tested.
- `TestTaglibVariants_ReachTheSameWriteHelpers` reads `taglib_cgo.go` as syntax (the file imports `"C"`, so it cannot be type-checked here) and follows its calls into `internal/tagger` and `internal/fileops` through the SSA program the oracle already built. For each of the four write entry points it compares the write helpers reached (path pre-flight `tagger.resolvePath`, `fileops.WriteTagsSafe`, `SafeWriteDeps.VerifyWritten`, `fileops.HashOptionsForPath`) in both variants and requires the three safe writers to reach all four and the in-place writer none. A call the syntax does not resolve to a receiver (a method) is matched by name, which can only widen what is reached.

## Deviations

- The oracle's `oracleVerb` gained `Revert` (the fixture's `RevertBookToVersion` shape; the old walk dropped such a write silently). No job's write set changes.
- The old `AnonFuncs` loop is gone: a closure is a `*ssa.Function` operand of its `MakeClosure` and is walked from there, and a mutant that removed the loop changed nothing.

## Follow-ups

- A value that mixes a parameter with a field or package-variable load (`if fn == nil { fn = steps[0] }`) is not resolved by the graph, so the field-loaded default is not followed; resolving it exactly needs a context-sensitive analysis. No job has the shape today; `MixedReadOnly` pins that the caller's callback is not blamed for the default's writes.
- The `JOBWRITES-F5-18` TODO item stays open for its remaining sub-items (deferral visibility, `author_books_legacy`, per-batch locking).
