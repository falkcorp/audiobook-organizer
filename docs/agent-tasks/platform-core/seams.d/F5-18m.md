# F5-18m seams and coined names

F5-18m hardens the maintenance jobs' write-set oracle (obligations O33, O34, O38 of the F5-18 prep split). It is test tooling: nothing it changes runs in a production binary. This file lists the readings the row took where the brief is silent, the files it touched beyond the oracle and its tests, and what later rows build on.

## Seams

- `kinds.go` and `kinds_writes.go` are part of this row's files. O38's second half (`FailJobWritesWith` unsafe under `t.Parallel`) cannot be fixed inside the test files: the helper swapped `jobWritesFor`, which `Kinds` read. The coordinator approved an injection seam (`kindsWith` plus a derivation parameter on `effectsFor`); the row built it as a parameter on `effectsFor` and an unexported `KindDeps.writes` field instead of a new `kindsWith`, because `make lint-deadcode-ratchet` rejects a new production function that no main reaches (`kindsWith`, `kindForWith` and `effectsWith` were all new, and the ratchet forbids adding them to the baseline by hand), while a parameter and a field add no identifier. `Kinds` and `kindFor` keep their signatures; `kindFor` reads `deps.writes` and falls back to `jobWritesFor` when it is nil; `effectsFor(writes, jobID)` takes the derivation (its two test callers pass `jobWritesFor`). `jobWritesFor` stays a plain `sync.OnceValues` (typed `writesDeriver`) and is never reassigned. `KindsWithFailingWrites(err)` in `export_writes_test.go` replaces `FailJobWritesWith`. `TestJobWrites_FailingDerivationIsNotSharedAcrossParallelTests` interleaves failing and real `Kinds` builds under `t.Parallel`; run under `-race` against the old swap it reports seven data races and four wrong results, and against the field none. F5-18 leaves `KindDeps.writes` nil.
- The walk is VTA over every function of the module (and every synthetic wrapper), seeded by CHA, the precedent in `tools/fixerstores`. The rules that keep a context-insensitive graph from reporting writes a job does not make, and from missing writes it should report: (1) A call through a function value is resolved from what the caller mentions (a parameter's callees under VTA are every function any caller passes there, so `registry.RunItems` would hand every job every other job's callback). A value a caller loads from a field, a package variable, a slice or a map and passes on is resolved at that caller from the module's stores into that variable or field (`oracleFlows`, field-sensitive by the field's declaration), which also covers `if fn == nil { fn = default }`. (2) Every function a body mentions as a value is walked there (callbacks handed to code outside the module). (3) An interface call is recorded by the interface method's own name (judged by verb, as before) AND its implementations are walked, and the result is the union: the set of implementations the program knows can be partial (an in-program type beside a store the wiring passes in, the `ManualOnlyFilesReader` shape) and a body can write through code the walk does not enter. A reporter's name (`oracleNotAWrite`) is not judged, but what implements it is still walked.
- CHA stands in where VTA has no callee: for a call on a module-declared interface (the value comes from wiring outside the loaded program; not for `error` or `io.Closer`, which every type implements), and for a function value read from a type assertion, a map or a context (set by code outside the program), where every function of the signature is the answer. It is NOT applied to a call result nor to a package variable or field. Evidence, measured on this branch while building it: with the fallback applied to those, a signature as common as `func()` or `func(context.Context, int) error` matches `FullScan`'s and the registry's closures, and `backfill-book-files` (51 spurious write keys), then `bulk-deluge-import` (85), `scan-composer-tags` (84) and `merge-chapter-groups` (83) reached the dedup engine, the registry and the embedding store through a `cancel()` returned by `context.WithTimeout` and a nil test hook (`chapterPrecheckTestHook`). Every excluded shape is recorded, not skipped: a call through a function value the walk finds no callee for is the call key `UNRESOLVED.<function>#<what it was read from>`, and `TestJobWrites_NoUnresolvedCalls` fails on any that is not in `oracleUnresolvedAllowed` (with a reason) or, for a closure that code outside the module made, `oracleOutsideClosureAllowed`; each allowance must be used. Today three calls are allowed (two test hooks nothing in the module sets and the `cancel` of `providerhttp`'s `attemptContext`, a variable holding `context.WithTimeout`) and four outside closures (`context.WithCancel`, `context.WithTimeout`, `strings.SplitSeq`, `strings.FieldsSeq`).
- An instance of a generic function, and the closures inside it, have no package; they are classified by the package of the generic they were made from (`oracleOwner`), so `slices.Backward[...]` is the standard library's whatever instantiated it.
- The scan stand-down hold's heartbeat (`ScanStandDownHold.Checkpoint`, which renews the lease in the settings table, and the `Beat` and `beat` it calls) is liveness infrastructure and is not walked (`oracleNotWalked`, narrowed to those three methods: the hold's other methods still are), as the progress and activity sinks' names are not judged (`oracleNotAWrite`); walking it gave two jobs a `settings` write they do not make.
- **The run reporter's own persistence is not a job's write (`oracleReporterOwn`, round 3, coordinator decision A).** Once the walk follows the module's implementations of an interface declared outside the module, a job's log line reaches the registry's persistence in production: `logger.StandardLogger.emit` → `slog.Handler.Handle` → `(*registry.fanoutHandler).Handle` → `(*registry.dbReporter).Log`, which writes the op-error row (`OpsV2Store.InsertOpErrorV2`, and through `prodSchedulerStore.InsertOpErrorV2` the `opRegistryStore` one, which `OpsV2DepAdapter.InsertOpErrorV2` hands to `OpsV2Store`) and the activity entry (`dbReporter.recordActivity` → `ActivityRecorder.Record`). Thirteen jobs gained those writes. They are the operations registry persisting every run's own log, through the registry's store, whatever the job; they are exempted by exact `(calling function, receiver.method)` pair only, so the same store methods called from anywhere else, job code included, are still noted (`TestOracleWalk_ReporterOwnIsScopedToItsFunctions`). **F5-18's write fences must not cover the op-log, op-error and activity families**: the registry writes them on behalf of every run, so a fence built to refuse writes outside a job's declared set would refuse the registry's own bookkeeping. The F5-18 brief does not say this today (its fencing item, commit 1, names `ErrFenced`/`WithFence` without a scope); it is listed under Follow-ups.
- `traceInert` is keyed by the full call key (`<receiver>.<method>`, `STOREFN.<store package>.<name>` or `STORECONCRETE.<receiver>.<method>`, a function keyed by its package so two store packages sharing a function name do not share a key), the same keys as `traceAliases`. The eleven bare names became eleven keyed entries; `TestTraceWriteName_InertIsKeyedByReceiver` proves another receiver's method of the same name is classified again, and `TestJobWrites_ClassificationTablesAreLive` fails on an alias or inert entry no job reaches.
- The two hand aliases `tagger.LibraryImporter.ImportPath` and `jobs.checkpointer.Save` stay as keyed `traceAliases` entries. An implementation the program does not contain (the wiring passes it in) would leave only the method's name to judge by, and the name alone says nothing about the `UpdateBookFile` or `SaveOperationState` they end in. The walk reaching what they stand for is a second line, not a reason to delete the first.
- A call to an instance of a generic function of the store package (`store.AsCapability[T]`) is a store call: it is keyed and judged by the generic's package (`oracleOwner`) in all three conditions, so its body is not walked, like every store function's (eight jobs lose the `store.StoreUnwrapper.Unwrap` key that walking `AsCapability`'s body used to record).
- The oracle has its own fixture (`testdata/oraclefix`, a module-path-shaped copy of the store package and a `fix` package of roots), because the jobs hold no write reached through a name the oracle cannot classify: a walk that stopped following interfaces would still pass every job-level test. `TestOracleWalk_NeedsTheCallGraph` runs the roots over an empty graph and shows the interface and the signature-fallback shapes find nothing while the shapes the module's own stores resolve still do, so the sensitivity of the main test is itself tested.
- `TestTaglibVariants_ReachTheSameWriteHelpers` reads `taglib_cgo.go` as syntax (the file imports `"C"`, so it cannot be type-checked here) and follows its calls into the module through the SSA program the oracle already built. For each of the four write entry points it compares, between the two variants, the write helpers reached (path pre-flight `tagger.resolvePath`, `fileops.WriteTagsSafe`, `SafeWriteDeps.VerifyWritten`, `fileops.HashOptionsForPath`), the union of resource kinds and the union of classified call keys the oracle's walk records for everything they call, and the file writers of package `os` (and the oracle's outside file-writer packages) that the variants' own bodies call; the safe writers must reach all four helpers and the in-place writer none. A method call in the syntax is resolved only to a write helper whose method name it names (`VerifyWritten`), no longer to every method of that name in the module.

## Deviations

- The oracle's `oracleVerb` gained `Revert` (the fixture's `RevertBookToVersion` shape; the old walk dropped such a write silently). No job's write set changes.
- The old `AnonFuncs` loop is gone: a closure is a `*ssa.Function` operand of its `MakeClosure` and is walked from there, and a mutant that removed the loop changed nothing.

## Follow-ups

- A value that mixes a parameter with a load of a variable the module never stores to is resolved only to what the callers pass; the unset default is recorded as `UNRESOLVED` (the nil hook shape) and has to be allowed with a reason. Resolving the pair exactly needs a context-sensitive analysis.
- F5-18: state in its brief that the write fences exclude the op-log, op-error and activity families the registry persists for every run (the `oracleReporterOwn` exemption above).
- The `JOBWRITES-F5-18` TODO item stays open for its remaining sub-items (following calls that leave the module, deferral visibility, `author_books_legacy`, per-batch locking).
