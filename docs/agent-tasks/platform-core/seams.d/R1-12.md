# R1-12 seams and coined names

Names the SDK-leaf PR added beyond the spec's signatures, and the spec members it left out, that later rows may rely on (implementation plan §(n) rule 5). Everything not listed here is 05-rbac §3.1/§3.3, 05-authn §3.1/§3.3, 07 §7.6.1 or 05-config §1.10.2 verbatim.

## Core packages (`github.com/falkcorp/mediacore/...`)

| Name | Where | What it is |
|---|---|---|
| `rbac.KindLegacyAtom`, `rbac.KindLegacyCheck` | `core/rbac/requirement.go` | Two `RequirementKind` values appended **after** `KindDelegated`, so the spec's six keep their values. 05-rbac gives `LegacyAtom`/`LegacyCheck` no kind, yet the two must be told apart from every other requirement and from each other: they differ for the auth-disabled principal (05-tasks §5T.3.7). The F4 checker switches on them. |
| `rbac.Requirement.Atom() string`, `rbac.Requirement.ReadSide() bool` | `core/rbac/requirement.go` | The read side of `LegacyAtom(atom)` / `LegacyCheck(atom, readSide)`; without it the F4 checker (another package) could not read the atom the leaf carries. `Atom` is `""` and `ReadSide` false for every other kind; `LegacyAtom` is never read-side. Not evaluation: `TestLegacyAtom_CarriesAtomOnly` fails if `Requirement` ever gains another exported method. |
| `rbac.Requirement.String()` forms beyond the spec's four | `core/rbac/requirement.go` | `any(a,b)`; `delegated(<reason>)` (so the reason, otherwise unread, is visible in a manifest dump); `legacy(<atom>)`; `legacy_check(<atom>)` and `legacy_check(<atom>,read)`; `invalid` for the zero value. `AllOf` of one scope prints as the bare scope, as `Need` does; `AnyOf` of one prints `any(a)` so the kind survives. |
| Constructor rule | `core/rbac/requirement.go` | `Need`, `AllOf`, `AnyOf` return the **zero Requirement** (invalid, so every registration API rejects it, R6) for no scope or for any scope that is not a concrete `ParsePermission` scope (malformed, wildcard, empty). `LegacyAtom("")` and `LegacyCheck("", _)` likewise. Duplicates are dropped, order kept. `Delegated` accepts any reason, the empty one included. Fail closed rather than a vacuously satisfiable requirement. |
| `rbac.ErrBadScope` | `core/rbac/permission.go` | The one member of 05-rbac §3.4's error block pulled forward: `ParsePermission`/`ParsePattern` wrap it. The rest of the block lands with the checker. |
| `Permission.Action()` of a pattern | `core/rbac/permission.go` | `"*"` for `ns:*`, the action for `ns:action.*`; `Namespace()` and `Action()` are `""` for a string with no colon (a type conversion, never a parse result). |
| `auth.OIDCAppHandoff` | `core/auth/methodspec.go` | 05-authn §3.3's interface, brought in because `MethodSpec.AppHandoff` names it. Dependency-free (context, `*User`, strings). |
| `auth.WithPrincipal(ctx, nil)` | `core/auth/method.go` | Binds no principal: `PrincipalFrom` then reports false even over a context that had one (a downgrade, never an escalation). The key type is unexported. |
| `jsonschemax` tag pass: `x-mediacore-reload`, `x-mediacore-protect`, `x-mediacore-sensitive` | `core/internal/jsonschemax/tags.go` | 05-config §1.3's tag table mapped as the spec says, with the details it leaves open: `x-mediacore-sensitive: true` is the keyword for `sensitive:"true"` (spec names no keyword; `x-mediacore-secret` and `-fail-closed` are not tag-driven); `reload:"live"` is refused (live is the absence of the tag), as is any value outside the table; keywords are written only when the tag is present; `enum=a\|b` values take the field's JSON type (string, integer, number, boolean); `pattern=` takes the rest of the tag, so it must be the last pair; `minimum`/`maximum` need an integer or number field, `format`/`pattern` a string field. A malformed tag, unknown key or wrong field type is an error from `For` naming the field, never a silent drop. |
| `jsonschemax.Overrides.With` | `core/internal/jsonschemax/jsonschemax.go` | Returns a new table holding clones of both operands' schemas (it neither mutates nor aliases them); the duplicate-type panic message is `jsonschemax: duplicate override for type <T>`. |

## Spec amendments

| Name | Amendment |
|---|---|
| `auth.Method.MayChangeCredentials` | `MethodSession` **and `MethodSessionDelegated`** return true (owner decision 2026-11-06), amending 05-authn §3.1's "only MethodSession … may change credentials". It keeps HEAD's reset-password flow (an admin mints a temp-login link; the user's delegated session sets the password), and every route that mints a delegated session is itself guarded by this check. `Interactive()` is unchanged: only `MethodSession`. |
| `archtest.NoInit` `//archtest:allow-var <reason>` | The escape hatch for spec-mandated struct values (`rbac.Public`, `rbac.AnyAuthenticated`; 05-rbac §3.1). Reason required, per spec only, refused on map/slice/func/pointer/chan values (03 R5). |
