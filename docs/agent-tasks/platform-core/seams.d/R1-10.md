## Spec deviation (amends 03 §3.2 item 6; lead-approved)

03 §3.2 item 6 (and R1-01's brief) defines `check_module_skew.py`'s "no skew" guarantee over every module in core's `go list -m all`. With the OTel, client_golang and gRPC requirements, core's pruned module graph lists seven modules that supply no package to core (`go-spew`, `go-jose/v4`, `go-difflib`, `rogpeppe/go-internal`, otel `stdouttrace`, `x/mod`, `x/tools`) at versions below the root's. `go mod tidy` deletes any require that would raise them, so the check and `make -C core ci`'s tidy-check could not both pass. The check now compares the modules that supply a package to core's build or tests (`go list -deps -test ./...` in core, unioned over linux, darwin and windows), still at their versions in core's `go list -m all` against the root's. The guarantee's stated purpose, "the binary could ship a dependency version core CI never ran", is kept: a module that supplies no package cannot change what core CI runs. Guarantees 2 (`core/go.sum` exists) and 3 (`--pin`) and the staticcheck tools-module comparison are unchanged. Every package-supplying module was raised to the root's version (`x/net`, `x/sys`, `x/text`, `proto/otlp`, `grpc-gateway`, `klauspost/compress`, and others).

## Gaps recorded

- `otlp_export_failures_total` and `span_redactions_total` (05-metrics §5/§6 core series) are not created here: the first needs the export-error path that `app.InstallProcessDefaults` owns (R1-15), the second the redacting span exporter R1-32 adds with `Options.Redactor`.
- The table entry `audiobook_organizer.deluge.rpc.duration` has no instrument (declared ahead of it, as at HEAD).
- The Prometheus exporter's translation strategy is pinned to `UnderscoreEscapingWithSuffixes` (05-metrics §3). HEAD set none, so its names followed the process-wide `model.NameValidationScheme` (UTF-8 by default): the classic text scrape (what the seeded contract scrape, the dashboards and the 2.x server read) was already underscore-escaped by promhttp, and that output is byte-identical here. A scraper negotiating `escaping=allow-utf-8` (a Prometheus 3 default) could have received dotted OTel names at HEAD and now receives the underscore names too. `TestTranslationStrategyPinned` proves the names no longer follow the global scheme.
