# F5-02 seams and coined names

This file lists what `internal/repairs/kinds.go` and its siblings added beyond 05-tasks §5T.8.2 and the F5-02 brief, the readings F5-02 took where the spec or the brief says nothing, and the seams later rows build on (F5-16's import of HEAD's rows and marks, F5-18's removal of the v2 reporter and the kernel wiring, the F5 flip). Everything not listed here follows the brief as written.

## Names beyond the spec

| Name | What it is |
|---|---|
| `repairs.Kinds(fixers, KindDeps) []tasks.Definition`, `Registry.Kinds(KindDeps)` | One `tasks.Fixer` definition per fixer, kind `repairs.KindPrefix+ID()` (`books.repairs.<id>`). `Registry.Kinds` exists so a list function that nothing else references is not an `unregistered-kind` finding in tasklint (conversion rule 4); the F5 flip passes its result to `Registrar.Tasks`. |
| `repairs.KindDeps` | Guard, Tags and Series readers; `NewWriter`; `PlanRows`; `BindStores`; `Scopes`; `StandDownKey`; `Concurrency`. See below for what the kernel supplies. |
| `repairs.PlannedRows` (`PlanOf`, `PlannedRow`) | The kernel's read of an apply run's plan rows. **Seam (F5-18 / kernel):** no module-facing accessor exists today. `tasks.FixerSpec.Load` is handed `(rc, params, rowID)` and not the planned row, and a fixer's `Replan` needs the row as planned (its `State`, its fingerprint). The kernel must implement this over the run's `plan_ref`; the bytes it returns are the `State` that `PlanRowOf` stored, i.e. HEAD's stored row JSON. A cleaner seam is for the executor to hand `Load` the planned `tasks.Row`; this PR does not touch `core/internal/executor`. |
| `repairs.PlanRowOf(Row) (tasks.Row, error)` | The one mapping of a repairs row to the executor's row. **Seam (F5-16, M4):** the import of HEAD's stored `opv2:row:` payloads must call this function, so an imported row fingerprints exactly like the row a native plan would have stored (see "M4" below). |
| `repairs.KindPrefix`, `repairs.ApplyConcurrencyKey` | `books.repairs.`; `books.repairs.apply`. |
| `repairs.WithStores[S]`, `repairs.StoresFrom[S]` (`stores.go`) | Generic and type-keyed. See the first deviation below. |
| `maintenance.FixerStores` (+ `FixerBookStores`, `FixerUserStores`), `(*Plugin).fixerStores(ctx)` (`stores_fixer.go`) | The 15 store accessors the fixers call, in two groups so no interface exceeds the width ratchet. |
| `repairsGuardTags(src)`, `(*Plugin).versionGroupPrimaryRepair(ctx, st, ...)`, `guardTagSource`, `vgPrimaryStores` | Two bodies shared between a fixer and an operation, defined outside the fixer files, take the stores they read as a parameter: `guardTagSource` (one accessor) and `vgPrimaryStores` (two). The operations pass their deps (`repairsGuardTags(p.deps)`); the fixers pass what `p.fixerStores(ctx)` returns (`retired-versions`, `version-group-primary-repair`). An earlier revision of this PR rebuilt the plugin around the shell's stores (`shellDeps`, `withFixerStores`) and called the bodies on that; the static guard could not tell that receiver from a bare `f.p`, so the bodies are now parameterised and `shellDeps` and `withFixerStores` are deleted. The other shared bodies take the stores from the context directly: the retire the fragment, duplicate-copies and consolidation-leftovers fixers share (`followUserStateInto`, `retireHandOff`) and retired-versions' own retire writer, `applied` record and provenance read (`newJournaledRetireWriter`, `recordApplied`, `retireOpProvenance`) all call `p.fixerStores(ctx)`. `TestPluginFixerStores_IsThePluginsDepsAccessorForAccessor` keeps the 16th-method tripwire for the fallback set. |
| `repairs.ErrNoRunEvents`, `rcReporter` (`rcreporter.go`) | The in-package `registry.Reporter` over `*tasks.RC` / `*tasks.ItemRC`. Disappears with F5-18's re-signing of `Plan` / `Replan`. |

## Deviations from the brief

1. **`FixerStores` is declared in `internal/plugins/maintenance`, not `internal/repairs/stores.go`.** The accessors' result types (`OpsStore`, `UserReadStateStore`, ...) are interfaces of the maintenance package, which imports `repairs`; `repairs` cannot name them. `stores.go` carries the set opaquely and type-keyed (`WithStores`/`StoresFrom`), so asking for the wrong type yields "absent", never a value of another type. `maintenance.FixerStores` is a new non-test file (`stores_fixer.go`, which the brief's `*_fixer.go` pattern admits).
2. **A fixer called with no shell falls back to HEAD's stores.** Rule 3 says a missing value is an error, never a fallback. HEAD's `RunPlan`/`RunApply` cannot bind stores (they live behind `repairs_ops.go` and `plugin.go`, which the brief forbids editing) and the 22 fixer test files, which must stay unchanged, call `Plan`/`Replan`/`Apply` directly with a bare context. So `(*Plugin).fixerStores(ctx)` returns the shell's stores when present and an adapter over the plugin's deps (exactly what `f.p.deps` returned) otherwise. The fallback is for that legacy v2 path only: the native shell refuses to run without `KindDeps.BindStores` (a plan, an apply and a follow-up are all refused, `TestRepairsKinds_RefusesWithoutBindStores`), so a native run can never fall back to the plugin's stores. What the 22 fixers read when the shell binds is checked by `TestFixers_PlanReplanAndApplyReadOnlyTheShellStores` (maintenance package, working in-memory stores, the plugin's own deps report any accessor reached), plus targeted tests for the retired-versions apply (live and resumed tail) and the shared retire. That test runs the fixers over a small library; a path it does not reach is not proved by it. **Seam (F5-18):** delete the fallback with `repairs_ops.go`.
3. **The candidate type is a wrapper, not `repairs.Row`.** `FixerSpec.Evaluate` runs at plan and at apply with the same signature and says nothing of which, and the apply needs the run's state (writer, scope, paths). `candidate{row, run}` says which: `run == nil` is a plan.
4. **The executor marks the row applied, not `Apply`.** The brief says Apply marks after success. `core/internal/executor/fixer.go` calls `w.MarkRowApplied` itself after `Apply` returns nil, so a second mark in `Apply` would be a double write. The mark order the brief asks for (mark only after the write succeeded) holds.
5. **`Guards` is empty on the definitions.** The executor drops a planned row a `Guard` refuses, where HEAD's plan keeps it listed and skipped (`Row.Skipped`). The framework guards run inside `Evaluate` and hold the row (`tasks.Row.Hold`) instead.
6. **`PartitionBy` is unset.** HEAD partitions rows that share any book transitively (union-find). One key per row cannot express that. `Row.Subjects` are every book of the row and the executor treats overlapping subjects as exclusive, which gives the same guarantee for the books the plan named (no two workers write one of them at once); `TestRepairsKinds_RowsSharingABookNeverApplyAtOnce` checks it on overlapping chains. The qualifier is HEAD's too: a book a Replan adds to a row (`newIDs`) is guarded but not locked, and series are not in `Subjects`.
7. **One gated `Write` per row.** `repairs.Writer` journals everything it writes itself; the executor sees one `w.Do` per row, `Resource` `books/books`, name `books.repairs.<id>`. The executor routes a Preview run to the plan stage and never applies in it, so the callback only sees Live; if its Writer ever answered `tasks.ErrPreview` the intent would be recorded and the fixer not called (`TestRepairsKinds_WriterAnsweringPreviewWritesNothing`). `Effects.Writes` is `books/books` and `books/series`.
8. **M4 is F5-16's.** The brief's tier line says "M4 imports HEAD's stored rows and marks into the shape this PR defines". The row shape and the decoder (`PlanRowOf`, `Load` reading HEAD's bytes, `TestRepairsKinds_LoadsHEADRowBytes`) are here; the import (crash-safe, idempotent, resumable, quarantine of unknown or undecodable rows, counted) is F5-16's. **Seam (F5-16):** read each HEAD `repairs.plan` run's `opv2:row:` payloads, call `PlanRowOf`, quarantine a payload `decodeRow` refuses (`ErrPlanRowsUnreadable`), and write the row under `plan:<id>`. HEAD's apply marks (`ApplyCheckpoint.Settled`) become the native marks of the apply run: only rows whose outcome is `settledForResume` (applied, partially_applied, changed_since_plan, skipped_guard, not_applicable, failed, owner_refused) are marked; `aborted_standdown_lost`, `canceled_skipped`, `would_apply` and `retry_later` are not.
9. **Row count is 22, not 25.** `52e732a28` retired `maintenance.normalize-letter-l-ordinals`, `maintenance.relink-stale-series` and `dedup.split-books` after `ac4368bdb`, so the registry at this base holds 22 fixers and 22 `*_fixer.go` files. The count test asserts 22 and the three retired ids are absent.
10. **Plan-only `Common` values do not carry.** HEAD's plan op (`repairs.plan`) had `ResumeDrop`, `PriorityLow`, a 2h timeout and its own `ConcurrencyKey`; a `Fixer` definition has one `Common`, so the apply values are used: `ResumeContinue`, `PriorityNormal`, 6h, key `books.repairs.apply`. A plan therefore queues behind an apply of any fixer and the reverse (HEAD kept them on separate keys).
11. **Approval has no plan age limit at HEAD; the native default is 7 days.** `Approval{PlanRequired: true}` leaves `MaxPlanAge` at its default. The brief does not say to carry a limit; recorded here.
12. **Guard-pass concurrency is the apply's.** HEAD's plan guard pass used `runtime.NumCPU()` workers; the native plan evaluates rows on the definition's `Parallelism` (`tasks.Fixed(4, ...)`, the I/O-bound count HEAD's apply used). Whole-library rows are therefore guarded on 4 workers, not NumCPU. The reason string on `Parallelism` says why.
13. **Files outside the brief's file list were touched.** `internal/books/tasklint_test.go` was not needed; `internal/plugins/maintenance/stores_fixer.go` is new; `internal/repairs/engine.go` is edited (guard and settle steps extracted); the dark kinds and the fallback helpers are baselined in `scripts/deadcode-baseline.txt` in a separate `chore(ci)` commit; maintenance and repairs test files were added (`kinds_test.go`, a maintenance test for the shell stores). Four existing test files were edited, mechanically (the `retireWriterFor(ctx, w)` signature change and a `ctx` field with a `cx()` helper on `retiredFixture`): `retired_versions_apply_revert_test.go`, `retired_versions_apply_test.go`, `retired_versions_decision_records_test.go` and `retired_versions_fixer_test.go` under `internal/plugins/maintenance/`. Every other test file in the PR is new.

14. **Fragment fixer window evidence.** `fragmentFixer.windowIndex()` read the store on every row; the row builders sit about 12 helpers below `buildRows`, so instead of re-signing the chain `fragLibrary` gained a `window` field set once per Plan and per `replanWith` from `windowIndexVia(st)` (same store, same capability lookup). A `fragLibrary` built by `loadLibrary` outside those two entries has no window evidence (no caller does). The alternative is the full `Via` chain.
15. **Kept-for-tests wrappers.** Eight helpers keep their original signature as a thin wrapper over the `...Via` variant because the fixers' tests call them (`fragmentFixer.stores`, `consolidationLeftoversFixer.newSource`, `duplicateCopiesFixer.detail`, `folderBooksFixer.handOff`, `junkTitleFixer.buildJunkIndex` and `candidateTitle`, `reconcileFixer.reader`, `versionTwinFixer.readers`). They are dead in production and baselined in the deadcode ratchet; they go with the HEAD path.

## What the native path does not carry (gaps for F5-18 / the flip)

The Fixer shape cannot express these HEAD behaviours of `RunApply` / the `repairs.apply` operation, so they are not reproduced; each needs an executor or kernel change, not a fixer change.

- **Owner apply.** `OwnerApplyRowIDs`, the one-shot grant, the audit note journaled on `OwnerWrites`, and `WithOwnerApply` on the fixer's context. A native apply never applies an owner row (`OwnerOnly` is carried on the row so the lane can show it).
- **Dry-run as a separate outcome.** HEAD's `would_apply`. The executor has no Preview apply (a Preview run is a plan), so there is no per-row would-apply outcome in the native shell.
- **Per-row outcomes.** HEAD reports `partially_applied`, `retry_later`, `skipped_guard`, `not_applicable`, `canceled_skipped` per row. The executor knows applied, skipped (`changed_since_plan`, `gone`) and failed. Here: guard holds, non-applicable and iTunes-set differences are skipped as `changed_since_plan` (with the reason in the run log); retry-later, partial and fenced rows are failed items with the fixer's error chain intact (`errors.Is` for `ErrRetryLater`, `ErrPartiallyApplied`, `tasks.ErrFenced`), and are not marked, so the next run of the plan tries them again. HEAD settles a `partially_applied` row (it is not retried on resume); a native partial row is not marked and is re-evaluated by the next run, where the fixer's own `Replan` recognises the steps it already wrote.
- **Marks are per apply run.** `RunStore.Marks(ctx, run)`. A second apply run of the same plan has no marks; the guard across runs is the fingerprint compare (a row already fixed re-plans to a different fingerprint), which is HEAD's guard too. `TestRepairsKinds_SecondApplyOfSamePlanDoesNotDoubleApply` pins it.
- **Stand-down.** HEAD holds the library scan stand-down for the whole apply and hard-aborts a row on a lost lease. The shell takes `rc.StandDown(KindDeps.StandDownKey)` once per Live run (not for a `NoScanStandDown` fixer) and releases it after the last row in flight has left (the executor also releases it when the run ends). The lease check on each write is the executor's fence. **Seam (F5-18):** set `StandDownKey` to the concurrency key the library scan kinds (`books.library.scan`, `books.library.scan-full`, 05-tasks rename map) run under. With it empty a Live apply of a fixer that writes library rows is refused (`TestRepairsKinds_LiveApplyRefusesWithoutStandDownKey`), never run without the stand-down.
- **Replan after apply, `Resumed` checkpoint, metrics.** `metrics.ObserveFixerDuration` is not called by the native path; the executor has its own run metrics. HEAD's `ApplyCheckpoint` is replaced by the executor's marks.
- **`Apply` is called only for a row `Evaluate` kept.** `Evaluate` at apply returns, for every row it refuses, a row whose fingerprint cannot equal the planned one (an `refused` input), so the executor skips it and never calls `Apply`; `Apply` also refuses a row with no kept evaluation. The kept `Row.Detail` (which fixers' `Apply` require and which is never persisted) lives in a per-run map keyed by row id, released with the run.
- **Atoms.** `KindDeps.Scopes` is books' `AtomTable` (`internal/books/atoms.go`), which `repairs` cannot import. `Start`, `Approve` and `View` are the same `AllOf` of the scopes of `RequiredPermissions(f)`: HEAD gates reading a plan's rows with the same set (opaccess), so `View` is not left at `core:tasks.view`. An atom `Scopes` does not know leaves `Perms.Start` zero, and the constructor reports it: a kind whose gate cannot be resolved is not registrable.
- **`Registrar.Resources("books", ...)`.** The definitions write `books/books` and `books/series`; the books module must declare those resource kinds when F5-18 registers the kinds (the kernel checks `Effects.Writes` against them at registration).

## Readings taken

- **Run state is built once per run.** `BeginApply`, the writer and the stand-down hang off the first `Load` of the run (`sync.Once` per run id), not off every row, and end when the run's context ends (`context.AfterFunc`) or in `AfterApply`, whichever comes first, but only once the rows still inside Evaluate or Apply have left (`TestRepairsKinds_RunEndWaitsForRowsInFlight`): a stopped run does not end its scope or let go of the stand-down under a worker that is mid-row, as HEAD held both until `RunApply` returned. A callback that starts after the state is ending is refused. A refused build is cached for the attempt that was refused, not retried per row: the build (and the stand-down it asks for) runs once, the refusal is logged once, and every row of the attempt still fails with the same error because the executor records one failure per row (`TestRepairsKinds_RefusedRunStateIsKeptForTheAttempt`). A resumed attempt has its own context, does not reuse the slot of an earlier attempt whose context is done (`TestRepairsKinds_ResumedAttemptDoesNotReuseAPendingSlot`), and builds again; a refused slot leaves the map when its attempt ends. The cost of caching is that a refusal whose cause clears mid-attempt (a busy stand-down, a store that comes back) is not retried until the run is resumed. `ApplyScoped`'s scope values are layered behind the item's own context values.
- **The writer's inner fence follows the run's context** and wraps both `tasks.ErrFenced` and `opswriter.ErrFenced`, so a fixer's own `errors.Is(err, opswriter.ErrFenced)` still sees a stop.
- **`AfterApply` is bounded.** It reads one stored plan row per applied row to collect books, on a `tasks.ForEach` pool of the definition's width, and runs in Live only. A follow-up failure is logged and fails nothing (HEAD records it on the result).
- **Rows with a hold, retry-later.** A re-plan that holds a row transiently (`RetryLater`, `RetryFingerprint` equal to the plan's fingerprint) maps to a row with the planned fingerprint and `Retry` set, so the executor reaches `Apply`, which answers `ErrRetryLater` without writing. An empty `RetryFingerprint` never matches (fail closed), as at HEAD.
- **Unknown risk words grade `RiskMedium`**, never low.

## Owner questions

1. **`lostCandidatesFixer.Apply` calls `RefetchMetadataCandidates` through the plugin's captured deps** (`lost_candidates_fixer.go`, `f.p.deps.RefetchMetadataCandidates(ctx, fresh.RowID)`). No existing seam fits. It is a provider-chain service call that writes the candidate cache; it is not a store, and `repairs.Writer` has no path for it. The options and what each costs:
   - (a) Add a `MetadataRefetcher()` accessor to `FixerUserStores`. `pluginFixerStores` answers it from the deps and the kernel must supply it at F5-18. That makes `FixerStores` 16 methods: `recStores`, `tripDeps`, `TestPluginFixerStores_IsThePluginsDepsAccessorForAccessor` and the guard's accessor count (15) change with it. The shell then owns the refetch, which means it owns the provider rate limits and the cache write too.
   - (b) Leave it as a reviewed non-store dep (the guard's allowlist names it with this reason) until F5-18 decides whether a refetch is its own task kind rather than a fixer's `Apply`. Cost: a native run of this fixer refetches through the legacy plugin's deps, not the shell's.
   Not changed here; (b) is what the tree does today.
2. **Seven read-only lookups also go through the plugin's deps and are not in `FixerStores`.** The guard lists them as deps: `BookIDsWithIdentifiers`, `BooksWithMetadataSourceHash`, `BooksWithMetadataSourceHashInMemory` (version-twin metadata fixer), `CachedMetadataCandidates` (junk-title fixer), `LatestCandidateFetchOutcome`, `LatestCandidateFetchOutcomes` (lost-candidates fixer) and `LatestReconcileScan` (reconcile fixer). Each is a read through HEAD's store, not the one the shell binds. They were outside the 15 accessors this row moved, so they were left as they are. Moving them is the same shape as (a): accessors on `FixerStores`, the kernel's implementation. Whether they belong in `FixerStores` or behind a narrower reader is the question.

## The static guard

`TestFixerStores_NoFixerReachesAStoreExceptThroughTheShell` (`internal/plugins/maintenance/fixer_stores_guard_test.go`, pass in `tools/fixerstores`, allowlist in `testdata/fixer_stores_allowlist.txt`) walks a VTA call graph from the Plan, Replan, Apply, Meta, BeginApply, AfterApply, RequiredPermissions and PlanOnly of every type that implements `repairs.Fixer`. It fails on:

- a `FixerStores` accessor called on anything that is not a store-family interface (`FixerStores`, either half, or an interface made only of accessors), keyed on function and accessor together, so a new accessor in an allowlisted function is a new report;
- a conversion of the plugin's deps (or a plugin type) into a store-family interface (`convert:From->To`): this is what makes a parameterised shared body (`repairsGuardTags`, `versionGroupPrimaryRepair`) protected, since the body now reads whatever its caller passes and the conversion is the visible place a wrong source would enter. The one allowlisted conversion is `fixerStores`' fallback to `pluginFixerStores`;
- any `ServerDeps` method that is not an accessor (a dep), unless allowlisted with a reason;
- a func argument that the maintenance package passes and the pass cannot follow (a func read from a field or a call result it cannot look through), unless allowlisted with a reason; and
- an allowlist entry the pass no longer reports.

The walk follows every function of the module and prunes only `registry.RunItems`, whose call-graph edges join every caller to every callback. Func values and maintenance values made into interfaces that a call hands out are followed from the call, for every kind of call (a closure given to a store's `Update` included).

What it does not do: it is VTA, so it is unsound for reflection and imprecise for function values stored in struct fields (it can report a callee that never runs, and can miss one that does; a func read from a field and passed on is only an unresolved argument). It does not walk code outside the module (the standard library, third-party packages, mediacore). It judges a receiver by its static type, so a store read through a variable typed as a store-family interface is not a sink even if it was filled from the plugin's deps; the conversion check is what catches the fill, and only where the conversion is a visible instruction. It complements the tripwire tests (`tripDeps` in `stores_fixer_test.go`), which see every call a test makes and none that a test does not.

It skips under `-short` and runs in the "Fixture Tests (no -short, race)" jobs of `ci.yml` through `make test-fixtures` (the weight of `internal/plugins/maintenance` in `scripts/ci/fixture_weights.json` carries about 150 s for it and is marked estimated until a pipeline measures it). It needs the x/tools module pinned in `tools/fixerstores/go.mod` in the runner's module cache, or network to fetch it.

## Found, not changed

- `repairs.Fixer.Apply` implementations return `ErrChangedSincePlan` from inside their own locks; the native executor has no per-row `changed_since_plan` outcome for an `Apply` error (see per-row outcomes above), so a row refused under the fixer's lock is a failed item here.
- `tasks.FixerSpec.Load` receiving no planned row is the SDK gap behind `PlannedRows`.
- `taskstest.Conformance` is the static half only; the runtime assertions (preview writes nothing, no write after the fence, crash/resume, partition order) need the executor. This PR's driver in `kinds_test.go` mirrors the executor's `fixerApply` for the callbacks' observable behaviour; the real executor cannot be imported from the root module, so the end-to-end test through `coretest` joins F5-18.
