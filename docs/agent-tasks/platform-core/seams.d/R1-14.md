# R1-14 seams and coined names

This file lists what the `MountLegacy` / legacy route manifest / redirect-exclusion PR added beyond 05-http-api §4.8, §8.1 (R1 row) and §8.2 and 09 §9.2.4: names the spec does not have, readings it took where the spec or brief is silent, and the seams later rows (R1-15, R1-17, F4) build on. Everything not listed here follows the code contract as written: `LegacyMount`, `LegacyRoute`, `LegacyAuth`, `RouteInfo`, `MatchedPattern` and the sentinels R1-13 declared.

## Names beyond the spec

| Name | What it is |
|---|---|
| `httpapi.LegacyMatchAgrees(ctx, method, ginPath) (agrees, ok bool)` | The SEC2-22 post-match check. Core cannot import gin (N7), so the check is split: core's mount wrapper puts the matched mux pattern and the gin routes it admits into ctx, and the legacy engine's post-match middleware asks whether the route gin actually chose is one of them. A ServesSPA mount's "/" fallback is wrapped too, with `GET /` and `HEAD /` as its only entries. `ok` is false outside a wrapper (a request gin serves directly, as at R1), so the check is a no-op there. |
| `httpapi.Router.AllowAuthMethods(owner, methods...)` | How the kernel hands a module's `Registrar.AuthMethod` names to the router, so an `OwnAuth` route's `AuthMethod` is checked against what its owner registered (`ErrOwnAuthMethod`). The kernel calls it at P7. |
| `httpapi.LegacyRedirect{Prefix, Location}` and `LegacyMount.Redirects` | The 05-http-api §8.2 redirect as a mount field. `Prefix` is a clean subtree ("/api/"). `Location(r)` returns the target and whether it applies. The dispatcher consults it only for a path no claim, no native route and no manifest route covers, and answers 301 or the legacy 404. A claimed path (including `/api/core/`) is never redirected. |
| `internal/server.legacyMatchCheck()` | The gin half of the post-match check: 404 `endpoint not found` when `LegacyMatchAgrees` says the mux and gin chose different routes. Installed first in `setupRoutes`, so it runs before every route-level middleware and handler; the eight global `router.Use` calls of `NewServer` (logger, recovery, security headers, CORS, Basic auth, raw response controller, compression, tracing) run before it, and none of them runs a route handler. A request gin routes to no route (`FullPath` "") skips it: its NoRoute chain runs no route's handler, and gin's own answer there (the /api redirect, the SPA, gin's 404) keeps a mounted path's status, `Content-Type` and body what HEAD answers. |
| `internal/server.legacyAPIRedirect(method, path)` and `versionedAPIPrefix` | The redirect's decision as a pure function, shared by the gin middleware and `LegacyRedirects`. It keeps every HEAD exclusion and adds `^/api/(core\|[a-z][a-z0-9]{1,15})/v[0-9]+(/\|$)`, the versioned-API shape of 05-http-api §8.2. |
| `internal/server.(*Server).LegacyManifest()`, `LegacyRedirects()` | What R1-15's `books` module passes to `MountLegacy`. `LegacyManifest` walks gin's `Routes()` and fails with `ErrLegacyManifest`, naming every missing and extra route, when the hand-written manifest and gin disagree. |
| `(*Server).ownerCredRoute`, `Server.ownerRoutes`, `routeKey` | `ownerCredRoute` is `credRoute` with `ownerGateWhenOwnerSet` inserted before the last handler, recording the route in `ownerRoutes` ("METHOD /full/path", the key `credRoutes` uses, now built by `routeKey`). The nine owner-gated routes register through it, so `TestLegacyManifest_OwnerGuardsMatchRegistrations` compares the `Guards.Owner` rows with the registrations one to one, and `TestOwnerGateOnlyThroughOwnerCredRoute` keeps it the only way to get the gate. |
| `absAuthMethod = "books.abs"` | The `Registrar.AuthMethod` name the ABS routes' `OwnAuth` and `Delegated` requirement use. R1-15 registers it. |
| `testdata/public_routes.golden`, `testdata/own_auth_routes.golden` | Reviewed lists of the routes that serve without core auth (abs off: 14 plus `GET /`; abs on: 25) and the 64 ABS `OwnAuth` routes. `UPDATE_GOLDEN=1` rewrites them. A route joining either list fails the test until a reviewer accepts the diff. |

## Spec readings

| Topic | Reading |
|---|---|
| Generalised pattern (§4.8 rule 3) | A folded component's wildcard at segment `i` (1-based) is `{p<i>}`. The pattern is checked against every member with the real `http.ServeMux` (register, recover the panic) as the oracle, not a reimplementation of its precedence. |
| Kept routes (§4.8 rule 2) | A member is kept as its own pattern only when it is strictly more specific than every other member it overlaps, as gin's static-over-param preference would choose it. A member that is not (a HEAD-only member, for example) folds. |
| Identical requirements (§4.8 rule 4) | Compared on `Perm`, `Guards`, `RateClass`, `OwnAuth`, `AuthMethod`, `BasicExempt`, `NoCompress` and `Interactive`. Any difference refuses the set with `ErrPatternConflict` naming the routes. At base, the five conflict sets the spec names all qualify: every member is `library.view` or ABS `OwnAuth`. |
| Cross-owner overlap | A route strictly more specific than another owner's pattern is `ErrShadow` (the other owner would silently lose requests). Equal patterns across owners are the mux's own conflict. |
| Placement | A manifest route must sit inside one of its owner's claims (`ErrOutsideClaim`); a subtree claim `/x/` also covers `/x`. Outside `/api/` its first segment must be a `TopSegments` or `SPAShared` entry of its mount, reserved or not (`auth`, `health` and `metrics` pass only when listed; books lists them). The reserved segments that are core's or the SPA's own path space, `v<digits>`, `livez`, `readyz`, `assets`, `static` and `ui`, are refused even when listed. All refusals are `ErrPrefixCollision` (`TestLegacyPlace_CoreOnlySegmentsRefused`). |
| Public | `Public` on a route if and only if its requirement is `rbac.Public` (`ErrLegacyManifest` otherwise). Legacy rows carry no route name, so `Manifest.PublicRoutes` (keyed by name) does not cover them; the reviewed `public_routes.golden` is their gate. |
| `LegacyAuthGin` admission | The Registrar's check (R1-13, `ProblemLegacyAuth` at P6), not the router's. An earlier draft of this row also checked it in `Build` through a coined `AllowLegacyAuthGin`; it was dropped on rebase so there is one implementation. The router is kernel-only, so nothing reaches `MountLegacy` without the Registrar. |
| `Auth` | Required on every mount (R1-13's rule, adopted on rebase): `MountLegacy` refuses an `Auth` that is neither `LegacyAuthCore` nor `LegacyAuthGin` with `ErrLegacyManifest`. |
| The "/" fallback | A ServesSPA legacy mount's handler is the "/" owner only through a wrapper that admits `GET /` and `HEAD /` (05-http-api §8.2: the fallback reaches the legacy router's NoRoute chain only). An unclean non-/api path or an unmatched SPAShared GET that gin would route to any other handler gets the post-match 404 (`TestFallback_UncleanPathNeverRunsALegacyRoute`, `TestFallback_EncodedSlashOnSPASharedNeverRunsALegacyRoute`, real engine: `TestLegacyMount_FallbackNeverRunsARouteHandler`). Sanctioned parity change: `GET /public/session/../track/1`, which gin alone routes to PublicSessionTrack with session `..`, is a 404 through the mount, and so is `GET /public%2Fsession%2Fx%2Ftrack%2F1`, which gin decodes and answers from the same handler. The fallback also records no `http.route` (stage 2). |
| Drift check | `checkLegacyManifest` skips only `GET /` and `HEAD /` (the "/" owner's page); any other method on "/" needs a manifest row (`TestLegacyManifest_DriftFailsBoot`). |
| Unmatched requests on a mounted path | Answered with the status, `Content-Type` and body HEAD's gin gives. A wrong method under a legacy claim is the legacy 404 (no problem 405, no `Allow`). A path the mux would answer with its trailing-slash 307 (`GET /x` with only `/x/{$}`) is a miss: problem 404 natively, the legacy 404 under a legacy claim (gin runs with `RedirectTrailingSlash` off). An unmatched GET or HEAD on a `SPAShared` segment goes to the "/" owner before the legacy-claim 404, so `GET /login` is the shell. |
| `LegacyAuthCore` | Refused with `ErrNoAuthService` while it has non-public routes: there is no core auth service until R2. Books mounts `LegacyAuthGin`. |
| `LegacyCheck` | Refused in a manifest. Gin enforces the atom at R1; a `LegacyCheck` requirement would claim an enforcement core does not do. |
| Master-list routes | The four `users.manage` master-list routes record 05-rbac §6.2's `AllOf(core:users.manage, books:admin.view)`, not `LegacyAtom(users.manage)`. `LegacyAtom` alone is weaker than what gin enforces (it also requires admin). So 426 rows carry `LegacyAtom` (421 `s.perm` sites plus 5 fingerprint-worker routes), not every `s.perm` site. |
| `Interactive` | True exactly where `credRoutes` marks the route "always". A route whose credential guard is conditional (`credRouteWhen`) is `Interactive: false`; gin keeps applying that guard. |
| Owner guards | `ownerGateWhenOwnerSet()` routes are hand-listed (9 rows) and checked against the source by a scan in `TestLegacyManifest_OwnerGuardsMatchSource`, because HEAD records them nowhere a test can read. |
| `GET /` | Not in books' manifest. It belongs to the mount that serves the SPA ("/" owner); a second owner of "/" is refused. |
| ABS unauthenticated routes | `Public` (they serve without core auth; ABS's own token check is inside the handler). |

## Behaviour notes

- **405 versus 404 (decided 2026-11-07, implemented here).** A legacy-mounted path must answer with the status, `Content-Type` and body HEAD's gin gives. HEAD's gin answers a wrong method with its 404 (`HandleMethodNotAllowed` is off); R1-13's dispatcher answered a problem 405. The dispatcher now skips the 405 for a path under a legacy claim, and `TestLegacyMount_UnmatchedMethodMatchesGin` compares status, `Content-Type` and body of gin and the mount for every manifest path and every method gin has no route for, ABS off and on (core: `TestDispatch_LegacyWrongMethodIsLegacyNotFound`). **R1-15 requirement:** when gin moves behind the mount, that test must keep passing against the composed app.
- **Headers, OPTIONS and the Basic gate (review M1; R1-17).** Parity covers status, `Content-Type` and body, not headers. Responses core writes itself (the legacy 404, the 301, a problem 404) lack gin's CSP, X-Frame-Options, Referrer-Policy, Permissions-Policy, Reporting-Endpoints and HSTS and skip the Basic gate; gin's CORS middleware answers every OPTIONS 204 (with CORS headers for an Origin), while the mount answers OPTIONS as an unmatched method (`OPTIONS /api/v1/audiobooks` a legacy 404, `OPTIONS /api/audiobooks` a 301). Those are 05-http-api §4.2 perimeter stages 5, 6 and 8, which R1-17 builds. `TestLegacyMount_UnmatchedMethodMatchesGin` asserts the OPTIONS difference so it fails loudly when stage 6 (CORS) lands. **R1-15 requirement:** the mount must not serve production traffic until R1-17's stages 5, 6 and 8 wrap it.
- **Sanctioned, unchanged differences (review MINOR-5).** `GET /API/v1/...`, `GET /Health`, an unclaimed `/socket.io/x` and `POST /library` get gin's JSON 404 from gin and core's problem+json 404 through the mount; `GET /api//audiobooks` is a 301 from gin and a problem 404 through the mount (an unclean /api/ path never reaches a handler, §4.8). Whether `/socket.io/` is books' is R1-15's claim set to decide.
- **Trailing-slash redirect (review MINOR-5).** `ServeMux.Handler` returns the pattern that matched `path+"/"` for its 307; the dispatcher recognises that case (`slashRedirect`) and treats it as a miss (`TestDispatch_TrailingSlashPatternNoRedirect`).
- **`/api/core/…`.** Behind the mount the core claim wins, so `/api/core/vx` is a problem 404, never a redirect. Through gin alone (R1) the versioned-prefix exclusion gives the same answer.

## Seams for later rows

- **R1-15 (composition root):** `books` calls `LegacyManifest()` and passes the result to `r.MountLegacy(httpapi.LegacyMount{Owner: "books", Auth: httpapi.LegacyAuthGin, Handler: <the gin engine>, Routes: slices.Values(manifest), Redirects: srv.LegacyRedirects(), ServesSPA: true, ...})`, registers `AuthMethod("books.abs")`, and lists the abs-on public golden in `Manifest.PublicRoutes`. `booksMount` in `legacy_manifest_test.go` is the working shape. `TestManifest_SPermRoutesCarryAtomRequirement` must allow the four master-list `AllOf` rows. `LegacyAtom` resolution goes through books' atom table.
- **R1-17 (perimeter):** the perimeter wraps the mux, outside it. The post-match middleware must keep running before every route-level middleware and handler, and none of the global gin middleware ahead of it may run a route handler. Stages 5, 6 and 8 close the header, OPTIONS and Basic-gate differences above.
- **R2 (core auth):** `LegacyAuthCore` and `LegacyCheck` become legal once an auth service exists; lift `ErrNoAuthService` and the `LegacyCheck` refusal together.
- **F4:** moving a route from the manifest to `Handle` removes its row; `TestLegacyManifest_MatchesGinRoutes` fails until both sides change.
