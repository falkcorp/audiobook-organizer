# F4-06 seams and coined names

What F4-06 added beyond 05-authn §11, 05-rbac §6.3 and 05-storage §5S.3.13 and the F4-06 brief, the readings it took where they are silent, the discrepancies it found, and what F4-07 and F4-08 must do with it. Nothing here runs on `main`: `books.Module()` registers none of it (`ls internal/books/cutover/steps.go` finds nothing, `grep -c 'm3\.' internal/books/cutover/*.go` outside `identity_step.go` and `preflight.go` finds the tests only). F4-08 registers M3 in `steps.go` after M2 and supplies `m3.Config`.

## Names beyond the spec

| Name | What it is |
|---|---|
| `m3.Config` | `StepID`, `Atoms []AtomRow`, `SeedRoles []SeedRole`, `Catalog`, `Ambient`, `Auth auth.Importer`, `Roles rbac.Importer`, `Native NativeReader`, `Audit audit.Logger`, `Legacy func() storage.Reader`, `Now`, `KeyTTL`, `Logger`. `cutover.IdentityStep` sets `StepID` to `IdentityCutoverID` and refuses another. `Legacy` is an accessor for books' legacy range: the runner hands a Step one source pair, and M3 reads the rows it pulls ahead of its cursor and the rows that go with a row. |
| `m3.NativeReader` | `GetUser`, `GetRole`: what core's stores already hold, to find a key's owner and a taken role name when an earlier chunk committed them. A lookup of an absent record wraps `auth.ErrNotFound` or `rbac.ErrUnknownRole`. |
| `m3.SourcePrefixes()`, `SourceKeys()`, `SourceRanges()`, `SensitivePrefixes()`, `RefFamilyPrefixes()` | The 13 identity prefixes, the two exact bootstrap keys, the step's `Source`, the Sensitive prefixes and Verify's referential families, each pinned to its source list by a census (`TestIdentityCutover_SourceIsTheIdentityClaims`, `TestIdentityCutover_RefFamiliesAreTheMergesList` in `internal/books/store`). |
| `m3.JournalFamily`, `m3.MergeFix` | The family name and the Fix text of a merge-journal blocker. The text names no `storage cutover-blockers` action, which is how the command knows to offer neither fix nor delete. |
| `storage.ErrCutoverStarted`, `CutoverBlockerEdit`, `CutoverBlockerRecord`, `CutoverBlockerKey`, `CutoverBlockerFix`, `CutoverBlockerDelete` | The seam of `fix` and `delete`. The write goes through an unexported handle that admits `Set` and `Delete` only for keys inside the owning step's `Source` that resolve to the owner's retired claims, so no retired family is writable by anything else. |
| `kernel.CutoverBlockersOptions{Bind}` | `Bind` receives the opened store so a step's `Preflight`, `FixBlocker` and `DeleteBlocker` can bind the handles they read through. `core/app` passes none: F4-08 sets it from `db.Legacy`. |
| The Fix-text contract | A blocker's `Fix` offers `fix` or `delete` only when it contains `storage cutover-blockers` followed by `fix`, `delete` or `fix\|delete` (`kernel.blockerOffers`). A step's preflight must keep to it. |

## Readings taken where the spec or the brief is silent

| Question | Reading |
|---|---|
| Role names | `custom.role-<lower-cased ULID>`: HEAD's role IDs are ULIDs and start with a digit, so the slug takes a `role-` prefix. An ID longer than 32 bytes once slugged is cut to 23 bytes, `-` and 8 hex digits of the ID's SHA-256, so two long IDs never meet. A role whose ID cannot be named, whose name is taken, whose every atom is unknown, or that rbac refuses is quarantined; a role with no permissions is imported with the ambient scopes. |
| `EmailVerified` | True when the row has an address and its `email_source` is `setup`, `admin`, `invite` or `idp` (HEAD's trusted sources); HEAD stamps a source on every row that has an address at each store open, so a row without one is unverified, as HEAD reads it. |
| `PasswordResetRequired` | True when the hash is blank, the algorithm is named and it is not `oauth`: a restore or a factory credential reset blanked it. An account that never had an algorithm (the system user) has no password to reset. |
| Statuses | `""` and `active` are active, `inactive` is disabled, anything else is disabled and reported by ID and the status folded and cut to 32 bytes (SEC-11). HEAD's `_system` row (status `system`) is such a row: it imports disabled and is reported; core's own system user is core's. A key is revoked by `revoked` or any `revoked_at`; `inactive` is disabled; `""` and `active` are active; anything else is disabled and reported. |
| An empty scope list | The owner's whole set (not only its atoms' scopes), intersected with the owner's set as a role-only checker compiles it; only an admin owner's empty-list or every-atom key gets `core:admin` and every row's scopes. The ambient scopes are added unless the set is Confined, so an empty result still holds them: no key is imported with no scopes. |
| An undecodable merge journal | A preflight blocker (Fix: finish or undo the merge on the pre-freeze release): "a merge in progress cannot be ruled out". A journal with any other status does not block. |
| Two users that fold to one username | The second, in key order, is a blocker naming the first by ID: the importer's own refusal, decided from HEAD's rows because nothing is staged. |
| Journal tokens | `rewriteOutside` runs at the first item of every chunk, so a rewrite must settle: a raw invite token becomes `invite-sha256:<hex of its SHA-256>` in the key image, in the base64 images and in the conflict text, and a token already in that form is never hashed again. `Verify` fails any journal that still names a raw token. The journal's `digest` no longer matches its rewritten images; no merge is undone after the cutover, so nothing reads it. |
| The bootstrap rows | Ownership table row 8 retires `setting:bootstrap_token_hash` and `setting:bootstrap_token_expires_at` and has M3 delete them, so they are exact keys in `Source`. HEAD's expiry flag `setting:system:migration:apikey_expiry_stamp_v1_done` is row 16's, outside `Source`, and `Step` deletes it. The `startup_readonly_key_*` rows are not deleted (row 16 leaves them). |
| The allow-list and the roles | Quarantine-and-continue, with a fixed reason and a sealed record: neither is an identity. A user, key or identity the importer refuses while the step runs fails the chunk with `storage.ErrCutoverBlocked`, never a quarantine. |
| One chunk's batch | Indexed (see "Core changes"): the first item of a chunk imports every role and user ahead of the cursor and stages the journal and flag rewrites, so a key finds its owner in the same batch. A kill after the first chunk leaves natives under `c/auth/` and the rest of the keys in HEAD's rows; the boot that resumes skips the preflight (the cutover has started). |
| Orphaned references | Counted per referencing family by `Verify` (eleven families: the seven per-user key families, the two exact ones and the two owner-field ones), never a failure. The per-user families are read a user at a time, so a library of a few users costs a few lookups; the families are read concurrently, bounded by the CPU count. |
| `internal/arch` | `layerOverride` gains `internal/books/cutover`: 0 (it imports core and its own leaf `m3`, which names no module package; the import floor would otherwise put it at 3). |
| No `r2corpus/m3/` | The brief's file table lists `internal/books/testdata/r2corpus/m3/`. The R0-written stage1, overlay and blocker cells already carry every row M3 needs, and the expected answers are assertions in the tests, so no new corpus directory exists. |

## Core changes beyond the brief

| Change | Why |
|---|---|
| `core/internal/storagemigrate/run.go`: a cutover step's chunk batch is `NewIndexedBatch` | `authstore.ownerPresent` reads the owner back through the batch, and a plain batch does not see its own writes, so a key and its owner could never share a chunk and the step would need one chunk per user. A mutant that restores the plain batch fails `a cutover chunk's batch is indexed`. |
| `core/auth/import_check.go` | See above. |

## For F4-08

`m3.Config` needs, from the booted core and books:

- `Atoms`: `books.AtomTable()` rows as `m3.AtomRow{Name, Scopes}`.
- `SeedRoles`: the four HEAD seed IDs (`admin`, `editor`, `viewer`, `fp-worker`) with the native sets books' `DefaultGrants` and core's seed grant, resolved.
- `Catalog` and `Ambient`: core's catalog as the cutover build declares it, and `core:self`, `core:metrics.read`, `books:reading`.
- `Auth` and `Roles`: **the same store instances core hands the kernel**, because the role store seals imports at `Freeze`. `Native` is the read side of the same two.
- `Audit`: the `audit.Logger` whose `RecordIn` joins the chunk's batch (`core.role.create` with `imported: true`), or nil.
- `Legacy`: the accessor of books' legacy range, set when the store opens (also `CutoverBlockersOptions.Bind`, so the command's `Preflight`, `FixBlocker` and `DeleteBlocker` read through the command's store).
- `KeyTTL`: `handlers.DefaultAPIKeyTTL`. `Now`: the cutover's clock.

Claims. The cutover build's spec must retire the 13 `m3.SourcePrefixes()` **and** declare the two exact bootstrap keys (`m3.SourceKeys()`) as retired claims inside the read-write `setting:` family: `booksclaims.go` declares no exact claim for them at R1, and a Source key that no retired claim covers fails the cutover's own check. `TestIdentityCutover_SourceIsTheIdentityClaims` pins `serializedFamilies` and `serializedSubClaims` to `SourcePrefixes`; the rig of `identity_rig_test.go` (`spec(true)`) is the reference for the retirement.

Register `IdentityStep(cfg, <the flip's level>, books.BooksLevelStepRef(<its version>))` after M2 in `steps.go`. Not here, and F4-08's: the `cobra` wrapper for `storage cutover-blockers` under `cmd/`, the merge-undo 409 `merge_permanent`, `TestCutover_NoRawTokenOnDisk`, the live route of the worker key (`TestIdentityCutover_WorkerKeyStaysConfined` here asserts its checker input), and the reach oracle (F4-07).

## Spec discrepancies found

| Where | What |
|---|---|
| `storage.CutoverBlockerReport` | Its last line sent the operator to run `storage cutover-blockers` "on the pre-freeze release", which does not have the command: 05-storage §5S.3.13 calls it an R2 offline command and `kernel.OpenCutoverBlockers` runs on the cutover build. Fixed here: it says to run it on this release with the service stopped. |
| 04-package-mapping and the ownership table | The package mapping names four bootstrap rows (`startup_readonly_key_*` among them); the ownership table row 8 retires two. M3 follows the table: the other two are row 16's and stay. |

## Out of scope, noticed

- `abs_sess:` rows are not counted by `Verify`'s referential pass: ABS's families are untouched by M3 (05-authn §11), and nothing in R2 resolves them to a native user.
- `storage.Open` rewrites Pebble's manifest and WAL on every open, so "byte-identical" for a refused boot is asserted over the rows, the directory entries and the sidecar's bytes, not Pebble's own files.
- The dark exported API (`IdentityStep`, `m3.*`, `kernel.OpenCutoverBlockers`, `storage.BeginCutoverBlockers`, `EditCutoverBlocker` and the `auth.CheckImport*` predicates) is listed in `scripts/deadcode-baseline.txt` until F4-08 imports it.
