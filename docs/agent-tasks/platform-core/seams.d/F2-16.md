# F2-16 seams and coined names

This file lists what the kernel wiring of the F2 foundation added beyond 06 §6.5 and the F2 briefs, the readings it took where the spec or the brief is silent, the deviations from the brief, and the seams later rows build on. Everything not listed here follows the spec as written.

## Names beyond the spec

| Name | What it is |
|---|---|
| `module.Manifest.TaskLedger`, `module.Manifest.DataMigrations`; `Registrar.Tasks`, `Registrar.Resources`; `Registrations.Tasks`, `Registrations.Resources` | The manifest and registrar members the F2 foundation needs. The registrar only records (a nil definition, an empty or a duplicate resource kind is a `ProblemInvalidRegistration`); every judgement is the kernel's, at P1 (ledger, data-migration owner) and P7 (`taskProblems`). |
| `kernel.phaseP4c`, `Kernel.buildStores` | The new boot phase "P4c", after P4b: it builds health (`buildHealth`) and the native task stores (`buildTaskStores`). It is recorded only when a store is open, so a no-store boot keeps its phase list. |
| `taskOwnerSpec()`, and `auditOwnerSpec()` prepended in `storageOwners()` | core/audit and core/tasks are claimed in every app's store at the first P4b after F2-16 lands (one claim-ledger write each). They are claimed whether or not anything reads them yet, because P2 Open and P4a Prepare need the keyspace before P7 decides whether the tasks start. |
| `kernel.coreConfig` (`taskconfig.go`) | A defaults-only `config.Store` over `coreSections()`: no environment, no file, no layering. `declared(key)` (core keys only), `schedule(key)`, `window(name)` and the executor and scheduler adapters read it. F3-07 replaces it with the layered store; the adapters keep their shape. |
| `labelDefUpsert` = `tasks.def.upsert` | The bootseam region around the definition snapshot upserts; the crash-matrix row `Phase P7, tasks.def.upsert` is in `coretest/crashmatrix/rows.go`. |
| `bootseam.Seams.TaskRuns []TaskRunSeed{Kind, N}`, `coretest.WithRuns` | Test seam: n queued runs of a kind inserted at P4c before the start rule runs. |
| `app.App.TaskClient()`, `App.TaskRecord(ctx, id)`, `App.StartTasks(ctx)`; `kernel.StartTasks`, `kernel.TaskClient`, `kernel.TaskRecord` | Thin accessors for coretest, like `Routes` and `StorageAdmin` before them. `TaskClient` is nil when the start rule did not hold. |
| `coretest.Harness.RunTask`, `Harness.Runs`, `Harness.Reboot`, `RunResult` | RunTask starts a run as the harness administrator and waits (30 s) for a terminal state; Runs lists runs through the Client, held ones with `RunView.Held`; Reboot starts a new App over the same in-memory filesystem and state directory. |

## Readings

| Topic | Reading |
|---|---|
| Start rule | The executor, the scheduler and the task server start when a module registered a kind, or a bounded `Scan(RunPrefix, nil, 1)` finds a stored run. Registering a kind with no store open fails the boot (fail closed). The rule runs at P7, after `consume`. |
| Held runs | A disabled module's TaskLedger kinds are the executor's `Manifests` hold set: its runs are known, listed held, never dispatched, never dropped as unknown kinds. |
| Definition snapshot | An opaque JSON `{v, shape, title, help}` without the kind, upserted one batch per definition and only when the stored snapshot differs, inside the `tasks.def.upsert` region. |
| Data migrations runner | Built only when some manifest declares `DataMigrations`; its preflight runs before P4a Prepare, `RecordMetrics` after the storage metrics. |
| Audit before P4b | `buildAudit` runs right after P4a Prepare and before the P4b migrations, so a data-migration step can audit. `TestKernelBoot_F2CallsInOrder` proves the order from the log. |
| Shutdown order | Listener drain, then `stopCoreServices` (scheduler Stop, wait, executor Shutdown, then `stopAudit`), then workers and hooks, then `closeCore` (which also calls it first, idempotently, for the paths that do not go through `stop`). The config store closes with `context.WithoutCancel`: an expired boot context gave "subscribers still running". |
| P7 checks | `taskProblems` reports every problem: constructor problems, kind namespace, TaskLedger membership, duplicates, `PrioritySystem`, `Perms.Start` namespace, view-class core scopes without `StartableByViewers`, undeclared or foreign Effects resources, and `scheduler.ValidateSchedules`. |

## Deviations and blocked items

| Item | What happened |
|---|---|
| **The 19 task routes are not mounted.** | `httpapi.Router.checkPerm` appends `ErrNoAuthService` to every non-Public native route, `HandleRaw` is a comment only, and the Router's Deps carry no auth. The task server is built behind the start rule (`Kernel.tasks.server`) and never registered; marking the routes Public would expose them without authentication, so they are not. **Seam:** the row that lands `HandleRaw` and the router's auth mounts `server.Routes()` and `server.Handler()` where `startTasks` builds it, then deletes the two `scripts/deadcode-baseline.txt` lines this PR added (`taskhttp.Server.Handler`, `taskhttp.Server.Routes`), and regenerates `openapi/core.json` and the client. Until then `GET /api/core/v1/tasks/runs` has no HTTP cell; `Harness.Runs` is the non-HTTP form. |
| `app.App` gained three accessors. | The brief says no new App member; the precedent is `Routes` and `StorageAdmin`. coretest cannot reach the kernel any other way. |
| The op-ledger line of the brief's disabled-module test has no F2 equivalent. | `TestDisabledModuleWithRunsBoots` asserts the held-runs cells and the re-enable resume; HEAD's op ledger has nothing to compare. |
| `Executor OnTerminal` is nil, there is no `Deps.Tasks` and no TaskStarts. | Notify has not landed (F5). |
| Module schedule config keys are undeclared. | `declared` knows core's keys only, so a module kind's schedule key is refused until module settings (F3); core kinds are unaffected. |
| `app/offline_storage_test.go` expectation changed. | A served store now has core/audit, so the offline purge of an empty step succeeds; the refusal over a store without core/audit stays covered by `kernel/cutover_test.go` (`PurgeQuarantine` with a bare db). |
| `hello.CountTask` and its tasklint allowlist entry are deleted, as F2-05's seam said. | `hello.go` now registers `countTask(svc)`. `count.go` keeps the go-fix flattened literal (F2-05 noted the 06 §6.12.3 snapshot shows the nested form); the spec snapshot may be updated in a docs pass. |
