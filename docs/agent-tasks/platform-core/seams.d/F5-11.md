# F5-11 seams and coined names

F5-11 converts the 14 T6 group 6 maintenance definitions to native `books.<ID>` kinds (`internal/plugins/maintenance/kinds_t6_g6.go`). They are dark: nothing registers them before the tasks flip (F5-18). This file lists the readings the row took where the brief is silent, the helpers it added, and what later rows build on.

## Seams

- `t6g6Store` and `t6g6Writer` are composed by embedding each definition's own narrow interface, not one hand-written interface. Every core takes only its narrow piece; the composition is what `t6g6Deps` carries.
- `t6g6Deps` is wider than the brief's two fields. Besides `Store` and `NewWriter` it carries `ActivityLogFullDetailDays`, `StandDownKey`, `RootDir`, `ResolveReportPath` and `ITunesRoots`. F5-18 fills them. A native shell refuses at the top when a dep it needs is nil, instead of panicking inside a worker.
- `StandDownKey` empty refuses a live apply that needs the stand-down (recover-missing-files with repoints, repoint-book-file-rows). A native apply never runs without the lease. The native stand-down `Lost()` reports false: a lost lease is caught by the writer fence.
- Effects use only resources declared in `pkg/ops/effects.go` on origin/main: books, book_files, files, operations, activity, review_items, user_state. No resource name was coined. `operations` is the undo journal only (opchange, heal, repoint), never the activity log (that is `activity`).
- Native params drop `dry_run` and `apply`: the run's mode carries them (Preview reports, Live applies). Every native kind that writes refuses those keys, in any case, before it builds a writer (`t6g6RefuseModeKeys`, one test row per kind per spelling). Live-only writers (nightly compaction, recompact digests, iTunes heal) refuse Preview with `<kind>: preview not supported; start with mode live`.
- repair-merged-user-state reads through `env.Store` and writes through `env.Writer`. `merge.RepairMergedUserState` takes one store and probes it for the sync-identity, bookmark, bookmark-copier and position-timestamp capabilities, so the core composes that object from the two halves (`t6g6ComposeUserState`). A capability is present only when both halves carry it. Layers embed the concrete type below them; embedding the interface would hide the lower layers (found by CI, pinned by `TestT6G6More_ComposedUserStateStacksCapabilities`).
- iTunes heal's body now lives in `internal/reconcile` (`RunITunesHealVia` over `HealReader` and `HealWriter`); the HEAD shell calls it through `NewHeadHealWriter`. The native writer adapts the run to the three writes it makes (`CollapseHealDuplicates`, `HealTrack`, `HealWhisperJournal`).
- Resume: Restart maps to `ResumeContinue` only where the native body reads a checkpoint on restart (optimize, opchange ensure); iTunes heal and repair-transcribe-status restart from zero (`ResumeFromZero`).
- Optimize: `Resume` is `ResumeContinue` and `Timeout` is `tasks.MaxTimeout` (24h), against HEAD's 36h chain budget. Deviation from R5: the kernel only honours `tasks.ErrContinueInPlace` for `ResumeContinue`. The core checkpoints the finished children, yields between children when less than five minutes of the attempt remain, and fails a resumed run that is more than 36h past its first start. Not proven: `rc.Await` takes no context, so a child that is already in flight cannot be yielded; 36h parity is not claimed for a single long child.
- Optimize's children are `books.maintenance.temp-file-cleanup`, `books.acoustid.fingerprint-rescan`, `books.acoustid.scan` and `books.acoustid.backfill` (test-pinned). No row on origin/main or a sibling branch declares those kinds yet; the native optimize cannot run before the owning rows land. It has no progress relay (HEAD's `relayChildProgress` fed its watchdog); the native run adds a progress step after each child.
- The opchange ensure's yield is `tasks.ErrContinueInPlace` natively, written after a checkpoint marker; the executor's handling of it is not proven here.
- Hold renewal: a native apply holds the stand-down for the whole run, and core's `Hold` has no renew call, so a long recover or repoint relies on the lease outliving the run. At HEAD the registry renewed it. Follow-up for core (`Hold.Renew`), filed in the w27 state todo.

## Deviations

- Via variants are the shared cores; the old test-only wrappers were deleted with their baseline lines and the tests call the cores (coordinator ruling 1): `findOrphanBookFiles`, `planOrphanRepoints`, `probeAll`, `planRecoverMissingFiles`, `reconcileStaleHolds`, `staleRegroupHolds`, `decidedRegroupHolds`, `opChangeIndexProgressTo`, the opchange wrappers, three loopless `*Parallelism` functions. Tests use `t6g6TestPlanRecover`, `t6g6OrphanFixture` and `t6g6RecoverFixture` (`t6g6_head_fixtures_test.go`), which build the env a HEAD run hands the core.
- `internal/reconcile/itunes_heal.go` and four of its tests changed (outside the maintenance package), for the heal reader and writer split.
- `internal/arch/resume_restart_guard_test.go`: the opchange `restartWithoutCheckpoint` entry was removed, because the native shell now has a checkpoint call the static scan finds. The HEAD def still never checkpoints (`env.Checkpoint` is nil there).
- The nightly core holds an inlined copy of F5-08's `compactAndRecordCore` (`nightlyCompactAndRecord`, one function). Swap once F5-08 merges: replace its body with `return compactAndRecordCore(ctx, cutoff, startMsg, nightlyCompactRecordEnv{env})`, where the adapter maps `env.Log`, `env.Progress` and `env.Writer.CompactActivityEntries` to `compactRecordEnv`. The recompact core has no such twin. F5-18 removes the copy with the HEAD shells.
- Schedules dropped: the HEAD defs declared `10 0 * * *` (nightly compaction) and `15 2 * * *` (orphan scan) in the scheduler tables; the native definitions carry no schedule (the shell takes one through `sched`; F5-18 supplies them).
- Wider write sets than HEAD declared: probe-directory-books and relink-unlinked-books also write `books` (the aggregate recompute); iTunes heal writes books, book_files, files and operations; repair-merged writes books and user_state; recover writes book_files, books and files; repoint adds books and operations.
- ReadOnly: optimize (its children write), orphan book_file scan and orphan book_file repoint plan.
- Writes the cores make to the file system (reflinks, the heal journal, recover's file operations) are file I/O and bypass the gated writer; the database writes go through it.

## Follow-ups

- Hold renewal in core (above).
- F5-18 removes the HEAD v2 shells, the `t6g6Head*` adapters and the `var _ = t6g6KindList` and `var _ = (*Plugin).t6g6Kinds` lines, and the dark baseline lines for the native helpers (`t6g6DecodeNative`, `t6g6DecodeParams`, `t6g6NeedDep`, `t6g6NewWriter`, `t6g6RefuseModeKeys`, `itunesHealCore`).
- The wiring that builds `t6g6Deps` from the server (F5-18) is not proven here; the tests use fakes.
- A drift test between `t6g6SettingsManageScopes` and the settings.manage atom in `internal/books/atoms.go`: `internal/books` imports this package, so the test reads each definition's declared requirement and compares it to the scope list written out by hand; the real atom is not read.
- Deviation from R9: tasklint's unregistered-kind rule counts only package-level list functions as roots, never a method. `t6g6Kinds` delegates to the package-level `t6g6KindList(p, deps, sched)`, and `var _ = t6g6KindList` is the root. Same shape as F5-07's `t6g2KindList`.
