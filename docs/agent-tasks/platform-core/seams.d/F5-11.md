# F5-11 seams and coined names

F5-11 converts the 14 T6 group 6 maintenance definitions to native `books.<ID>` kinds (`internal/plugins/maintenance/kinds_t6_g6.go`). They are dark: nothing registers them before the tasks flip (F5-18). This file lists the readings the row took where the brief is silent, the helpers it added, and what later rows build on.

## Seams

- `t6g6Store` and `t6g6Writer` are composed by embedding each definition's own narrow interface, not one hand-written interface. Every core takes only its narrow piece; the composition is what `t6g6Deps` carries.
- `t6g6Deps` is wider than the brief's two fields. Besides `Store` and `NewWriter` it carries `ActivityLogFullDetailDays`, `StandDownKey`, `RootDir`, `ResolveReportPath` and `ITunesRoots`. F5-18 fills them.
- `StandDownKey` empty refuses a live apply that needs the stand-down (recover-missing-files with repoints, repoint-book-file-rows). A native apply never runs without the lease. The native stand-down `Lost()` reports false: a lost lease is caught by the writer fence.
- Coined write-set resource names: `operations` (the activity log and its digests, the undo ledger), `review_items` (regroup holds) and `user_state` (position, progress and bookmark rows moved by repair-merged-user-state).
- Native params drop `dry_run` and `apply`: the run's mode carries them (Preview reports, Live applies). Live-only writers (nightly compaction, recompact digests, iTunes heal) refuse Preview with `<kind>: preview not supported; start with mode live`.
- repair-merged-user-state does its whole pass through one writer call (`RepairMergedUserState`), because the merge package finds and moves the rows through one store. A Preview pass reports and writes nothing through it.
- Resume: Restart maps to `ResumeContinue` (the brief's reading), which differs from the F5-06 mapping for the same HEAD value.
- Optimize's native shell enqueues the children by `books.<HEAD id>` and awaits them; it has no progress relay (HEAD's `relayChildProgress` fed its watchdog), because `rc.Await` carries the child's liveness.
- The opchange ensure's yield is `tasks.ErrContinueInPlace` natively; the executor's handling of it is not proven here.
- iTunes heal's native writer must adapt the run to an `sdk.Reporter` (the heal body takes one). F5-18 builds it.

## Deviations

- Added Via variants and kept the old helpers as thin wrappers (tests call them): `previewOpChangeBookIndexVia`, `rebuildOpChangeBookIndexVia`, `ensureOpChangeBookIndexVia`, `t6g6FindOrphanBookFilesVia`, `t6g6PlanOrphanRepointsVia`, `t6g6ProbeAllVia`, `t6g6PlanRecoverVia`, `reconcileStaleHoldsVia`, `staleRegroupHoldsVia`, `decidedRegroupHoldsVia`. No existing symbol was renamed, re-signed or deleted.
- The nightly and recompact cores repeat the logic of `compactAndRecord` (in `compact_activity_log.go`, another row's file). F5-18 removes the duplicate with the HEAD shells.
- `opChangeIndexProgressTo` and `opChangeEnsureProgress` are kept for the old wrappers and are only reached through them.
- Wider write sets than HEAD declared: probe-directory-books and relink-unlinked-books also write `books` (the aggregate recompute), iTunes heal writes books, book_files and operations, nightly compaction and recompact write `operations`.
- ReadOnly: optimize (its children write), orphan book_file scan and orphan book_file repoint plan.
