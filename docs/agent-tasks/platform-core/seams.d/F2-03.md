# F2-03 seams and coined names

This file lists what the fresh executor (`core/internal/executor`) and the parity kit (`core/tasks/taskstest/parity`) added beyond 05-tasks, the readings F2-03 took where the spec or the brief says nothing, and the seams later rows build on. Everything not listed here follows the spec as written.

## Names beyond the spec

| Name | What it is |
|---|---|
| `executor.New(Options) (tasks.Executor, error)` | The constructor. Nothing outside core imports the package (the internal path enforces it); the kernel builds it at F5. |
| `executor.Options` | `Config`, `Stores`, `NewBatch`, `Keyspace` (the idempotency records), `Definitions`, `Manifests`, `Catalog`, `Principal`, `Health`, `Lanes`, `ChangeSinks`, `OnTerminal`, `Metrics`, `InstrumentsOff`, `Logger`, `Now`, `Getenv`, `ExtendTimeout`. |
| `executor.Config` | The `core.tasks.*` keys of 5T.10 the executor reads (`Workers`, `SystemWorkers`, `CPUSlots`, `Kinds`, `ShutdownDrain`, `ShutdownExtendMax`, `MinCheckpointInterval`, `MaxYields`, `ZombieCap`, `StandDownLease`, `IdempotencyTTL`, `ModuleMaxConcurrent`), plus four fixed timings tests may set (`DispatchTick`, `WatchdogInterval`, `ProgressInterval`, `MaxAttempts`). F3-01 fills it from core config; the config-file and JSON-env cells of `TestParallelismCap_LowersDeclared` wait for that. |
| `executor.Reconfigure(x, Config)` | Applies the hot keys; the restart keys are ignored. |
| `executor.Manifest{Module, Enabled, TaskLedger, TaskStarts}` | What the executor needs from a module manifest: held runs (5T.3.11) and the system actor's `TaskStarts`. F2-16 passes the kernel's manifests. |
| `executor.Principal` | `func(ctx) (tasks.Actor, rbac.Checker, bool)`: resolves a Client call's caller. F2-05's HTTP layer supplies it. |
| `executor.Attributes()`, `executor.InstrumentNames()` | The attribute keys for the kernel's `Provider.Core("ops", ...)` scope and the 18 instrument names (05-metrics §12's executor cell). |
| `executor.ScheduleMetrics`, `executor.Schedules(x)` | The scheduler's (F2-04) handle on the three schedule instruments. |
| Sentinels `ErrUnknownKind`, `ErrHeld`, `ErrNotPermitted`, `ErrPlanRequired`, `ErrPlanInvalid`, `ErrPlanTooOld`, `ErrApprovalRequired`, `ErrPlanRejected`, `ErrNoApproval`, `ErrReservedCheckpoint`, `ErrRowNotInPlan`, `ErrNotAwaitingDecision`, `ErrHoldLost`, `ErrLaneNotDeclared`, `ErrNoLaneCapacity`, `ErrDirtySource`, `ErrAlreadyRunning`, `ErrShuttingDown` | They live in the executor, not in `core/tasks`. **Seam:** F2-05 maps them to HTTP (404 `tasks.unknown_kind`, 403 `tasks.actor_not_permitted`, 409 `tasks.held`) and F2-16 needs `ErrHeld`; whichever comes first moves the ones it needs into the SDK. |
| `parity.Cases()`, `parity.Excluded`, `TestParity_ResumeCancelShutdown` | The oracle kit. F5-18 re-runs it over the converted definitions. |

## Stored formats the executor coined

| Record | Format |
|---|---|
| Checkpoint envelope | `{"core_attempt": <attempt>, "v": <body's JSON>}`. A value without the envelope (one the cutover imported) is read as it is. |
| Reserved checkpoint names | `core.rc` (RC's unnamed checkpoint: the store refuses an empty name), `core.zero` (the attempt from which ResumeFromZero voids earlier checkpoints), `core.approved` (an apply run's approved row IDs). A run body may not write or read any `core.` name (`ErrReservedCheckpoint`), so it cannot forge an approval. |
| Fixer plan rows | Stored as `plan:<Row.ID>` (`ReplaceRows` clears by prefix). Approve, the marks and the apply run use the bare `Row.ID`. **Seam:** F2-05's rows route strips the `plan:` prefix when it lists a plan. |
| Reject event | `RunEvent{Event: "reject"}` on the plan run; Approve refuses a plan that carries one, and so does its apply run. |
| Idempotency records | `idem/<kind>/<key>` in the tasks keyspace, kept `IdempotencyTTL`. |
| Reasons the executor writes | `cancel`, `shutdown`, `quiesce`, `timeout`, `error`, `watchdog`, `unknown_kind`, `resume_drop`, `resume_ask`, `restart_loop`, `yield_without_progress`, `yield_not_continue`, `max_yields`, `decided_drop`, `decided_finish`. |

## Readings taken

- **Approve permission.** Approve and reject need `Perms.Approve` (5T.3.7). There is no fallback to `Perms.Start`, because that fallback is decide's rule and definition validation guarantees `Perms.Approve` whenever `Approval` is set. The apply run is a start, so the approver also needs `Perms.Start`. A call with no identity is a kernel-internal call and acts as no one, never as the plan's actor. The verified-method half (SEC-24) belongs to F2-05's route.
- **A plan_ref only through Approve.** `Start`, `StartIn` and `rc.Enqueue` refuse a start that names a plan (`ErrApprovalRequired`). A Live start of a kind whose `Approval.PlanRequired` is set, without a plan, is `ErrPlanRequired`. An apply run with no approval record applies nothing (`ErrNoApproval`). A ResumeFromZero resume keeps the approval.
- **Continue in place.** It is honoured only for `ResumeContinue`. Progress counts only past the attempt's starting `Done`. A refused yield names the missing proof.
- **Shutdown of a Continue run** stamps `interrupted`, not HEAD's `interrupted_quiesced`. A `ResumeDrop` run stopped by Shutdown is stamped `interrupted` and dropped by the next boot's sweep.
- **Repeat cancel.** A run that is already terminal gives `tasks.ErrRunNotFound`; one in `stopping` gives nil.
- **Bounded drain.** Shutdown waits at most `min(ShutdownDrain, ctx deadline)`, plus one systemd extension for Uninterruptible runs.
- **Run log pages** are written only through `rc.Note`.
- **`DirtySet` sources fail closed** (`ErrDirtySource`) until the dirty-set store exists.
- **Watchdog** strikes Task-shaped runs only. Batch and Fixer runs are timed by their item loop.
- **Stand-down** quiesces only runs whose kind declares `Yields`.
- **`ref_lock_wait` buckets** are chosen here (milliseconds to ten minutes), since HEAD has no such histogram.
- **`Run` returns after starting its goroutines.** They stop at `Shutdown`.

## Noticed, out of scope

- A parent that awaits a child whose write set overlaps its own waits until it times out. The write-set gate has no parent exemption, as at HEAD (Gate 3b). Converted definitions with that shape (F5) need disjoint write sets or a ref lock.
- When `OnTerminal` returns an error, the attempt's end is not committed. The run stays `running` in the store until the next boot's resume sweep. 5T.4 step 3 says only that the error aborts the commit; whether the executor should retry is open.
