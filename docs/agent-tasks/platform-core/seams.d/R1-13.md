# R1-13 seams and coined names

This file covers what the kernel/app/module/httpapi skeleton PR added beyond 06 §6.4.1–§6.4.7, §6.5.1–§6.5.2 and 05-http-api §3. It lists names the spec does not have, readings it took where the spec or the brief is silent, the brief's tests it deferred, and the seams later rows build on. Those rows are R1-14, R1-15, R1-16, R1-17, R1-20, R1-30, R1-37, F3 and R2.

Everything not listed here follows the code contract as written.

## Names beyond the spec

| Name | What it is |
|---|---|
| `kernel.Config` | The kernel's view of `app.Options`; the kernel cannot import `app`. It holds the R1 option fields plus five seams. `LogOutput io.Writer` is the primary log output (default stderr; `Describe` uses `io.Discard`). `Notifier ReadinessNotifier` defaults to a no-op until R1-16. `ExtendStart func(string)` is `Deps.ExtendStart`'s target and a no-op until R1-16. `Listen func(httpapi.ListenOptions, http.Handler, *slog.Logger) (Server, error)` is start step 7's listener (default `httpapi.Listen`). `Exit func(int)` is what `RequestRestart` calls (default `os.Exit`). Tests inject the last three. |
| `kernel.R1Values`, `kernel.ModuleState`, `kernel.Description` | Field-for-field copies of the `app` types, so `app` converts with a plain type conversion. |
| `kernel.Server` | `interface{ Addr() net.Addr; Serve() error; Shutdown(context.Context) error }`. `*httpapi.Listener` satisfies it. |
| `kernel.ReadinessNotifier` | Coined by the brief: `interface{ Ready() error; Status(string) error; Stopping() error }`. `Status("starting")` is the only `Status` call at R1. |
| `errRestartRequested` (unexported) | `Run`'s error after a restart request has called `Exit(75)`. A test's `Exit` returns, so `Run` must return something. It was exported as `ErrRestartRequested` until the review of 039ef0dbd: in production the process has exited 75 before any caller could compare against it. |
| `module.Deps.RequestRestart func(reason string)` | `Lifecycle.RequestRestart` as a plain func, bound at P6, so a module can ask for 06 §6.5.2's restart (OPS8-12) after staging work the next boot applies. The spec names the restart path but not a `Deps` member. **Coordinator decision, 2026-11-07 (owner asleep, recommended option taken):** add it, and delete the coined `Kernel.Lifecycle()` accessor that nothing called. A call before readiness (start step 8) is logged at ERROR and ignored, without using up the first-reason slot, because honouring a request from `Register` or a hook's `Start` would restart the app in a loop. Tested by `TestDepsRequestRestart` and `TestRequestRestart_BeforeReadyIgnored`. |
| `httpapi.ErrRouteShape` | The sentinel for `Handle`'s malformed method, non-lowerCamel name, trailing-slash path and refused `RateClass`. They wrapped `ErrSchema` ("type cannot be described in OpenAPI") until the verification review. 05-http-api §3's sentinel list does not have it. |
| `httpapi.ListenOptions`, `httpapi.Listen`, `httpapi.Listener` | Start step 7's listener. The options are `Addr` (default `DefaultListen`, `":8484"`), `TLSCertFile`/`TLSKeyFile`, `ReadHeaderTimeout` (15s) and `IdleTimeout` (120s). `Listener` provides `Addr()`, `Serve()` (nil after `Shutdown`) and `Shutdown(ctx)`, which falls back to `Close` when ctx ends. |
| `httpapi.Router.AllowPublic(owner, names...)` | How the kernel hands `Manifest.PublicRoutes` to the router. `Handle` with `rbac.Public` on a route whose name the owner did not list fails `Build` (COR3-3). |
| `module.NewRegistrar`, `module.RegistrarConfig`, `module.Registrations`, `(*Registrar).Close` | The kernel builds each module's registrar from a config. `Close` ends registration and returns what was recorded; it is idempotent and returns the same registrations on every call. A call after `Close` records `ProblemRegistrarClosed` (06 §6.4.7's kind) and takes no effect. |
| `module.RegistrarConfig.AfterClose func(Problem)` | Receives each `ProblemRegistrarClosed` recorded after `Close`, outside the registrar's lock. The kernel reads `Err` once, right after `Register`, so a late call from a goroutine `Register` started would otherwise vanish; the kernel logs it at ERROR ("registrar call after Register returned; ignored"). |
| `module.NewProblem(module, kind, cause)`, `ProblemKind.String`, `module.IsReserved` | `NewProblem` keeps `cause` so that `errors.Is` still finds the httpapi sentinel through a kernel problem. |
| `module.ProblemInvalidRegistration` | The kind for a registration error that no spec kind names, such as a bad binding tag or a route shape. It is kept as the catch-all; the spec appends it to §6.4.7 (open question 3, answered). |
| `rbac.ReservedNamespaces()` | `{"core", "custom"}`: permission namespaces no module ID may take. |
| `log.OtherUserPredicate` | `func(rec Record, viewer string) bool`, the type `Registrar.LogOtherUserData` records. |
| Disabled reason `"default"` | `ModuleState.Disabled` for a module whose `Manifest.DefaultEnabled` is false. Until config (F3) no layer can set `core.modules.<id>.enabled`, so this is the only reason. |
| `lateStopFloor` (1s, unexported) | The least time the final close of metrics and logging gets once the budget is spent. It is the only step with a floor, so a stop overruns the budget by at most 1s. Until the review of 039ef0dbd every late `Stop` hook got its own floor, so a 2s budget with four blocking hooks took 5s. |
| `app.ExtendStart(step)` | A no-op until R1-16. It mirrors `Deps.ExtendStart`. |
| `app.ResolveStateDir(opts)` | The 05-config §1.7 rule over `<EnvPrefix>_CORE_PATHS_STATE_DIR`, `Options.StateDir` and an absolute `<EnvPrefix>_CORE_STORAGE_PATH`. It is backed by the unexported pure `resolveStateDir(explicit, def, dbPath, mkdir)`, which has `config.ResolveStateDir`'s signature and is replaced by it in F3. It reads env names only, from `Options.Env` or `os.Environ()`. The flag layer and the operator file's `core.storage.path` arrive with config. |
| `hello openapi [--out <file>]` | Writes `Description.Core`. By default it writes `core/openapi/core.json` under the go.mod that declares the core module, walking up from the working directory. With no subcommand, `hello` refuses any argument until the flag layer lands. |
| `testdata/specblocks/`, `blocks.json`, `regen.py` | Coined by the brief. `blocks.json` is `{"generator", "blocks": [{dest, heading, sha256, snapshot, spec}]}`, sorted keys, one `<path with / as ->.go.txt` per block. A block belongs to hello when its first line that is not blank and not `//go:build` is `// core/examples/hello/<file>.go`. |

## Spec readings

| Topic | Reading |
|---|---|
| Kernel shape (06 §6.4.6) | One package. The sub-packages §6.4.6 sketches are files at R1: `boot.go`, `kernel.go`, `supervisor.go`. |
| Phases that exist (06 §6.5.1, §6.4.10) | `New` runs P1 (catalog: IDs, duplicates, `MinCoreVersion`, enablement), P5 (logging, metrics, router), P6 (Register), P7 (consume registrations) and P8 (`Router.Build`). Each phase is timed into `mediacore_kernel_boot_phase_seconds{phase,step}`. P0–P4 and P9 need storage, config, auth or tasks, so they are absent rather than stubbed (STOP rule). |
| Claim collisions | Detected at P7 through `Router.Claim`, not as a separate P1 pass. This is equivalent at R1 because nothing runs between P1 and P7 that could act on a colliding claim. Every catalog entry's `/api/<id>/` is claimed, enabled or not, and so is core's `/api/core/` (06 §6.5.1 P1; 05-http-api §4.9): core's at P5 (`Router.CoreGroup` right after `NewRouter`), an enabled module's at P6 (`ModuleGroup`), a disabled module's at P7 before any `LegacyPrefixes` entry, so the collision is the prefix owner's. `TestModuleRootsClaimed`. |
| P8 and "R6 over the built router" | `Router.Build` runs at P8, per the P8 row and `Describe`'s text ("then calls Router.Build"). At R1, R6's check is `Build`'s own validation. |
| Reserved IDs (P1) | An ID is refused as `ProblemReservedID` when it is in `module.ReservedIDs()`, in `Options.ReservedAPINamespaces`, or equal to the first segment of another manifest's `LegacyPrefixes`. |
| `MinCoreVersion` | A strict three-part numeric comparison against `version.Version`. An unparsable value is `ProblemCoreTooOld`, so the module fails closed. |
| `AppID` | Validated like a module ID. A bad one is a `ProblemInvalidID` with `Module` "". |
| Mount segments (P7) | A mount's top segment outside its owner's `LegacyPrefixes` is `ProblemRouteOutsidePrefix` (coined mapping). A segment equal to another module's ID is `ProblemReservedID`. A second `ServesSPA` mount is `ProblemSPAOwner`, and that mount is not given to the router. |
| httpapi errors to kinds (P7) | `ErrNoPermission` maps to RouteWithoutPermission, `ErrOutsideClaim` to RouteOutsidePrefix, `ErrPrefixCollision` to LegacyPrefixCollision, `ErrForeignScope` to PermissionNamespace, `ErrUnknownScope` to UndeclaredPermission, and `ErrLegacyAuthGin`/`ErrOwnAuthMethod` to LegacyAuth. Anything else is InvalidRegistration. Each leaf of a joined error becomes one problem. |
| `Register`'s error | A panic is recovered and reported as an error. When `Register` returns `r.Err()` (06 §6.12.1's own pattern), its problems are counted once, not twice. |
| Problems joined | Every phase collects all its problems before failing, so one `*module.ValidationError` lists everything that phase found. `New` returns at the first phase that fails: a P1 failure means P5–P8 never run, so P1's and P7's problems are never joined into one error. |
| `Describe` | Runs P1, P5, P6 and P7 with every module treated as enabled and logging sent to `io.Discard`, then `Router.Build`. The core document's `info.version` is `version.Version`; a module's is its manifest version. |
| Start order (06 §6.5.2) | `Status("starting")`, then hooks in ID order (60s start limit each; a hook that overruns is abandoned in its goroutine), then workers, then `R1Values` read once, then listen, then `Ready`. A start failure rolls back the hooks already started, in reverse, within the default budget (25s): `R1Values`, and `core.shutdown.budget` with it, is read at step 7, after the hooks. A hook is started once its `Start` has returned nil: 06 §6.5.1's "every already-started hook is stopped in reverse order" is read as HEAD's `serviceregistry.Container.Start` (container.go:164-185), which adds a service to its started list only once its `Start` returned, and 05-health §5H.4's budget belongs to the started hooks' own `Stop`s. So the rollback waits for an abandoned `Start` only until min(deadline, now + `lateStopFloor`). If it returned nil by then, it is the newest started hook and is stopped first. If it is still running, the earlier hooks are stopped in reverse within the remaining budget, each awaited with a live ctx, and the late hook's `Stop` runs in the background once its `Start` returns nil (`TestStartRollback_HungStartCapped`, `TestStartRollbackReverseOrder`). Coordinator decision on the verification review's Q5; the first version waited the whole budget for it. `R1Values` runs under the kernel's panic recovery: a panic is a start failure and the stop order runs (`TestR1ValuesPanic_StopsInOrder`). |
| Stop order and budget (05-health §5H.4) | `Stopping`, then listener `Shutdown` within min(10s, remaining), then workers cancelled and awaited to the deadline, then hooks stopped in reverse, each within the deadline, then core closed (metrics provider, then logging last; this close alone gets at least `lateStopFloor`). Hooks reached after the deadline get no time of their own: their `Stop`s are called in the same reverse order from one background goroutine with an expired ctx and are not awaited, and the error names them (`TestStopBudget_LateHooksNotAwaited`). The budget is `R1Values.ShutdownBudget`, default 25s. A negative budget is an error returned with the stop, and the default is used. |
| `Run`'s error | Nil after a clean stop on ctx cancellation, per "clean shutdown returns nil". A stop caused by a `StopAppOnExit` worker, a `Stop` hook error or work abandoned at the budget is returned, joined with the cause of the stop. Kept (open question 4, answered). |
| Worker policies | `DegradeOnExit` logs and keeps the app up. `StopAppOnExit` stops the app with the worker's error. Panics are recovered under both. |
| Restart request | `RequestRestart(reason)` acts once (the first reason wins). It stops in the normal order, calls `Exit(75)` (`core.lifecycle.restart_exit_code`'s default; the key arrives with config), then returns `errRestartRequested`. Modules reach it through `Deps.RequestRestart`. A request before readiness is logged at ERROR and ignored (see `Deps.RequestRestart` above). |
| Router concurrency | Every `Router` method that touches registration state takes `Router.mu`, so a module goroutine calling `Handle` through its `*Group` while the kernel runs P7 or `Build` lands before `Build` or is refused with `errBuilt`, never races. `Routes` and `OpenAPI` iterate a snapshot. `TestRouter_ConcurrentLateRegistration` (it fails with DATA RACE without the locks). |
| Native route paths (05-http-api §3) | `Handle` refuses a path ending in `/` (a `ServeMux` subtree) unless it ends in `/{$}`. Observation: `ServeMux` still answers `GET /x` with a 307 to `/x/` for a `/x/{$}` pattern; `TestHandle_TrailingSlashRefused` pins that `/x/` serves and `/x/y` is a 404, and does not pin the redirect. |
| Body errors | A 400 or 422 never carries `err.Error()` or a Go type name. A JSON type mismatch is a 422 `FieldError("/body/<pointer>", "invalid_type", ...)` worded in JSON terms; a syntax error gives only its byte offset; an unknown field on a strict route is found by walking the body against the struct's JSON names (exact, then case-insensitive, as `encoding/json` matches), never by matching the error string. `TestDecode_ErrorsNameNoGoTypes`. |
| `RateClass` on native routes | `Handle` refuses `RateExempt` and any class above it. Only infra probes and the SPA handler are exempt, and those are registered by the router itself. The check is in `checkRouteShape`, which only `Handle` calls: legacy routes (`MountLegacy`, `LegacyRoute.RateClass`) do not pass through it, so R1-14 keeps the legacy manifest's `RateExempt` rows and owns their validation. `TestHandle_RateClassChecked`. |
| `Created[T]` | A handler returning `*Created[T]` is refused at registration (`ErrSchema`, "return Created[T] by value"); it used to panic at dispatch. `TestHandle_PointerCreatedRefused`. |
| `Router.Claim` | Refuses an empty owner, a prefix that does not start with `/`, `/` itself, a prefix containing `{`, and one that is not a clean literal path (`cleanUnder`). `TestClaim_RefusesUncleanPrefix`. |
| Registrations after `Router.Build` | Refused and logged at ERROR: `Handle`, `AllowPublic`, `MountLegacy`, `SPA`, `Claim`, `ModuleGroup` and `CoreGroup` return or record `errBuilt`. `TestRouter_RegistrationAfterBuildRefused`. |
| `LegacyMount.Auth` | Must be `LegacyAuthCore` or `LegacyAuthGin`. The zero value or an unknown value is refused: the registrar records `ProblemLegacyAuth` and `Router.MountLegacy` returns `ErrLegacyManifest`. `TestMountLegacy_RequiresAuth`, `TestRegistrar_Refusals`. |
| `TestNoGlobals` scope | It bans 03 R5's list, plus `log.SetFlags`/`log.SetPrefix` and assignment through `http.DefaultClient`/`http.DefaultTransport`. It skips `package main` under `core/examples/*/cmd/` (COR6-11). `app.InstallProcessDefaults` (R1-15) may make exactly 05-logging §10's seven installs. |

## Security fix folded in

A `body:"json"` route with `MaxBody < 0` (unbounded) is refused at registration with `ErrBadBinding`, so `Build` fails at boot. A JSON body always has a cap. This came from the coordinator's security review (MEDIUM), was committed as its own `fix(core)` commit, and is tested by `TestHandle_UnboundedJSONBodyRefused`. The rule is documented on `Route.MaxBody`.
