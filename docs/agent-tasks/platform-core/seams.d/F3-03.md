# F3-03 seams and coined names

This file lists what the core secrets PR added beyond 05-config §2 and the F3-03 brief: names the spec does not have, readings it took where the spec or the brief is silent, and the seams later rows (F3-04, F3-06, F3-07, F8-01) build on. Everything not listed here follows 05-config §2.3's code contract as the brief copies it.

Nothing here runs on `main`: no boot calls `secrets.Open`, creates `secrets.keyring` or writes `c/secrets/` until F3-07 (`grep -rn 'openSecrets(' core/kernel/ | grep -v _test.go | grep -vc 'func openSecrets'` prints 0).

## Names beyond the spec

| Name | What it is |
|---|---|
| `secrets.Options.InstallID` | The open store's `c/storage/install` marker. `Open` writes it into the keyring header when the header has none, and rewrites the header to it on `ResetBoot`. The spec has `Open` read the marker itself, but `secrets` cannot reach `storage.DB.Admin()` through a `storage.Keyspace`, so the caller passes it. `openSecrets` passes `db.Admin().InstallID()`. |
| `(*Store).Instrument(*metrics.Scope) error` | Registers the store's otel instruments on the `mediacore.secrets` scope. `Open` runs before P5, which is when scopes exist, so the kernel calls it after P5 instead of passing `Options.Metrics` at P4b. `Close` unregisters the callback. |
| `(*Store).UnexportedKeys() ([]string, error)` | The key IDs missing from `secrets.keyring.exported`, read from disk on each call. It feeds `secrets_keyring_not_exported`. |
| `(*Store).RetireBlocked() []string` | The verify keys past `retire_after` that the last `RetireUnused` kept, because the in-use check said yes or failed. It feeds `derive_key_retire_blocked`. |
| `(*Store).Undecryptable(ctx) ([]Name, error)` | The names whose record carries `Meta.Err`. It feeds `secrets_undecryptable`. |
| `(*Store).KeyFile() string`, `(*Store).KeyIDs() []string` | The keyring's path relative to the state directory, and the key IDs it holds. Read by the health detail and the offline commands. |
| `secrets.ExportKeyring`, `secrets.RotateDerive`, `secrets.SetInstallID`, `ExportResult`, `RotateResult` | The library halves of the three offline commands. Each works on an `*os.Root` state directory and opens no store. |
| `kernel.RotateDeriveOffline(ctx, c, now)`, `kernel.SetInstallIDOffline(ctx, c, id)` | The kernel halves. Each refuses unless the caller is the state directory's owner, then opens the store read-only through `OpenOffline`, which refuses while the service holds the lock. |
| `openSecrets`, `secretsInput`, `kernelSecrets` | The unexported P4b helper (the brief coins `openSecrets`), its input, and what it returns: the store plus the `*os.Root` it holds. |
| `core/internal/keyedmutex` | A copy of ABO's reference-counted per-key mutex. It imports only `sync`. |
| Test names | `TestKeyedMutex_SerializesPerKey` and `TestSecretsSeries_Golden` (the brief coins both), `TestKeyMaterial_NeverFormats`, `TestKeyring_Invariants`, `TestOpen_FirstRunKeyring`, `TestOpen_RefusesBadOptions`, `TestAll_NeverValues`, `TestKeyIDsReferenced`, `TestPut_SerializesPerName`, `TestClose_WipesAndRefuses`, `TestNoSecretInLogsOrErrors`, `TestMeta_StorageErrorIsAnError`, `TestRotateDerive_Refusals`, `TestExportKeyring_CopiesWithoutTheStore`, `TestExportKeyring_RefusesLooseOrOwnTargets`, `TestSecretsOwnerSpec`, `TestOpenSecrets_ScratchStateDir`, `TestSecretsHealth_Tokens`, `TestSecretsMetrics_Golden`, `TestRotateDerive_RefusedWhileServed`, `TestCoreSections_SecretKeys`, `TestValidatorAddedEntryNeverKeepsItsPath`. |

## Spec readings and deviations

| Topic | Reading |
|---|---|
| `Stage` and `StageUnreadable` take `ctx` | §2.3 has `Stage(b *storage.Batch, w Write)` and `StageUnreadable(b, n, reason, by)`. Both read the current record (create-only check, per-name lock), and every storage read takes a context, so both take `ctx` first. The importer's methods already had one. |
| `storage.ErrImportConflict` | Declared in `core/storage/import_errors.go`, because `secrets.Importer` is the first importer that returns it. F3-04 keeps it where it is and adds §5S.3.13's other sentinels beside it. |
| Importer semantics | Create-only. A record that already holds the same value, or the same unreadable marker, counts as already current and stages nothing. Anything else is `storage.ErrImportConflict`: another value, a cleared marker, a record that cannot be read. The importer bypasses the `Ephemeral` lock, because it writes the stored layer that an operator value hides. There is no import of a delete. |
| `Meta` | `Meta` returns a nil error for a name that is unset or whose record does not decrypt (the state is in `Meta.Set` and `Meta.Err`). A storage error is still an error (`TestMeta_StorageErrorIsAnError`). |
| `RetireUnused` | The decision lives in memory and never reaches the keyring file, so every boot decides again. When the in-use check returns true or fails, the key stays and is listed by `RetireBlocked`. Only a nil check or a cancelled context is returned as an error. |
| Missing keyring with records | `ErrKeyMissing` counts sealed and malformed records only. A cleared marker or an unreadable marker carries no ciphertext, so it does not block a first-run keyring. Regenerated IDs continue the numbering (`k<n>`, `d<n>` with n = highest stored kid + 1), so a new key never reuses an orphaned record's ID. |
| `export-keyring` target rules | It runs only as the state directory's owner. It writes mode 0600 and refuses an `--out` that exists looser than 0600, is not a regular file, is a symlink or a hard link, or is the keyring or the export record. The bytes are the keyring file's bytes. The record `secrets.keyring.exported` is `{"format":"mediacore-keyring-export/1","key_ids":[…],"at":…}` and holds no key material. |
| `rotate-derive` window | `retire_after` = now + max(`core.backup.retention.max_age`, `core.auth.session.remember_ttl`). It reads those keys' defaults through a throwaway `config.Store` over the core sections, because no stored override is readable offline until F3-07. The default is 168h. |
| `rotate-derive` and `set-install-id` open read-only | Both use a read-only `OpenOffline` plus an explicit `RefuseNotStateDirOwner`. They write the keyring file, not the store, and read-only mode still takes the lock, so a running service refuses them ("lock held by current process" in-process). |
| Offline key file | All three commands use the default `secrets.keyring`. `core.secrets.key_file` is not readable offline until the config flip hands these commands the app's config (F3-07). |
| Health | `core.secrets` reports one reason by precedence: `secrets_undecryptable` > `derive_key_retire_blocked` > `secrets_keyring_not_exported`, all `Degraded`. `Detail` lists every condition that holds. When the undecryptable check itself fails, the component reports `secrets_undecryptable` with the failure in `Detail`. A multi-reason `health.Result` is a todo (F8). |
| Owner spec | `secretsOwnerSpec()` (keyspace `c/secrets/`, `Serialized: [""]`) lives in `core/kernel/secrets.go` and is not added to `storageOwners`, so no boot lists the keyspace before F3-07. |
| `core.auth.oidc.<id>.client_secret` | **Not declared.** The config decoder refuses a `secrets.Ref` inside a list element, and `core.auth.oidc.providers` is a list. The correct fix is in the config engine: bind a `Ref` inside a list element to a secret name built from the entry's id (the spec's `core.auth.oidc.<id>.client_secret`). That is outside this row's file list. Tracked by `todo.d/2026-11-10-f3-03-oidc-client-secret-ref-in-list.md`. `core.http.basic_gate.password` is declared (`protect:"admin"`, no `reload` tag, not `FailClosed`). |

## Seams for later rows

| Row | Seam |
|---|---|
| F3-04 | A dry run passes a `KeyFile` inside its scratch directory. `Open` then never touches the state directory's keyring. The quarantine sealer adapter calls `Importer().ImportSecret`. |
| F3-06 (M2) | M2 reads HEAD's key file. Nothing here does. It stages a ciphertext it cannot decrypt with `Importer().ImportUnreadable(ctx, b, name, "key"\|"corrupt", by)`. |

Adds the boot-writer row and the crash-matrix cells. Binds F3-05's `httpapi.BasicGatePassword` to `secrets.RefTo("core.http.basic_gate.password")`. |
| F8-01 | Backup supplies `RetireUnused`'s real in-use check. The tests use a fake one. |
