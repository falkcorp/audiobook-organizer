## Goal

Build a durable identity layer for **individual audio files**, mirroring TASK-01's
book-level identity but for `BookFile`. Read
[`docs/specs/2026-07-29-abs-sync-api-design.md`](../../specs/2026-07-29-abs-sync-api-design.md)
§4.2b before writing any code.

**Why this exists as its own layer, separate from `BookFile.ID`:** the captured ABS
conformance fixtures show `contentUrl` is `/api/items/<itemId>/file/<ino>`, where
`ino` is ABS's filesystem inode as a string — fully opaque, not in track order. A
naive implementation would expose `BookFile.ID` directly as `ino`. That mostly works
today because `BookFile.ID` is already a stable ULID assigned once at
`CreateBookFile` and never regenerated by `UpdateBookFile` (re-verify below) — but
exposing the raw `BookFile.ID` gives this app's future file-replacement code (a
remux, a quality upgrade — same logical track, new physical file) no seam to signal
"this is a new physical file, but the client's cached download URL must keep
resolving." A separate `sync_file` layer, indirected the same way TASK-01 indirects
Book identity, gives that seam for free and costs one extra Pebble key per file.

## Background (verify before editing)

- **`BookFile.ID` today:** assigned once via `newULID()` inside `CreateBookFile` if
  empty, and **never regenerated** by `UpdateBookFile` (re-verify:
  `grep -n "func (s \*PebbleStore) CreateBookFile\|func (s \*PebbleStore) UpdateBookFile" internal/database/pebble_store_bookfiles.go`
  — expected: 2 hits, ~line 219 and ~line 286; then `grep -n "file.ID = id" internal/database/pebble_store_bookfiles.go`
  — expected: 1 hit, only inside `CreateBookFile`). This means an in-place metadata
  update, rename, or move that calls `UpdateBookFile` with the same `id` already
  preserves `BookFile.ID` for free — this task's job is the layer on top that also
  survives a **replace** (old row deleted, new row created with a new
  `BookFile.ID`), which nothing in this codebase does today (re-verify:
  `grep -rn "ReplaceBookFile\|func.*DeleteBookFile.*CreateBookFile" internal/` —
  expected: no output; there is no existing replace-in-place primitive). Build the
  `sync_file` primitives so a **future** replace path has a seam to call; do not
  build the replace path itself (out of scope — no such feature exists yet to hook).
- **Primary key form:** `book_file:<bookID>:<fileID>` (re-verify:
  `grep -n 'key := \[\]byte(fmt.Sprintf("book_file:%s:%s"' internal/database/pebble_store_bookfiles.go`
  — expected: 1 hit, ~line 261). BookFile identity is therefore the pair
  `(bookID, fileID)`, not `fileID` alone — mirror that in the `sync_file` reverse
  index.
- **No length constraint on `ino`.** Unlike `libraryItemId` (TASK-01, must be
  exactly 36 chars for Absorb), ABS's captured `ino` values in the oracle fixtures
  are plain numeric-looking strings (e.g. `"17"`, `"13"`) — any opaque string works.
  **Do not apply TASK-01's UUID-minting requirement here.** Reuse the existing
  `newULID()` helper (already in `internal/database/pebble_store.go`, re-verify:
  `grep -n "^func newULID" internal/database/pebble_store.go` — expected: 1 hit,
  ~line 355) — a 26-char ULID is fine for a file-sync ID and keeps this task
  dependency-free.
- **Pattern for adding a capability without touching `store.go`:** identical to
  TASK-01 — a small interface + `AsX` type-assertion helper, never added to the
  `Store` interface in `store.go`. If TASK-01 already landed, its
  `SyncIdentityStore`/`AsSyncIdentityStore` are in the same file as a working
  example to copy the shape of.

## Step-by-step

1. Open (or create, if TASK-01 hasn't landed — check first, per START HERE)
   `internal/database/pebble_store_syncid.go`.
2. Define:
   ```go
   type SyncFile struct {
   	SyncFileID    string    `json:"sync_file_id"`
   	BookID        string    `json:"book_id"`
   	CurrentFileID string    `json:"current_file_id"` // the live BookFile.ID
   	CreatedAt     time.Time `json:"created_at"`
   }
   ```
3. Key layout (three keys, all under the `sync_file:` prefix so they never collide
   with TASK-01's `sync_item:` keys):
   - `sync_file:<syncFileID>` → the `SyncFile` record (JSON) — the primary record.
   - `sync_file:lookup:<bookID>:<fileID>` → raw bytes of `syncFileID` — O(1)
     reverse lookup FROM a `(bookID, fileID)` pair TO its `syncFileID`, used by
     mint-on-first-encounter and by repoint.
   - `sync_file:book:<bookID>:<syncFileID>` → raw bytes of the current `fileID` —
     an **enumerable** index (prefix-scannable on `sync_file:book:<bookID>:`) so a
     caller can list every `sync_file` entry for a book without knowing the
     `syncFileID`s up front. This is the literal reverse-index shape the spec names
     in §4.2b (`sync_file:book:<bookID>:<fileID>`) and is what TASK-04's backfill
     idempotency check needs (see its brief).
4. Implement `MintOrGetSyncFileID(bookID, fileID string) (string, error)`:
   - Reject empty `bookID` or `fileID`.
   - Point-get `sync_file:lookup:<bookID>:<fileID>`; if found, return the existing
     `syncFileID`.
   - If `pebble.ErrNotFound`: mint via `newULID()`, build the `SyncFile` record,
     write all three keys above in one `NewBatch()`, commit with `pebble.Sync`.
   - Guard the check-then-mint race the same way as TASK-01: a package-level
     `sync.Mutex` (name it `syncFileMintMu`, separate from TASK-01's
     `syncIDMintMu` — different keyspace, no reason to share a lock and serialize
     unrelated work).
5. Implement `GetSyncFileID(bookID, fileID string) (string, bool, error)` — read-only,
   `("", false, nil)` on not-found.
6. Implement `ListSyncFilesForBook(bookID string) ([]SyncFile, error)` — prefix-scans
   `sync_file:book:<bookID>:` (upper bound: `append(prefix, 0xFF)`, matching the
   iteration convention in `GetAllBlockedHashes_Pebble`, re-verify:
   `grep -n "append(prefix, 0xFF)" internal/database/pebble_store_blocklist.go` —
   expected: 1 hit), then point-gets each `sync_file:<syncFileID>` to materialize the
   full `SyncFile` records. Used by TASK-04's backfill to know which `BookFile`s on a
   book already have a `sync_file` entry.
7. Implement `RepointSyncFile(bookID, oldFileID, newFileID string) error` — the file-level
   analogue of TASK-01's `RepointSyncItem`, for a **future** replace-in-place path
   (no caller yet, same as `RepointSyncItem` — do not invent one). Look up
   `syncFileID` via `sync_file:lookup:<bookID>:<oldFileID>`; if none, return `nil`
   (nothing to repoint). Otherwise, in one batch: delete
   `sync_file:lookup:<bookID>:<oldFileID>`, delete
   `sync_file:book:<bookID>:<syncFileID>` (old value) and rewrite it with the new
   `fileID`, write `sync_file:lookup:<bookID>:<newFileID>` → same `syncFileID`, and
   update the `SyncFile` record's `CurrentFileID` to `newFileID`.
8. Define, alongside `SyncFileStore`:
   ```go
   type SyncFileStore interface {
   	MintOrGetSyncFileID(bookID, fileID string) (string, error)
   	GetSyncFileID(bookID, fileID string) (string, bool, error)
   	ListSyncFilesForBook(bookID string) ([]SyncFile, error)
   	RepointSyncFile(bookID, oldFileID, newFileID string) error
   }

   func AsSyncFileStore(s any) SyncFileStore {
   	if s == nil {
   		return nil
   	}
   	if sf, ok := s.(SyncFileStore); ok {
   		return sf
   	}
   	return nil
   }
   ```
9. Write `internal/database/pebble_store_syncfile_test.go` (own file, even though the
   implementation shares `pebble_store_syncid.go` with TASK-01 — keeps the two
   tasks' tests from colliding on the same test file):
   - Mint-on-first-encounter for the same `(bookID, fileID)` pair returns the same
     ID twice.
   - Two different `fileID`s on the SAME book get two different `syncFileID`s.
   - The same `fileID` string reused on two DIFFERENT books (plausible — `BookFile`
     IDs are ULIDs, globally unique in practice, but the API takes both bookID and
     fileID as a pair — verify they don't collide) gets two independent
     `syncFileID`s.
   - `ListSyncFilesForBook` returns all minted entries for a book and none for
     another book.
   - `RepointSyncFile` moves the lookup index; minting again on the OLD `(bookID,
     oldFileID)` pair after repoint produces a **new, different** `syncFileID`
     (proves the lookup index really moved).
   - Concurrent mint race on the same `(bookID, fileID)` pair (mirror TASK-01's
     16-goroutine pattern) — all results identical, exactly one live record.
10. Add a `changelog.d/` fragment: `changelog.d/abs-sync-syncfile-keyspace.md`
    (guid `63f63dc2-4e48-4588-9c47-6ea212aa0ae9`), category `Added`.
