## Systemic pattern found across ALL 29 briefs in this group (worth flagging to coordinator once, not per-brief)

Every brief's `Source:` line's suggested re-find command (`grep -n "<paraphrased title>" TODO.md`) returns ZERO hits at HEAD, because the brief's title is a paraphrase/truncation of the actual TODO.md text, which is itself wrapped in markdown bold/backticks that break literal substring matches. Verified this is 29/29 in this group via a batch script (see `patches/anchor_results.json`-adjacent tooling below). The "or by the bold id" fallback is also frequently non-functional: for TODO items with a synthetic line-based id (e.g. "L1227"), that string ("L1227") does not appear literally anywhere in TODO.md — it is not a real "bold id", just a line-number label invented for the skeleton/README. It only works for the minority of items that have a real named id (SEC-CODEQL-BACKLOG, MERGE-CACHE-EVICT, VGBACKFILL-BOUNDS-FRAGILE, ARCH-8, etc.).

In every case checked so far, the **approximate line number** given in Source: does correctly land on (or within ~1-3 lines of) the right TODO.md item, so this is currently advisory rather than fatal — a weak model still has a working fallback. Two exceptions worth flagging as more serious when you reach them:
- **TASK-037**: Source line ~10523 lands on a numbered sub-bullet ("8. **Omnibus detection + dedup** — spec-only ... not started") inside an unrelated "follow-ups" list, not a dedicated top-level TODO checkbox. Worth checking whether this thin one-line pointer (to `docs/superpowers/specs/2026-05-31-omnibus-detection-and-dedup.md`, confirmed to exist per skeleton verdict_evidence) is enough basis for an Opus/L/review_critical schema-migration task, or whether it should be `needs_design` instead — the spec itself may not have been reviewed/approved yet (check the spec doc's own status).
